# 跳跃游戏 II

> 难度：中等 | 标签：贪心、数组、动态规划 | [LeetCode 原题](https://leetcode.cn/problems/jump-game-ii/description/)

## 题目描述

给定一个长度为 `n` 的 **0 索引**整数数组 `nums`。初始位置在下标 0。

每个元素 `nums[i]` 表示从索引 `i` 向后跳转的最大长度。换句话说，如果你在索引 `i` 处，你可以跳转到任意 `(i + j)` 处：

- `0 <= j <= nums[i]` 且
- `i + j < n`

返回到达 `n - 1` 的最小跳跃次数。测试用例保证可以到达 `n - 1`。

**示例 1：**

```
输入：nums = [2,3,1,1,4]
输出：2
解释：跳到最后一个位置的最小跳跃数是 2。
     从下标为 0 跳到下标为 1 的位置，跳 1 步，然后跳 3 步到达数组的最后一个位置。
```

**示例 2：**

```
输入：nums = [2,3,0,1,4]
输出：2
```

**提示:**

- `1 <= nums.length <= 10^4`
- `0 <= nums[i] <= 1000`
- 题目保证可以到达 `n - 1`

## 题解

### 思路

采用「贪心分层」的 BFS 思想：维护三个量——`jumps` 为已用跳跃次数、`end` 为当前这一跳能到达的最远边界、`farthest` 为扫描过程中所有可达位置能覆盖的最远位置。从左到右扫描（最后一格无需再跳，循环到 `n - 2`），每遇到一个可达位置就用它刷新 `farthest`；当扫描到当前层边界 `i == end` 时，说明这一跳的覆盖用尽，必须再跳一次，`jumps++` 并把边界推进到 `farthest`。

不变量是：`end` 之前的格子都已被某一次跳跃覆盖，`farthest` 是下一次跳跃能到达的最远格子。题目保证可以到达 `n - 1`，因此 `farthest` 一定会越过 `end`，不会原地打转。常见坑有两个：一是把 `jumps` 计在每个格子上（应在层边界处计数），二是循环跑完整个数组导致末尾多跳一次——到达最后一格就不再需要跳了。与 02 的区别在于：本题必须在「不得不跳」的边界处才计数，才能得到最小次数。

### 代码实现

::: code-group

```javascript [JavaScript]
var jump = function(nums) {
  let jumps = 0;
  let end = 0;
  let farthest = 0;
  for (let i = 0; i < nums.length - 1; i++) {
    farthest = Math.max(farthest, i + nums[i]);
    if (i === end) {
      jumps++;
      end = farthest;
    }
  }
  return jumps;
};
```

        jumps = end = farthest = 0
        for i in range(len(nums) - 1):

            if i == end:
                jumps += 1

        return jumps

### 复杂度分析

- 时间复杂度：O(n)，每个下标只扫描一次。
- 空间复杂度：O(1)，只维护三个标量。
