# 只允许一次函数调用

> 难度：简单 | 标签：闭包、高阶函数 | LeetCode 2666 · [原题链接](https://leetcode.cn/problems/allow-one-function-call/)

## 题目描述

给定一个函数 `fn`，它返回一个新的函数，返回的函数与原始函数完全相同，只不过它确保 `fn` 最多被调用一次。

- 第一次调用返回的函数时，它应该返回与 `fn` 相同的结果。

- 第一次后的每次调用，它应该返回 `undefined`。

**示例 1：**

```
输入：fn = (a,b,c) => (a + b + c), calls = [[1,2,3],[2,3,6]]
输出：[{"calls":1,"value":6}]
解释：
const onceFn = once(fn);
onceFn(1, 2, 3); // 6
onceFn(2, 3, 6); // undefined, fn 没有被调用
```

**示例 2：**

```
输入：fn = (a,b,c) => (a * b * c), calls = [[5,7,4],[2,3,6],[4,6,8]]
输出：[{"calls":1,"value":140}]
解释：
const onceFn = once(fn);
onceFn(5, 7, 4); // 140
onceFn(2, 3, 6); // undefined, fn 没有被调用
onceFn(4, 6, 8); // undefined, fn 没有被调用
```

**提示：**

- `calls` 是一个有效的 JSON 数组
- `1 <= calls.length <= 10`
- `1 <= calls[i].length <= 100`
- `2 <= JSON.stringify(calls).length <= 1000`

## 题解

::: details 点击查看题解

### 思路

最经典的闭包应用之一：外层用一个 `called` 布尔标记「是否已经执行过」，返回的包装函数每次进来先问这个标记。

关键顺序是 **先占坑再执行**：把 `called = true` 放在调用 `fn` 之前，即使 `fn` 内部再次触发包装函数也不会穿透（虽然本题不会遇到，但这是防御性写法）。

第一次调用要把结果返回给调用方，后续调用直接返回 `undefined`——注意本题语义就是「不再返回结果」，这与常见 `once` 实现（缓存并重复返回首次结果）不同；通用版的差异在于支付提交、单例初始化等场景需要拿一致结果，可按需改成返回缓存值。

参数与 `this` 用 `fn.apply(this, args)` 透传：包装函数常被直接当事件处理器用，丢 `this` 会让 `event.target` 之类失效。

与防抖/节流的区别：那些关心「时间窗口内的执行节奏」，本题只关心「执行次数上限」，不需要任何定时器。

工程变体：加 `reset()` 重新允许执行、或做成并发安全的 Promise 版 once（多个 `await` 同时触达也只发一次请求，缓存那个 Promise 本身）。

### 代码实现

```javascript
/**
 * @param {Function} fn
 * @return {Function}
 */
var once = function(fn) {
  let called = false; // 闭包记录是否已执行过

  return function(...args) {
    if (called) return undefined; // 已执行过，直接吞掉
    called = true; // 先占坑，再执行
    return fn.apply(this, args);
  };
};
```

### 复杂度分析

- 时间复杂度：O(1) 额外开销，真正执行 `fn` 最多一次。
- 空间复杂度：O(1)，闭包保存一个布尔标记（不计 `fn` 自身结果）。
