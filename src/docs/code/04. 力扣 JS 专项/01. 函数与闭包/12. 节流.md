# 节流

> 难度：中等 | 标签：闭包、定时器、性能优化 | LeetCode 2676（VIP 专属题） · [原题链接](https://leetcode.cn/problems/throttle/)

## 题目描述

> 本题为 LeetCode VIP 专属题，官方题面需登录后查看，以下为按原题题意整理的版本。

现给定一个函数 `fn` 和一个以毫秒为单位的时间 `t`，请你返回该函数的 **节流** 版本。

**节流** 函数首先立即被调用，然后在 `t` 毫秒的时间间隔内不能再次执行，但应该存储最新的函数参数，以便在延迟结束后使用这些参数调用 `fn`。

例如，`t = 50ms`，并且函数在 `30ms`、`40ms` 和 `60ms` 时被调用。

在 `30ms`，**节流** 函数 `fn` 应当立即以这些参数被调用，并且对 **节流** 函数 `fn` 的调用在接下来的 `t` 毫秒会被阻塞。

在 `40ms`，函数应当只是存储参数。

在 `60ms`，参数应该覆盖第二次调用中当前存储的参数，因为第二次和第三次调用是在 `80ms` 之前进行的。延迟结束后，应该使用延迟期间提供的最新参数来调用 **节流** 函数 `fn`，并且它还应该创建另一个 `80ms + t` 的延迟。

上面的图示展示了节流如何转换事件。每个矩形代表 100 毫秒，节流时间为 400 毫秒。每种颜色代表不同的输入集合。

**示例 1：**

```
输入：t = 100, 
calls = [
  {"t":20,"inputs":[1]}
]
输出：[{"t":20,"inputs":[1]}]
解释：第一次调用总是立即执行，没有延迟。
```

**示例 2：**

```
输入：t = 50, 
calls = [
  {"t":50,"inputs":[1]},
  {"t":75,"inputs":[2]}
]
输出：[{"t":50,"inputs":[1]},{"t":100,"inputs":[2]}]
解释：
第一次调用立即执行带有参数 (1) 的函数。 
第二次调用发生在 75 毫秒 时，在延迟期间内，因为 50 毫秒 + 50 毫秒 = 100 毫秒，所以下一次调用可以在 100 毫秒 时执行。因此，我们保存第二次调用的参数，以便在第一次调用的回调函数中使用。
```

**示例 3：**

```
输入：t = 70, 
calls = [
  {"t":50,"inputs":[1]},
  {"t":75,"inputs":[2]},
  {"t":90,"inputs":[8]},
  {"t": 140, "inputs":[5,7]},
  {"t": 300, "inputs": [9,4]}
]
输出：[{"t":50,"inputs":[1]},{"t":120,"inputs":[8]},{"t":190,"inputs":[5,7]},{"t":300,"inputs":[9,4]}]
解释：
第一次调用立即执行带有参数 (1) 的函数。 
第二次调用发生在 75 毫秒 时，在延迟期间内，因为 50 毫秒 + 70 毫秒 = 120 毫秒，所以它只应保存参数。 
第三次调用也在延迟期间内，因为我们只需要最新的函数参数，所以覆盖之前的参数。延迟期过后，在 120 毫秒时进行回调，并使用保存的参数进行调用。该回调会创建另一个延迟期间，时长为 120 毫秒 + 70 毫秒 = 190 毫秒，以便下一个函数可以在 190 毫秒时调用。 
第四次调用发生在 140 毫秒，在延迟期间内，因此应在 190 毫秒时作为回调进行调用。这将创建另一个延迟期间，时长为 190 毫秒 + 70 毫秒 = 260 毫秒。 
第五次调用发生在 300 毫秒，但它是在 260 毫秒 之后，所以应立即调用，并创建另一个延迟期间，时长为 300 毫秒 + 70 毫秒 = 370 毫秒。
```

**提示：**

- `0 <= t <= 1000`
- `1 <= calls.length <= 10`
- `0 <= calls[i].t <= 1000`
- `0 <= calls[i].inputs[j], calls[i].inputs.length <= 10`

## 题解

::: details 点击查看题解

### 思路

节流的语义是「按固定节奏」，与防抖「以最后一次为准」正相反：本题要求 leading（窗口开头立即执行一次）+ trailing（窗口内攒下的最新参数在窗口结束时补发一次），并且每次补发都会开启 **新的一段** `t` 毫秒窗口（示例 3 的 120 → 190 → 260 就是这么来的）。

实现只需要两个闭包变量：`timer` 标记当前是否处在冷却窗口（`null` 表示空闲），`pending` 存冷却期内最后一次调用的上下文与参数。

`timer === null` 时立即 `fn.apply(ctx, args)` 并挂一个 `t` 毫秒的定时器；冷却期内则只覆盖 `pending`，这保证「只保留最新参数」，后到的 90ms 调用把 75ms 的参数顶掉。

定时器到点先把 `timer` 置空（恢复空闲），再检查 `pending`——有就用它调用包装函数自身，这样 `timer` 又被挂上，自然形成下一段窗口；没有就静静结束。

因为补发是「递归调用包装函数」，`this`、参数与窗口管理完全复用同一套逻辑，不会出现两套分支。

`this` 必须在同步调用发生的那一刻捕获并存进 `pending`，定时器回调里是拿不到原调用上下文的。

旧资料里常见的时间戳 + 定时器「双保险」写法（时间戳判断该不该立即执行、定时器负责补发尾部）与本实现语义等价；纯时间戳版没有尾随、纯定时器版首帧有固定延迟，都不满足本题。

工程版节流还会挂一个 `cancel()` 清掉补发定时器并在组件卸载时调用；典型场景是 scroll / resize / mousemove 这类高频事件节流。

### 代码实现

```javascript
/**
 * @param {Function} fn
 * @param {number} t milliseconds
 * @return {Function}
 */
var throttle = function(fn, t) {
  let timer = null;        // null 表示当前不在冷却窗口内
  let pending = null;      // 冷却期内最近一次的 { ctx, args }

  const throttled = function(...args) {
    if (timer === null) {
      // 空闲：立即执行（leading），并开启新窗口
      fn.apply(this, args);
      timer = setTimeout(() => {
        timer = null; // 窗口结束，恢复空闲
        if (pending) {
          const { ctx, args: nextArgs } = pending;
          pending = null;
          // 用最新参数补发（trailing），同时进入下一段窗口
          throttled.apply(ctx, nextArgs);
        }
      }, t);
    } else {
      // 冷却中：只保存最新参数，后到的覆盖先前的
      pending = { ctx: this, args };
    }
  };

  return throttled;
};
```

### 复杂度分析

- 时间复杂度：O(1)，每次调用至多一次立即执行 + 一次定时器操作；被节流掉的调用不执行 `fn`。
- 空间复杂度：O(1)，闭包保存一个定时器句柄与一份待补发参数。
