# 函数防抖

> 难度：中等 | 标签：闭包、定时器、性能优化 | LeetCode 2627 · [原题链接](https://leetcode.cn/problems/debounce/)

## 题目描述

请你编写一个函数，接收参数为另一个函数和一个以毫秒为单位的时间 `t`，并返回该函数的 **函数防抖**后的结果。

**函数防抖**方法是一个函数，它的执行被延迟了 `t` 毫秒，如果在这个时间窗口内再次调用它，它的执行将被取消。你编写的防抖函数也应该接收传递的参数。

例如，假设 `t = 50ms`，函数分别在 `30ms`、 `60ms` 和 `100ms` 时调用。前两个函数调用将被取消，第三个函数调用将在 `150ms` 执行。如果改为 `t = 35ms`，则第一个调用将被取消，第二个调用将在 `95ms` 执行，第三个调用将在 `135ms` 执行。

请在不使用 lodash 的 `_.debounce()` 函数的前提下解决该问题。

**示例 1：**

```
输入：
t = 50
calls = [
  {"t": 50, inputs: [1]},
  {"t": 75, inputs: [2]}
]
输出：[{"t": 125, inputs: [2]}]
解释：
let start = Date.now();
function log(...inputs) { 
  console.log([Date.now() - start, inputs ])
}
const dlog = debounce(log, 50);
setTimeout(() => dlog(1), 50);
setTimeout(() => dlog(2), 75);

第一次调用被第二次调用取消，因为第二次调用发生在 100ms 之前
第二次调用延迟 50ms，在 125ms 执行。输入为 (2)。
```

**示例 2：**

```
输入：
t = 20
calls = [
  {"t": 50, inputs: [1]},
  {"t": 100, inputs: [2]}
]
输出：[{"t": 70, inputs: [1]}, {"t": 120, inputs: [2]}]
解释：
第一次调用延迟到 70ms。输入为 (1)。
第二次调用延迟到 120ms。输入为 (2)。
```

**示例 3：**

```
输入：
t = 150
calls = [
  {"t": 50, inputs: [1, 2]},
  {"t": 300, inputs: [3, 4]},
  {"t": 300, inputs: [5, 6]}
]
输出：[{"t": 200, inputs: [1,2]}, {"t": 450, inputs: [5, 6]}]
解释：
第一次调用延迟了 150ms，运行时间为 200ms。输入为 (1, 2)。
第二次调用被第三次调用取消
第三次调用延迟了 150ms，运行时间为 450ms。输入为 (5, 6)。
```

**提示：**

- `0 <= t <= 1000`
- `1 <= calls.length <= 10`
- `0 <= calls[i].t <= 1000`
- `0 <= calls[i].inputs.length <= 10`

## 题解

::: details 点击查看题解

### 思路

核心是闭包里的一个 `timer`：每次调用先 `clearTimeout` 取消上一次计划，再 `setTimeout` 重新排一个 `t` 毫秒后的调用——只有「安静」满 `t` 毫秒，回调才会真正执行。

所以语义是「以最后一次为准」：连续触发期间前几次全部作废，示例 3 里同一时刻的第二次调用正是被第三次顶掉的。

参数与 `this` 要透传到延迟执行的那一刻：在返回函数里用 `...args` 接住、用 `fn.apply(ctx, args)` 调用，定时器回调内部 `this` 已丢失，必须提前捕获。

`timer` 执行完记得置空，否则下一次判断「是否已有计划」会误以为还有未触发的定时器。

与节流的分工（见本目录的「节流」）：防抖等你停下来才动手，适合输入联想、窗口 resize 后重算、按钮防连点这类「只关心最终状态」的场景。

工程版防抖还有两个本题之外的扩展：`immediate` 模式（首次立即执行，冷却期内只重置计时）、`cancel()` 方法（组件卸载时清掉未触发的回调，避免迟到执行）；带返回值的版本则需用 Promise 包装原函数结果。

### 代码实现

```javascript
/**
 * @param {Function} fn
 * @param {number} t milliseconds
 * @return {Function}
 */
var debounce = function(fn, t) {
  let timer = null;

  return function(...args) {
    // 提前捕获调用上下文与参数，供延迟后使用
    const ctx = this;
    // 取消上一次计划，重新计时
    if (timer !== null) clearTimeout(timer);

    timer = setTimeout(() => {
      timer = null; // 执行完置空，方便下一轮判断
      fn.apply(ctx, args);
    }, t);
  };
};
```

### 复杂度分析

- 时间复杂度：O(1)，每次调用只做清定时器与挂定时器。
- 空间复杂度：O(1)，闭包保存一个定时器句柄与最近一次的参数（不计被裁剪的调用）。
