# 记忆函数

> 难度：中等 | 标签：闭包、缓存、高阶函数 | LeetCode 2623 · [原题链接](https://leetcode.cn/problems/memoize/)

## 题目描述

请你编写一个函数 `fn`，它接收另一个函数作为输入，并返回该函数的 **记忆化** 后的结果。

**记忆函数** 是一个对于相同的输入永远不会被调用两次的函数。相反，它将返回一个缓存值。

你可以假设有 **3** 个可能的输入函数：`sum`、`fib` 和 `factorial`。

- `sum` 接收两个整型参数 `a` 和 `b`，并返回 `a + b`。假设如果参数 `(b, a)` 已经缓存了值，其中 `a != b`，它不能用于参数 `(a, b)`。例如，如果参数是 `(3, 2)` 和 `(2, 3)`，则应进行两个单独的调用。

- `fib` 接收一个整型参数 `n`，如果 `n <= 1` 则返回 `1`，否则返回 `fib (n - 1) + fib (n - 2)`。

- `factorial` 接收一个整型参数 `n`，如果 `n <= 1` 则返回 `1`，否则返回 `factorial(n - 1) * n`。

**示例 1：**

```
输入：
fnName = "sum"
actions = ["call","call","getCallCount","call","getCallCount"]
values = [[2,2],[2,2],[],[1,2],[]]
输出：[4,4,1,3,2]
解释：
const sum = (a, b) => a + b;
const memoizedSum = memoize(sum);
memoizedSum (2, 2);// "call" - 返回 4。sum() 被调用，因为之前没有使用参数 (2, 2) 调用过。
memoizedSum (2, 2);// "call" - 返回 4。没有调用 sum()，因为前面有相同的输入。
// "getCallCount" - 总调用数： 1
memoizedSum(1, 2);// "call" - 返回 3。sum() 被调用，因为之前没有使用参数 (1, 2) 调用过。
// "getCallCount" - 总调用数： 2
```

**示例 2：**

```
输入：
fnName = "factorial"
actions = ["call","call","call","getCallCount","call","getCallCount"]
values = [[2],[3],[2],[],[3],[]]
输出：[2,6,2,2,6,2]
解释：
const factorial = (n) => (n <= 1) ? 1 : (n * factorial(n - 1));
const memoFactorial = memoize(factorial);
memoFactorial(2); // "call" - 返回 2。
memoFactorial(3); // "call" - 返回 6。
memoFactorial(2); // "call" - 返回 2。 没有调用 factorial()，因为前面有相同的输入。
// "getCallCount" -  总调用数：2
memoFactorial(3); // "call" - 返回 6。 没有调用 factorial()，因为前面有相同的输入。
// "getCallCount" - 总调用数：2
```

**示例 3：**

```
输入：
fnName = "fib"
actions = ["call","getCallCount"]
values = [[5],[]]
输出：[8,1]
解释：
fib(5) = 8 // "call"
// "getCallCount" - 总调用数：1
```

**提示：**

- `0 <= a, b <= 10^5`
- `1 <= n <= 10`
- `1 <= actions.length <= 10^5`
- `actions.length === values.length`
- `actions[i]` 为 "call" 和 "getCallCount" 中的一个
- `fnName` 为 "sum", "factorial" 和 "fib" 中的一个

## 题解

::: details 点击查看题解

### 思路

整体策略是「空间换时间」：闭包持有一张缓存表，调用时先算键，命中直接返回缓存值，未命中才真正执行原函数并写回缓存。

这正是动态规划「备忘录」的思想——`fib(5)` 这类递归函数被记忆化后，每个输入只算一次，`getCallCount` 才能是 1。

键的生成要区分参数组合：本题参数都是数字，把整个参数列表序列化成字符串即可，`(2, 2)`、`(1, 2)`、`(3, 2)`、`(2, 3)` 各自独立成键，顺序不同就是不同的键，正好满足题面「`(b, a)` 不能复用 `(a, b)`」的要求。

单参数场景（`fib`、`factorial`）序列化后就是参数本身，同样成立。

记忆化的前提是原函数是纯函数：相同输入必须恒定输出、无副作用；对依赖时间或随机数的函数做记忆化会得到错误结果。

缓存只增不减在本题数据范围内没有问题；实际工程中会追问缓存上限（LRU）与弱引用键的取舍。

### 代码实现

```javascript
/**
 * @param {Function} fn
 * @return {Function}
 */
function memoize(fn) {
  // 闭包持有缓存仓库，跨调用共享
  const cache = new Map();

  return function(...args) {
    // 数字参数序列化为字符串键：顺序不同即为不同键
    const key = JSON.stringify(args);
    if (cache.has(key)) {
      return cache.get(key); // 命中缓存，不再执行 fn
    }
    const result = fn(...args);
    cache.set(key, result);
    return result;
  };
}
```

### 复杂度分析

- 时间复杂度：平均 O(1)（键的序列化为 O(k)，k 为参数总长度）；首次调用仍为原函数的复杂度。
- 空间复杂度：O(m)，m 为不同参数组合的数量。
