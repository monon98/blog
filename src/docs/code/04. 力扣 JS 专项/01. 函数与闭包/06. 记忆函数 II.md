# 记忆函数 II

> 难度：困难 | 标签：闭包、缓存、Map | LeetCode 2630 · [原题链接](https://leetcode.cn/problems/memoize-ii/)

## 题目描述

现给定一个函数 `fn`，返回该函数的一个 **记忆化** 版本。

一个 **记忆化** 的函数是一个函数，它不会被相同的输入调用两次。而是会返回一个缓存的值。

函数 `fn` 可以是任何函数，对它所接受的值类型没有任何限制。如果两个输入值在 JavaScript 中使用 `===` 运算符比较时相等，则它们被视为相同。

**示例 1：**

```
输入： 
getInputs = () => [[2,2],[2,2],[1,2]]
fn = function (a, b) { return a + b; }
输出：[{"val":4,"calls":1},{"val":4,"calls":1},{"val":3,"calls":2}]
解释：
const inputs = getInputs();
const memoized = memoize(fn);
for (const arr of inputs) {
  memoized(...arr);
}

对于参数为 (2, 2) 的输入: 2 + 2 = 4，需要调用 fn() 。
对于参数为 (2, 2) 的输入: 2 + 2 = 4，这些输入之前已经出现过，因此不需要再次调用 fn()。
对于参数为 (1, 2) 的输入: 1 + 2 = 3，需要再次调用 fn()，总共调用了 2 次。
```

**示例 2：**

```
输入：
getInputs = () => [[{},{}],[{},{}],[{},{}]] 
fn = function (a, b) { return a + b; }
输出：[{"val":{},"calls":1},{"val":{},"calls":2},{"val":{},"calls":3}]
解释：
将两个空对象合并总是会得到一个空对象。尽管看起来应该缓存命中并只调用一次 fn()，但是这些空对象彼此之间都不是 === 相等的。
```

**示例 3：**

```
输入： 
getInputs = () => { const o = {}; return [[o,o],[o,o],[o,o]]; }
fn = function (a, b) { return ({...a, ...b}); }
输出：[{"val":{},"calls":1},{"val":{},"calls":1},{"val":{},"calls":1}]
解释：
将两个空对象合并总是会得到一个空对象。因为传入的每个对象都是相同的，所以第二个和第三个函数调用都会命中缓存。
```

**提示：**

- `1 <= inputs.length <= 10^5`
- `0 <= inputs.flat().length <= 10^5`
- `inputs[i][j] != NaN`

## 题解

::: details 点击查看题解

### 思路

本题的难点全在「键」：缓存必须严格按 `===` 判定相等，而参数可以是任意类型（数字、对象、数组……）。

最容易想到的 `JSON.stringify(args)` 键在这里会错：示例 2 里三个不同的 `{}` 序列化后都是 `{}`，会被误判为相同输入而错误命中；它把「值相等」当成了「引用相等」。

另一个思路是 lodash 式的 `resolver` 自定义键生成器，但那要求调用方额外提供规则，本题没有这个入口。

正确方案是 **逐参数建 Map 树**：根 Map 以第 1 个实参为键，其值是下一层 Map，以第 2 个实参为键……`Map` 的键比较语义恰好就是 `===`（对象按引用），与题意完全一致。

走到最后一层后用一个私有 `Symbol` 作为键存取结果，既不会与实参键冲突，也能区分「参数走过这条路」与「这条路已有结果」。

示例 2 每次的 `{}` 都是新引用 → 每层都查不到 → 三次都执行；示例 3 传的是同一个引用 → 每层都命中 → 只执行一次。

空间上这棵树按实际用到的参数组合增长，不做淘汰；单次调用只沿树下降一层一个 Map 查询。

### 代码实现

```javascript
/**
 * @param {Function} fn
 * @return {Function}
 */
function memoize(fn) {
  // 私有 Symbol 作「结果」标记，与实参键天然隔离
  const RESULT = Symbol("result");
  const root = new Map();

  return function(...args) {
    let node = root;
    // 逐参数下钻，Map 的键比较语义就是 ===
    for (const arg of args) {
      if (!node.has(arg)) node.set(arg, new Map());
      node = node.get(arg);
    }
    // 该组合算过就直接返回，否则执行并登记
    if (!node.has(RESULT)) {
      node.set(RESULT, fn(...args));
    }
    return node.get(RESULT);
  };
}
```

### 复杂度分析

- 时间复杂度：平均 O(m)，m 为参数个数（每层一次 Map 查找）；首次命中的组合仍要执行原函数。
- 空间复杂度：O(T)，T 为 Map 树中不同参数组合的节点总数。
