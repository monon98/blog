# 使对象不可变

> 难度：中等 | 标签：Proxy、不可变数据、错误处理 | LeetCode 2692（VIP 专属题） · [原题链接](https://leetcode.cn/problems/make-object-immutable/)

## 题目描述

> 本题为 LeetCode VIP 专属题，官方题面需登录后查看，以下为按原题题意整理的版本。

请你编写一个函数，该函数接收一个对象 `obj`，并返回该对象的一个新的 **不可变** 版本。

**不可变** 对象是指不能被修改的对象，如果试图修改它，则会抛出错误。

此新对象可能产生三种类型的错误消息：

- 如果试图修改对象的键，则会产生以下错误消息：`Error Modifying: ${key}`。
- 如果试图修改数组的索引，则会产生以下错误消息：`Error Modifying Index: ${index}`。
- 如果试图调用会改变数组的方法，则会产生以下错误消息：`Error Calling Method: ${methodName}`。你可以假设只有以下方法能够改变数组：`['pop', 'push', 'shift', 'unshift', 'splice', 'sort', 'reverse']`。

`obj` 是一个有效的 JSON 对象或数组，也就是说，它是 `JSON.parse()` 的输出结果。

请注意，应该抛出字符串字面量，而不是 `Error` 对象。

**示例 1：**

```
输入：
obj = {
  "x": 5
},
fn = (obj) => {
  obj.x = 5;
  return obj.x;
}
输出：{"value": null, "error": "Error Modifying: x"}
解释：试图修改对象的键会导致抛出错误。请注意，是否将值设置为与之前相同的值并不重要。
```

**示例 2：**

```
输入：
obj = [1, 2, 3],
fn = (arr) => {
  arr[1] = {};
  return arr[2];
}
输出：{"value": null, "error": "Error Modifying Index: 1"}
解释：试图修改数组会导致抛出错误。
```

**示例 3：**

```
输入：
obj = {
  "arr": [1, 2, 3]
},
fn = (obj) => {
  obj.arr.push(4);
  return 42;
}
输出：{"value": null, "error": "Error Calling Method: push"}
解释：调用可能导致修改的方法会导致抛出错误。
```

**示例 4：**

```
输入：
obj = {
  "x": 2,
  "y": 2
},
fn = (obj) => {
  return Object.keys(obj);
}
输出：{"value": ["x", "y"], "error": null}
解释：没有尝试进行修改，因此函数正常返回。
```

**提示：**

- `2 <= JSON.stringify(obj).length <= 10^5`

## 题解

::: details 点击查看题解

### 思路

整体策略是递归给每个节点套一层 `Proxy`：对象用 `set` 陷阱拦截一切赋值，数组除了 `set` 还要拦截那 7 个会改数组的方法。

`Object.freeze` 不可用——它在严格模式外会静默失败（不抛错），而且管不住 `push` 这类从原型链上借来的方法，题目要求的三种错误消息它一个都给不出。

错误必须抛 **字符串字面量** 而不是 `Error` 对象，所以直接 `throw \`Error Modifying: ${key}\``，判题端拿到的就是这个字符串本身。

三种消息按 target 形态区分：普通对象的 `set` 抛 `Error Modifying: ${key}`；数组的 `set` 抛 `Error Modifying Index: ${index}`；7 个变异方法用 `apply` 陷阱包一层代理，调用即抛 `Error Calling Method: ${methodName}`。

包装顺序是「先递归嵌套、后包当前节点」，这样每一层拿到的子值已经是代理，`obj.arr.push(4)` 里的 `arr` 天然带方法拦截。

给数组遮蔽变异方法时用 `Object.defineProperty` 写成 **不可枚举** 的自有属性：若直接赋值会多出一个可枚举键，`Object.keys(arr)` 与序列化结果都会被污染；不可枚举则完全不可见，只影响属性查找。

读操作一律放行（示例 4 的 `Object.keys` 必须正常返回），陷阱里只有 `set` 与 `apply`，其它协议默认走原生行为。

### 代码实现

```javascript
var makeImmutable = function (obj) {
  const MUTATORS = [
    "pop",
    "push",
    "shift",
    "unshift",
    "splice",
    "sort",
    "reverse",
  ];
  const isObj = (v) => v !== null && typeof v === "object";

  const wrap = (node) => {
    // 递归拷贝一层再包装：既覆盖嵌套结构，也不改动入参对象
    const copy = Array.isArray(node)
      ? node.map((v) => (isObj(v) ? wrap(v) : v))
      : Object.fromEntries(
          Object.entries(node).map(([k, v]) => [k, isObj(v) ? wrap(v) : v])
        );

    if (Array.isArray(copy)) {
      for (const name of MUTATORS) {
        // 不可枚举的自有属性遮蔽变异方法，Object.keys 不受影响
        Object.defineProperty(copy, name, {
          value: new Proxy(copy[name], {
            apply() {
              throw `Error Calling Method: ${name}`;
            },
          }),
          configurable: true,
          writable: true,
        });
      }
    }

    return new Proxy(copy, {
      set(target, key) {
        throw Array.isArray(target)
          ? `Error Modifying Index: ${String(key)}`
          : `Error Modifying: ${String(key)}`;
      },
    });
  };

  return wrap(obj);
};
```

### 复杂度分析

- 时间复杂度：O(n)，每个节点包装一次；每次违规写入 O(1) 抛错。
- 空间复杂度：O(n)，复制并包装后的整棵新结构。
