# 相等还是不相等

> 难度：简单 | 标签：断言、闭包、错误处理 | LeetCode 2704 · [原题链接](https://leetcode.cn/problems/to-be-or-not-to-be/)

## 题目描述

请你编写一个名为 `expect` 的函数，用于帮助开发人员测试他们的代码。它应该接受任何值 `val` 并返回一个包含以下两个函数的对象。

- `toBe(val)` 接受另一个值并在两个值相等（ `===` ）时返回 `true` 。如果它们不相等，则应抛出错误 `"Not Equal"` 。
- `notToBe(val)` 接受另一个值并在两个值不相等（ `!==` ）时返回 `true` 。如果它们相等，则应抛出错误 `"Equal"` 。

**示例 1：**

```
输入：func = () => expect(5).toBe(5)
输出：{"value": true}
解释：5 === 5 因此该表达式返回 true。
```

**示例 2：**

```
输入：func = () => expect(5).toBe(null)
输出：{"error": "Not Equal"}
解释：5 !== null 因此抛出错误 "Not Equal"。
```

**示例 3：**

```
输入：func = () => expect(5).notToBe(null)
输出：{"value": true}
解释：5 !== null 因此该表达式返回 true。
```

## 题解

::: details 点击查看题解

### 思路

整体策略是工厂函数：`expect(val)` 用闭包把被测值 `val` 固定下来，返回一个装着 `toBe` 与 `notToBe` 两个方法的对象，调用方再传入比较值。

两个方法就是同一套断言的正反面：`toBe` 要求 `===` 成立才返回 `true`，否则抛错；`notToBe` 要求 `!==` 成立才返回 `true`，否则抛错，两者的错误消息互不相同。

比较必须用严格相等 `===`/`!==`，不能用 `==`——`0 == ""`、`null == undefined` 这类隐式转换会让本该报错的断言通过。

抛出的是 `new Error("Not Equal")` 这样的错误对象，判题端读取的是它的 `message`，与期望的 `{"error": "Not Equal"}` 对齐；直接 `throw "Not Equal"` 也能通过，但抛 `Error` 更符合实践（栈信息可读）。

方法要写成对象里的箭头函数或简写方法，让 `val` 始终来自外层闭包——若把它挂到 `this` 上，解构调用（`const { toBe } = expect(5)`）就会丢上下文。

这类「返回方法集」的写法是链式断言库（`expect(x).toBe(y)`）的最简雏形。

### 代码实现

```javascript
var expect = function (val) {
  return {
    toBe(v) {
      if (v === val) return true;
      throw new Error("Not Equal");
    },
    notToBe(v) {
      if (v !== val) return true;
      throw new Error("Equal");
    },
  };
};
```

### 复杂度分析

- 时间复杂度：O(1)，一次严格比较即可得出结果。
- 空间复杂度：O(1)，只持有闭包引用与返回对象。
