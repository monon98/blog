# 不可变辅助工具

> 难度：困难 | 标签：Proxy、不可变数据、写时复制 | LeetCode 2691（VIP 专属题） · [原题链接](https://leetcode.cn/problems/immutability-helper/)

## 题目描述

> 本题为 LeetCode VIP 专属题，官方题面需登录后查看，以下为按原题题意整理的版本。

创建带有微小修改的不可变对象的克隆副本是一个繁琐的过程。请你编写一个名为 `ImmutableHelper` 的类，作为满足这一要求的工具。构造函数接受一个不可变对象 `obj`，该对象将是一个 JSON 对象或数组。

该类有一个名为 `produce` 的方法，它接受一个名为 `mutator` 的函数，返回一个新对象，它与原始对象相似，但应用了这些变化。

`mutator` 函数接受 `obj` 的 **代理** 版本。函数的使用者可以（看起来）对该对象进行修改，但原始对象 `obj` 实际上没有被改变。

例如，用户可以编写如下代码：

```
const originalObj = {"x": 5};
const helper = new ImmutableHelper(originalObj);
const newObj = helper.produce((proxy) => {
  proxy.x = proxy.x + 1;
});
console.log(originalObj); // {"x": 5}
console.log(newObj); // {"x": 6}
```

`mutator` 函数的属性：

- 它始终返回 `undefined`。
- 它永远不会访问不存在的键。
- 它永远不会删除键（ `delete obj.key` ）。
- 它永远不会在代理对象上调用方法（ `push`、`shift` 等）。
- 它永远不会将键设置为对象（ `proxy.x = {}` ）。

**关于如何测试解决方案的说明：** 解决方案验证器仅分析返回结果与原始 `obj` 之间的差异。进行完全比较的计算开销太大。此外，对原始对象进行的任何变更都将导致答案错误。

**示例 1：**

```
输入：
obj = {"val": 10},
mutators = [
  proxy => { proxy.val += 1; },
  proxy => { proxy.val -= 1; }
]
输出：
[
  {"val": 11},
  {"val": 9}
]
解释：
const helper = new ImmutableHelper({val: 10});
helper.produce(proxy => { proxy.val += 1; }); // { "val": 11 }
helper.produce(proxy => { proxy.val -= 1; }); // { "val": 9 }
```

**示例 2：**

```
输入：
obj = {"arr": [1, 2, 3]},
mutators = [
  proxy => {
    proxy.arr[0] = 5;
    proxy.newVal = proxy.arr[0] + proxy.arr[1];
  }
]
输出：
[
  {"arr": [5, 2, 3], "newVal": 7}
]
解释：对原始数组进行了两次编辑。首先将数组的第一个元素设置为 5。然后添加了一个值为 7 的新键。
```

**示例 3：**

```
输入：
obj = {"obj": {"val": {"x": 10, "y": 20}}}
mutators = [
  proxy => {
    let data = proxy.obj.val;
    let temp = data.x;
    data.x = data.y;
    data.y = temp;
  }
]
输出：
[
  {"obj": {"val": {"x": 20, "y": 10}}}
]
解释：交换了 "x" 和 "y" 的值。
```

**提示：**

- `2 <= JSON.stringify(obj).length <= 4 * 10^5`
- `produce() 的总调用次数 < 10^5`

## 题解

::: details 点击查看题解

### 思路

整体策略是「写时复制」的代理：`produce` 开始时只把根浅拷贝一份，之后每下钻一层就复制那一层并挂回已拷贝的父节点，真正被写入的节点一定落在拷贝上，原始对象全程只读。

不能直接对原对象套 `Proxy` 然后原地写——题目明确「对原始对象进行的任何变更都将导致答案错误」，验证器会比对原对象。也不能每次 `produce` 都整体深拷贝：载荷上限 4×10^5、调用次数接近 10^5，全量拷贝的最坏代价过大。

代理只需要两个陷阱：`get` 遇到对象值时先复制再返回子代理，保证「读到哪、拷到哪」；`set` 直接写进当前节点（此时它必是本轮拷贝），不做任何拦截。

要用一个 `Set` 记录本轮已复制的节点：同一条路径被重复读取时不能再次复制，否则先取出的 `data` 与后来读到的 `proxy.obj.val` 会指向两份不同副本，示例 3 的交换就会失效。

题目给的 mutator 四条约束（不删键、不调数组方法、不访问不存在的键、不写入对象值）让实现大幅简化：不需要 `delete`/方法调用相关陷阱，也不用担心写进来的值是需要再包装的结构。

未被访问的子树在结果里与原对象共享引用——这是刻意的，既省时间又不破坏不可变语义（没人会改它）。

### 代码实现

```javascript
class ImmutableHelper {
  constructor(obj) {
    this.obj = obj;
  }

  produce(mutator) {
    // 本轮已复制过的节点，避免同一条路径重复复制
    const copied = new Set();

    const shallow = (node) => (Array.isArray(node) ? [...node] : { ...node });

    const root = shallow(this.obj);
    copied.add(root);

    const wrap = (node) =>
      new Proxy(node, {
        get(target, key) {
          const value = target[key];
          if (value === null || typeof value !== "object") return value;
          if (!copied.has(value)) {
            // 下钻前复制子节点并挂回父拷贝，原对象引用不被触碰
            const clone = shallow(value);
            copied.add(clone);
            target[key] = clone;
            return wrap(clone);
          }
          return wrap(value);
        },
        set(target, key, value) {
          // target 一定是本轮的拷贝，可以安全写入
          target[key] = value;
          return true;
        },
      });

    mutator(wrap(root));
    return root;
  }
}
```

### 复杂度分析

- 时间复杂度：O(k)，k 为 mutator 访问到的节点数，只复制路径上的节点，未触及的子树零开销。
- 空间复杂度：O(k)，本轮复制出的节点数；结果与原对象共享未修改部分。
