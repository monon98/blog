# 有时间限制的 Promise 对象

> 难度：中等 | 标签：Promise、定时器、闭包 | LeetCode 2637 · [原题链接](https://leetcode.cn/problems/promise-time-limit/)

## 题目描述

请你编写一个函数，它接受一个异步函数 `fn` 和一个以毫秒为单位的时间 `t`。它应根据限时函数返回一个有 **限时** 效果的函数。函数 `fn` 接受提供给 **限时** 函数的参数。

**限时** 函数应遵循以下规则：

- 如果 `fn` 在 `t` 毫秒的时间限制内完成，**限时** 函数应返回结果。
- 如果 `fn` 的执行超过时间限制，**限时** 函数应拒绝并返回字符串 `"Time Limit Exceeded"`。

**示例 1：**

```
输入：
fn = async (n) => {
  await new Promise(res => setTimeout(res, 100));
  return n * n;
}
inputs = [5]
t = 50
输出：{"rejected":"Time Limit Exceeded","time":50}
解释：
const limited = timeLimit(fn, t)
const start = performance.now()
let result;
try {
  const res = await limited(...inputs)
  result = {"resolved": res, "time": Math.floor(performance.now() - start)};
} catch (err) {
  result = {"rejected": err, "time": Math.floor(performance.now() - start)};
}
console.log(result) // 输出结果

提供的函数设置在 100ms 后执行完成，但是设置的超时时间为 50ms，所以在 t=50ms 时拒绝因为达到了超时时间。
```

**示例 2：**

```
输入：
fn = async (n) => {
  await new Promise(res => setTimeout(res, 100));
  return n * n;
}
inputs = [5]
t = 150
输出：{"resolved":25,"time":100}
解释：在 t=100ms 时执行 5*5=25，没有达到超时时间。
```

**示例 3：**

```
输入：
fn = async (a, b) => {
  await new Promise(res => setTimeout(res, 120));
  return a + b;
}
inputs = [5,10]
t = 150
输出：{"resolved":15,"time":120}
解释：在 t=120ms 时执行 5+10=15，没有达到超时时间。
```

**示例 4：**

```
输入：
fn = async () => {
  throw "Error";
}
inputs = []
t = 1000
输出：{"rejected":"Error","time":0}
解释：此函数始终丢出 Error
```

**提示：**

- `0 <= inputs.length <= 10`
- `0 <= t <= 1000`
- `fn` 返回一个 Promise 对象

## 题解

::: details 点击查看题解

### 思路

整体策略是「竞速」：返回的限时函数内部 new 一个 Promise，一边挂 `setTimeout(t)` 到点就 `reject("Time Limit Exceeded")`，一边调用 `fn`，谁先结算谁生效——Promise 只认第一次结算，所以不用自己加锁。

`fn` 必须放进微任务里调用（`Promise.resolve().then(() => fn(...args))`），不能裸调：这样 `fn` 即使同步 `throw`（示例 4）也会变成 promise 拒绝，而不是把整个调用同步炸出去，`time` 才是 0ms。

无论 `fn` 成功还是失败，回调里都要 `clearTimeout`：否则超时定时器会一直挂到 `t` 毫秒后才释放事件循环资源。反过来，超时先触发后 `fn` 再结算时，`clearTimeout` 对已触发的定时器是无害的空操作，`resolve` 也会被忽略——两个方向都安全。

失败要原样透传：`fn` 抛出的 `"Error"` 必须是同一个字符串（示例 4），不能包一层 `Error`；超时则固定是字符串 `"Time Limit Exceeded"`。

参数用 `...args` 收集再展开；若要连调用时的 `this` 一起透传，把返回的函数写成普通函数并在内部 `fn.apply(this, args)` 即可（本题判题不涉及 `this`）。

### 代码实现

```javascript
/**
 * @param {Function} fn
 * @param {number} t
 * @return {Function}
 */
var timeLimit = function(fn, t) {
  return async function(...args) {
    return new Promise((resolve, reject) => {
      // 超时定时器：先到就以 "Time Limit Exceeded" 拒绝
      const timer = setTimeout(() => reject("Time Limit Exceeded"), t);
      // 放进微任务调用 fn：同步抛错也会变成拒绝（示例 4）
      Promise.resolve()
        .then(() => fn(...args))
        .then(
          (value) => {
            clearTimeout(timer); // fn 先完成：清掉超时定时器
            resolve(value);
          },
          (reason) => {
            clearTimeout(timer); // fn 先失败：同样清掉定时器，原因原样透传
            reject(reason);
          }
        );
    });
  };
};
```

### 复杂度分析

- 时间复杂度：O(1)，每次调用只注册一个定时器、一条微任务链，与参数规模无关。
- 空间复杂度：O(1)，闭包保存一个定时器句柄。
