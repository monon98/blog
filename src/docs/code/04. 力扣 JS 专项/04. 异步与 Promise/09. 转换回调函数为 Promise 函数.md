# 转换回调函数为 Promise 函数

> 难度：中等 | 标签：高阶函数、闭包、Promise | LeetCode 2776（VIP 专属题） · [原题链接](https://leetcode.cn/problems/convert-callback-based-function-to-promise-based-function/)

## 题目描述

> 本题为 LeetCode VIP 专属题，官方题面需登录后查看，以下为按原题题意整理的版本。

编写一个函数，接受另一个函数 `fn`，并将基于回调函数的函数转换为基于 Promise 的函数。

`promisify` 函数接受一个函数 `fn`，`fn` 将回调函数作为其第一个参数，并且还可以接受其他额外的参数。

`promisify` 返回一个新函数，新函数会返回一个 Promise 对象。当回调函数被成功调用时，新函数返回的 Promise 对象应该使用原始函数的结果（回调的第一个参数）进行解析；当回调函数被调用出现错误（回调的第二个参数携带错误）时，返回的 Promise 对象应该被拒绝并携带该错误信息。最终返回的基于 Promise 的函数应该接受额外的参数作为输入。

以下是一个可以传递给 `promisify` 的函数示例：

```
function sum(callback, a, b) {
  if (a < 0 || b < 0) {
    const err = Error('a and b must be positive');
    callback(undefined, err);
  } else {
    callback(a + b);
  }
}
```

这是基于 Promise 的等效代码：

```
async function sum(a, b) {
  if (a < 0 || b < 0) {
    throw Error('a and b must be positive');
  } else {
    return a + b;
  }
}
```

**示例 1：**

```
输入：
fn = (callback, a, b, c) => {
  return callback(a * b * c);
}
args = [1, 2, 3]
输出：{"resolved": 6}
解释：
const asyncFunc = promisify(fn);
asyncFunc(1, 2, 3).then(console.log); // 6

fn 以回调函数作为第一个参数和 args 作为其余参数进行调用。当使用 (1, 2, 3) 调用时，基于 Promise 的 fn 将解析为值 6。
```

**示例 2：**

```
输入：
fn = (callback, a, b, c) => {
  callback(a * b * c, "Promise Rejected");
}
args = [4, 5, 6]
输出：{"rejected": "Promise Rejected"}
解释：
const asyncFunc = promisify(fn);
asyncFunc(4, 5, 6).catch(console.log); // "Promise Rejected"

fn 以回调函数作为第一个参数和 args 作为其余参数进行调用。在回调函数的第二个参数中，接受一个错误消息，因此当调用 fn 时，Promise 被拒绝并携带回调函数中提供的错误消息。请注意，不管将什么作为回调函数的第一个参数传递都无关紧要。
```

**提示：**

- `1 <= args.length <= 100`
- `0 <= args[i] <= 10^4`

## 题解

::: details 点击查看题解

### 思路

整体策略：`promisify` 返回一个新函数，内部 `new Promise`，把「注入的回调」作为 `fn` 的第一个参数、调用方传来的 `args` 展开在后面；原函数拿到回调后同步或异步结算，都能被接住。

**回调约定要特别注意**：本题是「数据在前、错误在后」——`callback(data, error)`，第二个参数有错误就 `reject(error)`，否则 `resolve(data)`。这与 Node.js 生态的「错误优先」`callback(err, data)` 正好相反（旧页 promisify 讲的是 Node 版），照搬 Node 写法必然判错。示例 2 也印证了这一点：第一个参数传什么完全不重要，只要第二个参数带错误就拒绝。

高阶函数 + 闭包注入回调（旧页核心要点）：包装函数被调用的那一刻才创建 Promise 并注入回调，回调里用真值判断错误——本题错误消息是字符串，非空即拒绝；`callback(data)` 只有一个参数时 `error` 为 `undefined`，自然走 resolve。

同步抛错也有兜底：`fn` 若没有调用回调而是直接 `throw`，`new Promise` 的 executor 内同步异常会被 Promise 构造器捕获并转成拒绝，不会把异常漏到调用栈外。

`this` 透传（旧页要点）：返回的函数写成普通函数并用 `fn.call(this, callback, ...args)`，调用方的上下文就原样传给 `fn`；本题判题不涉及 `this`，工程实现建议保留。

回调可能被多次调用：Promise 只认第一次结算，后续调用自动忽略。旧页还有两个可作谈资的延伸：Node 的 `util.promisify` 支持自定义符号 `util.promisify.custom` 定制转换行为；多结果回调（如 `child_process.exec` 的 stdout/stderr）需要收集多个非错误参数的变体——两者都属于 Node 错误优先生态，与本题约定不同。

### 代码实现

```javascript
/**
 * @param {Function} fn
 * @return {Function}
 */
var promisify = function(fn) {
  return function (...args) {
    return new Promise((resolve, reject) => {
      // 注入的回调：数据在前、错误在后（本题约定，与 Node 相反）
      const callback = (data, error) => {
        if (error) reject(error);
        else resolve(data);
      };
      // Promise 构造器会把 executor 内的同步抛错转成拒绝；call 保留调用时的 this
      fn.call(this, callback, ...args);
    });
  };
};
```

### 复杂度分析

- 时间复杂度：O(1)，每次调用只创建一个 Promise 并转发一次回调，与 `args` 长度无关（展开是常数次操作）。
- 空间复杂度：O(1)，闭包保存注入的回调与参数引用。
