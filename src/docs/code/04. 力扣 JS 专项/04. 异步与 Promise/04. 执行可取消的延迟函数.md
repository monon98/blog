# 执行可取消的延迟函数

> 难度：简单 | 标签：定时器、闭包、取消 | LeetCode 2715 · [原题链接](https://leetcode.cn/problems/timeout-cancellation/)

## 题目描述

给定一个函数 `fn`，一个参数数组 `args` 和一个以毫秒为单位的超时时间 `t`，返回一个取消函数 `cancelFn`。

在 `cancelTimeMs` 的延迟后，返回的取消函数 `cancelFn` 将被调用。

```
setTimeout(cancelFn, cancelTimeMs)
```

最初，函数 `fn` 的执行应该延迟 `t` 毫秒。

如果在 `t` 毫秒的延迟之前调用了函数 `cancelFn`，它应该取消 `fn` 的延迟执行。否则，如果在指定的延迟 `t` 内没有调用 `cancelFn`，则应执行 `fn`，并使用提供的 `args` 作为参数。

**示例 1：**

```
输入：fn = (x) => x * 5, args = [2], t = 20
输出：[{"time": 20, "returned": 10}]
解释：
const cancelTimeMs = 50;
const cancelFn = cancellable((x) => x * 5, [2], 20);
setTimeout(cancelFn, cancelTimeMs);

取消操作被安排在延迟了 cancelTimeMs（50毫秒）后进行，这发生在 fn(2) 在 20 毫秒时执行之后。
```

**示例 2：**

```
输入：fn = (x) => x**2, args = [2], t = 100
输出：[]
解释：
const cancelTimeMs = 50;
const cancelFn = cancellable((x) => x**2, [2], 100);
setTimeout(cancelFn, cancelTimeMs);

取消操作被安排在延迟了 cancelTimeMs（50毫秒）后进行，这发生在 fn(2) 在 100 毫秒时执行之前，导致 fn(2) 从未被调用。
```

**示例 3：**

```
输入：fn = (x1, x2) => x1 * x2, args = [2,4], t = 30
输出：[{"time": 30, "returned": 8}]
解释：
const cancelTimeMs = 100;
const cancelFn = cancellable((x1, x2) => x1 * x2, [2,4], 30);
setTimeout(cancelFn, cancelTimeMs);

取消操作被安排在延迟了 cancelTimeMs（100毫秒）后进行，这发生在 fn(2,4) 在 30 毫秒时执行之后。
```

**提示：**

- `fn` 是一个函数
- `args` 是一个有效的 JSON 数组
- `1 <= args.length <= 10`
- `20 <= t <= 1000`
- `10 <= cancelTimeMs <= 1000`

## 题解

::: details 点击查看题解

### 思路

整体策略：先挂 `setTimeout(() => fn(...args), t)` 把 `fn` 的执行推迟 `t` 毫秒，返回的 `cancelFn` 只做一件事——`clearTimeout` 清掉这个尚未触发的定时器，循环/延迟即断。

`fn` 是否执行，完全取决于 `t` 与 `cancelTimeMs` 谁先到：取消更早（示例 2）则 `fn` 从未被调用、输出空数组；取消更晚（示例 1、3）时定时器早已触发，`clearTimeout` 对已执行的定时器只是无害的空操作，`fn` 的执行记录照常保留——所以取消函数无需判断「是否已经执行过」。

题面用 `setTimeout(cancelFn, cancelTimeMs)` 来调用取消函数，这是「延迟取消」的典型写法：两个定时器在赛跑，先到期的那个决定结果。

`args` 在调度时刻就被闭包捕获，`t` 毫秒后展开传入；若 `fn` 依赖调用时的 `this`，需要在 `cancellable` 被调用的那一刻记录并用 `fn.apply` 透传（本题判题不涉及）。

工程要点：组件卸载、页面离开时必须调用 `cancelFn`，否则挂起的回调会在「已销毁」的对象上执行，造成内存泄漏与僵尸回调；`clearTimeout` 是幂等的，重复取消安全。

### 代码实现

```javascript
/**
 * @param {Function} fn
 * @param {Array Arguments} args
 * @param {number} t
 * @return {Function}
 */
var cancellable = function(fn, args, t) {
  // 先安排 t 毫秒后执行 fn
  const timer = setTimeout(() => fn(...args), t);

  return function cancel() {
    // 取消尚未执行的延迟；若已执行则为无害的空操作
    clearTimeout(timer);
  };
};
```

### 复杂度分析

- 时间复杂度：O(1)，注册与取消各一次定时器操作。
- 空间复杂度：O(1)，闭包保存一个定时器句柄与参数数组的引用。
