# 间隔取消

> 难度：简单 | 标签：定时器、闭包、取消 | LeetCode 2725 · [原题链接](https://leetcode.cn/problems/interval-cancellation/)

## 题目描述

现给定一个函数 `fn`，一个参数数组 `args` 和一个时间间隔 `t`，返回一个取消函数 `cancelFn`。

在经过 `cancelTimeMs` 毫秒的延迟后，将调用返回的取消函数 `cancelFn`。

```
setTimeout(cancelFn, cancelTimeMs)
```

函数 `fn` 应立即使用参数 `args` 调用，然后每隔 `t` 毫秒调用一次，直到在 `cancelTimeMs` 毫秒时调用 `cancelFn`。

**示例 1：**

```
输入：fn = (x) => x * 2, args = [4], t = 35, cancelT = 190
输出：
[
   {"time": 0, "returned": 8},
   {"time": 35, "returned": 8},
   {"time": 70, "returned": 8},
   {"time": 105, "returned": 8},
   {"time": 140, "returned": 8},
   {"time": 175, "returned": 8}
]
解释：
const cancelTimeMs = 190;
const cancelFn = cancellable((x) => x * 2, [4], 35);
setTimeout(cancelFn, cancelTimeMs);

每隔 35ms，调用 fn(4)。直到 t=190ms，然后取消。
第一次调用 fn 是在 0ms。fn(4) 返回 8。
第二次调用 fn 是在 35ms。fn(4) 返回 8。
第三次调用 fn 是在 70ms。fn(4) 返回 8。
第四次调用 fn 是在 105ms。fn(4) 返回 8。
第五次调用 fn 是在 140ms。fn(4) 返回 8。
第六次调用 fn 是在 175ms。fn(4) 返回 8。
在 t=190ms 时取消
```

## 题解

::: details 点击查看题解

### 思路

整体策略：立即调用一次 `fn(...args)`（t=0 时刻的记录），随后用 **递归 `setTimeout`** 每隔 `t` 毫秒再调一次，形成 `setTimeout` 链模拟 `setInterval`；返回的 `cancelFn` 只需 `clearTimeout` 清掉链上「尚未触发的那一次」，循环即断。

与原生 `setInterval` 的时序差异（旧页「sleep 与 setInterval」的独有讲解）：原生版按固定间隔触发，`fn` 执行耗时超过 `t` 时后续回调会排队堆叠；`setTimeout` 链要等本轮回调跑完才排下一次，天然不堆叠，代价是「两次执行的间隔 = t + 上次执行耗时」产生漂移。本题 `fn` 同步返回、判题只看调用时刻约等于 0、t、2t…，两种写法等价。

精确计时的追问答案是漂移补偿：每轮用「目标执行时刻 - 实际执行时刻」重算剩余延迟，让长期节奏贴住 0、t、2t… 的理想时间轴。

取消语义要对照示例看：`cancelFn` 在 `cancelTimeMs` 被调用，此时若链上还挂着下一次定时器就清掉（示例 1 里 190ms 取消，本应在 210ms 的第七次调用永远不会发生）；已经发生过的调用则照常留在输出里，取消不影响历史。

工程要点（旧页考察点）：组件卸载、页面离开时必须调用 `cancelFn`，否则僵尸回调在对象销毁后继续执行，造成内存泄漏与报错；`clearTimeout` 幂等，重复取消安全。

### 代码实现

```javascript
/**
 * @param {Function} fn
 * @param {Array Arguments} args
 * @param {number} t
 * @return {Function}
 */
var cancellable = function(fn, args, t) {
  let timer = null;

  function run() {
    fn(...args); // 0ms 的首次调用与后续调用走同一入口
    timer = setTimeout(run, t); // 每轮执行完再排下一次：不堆叠、但会漂移
  }

  run(); // 立即执行第一次

  return function cancel() {
    clearTimeout(timer); // 清掉链上下一次，循环即停
  };
};
```

### 复杂度分析

- 时间复杂度：O(k)，k 为取消前的实际执行次数，约等于 cancelT / t + 1。
- 空间复杂度：O(1)，闭包只保存当前挂起的定时器句柄。
