# 并行执行 Promise 以获取独有的结果

> 难度：中等 | 标签：Promise、并发、错误处理 | LeetCode 2795（VIP 专属题） · [原题链接](https://leetcode.cn/problems/parallel-execution-of-promises-for-individual-results-retrieval/)

## 题目描述

> 本题为 LeetCode VIP 专属题，官方题面需登录后查看，以下为按原题题意整理的版本。

给定一个数组 `functions`，返回一个 promise 对象 `promise`。`functions` 是一个返回 promise 对象 `fnPromise` 的函数数组，每个 `fnPromise` 可以被解析（resolved）或拒绝（rejected）。

- 如果 `fnPromise` 被解析：`obj = { status: "fulfilled", value: 解析的值 }`
- 如果 `fnPromise` 被拒绝：`obj = { status: "rejected", reason: 拒绝的原因（捕获的错误消息）}`

该 `promise` 应该解析为一个包含这些对象 `obj` 的数组。数组中的每个 `obj` 应该对应原始函数数组中的 promise，并保持相同的顺序。

请在不使用内置方法 `Promise.allSettled()` 的情况下实现它。

**示例 1：**

```
输入：functions = [
    () => new Promise(resolve => setTimeout(() => resolve(15), 100))
]
输出：{"t":100,"values":[{"status":"fulfilled","value":15}]}
解释：
const time = performance.now()
const promise = promiseAllSettled(functions);

promise.then(res => {
    const out = {t: Math.floor(performance.now() - time), values: res}
    console.log(out) // {"t":100,"values":[{"status":"fulfilled","value":15}]}
})

返回的 promise 在 100 毫秒内解析。由于函数数组中的 promise 被解析，返回的 promise 的解析值设置为 [{"status":"fulfilled","value":15}]。
```

**示例 2：**

```
输入：functions = [
    () => new Promise(resolve => setTimeout(() => resolve(20), 100)),
    () => new Promise(resolve => setTimeout(() => resolve(15), 100))
]
输出：
{
    "t":100,
    "values": [
        {"status":"fulfilled","value":20},
        {"status":"fulfilled","value":15}
    ]
}
解释：返回的 promise 在 100 毫秒内解析，因为解析时间取决于需要最长时间来解析的 promise。由于函数数组中的 promise 都被解析，返回的 promise 的解析值设置为 [{"status":"fulfilled","value":20},{"status":"fulfilled","value":15}]。
```

**示例 3：**

```
输入：functions = [
    () => new Promise(resolve => setTimeout(() => resolve(30), 200)),
    () => new Promise((resolve, reject) => setTimeout(() => reject("Error"), 100))
]
输出：
{
    "t":200,
    "values": [
        {"status":"fulfilled","value":30},
        {"status":"rejected","reason":"Error"}
    ]
}
解释：返回的 promise 在 200 毫秒内解析，因为解析时间取决于需要最长时间来解析的 promise。由于函数数组中的一个 promise 被解析，另一个被拒绝，返回的 promise 的解析值设置为 [{"status":"fulfilled","value":30},{"status":"rejected","reason":"Error"}]。数组中的每个对象对应原始函数数组中的 promise，并保持相同的顺序。
```

**提示：**

- `1 <= functions.length <= 10`

## 题解

::: details 点击查看题解

### 思路

整体策略是手写一份 `Promise.allSettled`：并行启动每个工厂，给每个 promise 同时挂成功、失败两个回调，把状态对象写回 **原下标**，计数器到齐后 resolve 结果数组。

与 `Promise.all` 的本质差异（旧页「并发控制」讨论过两种失败语义）：`all` 首败即 reject，本题任何失败都 **不能** 让外层 reject——失败被转成 `{ status: "rejected", reason }` 记录，外层 promise 永远 resolve，一个都不能漏。

保序靠下标写入而非完成顺序：示例 3 里 100ms 就完成的 rejected 记录不会排到前面，最终数组严格按输入顺序排列，完成先后只影响写入时机。

用 `Promise.resolve().then(fn)` 启动（旧页 Scheduler 的技巧）：放进微任务调用，工厂同步 `throw` 也会变成一条 rejected 记录，而不是炸掉同步遍历。

用 `settledCount` 计数判断结束最稳，不要用「数组是否被填满」去判断：下标写入在完成顺序上是乱序的，`in` / `length` 对稀疏数组的判断很容易踩坑。

等待语义要对齐示例 3：即使已有任务失败，也要等最慢的那个（200ms 的 fulfilled）结算后才 resolve——「所有任务结算完毕」是 resolve 的前提，失败不会提前收尾。

### 代码实现

```javascript
/**
 * @param {Array<() => Promise<any>>} functions
 * @return {Promise<Array<{status: string, value?: any, reason?: any}>>}
 */
var promiseAllSettled = function(functions) {
  return new Promise((resolve) => {
    const results = new Array(functions.length);
    let settledCount = 0;

    functions.forEach((fn, i) => {
      // 微任务中启动：同步抛错也会变成 rejected 记录
      Promise.resolve()
        .then(fn)
        .then(
          (value) => {
            results[i] = { status: "fulfilled", value };
          },
          (reason) => {
            results[i] = { status: "rejected", reason };
          }
        )
        .then(() => {
          // 无论成败都计一次，全部结算后按输入顺序 resolve
          settledCount++;
          if (settledCount === functions.length) resolve(results);
        });
    });
  });
};
```

### 复杂度分析

- 时间复杂度：O(n)，每个任务注册回调并结算一次，n 为 `functions.length`。
- 空间复杂度：O(n)，结果数组与 n 个 promise 监听链。
