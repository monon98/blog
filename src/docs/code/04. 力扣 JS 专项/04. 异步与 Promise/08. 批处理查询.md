# 批处理查询

> 难度：困难 | 标签：Promise、节流、批处理 | LeetCode 2756（VIP 专属题） · [原题链接](https://leetcode.cn/problems/query-batching/)

## 题目描述

> 本题为 LeetCode VIP 专属题，官方题面需登录后查看，以下为按原题题意整理的版本。

将多个小查询批处理为单个大查询可以是一种有用的优化。请你编写一个名为 `QueryBatcher` 的类来实现这个功能。

它的构造函数应接受两个参数：

- 一个异步函数 `queryMultiple`，它接受一个字符串键数组 `input` 作为输入。它将返回一个与输入数组长度相同的值数组，每个索引对应与 `input[i]` 相关联的值。可以假设该 promise 永远不会被拒绝。
- 一个以毫秒为单位的节流时间 `t`。

该类只有一个方法：

- `async getValue(key)`：接受一个字符串键，并返回一个解析后的字符串值。传递给该函数的键最终都应传递给 `queryMultiple` 函数；`queryMultiple` 不应在 `t` 毫秒内被连续调用。第一次调用 `getValue` 时，应立即使用该单个键调用 `queryMultiple`。如果在 `t` 毫秒之后又调用了 `getValue`，则这期间传入的所有键都应一并传递给 `queryMultiple`，并最终各自返回结果。可以假设传给该方法的每个键都是唯一的。

题面配有一张节流示意图：每个矩形代表 100 毫秒，节流时间为 400 毫秒——同一节流窗口内陆续到来的多个键会被合并成一次 `queryMultiple` 调用。

**示例 1：**

```
输入：
queryMultiple = async function(keys) {
  return keys.map(key => key + '!');
}
t = 100
calls = [
  {"key": "a", "time": 10},
  {"key": "b", "time": 20},
  {"key": "c", "time": 30}
]
输出：[
  {"resolved": "a!", "time": 10},
  {"resolved": "b!", "time": 110},
  {"resolved": "c!", "time": 110}
]
解释：
const batcher = new QueryBatcher(queryMultiple, 100);
setTimeout(() => batcher.getValue('a'), 10); // "a!" at t=10ms
setTimeout(() => batcher.getValue('b'), 20); // "b!" at t=110ms
setTimeout(() => batcher.getValue('c'), 30); // "c!" at t=110ms

queryMultiple 简单地给键添加了 "!"。
在 t=10ms 时，调用 getValue('a')，立即调用 queryMultiple(['a']) 并立即返回结果。
在 t=20ms 时，调用 getValue('b')，但查询需要排队等待。
在 t=30ms 时，调用 getValue('c')，但查询需要排队等待。
在 t=110ms 时，调用 queryMultiple(['b', 'c']) 并立即返回结果。
```

**示例 2：**

```
输入：
queryMultiple = async function(keys) {
  await new Promise(res => setTimeout(res, 100));
  return keys.map(key => key + '!');
}
t = 100
calls = [
  {"key": "a", "time": 10},

```
输入：
queryMultiple = async function(keys) {

  {"key": "a", "time": 10},
  {"key": "b", "time": 20},

**提示：**

- `0 <= t <= 1000`
- `0 <= calls.length <= 10`
- `1 <= key.length <= 100`
- 所有的键都是唯一的

## 题解

::: details 点击查看题解

### 思路

整体策略是「记录上次发送时刻」的节流：维护 `lastCallTime`（上一次真正调用 `queryMultiple` 的时刻）。`getValue` 被调用时，如果距上次发送已满 `t` 毫秒且没有积压，就立即用这个单键发出去（首次调用时 `lastCallTime` 为负无穷，必走这条，满足「第一次立即查询」）；否则入队等待批量发送。

批量发送的 **触发时刻由上次发送决定**，而不是由键到达时刻决定：入队时若还没排定时器，就挂一个 `lastCallTime + t - now` 毫秒后的 `flush`。示例 1 里 b、c 分别在 20、30ms 到达，却在 110ms（= 上次发送 10ms + 节流 100ms）一起发出，就是这个公式的结果。

`flush` 把当前队列整体取走、更新 `lastCallTime` 为当前时刻，再用收集到的键数组调用 `queryMultiple`，最后按下标把返回值分配给每个等待者——排队时每个 `getValue` 都保存了自己的 `resolve`，返回值数组第 i 项正对应第 i 个键，这是「每个 key 拿到自己的值」的关键。

节流只看 **调用时刻** 的间隔，不看 `queryMultiple` 何时 resolve：示例 3 中 b、c、d 的查询 110ms 发出、410ms 才返回，但 e 在 250ms 到达时距上次发送已有 140ms，于是立即单发并在 350ms 返回，与仍在途的批量查询并行不冲突。

立即路径的条件要同时检查「队列为空」：`setTimeout` 可能晚触发，若新键到达时队列里还压着未发的键，必须走入队分支并入同一批，否则会插队造成两次调用间隔小于 `t`。

边界：`flush` 取到空队列直接返回；键保证唯一，无需去重；`queryMultiple` 保证不 reject，故不必处理失败分支。

### 代码实现

```javascript
class QueryBatcher {
  constructor(queryMultiple, t) {
    this.queryMultiple = queryMultiple;
    this.t = t;
    this.lastCallTime = -Infinity; // 上一次调用 queryMultiple 的时刻（首调视为早已过窗）
    this.queue = []; // 待批量发送的 { key, resolve }
    this.timer = null; // 窗口结束时的批量发送定时器
  }

  async getValue(key) {
    const now = Date.now();
    // 距上次调用已满 t 且没有积压：立即用单键发起
    if (this.queue.length === 0 && now - this.lastCallTime >= this.t) {
      this.lastCallTime = now;
      const values = await this.queryMultiple([key]);
      return values[0];
    }
    // 否则入队，等窗口结束统一发送
    return new Promise((resolve) => {
      this.queue.push({ key, resolve });
      this.scheduleFlush();
    });
  }

  scheduleFlush() {
    if (this.timer !== null) return; // 已排过，等它触发即可
    // 窗口结束时刻 = 上次发送时刻 + t
    const delay = Math.max(0, this.lastCallTime + this.t - Date.now());
    this.timer = setTimeout(() => this.flush(), delay);
  }

  async flush() {
    this.timer = null;
    const batch = this.queue.splice(0); // 一次取走全部等待者
    if (batch.length === 0) return;
    this.lastCallTime = Date.now(); // 记录本次调用时刻，供后续节流判断
    const values = await this.queryMultiple(batch.map((item) => item.key));
    // 按下标把各自的值交回每个 getValue
    batch.forEach((item, i) => item.resolve(values[i]));
  }
}
```

### 复杂度分析

- 时间复杂度：O(k)，k 为 `getValue` 调用次数，每个键至多入队、出队各一次。
- 空间复杂度：O(k)，队列最多同时积压一个窗口内到达的键与它们的 resolve。
