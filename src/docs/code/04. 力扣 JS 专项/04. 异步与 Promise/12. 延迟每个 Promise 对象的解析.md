# 延迟每个 Promise 对象的解析

> 难度：中等 | 标签：Promise、定时器 | LeetCode 2821（VIP 专属题） · [原题链接](https://leetcode.cn/problems/delay-the-resolution-of-each-promise/)

## 题目描述

> 本题为 LeetCode VIP 专属题，官方题面需登录后查看，以下为按原题题意整理的版本。

给定一个函数数组 `functions` 和一个数字 `ms`，返回一个新的函数数组。

- `functions` 是一个返回 Promise 对象的函数数组。
- `ms` 表示延迟的时间，以毫秒为单位。它决定了新数组中的每个函数返回的 Promise 在解析之前要等待的时间。

新数组中的每个函数应该返回一个 Promise 对象，在额外延迟 `ms` 毫秒后解析或拒绝，并保持与原始 `functions` 数组相同的顺序。`delayAll` 函数应确保 `functions` 中的每个函数都被延迟执行，形成返回延迟 Promise 的新函数数组。

**示例 1：**

```
输入：
functions = [
  () => new Promise((resolve) => setTimeout(resolve, 30))
],
ms = 50
输出：[80]
解释：数组中的 Promise 本应在 30 毫秒后解析，但被延迟了 50 毫秒，所以总共 30 毫秒 + 50 毫秒 = 80 毫秒。
```

**示例 2：**

```
输入：
functions = [
  () => new Promise((resolve) => setTimeout(resolve, 50)),
  () => new Promise((resolve) => setTimeout(resolve, 80))
],
ms = 70
输出：[120,150]
解释：数组中的 Promise 分别本应在 50 毫秒和 80 毫秒后解析，但它们被延迟了 70 毫秒，所以总共 50 毫秒 + 70 毫秒 = 120 毫秒 和 80 毫秒 + 70 毫秒 = 150 毫秒。
```

**示例 3：**

```
输入：
functions = [
  () => new Promise((resolve, reject) => setTimeout(reject, 20)),
  () => new Promise((resolve, reject) => setTimeout(reject, 100))
],
ms = 30
输出：[50,130]
```

**提示：**

- `functions` 是一个返回 Promise 对象的函数数组
- `10 <= ms <= 500`
- `1 <= functions.length <= 10`

## 题解

::: details 点击查看题解

### 思路

整体策略：用 `map` 生成新函数数组，每个包装器都是 async 函数——先 `await` 一个 `ms` 毫秒的定时器，再调用原函数并把它返回的 promise 交出去。

时间账是 `ms + 原有耗时`：原函数在 `ms` 之后才启动，所以总解析时刻 = 等待 + 自身耗时（示例 1：50 + 30 = 80；示例 2：70 + 50 = 120、70 + 80 = 150）。

拒绝同样被延迟且原样透传（示例 3）：`await` 定时器之后 `return fn()`，async 函数会把原 promise 的拒绝原因原封不动地转交，20 + 30 = 50、100 + 30 = 130。

关键在 **写在调用 fn 之前** 的那句 `await`——这正对应题面「每个函数都被延迟执行」。另一种写法是「延迟结算」：立即调用 `fn`，在其结果上再挂一个 `ms` 的延迟；由于所有包装器同时开始、并行执行，两种写法的可观察时间恰好相同，都能通过判题，但题面措辞是延迟执行，取前者更贴题。

每个包装器的定时器彼此独立、同时起跑，顺序由 `map` 天然保持；如果把等待写成串行（等前一个完成再开始下一个），示例 2 的第二个结果会被拖到 50 + 70 + 80 = 200ms，与题面不符。

### 代码实现

```javascript
/**
 * @param {Array<() => Promise<any>>} functions
 * @param {number} ms
 * @return {Array<() => Promise<any>>}
 */
var delayAll = function(functions, ms) {
  return functions.map((fn) => async function() {
    // 先等 ms 毫秒再启动原函数：各包装器同时开始等待，互不拖累
    await new Promise((resolve) => setTimeout(resolve, ms));
    return fn(); // 原 promise 的解析/拒绝原样透传
  });
};
```

### 复杂度分析

- 时间复杂度：O(n)，生成 n 个包装器各一次；运行期每个包装器注册一个定时器，n 为 `functions.length`。
- 空间复杂度：O(n)，新函数数组与运行期 n 个定时器。
