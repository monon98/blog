# 自定义间隔

> 难度：中等 | 标签：定时器、闭包、取消 | LeetCode 2805（VIP 专属题） · [原题链接](https://leetcode.cn/problems/custom-interval/)

## 题目描述

> 本题为 LeetCode VIP 专属题，官方题面需登录后查看，以下为按原题题意整理的版本。

**函数 `customInterval`**

给定一个函数 `fn`、一个数字 `delay` 和一个数字 `period`，返回一个数字 `id`。`customInterval` 是一个函数，它应该根据公式 `delay + period * count` 在间隔中执行提供的函数 `fn`，公式中的 `count` 表示从初始值 0 开始、该间隔已经执行的次数。

**函数 `customClearInterval`**

给定 `id`，`id` 是 `customInterval` 的返回值。`customClearInterval` 应该停止按间隔执行提供的函数 `fn`。

**注意：** 在 Node.js 中，`setTimeout` 和 `setInterval` 函数返回一个对象，而不是一个数字。

**示例 1：**

```
输入：delay = 50, period = 20, stopTime = 225
输出：[50,120,210]
解释：
const t = performance.now()
const result = []

const fn = () => {
    result.push(Math.floor(performance.now() - t))
}
const id = customInterval(fn, delay, period)

setTimeout(() => {
    customClearInterval(id)
}, 225)

50 + 20 * 0 = 50 // 50ms - 第一个函数调用
50 + 20 * 1 = 70 // 50ms + 70ms = 120ms - 第二个函数调用
50 + 20 * 2 = 90 // 50ms + 70ms + 90ms = 210ms - 第三个函数调用
```

**示例 2：**

```
输入：delay = 20, period = 20, stopTime = 150
输出：[20,60,120]
解释：
20 + 20 * 0 = 20 // 20ms - 第一个函数调用
20 + 20 * 1 = 40 // 20ms + 40ms = 60ms - 第二个函数调用
20 + 20 * 2 = 60 // 20ms + 40ms + 60ms = 120ms - 第三个函数调用
```

**示例 3：**

```
输入：delay = 100, period = 200, stopTime = 500
输出：[100,400]
解释：
100 + 200 * 0 = 100 // 100ms - 第一个函数调用
100 + 200 * 1 = 300 // 100ms + 300ms = 400ms - 第二个函数调用
```

**提示：**

- `20 <= delay, period <= 250`
- `20 <= stopTime <= 1000`

## 题解

::: details 点击查看题解

### 思路

第 k 次执行前的等待时长是 `delay + period * k`（k 为已执行次数，从 0 起），间隔在逐次变长，所以固定间隔的 `setInterval` 根本用不了，只能 **递归 `setTimeout`**：每轮回调里 `count++`，再用 `delay + period * count` 排下一次。对照示例 1：等待 50 → 70 → 90，累计就是 50、120、210 三次调用时刻。

这与旧页「用 setTimeout 递归模拟 setInterval」的骨架完全相同——本题只是把「下一次的延迟」从常量参数化成了线性递增公式；同样地，执行完才排下一次，天然不堆叠回调，代价是实际间隔 = 公式延迟 + `fn` 执行耗时的漂移（`fn` 极快时可忽略，判题用 `performance.now()` 宽松比对）。

`id` 必须是 **数字**：题面特意提醒 Node 的定时器句柄是对象，不能直接把 `setTimeout` 的返回值当 id。用自增计数器造数字 id，把 `id → 句柄` 存进模块级的 Map 即可。

`customClearInterval` 按 id 从 Map 取句柄、`clearTimeout` 并删除条目；Map 里每轮都用最新的句柄覆盖，保证任意时刻取消都能清掉「还在排队的那一次」。取不到 id 直接返回，重复取消因此天然幂等。

边界：`fn` 抛错会中断「执行完再排下一次」的链条，健壮版可把 `fn()` 包进 try/catch 后继续排程（本题判题不会触发）；工程上组件卸载时必须调用 `customClearInterval`，否则僵尸回调持续执行造成泄漏——这与旧页 setInterval 的清理要点一致。

### 代码实现

```javascript
const intervalTimers = new Map(); // id(数字) → 最近一次的定时器句柄
let nextId = 1; // 自增生成数字 id（Node 的定时器句柄是对象，不能直接用）

/**
 * @param {Function} fn
 * @param {number} delay
 * @param {number} period
 * @return {number}
 */
function customInterval(fn, delay, period) {
  const id = nextId++;
  let count = 0; // 已执行次数，决定下一次的等待时长

  function schedule() {
    const timer = setTimeout(() => {
      fn();
      count++;
      schedule(); // 下一次等待 = delay + period * count
    }, delay + period * count);
    intervalTimers.set(id, timer); // 每轮覆盖，保证任意时刻都能取消
  }

  schedule();
  return id;
}

/**
 * @param {number} id
 */
function customClearInterval(id) {
  const timer = intervalTimers.get(id);
  if (timer === undefined) return; // 重复取消直接忽略
  clearTimeout(timer);
  intervalTimers.delete(id);
}
```

### 复杂度分析

- 时间复杂度：O(m)，m 为停止前的实际执行次数，每轮只做一次定时器注册与一次 Map 写入。
- 空间复杂度：O(a)，a 为同时存活的自定义间隔数量，每个占用一个 Map 条目与一个定时器句柄。
