# 睡眠函数

> 难度：简单 | 标签：Promise、定时器 | LeetCode 2621 · [原题链接](https://leetcode.cn/problems/sleep/)

## 题目描述

请你编写一个异步函数，它接收一个正整数参数 `millis`，并休眠 `millis` 毫秒。要求此函数可以解析任何值。

**请注意**，实际睡眠持续时间与 `millis` 之间的微小偏差是可以接受的。

**示例 1：**

```
输入：millis = 100
输出：100
解释：
在 100ms 后此异步函数执行完时返回一个 Promise 对象
let t = Date.now();
sleep(100).then(() => {
  console.log(Date.now() - t); // 100
});
```

**示例 2：**

```
输入：millis = 200
输出：200
解释：在 200ms 后函数执行完时返回一个 Promise 对象
```

**提示：**

- `1 <= millis <= 1000`

## 题解

::: details 点击查看题解

### 思路

整体策略就一行：把回调式的 `setTimeout` 包成 Promise——`new Promise((resolve) => setTimeout(resolve, millis))`，这是「回调 API Promise 化」的最小范例，也是 async/await 生态的基石技巧。

`setTimeout` 到点后调用不带参数的 `resolve()`，解析值是 `undefined`，正好满足「可以解析任何值」；调用方 `await` 之后拿到什么并不关心，只关心「停了 millis 毫秒」再继续。

不能用 `while (Date.now() - start < millis) {}` 忙等：那会把主线程卡死；定时器把控制权交还事件循环，等待期间页面照常响应，这才是「异步睡眠」和「同步阻塞」的本质区别。

题面特意说明「微小偏差可接受」：`setTimeout` 的最小延迟（嵌套定时器常被钳到 4ms）、事件循环排队、后台标签页节流都会让实际时长略大于 `millis`，所以判题用的是宽松阈值而非精确相等。

工程里常给 sleep 加可取消版本（挂起期间能被中断），思路见本分类的「执行可取消的延迟函数」。

### 代码实现

```javascript
/**
 * @param {number} millis
 * @return {Promise}
 */
const sleep = async (millis) => {
  // 把回调式定时器包装成 Promise：到点 resolve，await 之后函数自然返回 undefined
  await new Promise((resolve) => setTimeout(resolve, millis));
};
```

### 复杂度分析

- 时间复杂度：O(1)，同步部分只注册一个定时器，真实耗时由 `millis` 决定，不随输入规模增长。
- 空间复杂度：O(1)，只创建一个 Promise 对象。
