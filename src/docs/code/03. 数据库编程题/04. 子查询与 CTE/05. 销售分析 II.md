# 销售分析 II

> 难度：简单 | 标签：多表连接、NOT EXISTS、子查询 | [LeetCode 原题](https://leetcode.cn/problems/sales-analysis-ii/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

`Product` 表：

```
+--------------+---------+
| Column Name  | Type    |
+--------------+---------+
| product_id   | int     |
| product_name | varchar |
| unit_price   | int     |
+--------------+---------+
product_id 是该表的主键。
每一行表示一个产品的编号、名称与单价。
```

`Sales` 表：

```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| seller_id   | int     |
| product_id  | int     |
| buyer_id    | int     |
| sale_date   | date    |
| quantity    | int     |
| price       | int     |
+-------------+---------+
该表没有主键，可能存在重复行。
product_id 是 Product 表的外键。
每一行代表一次销售：哪个卖家把哪个产品卖给了哪个买家。
```

编写一个 SQL 查询，报告 **购买了产品 “S8” 但没有购买任何其他产品** 的买家 id（`buyer_id`）。

结果可以按任意顺序返回。

**示例 1：**

```
输入：
Product 表：
+------------+--------------+------------+
| product_id | product_name | unit_price |
+------------+--------------+------------+
| 1          | S8           | 1000       |
| 2          | G4           | 800        |
| 3          | iPhone       | 1400       |
+------------+--------------+------------+
Sales 表：
+-----------+------------+----------+------------+----------+-------+
| seller_id | product_id | buyer_id | sale_date  | quantity | price |
+-----------+------------+----------+------------+----------+-------+
| 1         | 1          | 1        | 2019-01-21 | 2        | 2000  |
| 1         | 2          | 2        | 2019-02-17 | 1        | 800   |
| 2         | 1          | 3        | 2019-06-02 | 1        | 800   |
| 3         | 3          | 3        | 2019-05-13 | 2        | 2800  |
+-----------+------------+----------+------------+----------+-------+
输出：
+----------+
| buyer_id |
+----------+
| 1        |
+----------+
解释：
买家 1 只买过 S8，符合条件。
买家 2 只买过 G4，没有买过 S8，不符合条件。
买家 3 既买了 S8 又买了 iPhone，不符合「没有购买其他产品」的要求。
```

## 题解

::: details 点击查看题解

### 思路

条件分成两半：**必须买过 S8**，且**不能买过 S8 以外的任何产品**。前半句用一次 `JOIN Product` 过滤 `product_name = 'S8'` 即可；后半句适合用 `NOT EXISTS` 表达——对每个候选买家，检查是否存在一条属于他的、产品名不等于 S8 的订单，存在就排除。

之所以推荐 `NOT EXISTS` 而不是 `NOT IN`，是因为 `NOT IN` 在子查询结果含 `NULL` 时会整体返回 `UNKNOWN`，导致一行都查不出来，这是 SQL 里最经典的坑之一；`NOT EXISTS` 只关心子查询是否返回行，不受 `NULL` 影响。

还有一个细节：同一个买家可能有多条 S8 订单，`SELECT buyer_id` 必须加 `DISTINCT`，否则买家 1 会被重复输出。另外「没有购买其他产品」比较的是产品名而不是 `product_id`，如果一个产品被改名或存在同名不同 id 的情况，应当以题目语义（产品名）为准；本题 `Product.product_id` 是主键，两种写法结果一致。

替代写法：先按 `buyer_id` 聚合，用 `MAX(product_name = 'S8') = 1 AND MAX(product_name <> 'S8') = 0` 判断，一次分组就能得出结论，数据量大时通常比相关子查询更快。

### SQL 实现

```sql
SELECT DISTINCT s.buyer_id
FROM Sales s
JOIN Product p
    ON p.product_id = s.product_id
WHERE p.product_name = 'S8'
  AND NOT EXISTS (
      SELECT 1
      FROM Sales s2
      JOIN Product p2
          ON p2.product_id = s2.product_id
      WHERE s2.buyer_id = s.buyer_id
        AND p2.product_name <> 'S8'
  )
ORDER BY s.buyer_id;
```

### 复杂度分析

- 时间复杂度：O(n × m) 的最坏形态来自相关子查询，实际有索引时接近 O(n)；n 为销售记录数。
- 空间复杂度：O(1)，除结果集外只用到常量级临时空间。

:::
