# 向公司 CEO 汇报工作的所有人

> 难度：中等 | 标签：递归 CTE、自连接、层级查询 | [LeetCode 原题](https://leetcode.cn/problems/all-people-report-to-the-given-manager/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

`Employees` 表：

```
+---------------+---------+
| Column Name   | Type    |
+---------------+---------+
| employee_id   | int     |
| employee_name | varchar |
| manager_id    | int     |
+---------------+---------+
employee_id 是该表的主键。
manager_id 是该员工直属上级的 employee_id。
公司的 CEO 是 employee_id = 1 的员工（CEO 的 manager_id 也记为 1）。
```

编写一个 SQL 查询，报告 **所有直接或间接向 CEO 汇报工作的员工** 的 `employee_id`，不包含 CEO 本人。

- 「直接或间接」指沿 `manager_id` 逐级向上，最终能走到 `employee_id = 1`；
- 只报告员工 id，列名为 `employee_id`，顺序不限。

**示例 1：**

```
输入：
Employees 表：
+-------------+---------------+------------+
| employee_id | employee_name | manager_id |
+-------------+---------------+------------+
| 1           | Boss          | 1          |
| 3           | Alice         | 3          |
| 2           | Bob           | 1          |
| 4           | Daniel        | 2          |
| 7           | Luis          | 4          |
| 8           | John          | 3          |
| 9           | Angela        | 8          |
| 77          | Robert        | 1          |
+-------------+---------------+------------+
输出：
+-------------+
| employee_id |
+-------------+
| 2           |
| 4           |
| 7           |
| 77          |
+-------------+
解释：
Bob(2)、Robert(77) 直接向 CEO 汇报；
Daniel(4) 向 Bob 汇报、Luis(7) 向 Daniel 汇报，属于间接汇报。
Alice(3) 的 manager_id 是 3（自己管自己），John(8) 向 Alice 汇报、Angela(9) 向 John 汇报，
这条链始终走不到 CEO，因此都不计入结果。
```

## 题解

::: details 点击查看题解

### 思路

组织机构是一棵树（或森林），要求的是「以 CEO 为根的子树里除根以外的所有节点」，这类逐层展开的查询正是递归 CTE 的典型场景。

递归 CTE 分两部分：锚点成员 `SELECT ... WHERE manager_id = 1 AND employee_id <> 1` 取出 CEO 的直接下属（`employee_id <> 1` 是为了排除 CEO 自己，因为 CEO 的 `manager_id` 也是 1）；递归成员把 `Employees` 与上一轮的 `subordinates` 按 `e.manager_id = s.employee_id` 连接，得到下一层。两部分用 `UNION` 连接，MySQL 8 的递归 CTE 支持 `UNION`（去重）与 `UNION ALL`。

这里特意用 `UNION` 而非 `UNION ALL`：示例中 Alice 的 `manager_id` 指向自己，形成了一个自环。自环本身不在 CEO 子树内，不会被访问到；但如果数据里某个 CEO 下属也出现类似的自环或环，`UNION ALL` 会让递归无限进行，而 `UNION` 的去重能让环上的节点只出现一次，从而安全终止。这也是「递归 CTE 一定要考虑环」的实践要点。

易错点：一是锚点里必须排除 CEO 本人；二是递归成员的连接方向不能反，应是子节点的 `manager_id` 等于父节点的 `employee_id`；三是 `cte_max_recursion_depth` 默认 1000 层，组织层级极深时需要调大；四是最后建议 `DISTINCT` 去重并按 id 排序，输出更稳定。

### SQL 实现

```sql
WITH RECURSIVE subordinates AS (
    SELECT employee_id
    FROM Employees
    WHERE manager_id = 1
      AND employee_id <> 1
    UNION
    SELECT e.employee_id
    FROM Employees e
    JOIN subordinates s
        ON e.manager_id = s.employee_id
)
SELECT DISTINCT employee_id
FROM subordinates
ORDER BY employee_id;
```

### 复杂度分析

- 时间复杂度：O(n)，n 为员工数，每个节点最多被访问一次（`UNION` 去重保证）。
- 空间复杂度：O(n)，递归 CTE 需要保存已展开的层级结果。
