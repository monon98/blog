# 购买了产品 A 和产品 B 却没有购买产品 C 的顾客

> 难度：中等 | 标签：EXISTS 子查询、多条件过滤 | [LeetCode 原题](https://leetcode.cn/problems/customers-who-bought-products-a-and-b-but-not-c/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

`Customers` 表：

```
+---------------+---------+
| Column Name   | Type    |
+---------------+---------+
| customer_id   | int     |
| customer_name | varchar |
+---------------+---------+
customer_id 是该表的主键。
每一行表示一个顾客的 id 与姓名。
```

`Orders` 表：

```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| order_id    | int     |
| customer_id | int     |
| product_name| varchar |
+-------------+---------+
order_id 是该表的主键。
每一行表示某个顾客购买了一个产品，product_name 为产品名称（如 'A'、'B'、'C'、'D'）。
同一顾客可以有多条订单。
```

编写一个 SQL 查询，报告 **购买了产品 A 和产品 B、但没有购买产品 C** 的顾客的 `customer_id` 与 `customer_name`。

结果可以按任意顺序返回。

**示例 1：**

```
输入：
Customers 表：
+-------------+---------------+
| customer_id | customer_name |
+-------------+---------------+
| 1           | Daniel        |
| 2           | Diana         |
| 3           | Elizabeth     |
| 4           | Jhon          |
+-------------+---------------+
Orders 表：
+----------+-------------+--------------+
| order_id | customer_id | product_name |
+----------+-------------+--------------+
| 10       | 1           | A            |
| 20       | 1           | B            |
| 30       | 1           | D            |
| 40       | 1           | C            |
| 50       | 2           | A            |
| 60       | 3           | A            |
| 70       | 3           | B            |
| 80       | 3           | D            |
| 90       | 4           | C            |
+----------+-------------+--------------+
输出：
+-------------+---------------+
| customer_id | customer_name |
+-------------+---------------+
| 3           | Elizabeth     |
+-------------+---------------+
解释：
顾客 1 买过 A、B，但也买过 C，不符合；
顾客 2 只买过 A，没有买 B，不符合；
顾客 3 买过 A 和 B，且没有买过 C，符合；
顾客 4 只买过 C，不符合。
```

## 题解

::: details 点击查看题解

### 思路

三个条件本质上都是「存在性」判断：存在一条 A 订单、存在一条 B 订单、不存在任何 C 订单。用三个 `EXISTS` / `NOT EXISTS` 相关子查询表达最贴合语义，而且每个子查询一旦命中（或对于 `NOT EXISTS` 一旦找到反例）就能提前结束，不必把整张 `Orders` 扫完。

把 `Customers` 作为主表很关键：题目要求输出顾客 id 与姓名，而且「没有购买 C」的顾客理论上可能一条订单都没有；如果从 `Orders` 出发再 `JOIN Customers`，需要额外去重，逻辑也更绕。

易错点：一是只写 `product_name = 'A' AND product_name = 'B'` 这样的条件放在同一个子查询里必然为空，因为一行订单只能对应一个产品名——必须拆成独立的 `EXISTS`；二是「没有购买 C」要用 `NOT EXISTS`（或 `NOT IN` 加 `NULL` 处理），不能写成 `product_name <> 'C'`，那样只要顾客还买过别的产品就会被误判为符合；三是同一顾客可能重复购买同一产品，`EXISTS` 天然去重，无需 `DISTINCT`。

替代写法：按 `customer_id` 分组后用条件聚合 `HAVING SUM(product_name = 'A') > 0 AND SUM(product_name = 'B') > 0 AND SUM(product_name = 'C') = 0`，一次扫描即可，数据量大时往往比多次相关子查询更快，但需要再连接 `Customers` 取姓名。

### SQL 实现

```sql
SELECT c.customer_id,
       c.customer_name
FROM Customers c
WHERE EXISTS (
        SELECT 1
        FROM Orders o
        WHERE o.customer_id = c.customer_id
          AND o.product_name = 'A'
      )
  AND EXISTS (
        SELECT 1
        FROM Orders o
        WHERE o.customer_id = c.customer_id
          AND o.product_name = 'B'
      )
  AND NOT EXISTS (
        SELECT 1
        FROM Orders o
        WHERE o.customer_id = c.customer_id
          AND o.product_name = 'C'
      )
ORDER BY c.customer_id;
```

### 复杂度分析

- 时间复杂度：O(c × n) 的最坏形态（c 为顾客数、n 为订单数），有 `customer_id` 索引时接近 O(c + n)。
- 空间复杂度：O(1)，除结果集外只用到常量级临时空间。

:::
