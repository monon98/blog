# 可疑银行账户

> 难度：中等 | 标签：CTE、分组聚合、日期函数 | [LeetCode 原题](https://leetcode.cn/problems/suspicious-bank-accounts/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

表：`Accounts`

```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| account_id  | int     |
| max_income  | int     |
+-------------+---------+
```

`account_id` 是该表唯一列，每行给出一个账户的月收入上限。

表：`Transactions`

```
+----------------+----------+
| Column Name    | Type     |
+----------------+----------+
| transaction_id | int      |
| account_id     | int      |
| type           | enum     |
| amount         | int      |
| day            | datetime |
+----------------+----------+
```

`transaction_id` 是该表唯一列；`type` 取值为 `('creditor', 'debtor')`，`'creditor'` 表示存入，`'debtor'` 表示取出；`amount` 是金额。

若一个账户在**连续两个及以上月份**中，**每个月的总收入**都超过 `max_income`，则该账户被视为**可疑**。某月的总收入只统计该月 `type = 'creditor'` 的金额之和（`debtor` 不计入收入）。

请写一个解决方案，报告所有可疑账户的 `account_id`，顺序任意。

**示例 1：**

```
输入：
Accounts 表：
+------------+------------+
| account_id | max_income |
+------------+------------+
| 3          | 21000      |
| 4          | 10400      |
+------------+------------+
Transactions 表：
+----------------+------------+----------+--------+---------------------+
| transaction_id | account_id | type     | amount | day                 |
+----------------+------------+----------+--------+---------------------+
| 2              | 3          | Creditor | 107100 | 2021-06-02 11:38:14 |
| 4              | 4          | Creditor | 10400  | 2021-06-20 12:39:18 |
| 11             | 4          | Debtor   | 58800  | 2021-07-23 12:41:55 |
| 1              | 4          | Creditor | 49300  | 2021-05-03 16:11:04 |
| 15             | 3          | Debtor   | 75500  | 2021-05-23 14:40:20 |
| 10             | 3          | Creditor | 102100 | 2021-06-15 10:37:16 |
| 14             | 4          | Creditor | 56300  | 2021-07-21 12:12:25 |
| 19             | 4          | Debtor   | 101100 | 2021-05-09 15:21:49 |
| 8              | 3          | Creditor | 64900  | 2021-07-26 15:09:56 |
| 7              | 3          | Creditor | 90900  | 2021-06-14 11:23:07 |
+----------------+------------+----------+--------+---------------------+
输出：
+------------+
| account_id |
+------------+
| 3          |
+------------+
```

解释：账户 3 在 2021 年 6 月收入 107100 + 102100 + 90900 = 300100，7 月收入 64900，连续两个月都超过 21000，因此可疑；账户 4 在 5 月收入 49300、7 月收入 56300 都超限，但 6 月只有 10400 没超，没有出现「连续两个月都超」的情况，因此不可疑。

## 题解

::: details 点击查看题解

### 思路

分三步：先按 (账户, 月份) 汇总当月 `creditor` 收入；再把收入超过该账户 `max_income` 的月份取出来当作「超限月份」；最后在这些超限月份里找是否存在相邻两个月。

本题最大的坑在于判断口径：不是「相邻两个月收入之和超限」，而是「相邻两个月**各自**都超限」。账户 4 就是反例——5 月和 7 月都超，但 6 月没超，若误写成两个月求和再比较，就会把 4 也报出来。所以一定要先把每个月单独打上超限标记，再做相邻匹配。

月份归一用 `DATE_FORMAT(day, '%Y-%m-01')` 得到月初日期，相邻判断用 `DATE_ADD(..., INTERVAL 1 MONTH)`，跨年（12 月到次年 1 月）也不会出错；不要用 `%Y%m` 拼整数再加 1，那样 202112 会变成 202113。

### SQL 实现

```sql
WITH monthly AS (
    SELECT
        account_id,
        DATE_FORMAT(day, '%Y-%m-01') AS month_start,
        SUM(amount) AS income
    FROM Transactions
    WHERE type = 'creditor'
    GROUP BY account_id, DATE_FORMAT(day, '%Y-%m-01')
),
over_limit AS (
    SELECT m.account_id, m.month_start
    FROM monthly AS m
    JOIN Accounts AS a ON a.account_id = m.account_id
    WHERE m.income > a.max_income
)
SELECT DISTINCT o1.account_id
FROM over_limit AS o1
JOIN over_limit AS o2
  ON o2.account_id = o1.account_id
 AND o2.month_start = DATE_ADD(o1.month_start, INTERVAL 1 MONTH)
ORDER BY o1.account_id;
```

### 复杂度分析

- 时间复杂度：O(n log n)，主要为按月分组（排序或哈希聚合）以及超限月份集合的自连接；月份数量远小于交易数，自连接开销很小。
- 空间复杂度：O(m)，m 为「账户 × 月份」的组合数，用于存放 CTE 结果。
