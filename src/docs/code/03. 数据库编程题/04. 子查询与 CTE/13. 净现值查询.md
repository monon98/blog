# 净现值查询

> 难度：简单 | 标签：多表连接、LEFT JOIN | [LeetCode 原题](https://leetcode.cn/problems/npv-queries/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

`NPV` 表：

```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| id          | int     |
| year        | int     |
| npv         | int     |
+-------------+---------+
(id, year) 是该表的主键。
每一行记录某个项目在某一年的净现值（npv）。
```

`Queries` 表：

```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| id          | int     |
| year        | int     |
+-------------+---------+
(id, year) 是该表的主键。
每一行是一次查询：项目 id 在该年份的净现值是多少。
```

编写一个 SQL 查询，对 `Queries` 中的每一次查询，返回对应项目在该年份的 `npv`；如果 `NPV` 表中没有匹配的记录，则 `npv` 返回 `NULL`。

返回列：`id`、`year`、`npv`，顺序不限。

**示例 1：**

```
输入：
NPV 表：
+----+------+-----+
| id | year | npv |
+----+------+-----+
| 1  | 2018 | 100 |
| 7  | 2020 | 30  |
| 13 | 2019 | 40  |
| 1  | 2019 | 113 |
| 2  | 2008 | 121 |
| 3  | 2009 | 21  |
| 11 | 2020 | 99  |
| 7  | 2019 | 0   |
+----+------+-----+
Queries 表：
+----+------+
| id | year |
+----+------+
| 1  | 2019 |
| 2  | 2008 |
| 3  | 2009 |
| 7  | 2018 |
| 7  | 2019 |
| 7  | 2020 |
| 13 | 2019 |
+----+------+
输出：
+----+------+------+
| id | year | npv  |
+----+------+------+
| 1  | 2019 | 113  |
| 2  | 2008 | 121  |
| 3  | 2009 | 21   |
| 7  | 2018 | NULL |
| 7  | 2019 | 0    |
| 7  | 2020 | 30   |
| 13 | 2019 | 40   |
+----+------+------+
解释：
查询 (7, 2018) 在 NPV 表中没有对应记录，因此返回 NULL；
其余查询都能找到匹配行，其中 (7, 2019) 的净现值是 0，注意 0 不是 NULL。
```

## 题解

::: details 点击查看题解

### 思路

这是一道标准的「左表驱动 + 可选匹配」问题：`Queries` 是必须全部输出的主表，`NPV` 只是提供数据的从表，所以要 `FROM Queries q LEFT JOIN NPV n`，连接键是复合键 `id` 和 `year` 同时相等。

`LEFT JOIN` 的关键特性是：左表每一行都会保留，右表匹配不到时右表列为 `NULL`。这正好满足「没有记录返回 NULL」的要求，不需要额外写 `COALESCE` 或 `IFNULL`。

易错点：一是连接条件必须同时写 `n.id = q.id AND n.year = q.year`，只写其中一个会把不同年份（或不同项目）的数据错误地拼到一起；二是不能颠倒成 `NPV LEFT JOIN Queries`，那样没有 NPV 记录的查询会直接消失，输出少行；三是别把 `0` 当成缺失值，示例中 `(7, 2019)` 的 npv 就是 0，用 `nullif` 之类的处理反而会出错；四是连接条件要写在 `ON` 里而不是 `WHERE` 里，写进 `WHERE` 会让 `LEFT JOIN` 退化成 `INNER JOIN`。

替代写法：用标量子查询 `SELECT npv FROM NPV WHERE id = q.id AND year = q.year`，结果相同，但每行都要执行一次子查询，数据量大时不如 JOIN。

### SQL 实现

```sql
SELECT q.id,
       q.year,
       n.npv
FROM Queries q
LEFT JOIN NPV n
    ON n.id = q.id
   AND n.year = q.year;
```

### 复杂度分析

- 时间复杂度：O(q + n)，q 为查询数、n 为 NPV 记录数，有复合主键索引时连接接近线性。
- 空间复杂度：O(1)，除结果集外只用到常量级临时空间。
