# 找到遗失的ID

> 难度：中等 | 标签：递归 CTE、子查询 | [LeetCode 原题](https://leetcode.cn/problems/find-the-missing-ids/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

表：`Customers`

```
+---------------+---------+
| Column Name   | Type    |
+---------------+---------+
| customer_id   | int     |
| customer_name | varchar |
+---------------+---------+
```

`customer_id` 是该表主键，每行是一位顾客的编号和姓名。

请写一个解决方案，找出所有**遗失的顾客 id**：即那些没有出现在 `Customers` 表中、但取值介于 `1` 与表中**最大** `customer_id` 之间的整数 id。注意：最大的 `customer_id` 不会超过 `100`。

返回列名为 `ids`，按 `ids` 升序排列。

**示例 1：**

```
输入：
Customers 表：
+-------------+---------------+
| customer_id | customer_name |
+-------------+---------------+
| 1           | Alice         |
| 4           | Bob           |
| 5           | Charlie       |
+-------------+---------------+
输出：
+-----+
| ids |
+-----+
| 2   |
| 3   |
+-----+
```

解释：表里最大的 `customer_id` 是 5，所以在 `[1, 5]` 范围内，ID 2 和 3 从表中遗失。

## 题解

::: details 点击查看题解

### 思路

SQL 没有现成的整数序列，而遗失的 ID 只可能出现在 `[1, max-1]` 这段连续区间里，所以先「造出候选集」再排除已有编号。递归 CTE 是最直接的造数方式：起点 `SELECT 1`，每轮 `n + 1`，一直加到 100（题面保证最大 `customer_id` 不超过 100，所以上限写死 100 是安全的）。

拿到 1..100 之后，外层 `WHERE` 做两件事：只保留 `n < (SELECT MAX(customer_id) FROM Customers)` 的候选（最大值本身一定存在，它之后的数也不属于「遗失」），再 `NOT IN` 排除表里已存在的编号。

有一个 MySQL 8 的限制要注意：递归 CTE 的**递归部分**里不能出现聚合、窗口、`GROUP BY`、`ORDER BY`、`DISTINCT` 这类构造，所以 `MAX(customer_id)` 这样的子查询必须放到最外层，而不要把 `WHERE n < (SELECT MAX(...))` 写进 `UNION ALL` 下面的那半截。不想用递归也可以造 10 × 10 的数字笛卡尔积得到 0..99 的序列。

### SQL 实现

```sql
WITH RECURSIVE seq AS (
    SELECT 1 AS n
    UNION ALL
    SELECT n + 1
    FROM seq
    WHERE n < 100
)
SELECT n AS ids
FROM seq
WHERE n < (SELECT MAX(customer_id) FROM Customers)
  AND n NOT IN (SELECT customer_id FROM Customers)
ORDER BY n;
```

### 复杂度分析

- 时间复杂度：O(k · n) 级别，k 为生成的候选数（最多 100），`NOT IN` 子查询若未优化成半连接则每个候选都要查一次；加索引后可视为 O(k + n)。
- 空间复杂度：O(k)，递归 CTE 的临时结果集大小与候选数量成正比。

:::
