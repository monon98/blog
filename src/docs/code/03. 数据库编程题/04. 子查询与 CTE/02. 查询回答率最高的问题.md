# 查询回答率最高的问题

> 难度：中等 | 标签：分组聚合、条件聚合、排序取优 | [LeetCode 原题](https://leetcode.cn/problems/get-highest-answer-rate-question/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

`SurveyLog` 表：

```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| id          | int     |
| action      | varchar |
| question_id | int     |
| answer_id   | int     |
| q_num       | int     |
| timestamp   | int     |
+-------------+---------+
这张表没有主键，可能存在重复行。
action 取值为 'show'（问题被展示）、'answer'（问题被回答）或 'skip'（问题被跳过）。
answer_id 在 action = 'answer' 时有值，其余情况为 NULL。
q_num 表示该问题在整份问卷中的题号（实际问题所在的位置），timestamp 为行为发生时刻的整数编号。
```

编写一个 SQL 查询，找出 **回答率最高** 的问题。

- 回答率 = 该问题被回答的次数 ÷ 该问题被展示的次数，即 `action = 'answer'` 的记录数除以 `action = 'show'` 的记录数；
- `skip` 记录既不进入分子也不进入分母；
- 若多个问题的回答率并列最高，返回 `question_id` 最小的那个；
- 结果只输出一列，列名为 `survey_log`。

**示例 1：**

```
输入：
SurveyLog 表：
+----+--------+-------------+-----------+-------+-----------+
| id | action | question_id | answer_id | q_num | timestamp |
+----+--------+-------------+-----------+-------+-----------+
| 5  | show   | 285         | NULL      | 1     | 123       |
| 5  | answer | 285         | 124124    | 1     | 124       |
| 5  | show   | 369         | NULL      | 2     | 125       |
| 5  | skip   | 369         | NULL      | 2     | 126       |
+----+--------+-------------+-----------+-------+-----------+
输出：
+------------+
| survey_log |
+------------+
| 285        |
+------------+
解释：
问题 285 被展示 1 次、被回答 1 次，回答率为 1/1 = 1。
问题 369 被展示 1 次、被跳过 1 次，回答率为 0/1 = 0。
因此回答率最高的问题是 285。
```

## 题解

::: details 点击查看题解

### 思路

这题的核心是「条件聚合」：一张日志表里同时混着 show 和 answer 两种行为，需要按问题把它们分别数出来。MySQL 中布尔表达式返回 0/1，因此 `SUM(action = 'answer')` 就是回答次数，`SUM(action = 'show')` 就是展示次数，一次 `GROUP BY question_id` 即可得到每个问题的回答率。

分子分母都只认对应的 action，`skip` 记录自然被排除。排序时按回答率降序、`question_id` 升序，再用 `LIMIT 1` 取第一条；`ORDER BY` 中可以直接使用聚合表达式，也可以在 `SELECT` 里给出别名后按别名排序。

几个坑：一是别忘了处理分母为 0 的情况，用一个只有 `skip` 没有问题展示过的测试数据就会触发除零，`NULLIF(SUM(action = 'show'), 0)` 会把分母变成 NULL，排序时该行排到最后而不是报错；二是并列时题目要求返回较小的 `question_id`，必须显式写第二排序键，不能只依赖默认顺序；三是输出列名是 `survey_log` 而不是 `question_id`，需要起别名。

替代写法：先按 `(question_id, action)` 分组计数，再用 `CASE WHEN` 或 `PIVOT` 思路把 show/answer 转成两列后计算比率，逻辑更直白但多一层子查询。

### SQL 实现

```sql
SELECT question_id AS survey_log
FROM SurveyLog
GROUP BY question_id
ORDER BY SUM(action = 'answer') / NULLIF(SUM(action = 'show'), 0) DESC,
         question_id
LIMIT 1;
```

### 复杂度分析

- 时间复杂度：O(n log q)，n 为日志行数，分组聚合接近线性，排序 q 个问题主导。
- 空间复杂度：O(q)，q 为问题数，用于保存每个问题的计数状态。

```sql
Create table If Not Exists SurveyLog (id int, action varchar(255), question_id int, answer_id int, q_num int, timestamp int);
Truncate table SurveyLog;
insert into SurveyLog (id, action, question_id, answer_id, q_num, timestamp) values ('5', 'show', '285', NULL, '1', '123');
insert into SurveyLog (id, action, question_id, answer_id, q_num, timestamp) values ('5', 'answer', '285', '124124', '1', '124');
insert into SurveyLog (id, action, question_id, answer_id, q_num, timestamp) values ('5', 'show', '369', NULL, '2', '125');
insert into SurveyLog (id, action, question_id, answer_id, q_num, timestamp) values ('5', 'skip', '369', NULL, '2', '126');
```
