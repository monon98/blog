# 每日新用户统计

> 难度：中等 | 标签：日期函数、分组聚合、子查询 | [LeetCode 原题](https://leetcode.cn/problems/new-users-daily-count/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

`Traffic` 表：

```
+---------------+---------+
| Column Name   | Type    |
+---------------+---------+
| user_id       | int     |
| activity      | enum    |
| activity_date | date    |
+---------------+---------+
该表没有主键，可能存在重复行。
activity 是 ENUM 类型，取值为 ('login', 'logout', 'jobs', 'groups', 'homepage')。
每一行表示某个用户在某个日期进行的一次活动。
```

用户在某天「登录」指当天存在 `action = 'login'` 的记录；某个用户的「首次登录日期」是其所有登录日期中最早的一天。

编写一个 SQL 查询，报告 **最近 90 天内（2019-04-01 至 2019-06-30，含两端）** 每天首次登录的新用户数量。假设今天是 `2019-06-30`。

返回结果表包含 `login_date` 与 `user_count` 两列，按 `login_date` 升序排列。

**示例 1：**

```
输入：
Traffic 表：
+---------+----------+---------------+
| user_id | activity | activity_date |
+---------+----------+---------------+
| 1       | login    | 2019-05-01    |
| 1       | homepage | 2019-05-01    |
| 1       | logout   | 2019-05-01    |
| 2       | login    | 2019-06-21    |
| 2       | logout   | 2019-06-21    |
| 3       | login    | 2019-01-01    |
| 3       | jobs     | 2019-01-01    |
| 3       | logout   | 2019-01-01    |
| 4       | login    | 2019-06-21    |
| 4       | groups   | 2019-06-21    |
| 4       | logout   | 2019-06-21    |
| 5       | login    | 2019-03-01    |
| 5       | logout   | 2019-03-01    |
| 5       | login    | 2019-06-21    |
| 5       | logout   | 2019-06-21    |
+---------+----------+---------------+
输出：
+------------+------------+
| login_date | user_count |
+------------+------------+
| 2019-05-01 | 1          |
| 2019-06-21 | 2          |
+------------+------------+
解释：
用户 1 首次登录是 2019-05-01；用户 2 和用户 4 首次登录都是 2019-06-21，因此当天新增 2 人。
用户 3 首次登录是 2019-01-01，用户 5 首次登录是 2019-03-01，都在 90 天窗口之外，不计入。
用户 5 在 2019-06-21 的登录不是首次登录，也不计入。
```

## 题解

::: details 点击查看题解

### 思路

「每天新增用户数」的实质是：先求每个用户的首次登录日期，再按这个日期分组计数。第一步用 `WHERE activity = 'login'` + `GROUP BY user_id` + `MIN(activity_date)` 得到首登日；第二步把这份结果与原表按「用户 + 日期」连接，只留下首登当天的 login 记录，最后按日期分组统计人数。

日期范围条件要小心：题目要求最近 90 天，且给定今天是 2019-06-30，因此窗口是 `[2019-04-01, 2019-06-30]`。可以用 `BETWEEN '2019-04-01' AND '2019-06-30'` 硬编码，更通用的写法是 `activity_date BETWEEN DATE_SUB('2019-06-30', INTERVAL 90 DAY) AND '2019-06-30'`；注意 `DATE_SUB(..., INTERVAL 90 DAY)` 得到的是 2019-04-01，两端都是闭区间。

易错点：一是必须先过滤 `activity = 'login'` 再求 `MIN`，否则用户当天只有 homepage 活动时，`MIN` 会把非登录日期当成首登日；二是窗口过滤要作用在**首登日**上，而不是原表任意活动日期——如果写在连接前对原表过滤，逻辑上也等价（首登日一定落在窗口内才有效），但写在最终结果上更直观；三是同一天同一用户可能有多条 login 记录（`Traffic` 无主键），`COUNT(DISTINCT user_id)` 能避免重复计数。

替代写法：用 `ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY activity_date)` 在 login 记录里取 `rn = 1`，同样能得到首登日，适合需求扩展成「前 N 天」的场景。

### SQL 实现

```sql
SELECT t.activity_date AS login_date,
       COUNT(DISTINCT t.user_id) AS user_count
FROM Traffic t
JOIN (
    SELECT user_id, MIN(activity_date) AS first_login
    FROM Traffic
    WHERE activity = 'login'
    GROUP BY user_id
) f
    ON f.user_id = t.user_id
   AND f.first_login = t.activity_date
WHERE t.activity = 'login'
  AND t.activity_date BETWEEN DATE_SUB('2019-06-30', INTERVAL 90 DAY) AND '2019-06-30'
GROUP BY t.activity_date
ORDER BY login_date;
```

### 复杂度分析

- 时间复杂度：O(n log n)，n 为活动记录数，分组求最小日期与连接去重主导。
- 空间复杂度：O(u)，u 为用户数，用于保存每个用户的首登日。
