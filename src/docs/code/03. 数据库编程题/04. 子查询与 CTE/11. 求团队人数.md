# 求团队人数

> 难度：简单 | 标签：分组聚合、多表连接 | [LeetCode 原题](https://leetcode.cn/problems/find-the-team-size/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

`Employee` 表：

```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| employee_id | int     |
| team_id     | int     |
+-------------+---------+
employee_id 是该表的主键。
每一行表示某个员工及其所属团队的 id。
```

编写一个 SQL 查询，报告 **每个员工所在团队的人数**。

- 对每个员工输出 `employee_id` 与 `team_size`；
- `team_size` 是与该员工 `team_id` 相同的员工总数（包含自己）；
- 结果按 `employee_id` 升序排列。

**示例 1：**

```
输入：
Employee 表：
+-------------+---------+
| employee_id | team_id |
+-------------+---------+
| 1           | 8       |
| 2           | 8       |
| 3           | 8       |
| 4           | 7       |
| 5           | 9       |
| 6           | 9       |
+-------------+---------+
输出：
+-------------+-----------+
| employee_id | team_size |
+-------------+-----------+
| 1           | 3         |
| 2           | 3         |
| 3           | 3         |
| 4           | 1         |
| 5           | 2         |
| 6           | 2         |
+-------------+-----------+
解释：
员工 1、2、3 都属于团队 8，团队人数为 3；
员工 4 独占团队 7，团队人数为 1；
员工 5、6 属于团队 9，团队人数为 2。
```

## 题解

::: details 点击查看题解

### 思路

「团队人数」是对 `team_id` 这一列的聚合结果，但输出又要求细化到每个员工，所以需要先按团队算出人数，再把结果拼回员工明细行——这是「聚合结果回填到明细」的典型写法。

最直观的做法是子查询：`SELECT team_id, COUNT(*) AS team_size FROM Employee GROUP BY team_id` 得到每个团队的人数，再与 `Employee` 按 `team_id` 等值连接，员工行就能带上自己团队的人数。因为 `team_id` 在子查询里唯一，连接不会放大行数。

也可以用窗口函数 `COUNT(*) OVER (PARTITION BY team_id)` 一步完成，不需要子查询，可读性更好，在数据量大时通常也更快。两种写法结果一致。

易错点：一是 `COUNT(*)` 统计的是团队内的行数，而 `employee_id` 是主键，所以不需要 `DISTINCT`，但如果实际表允许重复员工行，就应该改成 `COUNT(DISTINCT employee_id)`；二是连接键是 `team_id` 而不是 `employee_id`，写错会退化成每人一行；三是题目要求按 `employee_id` 升序输出，别忘了 `ORDER BY`。

### SQL 实现

```sql
SELECT e.employee_id,
       t.team_size
FROM Employee e
JOIN (
    SELECT team_id, COUNT(*) AS team_size
    FROM Employee
    GROUP BY team_id
) t
    ON t.team_id = e.team_id
ORDER BY e.employee_id;
```

窗口函数写法（等价）：

```sql
SELECT employee_id,
       COUNT(*) OVER (PARTITION BY team_id) AS team_size
FROM Employee
ORDER BY employee_id;
```

### 复杂度分析

- 时间复杂度：O(n log n)，n 为员工数，分组与排序主导（窗口写法同样需要排序）。
- 空间复杂度：O(t)，t 为团队数，用于保存每个团队的人数。
