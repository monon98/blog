# 游戏玩法分析 IV

> 难度：中等 | 标签：日期函数、子查询、分组聚合 | [LeetCode 原题](https://leetcode.cn/problems/game-play-analysis-iv/)

## 题目描述

Table: `Activity`

```
+--------------+---------+
| Column Name  | Type    |
+--------------+---------+
| player_id    | int     |
| device_id    | int     |
| event_date   | date    |
| games_played | int     |
+--------------+---------+
（player_id，event_date）是此表的主键（具有唯一值的列的组合）。
这张表显示了某些游戏的玩家的活动情况。
每一行是一个玩家的记录，他在某一天使用某个设备注销之前登录并玩了很多游戏（可能是 0）。
```

编写解决方案，报告在首次登录的第二天再次登录的玩家的 **比率**，**四舍五入到小数点后两位**。换句话说，你需要计算从首次登录后的第二天登录的玩家数量，并将其除以总玩家数。

结果格式如下所示：

**示例 1：**

```
输入：
Activity table:
+-----------+-----------+------------+--------------+
| player_id | device_id | event_date | games_played |
+-----------+-----------+------------+--------------+
| 1         | 2         | 2016-03-01 | 5            |
| 1         | 2         | 2016-03-02 | 6            |
| 2         | 3         | 2017-06-25 | 1            |
| 3         | 1         | 2016-03-02 | 0            |
| 3         | 4         | 2018-07-03 | 5            |
+-----------+-----------+------------+--------------+
输出：
+-----------+
| fraction  |
+-----------+
| 0.33      |
+-----------+
解释：
只有 ID 为 1 的玩家在第一天登录后才重新登录，所以答案是 1/3 = 0.33
```

## 题解

::: details 点击查看题解

### 思路

分母很直接：`COUNT(DISTINCT player_id)` 就是总玩家数。难点在分子——「首次登录的第二天再次登录」需要把每个玩家的首次登录日期求出来，再拿它加一天去和该玩家的其他登录记录匹配。

先用子查询按 `player_id` 求 `MIN(event_date)` 得到首登日，然后与原表做等值连接，连接条件同时写 `player_id` 相同和 `event_date = DATE_ADD(first_date, INTERVAL 1 DAY)`；能连上的玩家就是满足条件的玩家，再 `COUNT(DISTINCT player_id)` 去重（虽然 `(player_id, event_date)` 是主键、不会重复，但写成 `DISTINCT` 更稳妥）。

易错点：第一，别把「第二天」写成 `event_date = first_date`，题意是首登日的**次日**；第二，MySQL 里日期加减用 `DATE_ADD(..., INTERVAL 1 DAY)`，不要用不支持的函数；第三，`ROUND(..., 2)` 要作用在最终比值上，而不是先对分子分母取整；第四，分子是 0 时 `ROUND(0/n, 2)` 返回 0.00，符合预期，不需要额外判空。

替代写法：用窗口函数 `ROW_NUMBER() OVER (PARTITION BY player_id ORDER BY event_date)` 取每个玩家的第 1、2 条记录，再判断两条日期是否相差一天，可读性也不错，但在玩家记录很多时不如「首登日 + 日期匹配」高效。

### SQL 实现

```sql
SELECT ROUND(
           COUNT(DISTINCT a.player_id) / (SELECT COUNT(DISTINCT player_id) FROM Activity),
           2
       ) AS fraction
FROM Activity a
JOIN (
    SELECT player_id, MIN(event_date) AS first_date
    FROM Activity
    GROUP BY player_id
) f
    ON f.player_id = a.player_id
   AND a.event_date = DATE_ADD(f.first_date, INTERVAL 1 DAY);
```

### 复杂度分析

- 时间复杂度：O(n log n)，n 为活动记录数，按玩家分组求最小日期与连接去重主导。
- 空间复杂度：O(p)，p 为玩家数，用于保存每个玩家的首登日。
