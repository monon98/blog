# 无效的推文 II

> 难度：简单 | 标签：字符串函数、条件过滤 | [LeetCode 原题](https://leetcode.cn/problems/invalid-tweets-ii/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

`Tweets` 表：

```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| tweet_id    | int     |
| content     | varchar |
+-------------+---------+
tweet_id 是该表的主键。
每一行是一条推文的内容。
```

一条推文只要满足**任意一条**下面条件就算无效：

- 长度超过 `140` 个字符；
- `@` 提及超过 `3` 个；
- `#` 话题标签超过 `3` 个。

返回列：`tweet_id`，按 `tweet_id` 升序排列。

**示例 1（节选，完整数据见下方建表语句）：**

输入：

```
Tweets 表：
+----------+-----------------------------------------------------------------------------------+
| tweet_id | content                                                                           |
+----------+-----------------------------------------------------------------------------------+
| 1        | What an amazing meal @MaxPower @AlexJones @JohnDoe #Learning #Fitness #Love       |
| 2        | Learning something new every day @AnnaWilson #Learning #Foodie                    |
| 13       | What an amazing meal @EmilyClark @JohnDoe @LisaTaylor @MaxPower #Foodie #Fitness  |
| 14       | Work hard, play hard, and cherish every moment @LisaTaylor @SaraJohnson           |
|          | @MaxPower @ChrisAnderson #TechLife #Nature #Music                                 |
+----------+-----------------------------------------------------------------------------------+
```

输出：

```
+----------+
| tweet_id |
+----------+
| 4        |
| 7        |
| 13       |
| 14       |
+----------+
```

解释：tweet_id 为 4、7、13、14 的推文都有 4 个 `@` 提及，超过 3 个，因此无效；其余推文既不超过 140 个字符，提及和标签也都不超过 3 个。

## 题解

::: details 点击查看题解

### 思路

三个条件是彼此独立的，用 `OR` 连起来即可，不需要嵌套子查询。长度用 `CHAR_LENGTH(content) > 140`——它数的是字符数而不是字节数，虽然本题数据都是 ASCII，但换成含中文的内容时 `CHAR_LENGTH` 才是正确语义。

统计 `@` 和 `#` 的个数用"长度差值法"：`LENGTH(content) - LENGTH(REPLACE(content, '@', ''))`。把目标字符全部替换成空串，长度减少多少就说明出现了多少次，这是 SQL 里统计单字符出现次数的常用技巧，比 `LIKE` 循环或正则都简单。

易错点：一是"超过 3 个"是 `> 3`（即 4 个及以上），写成 `>= 3` 会把只有 3 个提及的正常推文误判；二是混用 `LENGTH`/`CHAR_LENGTH` 时要注意多字节字符，字符删除用 `REPLACE` 前后单位一致即可；三是三个条件之间必须是 `OR`，写成 `AND` 就只有"同时超长又多提及又多标签"才算无效。

替代写法：MySQL 8 可以用 `REGEXP_LIKE(content, '@.*@.*@.*@')` 判断是否有 4 个提及，`(content REGEXP '@[^@]*@[^@]*@[^@]*@')` 同样可行，但可读性和通用性不如长度差值法。

### SQL 实现

```sql
SELECT tweet_id
FROM Tweets
WHERE CHAR_LENGTH(content) > 140
   OR LENGTH(content) - LENGTH(REPLACE(content, '@', '')) > 3
   OR LENGTH(content) - LENGTH(REPLACE(content, '#', '')) > 3
ORDER BY tweet_id;
```

### 复杂度分析

- 时间复杂度：O(n·L)，n 为推文数、L 为推文平均长度，每行做两次替换扫描。
- 空间复杂度：O(1)，只输出命中的 `tweet_id`。
