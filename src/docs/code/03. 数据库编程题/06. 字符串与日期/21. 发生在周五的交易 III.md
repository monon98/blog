# 发生在周五的交易 III

> 难度：中等 | 标签：递归 CTE、多表连接、LEFT JOIN 补空 | [LeetCode 原题](https://leetcode.cn/problems/friday-purchase-iii/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

`Purchases` 表：

```
+---------------+------+
| Column Name   | Type |
+---------------+------+
| user_id       | int  |
| purchase_date | date |
| amount_spend  | int  |
+---------------+------+
(user_id, purchase_date, amount_spend) 是该表的联合主键。
purchase_date 的范围是 2023 年 11 月 1 日到 2023 年 11 月 30 日。
```

`Users` 表：

```
+-------------+------+
| Column Name | Type |
+-------------+------+
| user_id     | int  |
| membership  | enum |
+-------------+------+
user_id 是该表的主键。
membership 是枚举类型，取值为 Standard、Premium、VIP。
```

编写一个查询，计算 2023 年 11 月**每个周**的**周五**里，`Premium` 和 `VIP` 会员的消费总额。如果某个周五这两类会员都没有消费，对应金额按 0 返回（也就是说每个周都要输出 Premium 和 VIP 两行）。

返回列：`week_of_month`、`membership`、`total_amount`，按 `week_of_month` 升序、`membership` 升序排列。

**示例 1：**

输入：

```
Purchases 表：
+---------+---------------+--------------+
| user_id | purchase_date | amount_spend |
+---------+---------------+--------------+
| 11      | 2023-11-03    | 1126         |
| 15      | 2023-11-10    | 7473         |
| 17      | 2023-11-17    | 2414         |
| 12      | 2023-11-24    | 9692         |
| 8       | 2023-11-24    | 5117         |
| 1       | 2023-11-24    | 5241         |
| 10      | 2023-11-22    | 8266         |
| 13      | 2023-11-21    | 12000        |
+---------+---------------+--------------+

Users 表：
+---------+------------+
| user_id | membership |
+---------+------------+
| 11      | Premium    |
| 15      | VIP        |
| 17      | Standard   |
| 12      | VIP        |
| 8       | Premium    |
| 1       | VIP        |
| 10      | Standard   |
| 13      | Premium    |
+---------+------------+
```

输出：

```
+---------------+------------+--------------+
| week_of_month | membership | total_amount |
+---------------+------------+--------------+
| 1             | Premium    | 1126         |
| 1             | VIP        | 0            |
| 2             | Premium    | 0            |
| 2             | VIP        | 7473         |
| 3             | Premium    | 0            |
| 3             | VIP        | 0            |
| 4             | Premium    | 5117         |
| 4             | VIP        | 14933        |
+---------------+------------+--------------+
```

解释：

- 第 1 周周五 2023-11-03：用户 11（Premium）消费 1126，VIP 无消费。
- 第 2 周周五 2023-11-10：用户 15（VIP）消费 7473，Premium 无消费。
- 第 3 周周五 2023-11-17：用户 17 是 Standard，不计入，Premium 和 VIP 都是 0。
- 第 4 周周五 2023-11-24：Premium 5117，VIP 9692 + 5241 = 14933。

## 题解

::: details 点击查看题解

### 思路

和「发生在周五的交易 I」相比，这题多了两个要求：只看 Premium / VIP 会员，而且**没有消费的周也要输出 0**。后一条决定了写法：不能直接从 `Purchases` 出发分组，那样空组合会整行消失，必须先用"周 1~4 × 会员 2 种"造出一个完整的骨架，再去左连接实际消费。

骨架用递归 CTE 生成 1..4 的周号，会员表用两行 `UNION ALL` 常量表，两者 `CROSS JOIN` 得到 8 行，然后 `LEFT JOIN` 到"周五消费明细"上，`IFNULL(SUM(amount_spend), 0)` 把空组合补成 0。

消费明细里要同时拿到会员类型和周号：`JOIN Users USING (user_id)` 过滤出会员类型（`WHERE` 里再限 Premium/VIP），`CEIL(DAYOFMONTH(purchase_date) / 7)` 算出周号，`DAYOFWEEK(purchase_date) = 6` 限定周五。

易错点：一是把骨架表和消费表的连接条件写漏字段（必须同时按 `week_of_month` 和 `membership` 连接，只按周连接会让金额翻倍）；二是用内连接导致空组合丢失；三是聚合后忘了 `GROUP BY`，或者在 `IFNULL` 外层去 `SUM` 已经补 0 的值（那样空组合会变成多行 0）；四是 Standard 会员必须过滤掉，而不是靠后续 SUM 自然为 0 处理。

替代写法：用 `UNION ALL` 手写 8 行骨架（4 周 × 2 会员），或用数字表 `SELECT 1 UNION SELECT 2 ...`，效果一致。

### SQL 实现

```sql
WITH RECURSIVE weeks AS (
    SELECT 1 AS week_of_month
    UNION ALL
    SELECT week_of_month + 1 FROM weeks WHERE week_of_month < 4
),
members AS (
    SELECT 'Premium' AS membership
    UNION ALL
    SELECT 'VIP'
),
friday_spend AS (
    SELECT CEIL(DAYOFMONTH(p.purchase_date) / 7) AS week_of_month,
           u.membership,
           p.amount_spend
    FROM Purchases AS p
    JOIN Users AS u USING (user_id)
    WHERE p.purchase_date >= '2023-11-01'
      AND p.purchase_date < '2023-12-01'
      AND DAYOFWEEK(p.purchase_date) = 6
)
SELECT w.week_of_month,
       m.membership,
       IFNULL(SUM(f.amount_spend), 0) AS total_amount
FROM weeks AS w
CROSS JOIN members AS m
LEFT JOIN friday_spend AS f
    ON f.week_of_month = w.week_of_month
   AND f.membership = m.membership
GROUP BY w.week_of_month, m.membership
ORDER BY w.week_of_month, m.membership;
```

### 复杂度分析

- 时间复杂度：O(n + 8)，n 为交易行数，连接与分组都在小结果集上完成。
- 空间复杂度：O(8)，骨架表大小固定。

:::
