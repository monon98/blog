# 统计文本中单词的出现次数

> 难度：中等 | 标签：字符串函数、LIKE 模式匹配、聚合统计 | [LeetCode 原题](https://leetcode.cn/problems/count-occurrences-in-text/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

`Files` 表：

```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| file_name   | varchar |
| content     | text    |
+-------------+---------+
file_name 是具有唯一值的列。
每一行包含文件名和该文件的文本内容。
```

编写一个查询，统计 `bull` 和 `bear` 这两个单词以**独立单词**形式出现在多少个文件中。

"独立单词"的判定很严格：单词前后都必须有空格。因此出现在其他单词内部（如 `bullet`、`bears`）、或者紧挨着标点与句首句尾（如 `bull.`）的情况都不计入。

返回两列 `word`、`count`，分别是单词本身和包含该单词的文件数，顺序不限。

**示例 1：**

输入（`Files` 表，content 完整内容见下方建表语句）：

- `draft1.txt`：The stock exchange predicts a bull market which would make many investors happy.
- `draft2.txt`：The stock exchange predicts a bull market which would make many investors happy, but analysts warn of possibility of too much optimism and that in fact we are awaiting a bear market.
- `final.txt`：在 draft2.txt 的基础上再追加 As always predicting the future market is an uncertain game and all investors should follow their instincts and best practices.

输出：

```
+------+-------+
| word | count |
+------+-------+
| bull | 3     |
| bear | 2     |
+------+-------+
```

解释：

- 三个文件里都出现了 ` bull `，所以 `bull` 的文件数是 3。
- 只有 `draft2.txt` 和 `final.txt` 里出现了 ` bear `，所以 `bear` 的文件数是 2。

## 题解

::: details 点击查看题解

### 思路

题目要的是「包含该词的文件数」，不是总的出现次数，所以统计粒度是 `Files` 的行。既然"独立单词"要求前后都有空格，那么直接匹配 `'% bull %'` 就够了——句中出现的独立单词一定被空格包住，而被标点、句首句尾包住的情况正好不满足这个模式，天然被排除。

两个单词是固定的一行结果，最省事的写法是把两个 `COUNT(*)` 用 `UNION` 竖着拼起来，而不是想办法写成一行两列（那样得用 `COUNT(IF(...))` 之类的条件聚合，还会遇到"没有任何文件匹配时输出 0 行"和"必须输出两行"的麻烦）。

易错点：一是别偷懒写 `'%bull%'`，它会把 `bullet`、`bullish` 一起算进去；二是 `count` 是聚合函数名，做别名时必须加反引号，否则报语法错误；三是 `UNION` 会去重，这里两行的 `word` 不同，不会误合并，但如果扩展成"再统计一次总次数"就要留意 `UNION ALL`。

替代写法：`SELECT 'bull' AS word, SUM(content LIKE '% bull %') AS count FROM Files` 也能得到同样结果，条件写在 `SUM` 里做计数。

### SQL 实现

```sql
SELECT 'bull' AS word, COUNT(*) AS `count`
FROM Files
WHERE content LIKE '% bull %'
UNION
SELECT 'bear' AS word, COUNT(*) AS `count`
FROM Files
WHERE content LIKE '% bear %';
```

### 复杂度分析

- 时间复杂度：O(n·L)，n 为文件数、L 为文本平均长度，每行都要做两次字符串扫描。
- 空间复杂度：O(1)，只返回两行结果。

:::

## 建表与测试数据

```sql
Create table If Not Exists Files (file_name varchar(100), content text );
Truncate table Files;
insert into Files (file_name, content) values ('draft1.txt', 'The stock exchange predicts a bull market which would make many investors happy.');
insert into Files (file_name, content) values ('draft2.txt', 'The stock exchange predicts a bull market which would make many investors happy, but analysts warn of possibility of too much optimism and that in fact we are awaiting a bear market.');
insert into Files (file_name, content) values ('final.txt', 'The stock exchange predicts a bull market which would make many investors happy, but analysts warn of possibility of too much optimism and that in fact we are awaiting a bear market. As always predicting the future market is an uncertain game and all investors should follow their instincts and best practices.');
```
