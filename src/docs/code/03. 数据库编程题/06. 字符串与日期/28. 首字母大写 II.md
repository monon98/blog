# 首字母大写 II

> 难度：困难 | 标签：窗口函数、递归 CTE、字符串函数 | [LeetCode 原题](https://leetcode.cn/problems/first-letter-capitalization-ii/)

## 题目描述

表：`user_content`

```
+--------------+---------+
| Column Name  | Type    |
+--------------+---------+
| content_id   | int     |
| content_text | varchar |
+--------------+---------+
content_id 是该表的唯一键。
每一行包含一个唯一的 ID 以及对应的文本内容。
```

**单词**是指不包含空格的极大非空字符序列。

编写一个解决方案，按照以下规则对 `content_text` 列中的文本进行转换，并对每个单词应用这些规则：

	- 如果单词以一个不是英文字母的字符开头，则保持整个单词不变。

	- 否则，如果单词由两个或更多非空的英文字母部分通过连字符 - 连接而成，则将每个部分的首字母转换为大写，并将每个部分的其余字母转换为小写。例如，top-rated 转换为 Top-Rated，FR-ONT-end 转换为 Fr-Ont-End。

	- 否则，将单词的首字母转换为大写，并将其余所有英文字母转换为小写。所有特殊字符保持不变。

所有其他**格式**和**空格**必须保持**不变**。

返回*结果表，其中同时包含原始的 `content_text` 以及按照上述规则转换后的文本*。

结果格式如下例所示。

示例：

**输入：**

user_content 表：

+------------+---------------------------------+
| content_id | content_text                    |
+------------+---------------------------------+
| 1          | hello world of SQL              |
| 2          | the QUICK-brown fox             |
| 3          | modern-day DATA science         |
| 4          | web-based FRONT-end development |
+------------+---------------------------------+

**输出：**

+------------+---------------------------------+---------------------------------+
| content_id | original_text                   | converted_text                  |
+------------+---------------------------------+---------------------------------+
| 1          | hello world of SQL              | Hello World Of Sql              |
| 2          | the QUICK-brown fox             | The Quick-Brown Fox             |
| 3          | modern-day DATA science         | Modern-Day Data Science         |
| 4          | web-based FRONT-end development | Web-Based Front-End Development |
+------------+---------------------------------+---------------------------------+

**解释：**

	- 对于 content_id = 1：

		将每个单词的首字母大写，得到 "Hello World Of Sql"。

	- 对于 content_id = 2：

		带连字符的单词 "QUICK-brown" 转换为 "Quick-Brown"。

		- 其他单词按照普通的大小写转换规则处理。

	- 对于 content_id = 3：

		带连字符的单词 "modern-day" 转换为 "Modern-Day"。

		- "DATA" 转换为 "Data"。

	- 对于 content_id = 4：

		"web-based" 转换为 "Web-Based"。

		- "FRONT-end" 转换为 "Front-End"。

**提示：**

	- content_text 仅包含英文字母、空格以及字符 \、@、-、/、^ 和 ,。

## 题解

::: details 点击查看题解

### 思路

和「首字母大写」一样，MySQL 没有现成的 title case 函数，这里继续用逐字符扫描，但要在"是否大写"的判断上加两个条件。

第一，**单词首字符不是字母时整词保持原样**。所以不能无脑把非首字母都转小写，必须先知道当前字符所在单词的第一个字符是谁。做法是给每个字符算出"单词编号"——当前位置之前出现过多少个空格（`SUM(IF(ch = ' ', 1, 0)) OVER (... ROWS BETWEEN UNBOUNDED PRECEDING AND 1 PRECEDING)`），再按单词编号分组用 `FIRST_VALUE(ch) OVER (PARTITION BY content_id, word_idx ORDER BY pos)` 拿到每个单词的首字符。只有首字符是字母时才做大小写转换，否则原样输出。

第二，**连字符分段的首字母也要大写**。这只要在"大写位置"的判断里补一条 `prev_ch = '-'`：位于单词开头、或者紧跟在 `-` 后面的字母取大写，其余字母取小写，非字母字符（`-`、`@`、`/`、`^`、`,`、`\`）原样保留。

最后同样用 `GROUP_CONCAT(... ORDER BY pos SEPARATOR '')` 拼回整串，空格、标点、位置全部天然保真。

易错点：一是窗口帧写 `ROWS BETWEEN UNBOUNDED PRECEDING AND 1 PRECEDING` 时，第一行没有前一行，累加结果是 `NULL`，要 `IFNULL(..., 0)` 归零，否则第一行会被分到 `NULL` 单词组里；二是漏掉"单词首字符是否为字母"的判断，会把 `@abc` 这种词也改成 `@Abc`；三是 `prev_ch = '-'` 只能大写字母，判断里要同时要求当前字符是字母；四是 `ch REGEXP '[A-Za-z]'` 在 MySQL 8 默认不区分大小写，结果符合预期，但别用 `[a-z]` 之类容易误判的写法。

替代写法：先按空格递归拆词，再对每个词按 `-` 递归拆分处理，逻辑更贴近规则原文，但实现层数更多、边界（连续空格、句尾）更啰嗦。

### SQL 实现

```sql
WITH RECURSIVE nums AS (
    SELECT 1 AS n
    UNION ALL
    SELECT n + 1 FROM nums WHERE n < 255
),
chars AS (
    SELECT c.content_id,
           c.content_text,
           n.n AS pos,
           SUBSTRING(c.content_text, n.n, 1) AS ch,
           SUBSTRING(c.content_text, n.n - 1, 1) AS prev_ch,
           IFNULL(SUM(IF(SUBSTRING(c.content_text, n.n, 1) = ' ', 1, 0)) OVER (
                      PARTITION BY c.content_id
                      ORDER BY n.n
                      ROWS BETWEEN UNBOUNDED PRECEDING AND 1 PRECEDING
                  ), 0) AS word_idx
    FROM user_content AS c
    JOIN nums AS n ON n.n <= CHAR_LENGTH(c.content_text)
),
marked AS (
    SELECT content_id,
           content_text,
           pos,
           ch,
           prev_ch,
           FIRST_VALUE(ch) OVER (PARTITION BY content_id, word_idx ORDER BY pos) AS word_head
    FROM chars
)
SELECT content_id,
       content_text AS original_text,
       GROUP_CONCAT(
           CASE
               WHEN ch REGEXP '[A-Za-z]' AND word_head REGEXP '[A-Za-z]' THEN
                   IF(pos = 1 OR prev_ch = ' ' OR prev_ch = '-', UPPER(ch), LOWER(ch))
               ELSE ch
           END
           ORDER BY pos SEPARATOR ''
       ) AS converted_text
FROM marked
GROUP BY content_id, content_text
ORDER BY content_id;
```

### 复杂度分析

- 时间复杂度：O(n·L log n)，n 为行数、L 为文本长度，逐字符展开后需要按位置与单词分组做窗口计算。
- 空间复杂度：O(n·L)，中间结果是"每行每字符一行记录"。
