# 查找最长的电话

> 难度：中等 | 标签：窗口函数、多表连接、日期时间格式化 | [LeetCode 原题](https://leetcode.cn/problems/find-longest-calls/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

`Contacts` 表：

```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| id          | int     |
| first_name  | varchar |
| last_name   | varchar |
+-------------+---------+
id 是该表的主键，也是 Calls 表 contact_id 的外键。
每一行包含联系人 ID、名和姓。
```

`Calls` 表：

```
+-------------+------+
| Column Name | Type |
+-------------+------+
| contact_id  | int  |
| type        | enum |
| duration    | int  |
+-------------+------+
(contact_id, type, duration) 是该表的联合主键。
type 是枚举类型，取值为 incoming、outgoing；duration 是通话时长（秒）。
```

编写一个查询，找出**呼入**（incoming）和**呼出**（outgoing）各最长的 3 通电话。

返回列：`first_name`、`type`、`duration_formatted`（时长格式化为 `HH:MM:SS`），按 `type` 降序、`duration` 降序、`first_name` 降序排列。

**示例 1：**

输入：

```
Contacts 表：
+----+------------+-----------+
| id | first_name | last_name |
+----+------------+-----------+
| 1  | John       | Doe       |
| 2  | Jane       | Smith     |
| 3  | Alice      | Johnson   |
| 4  | Michael    | Brown     |
| 5  | Emily      | Davis     |
+----+------------+-----------+

Calls 表：
+------------+----------+----------+
| contact_id | type     | duration |
+------------+----------+----------+
| 1          | incoming | 120      |
| 1          | outgoing | 180      |
| 2          | incoming | 300      |
| 2          | outgoing | 240      |
| 3          | incoming | 150      |
| 3          | outgoing | 360      |
| 4          | incoming | 420      |
| 4          | outgoing | 200      |
| 5          | incoming | 180      |
| 5          | outgoing | 280      |
+------------+----------+----------+
```

输出：

```
+------------+----------+--------------------+
| first_name | type     | duration_formatted |
+------------+----------+--------------------+
| Alice      | outgoing | 00:06:00           |
| Emily      | outgoing | 00:04:40           |
| Jane       | outgoing | 00:04:00           |
| Michael    | incoming | 00:07:00           |
| Jane       | incoming | 00:05:00           |
| Emily      | incoming | 00:03:00           |
+------------+----------+--------------------+
```

解释：呼出最长三通是 Alice（360 秒）、Emily（280 秒）、Jane（240 秒）；呼入最长三通是 Michael（420 秒）、Jane（300 秒）、Emily（180 秒）。`outgoing` 字典序比 `incoming` 大，所以排在前面。

## 题解

::: details 点击查看题解

### 思路

"每类取前 3"是典型的分组排名问题：用 `RANK() OVER (PARTITION BY type ORDER BY duration DESC)` 给每通电话在同类内排名，再筛 `rk <= 3`。用 `RANK()` 而不是 `ROW_NUMBER()` 是为了让并列时一起保留（题目数据无并列，但语义上更稳）；如果用 `ROW_NUMBER()`，并列时谁进前三就变成随机的。

时长格式化交给 `SEC_TO_TIME(duration)` 得到 `TIME` 值，再用 `DATE_FORMAT(..., '%H:%i:%s')` 转成字符串。注意 MySQL 的 `%i` 才是分钟，写成 `%m` 会变成月份。格式化后的 `HH:MM:SS` 是定长字符串，直接按它降序排序等价于按时长降序，不过为了表达清楚，`ORDER BY` 里也可以显式排序三列。

易错点：一是忘了先 `JOIN Contacts` 拿 `first_name`；二是窗口函数的 `PARTITION BY` 写成 `contact_id` 就变成"每个联系人取前 3"；三是 `duration` 与格式化字符串混用排序；四是最终的排序方向全是 `DESC`，少写一个 `DESC` 顺序就反了。

替代写法：不写窗口函数的话，可以用"每个 `type` 里比它长的记录数 `< 3`"的自连接写法，但性能和可读性都更差。

### SQL 实现

```sql
WITH ranked AS (
    SELECT c.first_name,
           ca.type,
           DATE_FORMAT(SEC_TO_TIME(ca.duration), '%H:%i:%s') AS duration_formatted,
           RANK() OVER (PARTITION BY ca.type ORDER BY ca.duration DESC) AS rk
    FROM Calls AS ca
    JOIN Contacts AS c ON c.id = ca.contact_id
)
SELECT first_name, type, duration_formatted
FROM ranked
WHERE rk <= 3
ORDER BY type DESC, duration_formatted DESC, first_name DESC;
```

### 复杂度分析

- 时间复杂度：O(n log n)，n 为通话记录数，需要按 `(type, duration)` 排序。
- 空间复杂度：O(n)，窗口计算需要存放排名中间结果。

:::
