# 首字母大写

> 难度：困难 | 标签：递归 CTE、字符串函数、窗口函数 | [LeetCode 原题](https://leetcode.cn/problems/first-letter-capitalization/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

`user_content` 表：

```
+--------------+---------+
| Column Name  | Type    |
+--------------+---------+
| content_id   | int     |
| content_text | varchar |
+--------------+---------+
content_id 是该表具有唯一值的列。
每一行包含一个唯一的 ID 以及对应的文本内容，文本中只有英文字母和空格，不含特殊字符。
```

编写一个查询，对 `content_text` 做如下转换：

- 每个**单词**的首字母转为大写；
- 单词中的其余字母全部转为小写；
- 原有的空格（包括空格的位置和数量）全部保持不变。

返回结果表，包含原始的 `content_text`（列名 `original_text`）和转换后的文本（列名 `converted_text`）。

**示例 1：**

输入：

```
user_content 表：
+------------+-----------------------------------+
| content_id | content_text                      |
+------------+-----------------------------------+
| 1          | hello world of SQL                |
| 2          | the QUICK brown fox               |
| 3          | data science AND machine learning |
| 4          | TOP rated programming BOOKS       |
+------------+-----------------------------------+
```

输出：

```
+------------+-----------------------------------+-----------------------------------+
| content_id | original_text                     | converted_text                    |
+------------+-----------------------------------+-----------------------------------+
| 1          | hello world of SQL                | Hello World Of Sql                |
| 2          | the QUICK brown fox               | The Quick Brown Fox               |
| 3          | data science AND machine learning | Data Science And Machine Learning |
| 4          | TOP rated programming BOOKS       | Top Rated Programming Books       |
+------------+-----------------------------------+-----------------------------------+
```

解释：

- `SQL` 变成 `Sql`：首字母大写、其余字母小写，而不是整体保留原样。
- `QUICK` 变成 `Quick`、`TOP` 变成 `Top`、`BOOKS` 变成 `Books`，规则一致。
- 单词之间的空格数量和位置都没有变化。

## 题解

::: details 点击查看题解

### 思路

MySQL 没有 `initcap` / `title()` 这类内置函数，所以必须自己拼。这里用"逐字符扫描"的写法：用递归 CTE 生成 1..255 的位置序列，把每个字符串按字符炸开成多行，记下每个字符以及它的**前一个字符**。

判定规则非常简单：如果当前字符位于字符串开头（`pos = 1`）或前一个字符是空格，就把它转成大写，否则转成小写。因为输入只有字母和空格，这个规则等价于"每个单词首字母大写、其余小写"，而且空格本身经过 `UPPER`/`LOWER` 后仍是空格，位置与数量自然保持不变。

最后按 `pos` 用 `GROUP_CONCAT(... ORDER BY pos SEPARATOR '')` 把字符拼回整串。`ORDER BY` 和 `SEPARATOR ''` 都不能省：前者保证顺序（否则结果乱序），后者去掉默认的逗号分隔符。

易错点：一是 `GROUP_CONCAT` 默认最大长度 1024，文本很长时会被截断（可用 `SET SESSION group_concat_max_len` 调整）；二是 `SUBSTRING(s, 0, 1)` 返回空串而不是报错，`pos = 1` 的边界正好可以利用；三是别用 `UPPER(LEFT(s,1)) + LOWER(SUBSTRING(s,2))` 这种写法，它只处理第一个单词。

替代写法：递归按空格拆词、对每个词做 `UPPER(LEFT(w,1)) + LOWER(SUBSTRING(w,2))` 再拼回去，逻辑更直观，但连续多个空格时需要额外处理空词，容易丢空格。

### SQL 实现

```sql
WITH RECURSIVE nums AS (
    SELECT 1 AS n
    UNION ALL
    SELECT n + 1 FROM nums WHERE n < 255
),
chars AS (
    SELECT c.content_id,
           c.content_text,
           n.n AS pos,
           SUBSTRING(c.content_text, n.n, 1) AS ch,
           SUBSTRING(c.content_text, n.n - 1, 1) AS prev_ch
    FROM user_content AS c
    JOIN nums AS n ON n.n <= CHAR_LENGTH(c.content_text)
)
SELECT content_id,
       content_text AS original_text,
       GROUP_CONCAT(
           IF(pos = 1 OR prev_ch = ' ', UPPER(ch), LOWER(ch))
           ORDER BY pos SEPARATOR ''
       ) AS converted_text
FROM chars
GROUP BY content_id, content_text
ORDER BY content_id;
```

### 复杂度分析

- 时间复杂度：O(n·L)，n 为行数、L 为文本长度，逐字符展开后还要按位置排序拼接。
- 空间复杂度：O(n·L)，中间结果是"每行每字符一行记录"。
