# 不同国家的天气类型

> 难度：简单 | 标签：多表连接、分组聚合、CASE 表达式 | [LeetCode 原题](https://leetcode.cn/problems/weather-type-in-each-country/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

`Countries` 表：

```
+---------------+---------+
| Column Name   | Type    |
+---------------+---------+
| country_id    | int     |
| country_name  | varchar |
+---------------+---------+
country_id 是这张表的主键，每一行是一个国家。
```

`Weather` 表：

```
+---------------+------+
| Column Name   | Type |
+---------------+------+
| country_id    | int  |
| weather_state | int  |
| day           | date |
+---------------+------+
(country_id, day) 是该表的复合主键，每一行记录某个国家某一天的天气状况（weather_state）。
```

编写一个查询，找出每个国家在 **2019 年 11 月** 的天气类型。天气类型由该月 `weather_state` 的平均值决定：

- 平均值 **小于等于 15** → `Cold`
- 平均值 **大于等于 25** → `Hot`
- 其余情况 → `Warm`

结果列依次为 `country_name`、`weather_type`，顺序不限。2019 年 11 月没有任何天气记录的国家不出现在结果中。

**示例 1：**

```
输入：
Countries 表：
+------------+--------------+
| country_id | country_name |
+------------+--------------+
| 2          | USA          |
| 3          | Australia    |
| 7          | Peru         |
| 5          | China        |
| 8          | Morocco      |
| 9          | Spain        |
+------------+--------------+
Weather 表：
+------------+---------------+------------+
| country_id | weather_state | day        |
+------------+---------------+------------+
| 2          | 15            | 2019-11-01 |
| 2          | 12            | 2019-10-28 |
| 2          | 12            | 2019-10-27 |
| 3          | -2            | 2019-11-10 |
| 3          | 0             | 2019-11-11 |
| 3          | 3             | 2019-11-12 |
| 5          | 16            | 2019-11-07 |
| 5          | 18            | 2019-11-09 |
| 5          | 21            | 2019-11-23 |
| 7          | 25            | 2019-11-28 |
| 7          | 22            | 2019-12-01 |
| 7          | 20            | 2019-12-02 |
| 8          | 25            | 2019-11-05 |
| 8          | 27            | 2019-11-15 |
| 8          | 31            | 2019-11-25 |
| 9          | 7             | 2019-10-23 |
| 9          | 3             | 2019-12-23 |
+------------+---------------+------------+
输出：
+--------------+--------------+
| country_name | weather_type |
+--------------+--------------+
| USA          | Cold         |
| Australia    | Cold         |
| Peru         | Hot          |
| China        | Warm         |
| Morocco      | Hot          |
+--------------+--------------+
解释：
USA 11 月只有一条记录 15，平均值为 15，因此为 Cold。
Australia 11 月为 (-2 + 0 + 3) / 3 = 0.333，因此为 Cold。
Peru 11 月只有 11 月 28 日的 25，平均值为 25，因此为 Hot。
China 11 月为 (16 + 18 + 21) / 3 = 18.333，因此为 Warm。
Morocco 11 月为 (25 + 27 + 31) / 3 = 27.667，因此为 Hot。
Spain 在 2019 年 11 月没有天气记录，不出现在结果中。
```

## 题解

::: details 点击查看题解

### 思路

要先按国家求 2019 年 11 月的平均气温，再用 `CASE` 把连续数值切成三档。日期过滤写成 `DATE_FORMAT(day, '%Y-%m') = '2019-11'` 或 `day BETWEEN '2019-11-01' AND '2019-11-30'` 都可以；前者可读性好，后者能命中 `day` 上的索引，数据量大时更划算。

关键在两处：一是**先用 `WHERE` 过滤月份再 `AVG`**。如果把月份条件写进 `CASE`（`AVG(CASE WHEN ... THEN weather_state END)`），没有该月数据的国家会返回 `NULL` 而不是被排除，还要额外判空。二是 `AVG` 恰好落在 15 或 25 这类边界时，题目要求 `<= 15` 为 Cold、`>= 25` 为 Hot，两个 `WHEN` 的先后顺序不影响结果（15 与 25 互不重叠），但比较符号不能写成 `< 15` / `> 25`，否则边界会落到 `Warm`，Peru（25）就会算错。

`GROUP BY country_name` 之所以可行，是因为 `country_id` 与 `country_name` 一一对应；更严谨的写法是 `GROUP BY c.country_id, c.country_name`，如果在严格 `ONLY_FULL_GROUP_BY` 场景下不想依赖函数依赖，建议照后者写。

### SQL 实现

```sql
SELECT c.country_name,
       CASE
           WHEN AVG(w.weather_state) <= 15 THEN 'Cold'
           WHEN AVG(w.weather_state) >= 25 THEN 'Hot'
           ELSE 'Warm'
       END AS weather_type
FROM Weather w
JOIN Countries c ON c.country_id = w.country_id
WHERE w.day >= '2019-11-01' AND w.day <= '2019-11-30'
GROUP BY c.country_id, c.country_name;
```

### 复杂度分析

- 时间复杂度：O(n)，n 为天气记录数，一次连接 + 分组聚合。
- 空间复杂度：O(k)，k 为有该月数据的国家数。
