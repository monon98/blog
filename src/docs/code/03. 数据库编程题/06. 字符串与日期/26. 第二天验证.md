# 第二天验证

> 难度：简单 | 标签：多表连接、日期函数 | [LeetCode 原题](https://leetcode.cn/problems/second-day-verification/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

`emails` 表：

```
+-------------+----------+
| Column Name | Type     |
+-------------+----------+
| email_id    | int      |
| user_id     | int      |
| signup_date | datetime |
+-------------+----------+
(email_id, user_id) 是该表的联合主键。
每一行记录邮件 ID、用户 ID 和注册时间。
```

`texts` 表：

```
+---------------+----------+
| Column Name   | Type     |
+---------------+----------+
| text_id       | int      |
| email_id      | int      |
| signup_action | enum     |
| action_date   | datetime |
+---------------+----------+
(text_id, email_id) 是该表的联合主键。
signup_action 是枚举类型，取值为 Verified、Not Verified；action_date 是操作时间。
```

编写一个查询，找出在注册后**第二天完成验证**的用户 ID。

返回列：`user_id`，按 `user_id` 升序排列。

**示例 1：**

输入：

```
emails 表：
+----------+---------+---------------------+
| email_id | user_id | signup_date         |
+----------+---------+---------------------+
| 125      | 7771    | 2022-06-14 09:30:00 |
| 433      | 1052    | 2022-07-09 08:15:00 |
| 234      | 7005    | 2022-08-20 10:00:00 |
+----------+---------+---------------------+

texts 表：
+---------+----------+--------------+---------------------+
| text_id | email_id | signup_action| action_date         |
+---------+----------+--------------+---------------------+
| 1       | 125      | Verified     | 2022-06-15 08:30:00 |
| 2       | 433      | Not Verified | 2022-07-10 10:45:00 |
| 4       | 234      | Verified     | 2022-08-21 09:30:00 |
+---------+----------+--------------+---------------------+
```

输出：

```
+---------+
| user_id |
+---------+
| 7005    |
| 7771    |
+---------+
```

解释：

- 用户 7771 在 2022-06-14 注册、2022-06-15 验证，正好是注册的第二天，计入。
- 用户 1052 虽然在第二天（2022-07-10）有操作，但动作是 Not Verified，不计入。
- 用户 7005 在 2022-08-20 注册、2022-08-21 验证，计入。

## 题解

::: details 点击查看题解

### 思路

两个条件都落在两张表的连接结果上：`signup_action = 'Verified'`（已通过验证）和 `DATEDIFF(action_date, signup_date) = 1`（验证时间比注册时间晚一天）。所以直接把两表按 `email_id` 内连接，把条件写在 `ON` 里，再对 `user_id` 排序输出即可，不需要分组或去重。

`DATEDIFF(a, b)` 只比较日期部分、忽略时分秒，正好符合"第二天"的语义：2022-06-14 09:30 到 2022-06-15 08:30 只有 23 小时，但日期差是 1，仍然计入。

易错点：一是 `DATEDIFF` 的参数顺序，写反了会得到 -1；二是用 `TIMESTAMPDIFF(HOUR, ...) = 24` 之类会漏掉不足 24 小时的跨天情况；三是不加 `signup_action` 条件，会把"第二天才点但没验证成功"的用户也算进来；四是 `emails` 表的主键是 `(email_id, user_id)`，如果同一封邮件对应多个用户需要按用户去重，本题数据一对一，直接输出即可。

替代写法：`TO_DAYS(action_date) - TO_DAYS(signup_date) = 1` 与 `DATEDIFF` 等价；也可以用 `t.action_date >= e.signup_date + INTERVAL 1 DAY AND t.action_date < e.signup_date + INTERVAL 2 DAY`，但可读性差得多。

### SQL 实现

```sql
SELECT e.user_id
FROM emails AS e
JOIN texts AS t
    ON t.email_id = e.email_id
   AND t.signup_action = 'Verified'
   AND DATEDIFF(t.action_date, e.signup_date) = 1
ORDER BY e.user_id;
```

### 复杂度分析

- 时间复杂度：O(n + m)，n、m 为两张表的行数，若 `email_id` 上有索引，连接接近线性扫描。
- 空间复杂度：O(1)，除结果集外只需要常量空间。

:::

## 建表与测试数据

```sql
CREATE TABLE If not exists emails (
    email_id INT,
    user_id INT,
    signup_date DATETIME
);;
CREATE TABLE If not exists texts (
    text_id INT,
    email_id INT,
    signup_action ENUM('Verified', 'Not Verified'),
    action_date DATETIME
);;
Truncate table emails;
insert into emails (email_id, user_id, signup_date) values ('125', '7771', '2022-06-14 09:30:00');
insert into emails (email_id, user_id, signup_date) values ('433', '1052', '2022-07-09 08:15:00');
insert into emails (email_id, user_id, signup_date) values ('234', '7005', '2022-08-20 10:00:00');
Truncate table texts;
insert into texts (text_id, email_id, signup_action, action_date) values ('1', '125', 'Verified', '2022-06-15 08:30:00');
insert into texts (text_id, email_id, signup_action, action_date) values ('2', '433', 'Not Verified', '2022-07-10 10:45:00');
insert into texts (text_id, email_id, signup_action, action_date) values ('4', '234', 'Verified', '2022-08-21 09:30:00');
```
