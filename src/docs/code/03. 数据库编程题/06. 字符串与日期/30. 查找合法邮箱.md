# 查找合法邮箱

> 难度：简单 | 标签：正则匹配、字符串函数 | [LeetCode 原题](https://leetcode.cn/problems/find-valid-emails/)

## 题目描述

表：`Users`

```
+-----------------+---------+
| Column Name     | Type    |
+-----------------+---------+
| user_id         | int     |
| email           | varchar |
+-----------------+---------+
(user_id) 是这张表的唯一主键。
每一行包含用户的唯一 ID 和邮箱地址。
```

编写一个解决方案来查找所有 **合法邮箱地址**。一个合法的邮箱地址符合下述条件：

	- 只包含一个 @ 符号。

	- 以 .com 结尾。

	- @ 符号前面的部分只包含 字母数字 字符和 下划线。

	- @ 符号后面与 .com 前面的部分 包含 只有字母 的域名。

返回结果表以 `user_id` **升序** 排序。

示例：

**输入：**

Users 表：

+---------+---------------------+
| user_id | email               |
+---------+---------------------+
| 1       | alice@example.com   |
| 2       | bob_at_example.com  |
| 3       | charlie@example.net |
| 4       | david@domain.com    |
| 5       | eve@invalid         |
+---------+---------------------+

**输出：**

+---------+-------------------+
| user_id | email             |
+---------+-------------------+
| 1       | alice@example.com |
| 4       | david@domain.com  |
+---------+-------------------+

**解释：**

	- alice@example.com 是合法的因为它包含一个 @，alice 是只有字母数字的，并且 example.com 以字母开始并以 .com 结束。

	- bob_at_example.com 是不合法的因为它包含下划线但没有 @。

	- charlie@example.net 是不合法的因为域名没有以 .com 结尾。

	- david@domain.com 是合法的因为它满足所有条件。

	- eve@invalid 是不合法的因为域名没有以 .com 结尾。

结果表以 user_id 升序排序。

## 题解

::: details 点击查看题解

### 思路

四个条件其实可以合成一条锚定正则：`^[A-Za-z0-9_]+@[A-Za-z]+\\.com$`。

- `^...$` 锚定整串，避免"部分匹配"通过（比如 `xx alice@example.com yy` 这种夹在中间的内容）。
- `[A-Za-z0-9_]+` 约束 `@` 前的本地部分只能是字母、数字和下划线；因为字符组里不含 `@`，所以整串不可能出现两个 `@`，"只包含一个 @ 符号"这个条件被自动满足。
- `[A-Za-z]+` 约束 `@` 与 `.com` 之间的域名只有字母。
- `\\.com$` 要求以 `.com` 结尾，其中 `\\.` 在 SQL 字符串字面量里表示正则的 `\.`（转义点号，否则 `.` 会匹配任意字符，`x@abcXcom` 也会通过）。

最后按 `user_id` 升序输出即可。

易错点：一是漏写 `^`/`$`，`bob_at_example.com` 之外的脏数据可能部分命中；二是反斜杠转义层数搞错——SQL 字符串里写两个反斜杠，正则里才是 `\.`；三是用 `LIKE` 代替正则：`LIKE` 里 `_` 是"任意单字符"通配符，`%` 是"任意串"，没法表达"只允许下划线"，所以本题必须用 `REGEXP`；四是把域名部分写成 `[A-Za-z0-9]+` 会放过 `a@b1.com` 这类含数字的域名，题目要求域名只有字母。

补充说明：MySQL 8 的 `REGEXP` 默认大小写不敏感（取决于比较规则），所以 `[A-Za-z]` 与 `[a-z]` 在这里等价；如果确实需要区分大小写，要用 `REGEXP_LIKE(email, ..., 'c')`。

替代写法：把条件拆成多个字符串函数组合（`SUBSTRING_INDEX` 取本地部分和域名、`RIGHT(email, 4) = '.com'`、`email NOT REGEXP '[^A-Za-z0-9_@.]'`…），可读性远不如一条正则，且容易漏掉某个约束。

### SQL 实现

```sql
SELECT user_id, email
FROM Users
WHERE email REGEXP '^[A-Za-z0-9_]+@[A-Za-z]+\\.com$'
ORDER BY user_id;
```

### 复杂度分析

- 时间复杂度：O(n·L)，n 为邮箱数量、L 为邮箱平均长度，每行一次正则匹配。
- 空间复杂度：O(1)，只输出命中的行。
