# 寻找黄金时段客户

> 难度：中等 | 标签：分组聚合、日期函数、条件表达式 | [LeetCode 原题](https://leetcode.cn/problems/find-golden-hour-customers/)

## 题目描述

表：`restaurant_orders`

```
+------------------+----------+
| Column Name      | Type     |
+------------------+----------+
| order_id         | int      |
| customer_id      | int      |
| order_timestamp  | datetime |
| order_amount     | decimal  |
| payment_method   | varchar  |
| order_rating     | int      |
+------------------+----------+
order_id 是这张表的唯一主键。
payment_method 可以是 cash，card 或 app。
order_rating 在 1 到 5 之间，其中 5 是最佳（如果没有评分则是 NULL）。
order_timestamp 同时包含日期和时间信息。
```

编写一个解决方案来寻找 **黄金时间客户** - 高峰时段持续订购且满意度高的客户。客户若满足以下所有条件，则被视为 **黄金时段客户**：

	- 进行 至少 3 笔订单。

	- 他们有 至少 60% 的订单在 高峰时间 中（11:00-14:00 或 18:00-21:00）。

	- 他们的 平均评分 至少为 4.0，四舍五入到小数点后 2 位。

	- 已评价至少 50% 的订单。

返回结果表按 `average_rating` **降序** 排序，然后按 `customer_id` **降序 **排序。

结果格式如下所示。

示例：

**输入：**

restaurant_orders 表：

	- 客户 101：

		总订单数：4（至少 3 笔）

		- 高峰时间占比：0/3 = 0%（至少 60%）

		- 结果：不是黄金时段客户（高峰时段订单不足）

	- 客户 105:

		总订单数：3（至少 3 笔）

		- 高峰时间订单：3 笔中有 3 笔（12:15，13:00，11:45 都在中午高峰时间）

		- 平均评分：(4+5+4)/3 = 4.33（至少 4.0）

		- 结果：黄金时段客户

## 题解

::: details 点击查看题解

### 思路

四个筛选条件全部是客户级聚合，所以一次 `GROUP BY customer_id` 就能算出全部指标：订单总数 `COUNT(*)`；高峰单占比用 `SUM(条件)`（布尔在 MySQL 中按 1/0 求和）除以总数；平均评分 `ROUND(AVG(order_rating), 2)`——`AVG` 自动忽略 NULL，正好只对已评价订单求均值；评价完成率是 `SUM(order_rating IS NOT NULL) / COUNT(*)`。

高峰时段判断用 `TIME(order_timestamp)` 与两个闭区间比较：`BETWEEN '11:00:00' AND '14:00:00'` 或 `BETWEEN '18:00:00' AND '21:00:00'`。占比阈值「至少 60%」写成 `5 * 高峰单数 >= 3 * 总单数` 的整数比较，避免浮点误差与除零问题。

易错点有三个：一是「平均评分至少 4.0」要用四舍五入后的 `average_rating` 判断（MySQL 的 HAVING 可以直接引用 SELECT 别名，且别名求值在 WHERE 之后，等价于对 ROUND 结果过滤）；二是评价完成率的分母是全部订单、分子是未评价为 NULL 的订单数，别误写成 `AVG(order_rating IS NOT NULL)` 之外的形式；三是排序必须两级 `average_rating DESC, customer_id DESC`，样例中 103 与 101 同为 4.67，靠第二关键字才得到正确顺序。另外输出的 `peak_hour_percentage` 按官方解法四舍五入为整数（`ROUND(x / COUNT(*) * 100)`）。

替代写法：先用子查询算出 `is_peak`、`is_rated` 两个布尔列再聚合，逻辑一样但多一层嵌套；条件也可以全部放进 HAVING 用相关子查询写，效率更差。

### SQL 实现

```sql
SELECT customer_id,
       COUNT(*) AS total_orders,
       ROUND(
           SUM(TIME(order_timestamp) BETWEEN '11:00:00' AND '14:00:00'
             OR TIME(order_timestamp) BETWEEN '18:00:00' AND '21:00:00')
           / COUNT(*) * 100
       ) AS peak_hour_percentage,
       ROUND(AVG(order_rating), 2) AS average_rating
FROM restaurant_orders
GROUP BY customer_id
HAVING total_orders >= 3
   AND 5 * SUM(TIME(order_timestamp) BETWEEN '11:00:00' AND '14:00:00'
             OR TIME(order_timestamp) BETWEEN '18:00:00' AND '21:00:00')
       >= 3 * COUNT(*)
   AND average_rating >= 4.0
   AND SUM(order_rating IS NOT NULL) >= 0.5 * COUNT(*)
ORDER BY average_rating DESC, customer_id DESC;
```

### 复杂度分析

- 时间复杂度：O(n log n)，n 为订单行数，分组为 O(n)，排序为 O(k log k)（k 为客户数）。
- 空间复杂度：O(k)，k 为客户数，用于分组结果与排序。
