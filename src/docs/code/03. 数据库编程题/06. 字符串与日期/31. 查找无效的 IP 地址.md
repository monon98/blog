# 查找无效的 IP 地址

> 难度：困难 | 标签：正则匹配、分组聚合、字符串函数 | [LeetCode 原题](https://leetcode.cn/problems/find-invalid-ip-addresses/)

## 题目描述

表：`logs`

```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| log_id      | int     |
| ip          | varchar |
| status_code | int     |
+-------------+---------+
log_id 是这张表的唯一主键。
每一行包含服务器访问日志信息，包括 IP 地址和 HTTP 状态码。
```

编写一个解决方案来查找 **无效的 IP 地址**。每个 IP 地址中的八位字节包含 `1` 到 `3` 位数字。一个 IPv4 地址如果满足以下任何条件之一，则无效：

	- 任何 8 位字节中包含 大于 255 的数字

	- 任何 8 位字节中含有 前导零（如 01.02.03.04）

	- 少于或多于 4 个 8 位字节

返回结果表分别以 `invalid_count`，`ip` **降序** 排序。

结果格式如下所示。

示例：

**输入：**

logs 表：

+--------+---------------+-------------+
| log_id | ip            | status_code |
+--------+---------------+-------------+
| 1      | 192.168.1.1   | 200         |
| 2      | 256.1.2.3     | 404         |
| 3      | 192.168.001.1 | 200         |
| 4      | 192.168.1.1   | 200         |
| 5      | 192.168.1     | 500         |
| 6      | 256.1.2.3     | 404         |
| 7      | 192.168.001.1 | 200         |
+--------+---------------+-------------+

**输出：**

+---------------+--------------+
| ip            | invalid_count|
+---------------+--------------+
| 256.1.2.3     | 2            |
| 192.168.001.1 | 2            |
| 192.168.1     | 1            |
+---------------+--------------+

**解释：**

	- 256.1.2.3 是无效的，因为 256 > 255

	- 192.168.001.1 是无效的，因为有前导零

	- 192.168.1 是非法的，因为只有 3 个 8 位字节

输出表分别以 `invalid_count`，`ip` 降序排序。

## 题解

::: details 点击查看题解

### 思路

三个无效条件（超 255、前导零、不是恰好 4 段）其实可以合并成一条「合法 IPv4」正则，取反即为非法：`ip NOT REGEXP 合法模式`。单个八位字节的合法形式为 `25[0-5]|2[0-4][0-9]|1[0-9]{2}|[1-9][0-9]|[1-9]|0`，分别覆盖 250-255、200-249、100-199、10-99、1-9、0 六段，天然排除了前导零（如 `001` 无法被任何分支匹配）和大于 255 的值；外层用 `(八位字节\.){3}八位字节` 锚定 `^...$`，恰好要求 4 段，段数不足或超出都会匹配失败。

易错点有三个：一是漏掉 `^`、`$` 锚定，`1.2.3.4.5` 里的一段会被部分匹配放过去；二是正则里 `.` 必须写成 `\\.`（SQL 字符串字面量中两个反斜杠才表示正则的 `\.`），否则 `.` 匹配任意字符；三是不要试图先 `GROUP BY ip` 再判断，判断必须在行级完成，分组只用于统计出现次数。

替代写法：用 `SUBSTRING_INDEX` 依次切出四段，判断段数（点号个数）与每段 `CAST(... AS UNSIGNED) <= 255` 及前导零，逻辑同样清晰但代码更长，还需要单独处理段数不足时切片结果重复的问题。

### SQL 实现

```sql
SELECT ip, COUNT(*) AS invalid_count
FROM logs
WHERE ip NOT REGEXP '^(25[0-5]|2[0-4][0-9]|1[0-9]{2}|[1-9][0-9]|[1-9]|0)(\\.(25[0-5]|2[0-4][0-9]|1[0-9]{2}|[1-9][0-9]|[1-9]|0)){3}$'
GROUP BY ip
ORDER BY invalid_count DESC, ip DESC;
```

### 复杂度分析

- 时间复杂度：O(n·L)，n 为日志行数、L 为 IP 平均长度，每行执行一次正则匹配后哈希分组。
- 空间复杂度：O(k)，k 为不同的非法 IP 数量。

:::
