# 查找活跃用户

> 难度：中等 | 标签：窗口函数、日期函数 | [LeetCode 原题](https://leetcode.cn/problems/find-active-users/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

`Users` 表：

```
+-------------+----------+
| Column Name | Type     |
+-------------+----------+
| user_id     | int      |
| item        | varchar  |
| created_at  | date     |
| amount      | int      |
+-------------+----------+
这张表可能包含重复记录。每一行包括用户 ID、购买的商品、购买日期和购买金额。
```

编写一个解决方案找出**活跃用户**。活跃用户是指在其任何一次购买之后的**七天内**进行了第二次购买的用户。也就是说，同一用户存在两笔购买，日期相差不超过 7 天（含首尾两天）。返回任意顺序的 `user_id` 列表。

**示例 1：**

```
输入：
Users 表：
+---------+-------------------+------------+--------+
| user_id | item              | created_at | amount |
+---------+-------------------+------------+--------+
| 5       | Smart Crock Pot   | 2021-09-18 | 698882 |
| 6       | Smart Lock        | 2021-09-14 | 11487  |
| 6       | Smart Thermostat  | 2021-09-10 | 674762 |
| 8       | Smart Light Strip | 2021-09-29 | 630773 |
| 4       | Smart Cat Feeder  | 2021-09-02 | 693545 |
| 4       | Smart Bed         | 2021-09-13 | 170249 |
+---------+-------------------+------------+--------+
输出：
+---------+
| user_id |
+---------+
| 6       |
+---------+
解释：
用户 5 只有一笔购买，不是活跃用户。
用户 6 有两笔购买（2021-09-10 与 2021-09-14），间隔 4 天，是活跃用户。
用户 8 只有一笔购买，不是活跃用户。
用户 4 有两笔购买（2021-09-02 与 2021-09-13），间隔 11 天，不是活跃用户。
```

## 题解

::: details 点击查看题解

### 思路

这题和「7 天内两次购买的用户」是同一类问题：判定条件是「存在两笔间隔 ≤ 7 天的购买」。既然只要求存在性，把同一用户的购买按日期排序后，**相邻两笔**的间隔就是最短的候选，检查相邻即可，无需两两配对。

实现上按 `user_id` 分区、`created_at` 排序取 `LAG`，`DATEDIFF(created_at, 上一笔) <= 7` 即命中。三点注意：分区键必须是 `user_id`，否则会跨用户比较出假的「活跃」；`DATEDIFF` 的参数顺序不能反（反了得到负数，条件恒真）；首行的 `LAG` 是 `NULL`，比较结果为 `UNKNOWN`，自动被过滤，不用写 `IS NOT NULL`，但为了可读性也可以补上。

边界语义要留意：题目说的是「7 天内，含首尾两天」，所以间隔正好 7 天算活跃（`<= 7`），间隔 0（同一天两笔）也算。数据里用户 4 的 11 天正好作为反例，若把阈值写成 `<= 8` 就会误判。另外表里可能重复记录（同一用户同一天多笔），窗口函数天然处理，不需要先 `DISTINCT` 去重——反过来若先按 `(user_id, created_at)` 去重，同一天重复购买的情况仍然存在（仍有两条相同日期），结果不受影响。

因为有 `DISTINCT user_id`，外层用 `IN` 子查询或直接套派生表都可以；这里用派生表 + `DISTINCT` 最直白。

### SQL 实现

```sql
SELECT DISTINCT user_id
FROM (
    SELECT user_id,
           DATEDIFF(created_at,
                    LAG(created_at) OVER (PARTITION BY user_id ORDER BY created_at)) AS diff
    FROM Users
) t
WHERE diff <= 7;
```

### 复杂度分析

- 时间复杂度：O(n log n)，n 为购买记录数，窗口排序为主开销。
- 空间复杂度：O(n)，中间结果与去重集合。

:::
