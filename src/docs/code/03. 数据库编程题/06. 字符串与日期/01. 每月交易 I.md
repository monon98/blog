# 每月交易 I

> 难度：中等 | 标签：分组聚合、日期函数 | [LeetCode 原题](https://leetcode.cn/problems/monthly-transactions-i/)

## 题目描述

表：`Transactions`

```
+---------------+---------+
| Column Name   | Type    |
+---------------+---------+
| id            | int     |
| country       | varchar |
| state         | enum    |
| amount        | int     |
| trans_date    | date    |
+---------------+---------+
id 是这个表的主键。
该表包含有关传入事务的信息。
state 列类型为 ["approved", "declined"] 之一。
```

编写一个 sql 查询来查找每个月和每个国家/地区的事务数及其总金额、已批准的事务数及其总金额。

以 **任意顺序** 返回结果表。

查询结果格式如下所示。

**示例 1:**

```
输入：
Transactions table:
+------+---------+----------+--------+------------+
| id   | country | state    | amount | trans_date |
+------+---------+----------+--------+------------+
| 121  | US      | approved | 1000   | 2018-12-18 |
| 122  | US      | declined | 2000   | 2018-12-19 |
| 123  | US      | approved | 2000   | 2019-01-01 |
| 124  | DE      | approved | 2000   | 2019-01-07 |
+------+---------+----------+--------+------------+
输出：
+----------+---------+-------------+----------------+--------------------+-----------------------+
| month    | country | trans_count | approved_count | trans_total_amount | approved_total_amount |
+----------+---------+-------------+----------------+--------------------+-----------------------+
| 2018-12  | US      | 2           | 1              | 3000               | 1000                  |
| 2019-01  | US      | 1           | 1              | 2000               | 2000                  |
| 2019-01  | DE      | 1           | 1              | 2000               | 2000                  |
+----------+---------+-------------+----------------+--------------------+-----------------------+
```

## 题解

::: details 点击查看题解

### 思路

分组键是「月份 × 国家」，但表里只有精确到日的 `trans_date`，直接 `GROUP BY trans_date` 会按天拆开，必须先用 `DATE_FORMAT(trans_date, '%Y-%m')` 把日期截断到月。`%Y-%m` 而不是 `%Y%m`，是因为题目输出带连字符，日期格式化顺便一次到位，比 `CONCAT(YEAR(..), '-', MONTH(..))` 少一次拼接，且月份会自动补零。

四个指标里两个是「全部」、两个是「仅 approved」，用条件聚合一次算出即可：`SUM(state = 'approved')` 统计已批准笔数（布尔值 0/1 求和），`SUM(CASE WHEN state = 'approved' THEN amount ELSE 0 END)` 统计已批准金额。金额列一定要给 `ELSE 0`，让未批准的行贡献 0；如果省略 `ELSE`，`CASE` 返回 `NULL`，`SUM` 会自动跳过，结果数值上恰好相同，但可读性差且与 `COUNT` 混用时容易出错。

易错点：`GROUP BY` 里写别名 `month` 在 MySQL 中合法（标准 SQL 也允许按输出列名分组），但有些引擎不允许，写 `GROUP BY DATE_FORMAT(trans_date, '%Y-%m'), country` 更保险。另外这只是「每月交易 I」，如果还需要把退单（chargeback）也统计进来就是另一道题的写法，两者不要混。

### SQL 实现

```sql
SELECT DATE_FORMAT(trans_date, '%Y-%m')                        AS month,
       country,
       COUNT(*)                                                AS trans_count,
       SUM(state = 'approved')                                 AS approved_count,
       SUM(amount)                                             AS trans_total_amount,
       SUM(CASE WHEN state = 'approved' THEN amount ELSE 0 END) AS approved_total_amount
FROM Transactions
GROUP BY month, country;
```

### 复杂度分析

- 时间复杂度：O(n)，n 为交易行数，一次扫描 + 哈希分组。
- 空间复杂度：O(g)，g 为「月份 × 国家」分组数。
