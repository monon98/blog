# 查找突发行为

> 难度：中等 | 标签：窗口函数、日期区间匹配 | [LeetCode 原题](https://leetcode.cn/problems/find-bursty-behavior/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

`Posts` 表：

```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| post_id     | int     |
| user_id     | int     |
| post_date   | date    |
+-------------+---------+
post_id 是该表具有唯一值的列。
每一行包含帖子 ID、发布者 ID 和发布日期。
```

请找出 2024 年 2 月里表现出**突发行为**（bursty behavior）的用户。突发行为的定义是：存在某个**连续 7 天**的时间段，该用户在其中的发帖数**至少是其 2 月平均每周发帖数的 2 倍**。

分析时只统计 2024-02-01 到 2024-02-28 的日期，2 月按**正好 4 周**计算，即平均每周发帖数 = 2 月发帖总数 / 4。

返回列：`user_id`、`max_7day_posts`（任意连续 7 天内的最大发帖数）、`avg_weekly_posts`（2 月平均每周发帖数），按 `user_id` 升序排列。

**示例 1：**

输入：

```
Posts 表：
+---------+---------+------------+
| post_id | user_id | post_date  |
+---------+---------+------------+
| 1       | 1       | 2024-02-27 |
| 2       | 5       | 2024-02-06 |
| 3       | 3       | 2024-02-25 |
| 4       | 3       | 2024-02-14 |
| 5       | 3       | 2024-02-06 |
| 6       | 2       | 2024-02-25 |
+---------+---------+------------+
```

输出：

```
+---------+----------------+------------------+
| user_id | max_7day_posts | avg_weekly_posts |
+---------+----------------+------------------+
| 1       | 1              | 0.2500           |
| 2       | 1              | 0.2500           |
| 5       | 1              | 0.2500           |
+---------+----------------+------------------+
```

解释：

- 用户 1、2、5 在 2 月各只发了 1 条帖子，平均每周 0.25 条，任意 7 天窗口内最多 1 条，满足 1 >= 2 × 0.25。
- 用户 3 发了 3 条帖子（2 月 6 日、14 日、25 日），平均每周 0.75 条；但这三条两两相隔超过 7 天，任意 7 天窗口内最多只有 1 条，1 < 2 × 0.75 = 1.5，因此不算突发行为。

## 题解

::: details 点击查看题解

### 思路

题目要同时算两件事：一是"每个用户任意 7 天滑动窗口内的最大发帖数"，二是"2 月平均每周发帖数"，最后用后者筛前者。平均每周发帖数很直接：`COUNT(*) / 4`，注意题目把 2 月固定当 4 周，所以不要除以真实周数（28/7 恰好也是 4，但换个月就错）。

滑动窗口用窗口函数最省事：`COUNT(*) OVER (PARTITION BY user_id ORDER BY post_date RANGE BETWEEN INTERVAL 6 DAY PRECEDING AND CURRENT ROW)`。这里必须用 `RANGE` 而不是 `ROWS`——`ROWS` 按行数取前缀，`RANGE ... INTERVAL 6 DAY` 才是按**日期值**取"当天及之前 6 天"这个真正的 7 天窗口。窗口右端固定为当前行，因此每一行都代表一个以该天为结束日的 7 天窗口，取 `MAX()` 就得到用户的最大窗口发帖数。

易错点：一是 `RANGE` 帧要求排序列是日期/数值类型，直接对 `post_date` 用即可；二是比较时写 `>= 2 * avg`，`avg_weekly_posts` 是 `DECIMAL`，别用整数除法把它算成 0；三是 `0.2500` 这种四位小数来自 `COUNT(*) / 4` 的除法精度，`ROUND` 反而会改变格式；四是过滤日期要写在窗口之前（子查询里），否则窗口会把 2 月以外的数据也计入。

替代写法：经典的自连接——`Posts p1 JOIN Posts p2 ON p1.user_id = p2.user_id AND p2.post_date BETWEEN p1.post_date AND p1.post_date + INTERVAL 6 DAY`，再按 `(user_id, p1.post_id)` 分组计数取最大值，思路相同但复杂度是 O(n²)。

### SQL 实现

```sql
WITH windows_7d AS (
    SELECT user_id,
           post_date,
           COUNT(*) OVER (
               PARTITION BY user_id
               ORDER BY post_date
               RANGE BETWEEN INTERVAL 6 DAY PRECEDING AND CURRENT ROW
           ) AS cnt
    FROM Posts
    WHERE post_date BETWEEN '2024-02-01' AND '2024-02-28'
),
mx AS (
    SELECT user_id, MAX(cnt) AS max_7day_posts
    FROM windows_7d
    GROUP BY user_id
),
avg_weekly AS (
    SELECT user_id, COUNT(*) / 4 AS avg_weekly_posts
    FROM Posts
    WHERE post_date BETWEEN '2024-02-01' AND '2024-02-28'
    GROUP BY user_id
)
SELECT m.user_id,
       m.max_7day_posts,
       a.avg_weekly_posts
FROM mx AS m
JOIN avg_weekly AS a USING (user_id)
WHERE m.max_7day_posts >= 2 * a.avg_weekly_posts
ORDER BY m.user_id;
```

### 复杂度分析

- 时间复杂度：O(n log n)，窗口函数需要按 `(user_id, post_date)` 排序。
- 空间复杂度：O(n)，窗口中间结果与聚合结果各占 O(n)。
