# 7 天内两次购买的用户

> 难度：中等 | 标签：窗口函数、日期函数 | [LeetCode 原题](https://leetcode.cn/problems/users-with-two-purchases-within-seven-days/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

`Purchases` 表：

```
+---------------+------+
| Column Name   | Type |
+---------------+------+
| purchase_id   | int  |
| user_id       | int  |
| purchase_date | date |
+---------------+------+
purchase_id 包含唯一值，该表记录了用户的购买日期日志。
```

编写一个解决方案，找出**最多间隔 7 天**完成过两次购买的用户 id。也就是：同一用户存在两笔购买（可以是同一天的两笔），它们的 `purchase_date` 相差不超过 7 天。结果按 `user_id` 排序。

**示例 1：**

```
输入：
Purchases 表：
+-------------+---------+---------------+
| purchase_id | user_id | purchase_date |
+-------------+---------+---------------+
| 4           | 2       | 2022-03-13    |
| 1           | 5       | 2022-02-11    |
| 3           | 7       | 2022-06-19    |
| 6           | 2       | 2022-03-20    |
| 5           | 7       | 2022-06-19    |
| 2           | 2       | 2022-06-08    |
+-------------+---------+---------------+
输出：
+---------+
| user_id |
+---------+
| 2       |
| 7       |
+---------+
解释：
用户 2 在 2022-03-13 与 2022-03-20 各购买一次，相差 7 天，符合条件。
用户 5 只购买过 1 次，不符合条件。
用户 7 在同一天（2022-06-19）有两次购买，相差 0 天，符合条件。
```

## 题解

::: details 点击查看题解

### 思路

「存在两笔购买间隔不超过 7 天」听起来要两两配对，但对日期排序后的相邻两笔做比较就够了：如果存在任何一对间隔 ≤ 7 天，那么把该用户所有购买按日期排序后，必然存在某一对**相邻**购买间隔也 ≤ 7 天（中间再多几笔只会让间隔更小）。所以不必自连接成笛卡尔积，用 `LAG` 取「上一笔购买日期」即可，复杂度从 O(k²) 降到 O(k)。

几个细节决定成败。第一，`LAG` 必须按 `user_id` 分区、按 `purchase_date` 排序，否则会跨用户比较，把不同用户的日期混在一起。第二，比较要用 `DATEDIFF(当前, 上一笔)`，顺序反过来会得到负数，`<= 7` 就恒成立。第三，间隔 0 也要算——用户 7 在同一天有两笔（`purchase_id` 3 和 5），题目明确把这种情况视为「7 天内」；如果写 `BETWEEN 1 AND 7` 就会漏掉它。第四，每个用户的第一笔没有「上一笔」，`LAG` 返回 `NULL`，`NULL <= 7` 结果是 `UNKNOWN`（不成立），天然被过滤，不用额外处理。

最后要 `DISTINCT`：一个用户可能有多对相邻购买都满足条件，会重复出现多行。

替代写法：自连接 `JOIN ... ON a.user_id = b.user_id AND a.purchase_id <> b.purchase_id AND DATEDIFF(b.purchase_date, a.purchase_date) BETWEEN 0 AND 7`，逻辑直观但在购买记录多时是平方级；另有 `COUNT(*) OVER (RANGE BETWEEN ...)` 的区间计数思路，写起来更绕。

### SQL 实现

```sql
WITH t AS (
    SELECT user_id,
           DATEDIFF(purchase_date,
                    LAG(purchase_date) OVER (PARTITION BY user_id ORDER BY purchase_date)) AS diff
    FROM Purchases
)
SELECT DISTINCT user_id
FROM t
WHERE diff <= 7
ORDER BY user_id;
```

### 复杂度分析

- 时间复杂度：O(n log n)，n 为购买记录数，窗口排序为主开销。
- 空间复杂度：O(n)，中间结果与去重集合。
