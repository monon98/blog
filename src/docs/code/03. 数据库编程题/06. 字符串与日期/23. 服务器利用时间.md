# 服务器利用时间

> 难度：中等 | 标签：窗口函数、日期时间函数、嵌套区间匹配 | [LeetCode 原题](https://leetcode.cn/problems/server-utilization-time/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

`Servers` 表：

```
+----------------+----------+
| Column Name    | Type     |
+----------------+----------+
| server_id      | int      |
| status_time    | datetime |
| session_status | enum     |
+----------------+----------+
(server_id, status_time, session_status) 是该表的联合主键。
session_status 是枚举类型，取值为 start、stop。
每一行记录某台服务器在某时刻开始或结束一段运行会话。
```

编写一个查询，计算所有服务器**累计运行时间**，并把结果向下取整到**整天**。

返回列：`total_uptime_days`，顺序不限。

注意：同一台服务器的 start/stop 可能**嵌套**——上一次 start 还没被 stop 关闭时，又出现了一次 start（见示例中 server 3 的数据）。配对时按"栈"的语义：一次 start 由它之后第一个把深度降回上一层的 stop 关闭。

**示例 1（节选，完整数据见下方建表语句）：**

```
Servers 表：
+-----------+---------------------+----------------+
| server_id | status_time         | session_status |
+-----------+---------------------+----------------+
| 3         | 2023-11-04 16:29:47 | start          |
| 3         | 2023-11-04 23:16:48 | start          |
| 3         | 2023-11-05 01:15:48 | stop           |
| 3         | 2023-11-05 01:49:47 | stop           |
| 1         | 2023-11-13 03:05:31 | start          |
| 1         | 2023-11-13 11:10:31 | stop           |
+-----------+---------------------+----------------+
```

输出：

```
+-------------------+
| total_uptime_days |
+-------------------+
| 11                |
+-------------------+
```

解释：

- server 3 的四行是一段嵌套会话：23:16:48 的 start 先被 01:15:48 的 stop 关闭，16:29:47 的 start 被 01:49:47 的 stop 关闭，两段分别约 1.98 小时和 9.33 小时。
- 全部服务器、全部会话的秒数加起来约 1031880 秒，即 11.94 天，向下取整得到 11 天。

## 题解

::: details 点击查看题解

### 思路

如果数据保证 start/stop 严格交替，用 `LEAD()` 把下一行的 stop 配过来就行。但这题的数据里存在**嵌套**（同一台服务器在两段会话重叠的区间内又 start 了一次），简单配对会把区间算错：要么把内层 start 配到了外层 stop，要么重复计算重叠部分。

稳妥的做法是先用运行深度标记层级：按 `(server_id, status_time)` 排序，start 记 +1、stop 记 -1，前到当前行的累加和就是"当前有几层会话在跑"。那么一次 start（深度 d）对应的 stop，就是它之后**第一个深度为 d-1 的 stop**——这正是栈式（LIFO）配对，嵌套时内层先关、外层后关。把这 58 段区间的秒数求和，最后 `FLOOR(总秒数 / 86400)` 得到整天数。

实现上用两个窗口/连接组合：CTE `depth` 算出每行的深度，然后深度的表自连接，对每个 start 取满足条件的 stop 中时间最早的那个（`MIN(t.status_time)`）。

易错点：一是直接用 `TIMESTAMPDIFF(MINUTE, ...)` 再除，精度和取整方向会出错，应该用 `SECOND` 最后统一 `FLOOR`；二是深度排序要带上 `session_status` 作为次序键，保证同一时刻 start 排在 stop 前面；三是配对条件必须有 `t.status_time > s.status_time`，否则会匹配到自己或更早的 stop；四是 `FLOOR` 而不是 `ROUND`——题目要求向下取整。

替代写法：如果确认数据不嵌套，可以直接 `LEAD(status_time) OVER (PARTITION BY server_id ORDER BY status_time)` 取下一个时间点，再对 `session_status = 'start'` 的行求差值；本例数据嵌套，这样写会得到 11.34 天，取整后同样是 11，但语义上是错的。

### SQL 实现

```sql
WITH depth AS (
    SELECT server_id,
           status_time,
           session_status,
           SUM(IF(session_status = 'start', 1, -1)) OVER (
               PARTITION BY server_id
               ORDER BY status_time, session_status
               ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
           ) AS d
    FROM Servers
),
pairs AS (
    SELECT s.status_time AS start_time,
           MIN(t.status_time) AS stop_time
    FROM depth AS s
    JOIN depth AS t
        ON t.server_id = s.server_id
       AND t.session_status = 'stop'
       AND t.d = s.d - 1
       AND t.status_time > s.status_time
    WHERE s.session_status = 'start'
    GROUP BY s.server_id, s.status_time
)
SELECT FLOOR(SUM(TIMESTAMPDIFF(SECOND, start_time, stop_time)) / 86400) AS total_uptime_days
FROM pairs;
```

### 复杂度分析

- 时间复杂度：O(n log n)，n 为状态记录数，窗口排序加自连接（可用索引优化到 O(n log n)）。
- 空间复杂度：O(n)，深度表需要物化 n 行。
