# 修复表中的名字

> 难度：简单 | 标签：字符串函数 | [LeetCode 原题](https://leetcode.cn/problems/fix-names-in-a-table/)

## 题目描述

表： `Users`

```
+----------------+---------+
| Column Name    | Type    |
+----------------+---------+
| user_id        | int     |
| name           | varchar |
+----------------+---------+
user_id 是该表的主键(具有唯一值的列)。
该表包含用户的 ID 和名字。名字仅由小写和大写字符组成。
```

编写解决方案，修复名字，使得只有第一个字符是大写的，其余都是小写的。

返回按 `user_id` 排序的结果表。

返回结果格式示例如下。

示例 1：

```
输入：
Users table:
+---------+-------+
| user_id | name  |
+---------+-------+
| 1       | aLice |
| 2       | bOB   |
+---------+-------+
输出：
+---------+-------+
| user_id | name  |
+---------+-------+
| 1       | Alice |
| 2       | Bob   |
+---------+-------+
```

## 题解

::: details 点击查看题解

### 思路

目标是「首字母大写 + 其余小写」，所以要把字符串拆成两段分别处理再拼回去：`LEFT(name, 1)` 取首字符做 `UPPER`，`SUBSTRING(name, 2)` 取剩下的全部做 `LOWER`，最后 `CONCAT` 拼接。

不能直接对整串 `UPPER` 或 `LOWER`——那样 `aLice` 会变成 `ALICE` 或 `alice`，都不符合要求。也不要用 `INITCAP`：MySQL 没有这个函数（Oracle/PostgreSQL 才有），照抄会报 function does not exist。

`SUBSTRING(name, 2)` 在名字只有一个字符时返回空串，而 MySQL 的 `CONCAT` 遇到 `NULL` 才会传染，空串拼接是安全的，所以单字符名字不会出问题；但如果 `name` 可能是 `NULL`，`UPPER(NULL)` 会让整列变 `NULL`，需要 `COALESCE` 兜底（本题数据保证有值，可以不管）。另外注意 `CHAR_LENGTH` 与 `LENGTH` 的区别：这里用 `LEFT`/`SUBSTRING` 是按字符而非字节切，函数本身已按字符集处理，不需要自己算长度。

替代写法：`CONCAT(UPPER(SUBSTR(name, 1, 1)), LOWER(SUBSTR(name, 2)))` 完全等价，`SUBSTR` 是 `SUBSTRING` 的简写；也可以用 `INSERT` 直接替换首字符，但可读性不如拼接。

### SQL 实现

```sql
SELECT user_id,
       CONCAT(UPPER(LEFT(name, 1)), LOWER(SUBSTRING(name, 2))) AS name
FROM Users
ORDER BY user_id;
```

### 复杂度分析

- 时间复杂度：O(n · L)，n 为用户数、L 为名字长度，逐行做常数次字符串函数；末尾排序 O(n log n)。
- 空间复杂度：O(1)，不引入额外结构（结果集除外）。

