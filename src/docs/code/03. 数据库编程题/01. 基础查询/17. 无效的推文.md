# 无效的推文

> 难度：简单 | 标签：条件筛选、字符串函数 | [LeetCode 原题](https://leetcode.cn/problems/invalid-tweets/)

## 题目描述

表：`Tweets`

```
+----------------+---------+
| Column Name    | Type    |
+----------------+---------+
| tweet_id       | int     |
| content        | varchar |
+----------------+---------+
在 SQL 中，tweet_id 是这个表的主键。
content 只包含字母数字字符，'!'，' '，不包含其它特殊字符。
这个表包含某社交媒体 App 中所有的推文。
```

查询所有无效推文的编号（ID）。当推文内容中的字符数**严格大于** `15` 时，该推文是无效的。

以**任意顺序**返回结果表。

查询结果格式如下所示：

**示例 1：**

```
输入：
Tweets 表：
+----------+----------------------------------+
| tweet_id | content                          |
+----------+----------------------------------+
| 1        | Vote for Biden                   |
| 2        | Let us make America great again! |
+----------+----------------------------------+

输出：
+----------+
| tweet_id |
+----------+
| 2        |
+----------+
解释：
推文 1 的长度 length = 14。该推文是有效的。
推文 2 的长度 length = 32。该推文是无效的。
```

## 题解

::: details 点击查看题解

### 思路

这是一道单表过滤题：拿到「长度严格大于 15」的行，返回 `tweet_id` 即可。关键在「严格大于」四个字——边界值 15 本身是**有效**推文，条件必须写 `> 15`，写成 `>= 15` 就会把刚好 15 字符的推文误判为无效。

长度函数的选择是个易错点：MySQL 里 `LENGTH()` 返回的是**字节数**，`CHAR_LENGTH()` 返回的是**字符数**。本题 `content` 只含字母数字、`!` 和空格，全为单字节字符，两个函数结果完全相同，写哪个都能通过；但如果推文里出现中文等多字节字符，`LENGTH('你好')` 会返回 6 而不是 2，届时必须用 `CHAR_LENGTH()` 才符合「字符数」的题意。

本题只需过滤、无需去重（`tweet_id` 是主键），也无需排序（结果任意顺序）。替代写法：`WHERE CHAR_LENGTH(content) > 15`，或用 `BINARY` 比较之类的技巧，没必要。

### SQL 实现

```sql
SELECT tweet_id
FROM Tweets
WHERE CHAR_LENGTH(content) > 15;
```

### 复杂度分析

- 时间复杂度：O(n)，n 为推文数，逐行计算长度并过滤。
- 空间复杂度：O(1)，除结果集外只需常数额外空间。

:::
