# 查找高 tokens 使用量的用户

> 难度：简单 | 标签：分组聚合、HAVING、排序 | [LeetCode 原题](https://leetcode.cn/problems/find-users-with-high-token-usage/)

## 题目描述

表：`prompts`

```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| user_id     | int     |
| prompt      | varchar |
| tokens      | int     |
+-------------+---------+
(user_id, prompt) 是这张表的主键（值互不相同）。
每一行表示一个用户提交给 AI 系统的提示词以及所消耗的 token 数量。
```

根据下列要求编写一个解决方案来分析 **AI 提示词的使用模式**：

	- 对每一个用户，计算他们提交的 提示词的总数。

	- 对每个用户，计算 每个提示词所使用的平均 token 数（舍入到 2 位小数）。

	- 仅包含 至少提交了 3 个提示词 的用户。

	- 仅包含那些 至少提交过一个提示词 且该提示词的 tokens 数量 超过 自己平均 token 使用量的用户。

返回结果表按 **平均 token 数 降序** 排序，然后按* *`user_id` **升序** 排序。

结果格式如下所示。

示例：

**输入：**

prompts 表：

+---------+--------------------------+--------+
| user_id | prompt                   | tokens |
+---------+--------------------------+--------+
| 1       | Write a blog outline     | 120    |
| 1       | Generate SQL query       | 80     |
| 1       | Summarize an article     | 200    |
| 2       | Create resume bullet     | 60     |
| 2       | Improve LinkedIn bio     | 70     |
| 3       | Explain neural networks  | 300    |
| 3       | Generate interview Q&A   | 250    |
| 3       | Write cover letter       | 180    |
| 3       | Optimize Python code     | 220    |
+---------+--------------------------+--------+

**输出：**

+---------+---------------+------------+
| user_id | prompt_count  | avg_tokens |
+---------+---------------+------------+
| 3       | 4             | 237.5      |
| 1       | 3             | 133.33     |
+---------+---------------+------------+

**解释：**

	- 用户 1：

		总提示词数 = 3

		- 平均 token 数 = (120 + 80 + 200) / 3 = 133.33

		- 有一个提示词为 200 个 token，这超过了平均值

		- 包含在结果中

	- 用户 2:

		总提示词数 = 2（少于所需的最小值）

		- 从结果中排除

	- 用户 3:

		总提示词数 = 4

		- 平均 token 数 = (300 + 250 + 180 + 220) / 4 = 237.5

		- 有包含 300 和 250 个 token 的提示词，都大于平均数

		- 包含在结果中

结果表按 avg_tokens 降序排序，然后按 user_id 升序排序。

## 题解

::: details 点击查看题解

### 思路

四个要求里三个是分组聚合（`COUNT(*)`、`AVG(tokens)`、`ROUND(..., 2)`），真正的难点是第四个：「存在某个提示词的 tokens **超过本人平均值**」——这是对**组内每一行**的判断，而 `WHERE` 里不能出现聚合函数，所以必须放进 `HAVING`。

关键观察：组内只要**最大值**超过平均值，就必然存在超过平均值的行；反之若最大值都不超过平均值，则所有行都 `<=` 平均值，也就不存在严格超过的行（全相等时最大值 = 平均值，同样不满足「严格超过」）。于是条件可以化简成 `MAX(tokens) > AVG(tokens)`，一行搞定，无需相关子查询或窗口函数。如果硬要写成「每行和平均值比」，就得用 `AVG(tokens) OVER (PARTITION BY user_id)` 开窗口再外层过滤，代码量翻倍。

其余细节：`ROUND(AVG(tokens), 2)` 负责「舍入到 2 位小数」；提示词总数条件 `COUNT(*) >= 3`（注意是「至少 3 个」，`>` 和 `>=` 别写反，用户 2 恰好 2 条被排除）；排序按 `avg_tokens` 降序、`user_id` 升序，两个关键字都要写，`ORDER BY` 里引用别名即可（引用的是四舍五入后的值，与按原始均值排序在本题数据下结果一致）。用户 1、3 都满足「有行超过均值」，用户 2 因条数不够先被过滤，均值再高也不参与。

### SQL 实现

```sql
SELECT user_id,
       COUNT(*) AS prompt_count,
       ROUND(AVG(tokens), 2) AS avg_tokens
FROM prompts
GROUP BY user_id
HAVING COUNT(*) >= 3
   AND MAX(tokens) > AVG(tokens)
ORDER BY avg_tokens DESC, user_id ASC;
```

### 复杂度分析

- 时间复杂度：O(n log n)，n 为提示词条数，分组聚合 O(n)，组内比较均值与最大值 O(n)，排序最多 g log g（g 为用户数）。
- 空间复杂度：O(g)，分组哈希表规模与用户数同阶。

:::
