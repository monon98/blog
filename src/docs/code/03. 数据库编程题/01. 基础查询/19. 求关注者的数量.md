# 求关注者的数量

> 难度：简单 | 标签：分组聚合、排序 | [LeetCode 原题](https://leetcode.cn/problems/find-followers-count/)

## 题目描述

表： `Followers`

```
+-------------+------+
| Column Name | Type |
+-------------+------+
| user_id     | int  |
| follower_id | int  |
+-------------+------+
(user_id, follower_id) 是这个表的主键（具有唯一值的列的组合）。
该表包含一个关注关系中关注者和用户的编号，其中关注者关注用户。
```

编写解决方案，对于每一个用户，返回该用户的关注者数量。

按 `user_id` 的顺序返回结果表。

查询结果的格式如下示例所示。

**示例 1：**

```
输入：
Followers 表：
+---------+-------------+
| user_id | follower_id |
+---------+-------------+
| 0       | 1           |
| 1       | 0           |
| 2       | 0           |
| 2       | 1           |
+---------+-------------+
输出：
+---------+----------------+
| user_id | followers_count|
+---------+----------------+
| 0       | 1              |
| 1       | 1              |
| 2       | 2              |
+---------+----------------+
解释：
0 的关注者有 {1}
1 的关注者有 {0}
2 的关注者有 {0,1}
```

## 题解

::: details 点击查看题解

### 思路

关注关系是「谁关注了谁」的边表，一个 `user_id` 在表里出现多少行，就有多少个不同的人关注他，所以核心就是按 `user_id` 分组计数。

因为 `(user_id, follower_id)` 是**联合主键**，同一个用户不可能有两条完全相同的关注记录，所以组内行数 = 去重后的关注者数，直接 `COUNT(*)` 即可，不必写 `COUNT(DISTINCT follower_id)`——当然写了结果也一样，只是多付一次去重开销。这一点和「表可能有重复行」的题（如 1693）正好相反，读题时要看清主键说明。

两个小细节：输出列名要求是 `followers_count`，别忘了 `AS`；题目明确要求「按 `user_id` 的顺序返回」，虽然简单但漏写 `ORDER BY user_id` 在严格判题时会判错顺序。替代写法：窗口函数 `COUNT(*) OVER (PARTITION BY user_id)` 再外层去重，对本题属于杀鸡用牛刀。

### SQL 实现

```sql
SELECT user_id,
       COUNT(*) AS followers_count
FROM Followers
GROUP BY user_id
ORDER BY user_id;
```

### 复杂度分析

- 时间复杂度：O(n)，n 为关注关系行数，一次分组扫描；排序另需 O(g log g)，g 为用户数。
- 空间复杂度：O(g)，分组哈希表规模与用户数同阶。

:::
