# 寻找用户推荐人

> 难度：简单 | 标签：条件过滤、空值处理 | [LeetCode 原题](https://leetcode.cn/problems/find-customer-referee/)

## 题目描述

表: `Customer`

```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| id          | int     |
| name        | varchar |
| referee_id  | int     |
+-------------+---------+
在 SQL 中，id 是该表的主键列。
该表的每一行表示一个客户的 id、姓名以及推荐他们的客户的 id。
```

找出以下客户的姓名：

	- 被任何 id != 2 的用户推荐。

	- 没有被 任何用户推荐。

以 **任意顺序** 返回结果表。

结果格式如下所示。

**示例 1：**

```
输入：
Customer 表:
+----+------+------------+
| id | name | referee_id |
+----+------+------------+
| 1  | Will | null       |
| 2  | Jane | null       |
| 3  | Alex | 2          |
| 4  | Bill | null       |
| 5  | Zack | 1          |
| 6  | Mark | 2          |
+----+------+------------+
输出：
+------+
| name |
+------+
| Will |
| Jane |
| Bill |
| Zack |
+------+
```

## 题解

::: details 点击查看题解

### 思路

题目要的是两类人合起来：推荐人不是 2 的，以及压根没有推荐人的（`referee_id` 为 `NULL`）。写成一个条件就是 `referee_id IS NULL OR referee_id <> 2`。

最大的坑在 `NULL` 三值逻辑：`referee_id <> 2` 对 `NULL` 行求值结果是 `NULL` 而不是 `TRUE`，`WHERE` 会把它当假过滤掉。如果只写 `WHERE referee_id <> 2`，`Will`、`Jane`、`Bill` 三个没有推荐人的客户会全部丢失；`WHERE NOT (referee_id = 2)` 同样不行，`NOT NULL` 仍是 `NULL`。必须显式补上 `IS NULL` 分支。

替代写法：`WHERE IFNULL(referee_id, -1) <> 2` 或 `WHERE COALESCE(referee_id, 0) <> 2`，把空值映射成一个不可能的推荐人编号，一条比较即可覆盖两种情况；`NOT IN (2)` 也因同样的 NULL 问题不可用。

### SQL 实现

```sql
SELECT name
FROM Customer
WHERE referee_id IS NULL OR referee_id <> 2;
```

### 复杂度分析

- 时间复杂度：O(n)，全表扫描一次，n 为客户数。
- 空间复杂度：O(1)，仅过滤不额外占空间。
