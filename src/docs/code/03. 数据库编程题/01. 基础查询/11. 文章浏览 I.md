# 文章浏览 I

> 难度：简单 | 标签：条件过滤、去重 | [LeetCode 原题](https://leetcode.cn/problems/article-views-i/)

## 题目描述

`Views` 表：

```
+---------------+---------+
| Column Name   | Type    |
+---------------+---------+
| article_id    | int     |
| author_id     | int     |
| viewer_id     | int     |
| view_date     | date    |
+---------------+---------+
此表可能会存在重复行。（换句话说，在 SQL 中这个表没有主键）
此表的每一行都表示某人在某天浏览了某位作者的某篇文章。
请注意，同一人的 author_id 和 viewer_id 是相同的。
```

请查询出所有浏览过自己文章的作者。

结果按照作者的 `id` 升序排列。

查询结果的格式如下所示：

**示例 1：**

```
输入：
Views 表：
+------------+-----------+-----------+------------+
| article_id | author_id | viewer_id | view_date  |
+------------+-----------+-----------+------------+
| 1          | 3         | 5         | 2019-08-01 |
| 1          | 3         | 6         | 2019-08-02 |
| 2          | 7         | 7         | 2019-08-01 |
| 2          | 7         | 6         | 2019-08-02 |
| 4          | 7         | 1         | 2019-07-22 |
| 3          | 4         | 4         | 2019-07-21 |
| 3          | 4         | 4         | 2019-07-21 |
+------------+-----------+-----------+------------+

输出：
+------+
| id   |
+------+
| 4    |
| 7    |
+------+
```

## 题解

::: details 点击查看题解

### 思路

条件很直接：`author_id = viewer_id` 即「浏览者就是作者本人」。但输出有两个容易漏的要求：**去重** 和 **列别名**。

表没有主键且明确说可能存在重复行，示例中作者 4 的记录出现了两次（`2019-07-21` 两条一模一样），不过滤重复就会输出两行 `4`，所以必须 `DISTINCT`。其次输出列名是 `id` 而不是 `author_id`，要写 `author_id AS id`。

排序按作者 id 升序，`ORDER BY author_id` 或 `ORDER BY id` 在 MySQL 中皆可（排序引用原列或别名都合法）。替代写法：`SELECT author_id AS id ... GROUP BY author_id ORDER BY author_id`，用分组天然去重，与 `DISTINCT` 等价。

### SQL 实现

```sql
SELECT DISTINCT author_id AS id
FROM Views
WHERE author_id = viewer_id
ORDER BY author_id;
```

### 复杂度分析

- 时间复杂度：O(n log n)，过滤 O(n)，去重与排序受列基数影响。
- 空间复杂度：O(k)，k 为去重后的作者数。

:::
