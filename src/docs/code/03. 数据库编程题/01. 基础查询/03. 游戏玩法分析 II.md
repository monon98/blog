# 游戏玩法分析 II

> 难度：简单 | 标签：子查询、分组聚合 | [LeetCode 原题](https://leetcode.cn/problems/game-play-analysis-ii/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

活动表 `Activity`：

```
+--------------+---------+
| Column Name  | Type    |
+--------------+---------+
| player_id    | int     |
| device_id    | int     |
| event_date   | date    |
| games_played | int     |
+--------------+---------+
(player_id, event_date) 是这个表的主键（具有唯一值的列的组合）。
这张表展示了一些游戏玩家在游戏平台上的行为活动。
每行数据记录了一名玩家在退出平台之前，当天使用同一台设备登录平台后打开的游戏的数目（可能是 0 个）。
```

请编写解决方案，描述每一个玩家 **首次登录所使用的设备**。

返回结果的格式如下所示：

**示例 1：**

```
输入：
Activity 表：
+-----------+-----------+------------+--------------+
| player_id | device_id | event_date | games_played |
+-----------+-----------+------------+--------------+
| 1         | 2         | 2016-03-01 | 5            |
| 1         | 2         | 2016-05-02 | 6            |
| 2         | 3         | 2017-06-25 | 1            |
| 3         | 1         | 2016-03-02 | 0            |
| 3         | 4         | 2018-07-03 | 5            |
+-----------+-----------+------------+--------------+

输出：
+-----------+-----------+
| player_id | device_id |
+-----------+-----------+
| 1         | 2         |
| 2         | 3         |
| 3         | 1         |
+-----------+-----------+

解释：
玩家 1 首次登录日期是 2016-03-01，使用的设备是 2；
玩家 2 只登录过一次，设备是 3；
玩家 3 首次登录日期是 2016-03-02，使用的设备是 1（2018-07-03 的设备 4 不是首次登录）。
```

## 题解

::: details 点击查看题解

### 思路

这题比「游戏玩法分析 I」多了一步：先求出每名玩家的首次登录日期，还要回到原表取出 **当天那一行的 `device_id`**。不能对 `device_id` 直接做 `GROUP BY` 或取 `MIN`，因为设备编号的大小与登录先后无关，聚出来的设备很可能不是首次登录那天的。

推荐写法是联合键子查询：内层 `GROUP BY player_id` 配 `MIN(event_date)` 得到「玩家 → 首次登录日」，外层用 `(player_id, event_date) IN (...)` 精确匹配回原表。由于 `(player_id, event_date)` 是主键，匹配到的一定是唯一一行，取它的 `device_id` 即可。这里 `IN` 的行值比较在 MySQL 中是合法且高效的写法。

替代写法：窗口函数 `RANK() OVER (PARTITION BY player_id ORDER BY event_date)` 编号后筛 `rk = 1`，语义相同且不必回表；也可以自连接 `Activity a1 JOIN (SELECT player_id, MIN(event_date) ... ) a2 USING (player_id, event_date)`。

### SQL 实现

```sql
SELECT player_id, device_id
FROM Activity
WHERE (player_id, event_date) IN (
    SELECT player_id, MIN(event_date) AS event_date
    FROM Activity
    GROUP BY player_id
);
```

### 复杂度分析

- 时间复杂度：O(n)，一次聚合加一次行值匹配，n 为记录数。
- 空间复杂度：O(m)，m 为玩家数。

:::
