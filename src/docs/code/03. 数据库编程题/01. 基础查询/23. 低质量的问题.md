# 低质量的问题

> 难度：简单 | 标签：条件筛选、算术运算 | [LeetCode 原题](https://leetcode.cn/problems/low-quality-problems/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

表 `Problems`：

```
+-------------+------+
| 列名         | 类型 |
+-------------+------+
| problem_id  | int     |
| likes       | int     |
| dislikes    | int     |
+-------------+------+
在 SQL 中，problem_id 是这张表的主键。
该表的每一行都表示一个力扣问题的喜欢和不喜欢的数量。
```

找出 **低质量** 问题的 ID 集合。如果一个问题的喜欢率（喜欢数除以总投票数）**严格低于** `60%`，则该问题为 **低质量** 问题。

按 `problem_id` **升序** 排列返回结果表。

结果表的格式如下例所示。

**示例 1：**

```
输入：
Problems 表：
+------------+-------+----------+
| problem_id | likes | dislikes |
+------------+-------+----------+
| 6          | 1290  | 425      |
| 11         | 2677  | 8659     |
| 1          | 4446  | 2760     |
| 7          | 8569  | 6086     |
| 13         | 2050  | 4164     |
| 10         | 9002  | 7446     |
+------------+-------+----------+
输出：
+------------+
| problem_id |
+------------+
| 7          |
| 10         |
| 11         |
| 13         |
+------------+
解释：
喜欢的比率如下：
- 问题 1: (4446 / (4446 + 2760)) * 100 = 61.69858%
- 问题 6: (1290 / (1290 + 425)) * 100 = 75.21866%
- 问题 7: (8569 / (8569 + 6086)) * 100 = 58.47151%
- 问题 10: (9002 / (9002 + 7446)) * 100 = 54.73006%
- 问题 11: (2677 / (2677 + 8659)) * 100 = 23.61503%
- 问题 13: (2050 / (2050 + 4164)) * 100 = 32.99002%
问题 7, 10, 11, 和 13 是低质量问题，因为它们的同类百分比低于 60%。
```

## 题解

::: details 点击查看题解

### 思路

单表过滤题，唯一要算对的是「喜欢率」的公式：`likes / (likes + dislikes)`，**分母是总投票数（喜欢 + 不喜欢）**，不是单独的 likes 或 dislikes。很多人的第一直觉写成 `likes / dislikes < 0.6`，结果完全不对（问题 1 会算出 4446/2760 ≈ 1.6 被误判为低质量）。

三个细节值得注意。第一，题目要求**严格低于** 60%，边界必须是 `<` 而不是 `<=`——喜欢率恰好等于 60% 的问题不算低质量。第二，MySQL 的 `/` 是小数除法（`4446 / 7206` 得到 0.6169…），不像某些数据库对两个整数做整数除法截断成 0，所以直接写 `likes / (likes + dislikes) < 0.6` 就能正确比较；如果你习惯 `likes * 100 / (...) < 60` 也等价，但要小心整数除法的语言里必须先把任一操作数转成小数。第三，结果要求按 `problem_id` 升序，别漏 `ORDER BY`。

另外注意除数为 0 的情况：若某题 likes 和 dislikes 都是 0，`likes / (likes + dislikes)` 得 `NULL`，比较结果不为真，该行自然被排除——本题数据没有这种行，但这是个隐式行为，面试时可以主动提一句。替代写法：`WHERE likes * 100 < 60 * (likes + dislikes)`，纯整数比较，彻底避开除法。

### SQL 实现

```sql
SELECT problem_id
FROM Problems
WHERE likes / (likes + dislikes) < 0.6
ORDER BY problem_id;
```

### 复杂度分析

- 时间复杂度：O(n log n)，n 为问题数，逐行计算需 O(n)，排序需 O(n log n)。
- 空间复杂度：O(1)，除结果集外只需常数额外空间。
