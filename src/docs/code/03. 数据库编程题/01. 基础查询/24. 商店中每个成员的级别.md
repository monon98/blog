# 商店中每个成员的级别

> 难度：中等 | 标签：多表连接、分组聚合、CASE WHEN | [LeetCode 原题](https://leetcode.cn/problems/the-category-of-each-member-in-the-store/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

表 `Members`：

```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| member_id   | int     |
| name        | varchar |
+-------------+---------+
member_id 是该表的主键。
该表的每一行都表示成员的名称和 ID。
```

表 `Visits`：

```
+-------------+------+
| Column Name | Type |
+-------------+------+
| visit_id    | int  |
| member_id   | int  |
| visit_date  | date |
+-------------+------+
visit_id 是该表的主键。
member_id 是 Members 表中 member_id 的外键。
该表的每一行都包含关于访问商店的日期和访问该商店的成员的信息。
```

表 `Purchases`：

```
+----------------+------+
| Column Name    | Type |
+----------------+------+
| visit_id       | int  |
| charged_amount | int  |
+----------------+------+
visit_id 是该表的主键。
visit_id 是访问表 visit_id 的外键。
该表的每一行都包含了关于在商店中消费的信息。
```

一个商店想对其成员进行分类。有三个层次：

- **"钻石"**：如果转换率 **大于或等于** `80`。
- **"黄金"**：如果转换率 **大于或等于** `50` 且小于 `80`。
- **"白银"**：如果转化率 **小于** `50`。
- **"青铜"**：如果该成员从未访问过该商店。

成员的 **转化率** 为 `(100 * 该会员的购买总数) / 该成员的总访问次数`。

编写一个 SQL 来查询每个成员的 id、名称和类别。

以 **任意顺序** 返回结果表。

查询结果格式如下所示。

**示例 1：**

```
输入：
Members 表:
+-----------+---------+
| member_id | name    |
+-----------+---------+
| 9         | Alice   |
| 11        | Bob     |
| 3         | Winston |
| 8         | Hercy   |
| 1         | Narihan |
+-----------+---------+
Visits 表:
+----------+-----------+------------+
| visit_id | member_id | visit_date |
+----------+-----------+------------+
| 22       | 11        | 2021-10-28 |
| 16       | 11        | 2021-01-12 |
| 18       | 9         | 2021-12-10 |
| 19       | 3         | 2021-10-19 |
| 12       | 11        | 2021-03-01 |
| 17       | 8         | 2021-05-07 |
| 21       | 9         | 2021-05-12 |
+----------+-----------+------------+
Purchases 表:
+----------+----------------+
| visit_id | charged_amount |
+----------+----------------+
| 12       | 2000           |
| 18       | 9000           |
| 17       | 7000           |
+----------+----------------+
输出：
+-----------+---------+----------+
| member_id | name    | category |
+-----------+---------+----------+
| 1         | Narihan | Bronze   |
| 3         | Winston | Silver   |
| 8         | Hercy   | Diamond  |
| 9         | Alice   | Gold     |
| 11        | Bob     | Silver   |
+-----------+---------+----------+
解释：
- id = 1 的成员 Narihan 没有访问过该商店。她获得了铜奖。
- id = 3 的成员 Winston 访问了商店一次，但没有购买任何东西。转化率=(100 * 0)/ 1 = 0。他获得了银奖。
- id = 8 的成员 Hercy 访问商店一次，购买一次。转化率=(100 * 1)/ 1 = 100。他获得了钻石奖。
- id = 9 的成员 Alice 访问了商店两次，购买了一次。转化率=(100 * 1)/ 2 = 50。她获得了金奖。
- id = 11 的用户 Bob 访问了商店三次，购买了一次。转化率=(100 * 1)/ 3 = 33.33。他获得了银奖。
```

## 题解

::: details 点击查看题解

### 思路

三张表层层外键：`Members` → `Visits` → `Purchases`，而结果要求**每个成员一行**，包括从来没进过店的 Narihan，所以必须以 `Members` 为左表做两次 `LEFT JOIN`——先连 `Visits`，再用 `visit_id` 连 `Purchases`。任何一处用 `INNER JOIN`，没访问过的成员都会被过滤掉，直接少一行。

分组后要算两个数：总访问次数 `COUNT(v.visit_id)` 和「发生了购买的次数」`COUNT(p.visit_id)`。后者用左连接后 Purchases 侧为 `NULL` 的行不会被 `COUNT` 计入，正好等于购买次数——注意不能写 `COUNT(*)`，那会把没消费的访问也算成购买。转化率公式是 `100 * 购买次数 / 访问次数`，MySQL 的 `/` 产出小数，`100 * 1 / 3 = 33.333…` 与示例吻合。

分类用 `CASE`，顺序有讲究：**先判 `COUNT(v.visit_id) = 0` 给 Bronze**，否则分母为 0 会触发除零错误（MySQL 里返回 `NULL` 而非报错，但会让后续条件全部落空成 Silver，结果同样错）；再依次判 `>= 80` Diamond、`>= 50` Gold，剩下 `ELSE` Silver。注意阈值是「大于等于」，Alice 恰好 50% 落在 Gold，边界别写成 `>`。

替代写法：先用子查询分别算出每人的访问数与购买数再 `JOIN` 分类，或用 `AVG(p.visit_id IS NOT NULL) * 100` 当转化率（布尔在 MySQL 里可参与运算），主解法的两次左连接是最直观的。

### SQL 实现

```sql
SELECT m.member_id,
       m.name,
       CASE
           WHEN COUNT(v.visit_id) = 0 THEN 'Bronze'
           WHEN 100 * COUNT(p.visit_id) / COUNT(v.visit_id) >= 80 THEN 'Diamond'
           WHEN 100 * COUNT(p.visit_id) / COUNT(v.visit_id) >= 50 THEN 'Gold'
           ELSE 'Silver'
       END AS category
FROM Members m
LEFT JOIN Visits v ON m.member_id = v.member_id
LEFT JOIN Purchases p ON v.visit_id = p.visit_id
GROUP BY m.member_id, m.name;
```

### 复杂度分析

- 时间复杂度：O((n + m + k) log g)，n/m/k 分别为三表行数，g 为成员数，连接与分组线性扫描，分组排序另计。
- 空间复杂度：O(g)，分组哈希表规模与成员数同阶。

:::
