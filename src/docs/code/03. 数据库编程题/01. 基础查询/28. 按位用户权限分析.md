# 按位用户权限分析

> 难度：中等 | 标签：位运算、聚合函数 | [LeetCode 原题](https://leetcode.cn/problems/bitwise-user-permissions-analysis/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

表 `user_permissions`：

```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| user_id     | int     |
| permissions | int     |
+-------------+---------+
user_id 是主键。
这张表的每一行包含用户 ID 和他们的权限，编码为一个整数。
```

`permissions` 整数中的每一个二进制位代表一个用户拥有的一个不同的访问级别或功能。

编写一个解决方案来计算以下内容：

- common_perms：授予 **所有用户** 的访问级别。在 `permissions` 列上使用 **按位与** 操作来计算。
- any_perms：授予 **任一用户** 的访问级别。在 `permissions` 列上使用 **按位或** 操作来计算。

以 **任意顺序** 返回结果表。

结果格式如下所示。

**示例：**

```
输入：
user_permissions 表：
+---------+-------------+
| user_id | permissions |
+---------+-------------+
| 1       | 5           |
| 2       | 12          |
| 3       | 7           |
| 4       | 3           |
+---------+-------------+
输出：
+--------------+-------------+
| common_perms | any_perms   |
+--------------+-------------+
| 0            | 15          |
+--------------+-------------+
解释：
- common_perms：代表所有权限的按位与结果：
    - 对于用户 1 (5)：5 (二进制 0101)
    - 对于用户 2 (12)：12 (二进制 1100)
    - 对于用户 3 (7)：7 (二进制 0111)
    - 对于用户 4 (3)：3 (二进制 0011)
    - 按位与：5 & 12 & 7 & 3 = 0 (二进制 0000)
- any_perms：代表所有权限的按位或结果：
    - 按位或：5 | 12 | 7 | 3 = 15 (二进制 1111)
```

## 题解

::: details 点击查看题解

### 思路

这题考察的是「按位运算」的语义与**聚合函数**的对应关系，而不是手写循环。

`common_perms` 要的是「每一位在**所有用户**里都为 1」——这正是按位与（AND）的定义：某一位只要有任何一个操作数是 0，结果就是 0。示例里第 0 位（值 1）在用户 1、3、4 中都是 1，但用户 2 的 12 = 1100 该位为 0，所以公共位只剩…逐位算下来 5 & 12 & 7 & 3 = 0。`any_perms` 要的是「至少一个用户拥有」，对应按位或：5 | 12 | 7 | 3 = 15（1111）。

MySQL 把这两个运算做成了**聚合函数** `BIT_AND(col)` 和 `BIT_OR(col)`，一条 `SELECT` 全表扫一遍即可，结果天然只有一行（没有 `GROUP BY`，整个表就是一个组），既不需要自连接，也不需要窗口函数。两个函数与 `SUM`、`MAX` 一样会忽略 `NULL` 行——若表里有 `permissions` 为 `NULL` 的行，`BIT_AND` 会把它跳过而不是让结果变 `NULL`，本题数据无 `NULL`，但这是与「手动初始化为全 1 再逐行 AND」的实现之间的一个差异点。

替代写法：窗口函数 `BIT_AND(permissions) OVER ()` 也能得到同样的值（每行重复），或者先 `SELECT permissions FROM ... ORDER BY ...` 取出来在应用层循环累算——面试时能说清「AND = 全员都有、OR = 至少一人有」就达到目的了。

### SQL 实现

```sql
SELECT BIT_AND(permissions) AS common_perms,
       BIT_OR(permissions) AS any_perms
FROM user_permissions;
```

### 复杂度分析

- 时间复杂度：O(n)，n 为用户数，全表扫描一次。
- 空间复杂度：O(1)，结果固定一行，无需额外结构。
