# 仓库经理

> 难度：简单 | 标签：多表连接、分组聚合 | [LeetCode 原题](https://leetcode.cn/problems/warehouse-manager/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

表 `Warehouse`：

```
+--------------+---------+
| Column Name  | Type    |
+--------------+---------+
| name         | varchar |
| product_id   | int     |
| units        | int     |
+--------------+---------+
(name, product_id) 是该表的主键（具有唯一值的列的组合）。
该表的行包含了每个仓库存放的每种商品的数量。
```

表 `Products`：

```
+---------------+---------+
| Column Name   | Type    |
+---------------+---------+
| product_id    | int     |
| product_name  | varchar |
| Width         | int     |
| Length        | int     |
| Height        | int     |
+---------------+---------+
product_id 是该表的主键（具有唯一值的列）。
该表的行包含了每件商品以英尺为单位的尺寸（宽度、长度和高度）信息。
```

编写解决方案，报告每个仓库的存货量是多少 **立方英尺**。

返回结果没有顺序要求。

返回结果格式如下例所示。

**示例 1：**

```
输入：
Warehouse 表：
+------------+--------------+-------------+
| name       | product_id   | units       |
+------------+--------------+-------------+
| LCHouse1   | 1            | 1           |
| LCHouse1   | 2            | 10          |
| LCHouse1   | 3            | 5           |
| LCHouse2   | 1            | 2           |
| LCHouse2   | 2            | 2           |
| LCHouse3   | 4            | 1           |
+------------+--------------+-------------+
Products 表：
+------------+--------------+------------+----------+-----------+
| product_id | product_name | Width      | Length   | Height    |
+------------+--------------+------------+----------+-----------+
| 1          | LC-TV        | 5          | 50       | 40        |
| 2          | LC-KeyChain  | 5          | 5        | 5         |
| 3          | LC-Phone     | 2          | 10       | 10        |
| 4          | LC-T-Shirt   | 4          | 10       | 20        |
+------------+--------------+------------+----------+-----------+
输出：
+----------------+------------+
| warehouse_name | volume     |
+----------------+------------+
| LCHouse1       | 12250      |
| LCHouse2       | 20250      |
| LCHouse3       | 800        |
+----------------+------------+
解释：
商品 1（LC-TV）一件的体积为 5 × 50 × 40 = 10000；
商品 2（LC-KeyChain）一件为 5 × 5 × 5 = 125；
商品 3（LC-Phone）一件为 2 × 10 × 10 = 200；
商品 4（LC-T-Shirt）一件为 4 × 10 × 20 = 800。
仓库 LCHouse1：1 × 10000 + 10 × 125 + 5 × 200 = 12250 立方英尺；
仓库 LCHouse2：2 × 10000 + 2 × 125 = 20250 立方英尺；
仓库 LCHouse3：1 × 800 = 800 立方英尺。
```

## 题解

::: details 点击查看题解

### 思路

件数在 `Warehouse`、尺寸在 `Products`，必须先按 `product_id` 等值连接把「每件商品的体积」和「件数」对齐到同一行，再按仓库名分组求和：`SUM(width * length * height * units)`。连接用 `JOIN ... USING (product_id)` 或 `ON w.product_id = p.product_id` 都行；用 `USING` 时同名列只保留一份，本题不取它，无所谓。

输出两列的别名要对上：仓库名从 `name` 改成 `warehouse_name`，体积列叫 `volume`。易错点是求和顺序——先 `SUM(units)` 再乘体积是错的，同一个仓库里是多种商品，必须 **逐商品相乘后再求和**；另外乘法在 `SUM` 内部完成，不要写成 `SUM(...) * SUM(...)`。

注意 `LCHouse3` 只有商品 4、`Products` 里所有商品都被某个仓库用到，本题用 `INNER JOIN` 结果一致；若存在「仓库里有商品但 `Products` 缺该商品」的脏数据，`INNER JOIN` 会把整条库存丢掉，更稳妥可用 `LEFT JOIN`（本题数据不涉及）。聚合时 `name` 在 `GROUP BY` 中，`ONLY_FULL_GROUP_BY` 模式下无歧义。

### SQL 实现

```sql
SELECT
    w.name AS warehouse_name,
    SUM(p.Width * p.Length * p.Height * w.units) AS volume
FROM Warehouse w
JOIN Products p ON w.product_id = p.product_id
GROUP BY w.name;
```

### 复杂度分析

- 时间复杂度：O(n)，n 为 `Warehouse` 行数，连接与分组各扫一遍。
- 空间复杂度：O(m)，m 为仓库数（分组结果）。

:::
