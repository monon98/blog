# 计算订单平均商品数量

> 难度：简单 | 标签：分组聚合 | [LeetCode 原题](https://leetcode.cn/problems/calculate-compressed-mean/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

表：`Orders`

```
+-------------------+------+
| Column Name       | Type |
+-------------------+------+
| order_id          | int  |
| item_count        | int  |
| order_occurrences | int  |
+-------------------+------+
order_id 是这张表具有唯一值的列。
这张表包括 order_id、item_count 和 order_occurrences。
```

编写一个计算每个订单的 **平均商品数量** 的解决方案，保留 2 位小数。以 **任意顺序** 返回结果表。结果格式如下例所示。

**示例 1：**

输入：

```
Orders table:
+----------+------------+-------------------+
| order_id | item_count | order_occurrences |
+----------+------------+-------------------+
| 10       | 1          | 500               |
| 11       | 2          | 1000              |
| 12       | 3          | 800               |
| 13       | 4          | 1000              |
+----------+------------+-------------------+
```

输出：

```
+-------------------------+
| average_items_per_order |
+-------------------------+
| 2.70                    |
+-------------------------+
```

解释：

- 总商品数：(1 * 500) + (2 * 1000) + (3 * 800) + (4 * 1000) = 8900
- 总订单数：500 + 1000 + 800 + 1000 = 3300
- 因此，每个订单的平均商品数量为 8900 / 3300 = 2.70

## 题解

::: details 点击查看题解

### 思路

这张表是「压缩存储」的：一行代表 500 个同规格订单，而不是一行一个订单。因此平均值不能简单 `AVG(item_count)`——那样会把 1、2、3、4 四个数直接平均成 2.50，完全错误。正确的算法是**加权平均**：分子是 `SUM(item_count * order_occurrences)`（总商品数），分母是 `SUM(order_occurrences)`（总订单数），两者相除。

除法在 MySQL 中默认产出小数，不会整数截断，`ROUND(..., 2)` 保留两位即可得到 2.70。注意别把 `ROUND` 写成 `TRUNCATE`，2.696… 截断会得到 2.69，与题面不符。

替代写法：如果表没有压缩（每行就是一个订单），直接 `ROUND(AVG(item_count), 2)` 就够了；遇到压缩表，先想清楚「每行代表几个样本」，再决定要不要加权。

### SQL 实现

```sql
SELECT ROUND(
    SUM(item_count * order_occurrences) / SUM(order_occurrences),
    2
) AS average_items_per_order
FROM Orders;
```

### 复杂度分析

- 时间复杂度：O(n)，n 为 Orders 行数，一次全表聚合。
- 空间复杂度：O(1)，只产出一行标量结果。

:::
