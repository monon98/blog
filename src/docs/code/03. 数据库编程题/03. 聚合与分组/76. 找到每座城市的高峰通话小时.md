# 找到每座城市的高峰通话小时

> 难度：中等 | 标签：窗口函数、日期函数、分组聚合 | [LeetCode 原题](https://leetcode.cn/problems/find-peak-calling-hours-for-each-city/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

表：`Calls`

```
+--------------+----------+
| Column Name  | Type     |
+--------------+----------+
| caller_id    | int      |
| recipient_id | int      |
| call_time    | datetime |
| city         | varchar  |
+--------------+----------+
(caller_id, recipient_id, call_time) 是该表的主键（具有唯一值的列）。
每一行包含 caller id、recipient id、call time 和 city。
```

编写一个查询，找到每个 `city` 的 **高峰** 通话 **小时**。如果 **多个小时** 有相同数量的通话，则所有这些小时都将被视为该特定城市的高峰小时。

按照 **高峰小时** 和 `city` 按 **降序** 排序返回结果表。结果格式如下例所示。

**示例 1：**

输入：

```
Calls table:
+-----------+--------------+---------------------+----------+
| caller_id | recipient_id | call_time           | city     |
+-----------+--------------+---------------------+----------+
| 8         | 4            | 2021-08-24 22:46:07 | Houston  |
| 4         | 8            | 2021-08-24 22:57:13 | Houston  |
| 5         | 1            | 2021-08-11 21:28:44 | Houston  |
| 8         | 3            | 2021-08-17 22:04:15 | Houston  |
| 11        | 3            | 2021-08-17 13:07:00 | New York |
| 8         | 11           | 2021-08-17 14:22:22 | New York |
+-----------+--------------+---------------------+----------+
```

输出：

```
+----------+-------------------+-----------------+
| city     | peak_calling_hour | number_of_calls |
+----------+-------------------+-----------------+
| Houston  | 22                | 3               |
| New York | 14                | 1               |
| New York | 13                | 1               |
+----------+-------------------+-----------------+
```

解释：

- 对于 Houston：高峰小时是 22:00，总共记录了 3 次通话。
- 对于 New York：13:00 和 14:00 都有相同数量的通话，因此这两个小时都被视为高峰小时。

输出表按照高峰小时和城市按降序排序。

## 题解

::: details 点击查看题解

### 思路

「每座城市的高峰小时」= 分组后的第一名，而并列要**全部保留**，这正是 `RANK()` 窗口函数的典型场景：先在内层按 `(city, HOUR(call_time))` 分组数出每城每小时的通话量，再对内层结果按 `city` 分区、按通话量降序 `RANK()`，取 `rk = 1` 的行。若用 `ROW_NUMBER` 或 `MAX` 自连接，New York 的 13、14 两点并列只会留一个，直接判错。

小时要用 `HOUR(call_time)` 从 datetime 中提取，只保留「几点」、丢弃日期，否则同一天的同一时刻会被拆成不同组，而题目统计的是跨日期的小时分布。注意输出列名是 `peak_calling_hour` 和 `number_of_calls`，别忘了给 `h`、`cnt` 起别名。

排序是双重降序：先按高峰小时降序，再按城市名降序（`ORDER BY 2 DESC, 1 DESC`）。New York 的两条 13、14 记录因此按 14 在前输出，与示例一致。

### SQL 实现

```sql
WITH
    T AS (
        SELECT
            *,
            RANK() OVER (
                PARTITION BY city
                ORDER BY cnt DESC
            ) AS rk
        FROM (
            SELECT
                city,
                HOUR(call_time) AS h,
                COUNT(1) AS cnt
            FROM Calls
            GROUP BY 1, 2
        ) AS t
    )
SELECT city, h AS peak_calling_hour, cnt AS number_of_calls
FROM T
WHERE rk = 1
ORDER BY 2 DESC, 1 DESC;
```

### 复杂度分析

- 时间复杂度：O(n log n)，n 为通话记录数，分组计数线性，窗口按城市分区排序引入对数因子。
- 空间复杂度：O(h)，h 为（城市 × 小时）组合数，最多 24 × 城市数。
