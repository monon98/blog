# 好友申请 I：总体通过率

> 难度：简单 | 标签：子查询、分组聚合 | [LeetCode 原题](https://leetcode.cn/problems/friend-requests-i-overall-acceptance-rate/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

`FriendRequest` 表记录发出的好友申请：

```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| sender_id   | int     |
| send_to_id  | int     |
| request_date| date    |
+-------------+---------+
每一行表示 sender_id 向 send_to_id 在 request_date 发出了一条好友申请。
```

`RequestAccepted` 表记录被接受的申请：

```
+--------------+---------+
| Column Name  | Type    |
+--------------+---------+
| requester_id | int     |
| accepter_id  | int     |
| accept_date  | date    |
+--------------+---------+
每一行表示 requester_id 发出、accepter_id 接受的好友申请在 accept_date 通过。
```

编写解决方案，计算好友申请的 **总体通过率**，即「被接受的申请数 ÷ 发出的申请数」，结果保留两位小数，列名为 `accept_rate`。

约定：

- 重复的申请或接受只计一次（同一对 (sender, send_to_id) 或 (requester_id, accepter_id) 只算一条）。
- 被接受的申请不一定出现在 `FriendRequest` 中，直接统计 `RequestAccepted` 的总数即可。
- 如果一条申请都没有发出，返回 `0.00`。

**示例 1:**

```
输入:
FriendRequest 表:
+------------+------------+--------------+
| sender_id  | send_to_id | request_date |
+------------+------------+--------------+
| 1          | 2          | 2016/06/01   |
| 1          | 3          | 2016/06/01   |
| 1          | 4          | 2016/06/01   |
| 2          | 3          | 2016/06/02   |
| 3          | 4          | 2016/06/09   |
+------------+------------+--------------+
RequestAccepted 表:
+--------------+-------------+--------------+
| requester_id | accepter_id | accept_date  |
+--------------+-------------+--------------+
| 1            | 2           | 2016/06/03   |
| 1            | 3           | 2016/06/08   |
| 2            | 3           | 2016/06/08   |
| 3            | 4           | 2016/06/09   |
| 3            | 4           | 2016/06/10   |
+--------------+-------------+--------------+
输出:
+------------+
| accept_rate|
+------------+
| 0.80       |
+------------+
解释: 5 条申请中有 4 条被接受（(3, 4) 重复出现只算一次），通过率为 0.80。
```

## 题解

::: details 点击查看题解

### 思路

通过率 = 去重后的接受数 ÷ 去重后的请求数，两个统计各自独立、互不关联，因此不必做 `JOIN`，用两个标量子查询分别算出分子分母再相除最清晰。去重是本题最大的坑：`RequestAccepted` 里 `(3, 4)` 出现了两次（同一条申请被接受两次记录），`FriendRequest` 也可能出现同一 sender 重复发给同一人的情况，两边都必须用 `COUNT(DISTINCT ...)` 只数一次。

拼接两个 id 时建议用 `CONCAT(requester_id, '_', accepter_id)` 而不是简单相加，避免 `(1, 23)` 与 `(12, 3)` 这类组合碰撞。另一个易错点是除数为 0：当 `FriendRequest` 为空时，标量子查询返回 `NULL`，直接相除会得到 `NULL` 而不是题目要求的 `0.00`，所以要用 `IFNULL(..., 0)` 兜底；MySQL 中 `COUNT / COUNT` 是小数除法，不会整数截断，最后 `ROUND(..., 2)` 保留两位即可。

替代写法：先把两表的 distinct 配对 `UNION ALL` 合并、打上是否接受的标记再聚合，适合进阶问题「按月份统计通过率」；本题单次统计用双子查询最直接。

### SQL 实现

```sql
SELECT ROUND(
    IFNULL(
        (SELECT COUNT(DISTINCT CONCAT(requester_id, '_', accepter_id))
         FROM RequestAccepted) /
        (SELECT COUNT(DISTINCT CONCAT(sender_id, '_', send_to_id))
         FROM FriendRequest),
        0
    ),
    2
) AS accept_rate;
```

### 复杂度分析

- 时间复杂度：O(m + n)，m、n 分别为两表行数，各自做一次去重计数。
- 空间复杂度：O(m + n)，去重哈希表存储所有配对。

:::
