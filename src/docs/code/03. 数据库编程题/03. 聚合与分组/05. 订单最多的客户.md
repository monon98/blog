# 订单最多的客户

> 难度：简单 | 标签：分组聚合 | [LeetCode 原题](https://leetcode.cn/problems/customer-placing-the-largest-number-of-orders/)

## 题目描述

表: `Orders`

```
+-----------------+----------+
| Column Name     | Type     |
+-----------------+----------+
| order_number    | int      |
| customer_number | int      |
+-----------------+----------+
在 SQL 中，Order_number是该表的主键。
此表包含关于订单ID和客户ID的信息。
```

查找下了 **最多订单** 的客户的 `customer_number` 。

测试用例生成后， **恰好有一个客户** 比任何其他客户下了更多的订单。

查询结果格式如下所示。

**示例 1:**

```
输入:
Orders 表:
+--------------+-----------------+
| order_number | customer_number |
+--------------+-----------------+
| 1            | 1               |
| 2            | 2               |
| 3            | 3               |
| 4            | 3               |
+--------------+-----------------+
输出:
+-----------------+
| customer_number |
+-----------------+
| 3               |
+-----------------+
解释:
customer_number 为 '3' 的顾客有两个订单，比顾客 '1' 或者 '2' 都要多，因为他们只有一个订单。
所以结果是该顾客的 customer_number ，也就是 3 。
```

**进阶：** 如果有多位顾客订单数并列最多，你能找到他们所有的 `customer_number` 吗？

## 题解

::: details 点击查看题解

### 思路

订单数 = 每个 `customer_number` 出现的次数，所以先 `GROUP BY customer_number` 计数，再取最大值对应的客户。经典写法是把「最大计数」做成标量子查询：`ORDER BY cnt DESC LIMIT 1` 取第一名，比 `MAX()` 再回表连一次更直接。

题目保证并列唯一，所以 `LIMIT 1` 安全；但进阶要求并列也全返回，这时应该换成 `HAVING COUNT(*) = (SELECT MAX(c) FROM (SELECT COUNT(*) AS c ... ) t)` 或 `RANK()` 窗口：`RANK() OVER (ORDER BY cnt DESC) = 1` 天然保留并列。两个写法都值得记住——唯一性是题面给的保证，不是数据本身的安全网。

易错点：直接 `SELECT customer_number, COUNT(*) ... ORDER BY 2 DESC LIMIT 1` 会多输出 `cnt` 列，要再包一层 `SELECT` 只留 `customer_number`；或者在内层取好再投影。另外建表语句里的表名是小写 `orders`，MySQL 在 Linux 上对表名大小写敏感，查询里要与建表名保持一致，否则会报表不存在。替代写法：`MAX(cnt)` 子查询 + `HAVING COUNT(*) = ...`。

### SQL 实现

```sql
SELECT customer_number
FROM orders
GROUP BY customer_number
ORDER BY COUNT(*) DESC
LIMIT 1;
```

### 复杂度分析

- 时间复杂度：O(n log n)，分组与排序主导，n 为订单数。
- 空间复杂度：O(k)，k 为客户数。

:::

