# 至少有5名直接下属的经理

> 难度：中等 | 标签：分组聚合、多表连接 | [LeetCode 原题](https://leetcode.cn/problems/managers-with-at-least-5-direct-reports/)

## 题目描述

表: `Employee`

```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| id          | int     |
| name        | varchar |
| department  | varchar |
| managerId   | int     |
+-------------+---------+
id 是此表的主键（具有唯一值的列）。
该表的每一行表示雇员的名字、他们的部门和他们的经理的id。
如果managerId为空，则该员工没有经理。
没有员工会成为自己的管理者。
```

编写一个解决方案，找出至少有**五个直接下属**的经理。

以 **任意顺序 **返回结果表。

查询结果格式如下所示。

**示例 1:**

```
输入:
Employee 表:
+-----+-------+------------+-----------+
| id  | name  | department | managerId |
+-----+-------+------------+-----------+
| 101 | John  | A          | Null      |
| 102 | Dan   | A          | 101       |
| 103 | James | A          | 101       |
| 104 | Amy   | A          | 101       |
| 105 | Anne  | A          | 101       |
| 106 | Ron   | B          | 101       |
+-----+-------+------------+-----------+
输出:
+------+
| name |
+------+
| John |
+------+
```

## 题解

::: details 点击查看题解

### 思路

「谁有多少下属」藏在 `managerId` 这一列里：`managerId = 101` 的每一行都是 101 号员工的直接下属。所以第一步按 `managerId` 分组计数，`HAVING COUNT(*) >= 5` 筛出「下属数达标」的经理 id；第二步再回到 `Employee` 表把 id 换成 `name`。

两步的连接方式二选一：其一是 `JOIN`——分组结果 `m` 与 `Employee e ON e.id = m.managerId`，只保留经理本人那一行，取 `e.name`；其二是子查询 `WHERE id IN (SELECT managerId ... HAVING COUNT(*) >= 5)`。注意 `managerId` 可能为 NULL（无人领导），`GROUP BY` 会把 NULL 归成一组，但 NULL 不可能等于任何 `id`，不会混进结果。

易错点：直接对全表 `GROUP BY managerId` 后忘了 `HAVING`，或把条件写成 `COUNT(*) = 5`——题目要求「至少五个」，用 `>=`。另一个小坑是输出只要 `name` 一列，别把 `id`、`department` 也带出去。替代写法：先 `SELECT DISTINCT managerId` 计数，或用窗口 `COUNT(*) OVER (PARTITION BY managerId)` 在明细层标记后再去重。

### SQL 实现

```sql
SELECT e.name
FROM Employee AS e
JOIN (
    SELECT managerId
    FROM Employee
    WHERE managerId IS NOT NULL
    GROUP BY managerId
    HAVING COUNT(*) >= 5
) AS m ON e.id = m.managerId;
```

### 复杂度分析

- 时间复杂度：O(n log n)，分组与连接主导，n 为员工数。
- 空间复杂度：O(g)，g 为经理数量。

:::
