# 活动参与者

> 难度：中等 | 标签：分组聚合、HAVING 子查询 | [LeetCode 原题](https://leetcode.cn/problems/activity-participants/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

`Friends` 表：

```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| id          | int     |
| name        | varchar |
| activity    | varchar |
+-------------+---------+
该表没有主键，可能包含重复行。
每一行表示一位朋友（name）参加的活动（activity）名称。
```

`Activities` 表：

```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| id          | int     |
| name        | varchar |
+-------------+---------+
id 是该表的主键，每一行是一门活动的名称（活动字典表）。
```

编写一个 SQL 查询，找出 **参加人数不是最多** 的所有活动名称，返回列 `activity`，顺序不限。

- 结果只包含至少有一人参加的活动；活动字典里没人参加的活动不返回。
- 若存在多个活动并列「参加人数最多」，它们都不返回。

**示例 1：**

```
输入：
Friends table:
+----+------------+--------------+
| id | name       | activity     |
+----+------------+--------------+
| 1  | Jonathan D.| Eating       |
| 2  | Jade W.    | Singing      |
| 3  | Victor J.  | Singing      |
| 4  | Elvis Q.   | Eating       |
| 5  | Daniel A.  | Eating       |
| 6  | Bob B.     | Horse Riding |
+----+------------+--------------+
Activities table:
+----+--------------+
| id | name         |
+----+--------------+
| 1  | Eating       |
| 2  | Singing      |
| 3  | Horse Riding |
+----+--------------+
输出：
+--------------+
| activity     |
+--------------+
| Singing      |
| Horse Riding |
+--------------+
解释：
Eating 有 3 人参加，Singing 有 2 人参加，Horse Riding 有 1 人参加。
参加人数最多的是 Eating，因此返回其余两项活动。
```

## 题解

::: details 点击查看题解

### 思路

先要拿到「活动 → 参加人数」的分布：按 `activity` 分组 `COUNT(*)` 即可。然后需要比较某活动的参加人数是否小于全局最大值。最大值不能直接写在 `HAVING COUNT(*) < MAX(COUNT(*))` 里——聚合函数不能嵌套，MySQL 会报错。

正确做法是把「每个活动的参加人数」做成一个派生表，再在外层取 `MAX(cnt)` 作为标量子查询，`HAVING COUNT(*) < (SELECT MAX(cnt) FROM ...)`。`HAVING` 里允许出现子查询，也允许引用当前分组的聚合值，所以这个写法合法且一次扫描即可完成。

也可以用 `WHERE` + 窗口函数：先把 `COUNT(*)` 和 `MAX(COUNT(*)) OVER ()` 一起算出来，再筛出小于最大值的行，可读性更好。注意结果用 `SELECT activity`（而不是 `DISTINCT`）——已经按 `activity` 分组，天然唯一。`Activities` 表在这里只是活动字典；没人参加的活动在 `Friends` 里没有行，用 `Friends` 分组的写法会自动排除掉它们，正好符合题意。

### SQL 实现

```sql
SELECT activity
FROM Friends
GROUP BY activity
HAVING COUNT(*) < (
    SELECT MAX(cnt)
    FROM (
        SELECT COUNT(*) AS cnt
        FROM Friends
        GROUP BY activity
    ) t
);
```

窗口函数写法：

```sql
SELECT activity
FROM (
    SELECT activity,
           COUNT(*) AS cnt,
           MAX(COUNT(*)) OVER () AS max_cnt
    FROM Friends
    GROUP BY activity
) t
WHERE cnt < max_cnt;
```

### 复杂度分析

- 时间复杂度：O(n log n)，n 为 `Friends` 行数，两次分组聚合（或一次分组 + 一次窗口）。
- 空间复杂度：O(a)，a 为活动种类数。

:::
