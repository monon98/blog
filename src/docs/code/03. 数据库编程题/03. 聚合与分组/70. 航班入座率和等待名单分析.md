# 航班入座率和等待名单分析

> 难度：中等 | 标签：多表连接、分组聚合 | [LeetCode 原题](https://leetcode.cn/problems/flight-occupancy-and-waitlist-analysis/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

`Flights` 表：

```
+-------------+------+
| 列名         | 类型 |
+-------------+------+
| flight_id   | int  |
| capacity    | int  |
+-------------+------+
flight_id 是该表中具有唯一值的列。
该表的每一行包含航班 ID 和它的座位容量。
```

`Passengers` 表：

```
+--------------+------+
| Column Name  | Type |
+--------------+------+
| passenger_id | int  |
| flight_id    | int  |
+--------------+------+
passenger_id 是该表中具有唯一值的列。
该表的每一行包含乘客 ID 和航班 ID。
```

乘客提前预订航班机票。如果乘客预订了某个航班的机票，并且该航班还有空座位，乘客的机票将会得到 **确认**。然而，如果航班已经满员，乘客将会进入 **等待名单**。

编写解决方案，报告每个航班已成功预订（获得座位）的乘客数 `booked_cnt` 以及处于等待名单上的乘客数 `waitlist_cnt`。按照 `flight_id` 升序排序返回结果表。

**示例 1：**

输入：

```
Flights table:
+-----------+----------+
| flight_id | capacity |
+-----------+----------+
| 1         | 2        |
| 2         | 2        |
| 3         | 1        |
+-----------+----------+

Passengers table:
+--------------+-----------+
| passenger_id | flight_id |
+--------------+-----------+
| 101          | 1         |
| 102          | 1         |
| 103          | 1         |
| 104          | 2         |
| 105          | 2         |
| 106          | 3         |
| 107          | 3         |
+--------------+-----------+
```

输出：

```
+-----------+------------+--------------+
| flight_id | booked_cnt | waitlist_cnt |
+-----------+------------+--------------+
| 1         | 2          | 1            |
| 2         | 2          | 0            |
| 3         | 1          | 1            |
+-----------+------------+--------------+
```

解释：

- 航班 1 的座位容量为 2。由于有 3 名乘客预订了机票，只有 2 名乘客可以获得座位。因此，有 2 名乘客成功预订，并且有 1 名乘客在等待名单上。
- 航班 2 的座位容量为 2。由于有 2 名乘客预订了机票，每个人都可以获得座位。结果是，有 2 名乘客成功预订了座位，且没有乘客在等待名单上。
- 航班 3 的座位容量为 1。由于有 2 名乘客预订了机票，只有 1 名乘客可以获得座位。因此，有 1 名乘客成功预订，并且有 1 名乘客在等待名单上。

## 题解

::: details 点击查看题解

### 思路

「成功预订人数」不是简单的乘客计数，而是被容量截断后的结果：`LEAST(乘客数, capacity)`；「等待名单」则是超出容量的部分，`GREATEST(乘客数 - capacity, 0)`。两个指标都依赖「每个航班的乘客总数」，所以核心动作是按 `flight_id` 分组统计。

连接方向必须是 `Flights LEFT JOIN Passengers`，而不能反过来：题目要求报告**每个**航班，若某航班一个乘客都没有（测试数据中可能出现），内连接或以 Passengers 为主表都会让该航班整行消失。左连接后 `COUNT(passenger_id)` 对空航班返回 0，`LEAST`/`GREATEST` 恰好算出 `booked_cnt = 0`、`waitlist_cnt = 0`，结果天然正确。

替代写法：也可以先用子查询 `GROUP BY flight_id` 统计乘客数，再与 `Flights` 连接，逻辑等价；但一次左连接 + 分组更简洁，也少一次扫描。

### SQL 实现

```sql
SELECT
    f.flight_id,
    LEAST(COUNT(p.passenger_id), f.capacity) AS booked_cnt,
    GREATEST(COUNT(p.passenger_id) - f.capacity, 0) AS waitlist_cnt
FROM Flights f
LEFT JOIN Passengers p ON p.flight_id = f.flight_id
GROUP BY f.flight_id, f.capacity
ORDER BY f.flight_id;
```

### 复杂度分析

- 时间复杂度：O(m + n)，m、n 分别为 Flights 与 Passengers 的行数，一次连接加分组即可完成。
- 空间复杂度：O(k)，k 为航班数量，用于存放分组中间结果。

:::
