# 无流量的帐户数

> 难度：中等 | 标签：子查询、日期范围 | [LeetCode 原题](https://leetcode.cn/problems/number-of-accounts-that-did-not-stream/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

订阅表 `Subscriptions`：

```
+-------------+------+
| Column Name | Type |
+-------------+------+
| account_id  | int  |
| start_date  | date |
| end_date    | date |
+-------------+------+
account_id 是该表的主键。
每一行表示某个账户的订阅开始与结束日期，且始终满足 start_date < end_date。
```

观看表 `Streams`：

```
+-------------+------+
| Column Name | Type |
+-------------+------+
| session_id  | int  |
| account_id  | int  |
| stream_date | date |
+-------------+------+
session_id 是该表的主键。
account_id 是指向订阅表的外键。
每一行表示某个账户在某个日期进行了一次观看会话。
```

请编写一个 SQL 查询，报告**订阅区间覆盖 2021 年、但在 2021 年内没有任何观看会话**的账户数量，结果列名为 `accounts_count`。

**示例 1：**

```
输入：
Subscriptions 表：
+------------+------------+------------+
| account_id | start_date | end_date   |
+------------+------------+------------+
| 9          | 2020-02-18 | 2021-10-30 |
| 3          | 2021-09-21 | 2021-11-13 |
| 11         | 2020-02-28 | 2020-08-18 |
| 13         | 2021-04-20 | 2021-09-22 |
| 4          | 2020-10-26 | 2021-05-08 |
| 5          | 2020-09-11 | 2021-01-17 |
+------------+------------+------------+

Streams 表：
+------------+------------+-------------+
| session_id | account_id | stream_date |
+------------+------------+-------------+
| 14         | 9          | 2020-05-16  |
| 16         | 3          | 2021-10-27  |
| 18         | 11         | 2020-04-29  |
| 17         | 13         | 2021-08-08  |
| 19         | 4          | 2020-12-31  |
| 13         | 5          | 2021-01-05  |
+------------+------------+-------------+

输出：
+----------------+
| accounts_count |
+----------------+
| 2              |
+----------------+

解释：账户 9 和 4 的订阅覆盖了 2021 年，但它们在 2021 年内没有任何观看会话；账户 3、13、5 在 2021 年内有会话；账户 11 的订阅在 2020 年就结束了，不算覆盖 2021 年。
```

## 题解

::: details 点击查看题解

### 思路

题意是统计「订阅区间覆盖 2021 年、但 2021 年内一次观看都没有」的账户数。注意 Streams 里可能有落在订阅区间内、却不在 2021 年的会话（比如账户 4 的 2020-12-31），这种依然算「2021 年无流量」。

「不存在」这类条件用 NOT EXISTS 相关子查询表达最稳妥：只要该账户在 2021 年没有任何会话记录就命中。相比之下 LEFT JOIN + IS NULL 在会话有多条时容易重复计数。

订阅覆盖 2021 的判定写成 start_date <= '2021-12-31' AND end_date >= '2021-01-01'，而不是 YEAR(start_date) = 2021，前者能走索引，语义也更准确（跨年订阅同样算覆盖）。

### SQL 实现

```sql
SELECT COUNT(*) AS accounts_count
FROM Subscriptions AS s
WHERE s.start_date <= '2021-12-31'
  AND s.end_date >= '2021-01-01'
  AND NOT EXISTS (
      SELECT 1
      FROM Streams AS st
      WHERE st.account_id = s.account_id
        AND st.stream_date BETWEEN '2021-01-01' AND '2021-12-31'
  );
```

### 复杂度分析

- 时间复杂度：O(n)，对每个订阅做一次按 account_id 的存在性探测（有索引时近似 O(n)）
- 空间复杂度：O(1)，只返回一个计数

:::
