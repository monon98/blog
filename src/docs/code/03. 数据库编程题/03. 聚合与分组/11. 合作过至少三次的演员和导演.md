# 合作过至少三次的演员和导演

> 难度：简单 | 标签：分组聚合 | [LeetCode 原题](https://leetcode.cn/problems/actors-and-directors-who-cooperated-at-least-three-times/)

## 题目描述

`ActorDirector` 表：

```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| actor_id    | int     |
| director_id | int     |
| timestamp   | int     |
+-------------+---------+
timestamp 是这张表的主键(具有唯一值的列).
```

编写解决方案找出合作过至少三次的演员和导演的 id 对 `(actor_id, director_id)`

**示例 1：**

```
输入：
ActorDirector 表：
+-------------+-------------+-------------+
| actor_id    | director_id | timestamp   |
+-------------+-------------+-------------+
| 1           | 1           | 0           |
| 1           | 1           | 1           |
| 1           | 1           | 2           |
| 1           | 2           | 3           |
| 1           | 2           | 4           |
| 2           | 1           | 5           |
| 2           | 1           | 6           |
+-------------+-------------+-------------+
输出：
+-------------+-------------+
| actor_id    | director_id |
+-------------+-------------+
| 1           | 1           |
+-------------+-------------+
解释：
唯一的 id 对是 (1, 1)，他们恰好合作了 3 次。
```

## 题解

::: details 点击查看题解

### 思路

按 `(actor_id, director_id)` 二元组分组，统计每组的行数（即合作次数），再用 `HAVING COUNT(*) >= 3` 过滤。`timestamp` 是主键，每行代表一次独立合作，所以直接 `COUNT(*)` 就是合作次数，无需去重。

易错点在于分组键必须同时包含两列：只按 `actor_id` 分组会把该演员与所有导演的合作混在一起，只按 `director_id` 同理。另外过滤条件要用 `HAVING` 而不是 `WHERE`——`COUNT(*)` 是聚合结果，只能在分组后判断；写成 `WHERE COUNT(*) >= 3` 会直接报错。

输出只要 `actor_id, director_id` 两列，不要带出 `COUNT`。替代写法：窗口函数 `COUNT(*) OVER (PARTITION BY actor_id, director_id)` 后在外层筛 `>= 3` 也能通过，但本题一次分组即可，没必要多扫一遍。

### SQL 实现

```sql
SELECT actor_id, director_id
FROM ActorDirector
GROUP BY actor_id, director_id
HAVING COUNT(*) >= 3;
```

### 复杂度分析

- 时间复杂度：O(n)，n 为表行数，一次哈希分组完成。
- 空间复杂度：O(k)，k 为不同 (actor_id, director_id) 对的数量。
