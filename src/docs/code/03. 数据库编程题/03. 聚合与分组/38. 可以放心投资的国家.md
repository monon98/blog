# 可以放心投资的国家

> 难度：中等 | 标签：多表连接、分组聚合、子查询 | [LeetCode 原题](https://leetcode.cn/problems/countries-you-can-safely-invest-in/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

表：`Person`

```
+--------------+---------+
| Column Name  | Type    |
+--------------+---------+
| id           | int     |
| name         | varchar |
| phone_number | varchar |
+--------------+---------+
id 是此表中具有唯一值的列。
每一行包含一个人的 id、姓名和电话号码，电话号码的前三位是这个人的国家区号。
```

表：`Country`

```
+--------------+---------+
| Column Name  | Type    |
+--------------+---------+
| name         | varchar |
| country_code | varchar |
+--------------+---------+
name 是此表中具有唯一值的列。
每一行包含国家名和它的三位区号。
```

表：`Calls`

```
+-----------+------+
| Column Name | Type |
+-----------+------+
| caller_id   | int  |
| callee_id   | int  |
| duration    | int  |
+-----------+------+
此表没有主键。
每一行记录一通电话的主叫者 id、被叫者 id 和通话时长（分钟）。
```

`caller_id` 和 `callee_id` 都是 `Person` 表中的 `id`。

编写一个解决方案，找出「与该国居民有关的通话」平均时长**严格大于**全局平均通话时长的国家。对某个国家而言，该国居民作为主叫者或被叫者的每一通电话都算与该国有关，把它们的 `duration` 求平均后再与 `Calls` 表中所有通话的平均时长比较。

返回结果表**无顺序要求**，只需包含国家名。

**示例 1：**

输入：

```
Person table:
+----+----------+--------------+
| id | name     | phone_number |
+----+----------+--------------+
| 3  | Jonathan | 051-1234567  |
| 12 | Elvis    | 051-7654321  |
| 1  | Moncef   | 212-1234567  |
| 2  | Maroua   | 212-6523651  |
| 7  | Meir     | 972-1234567  |
| 9  | Rachel   | 972-0011100  |
+----+----------+--------------+

Country table:
+----------+--------------+
| name     | country_code |
+----------+--------------+
| Peru     | 051          |
| Israel   | 972          |
| Morocco  | 212          |
| Germany  | 049          |
| Ethiopia | 251          |
+----------+--------------+

Calls table:
+-----------+-----------+----------+
| caller_id | callee_id | duration |
+-----------+-----------+----------+
| 1         | 9         | 33       |
| 2         | 9         | 4        |
| 1         | 2         | 59       |
| 3         | 12        | 102      |
| 3         | 12        | 330      |
| 12        | 3         | 5        |
| 7         | 9         | 13       |
| 7         | 1         | 3        |
| 9         | 7         | 1        |
| 1         | 7         | 7        |
+-----------+-----------+----------+
```

输出：

```
+---------+
| country |
+---------+
| Peru    |
+---------+
```

解释：

- 全局平均通话时长为 557 / 10 = 55.7 分钟。
- Peru（区号 051）的居民是 3 和 12，涉及他们的通话共三通，时长分别为 102、330、5。因为每通电话的两个当事人都是秘鲁人，所以每通电话对 Peru 计两次，合计 874 / 6 ≈ 145.67，大于 55.7。
- Morocco（区号 212）的平均时长约为 165 / 6 = 27.5，小于全局平均。
- Israel（区号 972）的平均时长约为 75 / 8 = 9.375，小于全局平均。
- Germany、Ethiopia 在 `Person` 表中没有居民，因此不会出现在结果里。

## 题解

::: details 点击查看题解

### 思路

国家信息是从电话号码里「拆」出来的：`phone_number` 的前三位就是区号，所以要先 `LEFT(p.phone_number, 3) = c.country_code` 把人归到国家，得到「人 → 国家」的映射。

真正的坑在第二步：一通电话同时涉及主叫和被叫两个人的国家，所以不能只按 `caller_id` 聚合，也不能只按 `callee_id` 聚合。把 `Calls` 用 `UNION ALL` 拆成「主叫视角」和「被叫视角」两行长表，再与「人 → 国家」连接，这样一通电话会自然地为双方各自的国家各贡献一次时长，正好符合题意。注意这里必须是 `UNION ALL`：两个方向的时长本来就该分别累加，去重会算错平均值。

聚合完成后用 `HAVING AVG(duration) > (SELECT AVG(duration) FROM Calls)` 与全局平均比较。全局平均必须用标量子查询（或 `AVG(duration) OVER ()` 窗口函数）单独算，不能直接写进 `HAVING` 里的聚合表达式中——聚合函数不能嵌套。

还有个容易忽略的细节：`Country` 里没有居民的国家（Germany、Ethiopia）在连接后根本不会出现，所以不需要 `LEFT JOIN`，也不需要额外过滤。

### SQL 实现

```sql
WITH person_country AS (
    SELECT p.id AS user_id, c.name AS country
    FROM Person p
    JOIN Country c ON LEFT(p.phone_number, 3) = c.country_code
),
all_calls AS (
    SELECT caller_id AS user_id, duration FROM Calls
    UNION ALL
    SELECT callee_id AS user_id, duration FROM Calls
)
SELECT pc.country
FROM all_calls a
JOIN person_country pc ON pc.user_id = a.user_id
GROUP BY pc.country
HAVING AVG(a.duration) > (SELECT AVG(duration) FROM Calls);
```

### 复杂度分析

- 时间复杂度：O(n + m)，n 为通话数、m 为人数；需要扫两遍 `Calls`（一遍拆双向、一遍算全局平均），再对人数做一次连接与分组。
- 空间复杂度：O(k)，k 为有居民的国家数，仅保存分组聚合结果。

:::
