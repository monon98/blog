# 好友申请 II ：谁有最多的好友

> 难度：中等 | 标签：分组聚合、UNION | [LeetCode 原题](https://leetcode.cn/problems/friend-requests-ii-who-has-the-most-friends/)

## 题目描述

`RequestAccepted` 表：

```
+----------------+---------+
| Column Name    | Type    |
+----------------+---------+
| requester_id   | int     |
| accepter_id    | int     |
| accept_date    | date    |
+----------------+---------+
(requester_id, accepter_id) 是这张表的主键(具有唯一值的列的组合)。
这张表包含发送好友请求的人的 ID ，接收好友请求的人的 ID ，以及好友请求通过的日期。
```

编写解决方案，找出拥有最多的好友的人和他拥有的好友数目。

生成的测试用例保证拥有最多好友数目的只有 1 个人。

查询结果格式如下例所示。

**示例 1：**

```
输入：
RequestAccepted 表：
+--------------+-------------+-------------+
| requester_id | accepter_id | accept_date |
+--------------+-------------+-------------+
| 1            | 2           | 2016/06/03  |
| 1            | 3           | 2016/06/08  |
| 2            | 3           | 2016/06/08  |
| 3            | 4           | 2016/06/09  |
+--------------+-------------+-------------+
输出：
+----+-----+
| id | num |
+----+-----+
| 3  | 3   |
+----+-----+
解释：
编号为 3 的人是编号为 1 ，2 和 4 的人的好友，所以他总共有 3 个好友，比其他人都多。
```

**进阶：**在真实世界里，可能会有多个人拥有好友数相同且最多，你能找到所有这些人吗？

## 题解

::: details 点击查看题解

### 思路

核心难点在于：好友关系是 **双向** 的——`RequestAccepted` 里每一行只记录了「发起方 → 接受方」，但对两人来说好友关系互相成立。所以统计每个人的好友数时，必须把 `requester_id` 和 `accepter_id` 两列都当作「人」来看待：先用 `UNION ALL` 把每行拆成两条记录（发起方一条、接受方一条），再按 id 分组计数，最后取最大值。

注意必须用 `UNION ALL` 而非 `UNION`：`UNION` 会做去重，如果同一个人既作为发起方又作为接受方出现（例如 id 1 向 2 发起、又被 4 接受），去重会把两条不同来源的记录合并成一条，导致计数偏小。拆分后示例中 id 3 出现 3 次（作为接受方 3 次），id 1 出现 2 次，正确得到 `3 → 3`。

因为题目保证最多者唯一，直接 `ORDER BY num DESC LIMIT 1` 即可。进阶问题（可能并列）改用窗口函数 `RANK()` 按 num 降序编号、筛 `rk = 1`，或用 `HAVING num = (SELECT MAX(...) ...)`，即可返回所有并列者。

### SQL 实现

```sql
SELECT id, COUNT(*) AS num
FROM (
    SELECT requester_id AS id FROM RequestAccepted
    UNION ALL
    SELECT accepter_id AS id FROM RequestAccepted
) t
GROUP BY id
ORDER BY num DESC
LIMIT 1;
```

### 复杂度分析

- 时间复杂度：O(n log n)，n 为好友关系数（拆分后为 2n），分组线性、排序主导。
- 空间复杂度：O(n)，拆分结果与分组哈希表。

:::
