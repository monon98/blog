# 总旅行距离

> 难度：简单 | 标签：多表连接、分组聚合 | [LeetCode 原题](https://leetcode.cn/problems/total-traveled-distance/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

表：`Users`

```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| user_id     | int     |
| name        | varchar |
+-------------+---------+
user_id 是此表中具有唯一值的列。
此表的每一行包含用户 id 和姓名。
```

表：`Rides`

```
+--------------+------+
| Column Name  | Type |
+--------------+------+
| ride_id      | int  |
| user_id      | int  |
| distance     | int  |
+--------------+------+
ride_id 是此表中具有唯一值的列。
此表中的每一行包含乘车 id、用户 id 和旅行距离。
```

编写一个解决方案，计算每个用户的旅行距离 `distance`。如果有用户没有任何旅行记录，那么他们的 distance 应被视为 0。输出 `user_id`、`name` 和总旅行距离 `traveled distance`。按 `user_id` 升序排序返回结果表。

**示例 1：**

输入：

```
Users table:
+---------+---------+
| user_id | name    |
+---------+---------+
| 17      | Addison |
| 14      | Ethan   |
| 4       | Michael |
| 2       | Avery   |
| 10      | Eleanor |
+---------+---------+

Rides table:
+---------+---------+----------+
| ride_id | user_id | distance |
+---------+---------+----------+
| 72      | 17      | 160      |
| 42      | 14      | 161      |
| 45      | 4       | 59       |
| 32      | 2       | 197      |
| 15      | 4       | 357      |
| 56      | 2       | 196      |
| 10      | 14      | 25       |
+---------+---------+----------+
```

输出：

```
+---------+---------+-------------------+
| user_id | name    | traveled distance |
+---------+---------+-------------------+
| 2       | Avery   | 393               |
| 4       | Michael | 416               |
| 10      | Eleanor | 0                 |
| 14      | Ethan   | 186               |
| 17      | Addison | 160               |
+---------+---------+-------------------+
```

解释：

- User id 为 2 的用户完成了两次旅行，分别为 197 和 196，总旅行距离为 393。
- User id 为 4 的用户完成了两次旅行，分别为 59 和 357，总旅行距离为 416。
- User id 为 14 的用户完成了两次旅行，分别为 161 和 25，总旅行距离为 186。
- User id 为 17 的用户只完成了一次旅行，距离为 160。
- User id 为 10 的用户没有完成任何旅行，因此总旅行距离为 0。

按升序排序的 `user_id` 返回结果表。

## 题解

::: details 点击查看题解

### 思路

统计总里程天然是「按用户分组求和」的问题，但题目明确要求**所有**用户都要出现在结果里，包括一次车都没打过的 Eleanor（距离记 0）。这决定了连接方向必须是 `Users LEFT JOIN Rides`：以用户表为主表，没匹配到行程的用户行依然保留，`SUM(distance)` 对全 NULL 的组返回 NULL，再用 `IFNULL(..., 0)` 兜底成 0。

如果图省事写成 `Rides JOIN Users`（内连接），Eleanor 这类用户会整行消失，直接判错；同理也不能先聚合 Rides 再连接 Users，因为那样同样会丢掉无行程用户——除非用右连接或子查询补行，都不如左连接直接。

列名 `traveled distance` 中间带空格，必须用反引号包裹别名；`GROUP BY` 建议把 `user_id` 和 `name` 一起写上（或只按 `user_id` 分组，依赖主键函数依赖），排序则按 `user_id` 升序，与题面一致。

### SQL 实现

```sql
SELECT
    u.user_id,
    u.name,
    IFNULL(SUM(r.distance), 0) AS `traveled distance`
FROM Users u
LEFT JOIN Rides r ON r.user_id = u.user_id
GROUP BY u.user_id, u.name
ORDER BY u.user_id;
```

### 复杂度分析

- 时间复杂度：O(m + n)，m 为用户数、n 为行程数，一次连接加分组求和。
- 空间复杂度：O(m)，分组结果最多为每个用户一行。

:::
