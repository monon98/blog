# 查询近 30 天活跃用户数 II

> 难度：简单 | 标签：日期函数、去重计数、聚合计算 | [LeetCode 原题](https://leetcode.cn/problems/user-activity-for-the-past-30-days-ii/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

`Activity` 表：

```
+---------------+---------+
| Column Name   | Type    |
+---------------+---------+
| user_id       | int     |
| session_id    | int     |
| activity_date | date    |
| activity_type | enum    |
+---------------+---------+
该表可能包含重复数据。
activity_type 列是 ENUM 类型，取值为 ('open_session', 'end_session', 'scroll_down', 'send_message')。
该表记录社交媒体网站的用户活动，每个会话只属于一个用户。
```

编写一个 SQL 查询，统计截至 `2019-07-27`（含当天）的 30 天内，活跃用户的 **人均会话数**，结果四舍五入保留两位小数，列名为 `average_sessions_per_user`。

- 统计窗口为 `2019-06-28` 至 `2019-07-27`（两端都包含）。
- 只要某个会话在窗口内有一条活动记录，就算该用户的一个活跃会话；同一个会话的多条活动记录只计一次。
- 窗口内没有任何活跃用户时，返回 `0`。

**示例 1：**

```
输入：
Activity table:
+---------+------------+---------------+---------------+
| user_id | session_id | activity_date | activity_type |
+---------+------------+---------------+---------------+
| 1       | 1          | 2019-07-20    | open_session  |
| 1       | 1          | 2019-07-20    | scroll_down   |
| 1       | 1          | 2019-07-20    | end_session   |
| 2       | 4          | 2019-07-20    | open_session  |
| 2       | 4          | 2019-07-21    | send_message  |
| 2       | 4          | 2019-07-21    | end_session   |
| 3       | 2          | 2019-07-21    | open_session  |
| 3       | 2          | 2019-07-21    | send_message  |
| 3       | 2          | 2019-07-21    | end_session   |
| 3       | 5          | 2019-07-21    | open_session  |
| 3       | 5          | 2019-07-21    | scroll_down   |
| 3       | 5          | 2019-07-21    | end_session   |
| 4       | 3          | 2019-06-25    | open_session  |
| 4       | 3          | 2019-06-25    | end_session   |
+---------+------------+---------------+---------------+
输出：
+---------------------------+
| average_sessions_per_user |
+---------------------------+
| 1.33                      |
+---------------------------+
解释：
窗口内活跃的用户是 1、2、3 号（4 号只有 2019-06-25 的记录，落在窗口外）。
1 号有 1 个会话，2 号有 1 个会话，3 号有 2 个会话（session 2 和 session 5）。
共 4 个会话、3 个活跃用户，平均值 = 4 / 3 = 1.33。
```

## 题解

::: details 点击查看题解

### 思路

两步走：先按用户汇总「该用户有多少个不同的会话」，再对所有用户求平均。第一步的分组键是 `user_id`，聚合用 `COUNT(DISTINCT session_id)`——样本里 3 号用户一个会话有 3 条活动、且有两个会话，若写成 `COUNT(*)` 会把活动条数当成会话数，结果直接偏大。

第二步注意分母是 **活跃用户数** 而不是全表用户数，所以平均值要在第一步的子查询结果上算：`SUM(sessions) / COUNT(*)`，其中 `COUNT(*)` 此时等于活跃用户人数。窗口过滤条件与上一题相同，左端用 `DATE_SUB('2019-07-27', INTERVAL 29 DAY)` 才是 30 天。

边界处理：如果窗口内没有任何活动，子查询为空，`SUM` 为 NULL、`COUNT(*)` 为 0，相除得到 NULL，需要用 `IFNULL(..., 0)` 兜底成 0；`ROUND` 放在最外层保证最终只有两位小数。

### SQL 实现

```sql
SELECT IFNULL(ROUND(SUM(sessions) / COUNT(*), 2), 0) AS average_sessions_per_user
FROM (
    SELECT user_id,
           COUNT(DISTINCT session_id) AS sessions
    FROM Activity
    WHERE activity_date BETWEEN DATE_SUB('2019-07-27', INTERVAL 29 DAY) AND '2019-07-27'
    GROUP BY user_id
) t;
```

### 复杂度分析

- 时间复杂度：O(n)，n 为 `Activity` 行数，一次扫描完成过滤与分组。
- 空间复杂度：O(u)，u 为活跃用户数，用于保存每个用户的会话数。

:::
