# 每月交易 II

> 难度：中等 | 标签：UNION、日期函数、分组聚合 | [LeetCode 原题](https://leetcode.cn/problems/monthly-transactions-ii/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

`Transactions` 表：

```
+---------------+---------+
| Column Name   | Type    |
+---------------+---------+
| id            | int     |
| country       | varchar |
| state         | enum    |
| amount        | int     |
| trans_date    | date    |
+---------------+---------+
id 是该表的主键，state 取值为 ('approved', 'declined')。
该表包含所有交易记录：发生日期、金额、所属国家以及交易状态。
```

`Chargebacks` 表：

```
+---------------+---------+
| Column Name   | Type    |
+---------------+---------+
| trans_id      | int     |
| trans_date    | date    |
+---------------+---------+
该表记录退单（chargeback）：trans_id 是被退单的那笔交易 id，trans_date 是退单发生的日期。
```

编写一个 SQL 查询，按月汇总每个国家的：

- `approved_count`：当月 `approved` 状态交易的笔数；
- `approved_amount`：当月 `approved` 状态交易的金额合计；
- `chargeback_count`：当月发生退单的笔数；
- `chargeback_amount`：当月发生退单的金额合计（金额取被退单交易的 `amount`）。

结果列依次为 `month`（格式 `YYYY-MM`）、`country`、`approved_count`、`approved_amount`、`chargeback_count`、`chargeback_amount`，顺序不限。某个月某国家只出现退单时，`approved_count` 与 `approved_amount` 记为 0，反之亦然。

**示例 1：**

```
输入：
Transactions table:
+-----+---------+----------+--------+------------+
| id  | country | state    | amount | trans_date |
+-----+---------+----------+--------+------------+
| 101 | US      | approved | 1000   | 2019-05-18 |
| 102 | US      | declined | 2000   | 2019-05-19 |
| 103 | US      | approved | 3000   | 2019-06-10 |
| 104 | US      | declined | 4000   | 2019-06-13 |
| 105 | US      | approved | 5000   | 2019-06-15 |
+-----+---------+----------+--------+------------+
Chargebacks table:
+----------+------------+
| trans_id | trans_date |
+----------+------------+
| 102      | 2019-05-29 |
| 101      | 2019-06-30 |
| 105      | 2019-09-18 |
+----------+------------+
输出：
+---------+---------+----------------+-----------------+------------------+-------------------+
| month   | country | approved_count | approved_amount | chargeback_count | chargeback_amount |
+---------+---------+----------------+-----------------+------------------+-------------------+
| 2019-05 | US      | 1              | 1000            | 1                | 2000              |
| 2019-06 | US      | 2              | 8000            | 1                | 1000              |
| 2019-09 | US      | 0              | 0               | 1                | 5000              |
+---------+---------+----------------+-----------------+------------------+-------------------+
解释：
2019-05：101 号交易 approved（1000），102 号交易在当月被退单（2000）。
2019-06：103、105 号交易 approved（3000 + 5000 = 8000），101 号交易在当月被退单（1000）。
2019-09：105 号交易在当月被退单（5000），当月没有 approved 交易。
```

## 题解

::: details 点击查看题解

### 思路

两类指标来自两张表，但它们的统计口径是 **同一个月度分组**，最自然的做法是把两类「事实」先统一成同一种宽表形态，再用一次 `GROUP BY` 同时算出四列。具体做法是：从 `Transactions` 里筛出 `state = 'approved'` 的行作为 approved 事实；把 `Chargebacks` 与 `Transactions` 连接，取出被退单交易的 `country` 和 `amount`，按 **退单日期** 归月作为 chargeback 事实。两者 `UNION ALL` 起来，每行带上一个标记列区分来源。

`UNION ALL` 而不是 `UNION`：同一笔交易可能既是 approved 又产生了一条退单，去重会丢数据；而且这里行本来就代表不同的事实。标记列用 `'approved'` / `'chargeback'` 字符串即可。

外层聚合时要用 `SUM(type = 'approved')` 这类条件计数，配合 `SUM(CASE WHEN type = 'approved' THEN amount ELSE 0 END)` 求金额，这样两类事实混合也能各归各列。注意退单的月份必须用 `Chargebacks.trans_date`，用交易日期归月会全部算错月份；国家则取交易表的，因为退单表没有国家字段。若某月某国没有 approved 交易，条件聚合天然给出 0。

### SQL 实现

```sql
SELECT month,
       country,
       SUM(type = 'approved')                                   AS approved_count,
       SUM(CASE WHEN type = 'approved' THEN amount ELSE 0 END)  AS approved_amount,
       SUM(type = 'chargeback')                                 AS chargeback_count,
       SUM(CASE WHEN type = 'chargeback' THEN amount ELSE 0 END) AS chargeback_amount
FROM (
    SELECT DATE_FORMAT(trans_date, '%Y-%m') AS month,
           country,
           amount,
           'approved' AS type
    FROM Transactions
    WHERE state = 'approved'

    UNION ALL

    SELECT DATE_FORMAT(c.trans_date, '%Y-%m') AS month,
           t.country,
           t.amount,
           'chargeback' AS type
    FROM Chargebacks c
    JOIN Transactions t ON t.id = c.trans_id
) x
GROUP BY month, country
ORDER BY month, country;
```

### 复杂度分析

- 时间复杂度：O(n + m)，n 为交易数、m 为退单数，扫描与一次哈希聚合。
- 空间复杂度：O(g)，g 为「月份 × 国家」的组合数，外加中间结果集。
