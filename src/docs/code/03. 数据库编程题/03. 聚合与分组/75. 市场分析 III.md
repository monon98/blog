# 市场分析 III

> 难度：中等 | 标签：多表连接、分组聚合、子查询 | [LeetCode 原题](https://leetcode.cn/problems/market-analysis-iii/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

表：`Users`

```
+----------------+---------+
| Column Name    | Type    |
+----------------+---------+
| seller_id      | int     |
| join_date      | date    |
| favorite_brand | varchar |
+----------------+---------+
seller_id 是该表具有唯一值的列。
该表包含卖家的 ID、加入日期以及最喜欢的品牌。
```

表：`Items`

```
+---------------+---------+
| Column Name   | Type    |
+---------------+---------+
| item_id       | int     |
| item_brand    | varchar |
+---------------+---------+
item_id 是该表具有唯一值的列。
该表包含商品 ID 和商品品牌。
```

表：`Orders`

```
+---------------+---------+
| Column Name   | Type    |
+---------------+---------+
| order_id      | int     |
| order_date    | date    |
| item_id       | int     |
| seller_id     | int     |
+---------------+---------+
order_id 是该表具有唯一值的列。
item_id 是指向 Items 表的外键。
seller_id 是指向 Users 表的外键。
该表包含订单 ID、下单日期、商品 ID 和卖家 ID。
```

编写一个解决方案，找到卖出数量 **最多** 的 **非最喜欢的品牌** 的 **不同商品** 的顶级卖家。如果有多个卖家有相同的最高卖出数量，返回所有这些卖家。

返回按 `seller_id` 升序排序的结果表。

**示例 1：**

输入：

```
Users table:
+-----------+------------+----------------+
| seller_id | join_date  | favorite_brand |
+-----------+------------+----------------+
| 1         | 2019-01-01 | Lenovo         |
| 2         | 2019-02-09 | Samsung        |
| 3         | 2019-01-19 | LG             |
+-----------+------------+----------------+

Orders table:
+----------+------------+---------+-----------+
| order_id | order_date | item_id | seller_id |
+----------+------------+---------+-----------+
| 1        | 2019-08-01 | 4       | 2         |
| 2        | 2019-08-02 | 2       | 3         |
| 3        | 2019-08-03 | 3       | 3         |
| 4        | 2019-08-04 | 1       | 2         |
| 5        | 2019-08-04 | 4       | 2         |
+----------+------------+---------+-----------+

Items table:
+---------+------------+
| item_id | item_brand |
+---------+------------+
| 1       | Samsung    |
| 2       | Lenovo     |
| 3       | LG         |
| 4       | HP         |
+---------+------------+
```

输出：

```
+-----------+-----------+
| seller_id | num_items |
+-----------+-----------+
| 2         | 1         |
| 3         | 1         |
+-----------+-----------+
```

解释：

- 卖家 ID 为 2 的用户销售了三件商品，但只有两件不是他最喜欢的商品。由于这两个商品相同，所以我们只计数 1。
- 卖家 ID 为 3 的用户销售了两件商品，但只有一件不是他最喜欢的商品。我们将只把非最喜欢商品列入计数中。
- 因为卖家 ID 为 2 和 3 的卖家都有一件商品列入计数，所以他们都将显示在输出中。

## 题解

::: details 点击查看题解

### 思路

这道题有三个容易被忽略的限定词：**不同商品**、**非最喜欢品牌**、**数量最多**。对应到 SQL 上，先是三表等值连接——`Orders` 拿到卖家，再按 `item_id` 连 `Items` 拿到品牌——然后在 `WHERE` 里用 `item_brand <> favorite_brand` 把自家偏好品牌过滤掉，最后按 `seller_id` 分组做 `COUNT(DISTINCT item_id)`。

`DISTINCT` 是本题最大的坑：测试数据里卖家 2 把商品 4（HP）卖了两次（order 1 和 order 5），若用 `COUNT(item_id)` 会得到 2，与正确答案 1 直接不符。过滤也必须发生在聚合**之前**，先过滤再计数才能保证「非最喜欢」这个条件作用在每一行上。

求「最多」时不能在同一层里既聚合又用 `WHERE num_items = MAX(...)`，因为 `MAX` 在聚合之后才能计算。常见做法是把分组结果存进 CTE，外层再与 `(SELECT MAX(num_items) FROM T)` 比较；并列第一的卖家会被同时保留，最后按 `seller_id` 升序输出。

### SQL 实现

```sql
WITH
    T AS (
        SELECT o.seller_id, COUNT(DISTINCT o.item_id) AS num_items
        FROM Orders o
        JOIN Users u ON o.seller_id = u.seller_id
        JOIN Items i ON o.item_id = i.item_id
        WHERE i.item_brand <> u.favorite_brand
        GROUP BY o.seller_id
    )
SELECT seller_id, num_items
FROM T
WHERE num_items = (SELECT MAX(num_items) FROM T)
ORDER BY seller_id;
```

### 复杂度分析

- 时间复杂度：O(n log n)，n 为连接后的行数，连接、去重计数与求最大值均为线性，窗口/排序引入对数因子。
- 空间复杂度：O(s)，s 为卖家数量，CTE 中每个卖家保留一行。
