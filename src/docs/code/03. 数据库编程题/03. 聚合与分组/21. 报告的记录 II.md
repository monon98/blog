# 报告的记录 II

> 难度：中等 | 标签：多表连接、分组聚合 | [LeetCode 原题](https://leetcode.cn/problems/reported-posts-ii/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

`Actions` 表：

```
+---------------+---------+
| Column Name   | Type    |
+---------------+---------+
| user_id       | int     |
| post_id       | int     |
| action_date   | date    |
| action        | enum    |
| extra         | varchar |
+---------------+---------+
该表没有主键，可能存在重复行。
action 列是 ENUM 类型，取值为 ('view', 'like', 'reaction', 'comment', 'report', 'share')。
extra 列拥有可选信息，例如举报的理由（reason for report）或反应的类型。
```

`Removals` 表：

```
+---------------+---------+
| Column Name   | Type    |
+---------------+---------+
| post_id       | int     |
| remove_date   | date    |
+---------------+---------+
post_id 是该表的主键。
每一行表示某个帖子因被举报或被管理员审核而被删除。
```

编写一个 SQL 查询，计算 **每天被举报为 spam 的帖子中最终被删除的比例** 的平均值，结果保留两位小数，列名为 `average_daily_percent`。

说明：

- 只考虑 `action = 'report'` 且 `extra = 'spam'` 的举报；
- 对每个有 spam 举报的日期，比例 = 该日被举报的帖子中后来被删除的帖子数 ÷ 该日被举报的帖子数（同一帖子被多人举报只算一个）；
- 不关心删除日期，只要该帖子出现在 `Removals` 中即视为已删除；
- 最后对所有有 spam 举报的日子求比例的平均值，只输出一个数字。

**示例 1:**

```
输入:
Actions 表:
+---------+---------+-------------+--------+--------+
| user_id | post_id | action_date | action | extra  |
+---------+---------+-------------+--------+--------+
| 1       | 1       | 2019-07-01  | view   | null   |
| 1       | 1       | 2019-07-01  | like   | null   |
| 1       | 1       | 2019-07-01  | share  | null   |
| 2       | 2       | 2019-07-04  | view   | null   |
| 2       | 2       | 2019-07-04  | report | spam   |
| 3       | 4       | 2019-07-04  | view   | null   |
| 3       | 4       | 2019-07-04  | report | spam   |
| 4       | 3       | 2019-07-02  | view   | null   |
| 4       | 3       | 2019-07-02  | report | spam   |
| 5       | 2       | 2019-07-03  | view   | null   |
| 5       | 2       | 2019-07-03  | report | racism |
| 5       | 5       | 2019-07-03  | view   | null   |
| 5       | 5       | 2019-07-03  | report | racism |
+---------+---------+-------------+--------+--------+
Removals 表:
+---------+-------------+
| post_id | remove_date |
+---------+-------------+
| 2       | 2019-07-20  |
| 3       | 2019-07-18  |
+---------+-------------+
输出:
+-----------------------+
| average_daily_percent |
+-----------------------+
| 75.00                 |
+-----------------------+
解释:
2019-07-04 的比例是 50%，因为当天两个被举报为 spam 的帖子（2 和 4）中只有一个（2）被删除。
2019-07-02 的比例是 100%，因为当天唯一被举报为 spam 的帖子 3 被删除了。
其余各天没有 spam 举报，不参与计算，平均值为 (50 + 100) / 2 = 75%。
注意输出只有一个数字，并且不关心删除日期。
```

## 题解

::: details 点击查看题解

### 思路

题目要求「先按天算比例、再对天求平均」，是典型的两层聚合。内层按 `action_date` 分组，分母是当天被举报为 spam 的 **去重帖子数** `COUNT(DISTINCT a.post_id)`，分子是这些帖子中出现在 `Removals` 里的去重数 `COUNT(DISTINCT r.post_id)`；外层对每天的比例求 `AVG` 再乘 100、`ROUND(..., 2)` 保留两位。

几个关键坑。其一，两个过滤条件都要写：`action = 'report'` 排除 view/like 等行为，`extra = 'spam'` 排除 racism 等其他理由——示例中 2019-07-03 全是 racism 举报，必须整日剔除，否则分母被污染、结果不再是 75。其二，分子分母都必须 `DISTINCT`：同一帖子可能被多人举报（分母会重复计数），而 `Removals.post_id` 是主键不会重复，但 JOIN 后与举报行相乘仍需去重保护。其三，`LEFT JOIN` 不能写成 `INNER JOIN`——没被删除的帖子必须留在分母里，否则比例会全变成 100%。

「不关心删除日期」意味着只要 `post_id` 在 `Removals` 中出现即可，无需比较 `remove_date` 与 `action_date`。替代写法：先用一个 CTE 把 spam 举报按 (日期, 帖子) 去重、再连 `Removals` 统计，逻辑等价，在举报行极多时更省内存。

### SQL 实现

```sql
SELECT ROUND(AVG(removed_pct) * 100, 2) AS average_daily_percent
FROM (
    SELECT a.action_date,
           COUNT(DISTINCT r.post_id) / COUNT(DISTINCT a.post_id) AS removed_pct
    FROM Actions a
    LEFT JOIN Removals r
        ON a.post_id = r.post_id
    WHERE a.action = 'report'
      AND a.extra = 'spam'
    GROUP BY a.action_date
) t;
```

### 复杂度分析

- 时间复杂度：O(n log n)，n 为 spam 举报行数，连接与分组接近线性，去重与排序主导。
- 空间复杂度：O(d + k)，d 为不同举报日期数，k 为去重帖子数，分组与去重哈希表开销。
