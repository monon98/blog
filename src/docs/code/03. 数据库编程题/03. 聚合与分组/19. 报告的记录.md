# 报告的记录

> 难度：简单 | 标签：分组聚合、日期函数 | [LeetCode 原题](https://leetcode.cn/problems/reported-posts/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

`Actions` 表：

```
+---------------+---------+
| Column Name   | Type    |
+---------------+---------+
| user_id       | int     |
| post_id       | int     |
| action_date   | date    |
| action        | enum    |
| extra         | varchar |
+---------------+---------+
该表没有主键，可能存在重复行。
action 列是 ENUM 类型，取值为 ('view', 'like', 'reaction', 'comment', 'report', 'share')。
extra 列拥有可选信息，例如举报的理由（reason for report）或反应的类型。
```

编写一个 SQL 查询，报告 **昨天（假设今天是 2019-07-05，即 2019-07-04）** 每个举报理由下被举报的帖子数量。结果包含 `report_reason`（即 `extra`）和 `report_count` 两列，只统计数量不为 0 的举报理由，以任意顺序返回。

**示例 1:**

```
输入:
Actions 表:
+---------+---------+-------------+--------+--------+
| user_id | post_id | action_date | action | extra  |
+---------+---------+-------------+--------+--------+
| 1       | 1       | 2019-07-01  | view   | null   |
| 1       | 1       | 2019-07-01  | like   | null   |
| 1       | 1       | 2019-07-01  | share  | null   |
| 2       | 4       | 2019-07-04  | view   | null   |
| 2       | 4       | 2019-07-04  | report | spam   |
| 3       | 4       | 2019-07-04  | view   | null   |
| 3       | 4       | 2019-07-04  | report | spam   |
| 4       | 3       | 2019-07-02  | view   | null   |
| 4       | 3       | 2019-07-02  | report | spam   |
| 5       | 2       | 2019-07-04  | view   | null   |
| 5       | 2       | 2019-07-04  | report | racism |
| 5       | 5       | 2019-07-04  | view   | null   |
| 5       | 5       | 2019-07-04  | report | racism |
+---------+---------+-------------+--------+--------+
输出:
+---------------+--------------+
| report_reason | report_count |
+---------------+--------------+
| spam          | 1            |
| racism        | 2            |
+---------------+--------------+
解释:
昨天（2019-07-04）被举报为 spam 的只有帖子 4（被两人各举报一次，按帖子去重计 1 个）。
被举报为 racism 的有帖子 2 和帖子 5，共 2 个。
2019-07-02 的 spam 举报不属于昨天，不计入。
```

## 题解

::: details 点击查看题解

### 思路

三个过滤条件缺一不可：`action = 'report'` 只看举报行为（表里还有 view、like 等噪声行）、`action_date = DATE_SUB('2019-07-05', INTERVAL 1 DAY)` 锁定昨天、再按 `extra` 分组计数。日期用 `DATE_SUB` 减一天比手写 `'2019-07-04'` 更能体现「昨天」的语义；替代写法 `DATEDIFF('2019-07-05', action_date) = 1` 也能通过，但对 `action_date` 有索引时 `=` 直接比较更利于利用索引。

最大的易错点是计数口径：`extra` 是举报理由，同一个帖子可能被多个用户以同一理由重复举报（示例中帖子 4 被 user 2 和 user 3 各举报一次 spam），题目要的是 **帖子数** 而非举报次数，所以必须 `COUNT(DISTINCT post_id)`，写成 `COUNT(*)` 会把 spam 数成 2。

另外「只统计数量不为 0 的理由」不需要额外 `HAVING`：分组本身只对存在的行进行，只要先过滤 `action = 'report'`，每个 `extra` 组至少有一条记录。注意 `extra` 可能为 `NULL` 的行——那些属于 view/like 等行为，已被 `action` 条件排除，不会混进结果。

### SQL 实现

```sql
SELECT extra AS report_reason,
       COUNT(DISTINCT post_id) AS report_count
FROM Actions
WHERE action = 'report'
  AND action_date = DATE_SUB('2019-07-05', INTERVAL 1 DAY)
GROUP BY extra;
```

### 复杂度分析

- 时间复杂度：O(n)，n 为表行数，一次条件过滤加分组计数。
- 空间复杂度：O(g)，g 为举报理由种类数，分组哈希表开销。

:::
