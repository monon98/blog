# 发票中的产品金额

> 难度：简单 | 标签：多表连接、分组聚合、IFNULL | [LeetCode 原题](https://leetcode.cn/problems/products-worth-over-invoices/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

表：`Product`

```
+------------+---------+
| Column Name | Type   |
+------------+---------+
| product_id  | int    |
| name        | varchar|
+------------+---------+
product_id 是此表中具有唯一值的列。
每一行包含产品 id 和产品名。
```

表：`Invoice`

```
+------------+------+
| Column Name | Type |
+------------+------+
| invoice_id  | int  |
| product_id  | int  |
| rest        | int  |
| paid        | int  |
| canceled    | int  |
| refunded    | int  |
+------------+------+
(invoice_id, product_id) 是此表中具有唯一值的列的组合。
每一行表示某张发票上某个产品的数量明细：
`rest` 为未付款数量，`paid` 为已付款数量，`canceled` 为取消数量，`refunded` 为退款数量。
`product_id` 是 `Product` 表中的 `product_id`。
```

编写一个解决方案，报告每个产品的 `product_id`、`name`，以及该产品在**所有发票**上 `rest`、`paid`、`canceled`、`refunded` 四个字段各自的总和。

如果某个产品从未出现在任何发票中，它的四个汇总值都输出 0。

返回结果表**无顺序要求**。

**示例 1：**

输入：

```
Product table:
+------------+-------+
| product_id | name  |
+------------+-------+
| 0          | ham   |
| 1          | bacon |
+------------+-------+

Invoice table:
+------------+------------+------+------+----------+----------+
| invoice_id | product_id | rest | paid | canceled | refunded |
+------------+------------+------+------+----------+----------+
| 23         | 0          | 2    | 0    | 5        | 0        |
| 12         | 0          | 0    | 4    | 0        | 3        |
| 1          | 1          | 1    | 1    | 0        | 1        |
| 2          | 1          | 1    | 0    | 1        | 1        |
| 3          | 1          | 0    | 1    | 1        | 1        |
| 4          | 1          | 1    | 1    | 1        | 0        |
+------------+------------+------+------+----------+----------+
```

输出：

```
+------------+-------+------+------+----------+----------+
| product_id | name  | rest | paid | canceled | refunded |
+------------+-------+------+------+----------+----------+
| 0          | ham   | 2    | 4    | 5        | 3        |
| 1          | bacon | 3    | 3    | 3        | 3        |
+------------+-------+------+------+----------+----------+
```

解释：

- 产品 0（ham）：rest 2 + 0 = 2，paid 0 + 4 = 4，canceled 5 + 0 = 5，refunded 0 + 3 = 3。
- 产品 1（bacon）：rest 1 + 1 + 0 + 1 = 3，paid 1 + 0 + 1 + 1 = 3，canceled 0 + 1 + 1 + 1 = 3，refunded 1 + 1 + 1 + 0 = 3。

## 题解

::: details 点击查看题解

### 思路

这是一道「主表 + 可选明细表」的典型题：`Product` 是全集，`Invoice` 里可能一条记录都没有。题目明确要求没上过发票的产品也要输出 0，因此必须用 `Product LEFT JOIN Invoice`，以内连接写法会把这些产品整行丢掉。

四个指标口径完全一致，都是对明细列求和，所以直接四个 `SUM(...)` 并列，再 `GROUP BY product_id, name` 即可。没有匹配行时 `SUM` 返回 NULL，要套 `IFNULL(..., 0)`；注意这里不能用 `COUNT`，`COUNT(i.rest)` 得到的是发票张数而不是数量之和。

有个细节值得一想：题面没要求过滤掉四列全为 0 的发票，也不该过滤——即使某张发票各项都是 0，它对总和没有贡献，留着不会影响结果；而如果误用 `WHERE rest + paid + canceled + refunded > 0`，会顺带把 `LEFT JOIN` 补出来的 NULL 行筛掉，零发票产品又会消失。

返回列名必须严格是 `rest`、`paid`、`canceled`、`refunded`（注意 `canceled` 是美式单 l 拼写，别写成 `cancelled`），列名对不上会直接判错。

### SQL 实现

```sql
SELECT p.product_id,
       p.name,
       IFNULL(SUM(i.rest), 0)     AS rest,
       IFNULL(SUM(i.paid), 0)     AS paid,
       IFNULL(SUM(i.canceled), 0) AS canceled,
       IFNULL(SUM(i.refunded), 0) AS refunded
FROM Product p
LEFT JOIN Invoice i ON i.product_id = p.product_id
GROUP BY p.product_id, p.name
ORDER BY p.product_id;
```

### 复杂度分析

- 时间复杂度：O(n + m)，n 为产品数、m 为发票明细数。
- 空间复杂度：O(n)，每个产品一行结果。

:::
