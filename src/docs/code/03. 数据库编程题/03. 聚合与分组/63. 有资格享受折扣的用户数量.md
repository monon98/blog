# 有资格享受折扣的用户数量

> 难度：简单 | 标签：条件过滤、去重计数 | [LeetCode 原题](https://leetcode.cn/problems/the-number-of-users-that-are-eligible-for-discount/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

购买表 `Purchases`：

```
+-------------+----------+
| Column Name | Type     |
+-------------+----------+
| user_id     | int      |
| time_stamp  | datetime |
| amount      | int      |
+-------------+----------+
(user_id, time_stamp) 是该表的主键。
每一行表示 user_id 这名用户在 time_stamp 这个时间的一笔消费，金额为 amount。
```

如果用户在时间区间 `[startDate, endDate]` 内**有一笔**消费的金额**至少**为 `minAmount`，则该用户有资格享受折扣。把日期转成时间时，两端都视为当天的开始（例如 `endDate = 2022-03-20` 视为 `2022-03-20 00:00:00`）。

原题要求实现函数 `getUserIDs(startDate, endDate, minAmount)`，返回符合折扣条件的用户**数量**（结果列名 `user_cnt`）。下面按普通查询写出核心逻辑，把示例参数代入即可。

**示例 1：**

```
输入：
Purchases 表：
+---------+---------------------+--------+
| user_id | time_stamp          | amount |
+---------+---------------------+--------+
| 1       | 2022-04-20 09:03:00 | 4416   |
| 2       | 2022-03-19 19:24:02 | 678    |
| 3       | 2022-03-18 12:03:09 | 4523   |
| 3       | 2022-03-30 09:43:42 | 626    |
+---------+---------------------+--------+

startDate = 2022-03-08, endDate = 2022-03-20, minAmount = 1000

输出：
+----------+
| user_cnt |
+----------+
| 1        |
+----------+

解释：
用户 1 金额达标但不在时间区间内；
用户 2 在区间内但金额 678 < 1000；
用户 3 有一笔 4523 的消费既在区间内又金额达标，因此唯一符合条件。
```

## 题解

::: details 点击查看题解

### 思路

条件是「单笔订单金额 >= minAmount」，不是区间内累计金额达标，所以金额过滤直接写在行级 WHERE，不要先按用户 SUM(amount) 再比较，否则多笔小额会被误判为合格。

时间区间是闭区间 [startDate, endDate]，且 endDate 被视为当天 00:00:00，用 BETWEEN 直接和 datetime 列比较即可。

同一用户可能有多笔达标订单，要 COUNT(DISTINCT user_id)。原题要求提交一个函数 getUserIDs(startDate, endDate, minAmount)，把参数替换成示例值就是这条查询。

### SQL 实现

```sql
SELECT COUNT(DISTINCT user_id) AS user_cnt
FROM Purchases
WHERE time_stamp BETWEEN '2022-03-08' AND '2022-03-20'
  AND amount >= 1000;
```

### 复杂度分析

- 时间复杂度：O(n)，一次全表扫描，n 为购买记录数
- 空间复杂度：O(1)，只返回一个计数

:::
