# 寻找面试候选人

> 难度：中等 | 标签：窗口函数、UNION、分组聚合 | [LeetCode 原题](https://leetcode.cn/problems/find-interview-candidates/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

表：`Contests`

```
+-------------+------+
| Column Name | Type |
+-------------+------+
| contest_id  | int  |
| gold_medal  | int  |
| silver_medal| int  |
| bronze_medal| int  |
+-------------+------+
contest_id 是此表中具有唯一值的列。
每一行表示一场周赛，三列分别是金、银、铜牌获得者的 `user_id`。
三列都是 `Users` 表中的 `user_id`。
```

表：`Users`

```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| user_id     | int     |
| mail        | varchar |
| name        | varchar |
+-------------+---------+
user_id 是此表中具有唯一值的列。
每一行包含一名用户的 id、邮箱和姓名。
```

如果一名用户满足下面任意一个条件，他就是面试候选人：

1. 连续三场比赛都获得**金牌**；
2. 连续三场比赛中都至少获得一枚**奖牌**（金、银、铜皆可）。

编写一个解决方案，报告所有面试候选人的 `name` 和 `mail`。

返回结果表**无顺序要求**。

**示例 1：**

输入：

```
Contests table:
+------------+------------+--------------+--------------+
| contest_id | gold_medal | silver_medal | bronze_medal |
+------------+------------+--------------+--------------+
| 190        | 1          | 5            | 2            |
| 191        | 2          | 3            | 5            |
| 192        | 5          | 2            | 3            |
| 193        | 1          | 3            | 5            |
| 194        | 4          | 5            | 2            |
| 195        | 4          | 2            | 1            |
| 196        | 1          | 5            | 2            |
+------------+------------+--------------+--------------+

Users table:
+---------+-------------------+-------+
| user_id | mail              | name  |
+---------+-------------------+-------+
| 1       | sarah@leetcode.com| Sarah |
| 2       | bob@leetcode.com  | Bob   |
| 3       | alice@leetcode.com| Alice |
| 4       | hercy@leetcode.com| Hercy |
| 5       | quarz@leetcode.com| Quarz |
+---------+-------------------+-------+
```

输出：

```

+-------+--------------------+
| name  | mail               |
+-------+--------------------+
| Alice | alice@leetcode.com |
| Bob   | bob@leetcode.com   |
| Quarz | quarz@leetcode.com |
+-------+--------------------+

```

解释：

- Bob（2）在 190、191、192 连续三场都拿到奖牌。
- Quarz（5）在 190、191、192 连续三场都拿到奖牌（其中 192 是金牌）。
- Alice（3）在 191、192、193 连续三场都拿到奖牌。
- Sarah（1）的金牌出现在 190、193、196，不连续；Hercy（4）只在 194、195 两场获奖，都不满足条件。

## 题解

::: details 点击查看题解

### 思路

第一步是把「一行三块奖牌」竖起来：三列分别 `SELECT contest_id, 名次列 AS user_id`，用 `UNION` 拼成长表。这里用 `UNION`（去重）而不是 `UNION ALL`，因为理论上同一个人同一场可以拿两块奖牌（数据里没有），先去重能让后续「同一场是否出现」的判断更干净。

第二步是判断「连续三场」。经典做法是 gaps-and-islands：按 `user_id` 分组、`contest_id` 排序后取 `ROW_NUMBER()`，用 `contest_id - ROW_NUMBER()` 得到一个「岛号」，连续编号的赛事会算出同一个岛号；再按 `(user_id, 岛号)` 分组，`COUNT(*) >= 3` 即说明至少连续三场。这个写法不要求赛事 id 恰好从某个值开始。

为什么不直接用 `m1.contest_id + 1 = m2.contest_id` 自连接？那样要求赛事编号严格连续无断号，一旦某周停赛（编号跳号）就会漏判；差值法把「编号递增」和「编号连续」区分开来，更健壮。

还有一个可以省一大段代码的观察：条件 1（连续三场金牌）其实被条件 2（连续三场有奖牌）包含——拿金牌的人当然也拿了奖牌，所以只要判断长表里某人有连续三场记录即可，不必单独再查金牌。最后用 `IN` 或 `EXISTS` 回连 `Users` 取姓名邮箱，不要用连接后直接输出：同一个人可能有多段满足条件的连续区间，内连接会产生重复行。

### SQL 实现

```sql
WITH medals AS (
    SELECT contest_id, gold_medal   AS user_id FROM Contests
    UNION
    SELECT contest_id, silver_medal AS user_id FROM Contests
    UNION
    SELECT contest_id, bronze_medal AS user_id FROM Contests
),
runs AS (
    SELECT user_id,
           contest_id - ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY contest_id) AS grp
    FROM medals
)
SELECT u.name, u.mail
FROM Users u
JOIN (
    SELECT user_id
    FROM runs
    GROUP BY user_id, grp
    HAVING COUNT(*) >= 3
) r ON r.user_id = u.user_id
ORDER BY u.name;
```

### 复杂度分析

- 时间复杂度：O(n log n)，n 为赛事数，主要开销在窗口函数排序（展开后为 3n 条记录）。
- 空间复杂度：O(n)，需要物化长表与岛号。
