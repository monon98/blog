# 最大数量高于平均水平的订单

> 难度：中等 | 标签：嵌套聚合、子查询、HAVING | [LeetCode 原题](https://leetcode.cn/problems/orders-with-maximum-quantity-above-average/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

表：`OrdersDetails`

```
+-------------+------+
| Column Name | Type |
+-------------+------+
| order_id    | int  |
| product_id  | int  |
| quantity    | int  |
+-------------+------+
(order_id, product_id) 是此表中具有唯一值的列的组合。
每一行表示某个订单中某个产品的购买数量。
同一个订单可以包含多个产品，对应多行记录。
```

一个订单的「最大数量」定义为该订单中所有产品数量的最大值。

编写一个解决方案，找出「订单内最大数量」**严格大于**「所有订单最大数量平均值」的订单 id。

返回结果表**无顺序要求**。

**示例 1：**

输入：

```
OrdersDetails table:
+----------+------------+----------+
| order_id | product_id | quantity |
+----------+------------+----------+
| 1        | 1          | 12       |
| 1        | 2          | 10       |
| 1        | 3          | 15       |
| 2        | 1          | 8        |
| 2        | 4          | 4        |
| 2        | 5          | 6        |
| 3        | 3          | 5        |
| 3        | 4          | 18       |
| 3        | 9          | 20       |
| 4        | 5          | 2        |
| 4        | 6          | 8        |
| 5        | 7          | 9        |
| 5        | 8          | 9        |
| 2        | 9          | 4        |
+----------+------------+----------+
```

输出：

```
+----------+
| order_id |
+----------+
| 1        |
| 3        |
+----------+
```

解释：

- 各订单的最大数量：订单 1 为 15，订单 2 为 8，订单 3 为 20，订单 4 为 8，订单 5 为 9。
- 平均值 = (15 + 8 + 20 + 8 + 9) / 5 = 12。
- 最大数量严格大于 12 的只有订单 1（15）和订单 3（20）；订单 5 的 9 不大于 12，不入选。

## 题解

::: details 点击查看题解

### 思路

这是典型的两级聚合：第一层求「每个订单的最大数量」，第二层对这批最大数量求平均值，最后再把每个订单的最大值与平均值比较。SQL 不允许聚合函数嵌套（`AVG(MAX(quantity))` 非法），所以内层必须落到一个派生表或 CTE 里，外层再引用它的结果。

容易写错的版本是 `HAVING MAX(quantity) > (SELECT AVG(quantity) FROM OrdersDetails)`：那个子查询算的是**全部明细行**的平均数量（本例 130/14 ≈ 9.29），而不是「订单数」为分母的平均值。题目的比较基准是订单级最大值再平均，本题数据下两者恰好都只筛出 1、3，但换成别的数据就会出错。

另一个细节是「严格大于」。示例里订单 5 的最大值 9 与平均 12 差得远，如果数据出现恰好相等的情况，用 `>` 而不是 `>=`。

替代写法：用窗口函数一次算出两个值，`SELECT DISTINCT order_id FROM (SELECT order_id, MAX(quantity) OVER (PARTITION BY order_id) AS mx, AVG(MAX(quantity)) OVER () AS avg_mx FROM OrdersDetails) t WHERE mx > avg_mx`。但 `AVG(MAX(...)) OVER ()` 仍是聚合套窗口，实际执行时 MySQL 会要求再套一层，派生表方案更直白。

### SQL 实现

```sql
SELECT order_id
FROM OrdersDetails
GROUP BY order_id
HAVING MAX(quantity) > (
    SELECT AVG(order_max)
    FROM (SELECT MAX(quantity) AS order_max FROM OrdersDetails GROUP BY order_id) AS t
);
```

### 复杂度分析

- 时间复杂度：O(n log n)，n 为明细行数，两次分组聚合（内层按订单、外层单值）。
- 空间复杂度：O(k)，k 为订单数，内层派生表每单一行。
