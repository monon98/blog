# 即时食物配送 II

> 难度：中等 | 标签：子查询、分组聚合、条件计数 | [LeetCode 原题](https://leetcode.cn/problems/immediate-food-delivery-ii/)

## 题目描述

配送表: `Delivery`

```
+-----------------------------+---------+
| Column Name                 | Type    |
+-----------------------------+---------+
| delivery_id                 | int     |
| customer_id                 | int     |
| order_date                  | date    |
| customer_pref_delivery_date | date    |
+-----------------------------+---------+
delivery_id 是该表中具有唯一值的列。
该表保存着顾客的食物配送信息，顾客在某个日期下了订单，并指定了一个期望的配送日期（和下单日期相同或者在那之后）。
```

如果顾客期望的配送日期和下单日期相同，则该订单称为 「**即时订单**」，否则称为「**计划订单**」。

「**首次订单**」是顾客最早创建的订单。我们保证一个顾客只会有一个「首次订单」。

编写解决方案以获取即时订单在所有用户的首次订单中的比例。**保留两位小数。**

结果示例如下所示：

**示例 1：**

```
输入：
Delivery 表：
+-------------+-------------+------------+-----------------------------+
| delivery_id | customer_id | order_date | customer_pref_delivery_date |
+-------------+-------------+------------+-----------------------------+
| 1           | 1           | 2019-08-01 | 2019-08-02                  |
| 2           | 2           | 2019-08-02 | 2019-08-02                  |
| 3           | 1           | 2019-08-11 | 2019-08-12                  |
| 4           | 3           | 2019-08-24 | 2019-08-24                  |
| 5           | 3           | 2019-08-21 | 2019-08-22                  |
| 6           | 2           | 2019-08-11 | 2019-08-13                  |
| 7           | 4           | 2019-08-09 | 2019-08-09                  |
+-------------+-------------+------------+-----------------------------+
输出：
+----------------------+
| immediate_percentage |
+----------------------+
| 50.00                |
+----------------------+
解释：
1 号顾客的 1 号订单是首次订单，并且是计划订单。
2 号顾客的 2 号订单是首次订单，并且是即时订单。
3 号顾客的 5 号订单是首次订单，并且是计划订单。
4 号顾客的 7 号订单是首次订单，并且是即时订单。
因此，一半顾客的首次订单是即时的。
```

## 题解

::: details 点击查看题解

### 思路

比第 25 题（即时食物配送 I）多了一步筛选：分母不再是全部订单，而是「每个顾客的首次订单」。所以先把每位顾客的首次下单日期取出来：`GROUP BY customer_id` 后取 `MIN(order_date)`，得到一张「顾客 → 首次下单日期」的小表；再把它和原表按 `customer_id` 与 `order_date` 双键连接，剩下的行恰好就是每个顾客的首次订单。

双键连接是本题的关键。只按 `customer_id` 连接会把该顾客的所有订单都匹配上，比例就退化成「全部订单里的即时比例」。题目保证每位顾客只有一笔首次订单，所以连接后行数正好等于顾客数，可以直接用 `COUNT(*)` 作分母。

分子沿用条件计数写法 `SUM(order_date = customer_pref_delivery_date)`。另一种常见写法是窗口函数：`RANK() OVER (PARTITION BY customer_id ORDER BY order_date)` 取排名第一的行，再算比例，语义相同但多一层子查询。

### SQL 实现

```sql
SELECT ROUND(
           SUM(d.order_date = d.customer_pref_delivery_date) / COUNT(*) * 100,
           2
       ) AS immediate_percentage
FROM Delivery d
JOIN (
    SELECT customer_id, MIN(order_date) AS first_order_date
    FROM Delivery
    GROUP BY customer_id
) f
    ON d.customer_id = f.customer_id
   AND d.order_date = f.first_order_date;
```

窗口函数写法：

```sql
SELECT ROUND(
           SUM(order_date = customer_pref_delivery_date) / COUNT(*) * 100,
           2
       ) AS immediate_percentage
FROM (
    SELECT *,
           RANK() OVER (PARTITION BY customer_id ORDER BY order_date) AS rk
    FROM Delivery
) t
WHERE rk = 1;
```

### 复杂度分析

- 时间复杂度：O(n log n)，n 为 `Delivery` 行数，分组取最小值与连接均可借助排序/哈希，最坏受排序影响。
- 空间复杂度：O(c)，c 为顾客数，用于保存首次订单子表。
