# 消费者下单频率

> 难度：简单 | 标签：条件聚合、多表连接 | [LeetCode 原题](https://leetcode.cn/problems/customer-order-frequency/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

表：`Customers`

```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| customer_id | int     |
| name        | varchar |
| country     | varchar |
+-------------+---------+
customer_id 是此表中具有唯一值的列。
每一行包含客户 id、姓名和所在国家。
```

表：`Product`

```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| product_id  | int     |
| description | varchar |
| price       | int     |
+-------------+---------+
product_id 是此表中具有唯一值的列。
每一行包含产品 id、描述和单价。
```

表：`Orders`

```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| order_id    | int     |
| customer_id | int     |
| product_id  | int     |
| order_date  | date    |
| quantity    | int     |
+-------------+---------+
order_id 是此表中具有唯一值的列。
每一行包含一次下单的客户、产品、日期和数量。
```

编写一个解决方案，报告在 **2020 年 6 月和 7 月每个月**消费金额都不少于 100 的客户的 `customer_id` 和 `name`。某个客户在某个月的消费金额等于该月所有订单的 `price * quantity` 之和。

返回结果表**无顺序要求**。

**示例 1：**

输入：

```
Customers table:
+-------------+----------+---------+
| customer_id | name     | country |
+-------------+----------+---------+
| 1           | Winston  | USA     |
| 2           | Jonathan | Peru    |
| 3           | Moustafa | Egypt   |
+-------------+----------+---------+

Product table:
+------------+-------------+-------+
| product_id | description | price |
+------------+-------------+-------+
| 10         | LC Phone    | 300   |
| 20         | LC T-Shirt  | 10    |
| 30         | LC Book     | 45    |
| 40         | LC Keychain | 2     |
+------------+-------------+-------+

Orders table:
+----------+-------------+------------+------------+----------+
| order_id | customer_id | product_id | order_date | quantity |
+----------+-------------+------------+------------+----------+
| 1        | 1           | 10         | 2020-06-10 | 1        |
| 2        | 1           | 20         | 2020-07-01 | 1        |
| 3        | 1           | 30         | 2020-07-08 | 2        |
| 4        | 2           | 10         | 2020-06-15 | 2        |
| 5        | 2           | 40         | 2020-07-01 | 10       |
| 6        | 3           | 20         | 2020-06-24 | 2        |
| 7        | 3           | 30         | 2020-06-25 | 2        |
| 9        | 3           | 30         | 2020-05-08 | 3        |
+----------+-------------+------------+------------+----------+
```

输出：

```
+-------------+---------+
| customer_id | name    |
+-------------+---------+
| 1           | Winston |
+-------------+---------+
```

解释：

- 客户 1 六月消费 300，七月消费 10 + 90 = 100，两个月都不少于 100，入选。
- 客户 2 六月消费 600，但七月只消费 2 * 10 = 20，不入选。
- 客户 3 六月消费 20 + 90 = 110，七月没有任何订单（五月的 135 不算），不入选。

## 题解

::: details 点击查看题解

### 思路

金额要靠 `Product.price * Orders.quantity` 算出来，所以必须把 `Orders` 和 `Product` 连起来；客户名字在 `Customers` 里，再连一张表。聚合的粒度是「客户 × 月份」，但题目只关心 6 月和 7 月两个固定的桶，用两条 `SUM(IF(...))` 做条件聚合比先 `GROUP BY 客户, 月份` 再透视更简单。

条件聚合的含义：`SUM(IF(月份条件成立, 金额, 0))` 会把不符合条件的行按 0 累加，于是每个客户只出一行，两个 SUM 分别就是六月和七月的消费额。随后 `HAVING` 里要求两个值都 `>= 100`，注意是「每个月都达标」而不是「两个月合计达标」，用 `AND` 连接。

判断月份别用 `MONTH(order_date)`：虽然本题只有 2020 年的数据，但按题意加年份更稳妥，用左闭右开区间「2020-06-01, 2020-07-01)」和「2020-07-01, 2020-08-01)」，既能走日期索引，也不会漏掉月末的时分秒。

如果更习惯先分组再筛，也可以写成 `GROUP BY customer_id, DATE_FORMAT(order_date, "%Y-%m")` 加 `HAVING COUNT(DISTINCT 月份) = 2` 的写法，但那还要再过滤单月金额，反而绕；条件聚合是这类「按月分段汇总」题的标准套路。

### SQL 实现

```sql
SELECT o.customer_id, c.name
FROM Orders o
JOIN Product p ON p.product_id = o.product_id
JOIN Customers c ON c.customer_id = o.customer_id
GROUP BY o.customer_id, c.name
HAVING SUM(IF(o.order_date >= '2020-06-01' AND o.order_date < '2020-07-01',
              p.price * o.quantity, 0)) >= 100
   AND SUM(IF(o.order_date >= '2020-07-01' AND o.order_date < '2020-08-01',
              p.price * o.quantity, 0)) >= 100;
```

### 复杂度分析

- 时间复杂度：O(n)，n 为订单数，三张表各扫一遍后分组聚合。
- 空间复杂度：O(m)，m 为客户数，分组结果最多每个客户一行。

:::
