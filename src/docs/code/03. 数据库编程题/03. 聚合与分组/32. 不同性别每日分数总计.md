# 不同性别每日分数总计

> 难度：中等 | 标签：窗口函数、累计求和 | [LeetCode 原题](https://leetcode.cn/problems/running-total-for-different-genders/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

`Scores` 表：

```
+--------------+---------+
| Column Name  | Type    |
+--------------+---------+
| player_name  | varchar |
| gender       | varchar |
| day          | date    |
| score_points | int     |
+--------------+---------+
(gender, day) 是该表的主键，gender 取值为 'F' 或 'M'。
每一行记录某个玩家在某一天获得的分数。
```

编写一个 SQL 查询，按性别计算 **按天累计的分数总和**（running total）：对每个性别，把该性别截至当天（含当天）的所有 `score_points` 累加，返回列 `gender`、`day`、`total`，结果按 `gender`、`day` 升序排列。

**示例 1：**

```
输入：
Scores table:
+-------------+--------+------------+--------------+
| player_name | gender | day        | score_points |
+-------------+--------+------------+--------------+
| Aron        | F      | 2020-01-01 | 17           |
| Alice       | F      | 2020-01-07 | 23           |
| Bajrang     | M      | 2020-01-07 | 7            |
| Khali       | M      | 2019-12-25 | 11           |
| Slaman      | M      | 2019-12-30 | 13           |
| Joe         | M      | 2019-12-31 | 3            |
| Jose        | M      | 2019-12-18 | 2            |
| Priya       | F      | 2019-12-31 | 23           |
| Priyanka    | F      | 2019-12-30 | 17           |
+-------------+--------+------------+--------------+
输出：
+--------+------------+-------+
| gender | day        | total |
+--------+------------+-------+
| F      | 2019-12-30 | 17    |
| F      | 2019-12-31 | 40    |
| F      | 2020-01-01 | 57    |
| F      | 2020-01-07 | 80    |
| M      | 2019-12-18 | 2     |
| M      | 2019-12-25 | 13    |
| M      | 2019-12-30 | 26    |
| M      | 2019-12-31 | 29    |
| M      | 2020-01-07 | 36    |
+--------+------------+-------+
解释：
以 F 为例：12-30 得 17 分，累计 17；12-31 得 23 分，累计 40；
2020-01-01 得 17 分，累计 57；2020-01-07 得 23 分，累计 80。
M 组同理，按日期依次累加 2、11、13、3、7。
```

## 题解

::: details 点击查看题解

### 思路

「按性别分组、按日期累加」正好对应窗口函数的 `PARTITION BY gender ORDER BY day`：分区保证每遇到一个新性别就重新开始累加，排序保证累计范围是从该性别最早一天到当前行。窗口聚合默认的帧就是 `RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW`，即「截至当前行」，所以直接写 `SUM(score_points) OVER (PARTITION BY gender ORDER BY day)` 即可，不必显式写帧。

由于 `(gender, day)` 是主键，同一天同一性别只有一行，`RANGE` 与 `ROWS` 两种帧的结果相同；如果换成一天多行的表，需要明确用 `ROWS` 还是 `RANGE`，因为 `RANGE` 会把同一天的所有行一起纳入累计（同日多行的 total 会相同），这是窗口函数常见的理解偏差。

MySQL 8 之前没有窗口函数，只能用自连接：对每一行再连一次 `Scores`，条件为「同性别且日期不晚于当前行」再 `SUM`，复杂度 O(n²)，可以提一句但不必作为主解。排序按 `gender, day`，与窗口的排序键一致，也让结果更稳定。

### SQL 实现

```sql
SELECT gender,
       day,
       SUM(score_points) OVER (
           PARTITION BY gender
           ORDER BY day
       ) AS total
FROM Scores
ORDER BY gender, day;
```

### 复杂度分析

- 时间复杂度：O(n log n)，n 为 `Scores` 行数，窗口内部需要按「性别 + 日期」排序。
- 空间复杂度：O(n)，窗口排序与结果集占用与行数同阶。

:::
