# 查询活跃业务

> 难度：中等 | 标签：子查询、分组聚合 | [LeetCode 原题](https://leetcode.cn/problems/active-businesses/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

`Events` 表：

```
+---------------+---------+
| Column Name   | Type    |
+---------------+---------+
| business_id   | int     |
| event_type    | varchar |
| occurrences   | int     |
+---------------+---------+
(business_id, event_type) 是该表的主键。
每一行记录了某个业务（business）的某种事件（event_type）发生了多少次（occurrences）。
```

编写一个 SQL 查询，找出所有 **活跃业务**。

活跃业务的定义：存在 **多于一种** 事件类型，使得该业务在这种事件上的 `occurrences` **大于** 所有业务在该种事件上 `occurrences` 的平均值。

以任意顺序返回结果表，结果只包含 `business_id` 一列。

**示例 1:**

```
输入:
Events 表:
+-------------+------------+-------------+
| business_id | event_type | occurrences |
+-------------+------------+-------------+
| 1           | reviews    | 7           |
| 3           | reviews    | 3           |
| 1           | ads        | 11          |
| 2           | ads        | 7           |
| 3           | ads        | 6           |
| 1           | page views | 3           |
| 2           | page views | 12          |
+-------------+------------+-------------+
输出:
+-------------+
| business_id |
+-------------+
| 1           |
+-------------+
解释:
reviews、ads、page views 的平均值分别为 (7+3)/2 = 5、(11+7+6)/3 = 8、(3+12)/2 = 7.5。
业务 1 的 reviews 事件 7 次（大于 5），ads 事件 11 次（大于 8），
两种事件都超过各自平均值，所以业务 1 是活跃业务。
业务 2 只有 page views（12 > 7.5）一种超过平均值，不满足「多于一种」。
业务 3 没有任何事件超过平均值。
```

## 题解

::: details 点击查看题解

### 思路

两层聚合是本题的核心：内层先按 `event_type` 分组，算出 **每种事件在所有业务上的平均出现次数**；外层把这份平均值连接回明细行，筛出「该业务该事件的 occurrences 大于该事件平均值」的行，最后再按 `business_id` 分组，用 `HAVING COUNT(*) > 1` 保证超过平均值的事件 **种类** 多于一种。

易错点有三个。其一，平均值的分组键是 `event_type` 而不是全表——必须「同类事件比同类平均」，把所有事件混在一起算一个总平均就完全错了。其二，判定条件是严格大于 `>`，等于平均值不算超过。其三，最后统计的是「超过平均值的事件种类数」而不是 occurrences 总和，所以是 `COUNT(*) > 1`（每行代表一种事件的一次达标），不能写成 `SUM(occurrences) > 1`。

平均值子查询与明细的连接放在 `JOIN` 的 `ON` 条件里最自然；替代写法是用窗口函数 `AVG(occurrences) OVER (PARTITION BY event_type)` 直接在明细行上算平均，省掉一次连接，可读性相当。

### SQL 实现

```sql
SELECT e.business_id
FROM Events e
JOIN (
    SELECT event_type, AVG(occurrences) AS avg_occ
    FROM Events
    GROUP BY event_type
) a
    ON e.event_type = a.event_type
WHERE e.occurrences > a.avg_occ
GROUP BY e.business_id
HAVING COUNT(*) > 1;
```

窗口函数写法：

```sql
SELECT business_id
FROM (
    SELECT business_id,
           occurrences,
           AVG(occurrences) OVER (PARTITION BY event_type) AS avg_occ
    FROM Events
) t
WHERE occurrences > avg_occ
GROUP BY business_id
HAVING COUNT(*) > 1;
```

### 复杂度分析

- 时间复杂度：O(n log n)，n 为事件记录数，分组求均值与连接接近线性，排序主导。
- 空间复杂度：O(k)，k 为「业务 × 事件类型」组合数与分组哈希表开销。
