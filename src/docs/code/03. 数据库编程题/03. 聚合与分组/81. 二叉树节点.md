# 二叉树节点

> 难度：中等 | 标签：CASE WHEN、子查询 | [LeetCode 原题](https://leetcode.cn/problems/binary-tree-nodes/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

`Tree` 表：

```
+-------------+------+
| Column Name | Type |
+-------------+------+
| N           | int  |
| P           | int  |
+-------------+------+
N 是该表中具有不同值的列。
每一行包含节点 N 及其父节点 P，P 为 NULL 表示 N 是树的根。
```

节点类型定义：

- `Root`：没有父节点的节点（`P IS NULL`）。
- `Leaf`：没有任何子节点的节点（不是其他任何节点的父节点）。
- `Inner`：既不是根节点，也不是叶子节点。

编写一个解决方案，为每个节点输出其类型 `Type`，并按节点值 `N` **升序** 返回结果表。

**示例 1：**

输入：

```
Tree 表：
+---+------+
| N | P    |
+---+------+
| 1 | 2    |
| 3 | 2    |
| 6 | 8    |
| 9 | 8    |
| 2 | 5    |
| 8 | 5    |
| 5 | NULL |
+---+------+
```

输出：

```
+---+-------+
| N | Type  |
+---+-------+
| 1 | Leaf  |
| 2 | Inner |
| 3 | Leaf  |
| 5 | Root  |
| 6 | Leaf  |
| 8 | Inner |
| 9 | Leaf  |
+---+-------+
```

解释：

- 节点 5 没有父节点，是根节点。
- 节点 1、3、6、9 没有任何子节点，是叶子节点。
- 节点 2、8 既是别人的父节点、自己又有父节点，是内部节点。

## 题解

::: details 点击查看题解

### 思路

角色判断依赖两个信息：这一行自己的 `P`（有没有父），以及「是否有人把 `N` 当作 `P`」（有没有子）。前者在同一行就能读到，后者必须再查一次表，所以天然需要一个自连接或子查询。

最省事的写法是用 `CASE WHEN` 按优先级短路：`P IS NULL` 直接判根；否则用 `EXISTS` 检查是否存在 `c.P = t.N` 的子节点，有就是 `Inner`，没有就是 `Leaf`。

这里有个经典坑：如果用 `N NOT IN (SELECT P FROM Tree)` 判叶子，而 `P` 列里含有 `NULL`（根节点那一行），`NOT IN` 与 `NULL` 比较会得到 `UNKNOWN`，整条判断恒不成立，根节点之外的节点也会被判错。要么写成 `NOT IN (SELECT P FROM Tree WHERE P IS NOT NULL)`，要么干脆用 `EXISTS`，语义更直白。

替代写法是自左连接 `LEFT JOIN Tree c ON c.P = t.N`，再配合 `DISTINCT` 去重：一个节点最多有两个子节点，连接后每个节点会膨胀成多行，忘了 `DISTINCT` 就会输出重复节点。

### SQL 实现

```sql
SELECT
    t.N,
    CASE
        WHEN t.P IS NULL THEN 'Root'
        WHEN EXISTS (SELECT 1 FROM Tree c WHERE c.P = t.N) THEN 'Inner'
        ELSE 'Leaf'
    END AS Type
FROM Tree t
ORDER BY t.N;
```

### 复杂度分析

- 时间复杂度：O(n) 到 O(n^2)，n 为节点数；相关子查询在无索引时最坏要对每个节点扫一遍全表。
- 空间复杂度：O(1)，只用了常量级的额外空间（不计结果集）。
