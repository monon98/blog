# 即时食物配送 I

> 难度：简单 | 标签：条件聚合、数值计算 | [LeetCode 原题](https://leetcode.cn/problems/immediate-food-delivery-i/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

`Delivery` 表：

```
+-----------------------------+---------+
| Column Name                 | Type    |
+-----------------------------+---------+
| delivery_id                 | int     |
| customer_id                 | int     |
| order_date                  | date    |
| customer_pref_delivery_date | date    |
+-----------------------------+---------+
delivery_id 是该表中具有唯一值的列。
该表保存顾客的食物配送信息：顾客在某天下单（order_date），并指定了一个期望的配送日期（customer_pref_delivery_date）。
```

如果顾客期望的配送日期和下单日期 **相同**，则该订单称为「**即时订单**」，否则称为「**计划订单**」。

编写一个 SQL 查询，求出即时订单占全部订单的 **百分比**，结果四舍五入保留两位小数，列名为 `immediate_percentage`。

**示例 1：**

```
输入：
Delivery table:
+-------------+-------------+------------+-----------------------------+
| delivery_id | customer_id | order_date | customer_pref_delivery_date |
+-------------+-------------+------------+-----------------------------+
| 1           | 1           | 2019-08-01 | 2019-08-02                  |
| 2           | 5           | 2019-08-02 | 2019-08-02                  |
| 3           | 1           | 2019-08-11 | 2019-08-11                  |
| 4           | 3           | 2019-08-24 | 2019-08-26                  |
| 5           | 4           | 2019-08-21 | 2019-08-22                  |
| 6           | 2           | 2019-08-11 | 2019-08-13                  |
+-------------+-------------+------------+-----------------------------+
输出：
+----------------------+
| immediate_percentage |
+----------------------+
| 33.33                |
+----------------------+
解释：
2 号订单和 3 号订单的期望配送日期与下单日期相同，是即时订单。
其余 4 单为计划订单，因此即时订单占比 = 2 / 6 * 100 = 33.33。
```

## 题解

::: details 点击查看题解

### 思路

全表只有一张表，不需要分组，直接对整表做一次「条件计数 + 比例计算」。判断即时订单的条件就是 `order_date = customer_pref_delivery_date`，在 MySQL 里比较表达式返回 0/1，所以 `SUM(order_date = customer_pref_delivery_date)` 恰好等于即时订单的条数，除以 `COUNT(*)` 再乘 100 就是百分比。

容易踩的坑是把分子写成 `COUNT(CASE WHEN ... THEN 1 END)` 却忘了 `COUNT(*)` 与 `AVG` 的语义差别：其实直接 `AVG(order_date = customer_pref_delivery_date) * 100` 更简洁，效果等同。另外分子分母都是整数，在 MySQL 中 `/` 本身就是小数除法，不必 `CAST`；但若换到会做整除的方言（如某些数据库的整数相除），需要显式转成实数。

`ROUND(..., 2)` 放在最外层即可保证输出两位小数；本题保证至少有一条订单，不必处理除零。

### SQL 实现

```sql
SELECT ROUND(
           SUM(order_date = customer_pref_delivery_date) / COUNT(*) * 100,
           2
       ) AS immediate_percentage
FROM Delivery;
```

等价的 `AVG` 写法：

```sql
SELECT ROUND(AVG(order_date = customer_pref_delivery_date) * 100, 2) AS immediate_percentage
FROM Delivery;
```

### 复杂度分析

- 时间复杂度：O(n)，n 为 `Delivery` 行数，一次全表扫描。
- 空间复杂度：O(1)，只维护常量个聚合中间值。

:::
