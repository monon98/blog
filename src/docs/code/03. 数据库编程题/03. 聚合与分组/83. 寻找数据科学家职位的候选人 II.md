# 寻找数据科学家职位的候选人 II

> 难度：中等 | 标签：多表连接、窗口函数、分组聚合 | [LeetCode 原题](https://leetcode.cn/problems/find-candidates-for-data-scientist-position-ii/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

`Candidates` 表：

```
+--------------+---------+
| Column Name  | Type    |
+--------------+---------+
| candidate_id | int     |
| skill        | varchar |
| proficiency  | int     |
+--------------+---------+
(candidate_id, skill) 是该表的主键。
每一行包含候选人、技能以及熟练程度（1-5）。
```

`Projects` 表：

```
+--------------+---------+
| Column Name  | Type    |
+--------------+---------+
| project_id   | int     |
| skill        | varchar |
| importance   | int     |
+--------------+---------+
(project_id, skill) 是该表的主键。
每一行包含项目 ID、所需技能以及该技能的重要性（1-5）。
```

编写一个解决方案，为 **每一个项目** 找出 **最佳候选人**：

1. 候选人必须拥有项目要求的 **全部** 技能。
2. 对每个「候选人-项目」组合计算分数：从 `100` 分开始；某项技能熟练程度 **大于** 重要性则 **加** `10` 分，**小于** 则 **减** `5` 分，**等于** 则不变。
3. 每个项目只输出分数最高的候选人；分数相同时取 `candidate_id` **更小** 者。没有合适候选人的项目不输出。

返回结果表按 `project_id` 升序排序。

**示例 1：**

输入：

```
Candidates 表：
+--------------+------------+-------------+
| candidate_id | skill      | proficiency |
+--------------+------------+-------------+
| 101          | Python     | 5           |
| 101          | Tableau    | 3           |
| 101          | PostgreSQL | 4           |
| 101          | TensorFlow | 2           |
| 102          | Python     | 4           |
| 102          | Tableau    | 5           |
| 102          | PostgreSQL | 4           |
| 102          | R          | 4           |
| 103          | Python     | 3           |
| 103          | Tableau    | 5           |
| 103          | PostgreSQL | 5           |
| 103          | Spark      | 4           |
+--------------+------------+-------------+

Projects 表：
+------------+------------+------------+
| project_id | skill      | importance |
+------------+------------+------------+
| 501        | Python     | 4          |
| 501        | Tableau    | 3          |
| 501        | PostgreSQL | 5          |
| 502        | Python     | 3          |
| 502        | Tableau    | 4          |
| 502        | R          | 2          |
+------------+------------+------------+
```

输出：

```
+------------+--------------+-------+
| project_id | candidate_id | score |
+------------+--------------+-------+
| 501        | 101          | 105   |
| 502        | 102          | 130   |
+------------+--------------+-------+
```

解释：

- 项目 501 需要 Python、Tableau、PostgreSQL。101、102、103 都具备这三项，分数都是 105，按规则取 `candidate_id` 最小的 101。
- 项目 502 需要 Python、Tableau、R，只有 102 具备 R，其分数为 100 + 10 + 10 + 10 = 130。

## 题解

::: details 点击查看题解

### 思路

两表通过 `skill` 等值连接后，每个「候选人 × 项目」会摊成多行（每项技能一行），于是可以把分数 `100 + SUM(CASE ...)` 和已匹配技能数 `COUNT(*)` 一起在 `GROUP BY candidate_id, project_id` 里算出来。

关键在「必须覆盖全部技能」这一条。只在连接结果里出现，并不代表技能齐全 —— 例如 103 在项目 502 上只匹配到 Python 和 Tableau，照样能算出一个分数。所以必须再拿一次每个项目所需的技能总数（`Projects` 按 `project_id` 分组计数），与匹配数对齐，只保留 `matched_skills = required_skills` 的组合。

取每个项目的最优者用窗口函数最自然：`RANK() OVER (PARTITION BY project_id ORDER BY score DESC, candidate_id ASC)`。把 `candidate_id` 放进排序键后，同分时小 ID 排在前，筛选 `rk = 1` 就唯一确定了。这里用 `RANK` 或 `ROW_NUMBER` 结果都一样（排序键已保证唯一），但 `RANK` 更能表达「排名第一」的语义。

易错点：排序键只写 `score DESC` 而忘了 `candidate_id`，同分时结果就不确定了；另外没有合适候选人的项目要靠 `matched_skills = required_skills` 的过滤自然剔除，不需要额外处理。

### SQL 实现

```sql
WITH matched AS (
    SELECT
        c.candidate_id,
        p.project_id,
        COUNT(*) AS matched_skills,
        100 + SUM(
            CASE
                WHEN c.proficiency > p.importance THEN 10
                WHEN c.proficiency < p.importance THEN -5
                ELSE 0
            END
        ) AS score
    FROM Candidates c
    JOIN Projects p ON p.skill = c.skill
    GROUP BY c.candidate_id, p.project_id
),
required AS (
    SELECT project_id, COUNT(*) AS required_skills
    FROM Projects
    GROUP BY project_id
),
ranked AS (
    SELECT
        m.project_id,
        m.candidate_id,
        m.score,
        RANK() OVER (
            PARTITION BY m.project_id
            ORDER BY m.score DESC, m.candidate_id ASC
        ) AS rk
    FROM matched m
    JOIN required r ON r.project_id = m.project_id
    WHERE m.matched_skills = r.required_skills
)
SELECT project_id, candidate_id, score
FROM ranked
WHERE rk = 1
ORDER BY project_id;
```

### 复杂度分析

- 时间复杂度：O(n + m + k log k)，n、m 分别为 Candidates 与 Projects 的行数，k 为候选-项目组合数；主要开销在连接、分组与窗口排序。
- 空间复杂度：O(k)，用于存放中间组合与排名结果。
