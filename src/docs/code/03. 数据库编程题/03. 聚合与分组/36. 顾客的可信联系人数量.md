# 顾客的可信联系人数量

> 难度：中等 | 标签：多表连接、条件聚合、子查询 | [LeetCode 原题](https://leetcode.cn/problems/number-of-trusted-contacts-of-a-customer/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

`Customers` 表：

```
+---------------+---------+
| Column Name   | Type    |
+---------------+---------+
| customer_id   | int     |
| customer_name | varchar |
| email         | varchar |
+---------------+---------+
customer_id 是该表的主键，email 是顾客的邮箱（唯一）。
```

`Contacts` 表：

```
+---------------+---------+
| Column Name   | Type    |
+---------------+---------+
| user_id       | int     |
| contact_name  | varchar |
| contact_email | varchar |
+---------------+---------+
该表记录每位顾客手机里的联系人：user_id 是顾客编号，contact_name / contact_email 是联系人姓名与邮箱。
```

`Invoices` 表：

```
+------------+---------+
| Column Name| Type    |
+------------+---------+
| invoice_id | int     |
| price      | int     |
| user_id    | int     |
+------------+---------+
该表记录顾客的账单，user_id 是开票的顾客编号。
```

如果某位联系人的邮箱 **也出现在 `Customers` 表中**，说明这位联系人本身也是本平台的顾客，称其为「可信联系人」；否则为「不可信联系人」。

编写一个 SQL 查询，对每位顾客输出：`customer_id`、`customer_name`、`number_of_invoices`（账单数）、`number_of_trusted_contacts`（可信联系人数）、`number_of_untrusted_contacts`（不可信联系人数）。结果按 `customer_id` 升序排列，没有账单或联系人的顾客对应数量记 0。

**示例 1：**

```
输入：

+-------------+---------------+-------------------+
| customer_id | customer_name | email             |
+-------------+---------------+-------------------+

| 2           | Bob           | bob@leetcode.com  |
| 13          | John          | john@leetcode.com |

+-------------+---------------+-------------------+

+---------+--------------+-------------------+
| user_id | contact_name | contact_email     |
+---------+--------------+-------------------+
| 1       | Bob          | bob@leetcode.com  |
| 1       | John         | john@leetcode.com |
| 1       | Jal          | jal@leetcode.com  |
| 2       | Omar         | omar@leetcode.com |
| 2       | Meir         | meir@leetcode.com |
| 6       | Alice        | alice@leetcode.com|
+---------+--------------+-------------------+

+------------+-------+---------+
| invoice_id | price | user_id |
+------------+-------+---------+

| 88         | 200   | 1       |

+------------+-------+---------+

+-------------+---------------+--------------------+-----------------------------+-------------------------------+
| customer_id | customer_name | number_of_invoices | number_of_trusted_contacts  | number_of_untrusted_contacts  |
+-------------+---------------+--------------------+-----------------------------+-------------------------------+
| 1           | Alice         | 2                  | 2                           | 1                             |

解释：
Alice：2 张账单；联系人是 Bob（平台顾客，可信）、John（可信）、Jal（不可信）。
Bob：2 张账单；联系人是 Omar、Meir，都不是平台顾客。
Alex：1 张账单；联系人是 Alice，是平台顾客。
John：1 张账单，没有联系人，两个联系人数都为 0。
```

## 题解

::: details 点击查看题解

### 思路

三个指标来自三张表，粒度都不同（账单是「一对多」、联系人是「一对多」），如果把它们直接写在同一个 `JOIN` 里再聚合，会因笛卡尔膨胀导致计数翻倍——比如 Alice 有 2 张账单、3 个联系人，直接三表连接会得到 6 行。正确做法是 **先把每张子表聚合成「顾客 → 指标」的形式，再与 `Customers` 左连接**，每个子查询内部只有一个分组维度，不会互相污染。

账单子查询就是 `GROUP BY user_id` 求 `COUNT(*)`。联系人的可信判定用邮箱与 `Customers.email` 做 `LEFT JOIN`：能匹配上说明该邮箱也是平台顾客，记为可信；匹配不上（`ce.customer_id IS NULL`）记为不可信。`COUNT(ce.customer_id)` 只统计非 NULL，恰好是可信数；`COUNT(*) - COUNT(ce.customer_id)` 就是不可信数，这样一个子查询同时产出两列。

外层必须用 `LEFT JOIN` 并配合 `IFNULL(..., 0)`：John 没有联系人、没有任何子查询行，左连接后为 NULL，若用内连接就会把这位顾客整行丢掉。这里用 `COUNT` 的语义已经能避免 NULL 求和问题，但聚合子查询「没有行」的情况仍需 `IFNULL` 兜底。最后按 `customer_id` 排序即可。

### SQL 实现

```sql
SELECT c.customer_id,
       c.customer_name,
       IFNULL(i.number_of_invoices, 0)     AS number_of_invoices,
       IFNULL(ct.number_of_trusted_contacts, 0)   AS number_of_trusted_contacts,
       IFNULL(ct.number_of_untrusted_contacts, 0) AS number_of_untrusted_contacts
FROM Customers c
LEFT JOIN (
    SELECT user_id,
           COUNT(*) AS number_of_invoices
    FROM Invoices
    GROUP BY user_id
) i ON i.user_id = c.customer_id
LEFT JOIN (
    SELECT co.user_id,
           COUNT(ce.customer_id) AS number_of_trusted_contacts,
           COUNT(*) - COUNT(ce.customer_id) AS number_of_untrusted_contacts
    FROM Contacts co
    LEFT JOIN Customers ce ON ce.email = co.contact_email
    GROUP BY co.user_id
) ct ON ct.user_id = c.customer_id
ORDER BY c.customer_id;
```

### 复杂度分析

- 时间复杂度：O(n + m + k)，n、m、k 分别为三张表的行数，两次分组聚合加两次连接。
- 空间复杂度：O(c)，c 为有账单或有联系人的顾客数，用于保存两个聚合子表。
