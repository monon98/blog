# 游戏玩法分析 III

> 难度：中等 | 标签：窗口函数、分组聚合 | [LeetCode 原题](https://leetcode.cn/problems/game-play-analysis-iii/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

`Activity` 表：

```
+--------------+---------+
| Column Name  | Type    |
+--------------+---------+
| player_id    | int     |
| device_id    | int     |
| event_date   | date    |
| games_played | int     |
+--------------+---------+
(player_id, event_date) 是这个表的主键（具有唯一值的列的组合）。
这张表展示了一些游戏玩家在游戏平台上的行为活动。
每行记录了一名玩家在某一天使用某台设备登录后、退出之前打开的游戏数目（可能是 0 个）。
```

编写解决方案，报告每位玩家在每个登录日期为止 **累计玩过的游戏总数**，即该玩家直到该日期（含当天）玩过的游戏总量。

返回结果按 `player_id`、`event_date` 升序排序（顺序任意亦可），结果格式如下所示。

**示例 1：**

```
输入：
Activity 表：
+-----------+-----------+------------+--------------+
| player_id | device_id | event_date | games_played |
+-----------+-----------+------------+--------------+
| 1         | 2         | 2016-03-01 | 5            |
| 1         | 2         | 2016-05-02 | 6            |
| 1         | 3         | 2017-06-25 | 1            |
| 3         | 1         | 2016-03-02 | 0            |
| 3         | 4         | 2018-07-03 | 5            |
+-----------+-----------+------------+--------------+

输出：
+-----------+------------+---------------------+
| player_id | event_date | games_played_so_far |
+-----------+------------+---------------------+
| 1         | 2016-03-01 | 5                   |
| 1         | 2016-05-02 | 11                  |
| 1         | 2017-06-25 | 12                  |
| 3         | 2016-03-02 | 0                   |
| 3         | 2018-07-03 | 5                   |
+-----------+------------+---------------------+

解释：
玩家 1 到 2016-05-02 为止共玩了 5 + 6 = 11 局，到 2017-06-25 为止共玩了 5 + 6 + 1 = 12 局。
玩家 3 到 2018-07-03 为止共玩了 0 + 5 = 5 局。
注意：对每位玩家，只统计他实际登录过的日期。
```

## 题解

::: details 点击查看题解

### 思路

这是典型的「分组内按日期累加」问题，窗口函数一行搞定：`SUM(games_played) OVER (PARTITION BY player_id ORDER BY event_date)`——按玩家分区保证互不串味，按 `event_date` 排序后，窗口默认帧是「分区起点到当前行」，于是每一行都带上截至当天的累计值。

两个易错点。第一，`ORDER BY` 的列必须与题目语义一致（日期），写成 `ORDER BY games_played` 累加的就是游戏数顺序而非时间顺序，结果完全错误。第二，只统计登录过的日期——窗口函数天然只在表里存在的行上输出，不会给没登录的日子补 0，这正是题目注释强调的点。

替代写法一：自连接 `t1 JOIN t2 ON t1.player_id = t2.player_id AND t1.event_date >= t2.event_date`，再按 `(t1.player_id, t1.event_date)` 分组 `SUM(t2.games_played)`，语义相同但复杂度更高。替代写法二：相关子查询逐行求和。窗口写法最简洁，也是这类「running total」的通用模板。

### SQL 实现

```sql
SELECT
    player_id,
    event_date,
    SUM(games_played) OVER (
        PARTITION BY player_id
        ORDER BY event_date
    ) AS games_played_so_far
FROM Activity
ORDER BY player_id, event_date;
```

### 复杂度分析

- 时间复杂度：O(n log n)，窗口排序主导，n 为登录记录数。
- 空间复杂度：O(n)，窗口累计的中间状态。

:::
