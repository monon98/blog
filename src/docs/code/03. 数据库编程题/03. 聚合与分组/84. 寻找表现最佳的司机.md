# 寻找表现最佳的司机

> 难度：中等 | 标签：多表连接、窗口函数、分组聚合 | [LeetCode 原题](https://leetcode.cn/problems/find-top-performing-driver/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

`Drivers` 表：

```
+------------+---------+
| Column Name| Type    |
+------------+---------+
| driver_id  | int     |
| name       | varchar |
| age        | int     |
| experience | int     |
| accidents  | int     |
+------------+---------+
driver_id 是该表的主键。
每一行包含司机 ID、姓名、年龄、驾龄（年）以及事故数。
```

`Vehicles` 表：

```
+------------+---------+
| Column Name| Type    |
+------------+---------+
| vehicle_id | int     |
| driver_id  | int     |
| model      | varchar |
| fuel_type  | varchar |
| mileage    | int     |
+------------+---------+
vehicle_id 是该表的主键。
每一行包含车辆 ID、所属司机、车型、动力类型以及里程数。
```

`Trips` 表：

```
+------------+---------+
| Column Name| Type    |
+------------+---------+
| trip_id    | int     |
| vehicle_id | int     |
| distance   | int     |
| duration   | int     |
| rating     | int     |
+------------+---------+
trip_id 是该表的主键。
每一行包含行程 ID、使用的车辆、行驶距离、行程时长（分钟）以及乘客评分（1-5）。
```

编写一个解决方案，找出 **每种动力类型** 中 **表现最好的司机**，评判标准依次为：

1. 司机的表现由其所有行程的 **平均评分** 决定，平均评分四舍五入到 `2` 位小数。
2. 平均评分相同则 **总里程更多** 的司机更优。
3. 仍然相同则 **事故数更少** 的司机更优。

返回结果表，以 `fuel_type` 升序排序。

**示例 1：**

输入：

```
Drivers 表：
+-----------+---------+-----+------------+-----------+
| driver_id | name    | age | experience | accidents |
+-----------+---------+-----+------------+-----------+
| 1         | Alice   | 34  | 10         | 1         |
| 2         | Bob     | 45  | 20         | 3         |
| 3         | Charlie | 28  | 5          | 0         |
+-----------+---------+-----+------------+-----------+

Vehicles 表：
+------------+-----------+---------+-----------+---------+
| vehicle_id | driver_id | model   | fuel_type | mileage |
+------------+-----------+---------+-----------+---------+
| 100        | 1         | Sedan   | Gasoline  | 20000   |
| 101        | 2         | SUV     | Electric  | 30000   |
| 102        | 3         | Coupe   | Gasoline  | 15000   |
+------------+-----------+---------+-----------+---------+

Trips 表：
+---------+------------+----------+----------+--------+
| trip_id | vehicle_id | distance | duration | rating |
+---------+------------+----------+----------+--------+
| 201     | 100        | 50       | 30       | 5      |
| 202     | 100        | 30       | 20       | 4      |
| 203     | 101        | 100      | 60       | 4      |
| 204     | 101        | 80       | 50       | 5      |
| 205     | 102        | 40       | 30       | 5      |
| 206     | 102        | 60       | 40       | 5      |
+---------+------------+----------+----------+--------+
```

输出：

```
+-----------+-----------+--------+----------+
| fuel_type | driver_id | rating | distance |
+-----------+-----------+--------+----------+
| Electric  | 2         | 4.50   | 180      |
| Gasoline  | 3         | 5.00   | 100      |
+-----------+-----------+--------+----------+
```

解释：

- `Gasoline` 类型下有 Alice（平均 4.5）与 Charlie（平均 5.0），Charlie 更优。
- `Electric` 类型下只有 Bob，平均评分 4.5，直接入选。

## 题解

::: details 点击查看题解

### 思路

评判指标全部落在「司机 + 动力类型」这个粒度上，所以先把三张表串起来：`Drivers` 按 `driver_id` 连 `Vehicles`，再按 `vehicle_id` 连 `Trips`，然后 `GROUP BY fuel_type, driver_id` 聚合出平均评分、总里程、事故数。

有一个容易忽略的细节：一名司机可能拥有同一动力类型的多辆车，与 `Vehicles` 连接后 `Drivers` 的行会被复制。此时事故数如果写 `SUM(d.accidents)`，会按车辆数被重复累加；事故数本来就属于司机，应该用 `MAX(d.accidents)`（组内取值唯一）。总里程则确实要 `SUM(t.distance)`，因为那是每趟行程的累加。

选出每种动力的第一名用 `RANK()` 而不是 `GROUP BY + MAX`：`MAX(rating)` 只能带回分数，带不回对应的 `driver_id` —— 这正是分组聚合最常见的「取最大值的整行」陷阱。窗口排序键按题目优先级写：`rating DESC, distance DESC, accidents ASC`，`RANK` 保证三项全并列时同时输出（若要求唯一则换 `ROW_NUMBER`）。

排序时直接用四舍五入后的 `rating` 比较，与题面「平均评分保留 2 位小数」的定义一致，避免 `4.499` 与 `4.50` 这类显示相同却排序不同的情况。

### SQL 实现

```sql
WITH driver_stats AS (
    SELECT
        v.fuel_type,
        d.driver_id,
        ROUND(AVG(t.rating), 2) AS rating,
        SUM(t.distance) AS distance,
        MAX(d.accidents) AS accidents
    FROM Drivers d
    JOIN Vehicles v ON v.driver_id = d.driver_id
    JOIN Trips t ON t.vehicle_id = v.vehicle_id
    GROUP BY v.fuel_type, d.driver_id
),
ranked AS (
    SELECT
        fuel_type,
        driver_id,
        rating,
        distance,
        RANK() OVER (
            PARTITION BY fuel_type
            ORDER BY rating DESC, distance DESC, accidents ASC
        ) AS rk
    FROM driver_stats
)
SELECT fuel_type, driver_id, rating, distance
FROM ranked
WHERE rk = 1
ORDER BY fuel_type;
```

### 复杂度分析

- 时间复杂度：O(n + m log m)，n 为三表连接后的行程行数，m 为「动力类型 × 司机」组合数，主要开销在连接与窗口排序。
- 空间复杂度：O(m)，用于存放每个司机-动力类型的聚合结果与排名。
