# 苹果和橘子的个数

> 难度：中等 | 标签：多表连接、聚合函数、IFNULL | [LeetCode 原题](https://leetcode.cn/problems/count-apples-and-oranges/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

表：`Boxes`

```
+-------------+------+
| Column Name | Type |
+-------------+------+
| box_id      | int  |
| chest_id    | int  |
| apple_count | int  |
| orange_count| int  |
+-------------+------+
box_id 是此表中具有唯一值的列。
每一行表示一个盒子：`apple_count`、`orange_count` 是盒子里**直接**放着的苹果和橘子数量；
`chest_id` 是盒子里那个箱子（chest）的 id，如果盒子里没有箱子则为 NULL。
`chest_id` 是 `Chests` 表中的 `chest_id`。
```

表：`Chests`

```
+-------------+------+
| Column Name | Type |
+-------------+------+
| chest_id    | int  |
| apple_count | int  |
| orange_count| int  |
+-------------+------+
chest_id 是此表中具有唯一值的列。
每一行表示一个箱子：`apple_count`、`orange_count` 是箱子里装的苹果和橘子数量。
```

编写一个解决方案，统计**所有盒子**里苹果和橘子的总数。盒子里的东西既包括盒子本身直接放的水果，也包括盒中箱子里的水果。

返回一行结果，包含两列：`apple_count` 和 `orange_count`。

**示例 1：**

输入：

```
Boxes table:
+--------+----------+-------------+--------------+
| box_id | chest_id | apple_count | orange_count |
+--------+----------+-------------+--------------+
| 2      | null     | 6           | 15           |
| 18     | 14       | 4           | 15           |
| 19     | 3        | 8           | 4            |
| 12     | 2        | 19          | 20           |
| 20     | 6        | 12          | 9            |
| 8      | 6        | 9           | 9            |
| 3      | 14       | 16          | 7            |
+--------+----------+-------------+--------------+

Chests table:
+----------+-------------+--------------+
| chest_id | apple_count | orange_count |
+----------+-------------+--------------+
| 6        | 5           | 6            |
| 14       | 20          | 10           |
| 2        | 8           | 8            |
| 3        | 19          | 4            |
| 16       | 19          | 19           |
+----------+-------------+--------------+
```

输出：

```
+-------------+--------------+
| apple_count | orange_count |
+-------------+--------------+
| 151         | 123          |
+-------------+--------------+
```

解释：

- 盒子 2 里没有箱子：6 个苹果、15 个橘子。
- 盒子 18 里有箱子 14：4 + 20 = 24 个苹果，15 + 10 = 25 个橘子。
- 盒子 19 里有箱子 3：8 + 19 = 27 个苹果，4 + 4 = 8 个橘子。
- 盒子 12 里有箱子 2：19 + 8 = 27 个苹果，20 + 8 = 28 个橘子。
- 盒子 20 里有箱子 6：12 + 5 = 17 个苹果，9 + 6 = 15 个橘子。
- 盒子 8 里有箱子 6：9 + 5 = 14 个苹果，9 + 6 = 15 个橘子。
- 盒子 3 里有箱子 14：16 + 20 = 36 个苹果，7 + 10 = 17 个橘子。
- 合计苹果 151 个、橘子 123 个。箱子 16 没有被任何盒子装着，不计入。

## 题解

::: details 点击查看题解

### 思路

每个盒子的水果量 = 盒子自身的 `apple_count/orange_count` + 盒中箱子的同名字段。这是一对零或一对一的补充关系（`Boxes.chest_id` 可空），所以用 `Boxes LEFT JOIN Chests ON box_id 对应的 chest_id`，然后逐行相加再整体求和。

必须从 `Boxes` 出发做左连接，理由有两个：一是 `chest_id` 为 NULL 的盒子（如盒子 2）如果用内连接会整行消失，它自身的 6 个苹果、15 个橘子就漏了；二是 `Chests` 里没有被任何盒子引用的箱子（如 16）不该计入，从左表出发天然把它排除在外。

`IFNULL(c.apple_count, 0)` 必不可少：没有箱子的盒子在连接后箱子字段全是 NULL，而 NULL 参与加法会让整个表达式变成 NULL，`SUM` 也会把它当不存在，最终结果偏小但不报错，属于很难一眼看出的错误。

题目只要求返回一行汇总，所以整条语句不需要 `GROUP BY`，两个 `SUM` 就是全局聚合；没有数据时 MySQL 返回一行 NULL，这种边界题面并未要求处理。

### SQL 实现

```sql
SELECT SUM(b.apple_count + IFNULL(c.apple_count, 0))   AS apple_count,
       SUM(b.orange_count + IFNULL(c.orange_count, 0)) AS orange_count
FROM Boxes b
LEFT JOIN Chests c ON c.chest_id = b.chest_id;
```

### 复杂度分析

- 时间复杂度：O(n)，n 为盒子数，一次左连接加一次全表聚合（`Chests` 走主键查找）。
- 空间复杂度：O(1)，只返回一行汇总结果。

:::
