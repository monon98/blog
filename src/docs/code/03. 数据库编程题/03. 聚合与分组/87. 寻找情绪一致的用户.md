# 寻找情绪一致的用户

> 难度：中等 | 标签：分组聚合、窗口函数、子查询 | [LeetCode 原题](https://leetcode.cn/problems/find-emotionally-consistent-users/)

## 题目描述

表：`reactions`

```
+--------------+---------+
| Column Name  | Type    |
+--------------+---------+
| user_id      | int     |
| content_id   | int     |
| reaction     | varchar |
+--------------+---------+
(user_id, content_id) 是这张表的主键（值互不相同）。
每一行代表用户对某条内容的反应。
```

根据以下要求编写一个解决方案，以识别 **情绪一致的用户**：

	- 为每个用户统计他们发送的总反应次数。

	- 仅包含 至少对 5 个不同内容项 作出反应的用户。

	- 如果用户 至少 60% 的反应属于 同一种类型，则认为其 情绪一致。

返回结果表按 `reaction_ratio` **降序** 排序，然后按 `user_id` **升序** 排序。

**注意：**

	- reaction_ratio 应该舍入到 2 位小数

结果格式如下所示。

示例：

**输入：**

reactions 表：

+---------+------------+----------+
| user_id | content_id | reaction |
+---------+------------+----------+
| 1       | 101        | like     |
| 1       | 102        | like     |
| 1       | 103        | like     |
| 1       | 104        | wow      |
| 1       | 105        | like     |
| 2       | 201        | like     |
| 2       | 202        | wow      |
| 2       | 203        | sad      |
| 2       | 204        | like     |
| 2       | 205        | wow      |
| 3       | 301        | love     |
| 3       | 302        | love     |
| 3       | 303        | love     |
| 3       | 304        | love     |
| 3       | 305        | love     |
+---------+------------+----------+

**输出：**

+---------+-------------------+----------------+
| user_id | dominant_reaction | reaction_ratio |
+---------+-------------------+----------------+
| 3       | love              | 1.00           |
| 1       | like              | 0.80           |
+---------+-------------------+----------------+

**解释：**

	- 用户 1：

		总反应数 = 5

		- 'like' 出现了 4 次

		- reaction_ratio = 4 / 5 = 0.80

		- 满足 60% 一致的要求

	- 用户 2：

		总反应数 = 5

		- 出现最多的反应只出现了 2 次

		- reaction_ratio = 2 / 5 = 0.40

		- 不满足一致的要求

	- 用户 3：

		总反应数 = 5

		- 'love' 出现了 5 次

		- reaction_ratio = 5 / 5 = 1.00

		- 满足一致的要求

结果表按 reaction_ratio 降序排序，然后按 user_id 升序排序。

## 题解

::: details 点击查看题解

### 思路

这题要同时拿三样东西：每个用户的反应总数、每个用户对不同内容的反应条数、以及出现次数最多的那种反应。前两者按 `user_id` 聚合即可，第三者需要先按 `(user_id, reaction)` 分组数出每种反应的次数，再在每个用户内部取最大值——这正是窗口函数 `ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY cnt DESC)` 的用武之地。

实现上分两步：第一步汇总每个用户的总反应数与去重内容数，第二步按 `(user_id, reaction)` 计数并用 `ROW_NUMBER` 打上名次，取 `rn = 1` 的就是主导反应。最后用比率 `cnt / total >= 0.6` 过滤，`ROUND(..., 2)` 输出两位小数，再按要求先按比率降序、再按 `user_id` 升序排序。

易错点：一是「至少 5 个不同内容项」必须用 `COUNT(DISTINCT content_id)`，示例中每个用户恰好只有 5 条且内容互不相同，所以两种计数看起来一样，但换成有重复内容的测试就会翻车；二是比率过滤不要用舍入后的值，否则 0.596 会被舍入成 0.60 而误入结果，本题用未舍入的原值比较更稳妥；三是排序键既可以用别名 `reaction_ratio`，也可以重复表达式，MySQL 支持前者。

关于并列：如果一个用户有两种反应次数相同且都达到 60%，题目没有定义选哪个。`ROW_NUMBER` 的 `ORDER BY cnt DESC` 后补上 `reaction` 作为次序键可以保证结果稳定，但本题的测试数据不会出现这种并列。替代写法是不用窗口函数，用 `(user_id, reaction)` 分组后与用户级最大计数做等值连接，可读性稍差。

### SQL 实现

```sql
WITH user_stat AS (
    SELECT user_id,
           COUNT(*) AS total_cnt,
           COUNT(DISTINCT content_id) AS content_cnt
    FROM reactions
    GROUP BY user_id
),
reaction_stat AS (
    SELECT user_id,
           reaction,
           COUNT(*) AS reaction_cnt,
           ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY COUNT(*) DESC, reaction) AS rn
    FROM reactions
    GROUP BY user_id, reaction
)
SELECT r.user_id,
       r.reaction AS dominant_reaction,
       ROUND(r.reaction_cnt / u.total_cnt, 2) AS reaction_ratio
FROM reaction_stat r
JOIN user_stat u
    ON u.user_id = r.user_id
WHERE u.content_cnt >= 5
  AND r.rn = 1
  AND r.reaction_cnt / u.total_cnt >= 0.6
ORDER BY reaction_ratio DESC, r.user_id;
```

### 复杂度分析

- 时间复杂度：O(n log n)，n 为 reactions 行数，两次分组聚合与一次窗口排序主导。
- 空间复杂度：O(u × r)，u 为用户数、r 为不同反应类型数，用于保存中间计数。

:::
