# 小众书籍

> 难度：中等 | 标签：分组聚合、多表连接 | [LeetCode 原题](https://leetcode.cn/problems/unpopular-books/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

`Books` 表：

```
+----------------+---------+
| Column Name    | Type    |
+----------------+---------+
| book_id        | int     |
| name           | varchar |
| available_from | date    |
+----------------+---------+
book_id 是该表的主键。
available_from 表示该书可售的起始日期。
```

`Orders` 表：

```
+----------------+---------+
| Column Name    | Type    |
+----------------+---------+
| order_id       | int     |
| book_id        | int     |
| quantity       | int     |
| dispatch_date  | date    |
+----------------+---------+
order_id 是该表的主键。
book_id 是 Books 表的外键。
每一行表示一本 book_id 的书在 dispatch_date 发货了 quantity 本。
```

编写解决方案，报告「小众书籍」：**过去一年内（假设今天是 2019-06-23，即 2018-06-23 至 2019-06-23 之间发货的订单）总销量少于 10 本** 的书，同时 **排除上架（available_from）距今不满一个月的书**（即要求 `available_from < 2019-05-23`）。一年内没有订单的书销量记为 0，满足条件。

以任意顺序返回结果表，结果包含 `book_id` 和 `name` 两列。

**示例 1:**

```
输入:
Books 表:
+---------+--------------------+----------------+
| book_id | name               | available_from |
+---------+--------------------+----------------+
| 1       | Kalila And Demna   | 2010-01-01     |
| 2       | 28 Letters         | 2012-05-12     |
| 3       | The Hobbit         | 2019-06-10     |
| 4       | 13 Reasons Why     | 2019-06-01     |
| 5       | The Hunger Games   | 2008-09-21     |
+---------+--------------------+----------------+
Orders 表:
+----------+---------+----------+---------------+
| order_id | book_id | quantity | dispatch_date |
+----------+---------+----------+---------------+
| 1        | 1       | 2        | 2018-07-26    |
| 2        | 1       | 1        | 2018-11-05    |
| 3        | 3       | 8        | 2019-06-11    |
| 4        | 4       | 6        | 2019-06-05    |
| 5        | 4       | 5        | 2019-06-20    |
| 6        | 5       | 9        | 2009-02-02    |
| 7        | 5       | 8        | 2010-04-13    |
+----------+---------+----------+---------------+
输出:
+-----------+--------------------+
| book_id   | name               |
+-----------+--------------------+
| 1         | Kalila And Demna   |
| 2         | 28 Letters         |
| 5         | The Hunger Games   |
+-----------+--------------------+
解释:
书 1 在一年内卖出 2 + 1 = 3 本（少于 10），且早已上架。
书 2 一年内没有订单（销量 0），且早已上架。
书 3 上架不满一个月（2019-06-10 距 2019-06-23 不足一个月），排除。
书 4 上架不满一个月，且一年内卖出 6 + 5 = 11 本（不少于 10），排除。
书 5 一年内没有订单（2009、2010 年的订单不在窗口内），销量 0，且早已上架。
```

## 题解

::: details 点击查看题解

### 思路

本题有三个独立条件，必须逐个落实：① 统计窗口是 2018-06-23 至 2019-06-23（今天往前一年），窗口外的订单一律不计；② 窗口内销量 `< 10`，没有订单的书要算 0 而不是被过滤掉；③ `available_from` 距今天不满一个月的书直接排除，即 `available_from < '2019-05-23'`。

用 `LEFT JOIN` 是关键：以 `Books` 为主表、把订单作为右表，并把窗口条件放进 `ON` 而不是 `WHERE`——放在 `ON` 里时，不满足窗口的订单行变成 `NULL` 右行，书仍然保留，配合 `IFNULL(SUM(quantity), 0)` 就能正确得到 0 销量。若把订单条件放进 `WHERE`，那些只有窗口外订单的书（如书 5）会被整行过滤掉，结果就漏了。

`HAVING IFNULL(SUM(quantity), 0) < 10` 在分组后过滤销量。注意三个条件的分工：可用性（`available_from`）是行级条件，写在 `WHERE`；销量是聚合条件，必须在 `HAVING`。替代写法：先在子查询里 `GROUP BY book_id` 算出窗口销量再与 `Books` 连接，逻辑等价。`dispatch_date` 的上界 2019-06-23 也不要漏——虽然示例数据没有更晚的订单，但严谨的窗口应是闭区间。

### SQL 实现

```sql
SELECT b.book_id, b.name
FROM Books b
LEFT JOIN Orders o
    ON b.book_id = o.book_id
   AND o.dispatch_date >= '2018-06-23'
   AND o.dispatch_date <= '2019-06-23'
WHERE b.available_from < '2019-05-23'
GROUP BY b.book_id, b.name
HAVING IFNULL(SUM(o.quantity), 0) < 10;
```

### 复杂度分析

- 时间复杂度：O(n log n)，n 为订单数，左连接与分组接近线性，分组排序主导。
- 空间复杂度：O(k)，k 为书籍数，连接与分组哈希表开销。
