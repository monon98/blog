# 销售分析 III

> 难度：简单 | 标签：多表连接、分组聚合、日期函数 | [LeetCode 原题](https://leetcode.cn/problems/sales-analysis-iii/)

## 题目描述

表： `Product`

```
+--------------+---------+
| Column Name  | Type    |
+--------------+---------+
| product_id   | int     |
| product_name | varchar |
| unit_price   | int     |
+--------------+---------+
product_id 是该表的主键（具有唯一值的列）。
该表的每一行显示每个产品的名称和价格。
```

表：`Sales`

```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| seller_id   | int     |
| product_id  | int     |
| buyer_id    | int     |
| sale_date   | date    |
| quantity    | int     |
| price       | int     |
+------ ------+---------+
这个表可能有重复的行。
product_id 是 Product 表的外键（reference 列）。
该表的每一行包含关于一个销售的一些信息。
```

编写解决方案，报告 `2019年春季` 才售出的产品。即 **仅 **在 `**2019-01-01**`** **（含）至 `**2019-03-31**`** **（含）之间出售的商品。

以 **任意顺序** 返回结果表。

结果格式如下所示。

**示例 1:**

```
输入：
Product table:
+------------+--------------+------------+
| product_id | product_name | unit_price |
+------------+--------------+------------+
| 1          | S8           | 1000       |
| 2          | G4           | 800        |
| 3          | iPhone       | 1400       |
+------------+--------------+------------+
Sales table:
+-----------+------------+----------+------------+----------+-------+
| seller_id | product_id | buyer_id | sale_date  | quantity | price |
+-----------+------------+----------+------------+----------+-------+
| 1         | 1          | 1        | 2019-01-21 | 2        | 2000  |
| 1         | 2          | 2        | 2019-02-17 | 1        | 800   |
| 2         | 2          | 3        | 2019-06-02 | 1        | 800   |
| 3         | 3          | 4        | 2019-05-13 | 2        | 2800  |
+-----------+------------+----------+------------+----------+-------+
输出：
+-------------+--------------+
| product_id  | product_name |
+-------------+--------------+
| 1           | S8           |
+-------------+--------------+
解释:
id 为 1 的产品仅在 2019 年春季销售。
id 为 2 的产品在 2019 年春季销售，但也在 2019 年春季之后销售。
id 为 3 的产品在 2019 年春季之后销售。
我们只返回 id 为 1 的产品，因为它是 2019 年春季才销售的产品。
```

## 题解

::: details 点击查看题解

### 思路

「仅在春季售出」等价于两个条件同时成立：该产品 **所有** 销售记录的最早日期不早于 2019-01-01，且最晚日期不晚于 2019-03-31。因此按 `product_id` 分组后，用 `MIN(sale_date)` 和 `MAX(sale_date)` 夹住整个销售区间，再用 `HAVING` 过滤；只要有一笔销售落在区间外，最大值或最小值就会越界，产品即被排除。这比「先筛出春季销售再看是否还有其他销售」的两层 `NOT EXISTS` 写法直观得多。

连接 `Product` 是为了输出 `product_name`，`INNER JOIN` 不会漏产品——能出现在结果里的产品必然有销售记录，零销量产品本来也不该返回。注意日期比较用字符串字面量 `'2019-01-01'` 即可，MySQL 会按 `DATE` 语义比较；边界是闭区间，务必写 `>=` 和 `<=`，漏掉等号会把恰好在 2019-01-01 或 2019-03-31 的产品错误排除。

常见错误是只用 `WHERE sale_date BETWEEN ...` 筛选：这样得到的是「在春季卖过的产品」，会把产品 2（春季之后又卖过）也包含进来，与「才售出」的语义相反。`HAVING` 中的 `MIN/MAX` 作用于 **未被 WHERE 过滤的全部行**，这正是本题的关键。

### SQL 实现

```sql
SELECT p.product_id, p.product_name
FROM Product p
JOIN Sales s
    ON p.product_id = s.product_id
GROUP BY p.product_id, p.product_name
HAVING MIN(s.sale_date) >= '2019-01-01'
   AND MAX(s.sale_date) <= '2019-03-31';
```

### 复杂度分析

- 时间复杂度：O(n log n)，n 为销售记录数，连接接近线性，分组与最值计算主导。
- 空间复杂度：O(k)，k 为产品数，分组哈希表开销。

:::
