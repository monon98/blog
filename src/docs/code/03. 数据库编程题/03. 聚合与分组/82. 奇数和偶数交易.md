# 奇数和偶数交易

> 难度：中等 | 标签：条件聚合、分组聚合 | [LeetCode 原题](https://leetcode.cn/problems/odd-and-even-transactions/)

## 题目描述

表：`transactions`

```
+------------------+------+
| Column Name      | Type |
+------------------+------+
| transaction_id   | int  |
| amount           | int  |
| transaction_date | date |
+------------------+------+
transactions_id 列唯一标识了表中的每一行。
这张表的每一行包含交易 id，金额总和和交易日期。
```

编写一个解决方案来查找每天 **奇数** 交易金额和 **偶数** 交易金额的 **总和**。如果某天没有奇数或偶数交易，显示为 `0`。

返回结果表以 `transaction_date` **升序** 排序。

结果格式如下所示。

示例：

**输入：**

`transactions` 表：

+----------------+--------+------------------+
| transaction_id | amount | transaction_date |
+----------------+--------+------------------+
| 1              | 150    | 2024-07-01       |
| 2              | 200    | 2024-07-01       |
| 3              | 75     | 2024-07-01       |
| 4              | 300    | 2024-07-02       |
| 5              | 50     | 2024-07-02       |
| 6              | 120    | 2024-07-03       |
+----------------+--------+------------------+

**输出：**

+------------------+---------+----------+
| transaction_date | odd_sum | even_sum |
+------------------+---------+----------+
| 2024-07-01       | 75      | 350      |
| 2024-07-02       | 0       | 350      |
| 2024-07-03       | 0       | 120      |
+------------------+---------+----------+

**解释：**

	- 对于交易日期：

		2024-07-01:

			奇数交易金额总和：75

			- 偶数交易金额总和：150 + 200 = 350

		- 2024-07-02:

			奇数交易金额总和：0

			- 偶数交易金额总和：300 + 50 = 350

		- 2024-07-03:

			奇数交易金额总和：0

			- 偶数交易金额总和：120

**注意：**输出表以 `transaction_date` 升序排序。

## 题解

::: details 点击查看题解

### 思路

题目要的是「同一天里的两个汇总值」，也就是说分组键只有一个 `transaction_date`，而奇数、偶数金额是同一组内的两个不同口径 —— 这正是条件聚合的典型场景：用 `SUM(CASE WHEN ... THEN amount ELSE 0 END)` 在一条 `GROUP BY` 里同时算出两列。

最常见的错误是按奇偶过滤后再分组：`WHERE amount % 2 = 1` 会把当天所有偶数交易直接丢掉，之后再想算 `even_sum` 就没有数据了；反过来，如果分两次查询再拼接，还要处理「某天只有一种奇偶」的缺失行。

`ELSE 0` 不能省。`SUM` 会忽略 `NULL`，若把 `ELSE` 写成 `NULL`，某个金额都不匹配的那一天会得到 `NULL` 而不是题面要求的 `0`。

判断奇偶用 `amount % 2` 即可；MySQL 里负数取模结果为负（`-3 % 2 = -1`），若金额可能为负，稳妥写法是 `ABS(amount) % 2` 或 `amount MOD 2 = 1` 之外再取绝对值。

替代写法：`SUM(IF(amount % 2 = 1, amount, 0))` 与 `CASE WHEN` 等价，只是可移植性稍差（`IF` 是 MySQL 方言）。

### SQL 实现

```sql
SELECT
    transaction_date,
    SUM(CASE WHEN amount % 2 = 1 THEN amount ELSE 0 END) AS odd_sum,
    SUM(CASE WHEN amount % 2 = 0 THEN amount ELSE 0 END) AS even_sum
FROM transactions
GROUP BY transaction_date
ORDER BY transaction_date;
```

### 复杂度分析

- 时间复杂度：O(n)，n 为交易行数，一次扫描同时完成分组与两个聚合。
- 空间复杂度：O(d)，d 为不同交易日期数，用于维护分组状态。
