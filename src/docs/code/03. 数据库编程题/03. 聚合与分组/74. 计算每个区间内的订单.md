# 计算每个区间内的订单

> 难度：中等 | 标签：分组聚合、数学运算 | [LeetCode 原题](https://leetcode.cn/problems/calculate-orders-within-each-interval/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

表：`Orders`

```
+-------------+------+
| Column Name | Type |
+-------------+------+
| minute      | int  |
| order_count | int  |
+-------------+------+
minute 是该表的主键。
该表的每一行包含分钟数以及在特定分钟数内收到的订单数量。总行数将是 6 的倍数。
```

编写一个查询，计算每个 **区间** 内的 **总订单数量**。每个区间被定义为 **6 分钟** 的组合：1 到 6 分钟属于第 1 个区间，而 7 到 12 分钟属于第 2 个区间，以此类推。

按 **升序顺序** 返回结果表，按 `interval_no` 排序。结果表的格式如下例所示。

**示例 1：**

输入：

```
Orders table:
+--------+-------------+
| minute | order_count |
+--------+-------------+
| 1      | 0           |
| 2      | 2           |
| 3      | 4           |
| 4      | 6           |
| 5      | 1           |
| 6      | 4           |
| 7      | 1           |
| 8      | 2           |
| 9      | 4           |
| 10     | 1           |
| 11     | 4           |
| 12     | 6           |
+--------+-------------+
```

输出：

```
+-------------+--------------+
| interval_no | total_orders |
+-------------+--------------+
| 1           | 17           |
| 2           | 18           |
+-------------+--------------+
```

解释：

- 区间号 1 包括从 1 到 6 分钟的时间。这 6 分钟内的总订单数量为 (0 + 2 + 4 + 6 + 1 + 4) = 17。
- 区间号 2 包括从 7 到 12 分钟的时间。这 6 分钟内的总订单数量为 (1 + 2 + 4 + 1 + 4 + 6) = 18。

按升序顺序返回结果表，按 `interval_no` 排序。

## 题解

::: details 点击查看题解

### 思路

题目的本质是「把 minute 映射成区间号再分组求和」。区间号的通项公式是 `FLOOR((minute - 1) / 6) + 1`，整理一下就是 `(minute + 5) DIV 6`（MySQL 的 `DIV` 是整数除法，等价于向下取整），1~6 映射为 1，7~12 映射为 2，以此类推。拿到区间号后 `GROUP BY` 并对 `order_count` 求 `SUM` 即可。

易错点有二：其一，区间是 **6 分钟** 一段而不是 15 分钟或 10 分钟，公式里的除数必须是 6；其二，`minute` 从 1 开始而不是从 0 开始，若写成 `minute DIV 6`，第 6 分钟会被划进区间 0、第 7 分钟划进区间 1，边界整体错位——`+5` 的作用正是把 1~6 这一段「顶」到同一个商上。

`interval_no` 是计算列，`GROUP BY` 和 `ORDER BY` 都可以直接引用它的别名（MySQL 支持在 GROUP BY 中使用 SELECT 别名）。若担心可移植性，把表达式在 GROUP BY 里原样重复一遍也行。

### SQL 实现

```sql
SELECT
    (minute + 5) DIV 6 AS interval_no,
    SUM(order_count) AS total_orders
FROM Orders
GROUP BY interval_no
ORDER BY interval_no;
```

### 复杂度分析

- 时间复杂度：O(n)，n 为 Orders 行数，一次扫描完成映射与求和（排序仅针对区间数）。
- 空间复杂度：O(k)，k 为区间数量。

:::
