# 销售分析 I

> 难度：简单 | 标签：多表连接、分组聚合 | [LeetCode 原题](https://leetcode.cn/problems/sales-analysis-i/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

`Product` 表：

```
+--------------+---------+
| Column Name  | Type    |
+--------------+---------+
| product_id   | int     |
| product_name | varchar |
| unit_price   | int     |
+--------------+---------+
product_id 是该表的主键。
该表的每一行显示每个产品的名称和价格。
```

`Sales` 表：

```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| seller_id   | int     |
| product_id  | int     |
| buyer_id    | int     |
| sale_date   | date    |
| quantity    | int     |
| price       | int     |
+-------------+---------+
该表没有主键，可能存在重复行。
product_id 是 Product 表的外键。
该表的每一行包含关于一次销售的信息，price 为该笔销售的总价。
```

编写解决方案，报告 **销售额最高** 的卖家（按 `price` 总和统计）。如果存在并列最高的卖家，**全部返回**。结果只包含 `seller_id` 一列，以任意顺序返回。

**示例 1:**

```
输入:
Product 表:
+------------+--------------+------------+
| product_id | product_name | unit_price |
+------------+--------------+------------+
| 1          | S8           | 1000       |
| 2          | G4           | 800        |
| 3          | iPhone       | 1400       |
+------------+--------------+------------+
Sales 表:
+-----------+------------+----------+------------+----------+-------+
| seller_id | product_id | buyer_id | sale_date  | quantity | price |
+-----------+------------+----------+------------+----------+-------+
| 1         | 1          | 1        | 2019-01-21 | 2        | 2000  |
| 1         | 2          | 2        | 2019-02-17 | 1        | 800   |
| 2         | 2          | 3        | 2019-06-02 | 1        | 800   |
| 3         | 3          | 4        | 2019-05-13 | 2        | 2800  |
+-----------+------------+----------+------------+----------+-------+
输出:
+-------------+
| seller_id   |
+-------------+
| 1           |
| 3           |
+-------------+
解释:
卖家 1 的总销售额为 2000 + 800 = 2800，卖家 3 的总销售额为 2800，
两者并列最高，卖家 2 只有 800，所以返回 1 和 3。
```

## 题解

::: details 点击查看题解

### 思路

按 `seller_id` 分组求 `SUM(price)` 得到每个卖家的总销售额，再取出最大值对应的所有卖家。注意统计口径是 `price` 列——表注释明确 `price` 是该笔销售的总价（单价 × 数量），不要再乘一次 `quantity`；也不要用 `Product.unit_price` 去算，那是产品标价，与实际成交额不同（示例里卖家 1 卖的 G4 标价 800，成交也是 800，但两套口径对复杂数据会给出不同答案）。

保留并列的关键与 1076 类似：用 `HAVING SUM(price) = (子查询求最大总销售额)`，而不是 `ORDER BY ... LIMIT 1`——后者在并列时只返回一个人，示例要求同时返回 1 和 3，会直接判错。子查询里先 `GROUP BY seller_id` 再 `ORDER BY SUM(price) DESC LIMIT 1` 取出最大值，外层用 `=` 匹配。

因为 `Sales` 表没有主键、可能有重复行，每一行都是一次真实销售，直接累加即可，不要加 `DISTINCT`。本题只统计有销售记录的卖家，不需要连接 `Product` 表。

### SQL 实现

```sql
SELECT seller_id
FROM Sales
GROUP BY seller_id
HAVING SUM(price) = (
    SELECT SUM(price) AS total
    FROM Sales
    GROUP BY seller_id
    ORDER BY total DESC
    LIMIT 1
);
```

### 复杂度分析

- 时间复杂度：O(n log n)，n 为销售记录数，两次分组求和，子查询排序主导。
- 空间复杂度：O(k)，k 为卖家数量，分组哈希表开销。

:::
