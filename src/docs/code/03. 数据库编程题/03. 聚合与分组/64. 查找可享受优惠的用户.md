# 查找可享受优惠的用户

> 难度：简单 | 标签：条件过滤、去重 | [LeetCode 原题](https://leetcode.cn/problems/the-users-that-are-eligible-for-discount/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

购买表 `Purchases`：

```
+-------------+----------+
| Column Name | Type     |
+-------------+----------+
| user_id     | int      |
| time_stamp  | datetime |
| amount      | int      |
+-------------+----------+
(user_id, time_stamp) 是该表的主键。
每一行表示 user_id 这名用户在 time_stamp 这个时间的一笔消费，金额为 amount。
```

如果用户在时间区间 `[startDate, endDate]` 内**有一笔**消费的金额**至少**为 `minAmount`，则该用户有资格享受折扣。把日期转成时间时，两端都视为当天的开始（例如 `endDate = 2022-03-20` 视为 `2022-03-20 00:00:00`）。

请编写一个解决方案，查询符合折扣条件的用户 ID，按 `user_id` 升序返回。

**示例 1：**

```
输入：
Purchases 表：
+---------+---------------------+--------+
| user_id | time_stamp          | amount |
+---------+---------------------+--------+
| 1       | 2022-04-20 09:03:00 | 4416   |
| 2       | 2022-03-19 19:24:02 | 678    |
| 3       | 2022-03-18 12:03:09 | 4523   |
| 3       | 2022-03-30 09:43:42 | 626    |
+---------+---------------------+--------+

startDate = 2022-03-08, endDate = 2022-03-20, minAmount = 1000

输出：
+---------+
| user_id |
+---------+
| 3       |
+---------+

解释：
用户 1 金额达标但不在时间区间内；
用户 2 在区间内但金额 678 < 1000；
用户 3 有一笔 4523 的消费既在区间内又金额达标，因此只有用户 3 符合条件。
```

## 题解

::: details 点击查看题解

### 思路

这是 2205 的「列表版」：同样以单笔订单为单位判断，金额 >= minAmount 且时间落在 [startDate, endDate] 内。

同一用户若有多笔达标订单会出现多行，必须用 DISTINCT 去重，并按 user_id 升序输出。

不要先用 GROUP BY user_id + SUM(amount) 判断是否达标——那是累计口径，与题意（单笔口径）不同。

### SQL 实现

```sql
SELECT DISTINCT user_id
FROM Purchases
WHERE amount >= 1000
  AND time_stamp BETWEEN '2022-03-08' AND '2022-03-20'
ORDER BY user_id;
```

### 复杂度分析

- 时间复杂度：O(n log n)，过滤后去重排序，n 为购买记录数
- 空间复杂度：O(k)，k 为达标用户数

:::
