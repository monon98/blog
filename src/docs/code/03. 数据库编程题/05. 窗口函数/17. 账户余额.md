# 账户余额

> 难度：中等 | 标签：窗口函数、前缀和 | [LeetCode 原题](https://leetcode.cn/problems/account-balance/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

表 `Transactions`：

```
+-------------+------------------------------+
| Column Name | Type                         |
+-------------+------------------------------+
| account_id  | int                          |
| day         | date                         |
| type        | ENUM('Deposit', 'Withdraw')  |
| amount      | int                          |
+-------------+------------------------------+
(account_id, day) 是该表的主键，即每个账户每天最多一笔交易。
type 为 'Deposit' 表示存款，'Withdraw' 表示取款。
```

要求：报告每个账户在**每笔交易之后的余额**。返回 `account_id`、`day`、`balance` 三列，按 `account_id` 升序、`day` 升序排列。

**示例 1：**

```
输入：
Transactions 表：
+------------+------------+----------+--------+
| account_id | day        | type     | amount |
+------------+------------+----------+--------+
| 1          | 2021-11-07 | Deposit  | 2000   |
| 1          | 2021-11-09 | Withdraw | 1000   |
| 1          | 2021-11-11 | Deposit  | 3000   |
| 2          | 2021-12-07 | Deposit  | 7000   |
| 2          | 2021-12-12 | Withdraw | 7000   |
+------------+------------+----------+--------+
输出：
+------------+------------+---------+
| account_id | day        | balance |
+------------+------------+---------+
| 1          | 2021-11-07 | 2000    |
| 1          | 2021-11-09 | 1000    |
| 1          | 2021-11-11 | 4000    |
| 2          | 2021-12-07 | 7000    |
| 2          | 2021-12-12 | 0       |
+------------+------------+---------+
解释：
账户 1：存 2000 后余额 2000，取 1000 后余额 1000，再存 3000 后余额 4000；
账户 2：存 7000 后余额 7000，全额取出后余额 0。
```

## 题解

::: details 点击查看题解

### 思路

"每笔交易之后的余额"就是**带符号金额的前缀和**：把 `Deposit` 记为正数、`Withdraw` 记为负数，按账户分区、按日期升序累加，任何一行的结果恰好是该时点的余额。

实现上有两个要点。第一，符号转换必须写在 `SUM(...) OVER (...)` 的参数里，写在外面（先 `SUM(amount)` 再按 `type` 加减）只会得到"全部存款 - 全部取款"的总额，拿不到每笔之后的余额。第二，窗口里必须 `ORDER BY day`，默认的 `RANGE UNBOUNDED PRECEDING AND CURRENT ROW` 才是前缀和语义；漏掉 `ORDER BY` 会退化成整分区求和，每行都是最终余额。

因为主键是 `(account_id, day)`，一天只有一笔交易，所以不存在同一天两笔的排序歧义。若真实场景一天可能多笔，应再加一个自增列（如交易日顺序）作为第二排序键。替代写法：相关子查询 `SUM(amount) WHERE day <= 当前行` 也能算前缀和，但复杂度 O(n^2)，窗口函数一次排序即可。

### SQL 实现

```sql
SELECT account_id,
       day,
       SUM(CASE WHEN type = 'Deposit' THEN amount ELSE -amount END)
           OVER (PARTITION BY account_id ORDER BY day) AS balance
FROM Transactions
ORDER BY account_id, day;
```

### 复杂度分析

- 时间复杂度：O(n log n)，窗口分区内排序主导。
- 空间复杂度：O(n)，保存每个账户的余额序列。

:::
