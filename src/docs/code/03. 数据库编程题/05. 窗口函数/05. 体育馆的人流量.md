# 体育馆的人流量

> 难度：困难 | 标签：窗口函数、连续区间 | [LeetCode 原题](https://leetcode.cn/problems/human-traffic-of-stadium/)

## 题目描述

表：`Stadium`

```
+---------------+---------+
| Column Name   | Type    |
+---------------+---------+
| id            | int     |
| visit_date    | date    |
| people        | int     |
+---------------+---------+
visit_date 是该表中具有唯一值的列。
每日人流量信息被记录在这三列信息中：序号 (id)、日期 (visit_date)、 人流量 (people)
每天只有一行记录，日期随着 id 的增加而增加
```

编写解决方案找出每行的人数大于或等于 `100` 且 `id` 连续的三行或更多行记录。

返回按 `visit_date` **升序排列** 的结果表。

查询结果格式如下所示。

**示例 1:**

```
输入：
Stadium 表:
+------+------------+-----------+
| id   | visit_date | people    |
+------+------------+-----------+
| 1    | 2017-01-01 | 10        |
| 2    | 2017-01-02 | 109       |
| 3    | 2017-01-03 | 150       |
| 4    | 2017-01-04 | 99        |
| 5    | 2017-01-05 | 145       |
| 6    | 2017-01-06 | 1455      |
| 7    | 2017-01-07 | 199       |
| 8    | 2017-01-09 | 188       |
+------+------------+-----------+
输出：
+------+------------+-----------+
| id   | visit_date | people    |
+------+------------+-----------+
| 5    | 2017-01-05 | 145       |
| 6    | 2017-01-06 | 1455      |
| 7    | 2017-01-07 | 199       |
| 8    | 2017-01-09 | 188       |
+------+------------+-----------+
解释：
id 为 5、6、7、8 的四行 id 连续，并且每行都有 >= 100 的人数记录。
请注意，即使第 7 行和第 8 行的 visit_date 不是连续的，输出也应当包含第 8 行，因为我们只需要考虑 id 连续的记录。
不输出 id 为 2 和 3 的行，因为至少需要三条 id 连续的记录。
```

## 题解

::: details 点击查看题解

### 思路

这题是典型的「连续区间」（gaps and islands）问题：先筛出 `people >= 100` 的行，再把 id 连续的行归成同一组，最后只保留组内行数 ≥ 3 的组。分组技巧是 `id - ROW_NUMBER()`：在一个 id 连续的片段里，`id` 和行号同步增长，差值恒定；一旦 id 出现断层，差值就会跳变，于是差值天然充当了「组号」。

得到组号后按组 `COUNT(*) >= 3` 过滤，再把属于这些组的原始行取出来，按 `visit_date` 升序输出即可。

易错点：一是「连续」只看 `id` 是否连续，不看 `visit_date`——示例里 id 7 和 8 的日期不是相邻两天，但 8 仍要输出；二是要求的是「三行**或更多**」，用三表自连接写死三行只能处理长度恰好为 3 的情况（长度 4 会重复输出或漏行），分组统计则天然支持任意长度；三是过滤 `people >= 100` 必须在分组**之前**做，否则会被低人流的日子把连续段截断。

### SQL 实现

```sql
WITH filtered AS (
    SELECT
        id,
        visit_date,
        people,
        id - ROW_NUMBER() OVER (ORDER BY id) AS grp
    FROM Stadium
    WHERE people >= 100
),
long_runs AS (
    SELECT grp
    FROM filtered
    GROUP BY grp
    HAVING COUNT(*) >= 3
)
SELECT
    f.id,
    f.visit_date,
    f.people
FROM filtered AS f
JOIN long_runs AS r ON r.grp = f.grp
ORDER BY f.visit_date;
```

### 复杂度分析

- 时间复杂度：O(n log n)，按 `id` 排序计算行号，再分组过滤与连接。
- 空间复杂度：O(n)，两个 CTE 都要物化中间结果。
