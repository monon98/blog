# 滚动平均步数

> 难度：中等 | 标签：窗口函数、日期函数 | [LeetCode 原题](https://leetcode.cn/problems/rolling-average-steps/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

`Steps` 表：

```
+-------------+------+
| Column Name | Type |
+-------------+------+
| user_id     | int  |
| steps_count | int  |
| steps_date  | date |
+-------------+------+
(user_id, steps_date) 是该表的主键，每一行记录某个用户某天的步数。
```

编写一个解决方案，计算每个用户的 **3 天滚动平均步数**：

- 对某一天来说，只有当「该天以及之前两天」这连续 3 天都有记录时，才能算出以该天为结束的 3 天滚动平均；否则该天不输出；
- 滚动平均为该连续 3 天步数之和除以 3，四舍五入到两位小数；
- 返回 `user_id`、`steps_date`、`rolling_average`，按 `user_id` 和 `steps_date` 升序排序。

**示例 1：**

```
输入：
Steps 表：
+---------+-------------+------------+
| user_id | steps_count | steps_date |
+---------+-------------+------------+
| 1       | 687         | 2021-09-02 |
| 1       | 395         | 2021-09-04 |
| 1       | 499         | 2021-09-05 |
| 1       | 712         | 2021-09-06 |
| 1       | 576         | 2021-09-07 |
| 2       | 153         | 2021-09-06 |
| 2       | 171         | 2021-09-07 |
| 2       | 530         | 2021-09-08 |
| 3       | 945         | 2021-09-04 |
| 3       | 120         | 2021-09-07 |
| 3       | 557         | 2021-09-08 |
| 3       | 840         | 2021-09-09 |
| 3       | 627         | 2021-09-10 |
| 5       | 382         | 2021-09-05 |
| 6       | 480         | 2021-09-01 |
| 6       | 191         | 2021-09-02 |
| 6       | 303         | 2021-09-05 |
+---------+-------------+------------+

输出：
+---------+------------+-----------------+
| user_id | steps_date | rolling_average |
+---------+------------+-----------------+
| 1       | 2021-09-06 | 535.33          |
| 1       | 2021-09-07 | 595.67          |
| 2       | 2021-09-08 | 284.67          |
| 3       | 2021-09-09 | 505.67          |
| 3       | 2021-09-10 | 674.67          |
+---------+------------+-----------------+

解释：
用户 1 在 09-03 没有记录，所以 09-04、09-05 都不满足「连续 3 天」；
09-06 这天可以取到 09-04、09-05、09-06，平均 (395 + 499 + 712) / 3 = 535.33；
09-07 取 09-05、09-06、09-07，平均 (499 + 712 + 576) / 3 = 595.67。
用户 3 的 09-07、09-08 之前缺数据，只有 09-09 与 09-10 满足条件。
```

## 题解

::: details 点击查看题解

### 思路

「3 天滚动平均」有两个条件：窗口内是连续 3 个自然日，且这 3 天都有数据。只用 `AVG(...) OVER (ROWS BETWEEN 2 PRECEDING AND CURRENT ROW)` 只能保证取到前 2 行，取不到「日期连续」：比如 user 1 缺了 2021-09-03，那么 09-05 这天的前两行是 09-02 和 09-04，算出来的是「跨了 4 天的平均」，题目要求这种情形应该直接不输出。

因此先用 `LAG(steps_date, 2)` 取「往前数第 2 行」的日期，判断它与当前日期是否正好相差 2 天：`DATEDIFF(steps_date, lag2) = 2`。成立说明中间没有断档，这 3 行恰好覆盖连续 3 天。

易错点：

- 不能用 `DATEDIFF(steps_date, LAG(steps_date, 1)) = 1` 只检查相邻两行，那样排除不掉「第 3 天缺失」的情况。
- 窗口函数的过滤条件不能写在同一层的 `WHERE` 中，要先落成 CTE/子查询再筛；本例把 `AVG`、`DATEDIFF` 都放在 CTE 里，外层只做过滤和排序。
- 一定要写 `ROWS` 帧。默认的 `RANGE 2 PRECEDING` 按「值」而不是按「行数」扩展，日期不连续时会取错行。

替代写法：用 `Steps a` 自连接 `Steps b`，条件为同用户且 `b.steps_date` 落在 `a.steps_date` 前 2 天内，再 `GROUP BY` 要求 `COUNT(*) = 3`，可读性差一些。

### SQL 实现

```sql
WITH t AS (
    SELECT user_id,
           steps_date,
           ROUND(AVG(steps_count) OVER (PARTITION BY user_id ORDER BY steps_date
                                        ROWS BETWEEN 2 PRECEDING AND CURRENT ROW), 2) AS rolling_average,
           DATEDIFF(steps_date,
                    LAG(steps_date, 2) OVER (PARTITION BY user_id ORDER BY steps_date)) = 2 AS is_consecutive
    FROM Steps
)
SELECT user_id, steps_date, rolling_average
FROM t
WHERE is_consecutive = 1
ORDER BY user_id, steps_date;
```

### 复杂度分析

- 时间复杂度：O(n log n)，n 为步数记录数，按用户和日期的窗口排序主导。
- 空间复杂度：O(n)，CTE 中保存了窗口结果。
