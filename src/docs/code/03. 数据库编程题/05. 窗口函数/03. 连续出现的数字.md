# 连续出现的数字

> 难度：中等 | 标签：窗口函数、连续区间 | [LeetCode 原题](https://leetcode.cn/problems/consecutive-numbers/)

## 题目描述

表：`Logs`

```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| id          | int     |
| num         | varchar |
+-------------+---------+
在 SQL 中，id 是该表的主键。
id 是一个自增列。
```

找出所有至少连续出现三次的数字。

返回的结果表中的数据可以按 **任意顺序** 排列。

结果格式如下面的例子所示：

**示例 1:**

```
输入：
Logs 表：
+----+-----+
| id | num |
+----+-----+
| 1  | 1   |
| 2  | 1   |
| 3  | 1   |
| 4  | 2   |
| 5  | 1   |
| 6  | 2   |
| 7  | 2   |
+----+-----+
输出：
Result 表：
+-----------------+
| ConsecutiveNums |
+-----------------+
| 1               |
+-----------------+
解释：1 是唯一连续出现至少三次的数字。
```

## 题解

::: details 点击查看题解

### 思路

要判断「某行与它前面两行的 `num` 是否相同」，用 `LAG(num, 1)` 和 `LAG(num, 2)` 一次把前两行的值取到当前行，三个值相等就说明以当前行结尾存在至少三次连续。`LAG` 按 `id` 排序，前两行不存在时返回 `NULL`，比较自然不成立，不需要额外处理边界。

结果要 `DISTINCT`：一段长度为 4 的连续数字，第 3、4 行都会满足条件，不去重就会重复输出同一个数字。

注意这里的「连续」指的是**行连续**（`id` 相邻），不是数值连续，所以按 `id` 排序取前两行是对的；传统写法是三表自连接 `l1.id + 1 = l2.id AND l2.id + 1 = l3.id`，它依赖 `id` 严格自增且无空洞，一旦 `id` 有断层就会漏判，而 `LAG` 只看行的相对顺序，更稳。也可以用 `LEAD` 往后看两行，思路对称。

### SQL 实现

```sql
WITH t AS (
    SELECT
        num,
        LAG(num, 1) OVER (ORDER BY id) AS prev_1,
        LAG(num, 2) OVER (ORDER BY id) AS prev_2
    FROM Logs
)
SELECT DISTINCT num AS ConsecutiveNums
FROM t
WHERE num = prev_1
  AND num = prev_2;
```

### 复杂度分析

- 时间复杂度：O(n log n)，按 `id` 排序后窗口扫描；`id` 有索引时接近 O(n)。
- 空间复杂度：O(n)，窗口函数需要缓存排序结果。
