# 排名靠前的旅行者

> 难度：简单 | 标签：多表连接、分组聚合 | [LeetCode 原题](https://leetcode.cn/problems/top-travellers/)

## 题目描述

表：`Users`

```
+---------------+---------+
| Column Name   | Type    |
+---------------+---------+
| id            | int     |
| name          | varchar |
+---------------+---------+
id 是该表中具有唯一值的列。
name 是用户名字。
```

表：`Rides`

```
+---------------+---------+
| Column Name   | Type    |
+---------------+---------+
| id            | int     |
| user_id       | int     |
| distance      | int     |
+---------------+---------+
id 是该表中具有唯一值的列。
user_id 是本次行程的用户的 id, 而该用户此次行程距离为 distance 。
```

编写解决方案，报告每个用户的旅行距离。

返回的结果表单，以 `travelled_distance` **降序排列** ，如果有两个或者更多的用户旅行了相同的距离, 那么再以 `name` **升序排列** 。

返回结果格式如下例所示。

**示例 1：**

```
输入：
Users 表：
+------+-----------+
| id   | name      |
+------+-----------+
| 1    | Alice     |
| 2    | Bob       |
| 3    | Alex      |
| 4    | Donald    |
| 7    | Lee       |
| 13   | Jonathan  |
| 19   | Elvis     |
+------+-----------+

Rides 表：
+------+----------+----------+
| id   | user_id  | distance |
+------+----------+----------+
| 1    | 1        | 120      |
| 2    | 2        | 317      |
| 3    | 3        | 222      |
| 4    | 7        | 100      |
| 5    | 13       | 312      |
| 6    | 19       | 50       |
| 7    | 7        | 120      |
| 8    | 19       | 400      |
| 9    | 7        | 230      |
+------+----------+----------+
输出：
+----------+--------------------+
| name     | travelled_distance |
+----------+--------------------+
| Elvis    | 450                |
| Lee      | 450                |
| Bob      | 317                |
| Jonathan | 312                |
| Alex     | 222                |
| Alice    | 120                |
| Donald   | 0                  |
+----------+--------------------+
解释：
Elvis 和 Lee 旅行了 450 英里，Elvis 是排名靠前的旅行者，因为他的名字在字母表上的排序比 Lee 更小。
Bob, Jonathan, Alex 和 Alice 只有一次行程，我们只按此次行程的全部距离对他们排序。
Donald 没有任何行程, 他的旅行距离为 0。
```

## 题解

::: details 点击查看题解

### 思路

这道题的关键是"没有行程的用户也要出现且距离为 0"，所以必须以 `Users` 为左表做 `LEFT JOIN`，内连接会把 `Donald` 直接丢掉。左连接后没有匹配行的用户 `SUM(distance)` 是 `NULL`，需要 `COALESCE` 或 `IFNULL` 转成 0，否则排序和输出都会出现 `NULL`。

分组键要用 `Users.id`（或 `id, name` 一起），不能用 `name`：真实数据里完全可能重名，按名字分组会把两个不同的人合并成一行。排序是 `travelled_distance` 降序、`name` 升序，正好对应示例里 `Elvis` 排在 `Lee` 前面。

替代写法：先在 `Rides` 里 `GROUP BY user_id` 算出每个人的总距离，再 `RIGHT JOIN` 回 `Users`，效果一样，但 `LEFT JOIN + 聚合` 一条语句就够，可读性更好。

### SQL 实现

```sql
SELECT u.name,
       COALESCE(SUM(r.distance), 0) AS travelled_distance
FROM Users u
LEFT JOIN Rides r ON r.user_id = u.id
GROUP BY u.id, u.name
ORDER BY travelled_distance DESC, u.name ASC;
```

### 复杂度分析

- 时间复杂度：O(n + m + k log k)，n、m 为两张表的行数，k 为用户数（排序开销）。
- 空间复杂度：O(k)，保存每个用户的累计距离。

:::
