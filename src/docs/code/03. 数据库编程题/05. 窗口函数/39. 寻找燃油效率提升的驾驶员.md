# 寻找燃油效率提升的驾驶员

> 难度：中等 | 标签：条件聚合、日期函数 | [LeetCode 原题](https://leetcode.cn/problems/find-drivers-with-improved-fuel-efficiency/)

## 题目描述

表：`drivers`

```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| driver_id   | int     |
| driver_name | varchar |
+-------------+---------+
driver_id 是这张表的唯一主键。
每一行都包含一个司机的信息。
```

表：`trips`

```
+---------------+---------+
| Column Name   | Type    |
+---------------+---------+
| trip_id       | int     |
| driver_id     | int     |
| trip_date     | date    |
| distance_km   | decimal |
| fuel_consumed | decimal |
+---------------+---------+
trip_id 是这张表的唯一主键。
每一行表示一名司机完成的一次行程，包括该次行程行驶的距离和消耗的燃油量。
```

编写一个解决方案，通过 **比较** 司机在 **上半年** 和 **下半年** 的 **平均燃油效率** 来找出 **燃油效率有所提高** 的司机。

	- 通过 distance_km / fuel_consumed 计算 每次 行程的 燃油效率。

	- 上半年：一月到六月，下半年：七月到十二月

	- 只包含在上半年和下半年都有行程的司机

	- 通过（second_half_avg - first_half_avg）计算 提升效率。

	- 将所有结果 四舍五入 到小数点后 2 位

返回结果表按提升效率 **降序** 排列，然后按司机姓名 **升序** 排列。

结果格式如下所示。

## 题解

::: details 点击查看题解

### 思路

统计粒度是「司机」，但每一行 `trips` 只代表一次行程，所以要先在司机维度上把行程分成上半年、下半年两池。最省事的写法是一次分组 + 条件聚合：`AVG(CASE WHEN MONTH(trip_date) <= 6 THEN 效率 END)` 只对上半年的行求平均，另一半同理。比起「两次子查询各算一半再 JOIN」，这样只扫一遍表，也不用处理外连接。

要让 `CASE` 没有命中时返回 `NULL` 而不是 `0`：`AVG` 会跳过 `NULL`，于是某一半完全没有行程时该列自然是 `NULL`，再用 `IS NOT NULL` 两个条件就能精准实现「上下半年都有行程」这个过滤。如果把 `ELSE 0` 写进去，只有半年数据的司机就会被算出一个虚假的均值，进而混进结果里。

第三个坑是舍入顺序。提升量要用**未舍入**的平均值相减、最后再 `ROUND`，先舍入再相减会因为两处各差 0.005 而使结果偏 0.01（例如 14.02 - 11.97 = 2.05，与真值 2.0507 舍入后一致，但换成别的数据就可能不一致）。排序直接引用别名：先按 `efficiency_improvement` 降序，再按 `driver_name` 升序，避免并列时顺序漂移。

替代写法：用窗口函数 `AVG(distance_km / fuel_consumed) OVER (PARTITION BY driver_id, MONTH(trip_date) <= 6)` 先算出行级均值再 `DISTINCT` 去重，逻辑更啰嗦且要去重，本题条件聚合更直接。

### SQL 实现

```sql
WITH t AS (
    SELECT driver_id,
           AVG(CASE WHEN MONTH(trip_date) <= 6 THEN distance_km / fuel_consumed END) AS first_half_avg,
           AVG(CASE WHEN MONTH(trip_date) >= 7 THEN distance_km / fuel_consumed END) AS second_half_avg
    FROM trips
    GROUP BY driver_id
)
SELECT d.driver_id,
       d.driver_name,
       ROUND(t.first_half_avg, 2)                        AS first_half_avg,
       ROUND(t.second_half_avg, 2)                       AS second_half_avg,
       ROUND(t.second_half_avg - t.first_half_avg, 2)    AS efficiency_improvement
FROM t
JOIN drivers d ON d.driver_id = t.driver_id
WHERE t.first_half_avg IS NOT NULL
  AND t.second_half_avg IS NOT NULL
  AND t.second_half_avg > t.first_half_avg
ORDER BY efficiency_improvement DESC, d.driver_name ASC;
```

### 复杂度分析

- 时间复杂度：O(n)，n 为行程数，一次扫描 + 一次哈希分组；结果排序为 O(k log k)，k 为司机数。
- 空间复杂度：O(k)，存放每个司机的两个均值。
