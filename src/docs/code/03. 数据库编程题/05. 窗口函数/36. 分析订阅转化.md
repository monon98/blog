# 分析订阅转化

> 难度：中等 | 标签：条件聚合、分组聚合 | [LeetCode 原题](https://leetcode.cn/problems/analyze-subscription-conversion/)

## 题目描述

表：`UserActivity`

```
+------------------+---------+
| Column Name      | Type    |
+------------------+---------+
| user_id          | int     |
| activity_date    | date    |
| activity_type    | varchar |
| activity_duration| int     |
+------------------+---------+
(user_id, activity_date, activity_type) 是这张表的唯一主键。
activity_type 是('free_trial', 'paid', 'cancelled')中的一个。
activity_duration 是用户当天在平台上花费的分钟数。
每一行表示一个用户在特定日期的活动。
```

订阅服务想要分析用户行为模式。公司提供7天免费试用，试用结束后，用户可以选择订阅 **付费计划** 或 **取消**。编写解决方案：

	- 查找从免费试用转为付费订阅的用户

	- 计算每位用户在 免费试用 期间的 平均每日活动时长（四舍五入至小数点后 2 位）

	- 计算每位用户在 付费 订阅期间的 平均每日活动时长（四舍五入到小数点后 2 位）

返回结果表以* *`user_id`* ***升序 **排序。

结果格式如下所示。

示例：

**输入：**

UserActivity 表：

+---------+---------------+---------------+-------------------+
| user_id | activity_date | activity_type | activity_duration |
+---------+---------------+---------------+-------------------+
| 1       | 2023-01-01    | free_trial    | 45                |
| 1       | 2023-01-02    | free_trial    | 30                |
| 1       | 2023-01-05    | free_trial    | 60                |
| 1       | 2023-01-10    | paid          | 75                |
| 1       | 2023-01-12    | paid          | 90                |
| 1       | 2023-01-15    | paid          | 65                |
| 2       | 2023-02-01    | free_trial    | 55                |
| 2       | 2023-02-03    | free_trial    | 25                |
| 2       | 2023-02-07    | free_trial    | 50                |
| 2       | 2023-02-10    | cancelled     | 0                 |
| 3       | 2023-03-05    | free_trial    | 70                |
| 3       | 2023-03-06    | free_trial    | 60                |
| 3       | 2023-03-08    | free_trial    | 80                |
| 3       | 2023-03-12    | paid          | 50                |
| 3       | 2023-03-15    | paid          | 55                |
| 3       | 2023-03-20    | paid          | 85                |
| 4       | 2023-04-01    | free_trial    | 40                |
| 4       | 2023-04-03    | free_trial    | 35                |
| 4       | 2023-04-05    | paid          | 45                |
| 4       | 2023-04-07    | cancelled     | 0                 |
+---------+---------------+---------------+-------------------+

**输出：**

+---------+--------------------+-------------------+
| user_id | trial_avg_duration | paid_avg_duration |
+---------+--------------------+-------------------+
| 1       | 45.00              | 76.67             |
| 3       | 70.00              | 63.33             |
| 4       | 37.50              | 45.00             |
+---------+--------------------+-------------------+

**解释：**

	- 用户 1:

		体验了 3 天免费试用，时长分别为 45，30 和 60 分钟。

		- 平均试用时长：(45 + 30 + 60) / 3 = 45.00 分钟。

		- 拥有 3 天付费订阅，时长分别为 75，90 和 65分钟。

		- 平均花费时长：(75 + 90 + 65) / 3 = 76.67 分钟。

	- 用户 2:

		体验了 3 天免费试用，时长分别为 55，25 和 50 分钟。

		- 平均试用时长：(55 + 25 + 50) / 3 = 43.33 分钟。

		- 没有转为付费订阅（只有 free_trial 和 cancelled 活动）。

		- 未包含在输出中，因为他未转换为付费用户。

	- 用户 3:

		体验了 3 天免费试用，时长分别为 70，60 和 80 分钟。

		- 平均试用时长：(70 + 60 + 80) / 3 = 70.00 分钟。

		- 拥有 3 天付费订阅，时长分别为 50，55 和 85 分钟。

		- 平均花费时长：(50 + 55 + 85) / 3 = 63.33 分钟。

	- 用户 4:

		体验了 2 天免费试用，时长分别为 40 和 35 分钟。

		- 平均试用时长：(40 + 35) / 2 = 37.50 分钟。

		- 在取消前有 1 天的付费订阅，时长为45分钟。

		- 平均花费时长：45.00 分钟。

结果表仅包括从免费试用转为付费订阅的用户（用户 1，3 和 4），并且以 user_id 升序排序。

## 题解

::: details 点击查看题解

### 思路

同一张表里既有 `free_trial` 也有 `paid` 活动，用条件聚合最直接：`AVG(CASE WHEN activity_type = 'free_trial' THEN activity_duration END)` 只在试用行上求平均，`paid` 同理。`CASE` 不写 `ELSE` 时其余行返回 `NULL`，而 `AVG` 会忽略 `NULL`，正好实现「分组内只对某类活动求均值」。

「从免费试用转为付费」用 `HAVING` 判断该用户是否两类活动都存在：`SUM(activity_type = 'paid') > 0 AND SUM(activity_type = 'free_trial') > 0`。示例里用户 2 只有 `free_trial` 和 `cancelled`，因此被排除。

易错点：

- `cancelled` 行的 `activity_duration` 虽然是 0，但绝不能进入付费均值。条件聚合天然排除它；如果写成 `AVG(activity_duration)` 全量平均就错了。
- 分母是「该类活动有记录的日期数」，不是固定的 7 天试用期，题目要的就是按实际记录求平均。
- `ROUND(..., 2)` 要作用在平均值上，别漏；`AVG` 的返回值是十进制，`ROUND` 后仍是两位小数。
- 输出按 `user_id` 升序。

替代写法：分别用两个子查询算出试用均值和付费均值，再按 `user_id` 内连接，逻辑清晰但要扫两遍表。

### SQL 实现

```sql
SELECT user_id,
       ROUND(AVG(CASE WHEN activity_type = 'free_trial' THEN activity_duration END), 2) AS trial_avg_duration,
       ROUND(AVG(CASE WHEN activity_type = 'paid' THEN activity_duration END), 2) AS paid_avg_duration
FROM UserActivity
GROUP BY user_id
HAVING SUM(activity_type = 'paid') > 0
   AND SUM(activity_type = 'free_trial') > 0
ORDER BY user_id;
```

### 复杂度分析

- 时间复杂度：O(n)，n 为活动记录数，一次分组聚合。
- 空间复杂度：O(1)，每个用户只保存两个平均值。
