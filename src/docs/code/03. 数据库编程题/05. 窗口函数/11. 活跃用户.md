# 活跃用户

> 难度：中等 | 标签：窗口函数、日期函数 | [LeetCode 原题](https://leetcode.cn/problems/active-users/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

表 `Accounts`：

```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| id          | int     |
| name        | varchar |
+-------------+---------+
id 是该表的主键，name 是账户名称。
```

表 `Logins`：

```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| id          | int     |
| login_date  | date    |
+-------------+---------+
该表记录每个账户的登录日期，同一个账户同一天可能有多条登录记录（重复行）。
```

要求：找出**连续登录天数达到 5 天及以上**的所有账户，返回 `id`、`name` 两列，按 `id` 升序排列。

**示例 1：**

```
输入：
Accounts 表：
+----+----------+
| id | name     |
+----+----------+
| 1  | Winston  |
| 7  | Jonathan |
+----+----------+

Logins 表：
+----+------------+
| id | login_date |
+----+------------+
| 7  | 2020-05-30 |
| 1  | 2020-05-30 |
| 7  | 2020-05-31 |
| 7  | 2020-06-01 |
| 7  | 2020-06-02 |
| 7  | 2020-06-02 |
| 7  | 2020-06-03 |
| 1  | 2020-06-07 |
| 7  | 2020-06-10 |
+----+------------+
输出：
+----+----------+
| id | name     |
+----+----------+
| 7  | Jonathan |
+----+----------+
解释：
账户 7 在 2020-05-30 到 2020-06-03 连续登录了 5 天（06-02 的重复记录不算新的一天），因此是活跃账户；
账户 1 只在 05-30 和 06-07 登录，没有连续 5 天，被排除。
```

## 题解

::: details 点击查看题解

### 思路

"连续 N 天"是一类固定套路：先对每个用户按日期排序并打上行号，再用 `login_date - 行号` 造一个分组键。日期每往后一天行号也加一，所以同一段连续日期得到的差值完全相同；一旦中间断档，行号跟不上日期的跳变，差值立刻变化，天然把连续段切开。最后在"用户 + 分组键"上 `COUNT(*) >= 5` 就筛出连续登录 5 天以上的用户。

两个坑必须避开。第一，同一天可能有重复登录（示例里账户 7 在 06-02 有两条），不先去重行号就会错位，连续段会被错误判断；所以要 `SELECT DISTINCT id, login_date`。第二，不能把窗口函数直接塞进 `INTERVAL` 表达式（`DATE_SUB(login_date, INTERVAL ROW_NUMBER() OVER (...) DAY)` 在 MySQL 里是语法错），必须用多层 CTE 把行号先物化出来。

最后用 `IN` 子查询而不是再 `JOIN` 一次 `Logins`，因为一个用户可能有多段"连续 5 天"，直接连接会让输出出现重复行。

### SQL 实现

```sql
WITH daily AS (
    SELECT DISTINCT id, login_date
    FROM Logins
),
numbered AS (
    SELECT id, login_date,
           ROW_NUMBER() OVER (PARTITION BY id ORDER BY login_date) AS rn
    FROM daily
),
grouped AS (
    SELECT id, DATE_SUB(login_date, INTERVAL rn DAY) AS grp
    FROM numbered
),
active AS (
    SELECT id
    FROM grouped
    GROUP BY id, grp
    HAVING COUNT(*) >= 5
)
SELECT a.id, a.name
FROM Accounts a
WHERE a.id IN (SELECT id FROM active)
ORDER BY a.id;
```

### 复杂度分析

- 时间复杂度：O(n log n)，去重与窗口排序占主导。
- 空间复杂度：O(n)，需要保存去重后的登录记录与分组键。
