# 找到第三笔交易

> 难度：中等 | 标签：窗口函数、LAG | [LeetCode 原题](https://leetcode.cn/problems/find-third-transaction/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

`Transactions` 表：

```
+------------------+----------+
| Column Name      | Type     |
+------------------+----------+
| user_id          | int      |
| spend            | decimal  |
| transaction_date | datetime |
+------------------+----------+
(user_id, transaction_date) 具有唯一值，每一行表示某个用户的一笔交易金额与交易时间。
```

编写一个查询，找出满足条件的用户的 **第三笔交易**（按 `transaction_date` 升序计数）：

- 该用户至少有 3 笔交易；
- 第三笔交易的 `spend` 严格大于前两笔交易的 `spend`；
- 返回 `user_id`、`third_transaction_spend`（第三笔金额）、`third_transaction_date`（第三笔时间），按 `user_id` 升序排序。

**示例 1：**

```
输入：
Transactions 表：
+---------+--------+---------------------+
| user_id | spend  | transaction_date    |
+---------+--------+---------------------+
| 1       | 65.56  | 2023-11-18 13:49:42 |
| 1       | 96.0   | 2023-11-30 02:47:26 |
| 1       | 7.44   | 2023-11-02 12:15:23 |
| 1       | 49.78  | 2023-11-12 00:13:46 |
| 2       | 40.89  | 2023-11-21 04:39:15 |
| 2       | 100.44 | 2023-11-20 07:39:34 |
| 3       | 37.33  | 2023-11-03 06:22:02 |
| 3       | 13.89  | 2023-11-11 16:00:14 |
| 3       | 7.0    | 2023-11-29 22:32:36 |
+---------+--------+---------------------+

输出：
+---------+-------------------------+------------------------+
| user_id | third_transaction_spend | third_transaction_date |
+---------+-------------------------+------------------------+
| 1       | 65.56                   | 2023-11-18 13:49:42    |
+---------+-------------------------+------------------------+

解释：
用户 1 按时间排序的三笔交易为 11-02（7.44）、11-12（49.78）、11-18（65.56），第三笔 65.56 大于前两笔，符合条件；
用户 2 只有 2 笔交易，没有第三笔；
用户 3 的第三笔是 11-29 的 7.00，小于前两笔，不符合条件。
```

## 题解

::: details 点击查看题解

### 思路

「第三笔交易」用 `ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY transaction_date)` 编号，筛 `rn = 3` 即可。题目还额外要求第三笔金额严格大于前两笔，于是用 `LAG(spend, 1)`、`LAG(spend, 2)` 把前两笔金额拉到同一行直接比较。

易错点：

- 排序键必须是 `transaction_date`。表里的插入顺序与时间顺序完全不一致（user 1 的第一行反而是第三笔），按行号或插入顺序取一定错。
- 条件要写全「第三笔 > 第一笔且第三笔 > 第二笔」。示例中 user 3 的第三笔只有 7.00，比前两笔都小，被正确过滤；user 2 不足三笔，`LAG` 为 `NULL`、`rn` 也不等于 3，自然不会出现。
- `LAG` 的默认偏移是 1，`LAG(spend) OVER w` 等价于 `LAG(spend, 1) OVER w`；用 `WINDOW w AS (...)` 可以少写两遍 `PARTITION BY ... ORDER BY ...`。
- 输出的列名要求是 `third_transaction_spend`、`third_transaction_date`，需要起别名。

替代写法：`ROW_NUMBER` 之后自连接两次取前两笔，逻辑直观但要扫多遍表，且条件写成连接条件时容易漏掉严格大于。

### SQL 实现

```sql
WITH t AS (
    SELECT user_id, spend, transaction_date,
           ROW_NUMBER() OVER w AS rn,
           LAG(spend, 1) OVER w AS prev1,
           LAG(spend, 2) OVER w AS prev2
    FROM Transactions
    WINDOW w AS (PARTITION BY user_id ORDER BY transaction_date)
)
SELECT user_id,
       spend AS third_transaction_spend,
       transaction_date AS third_transaction_date
FROM t
WHERE rn = 3
  AND spend > prev1
  AND spend > prev2
ORDER BY user_id;
```

### 复杂度分析

- 时间复杂度：O(n log n)，n 为交易数，按用户和交易时间排序主导。
- 空间复杂度：O(n)，CTE 中保存了带行号和前值的所有行。
