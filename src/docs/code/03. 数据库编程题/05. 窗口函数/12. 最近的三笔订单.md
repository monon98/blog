# 最近的三笔订单

> 难度：中等 | 标签：窗口函数、多表连接 | [LeetCode 原题](https://leetcode.cn/problems/the-most-recent-three-orders/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

表 `Customers`：

```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| customer_id | int     |
| name        | varchar |
+-------------+---------+
customer_id 是该表的主键，name 是顾客姓名。
```

表 `Orders`：

```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| order_id    | int     |
| order_date  | date    |
| customer_id | int     |
| cost        | int     |
+-------------+---------+
order_id 是该表的主键，customer_id 指向下单的顾客。
```

要求：对每个**下过订单**的顾客，找出其最近的 3 笔订单。返回 `customer_name`、`customer_id`、`order_id`、`order_date` 四列，按 `customer_name` 升序、`customer_id` 升序、`order_date` 降序排列。订单不足 3 笔的顾客只返回已有的订单，没有任何订单的顾客不出现。

**示例 1：**

```
输入：
Customers 表：
+-------------+-----------+
| customer_id | name      |
+-------------+-----------+
| 1           | Winston   |
| 2           | Jonathan  |
| 3           | Annabelle |
| 4           | Marwan    |
| 5           | Khaled    |
+-------------+-----------+

Orders 表：
+----------+------------+-------------+------+
| order_id | order_date | customer_id | cost |
+----------+------------+-------------+------+
| 1        | 2020-07-31 | 1           | 30   |
| 2        | 2020-07-30 | 2           | 40   |
| 3        | 2020-07-31 | 3           | 70   |
| 4        | 2020-07-29 | 4           | 100  |
| 5        | 2020-06-10 | 1           | 1010 |
| 6        | 2020-08-01 | 2           | 102  |
| 7        | 2020-08-01 | 3           | 111  |
| 8        | 2020-08-03 | 1           | 99   |
| 9        | 2020-08-07 | 2           | 32   |
| 10       | 2020-07-15 | 1           | 2    |
+----------+------------+-------------+-----------+
输出：
+---------------+-------------+----------+------------+
| customer_name | customer_id | order_id | order_date |
+---------------+-------------+----------+------------+
| Annabelle     | 3           | 7        | 2020-08-01 |
| Annabelle     | 3           | 3        | 2020-07-31 |
| Jonathan      | 2           | 9        | 2020-08-07 |
| Jonathan      | 2           | 6        | 2020-08-01 |
| Jonathan      | 2           | 2        | 2020-07-30 |
| Marwan        | 4           | 4        | 2020-07-29 |
| Winston       | 1           | 8        | 2020-08-03 |
| Winston       | 1           | 1        | 2020-07-31 |
| Winston       | 1           | 10       | 2020-07-15 |
+---------------+-------------+----------+------------+
解释：
Winston 共 4 笔订单，最近的 3 笔是 08-03、07-31、07-15；Annabelle 与 Marwan 订单不足 3 笔，全部返回；Khaled 没有订单，不出现在结果里。
```

## 题解

::: details 点击查看题解

### 思路

"每个分组取前 k 条"的标准解法是 `ROW_NUMBER()`：按 `customer_id` 分区、`order_date` 倒序编号，再筛 `rn <= 3`。这里用 `ROW_NUMBER` 而不是 `RANK` 是有意的——同一顾客如果有多笔订单落在同一天，`RANK` 会让并列的名次一起进入前 3，结果可能超过 3 行；`ROW_NUMBER` 保证每个顾客最多 3 行。真要处理同日并列，可以在窗口里再补一个 `order_id DESC` 让顺序确定下来。

第二个要点是"没有订单的顾客不出现"。因为筛选条件写在窗口编号之后，`JOIN Customers` 用内连接即可自然排除；如果写成 `LEFT JOIN` 再过滤 `rn <= 3`，`rn` 为 `NULL` 的行依然会被 `NULL <= 3` 判为未知而剔除，效果相同，但内连接语义更清楚。

排序容易写错：题目要求 `customer_name` 在前，`customer_id` 次之，最后才是 `order_date` 降序，而窗口里的排序键是 `order_date` 降序。注意窗口函数的 `ORDER BY` 只在计算名次时生效，不影响最终输出顺序，最终顺序必须在外层 `ORDER BY` 里重新声明。

### SQL 实现

```sql
WITH ranked AS (
    SELECT order_id, order_date, customer_id,
           ROW_NUMBER() OVER (PARTITION BY customer_id ORDER BY order_date DESC) AS rn
    FROM Orders
)
SELECT c.name AS customer_name,
       r.customer_id,
       r.order_id,
       r.order_date
FROM ranked r
JOIN Customers c ON c.customer_id = r.customer_id
WHERE r.rn <= 3
ORDER BY customer_name ASC, r.customer_id ASC, r.order_date DESC;
```

### 复杂度分析

- 时间复杂度：O(n log n)，窗口排序主导，n 为订单数。
- 空间复杂度：O(n)，需要保存带名次的订单。

:::
