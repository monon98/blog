# 查找得分最高的学生

> 难度：中等 | 标签：多表连接、分组聚合 | [LeetCode 原题](https://leetcode.cn/problems/find-top-scoring-students/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

`students` 表：

```
+-------------+----------+
| Column Name | Type     |
+-------------+----------+
| student_id  | int      |
| name        | varchar  |
| major       | varchar  |
+-------------+----------+
student_id 是主键，每一行包含学生 ID、姓名和专业。
```

`courses` 表：

```
+-------------+----------+
| Column Name | Type     |
+-------------+----------+
| course_id   | int      |
| name        | varchar  |
| credits     | int      |
| major       | varchar  |
+-------------+----------+
course_id 是主键，每一行包含课程 ID、课程名、学分以及该课程所属专业。
```

`enrollments` 表：

```
+-------------+----------+
| Column Name | Type     |
+-------------+----------+
| student_id  | int      |
| course_id   | int      |
| semester    | varchar  |
| grade       | varchar  |
+-------------+----------+
(student_id, course_id, semester) 是主键，每一行表示某学生在某学期修读某课程的成绩。
```

编写一个解决方案，找出 **修完本专业开设的全部课程、并且这些课程全部拿到 A** 的学生。返回 `student_id`，按 `student_id` 升序排序。

**示例 1：**

```
输入：
students 表：
+------------+---------+------------------+
| student_id | name    | major            |
+------------+---------+------------------+
| 1          | Alice   | Computer Science |
| 2          | Bob     | Computer Science |
| 3          | Charlie | Mathematics      |
| 4          | David   | Mathematics      |
+------------+---------+------------------+

courses 表：
+-----------+-----------------+---------+------------------+
| course_id | name            | credits | major            |
+-----------+-----------------+---------+------------------+
| 101       | Algorithms      | 3       | Computer Science |
| 102       | Data Structures | 3       | Computer Science |
| 103       | Calculus        | 4       | Mathematics      |
| 104       | Linear Algebra  | 4       | Mathematics      |
+-----------+-----------------+---------+------------------+

enrollments 表：
+------------+-----------+-----------+-------+
| student_id | course_id | semester  | grade |
+------------+-----------+-----------+-------+
| 1          | 101       | Fall 2023 | A     |
| 1          | 102       | Fall 2023 | A     |
| 2          | 101       | Fall 2023 | B     |
| 2          | 102       | Fall 2023 | A     |
| 3          | 103       | Fall 2023 | A     |
| 3          | 104       | Fall 2023 | A     |
| 4          | 103       | Fall 2023 | A     |
| 4          | 104       | Fall 2023 | B     |
+------------+-----------+-----------+-------+

输出：
+------------+
| student_id |
+------------+
| 1          |
| 3          |
+------------+

解释：
Alice 修完了本专业全部两门课并且都是 A；
Bob 的 Algorithms 只有 B，不符合；
Charlie 修完了数学专业全部两门课并且都是 A；
David 的 Linear Algebra 只有 B，不符合。
```

## 题解

::: details 点击查看题解

### 思路

「本专业所有课程都拿到 A」需要把「应修课程清单」和「实际成绩」对齐：从 `students` 出发，按 `major` 连接 `courses` 得到每个学生本专业应修的全部课程，再 `LEFT JOIN enrollments` 把成绩贴上去。

用 `LEFT JOIN` 而不是 `INNER JOIN` 是关键。若某学生没修本专业的某门课，内连接会把这门课整行丢掉，他反而「看起来」全 A；左连接保留这门课，只是 `grade` 为 `NULL`，`SUM(grade = 'A')` 不会把它算进去，于是 `SUM(...) = COUNT(...)` 不成立，学生被正确排除。

`HAVING SUM(e.grade = 'A') = COUNT(c.major)` 的含义是「拿到 A 的本专业课程数 = 本专业课程总数」，同时也隐含了「至少修过一门」，因此不需要再写额外的计数条件。

易错点：

- `SUM(grade = 'A')` 中 `grade` 为 `NULL` 时表达式结果是 `NULL`，`SUM` 会忽略它（等价于计 0），符合预期；如果改用 `COUNT(grade = 'A')` 就会把 `NULL` 也算一行，逻辑完全不同。
- 同一门课若学生在多个学期修过（表里 `semester` 也在主键中），左连接会产出多行，`COUNT(c.major)` 随之变大，结果可能出错。严谨写法是 `COUNT(DISTINCT c.course_id)` 配 `COUNT(DISTINCT CASE WHEN e.grade = 'A' THEN c.course_id END)`；本题每门课只有一条记录，简单写法足够。

### SQL 实现

```sql
SELECT s.student_id
FROM students s
JOIN courses c ON c.major = s.major
LEFT JOIN enrollments e
       ON e.student_id = s.student_id
      AND e.course_id = c.course_id
GROUP BY s.student_id
HAVING SUM(e.grade = 'A') = COUNT(c.major)
ORDER BY s.student_id;
```

### 复杂度分析

- 时间复杂度：O(n + m)，n 为学生与课程的组合数，m 为选课记录数，连接后可一次扫描聚合。
- 空间复杂度：O(1)，按学生分组保存计数。
