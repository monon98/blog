# 产品销售分析 IV

> 难度：中等 | 标签：窗口函数、分组聚合 | [LeetCode 原题](https://leetcode.cn/problems/product-sales-analysis-iv/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

表 `Sales`：

```
+-------------+------+
| Column Name | Type |
+-------------+------+
| sale_id     | int  |
| product_id  | int  |
| user_id     | int  |
| quantity    | int  |
+-------------+------+
sale_id 是该表的主键，每行表示某位用户购买了某个商品的数量。
```

表 `Product`：

```
+-------------+------+
| Column Name | Type |
+-------------+------+
| product_id  | int  |
| price       | int  |
+-------------+------+
product_id 是该表的主键，price 是该商品的单价。
```

要求：报告每位用户**花钱最多**的商品，如果同一位用户在多个商品上花费并列最多，则把这些商品全部返回。返回 `user_id`、`product_id` 两列，顺序任意。

**示例 1：**

```
输入：
Sales 表：
+---------+------------+---------+----------+
| sale_id | product_id | user_id | quantity |
+---------+------------+---------+----------+
| 1       | 1          | 101     | 10       |
| 2       | 3          | 101     | 7        |
| 3       | 1          | 102     | 9        |
| 4       | 2          | 102     | 6        |
| 5       | 3          | 102     | 10       |
| 6       | 1          | 102     | 6        |
+---------+------------+---------+----------+

Product 表：
+------------+-------+
| product_id | price |
+------------+-------+
| 1          | 10    |
| 2          | 25    |
| 3          | 15    |
+------------+-------+
输出：
+---------+------------+
| user_id | product_id |
+---------+------------+
| 101     | 3          |
| 102     | 1          |
| 102     | 2          |
| 102     | 3          |
+---------+------------+
解释：
用户 101：商品 1 花费 10*10 = 100，商品 3 花费 7*15 = 105，最贵是商品 3；
用户 102：商品 1 花费 (9+6)*10 = 150，商品 2 花费 6*25 = 150，商品 3 花费 10*15 = 150，三者并列，全部返回。
```

## 题解

::: details 点击查看题解

### 思路

花费是按商品累计的：同一个用户可能多次购买同一商品（用户 102 买了两次商品 1），必须先按 `(user_id, product_id)` 把 `quantity * price` 求和，才能比较"每个商品花了多少钱"。按单笔金额排序是常见错误，那样用户 102 只会剩下 150 的两笔而不是按商品汇总。

第二层是组内排名取第一。因为题目要求"并列全部返回"，必须用 `RANK()` 而不是 `ROW_NUMBER()`：示例里用户 102 的三个商品都是 150，`RANK` 让三行都拿到第 1 名，`ROW_NUMBER` 只会留一行。

坑点：价格来自 `Product`，要先连接再聚合，不能拿 `quantity` 当金额；`RANK` 在并列后会跳号（1、1、3），但这里只取 `rk = 1`，不受影响。替代写法：用 `(user_id, 汇总花费) IN (SELECT ...)` 再关联一次，或用 `MAX(total) GROUP BY user_id` 做半连接，都不如窗口函数一次排序干净。

### SQL 实现

```sql
WITH spending AS (
    SELECT s.user_id, s.product_id,
           SUM(s.quantity * p.price) AS total
    FROM Sales s
    JOIN Product p ON p.product_id = s.product_id
    GROUP BY s.user_id, s.product_id
),
ranked AS (
    SELECT user_id, product_id,
           RANK() OVER (PARTITION BY user_id ORDER BY total DESC) AS rk
    FROM spending
)
SELECT user_id, product_id
FROM ranked
WHERE rk = 1
ORDER BY user_id, product_id;
```

### 复杂度分析

- 时间复杂度：O(n log n)，分组聚合加窗口排序。
- 空间复杂度：O(m)，m 为用户与商品组合的数量。

:::
