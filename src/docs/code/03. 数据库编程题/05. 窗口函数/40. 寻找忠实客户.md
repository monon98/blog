# 寻找忠实客户

> 难度：中等 | 标签：分组聚合、HAVING、日期函数 | [LeetCode 原题](https://leetcode.cn/problems/find-loyal-customers/)

## 题目描述

表：`customer_transactions`

```
+------------------+---------+
| Column Name      | Type    |
+------------------+---------+
| transaction_id   | int     |
| customer_id      | int     |
| transaction_date | date    |
| amount           | decimal |
| transaction_type | varchar |
+------------------+---------+
transaction_id 是这张表的唯一主键。
transaction_type 可以是 “purchase” 或 “refund”。
```

编写一个解决方案来查找 **忠实客户**。如果满足下述所有条件，可以认为该客户是 **忠实** 客户：

	- 进行了 至少 3 次购买交易。

	- 活跃了 至少 30 天。

	- 他们的 退款率 少于 20%。

退款率是退款交易占交易总数（购买加退款）的比例，计算公式为退款交易数量除以总交易数量。

返回结果表以 `customer_id` **升序** 排序。

结果格式如下所示。

## 题解

::: details 点击查看题解

### 思路

三个条件都是「按客户的汇总指标」，天然就是 `GROUP BY customer_id` + `HAVING` 的形态，不需要先做子查询再回表，一条扫描就能判完。

三个指标各自的写法值得注意：购买次数用 `SUM(transaction_type = 'purchase')`——MySQL 里布尔值就是 0/1，求和即计数；活跃天数用 `DATEDIFF(MAX(transaction_date), MIN(transaction_date))`，注意题目说的「活跃了 30 天」在示例里是按**首末日期之差**算的（1 月 5 日到 2 月 20 日记为 46 天），所以不要再 `+1`，否则边界数据会误判；退款率是退款笔数除以**总笔数**（含退款），而不是除以购买笔数——客户 102 若按购买笔数算 2/3 = 66%，两种口径都不合格，但客户 104 按总笔数算 1/6 = 16.67% 才刚好过关，用错分母最容易在这里翻车。

还有一个容易忽略的点：`/` 在 MySQL 中是真除法，会返回小数，不必像某些方言那样担心整数截断（`1/6` 得 0）；但反过来，如果你写的是 `CAST` 或整除函数就要小心。此外 `HAVING` 里可以复用聚合表达式，也可写成 `SUM(refund) / COUNT(*) < 0.2`，二者等价。

替代写法：把三个指标写成三个 `SUM(CASE WHEN ...)`，或者用窗口函数 `COUNT(...) OVER (PARTITION BY customer_id)` 算好再 `DISTINCT` 去重——分组聚合仍然是最简洁的。

### SQL 实现

```sql
SELECT customer_id
FROM customer_transactions
GROUP BY customer_id
HAVING SUM(transaction_type = 'purchase') >= 3
   AND DATEDIFF(MAX(transaction_date), MIN(transaction_date)) >= 30
   AND SUM(transaction_type = 'refund') / COUNT(*) < 0.2
ORDER BY customer_id;
```

### 复杂度分析

- 时间复杂度：O(n)，n 为交易行数，一次扫描 + 哈希分组。
- 空间复杂度：O(k)，k 为客户数。
