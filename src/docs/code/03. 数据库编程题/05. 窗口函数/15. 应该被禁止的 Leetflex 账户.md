# 应该被禁止的 Leetflex 账户

> 难度：中等 | 标签：自连接、区间重叠判定 | [LeetCode 原题](https://leetcode.cn/problems/leetflex-banned-accounts/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

表 `LogInfo`：

```
+-------------+----------+
| Column Name | Type     |
+-------------+----------+
| account_id  | int      |
| ip_address  | int      |
| login       | datetime |
| logout      | datetime |
+-------------+----------+
该表没有主键，可能包含重复行。
表里记录每个账户一次登录的 IP、登录时间与登出时间，且保证 logout 晚于 login。
```

要求：找出**同一时刻从两个不同 IP 登录**的账户（即两条记录的登录时间段有交集，端点相接也算交集），返回不重复的 `account_id`。结果顺序任意。

**示例 1：**

```
输入：
LogInfo 表：
+------------+------------+---------------------+---------------------+
| account_id | ip_address | login               | logout              |
+------------+------------+---------------------+---------------------+
| 1          | 1          | 2021-02-01 09:00:00 | 2021-02-01 09:30:00 |
| 1          | 2          | 2021-02-01 08:00:00 | 2021-02-01 11:30:00 |
| 2          | 6          | 2021-02-01 20:30:00 | 2021-02-01 22:00:00 |
| 2          | 7          | 2021-02-02 20:30:00 | 2021-02-02 22:00:00 |
| 3          | 9          | 2021-02-01 16:00:00 | 2021-02-01 16:59:59 |
| 3          | 13         | 2021-02-01 17:00:00 | 2021-02-01 17:59:59 |
| 4          | 10         | 2021-02-01 16:00:00 | 2021-02-01 17:00:00 |
| 4          | 11         | 2021-02-01 17:00:00 | 2021-02-01 17:59:59 |
+------------+------------+---------------------+---------------------+
输出：
+------------+
| account_id |
+------------+
| 1          |
| 4          |
+------------+
解释：
账户 1 在 09:00:00 到 09:30:00 同时挂在 IP 1 和 IP 2 上，应当禁止；
账户 2 用了两个 IP，但时间是错开的，不禁止；
账户 3 的两段登录虽然同一天，但 16:59:59 登出、17:00:00 才登录，没有交集，不禁止；
账户 4 的两段在 17:00:00 这一时刻相接（端点算交集），应当禁止。
```

## 题解

::: details 点击查看题解

### 思路

同一个账户的两条登录记录，只要满足"账户相同、IP 不同、时间区间相交"就该封禁。区间相交的通用判定是 `a.login <= b.logout AND b.login <= a.logout`：两个区间不重叠的充要条件是 `a` 完全在 `b` 之前或之后，所以把这两种情况取反即可。这里端点相接也算相交，因此两端都用 `<=` 而不是 `<`，这正好解释了为什么账户 4 要被封而账户 3 不用（16:59:59 与 17:00:00 之间还差 1 秒）。

坑点：很多人写成 `a.login BETWEEN b.login AND b.logout`，在一对区间里能跑出正确答案，但它只检查"一条的登录时间落在另一条内"，并不对称；当区间只是尾部重叠（比如 `a` 在 `b` 结束前登出、`b` 的登录早于 `a` 的登录）时会漏判。用对称的相交判定更稳妥。

另一个细节是去重：一个账户可能有多对重叠记录，自连接会产生多行，必须 `DISTINCT`（或用 `EXISTS` / `IN` 子查询）保证每个账户只输出一次。

### SQL 实现

```sql
SELECT DISTINCT l1.account_id
FROM LogInfo l1
JOIN LogInfo l2
  ON l1.account_id = l2.account_id
 AND l1.ip_address <> l2.ip_address
 AND l1.login <= l2.logout
 AND l2.login <= l1.logout
ORDER BY l1.account_id;
```

### 复杂度分析

- 时间复杂度：O(n^2) 最坏情况（同账户记录很多时自连接），有 `account_id` 索引时可大幅降低。
- 空间复杂度：O(1)，只输出账户号（去重哈希另计）。

:::
