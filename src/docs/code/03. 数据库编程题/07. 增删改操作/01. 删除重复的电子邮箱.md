# 删除重复的电子邮箱

> 难度：简单 | 标签：DELETE、多表连接 | [LeetCode 原题](https://leetcode.cn/problems/delete-duplicate-emails/)

## 题目描述

表: `Person`

```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| id          | int     |
| email       | varchar |
+-------------+---------+
id 是该表的主键列(具有唯一值的列)。
该表的每一行包含一封电子邮件。电子邮件将不包含大写字母。
```

编写解决方案** 删除** 所有重复的电子邮件，只保留一个具有最小 `id` 的唯一电子邮件。

（对于 SQL 用户，请注意你应该编写一个 `DELETE` 语句而不是 `SELECT` 语句。）

（对于 Pandas 用户，请注意你应该直接修改 `Person` 表。）

运行脚本后，显示的答案是 `Person` 表。驱动程序将首先编译并运行您的代码片段，然后再显示 `Person` 表。`Person` 表的最终顺序 **无关紧要** 。

返回结果格式如下示例所示。

示例 1:

```
输入:
Person 表:
+----+------------------+
| id | email            |
+----+------------------+
| 1  | john@example.com |
| 2  | bob@example.com  |
| 3  | john@example.com |
+----+------------------+
输出:
+----+------------------+
| id | email            |
+----+------------------+
| 1  | john@example.com |
| 2  | bob@example.com  |
+----+------------------+
解释: john@example.com重复两次。我们保留最小的Id = 1。
```

## 题解

::: details 点击查看题解

### 思路

「保留最小 id」意味着：一行要被删，当且仅当**存在另一行同 email 且 id 更小**。这天然是一个自连接语义，用 MySQL 的多表 DELETE 直接表达：`p1` 是待删的目标行，`JOIN` 条件 `p1.email = p2.email AND p1.id > p2.id` 找到「证据行」，命中就删掉 `p1`。对 `id=1` 的 john，没有任何更小 id 的同邮箱行，连接不命中，保留；`id=3` 找到 `p1.id > p2.id`（3 > 1），删除。

易错点一：条件必须是严格 `>`，写成 `>=` 会把自己也连上，整组全删。易错点二：不能图省事写成 `DELETE FROM Person WHERE email IN (SELECT email FROM Person GROUP BY email HAVING COUNT(*) > 1)`——这只会删光重复邮箱的所有行（包括最小 id 那行），题目要求保留一行；而 `WHERE id NOT IN (SELECT MIN(id) ... GROUP BY email)` 在 MySQL 中会报 1093 错误（DELETE 的子查询不能直接引用目标表），需要再包一层派生表才能执行，自连接写法最直接。

注意重复组只删「多出来的」，不重复的行（如 bob）连接无命中，天然不受影响；`Person` 最终顺序无关紧要，无需 ORDER BY（DELETE 也不支持）。

### SQL 实现

```sql
DELETE p1
FROM Person p1
JOIN Person p2
  ON p1.email = p2.email
 AND p1.id > p2.id;
```

### 复杂度分析

- 时间复杂度：O(n²) 最坏（同邮箱行数平方），有 email 索引时接近 O(n)。
- 空间复杂度：O(1)，仅需连接时的临时结构。

:::
