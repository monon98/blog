# 变更性别

> 难度：简单 | 标签：UPDATE、条件表达式 | [LeetCode 原题](https://leetcode.cn/problems/swap-sex-of-employees/)

## 题目描述

`Salary` 表：

```
+-------------+----------+
| Column Name | Type     |
+-------------+----------+
| id          | int      |
| name        | varchar  |
| sex         | ENUM     |
| salary      | int      |
+-------------+----------+
id 是这个表的主键（具有唯一值的列）。
sex 这一列的值是 ENUM 类型，只能从 ('m', 'f') 中取。
本表包含公司雇员的信息。
```

请你编写一个解决方案来交换所有的 `'f'` 和 `'m'` （即，将所有 `'f'` 变为 `'m'` ，反之亦然），仅使用 **单个 update 语句** ，且不产生中间临时表。

注意，你必须仅使用一条 update 语句，且 **不能** 使用 select 语句。

结果如下例所示。

**示例 1:**

```
输入：
Salary 表：
+----+------+-----+--------+
| id | name | sex | salary |
+----+------+-----+--------+
| 1  | A    | m   | 2500   |
| 2  | B    | f   | 1500   |
| 3  | C    | m   | 5500   |
| 4  | D    | f   | 500    |
+----+------+-----+--------+
输出：
+----+------+-----+--------+
| id | name | sex | salary |
+----+------+-----+--------+
| 1  | A    | f   | 2500   |
| 2  | B    | m   | 1500   |
| 3  | C    | f   | 5500   |
| 4  | D    | m   | 500    |
+----+------+-----+--------+
解释：
(1, A) 和 (3, C) 从 'm' 变为 'f' 。
(2, B) 和 (4, D) 从 'f' 变为 'm' 。
```

## 题解

::: details 点击查看题解

### 思路

一条 UPDATE 内完成翻转，靠 `CASE` 表达式为每行计算新值：`sex = 'm'` 的行赋 `'f'`，否则（即 `'f'`）赋 `'m'`。因为表达式是对**更新前**的行值求值、再逐行写回，所以不会出现「先改成 f 的行又被翻回去」的问题——UPDATE 的 SET 表达式读取的是旧快照。

题目限定「单条 update、不能用 select、无临时表」，所以 `UPDATE ... SET sex = (SELECT ...)` 或 `UPDATE t1 JOIN ...` 这类借助查询的写法都被禁止，`CASE` 是唯一干净的解法。`ELSE 'm'` 覆盖所有非 `'m'` 的值；本题 sex 只有 'm'/'f' 两种取值（ENUM），也可以写成 `IF(sex = 'm', 'f', 'm')`，语义完全相同，`CASE` 更通用。

易错点：写成两步 `UPDATE ... SET sex='f' WHERE sex='m'; UPDATE ... SET sex='m' WHERE sex='f';` 会先全部变成 f 再全部变回 m——两条语句都违背题意，且结果是灾难性的；`REPLACE(sex, ...)` 之类的字符串函数也不必上，单字符翻转用条件表达式即可。另外注意 schema 里 sex 建为 `char(1)`，与 ENUM 等价处理，不影响解法。

### SQL 实现

```sql
UPDATE Salary
SET sex = CASE WHEN sex = 'm' THEN 'f' ELSE 'm' END;
```

### 复杂度分析

- 时间复杂度：O(n)，n 为员工数，全表扫描并逐行更新。
- 空间复杂度：O(1)，不产生临时表。

:::
