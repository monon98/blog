# 为订单类型为 0 的客户删除类型为 1 的订单

> 难度：中等 | 标签：子查询、多表连接 | [LeetCode 原题](https://leetcode.cn/problems/drop-type-1-orders-for-customers-with-type-0-orders/)

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

## 题目描述

表：`Orders`

```
+-------------+------+
| Column Name | Type |
+-------------+------+
| order_id    | int  |
| customer_id | int  |
| order_type  | int  |
+-------------+------+
order_id 是这张表的主键（具有唯一值的列）。
每一行表示一个订单的 ID、下该订单的客户 ID 以及订单类型。
订单类型可以是 0 或 1。
```

编写一个解决方案来报告所有订单，规则如下：

	- 如果某个客户 **至少有一个** 类型为 `0` 的订单，则 **不报告** 该客户的任何类型为 `1` 的订单。

	- 否则，报告该客户的全部订单。

返回结果表 **无顺序要求**。

结果格式如下所示。

示例：

**输入：**

Orders 表：

+----------+-------------+------------+
| order_id | customer_id | order_type |
+----------+-------------+------------+
| 1        | 1           | 0          |
| 2        | 1           | 0          |
| 11       | 2           | 0          |
| 12       | 2           | 1          |
| 21       | 3           | 1          |
| 22       | 3           | 0          |
| 31       | 4           | 1          |
| 32       | 4           | 1          |
+----------+-------------+------------+

**输出：**

+----------+-------------+------------+
| order_id | customer_id | order_type |
+----------+-------------+------------+
| 1        | 1           | 0          |
| 2        | 1           | 0          |
| 11       | 2           | 0          |
| 22       | 3           | 0          |
| 31       | 4           | 1          |
| 32       | 4           | 1          |
+----------+-------------+------------+

**解释：**

	- 客户 1 有两个类型为 0 的订单，全部返回。

	- 客户 2 有一个类型为 0 和一个类型为 1 的订单，只返回类型为 0 的订单（订单 12 被「删除」）。

	- 客户 3 有一个类型为 0 和一个类型为 1 的订单，只返回类型为 0 的订单（订单 21 被「删除」）。

	- 客户 4 有两个类型为 1 的订单且没有类型为 0 的订单，全部返回。

## 题解

::: details 点击查看题解

### 思路

题目的「删除」是形象说法：查询本身是**报告保留下来的订单**——类型为 0 的订单永远保留；类型为 1 的订单仅当其客户没有任何类型为 0 订单时才保留。因此判断的核心是「该客户是否存在 order_type = 0 的订单」这个布尔量。

先用 CTE `SELECT DISTINCT customer_id FROM Orders WHERE order_type = 0` 得到「有 0 类型订单的客户集合」，再拿 `Orders` 左连接它：保留条件写成 `o.order_type = 0 OR 匹配不到（h.customer_id IS NULL）`。前半支保住全部 0 类型订单，后半支保住「不在 0 类型客户集合里」的客户的全部（1 类型）订单，两条并起来正好是答案。

易错点一：不能写成 `WHERE order_type = 0 OR customer_id NOT IN (...)` 却忘了 0 类型客户自身——其实 `NOT IN` 写法中前半支 `order_type = 0` 已覆盖，逻辑等价；真正的坑是写成 `order_type = 0 OR order_type = 1 AND NOT EXISTS(...)` 时**运算优先级**——`AND` 高于 `OR`，必须加括号，否则条件退化。易错点二：用相关子查询 `NOT EXISTS` 逐行判断也可行（对每行回表查一次，数据大时更慢），且注意本题 DELETE 不是题面要求，返回查询结果即可。CTE 内 `DISTINCT` 可省（`IN` 会去重），但左连接场景下保留它语义更清晰。

### SQL 实现

```sql
WITH has_type0 AS (
    SELECT DISTINCT customer_id
    FROM Orders
    WHERE order_type = 0
)
SELECT o.order_id, o.customer_id, o.order_type
FROM Orders o
LEFT JOIN has_type0 h
  ON o.customer_id = h.customer_id
WHERE o.order_type = 0
   OR h.customer_id IS NULL;
```

### 复杂度分析

- 时间复杂度：O(n)，n 为订单行数，扫描两遍（CTE 一遍、连接过滤一遍），哈希连接近似线性。
- 空间复杂度：O(c)，c 为有 0 类型订单的客户数。
