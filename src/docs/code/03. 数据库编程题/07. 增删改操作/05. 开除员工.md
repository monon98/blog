# 开除员工

> 难度：中等 | 标签：多表连接、分组聚合、日期函数 | [LeetCode 原题](https://leetcode.cn/problems/employees-with-deductions/)

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

## 题目描述

表：`Employees`

```
+--------------+------+
| Column Name  | Type |
+--------------+------+
| employee_id  | int  |
| needed_hours | int  |
+--------------+------+
employee_id 是这张表的唯一主键。
每一行包含一个员工的 ID 以及他为拿到工资每月至少需要工作的小时数。
```

表：`Logs`

```
+-------------+----------+
| Column Name | Type     |
+-------------+----------+
| employee_id | int      |
| in_time     | datetime |
| out_time    | datetime |
+-------------+----------+
(employee_id, in_time, out_time) 是这张表的主键（列的组合具有唯一值）。
每一行表示该员工的一次上班打卡与下班打卡时间。所有时间都在 2022 年 10 月内。
out_time 可能在 in_time 的次日，表示工作跨过了午夜。
```

公司规定每个员工每月必须工作一定的小时数。员工按 **工作时段（session）** 上班，一个员工的工作时长等于 **所有时段分钟数之和**，其中 **每个时段的分钟数都要向上取整**。

	- 例如：某时段工作了 51 分钟 2 秒，则按 52 分钟计算。

编写一个解决方案来报告 **将被扣工资** 的员工 ID，即工作时长 **没有达到** `needed_hours` 的员工。

返回结果表 **无顺序要求**。

结果格式如下所示。

示例：

**输入：**

Employees 表：

+-------------+--------------+
| employee_id | needed_hours |
+-------------+--------------+
| 1           | 20           |
| 2           | 12           |
| 3           | 2            |
+-------------+--------------+

Logs 表：

+-------------+---------------------+---------------------+
| employee_id | in_time             | out_time            |
+-------------+---------------------+---------------------+
| 1           | 2022-10-01 09:00:00 | 2022-10-01 17:00:00 |
| 1           | 2022-10-06 09:05:04 | 2022-10-06 17:09:03 |
| 1           | 2022-10-12 23:00:00 | 2022-10-13 03:00:01 |
| 2           | 2022-10-29 12:00:00 | 2022-10-29 23:58:58 |
+-------------+---------------------+---------------------+

**输出：**

+-------------+
| employee_id |
+-------------+
| 2           |
| 3           |
+-------------+

**解释：**

	- 员工 1：三个时段分别工作 480、484、241 分钟（均向上取整），合计 1205 分钟 = 20 小时 5 分钟，达到 20 小时，不扣工资。

	- 员工 2：一个时段工作 11 小时 58 分 58 秒，按 719 分钟计不足 720 分钟（12 小时），将被扣工资。

	- 员工 3：没有任何工作时段，工作 0 小时，将被扣工资。

## 题解

::: details 点击查看题解

### 思路

三个判断要素里，`needed_hours` 在 `Employees` 表、实际工时在 `Logs` 表，且**员工 3 一条日志都没有**——这决定了必须用 `Employees LEFT JOIN Logs 聚合结果`，用 INNER JOIN 或直接从 `Logs` 出发聚合都会把没有打卡的员工丢掉，而他们恰恰要被报告（0 小时 < 2 小时）。

时段分钟数向上取整：`CEIL(TIMESTAMPDIFF(SECOND, in_time, out_time) / 60)`。用秒做差是因为 `TIMESTAMPDIFF(MINUTE, ...)` 本身就会**丢弃秒数向下取整**（11:58:58 会算成 11 小时 58 分），与题意「向上取整」相反；先取秒再除以 60 得到带小数的分钟数，`CEIL` 才能得到正确的 719 分钟。跨午夜由 `TIMESTAMPDIFF` 自动处理，无需特判日期。

聚合后比较：`SUM(CEIL(...)) < needed_hours * 60`（统一到分钟，避免浮点小时比较），没有日志的行 `SUM` 为 NULL，用 `COALESCE(..., 0)` 归零。替代写法：相关子查询逐员工算工时也可，或把 `CEIL` 换成 `FLOOR(x) + (x > FLOOR(x))`，都不如 `CEIL` 直观。

### SQL 实现

```sql
SELECT e.employee_id
FROM Employees e
LEFT JOIN (
    SELECT employee_id,
           SUM(CEIL(TIMESTAMPDIFF(SECOND, in_time, out_time) / 60)) AS minutes_worked
    FROM Logs
    GROUP BY employee_id
) t
  ON e.employee_id = t.employee_id
WHERE COALESCE(t.minutes_worked, 0) < e.needed_hours * 60
ORDER BY e.employee_id;
```

### 复杂度分析

- 时间复杂度：O(n + m)，n 为员工数、m 为日志行数，各自扫描一遍后哈希连接。
- 空间复杂度：O(n)，连接结果与按员工聚合的中间结果。

:::
