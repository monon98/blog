# 上升的温度

> 难度：简单 | 标签：多表连接、日期函数 | [LeetCode 原题](https://leetcode.cn/problems/rising-temperature/)

## 题目描述

表： `Weather`

```
+---------------+---------+
| Column Name   | Type    |
+---------------+---------+
| id            | int     |
| recordDate    | date    |
| temperature   | int     |
+---------------+---------+
id 是该表具有唯一值的列。
没有具有相同 recordDate 的不同行。
该表包含特定日期的温度信息
```

编写解决方案，找出与之前（昨天的）日历日期相比温度更高的所有日期的 `id` 。

返回结果 **无顺序要求** 。

结果格式如下例子所示。

示例 1：

```
输入：
Weather 表：
+----+------------+-------------+
| id | recordDate | Temperature |
+----+------------+-------------+
| 1  | 2015-01-01 | 10          |
| 2  | 2015-01-02 | 25          |
| 3  | 2015-01-03 | 20          |
| 4  | 2015-01-04 | 30          |
+----+------------+-------------+
输出：
+----+
| id |
+----+
| 2  |
| 4  |
+----+
解释：
2015-01-02 的温度比前一天高（10 -> 25）
2015-01-04 的温度比前一天高（20 -> 30）
```

## 题解

::: details 点击查看题解

### 思路

同一张表要和「自己的昨天」比，标准做法是 **自连接**：把 `Weather` 取两个别名，一份代表今天 `w`，一份代表昨天 `y`，连接条件是 `DATEDIFF(w.recordDate, y.recordDate) = 1`，即两天恰好相差一个日历日。连上之后再比较温度 `w.temperature > y.temperature`，命中的 `w.id` 就是答案。

三个易错点。第一，题目说的是「昨天的 **日历日期**」，因此条件必须是「日期差恰为 1 天」，不能写成 `w.recordDate > y.recordDate`，那样会把前天、大前天也算进来。第二，日期差写法有多种等价形式：`DATEDIFF(w.recordDate, y.recordDate) = 1`、`w.recordDate = DATE_SUB(y.recordDate, INTERVAL 1 DAY)`、`w.recordDate - INTERVAL 1 DAY = y.recordDate` 都可以（注意 `DATEDIFF` 是 MySQL 内置函数，两个参数顺序反了结果就是负数）。第三，表里 `id` 与 `recordDate` 都唯一且日期不重复，所以每个 `w` 最多匹配到一个 `y`，不会产生重复行。

替代写法是窗口函数：`LAG(temperature) OVER (ORDER BY recordDate)` 取出前一行温度，再比较，一次扫描即可完成，不需要连接；日期不连续时它与自连接的差别会体现出来——本题数据连续，两种写法结果一致，但自连接在「日期不连续」的变体里必须严格用日期差条件才能保证语义正确。

### SQL 实现

```sql
SELECT w.id
FROM Weather w
JOIN Weather y ON DATEDIFF(w.recordDate, y.recordDate) = 1
WHERE w.temperature > y.temperature;
```

### 复杂度分析

- 时间复杂度：O(n)，n 为记录数，单次扫描完成连接（`recordDate` 可建索引时更优）。
- 空间复杂度：O(n)，连接阶段的哈希表开销。
