# 院系无效的学生

> 难度：简单 | 标签：子查询、多表连接 | [LeetCode 原题](https://leetcode.cn/problems/students-with-invalid-departments/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

表 `Departments`：

```
+---------------+---------+
| Column Name   | Type    |
+---------------+---------+
| id            | int     |
| name          | varchar |
+---------------+---------+
在 SQL 中，id 是该表的主键。
该表记录了这所大学每个院系的 id 信息。
```

表 `Students`：

```
+---------------+---------+
| Column Name   | Type    |
+---------------+---------+
| id            | int     |
| name          | varchar |
| department_id | int     |
+---------------+---------+
在 SQL 中，id 是该表的主键。
该表记录了这所大学每名学生的 id 及其就读院系的 id。
```

编写解决方案，找出 **所在院系已不存在（被撤销）** 的所有学生的 id 和姓名。

返回结果表 **无顺序要求**。

结果格式如下所示。

**示例 1：**

```
输入：
Departments 表：
+------+--------------------------+
| id   | name                     |
+------+--------------------------+
| 1    | Electrical Engineering   |
| 7    | Computer Engineering     |
| 13   | Bussiness Administration |
+------+--------------------------+
Students 表：
+------+----------+---------------+
| id   | name     | department_id |
+------+----------+---------------+
| 23   | Alice    | 1             |
| 1    | Bob      | 7             |
| 5    | Jennifer | 13            |
| 2    | John     | 14            |
| 4    | Jasmine  | 77            |
| 3    | Steve    | 74            |
| 6    | Luis     | 1             |
| 8    | Jonathan | 7             |
| 7    | Daiana   | 33            |
| 11   | Madelynn | 1             |
+------+----------+---------------+
输出：
+------+----------+
| id   | name     |
+------+----------+
| 2    | John     |
| 7    | Daiana   |
| 4    | Jasmine  |
| 3    | Steve    |
+------+----------+
解释：
John、Daiana、Steve 和 Jasmine 分别就读于院系 14、33、74、77，这些院系在 Departments 表中不存在。
```

## 题解

::: details 点击查看题解

### 思路

「学生的院系 id 在院系表里找不到」是典型的反连接问题，两种写法都直截了当。最短的是 `WHERE department_id NOT IN (SELECT id FROM Departments)`——子查询列出所有现存院系，`NOT IN` 留下的就是挂靠在已撤销院系上的学生，一行内连接都不用写。

`NOT IN` 的经典陷阱必须提一句：子查询结果里只要混进一个 `NULL`，整个 `NOT IN` 的判断就永远为「未知」，返回 **零行**。本题 `Departments.id` 是主键、不含 `NULL`，所以安全；如果换成没有主键约束的列，更稳妥的是改写成 `NOT EXISTS (SELECT 1 FROM Departments d WHERE d.id = s.department_id)`——`NOT EXISTS` 对 `NULL` 完全免疫，这也是它被视为「反连接标准姿势」的原因。

第三种写法是左连接：`Students LEFT JOIN Departments ON department_id = d.id WHERE d.id IS NULL`，把「连不上的行」筛出来，与 183 题同一套路。三种写法在本题数据上结果一致；输出只要 `id, name` 两列、顺序任意，注意别把 `department_id` 也带出去。易错点是方向别反——要的是「学生查不到院系」，不是「院系没有学生」，后者（0 人的院系）不是本题要求，写成从 `Departments` 出发的左连接就南辕北辙了。

### SQL 实现

```sql
SELECT s.id, s.name
FROM Students s
WHERE s.department_id NOT IN (SELECT id FROM Departments);
```

### 复杂度分析

- 时间复杂度：O(n × m) 最坏、建索引后 O(n + m)，n 为学生数、m 为院系数。
- 空间复杂度：O(m)，保存院系 id 集合的开销。

:::
