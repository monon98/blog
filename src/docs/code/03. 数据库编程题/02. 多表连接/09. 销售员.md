# 销售员

> 难度：简单 | 标签：多表连接、子查询 | [LeetCode 原题](https://leetcode.cn/problems/sales-person/)

## 题目描述

表: `SalesPerson`

```
+-----------------+---------+
| Column Name     | Type    |
+-----------------+---------+
| sales_id        | int     |
| name            | varchar |
| salary          | int     |
| commission_rate | int     |
| hire_date       | date    |
+-----------------+---------+
sales_id 是该表的主键列(具有唯一值的列)。
该表的每一行都显示了销售人员的姓名和 ID ，以及他们的工资、佣金率和雇佣日期。
```

表: `Company`

```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| com_id      | int     |
| name        | varchar |
| city        | varchar |
+-------------+---------+
com_id 是该表的主键列(具有唯一值的列)。
该表的每一行都表示公司的名称和 ID ，以及公司所在的城市。
```

表: `Orders`

```
+-------------+------+
| Column Name | Type |
+-------------+------+
| order_id    | int  |
| order_date  | date |
| com_id      | int  |
| sales_id    | int  |
| amount      | int  |
+-------------+------+
order_id 是该表的主键列(具有唯一值的列)。
com_id 是 Company 表中 com_id 的外键（reference 列）。
sales_id 是来自销售员表 sales_id 的外键（reference 列）。
该表的每一行包含一个订单的信息。这包括公司的 ID 、销售人员的 ID 、订单日期和支付的金额。
```

编写解决方案，找出没有任何与名为 **“RED”** 的公司相关的订单的所有销售人员的姓名。

以 **任意顺序** 返回结果表。

返回结果格式如下所示。

**示例 1：**

```
输入：
SalesPerson 表:
+----------+------+--------+-----------------+------------+
| sales_id | name | salary | commission_rate | hire_date  |
+----------+------+--------+-----------------+------------+
| 1        | John | 100000 | 6               | 4/1/2006   |
| 2        | Amy  | 12000  | 5               | 5/1/2010   |
| 3        | Mark | 65000  | 12              | 12/25/2008 |
| 4        | Pam  | 25000  | 25              | 1/1/2005   |
| 5        | Alex | 5000   | 10              | 2/3/2007   |
+----------+------+--------+-----------------+------------+
Company 表:
+--------+--------+----------+
| com_id | name   | city     |
+--------+--------+----------+
| 1      | RED    | Boston   |
| 2      | ORANGE | New York |
| 3      | YELLOW | Boston   |
| 4      | GREEN  | Austin   |
+--------+--------+----------+
Orders 表:
+----------+------------+--------+----------+--------+
| order_id | order_date | com_id | sales_id | amount |
+----------+------------+--------+----------+--------+
| 1        | 1/1/2014   | 3      | 4        | 10000  |
| 2        | 2/1/2014   | 4      | 5        | 5000   |
| 3        | 3/1/2014   | 1      | 1        | 50000  |
| 4        | 4/1/2014   | 1      | 4        | 25000  |
+----------+------------+--------+----------+--------+
输出：
+------+
| name |
+------+
| Amy  |
| Mark |
| Alex |
+------+
解释：
根据表 orders 中的订单 '3' 和 '4' ，容易看出只有 'John' 和 'Pam' 两个销售员曾经向公司 'RED' 销售过。
所以我们需要输出表 salesperson 中所有其他人的名字。
```

## 题解

::: details 点击查看题解

### 思路

「找没有做过某件事的人」，本质是集合差：全集是所有销售员，减去「给 RED 公司下过单的销售员」。RED 的订单藏在 `Orders.com_id` 里，公司名要先到 `Company` 表换成 `com_id`，所以筛掉名单需要 **两张表连一次**：`Orders JOIN Company WHERE name = 'RED'`。

主解法用 `NOT EXISTS` 相关子查询：对外层每个销售员，到「RED 的订单」里找有没有他的 `sales_id`，找不到就输出。相关子查询天然是逐行判断，不惧怕任何 `NULL`，语义最稳。写成 `NOT IN (SELECT sales_id ...)` 也对，而且更短，但有一个必须知道的雷：**只要子查询结果里出现一个 `NULL`，`NOT IN` 的结果就永远为假**，整张表的销售员都会被过滤光；本题 `sales_id` 全非空才侥幸安全，生产数据里更推荐 `NOT EXISTS` 或左连接写法。

还要注意筛选条件的层次：`c.name = 'RED'` 必须在子查询（或连接条件）里先限定出「RED 的订单」，再谈 `sales_id` 是否出现；不能写成 `WHERE c.name = 'RED' AND sp.sales_id NOT IN (...)` 这类把两个问题搅在一起的条件。左连接替代写法：`LEFT JOIN (RED 订单去重后) r ON sp.sales_id = r.sales_id WHERE r.sales_id IS NULL`，与 183 题同一套路。

### SQL 实现

```sql
SELECT sp.name
FROM SalesPerson sp
WHERE NOT EXISTS (
    SELECT 1
    FROM Orders o
    JOIN Company c ON o.com_id = c.com_id
    WHERE c.name = 'RED'
      AND o.sales_id = sp.sales_id
);
```

### 复杂度分析

- 时间复杂度：O(s × o)，s 为销售员数、o 为 RED 公司订单数；为子查询加上 `com_id`、`sales_id` 索引后接近 O(s + o)。
- 空间复杂度：O(1)，逐行判断，无需额外结果集。

:::
