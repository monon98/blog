# 平均售价

> 难度：简单 | 标签：多表连接、分组聚合、日期函数 | [LeetCode 原题](https://leetcode.cn/problems/average-selling-price/)

## 题目描述

表：`Prices`

```
+---------------+---------+
| Column Name   | Type    |
+---------------+---------+
| product_id    | int     |
| start_date    | date    |
| end_date      | date    |
| price         | int     |
+---------------+---------+
(product_id，start_date，end_date) 是 prices 表的主键（具有唯一值的列的组合）。
prices 表的每一行表示的是某个产品在一段时期内的价格。
每个产品的对应时间段是不会重叠的，这也意味着同一个产品的价格时段不会出现交叉。
```

表：`UnitsSold`

```
+---------------+---------+
| Column Name   | Type    |
+---------------+---------+
| product_id    | int     |
| purchase_date | date    |
| units         | int     |
+---------------+---------+
该表可能包含重复数据。
该表的每一行表示的是每种产品的出售日期，单位和产品 id。
```

编写解决方案以查找每种产品的平均售价。`average_price` 应该 **四舍五入到小数点后两位**。如果产品没有任何售出，则假设其平均售价为 0。

返回结果表 **无顺序要求** 。

结果格式如下例所示。

**示例 1：**

```
输入：
Prices table:
+------------+------------+------------+--------+
| product_id | start_date | end_date   | price  |
+------------+------------+------------+--------+
| 1          | 2019-02-17 | 2019-02-28 | 5      |
| 1          | 2019-03-01 | 2019-03-22 | 20     |
| 2          | 2019-02-01 | 2019-02-20 | 15     |
| 2          | 2019-02-21 | 2019-03-31 | 30     |
+------------+------------+------------+--------+
UnitsSold table:
+------------+---------------+-------+
| product_id | purchase_date | units |
+------------+---------------+-------+
| 1          | 2019-02-25    | 100   |
| 1          | 2019-03-01    | 15    |
| 2          | 2019-02-10    | 200   |
| 2          | 2019-03-22    | 30    |
+------------+---------------+-------+
输出：
+------------+---------------+
| product_id | average_price |
+------------+---------------+
| 1          | 6.96          |
| 2          | 16.96         |
+------------+---------------+
解释：
平均售价 = 产品总价 / 销售的产品数量。
产品 1 的平均售价 = ((100 * 5)+(15 * 20) )/ 115 = 6.96
产品 2 的平均售价 = ((200 * 15)+(30 * 30) )/ 230 = 16.96
```

## 题解

::: details 点击查看题解

### 思路

平均售价的定义是「**加权平均**」：总金额除以总件数，即 `SUM(单价 × 件数) / SUM(件数)`，而不是把各时段单价做简单平均。难点在于每笔销售要先找到「发生时点落在哪个价格区间」的那一行 `Prices`——同一产品有多个不重叠的价格时段，所以连接条件是 **复合的**：`product_id` 相等，且 `purchase_date BETWEEN start_date AND end_date`。题目已保证时段不重叠，因此每笔销售最多匹配一条价格，连接不会放大行数。

三处细节。其一，以 `Prices` 为左表还是 `UnitsSold` 为左表会影响「没有售出的产品」：题面要求这类产品的平均价为 **0**，从 `Prices` 出发左连接后，没匹配到的行 `units` 全为 `NULL`，`SUM(price * units)` 得 `NULL`，除法结果 `NULL`，再套 `IFNULL(..., 0)` 归零即可（`NULL / NULL` 结果是 `NULL`，不会触发除零错误）。其二，除法结果必须 `ROUND(..., 2)` 才能两位小数，且 `ROUND` 放在最外层、聚合算完之后，先四舍五入再累分会引入误差。其三，`UnitsSold` 可能有重复数据，但重复行代表两笔真实销售，要如实计入分子分母，去重反而会算错。

替代写法：先在 `UnitsSold` 上连接 `Prices` 得到每笔销售的金额，再 `GROUP BY product_id` 用子查询包一层，外层 `LEFT JOIN` 处理 0 值——本质相同；也可以先聚合出各产品的总销量与总额，再补 0。注意 `product_id` 若只出现在 `UnitsSold` 而 `Prices` 里没有（本题测试数据不存在），从 `Prices` 出发的写法不会输出它，读题时按「以价格表为基准」理解即可。

### SQL 实现

```sql
SELECT
    p.product_id,
    ROUND(IFNULL(SUM(p.price * u.units) / NULLIF(SUM(u.units), 0), 0), 2) AS average_price
FROM Prices p
LEFT JOIN UnitsSold u
    ON p.product_id = u.product_id
   AND u.purchase_date BETWEEN p.start_date AND p.end_date
GROUP BY p.product_id;
```

### 复杂度分析

- 时间复杂度：O(n × m) 最坏、建索引后接近 O(n + m)，n 为价格时段数、m 为销售记录数。
- 空间复杂度：O(n)，分组聚合的哈希表开销。
