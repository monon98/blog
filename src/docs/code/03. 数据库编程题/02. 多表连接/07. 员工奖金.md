# 员工奖金

> 难度：简单 | 标签：多表连接、空值处理 | [LeetCode 原题](https://leetcode.cn/problems/employee-bonus/)

## 题目描述

表：`Employee`

```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| empId       | int     |
| name        | varchar |
| supervisor  | int     |
| salary      | int     |
+-------------+---------+
empId 是该表中具有唯一值的列。
该表的每一行都表示员工的 id 和姓名，以及他们经理的 id 和他们的工资。
```

表：`Bonus`

```
+-------------+------+
| Column Name | Type |
+-------------+------+
| empId       | int  |
| bonus       | int  |
+-------------+------+
empId 是该表具有唯一值的列。
empId 是 Employee 表中 empId 的外键(reference 列)。
该表的每一行都包含一个员工的 id 和他们各自的奖金。
```

编写一个解决方案来报告满足以下任一条件的每个员工的姓名和奖金金额：

	- 奖金 少于 1000 的员工。

	- 没有任何奖金的员工。

以 **任意顺序** 返回结果表。

结果格式如下所示。

**示例 1：**

```
输入：
Employee table:
+-------+--------+------------+--------+
| empId | name   | supervisor | salary |
+-------+--------+------------+--------+
| 3     | Brad   | null       | 4000   |
| 1     | John   | 3          | 1000   |
| 2     | Dan    | 3          | 2000   |
| 4     | Thomas | 3          | 4000   |
+-------+--------+------------+--------+
Bonus table:
+-------+-------+
| empId | bonus |
+-------+-------+
| 2     | 500   |
| 4     | 2000  |
+-------+-------+
输出：
+------+-------+
| name | bonus |
+------+-------+
| Brad | null  |
| John | null  |
| Dan  | 500   |
+------+-------+
```

## 题解

::: details 点击查看题解

### 思路

本题的陷阱全在 **NULL 的语义**：`Bonus` 表里根本没出现的员工也要出现在结果里（奖金为 `NULL`），所以绝不能用内连接——内连接会直接把 Brad、John 这类没有奖金记录的人丢掉。正确姿势是以 `Employee` 为左表 `LEFT JOIN Bonus`，让没奖金的行在 `bonus` 列上得到 `NULL`。

筛选条件要写成 `b.bonus < 1000 OR b.bonus IS NULL`。容易犯的错有两种：只写 `WHERE b.bonus < 1000`——`NULL < 1000` 的结果是 `NULL`（未知），行会被过滤掉，恰好漏掉题目明确要求的「没有奖金」群体；或者误以为 `WHERE b.bonus < 1000 OR b.bonus = NULL` 能行——`b.bonus = NULL` 永远不为真，必须用 `IS NULL`。

另一个要分清的概念是「**没有奖金记录**」与「**奖金值不满足条件**」：`Bonus` 表只有 empId 2（500）和 4（2000）两行，Brad、John 没有任何记录，连接后 `bonus` 为 `NULL`，靠 `IS NULL` 进入结果；Thomas（empId = 4）有一条 2000 的记录，既不小于 1000 也不是 `NULL`，两个条件都不满足，被正确排除。写完 SQL 后拿示例的三行输出逐条核对，是验证 NULL 相关条件最直接的办法。

替代写法：`WHERE IFNULL(b.bonus, 0) < 1000`，把 NULL 归一成 0 后只需一个比较，等价且更短；或者先用 `NOT IN` 取出无奖金记录的员工，再与奖金小于 1000 的员工 `UNION`。

### SQL 实现

```sql
SELECT e.name, b.bonus
FROM Employee e
LEFT JOIN Bonus b ON e.empId = b.empId
WHERE b.bonus < 1000 OR b.bonus IS NULL;
```

### 复杂度分析

- 时间复杂度：O(n + m)，n 为员工数、m 为奖金记录数，连接与过滤各一遍。
- 空间复杂度：O(min(n, m))，连接哈希表的开销。
