# 查找重叠的班次

> 难度：中等 | 标签：多表连接、自连接 | [LeetCode 原题](https://leetcode.cn/problems/find-overlapping-shifts/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

`EmployeeShifts` 表：

```
+------------------+----------+
| Column Name      | Type     |
+------------------+----------+
| employee_id      | int      |
| start_time       | time     |
| end_time         | time     |
+------------------+----------+
(employee_id, start_time) 是这张表的唯一键。
本表记录员工在某一天的班次起止时间。
```

编写解决方案，统计每位员工 **重叠班次的数量**。如果一个班次的 `end_time` 晚于另一个班次的 `start_time`，则认为这两个班次重叠。只返回至少有一个重叠班次的员工，按 `employee_id` 升序排序。

**示例 1：**

```
输入：
EmployeeShifts 表：
+-------------+------------+----------+
| employee_id | start_time | end_time |
+-------------+------------+----------+
| 1           | 08:00:00   | 12:00:00 |
| 1           | 11:00:00   | 15:00:00 |
| 1           | 14:00:00   | 18:00:00 |
| 2           | 09:00:00   | 17:00:00 |
| 2           | 16:00:00   | 20:00:00 |
| 3           | 10:00:00   | 12:00:00 |
| 3           | 13:00:00   | 15:00:00 |
| 3           | 16:00:00   | 18:00:00 |
| 4           | 08:00:00   | 10:00:00 |
| 4           | 09:00:00   | 11:00:00 |
+-------------+------------+----------+

输出：
+-------------+--------------------+
| employee_id | overlapping_shifts |
+-------------+--------------------+
| 1           | 2                  |
| 2           | 1                  |
| 4           | 1                  |
+-------------+--------------------+

解释：
- 员工 1 有三个班次：08:00-12:00、11:00-15:00、14:00-18:00。
  第一个与第二个重叠、第二个与第三个重叠，共 2 个重叠班次。
- 员工 2 的两个班次 09:00-17:00 与 16:00-20:00 彼此重叠，共 1 个。
- 员工 3 的三个班次互不重叠，因此不出现在结果中。
- 员工 4 的两个班次 08:00-10:00 与 09:00-11:00 彼此重叠，共 1 个。
```

## 题解

::: details 点击查看题解

### 怟路

「重叠」是两两之间的关系，所以最自然的写法是把 `EmployeeShifts` 自连接两次，限定同一个员工，再用区间相交条件 `t1.start_time < t2.start_time AND t1.end_time > t2.start_time` 描述「t1 的结束晚于 t2 的开始」。由于 `t1.start_time < t2.start_time` 已保证两行不同、且每对重叠区间恰好被数一次（早开始的当 t1、晚开始的当 t2），直接 `COUNT(*)` 按员工分组就是答案，最后 `HAVING overlapping_shifts > 0` 过滤掉没有重叠的员工。

区间题最容易写错的是边界：本题判定条件是「一个班次的 `end_time` **晚于** 另一个的 `start_time`」，即严格大于——恰好首尾相接（前一个 12:00 结束、后一个 12:00 开始）不算重叠。若写成 `>=` 会把相接也计入。另外注意 `TIME` 类型直接比较大小即可，不需要 `TIMESTAMP` 转换。

替代写法：用扫描线，把每个班次拆成 +1/-1 两个事件按时间排序做前缀和，统计「同时进行的班次数 > 0」的区间个数，可在不支持自连接优化的场景下把复杂度降到 O(n log n)；或者用 `LEAD(end_time)` 判断与下一班次是否相交（需按开始时间排序，能覆盖相邻相交但覆盖不到跨班次相交的复杂情形，需谨慎）。

### SQL 实现

```sql
SELECT
    t1.employee_id,
    COUNT(*) AS overlapping_shifts
FROM EmployeeShifts AS t1
JOIN EmployeeShifts AS t2
    ON t1.employee_id = t2.employee_id
    AND t1.start_time < t2.start_time
    AND t1.end_time > t2.start_time
GROUP BY t1.employee_id
HAVING overlapping_shifts > 0
ORDER BY t1.employee_id;
```

### 复杂度分析

- 时间复杂度：O(m²)，m 为单个员工的班次数，自连接后按员工分组。
- 空间复杂度：O(e)，e 为有重叠班次的员工数。

:::
