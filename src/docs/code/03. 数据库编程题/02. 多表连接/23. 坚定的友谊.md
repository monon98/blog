# 坚定的友谊

> 难度：中等 | 标签：多表连接、分组聚合 | [LeetCode 原题](https://leetcode.cn/problems/strong-friendship/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

表 `Friendship`：

```
+-------------+------+
| Column Name | Type |
+-------------+------+
| user1_id    | int  |
| user2_id    | int  |
+-------------+------+
(user1_id, user2_id) 是该表的主键。
该表的每一行都表示 user1_id 和 user2_id 是朋友。
注意 user1_id < user2_id。
```

一对朋友 x 和 y 之间如果拥有**至少三个共同好友**，则称这段友谊为**强友谊**（共同好友指同时与 x、y 都是朋友的第三个人，x、y 自己不算）。

编写解决方案，找出所有的强友谊。结果表中不能出现重复行，且保持 `user1_id < user2_id`，同时返回这段友谊的**共同好友数量** `common_friend`。以任意顺序返回。

**示例 1：**

```
输入：
Friendship 表：
+----------+----------+
| user1_id | user2_id |
+----------+----------+
| 1        | 2        |
| 1        | 3        |
| 2        | 3        |
| 1        | 4        |
| 2        | 4        |
| 1        | 5        |
| 2        | 5        |
| 1        | 7        |
| 3        | 7        |
| 1        | 6        |
| 3        | 6        |
| 2        | 6        |
+----------+----------+
输出：
+----------+----------+---------------+
| user1_id | user2_id | common_friend |
+----------+----------+---------------+
| 1        | 2        | 4             |
| 1        | 3        | 3             |
+----------+----------+---------------+
解释：
用户 1 和 2 有 4 个共同好友（3、4、5、6）。
用户 1 和 3 有 3 个共同好友（2、6、7）。
用户 2 和 3 只有 2 个共同好友（1、6），不足三个，因此不计入。
```

## 题解

::: details 点击查看题解

### 思路

难点在于**友谊表是单向存储的**：每对朋友只存一行，且保证 `user1_id < user2_id`，所以"user A 的好友列表"分散在 `user1_id` 和 `user2_id` 两列里。第一步先用 `UNION ALL` 把表**双向化**，得到每个用户完整的邻居集合 `friends(uid, fid)`，这一步不做，后面统计共同好友必然漏一半。

有了双向邻接表，再做两次自连接：`f` 取原始表中的一段友谊 `(user1_id, user2_id)`（题目保证 user1 < user2，天然去重），`a` 取 user2 的好友、`b` 取 user1 的好友，并要求 `b.fid = a.fid`——这个相等条件正是"存在第三个人同时是两者好友"。最后 `GROUP BY` 这对朋友、`COUNT(*)` 得到共同好友数，`HAVING COUNT(*) >= 3` 过滤。

易错点有三个。其一，别忘了最后必须回到 `Friendship` 原表确认这对人**本身是朋友**：只看"有 ≥3 个共同好友"会把没直接建立友谊的两人也捞出来，题目要的是"这段友谊是否坚定"。其二，`b.fid = a.fid` 这个人会不会误算成 user1/user2 自己？不会：`a.uid = user2_id` 时 `a.fid` 不可能是 user2（表里没有自环），同理 `b.fid` 不可能是 user1，边界安全。其三，去重靠"以原表行为锚 + user1 < user2"，不要在最后再 `DISTINCT`，`COUNT` 会被 `DISTINCT` 影响语义。

替代写法：先把双向邻接表自连接统计每对 `(x, y)`（`x < y`）的共同好友数，再用 `IN` 或 `JOIN` 回原表筛出确实是朋友的对，效果一样；窗口函数在这题帮不上忙，本质是三角形计数。

### SQL 实现

```sql
WITH friends AS (
    SELECT user1_id AS uid, user2_id AS fid FROM Friendship
    UNION ALL
    SELECT user2_id, user1_id FROM Friendship
)
SELECT f.user1_id, f.user2_id, COUNT(*) AS common_friend
FROM Friendship AS f
JOIN friends AS a ON a.uid = f.user2_id
JOIN friends AS b ON b.uid = f.user1_id AND b.fid = a.fid
GROUP BY f.user1_id, f.user2_id
HAVING COUNT(*) >= 3;
```

### 复杂度分析

- 时间复杂度：O(F²)，F 为友谊行数，双向化后两次连接近似按邻接表配对。
- 空间复杂度：O(2F)，双向邻接表的存储开销。
