# 市场分析 I

> 难度：中等 | 标签：多表连接、分组聚合、日期函数 | [LeetCode 原题](https://leetcode.cn/problems/market-analysis-i/)

编写解决方案找出每个用户的注册日期和在 **`2019` **年作为买家的订单总数。

以 **任意顺序** 返回结果表。

查询结果格式如下。

**示例 1:**

```

+---------+------------+----------------+

| 1         | 2018-01-01 | 1              |
```

## 题解

::: details 点击查看题解

### 思路

输出是「每个用户」一行、外加一个 2019 年的计数，包括一单都没有的用户（示例里 3、4 号都是 0），所以骨架必然是 **`Users` 左连接 `Orders` 后分组计数**，而不是从订单表出发聚合。

最大的坑是 **年份条件的位置**：`WHERE YEAR(order_date) = 2019` 会把左连接保留下来的「无订单用户」行一起过滤掉（`YEAR(NULL)` 不等于 2019），0 就变成了「没有这一行」，人数直接缺一半。正确做法是把限定写进连接条件 `ON u.user_id = o.buyer_id AND YEAR(o.order_date) = 2019`——`WHERE` 过滤的是连接结果，`ON` 只决定右表哪些行参与匹配，不影响左表保留。

计数用 `COUNT(o.order_id)`（`COUNT(*)` 在这里同样得 0/正数，但计列是更稳的习惯，绝不能 `COUNT(order_date)` 之类依赖非空的写法之外还要留意 `buyer_id` 而非 `seller_id`——题目问的是「作为 **买家** 的订单」，连错键会得到卖家侧的统计。日期过滤还有两种等价写法：`o.order_date BETWEEN '2019-01-01' AND '2019-12-31'` 或 `o.order_date >= '2019-01-01' AND o.order_date < '2020-01-01'`，这类范围条件还能利用索引，比 `YEAR()` 函数更友好；`Items` 表本题用不到，是干扰项。

### SQL 实现

```sql
SELECT
    u.user_id AS buyer_id,
    u.join_date,
    COUNT(o.order_id) AS orders_in_2019
FROM Users u
LEFT JOIN Orders o
    ON u.user_id = o.buyer_id
   AND YEAR(o.order_date) = 2019
GROUP BY u.user_id, u.join_date;
```

### 复杂度分析

- 时间复杂度：O(n + m)，n 为用户数、m 为订单数，连接与分组各一遍。
- 空间复杂度：O(n)，分组计数的哈希表开销。
