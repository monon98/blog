# 没有广告的剧集

> 难度：简单 | 标签：多表连接、子查询 | [LeetCode 原题](https://leetcode.cn/problems/ad-free-sessions/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

表 `Playback`：

```
+-------------+------+
| Column Name | Type |
+-------------+------+
| session_id  | int  |
| customer_id | int  |
| start_time  | int  |
| end_time    | int  |
+-------------+------+
session_id 是该表中具有唯一值的列。
customer_id 是观看该场播放的客户 ID。
该场播放在 start_time 与 end_time 之间的闭区间内进行（含端点）。
保证 start_time <= end_time，且同一客户的两场播放时间不重叠。
```

表 `Ads`：

```
+-------------+------+
| Column Name | Type |
+-------------+------+
| ad_id       | int  |
| customer_id | int  |
| timestamp   | int  |
+-------------+------+
ad_id 是该表中具有唯一值的列。
customer_id 是观看该广告的客户 ID。
timestamp 是该广告被展示的时刻。
```

编写解决方案，找出**没有被展示过任何广告**的播放场次。

判定标准：同一客户在 `[start_time, end_time]`（含端点）内出现过至少一条广告记录，该场播放就算有广告；只有完全没有命中广告的场次才是答案。

返回 `session_id`，以任意顺序返回。

**示例 1：**

```
输入：
Playback 表：
+------------+-------------+------------+----------+
| session_id | customer_id | start_time | end_time |
+------------+-------------+------------+----------+
| 1          | 1           | 1          | 5        |
| 2          | 1           | 15         | 23       |
| 3          | 2           | 10         | 12       |
| 4          | 2           | 17         | 28       |
| 5          | 2           | 2          | 8        |
+------------+-------------+------------+----------+
Ads 表：
+-------+-------------+-----------+
| ad_id | customer_id | timestamp |
+-------+-------------+-----------+
| 1     | 1           | 5         |
| 2     | 2           | 17        |
| 3     | 2           | 20        |
+-------+-------------+-----------+
输出：
+------------+
| session_id |
+------------+
| 2          |
| 3          |
| 5          |
+------------+
解释：
客户 1 在时刻 5 看到了广告 1，此时正处于播放场次 1 中。
客户 2 在时刻 17、20 看到了广告 2 和 3，此时正处于播放场次 4 中。
场次 1 和 4 至少出现过一条广告；场次 2、3、5 没有出现任何广告，因此返回它们。
```

## 题解

::: details 点击查看题解

### 思路

这是一个典型的**反连接（anti join）**：先找出"有广告的场次"，再取补集。把 `Playback` 和 `Ads` 按 `customer_id` 连接，并加上 `a.timestamp BETWEEN p.start_time AND p.end_time` 的时间条件，命中的行就是"某场播放被广告打断过"；用 `LEFT JOIN ... WHERE a.ad_id IS NULL` 保留没命中的场次，正好就是答案。

连接条件里**必须带 `customer_id`**：只按时间过滤会把别的客户的广告也算到这场播放头上，示例里时刻 5 的广告属于客户 1，若不加客户条件，其他客户在 1~5 之间的场次也会被误伤。`BETWEEN` 天然含端点，和题面"闭区间"一致——示例中广告 1 的 `timestamp = 5` 正好落在场次 1 的 `end_time = 5` 上，必须算作有广告。

取补集有几种等价写法：`LEFT JOIN + IS NULL`（主解，一次扫描、优化器友好）、`NOT IN (子查询)`（子查询里有 `NULL` 时会整体失效，本题列无 `NULL` 但要小心）、`NOT EXISTS`（语义最稳）。注意结果只需要 `session_id`，不要顺手把 `customer_id` 也查出来——判题比对列名会失败。另外有广告的场次可能命中多条广告，用 `LEFT JOIN` 去重与否都不影响 `IS NULL` 的判定，但用 `NOT IN` 时更要留意重复行。

### SQL 实现

```sql
SELECT p.session_id
FROM Playback AS p
LEFT JOIN Ads AS a
  ON p.customer_id = a.customer_id
 AND a.timestamp BETWEEN p.start_time AND p.end_time
WHERE a.ad_id IS NULL;
```

### 复杂度分析

- 时间复杂度：O(n × m)，n 为播放场次数、m 为广告数，最坏做一次嵌套循环匹配（实际可用连接键剪枝）。
- 空间复杂度：O(1)，只保留连接过程中的临时行，不需要额外聚合结构。

:::
