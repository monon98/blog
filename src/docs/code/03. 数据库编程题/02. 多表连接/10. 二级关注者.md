# 二级关注者

> 难度：中等 | 标签：多表连接、分组聚合 | [LeetCode 原题](https://leetcode.cn/problems/second-degree-follower/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

表 `Follow`：

```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| followee    | varchar |
| follower    | varchar |
+-------------+---------+
(followee, follower) 是该表的主键（具有唯一值的列的组合）。
该表的每一行都表示用户 follower 在社交网络上关注了用户 followee。
不存在用户关注自己的情况。
```

**二级关注者（second-degree follower）** 是同时满足以下两个条件的用户：

- 至少关注了一个人；

- 且至少被一个人关注。

编写解决方案，报告所有的二级关注者及其 **粉丝数量**。

返回结果按 `follower` **字母顺序升序** 排列。

结果格式如下所示。

**示例 1：**

```
输入：
Follow 表：
+----------+----------+
| followee | follower |
+----------+----------+
| Alice    | Bob      |
| Bob      | Cena     |
| Bob      | Donald   |
| Donald   | Edward   |
+----------+----------+
输出：
+----------+-----+
| follower | num |
+----------+-----+
| Bob      | 2   |
| Donald   | 1   |
+----------+-----+
解释：
用户 Bob 有 2 个粉丝。Bob 关注了 Alice，同时被 Cena 和 Donald 关注，因此 Bob 是二级关注者。
用户 Donald 有 1 个粉丝。Donald 关注了 Bob，同时被 Edward 关注，因此 Donald 是二级关注者。
用户 Alice 有 1 个粉丝，但 Alice 没有关注任何人，因此 Alice 不是二级关注者。
用户 Cena、Edward 只关注了别人却没有任何粉丝，也不是二级关注者。
```

## 题解

::: details 点击查看题解

### 思路

`Follow` 表一行 `('Alice', 'Bob')` 表示 **Bob 关注了 Alice**（前者是被关注者，后者是关注者），方向别搞反。判定「二级关注者」需要同时看到两条边：这个人 **发出** 的关注（作为 follower 出现）和 **指向他** 的关注（作为 followee 出现），一张表扫一遍是看不全的，必须自连接。

主解法是把 `Follow` 自连接两次：`f1.follower` 是候选者 X，条件 `f1.follower = f2.followee` 表示 X 关注了某人（`f1` 的那行存在）且 X 又被 `f2.follower` 关注（`f2` 的那行存在）。连接后的每个 X 都同时满足「关注了别人」和「被别人关注」，`COUNT(DISTINCT f2.follower)` 数的就是 X 的粉丝数——注意用 `DISTINCT`，X 关注多少人，X 的行就会在连接中被复制多少份，不去重会把粉丝数翻倍。最后按 `follower` 升序输出。

替代写法更省事：`SELECT followee AS follower, COUNT(DISTINCT follower) AS num FROM Follow WHERE followee IN (SELECT follower FROM Follow) GROUP BY followee ORDER BY followee`——先用 `IN` 筛出「自己也关注了别人」的被关注者（即二级关注者），再直接数他们的粉丝。两种写法等价，前者把「两跳关系」显式画了出来，是面试里更好讲的版本。易错点还有一个：`Alice` 有粉丝但不关注任何人、`Edward` 关注别人但没有粉丝，**两个条件缺一不可**，只写其中一个就会多输出。

### SQL 实现

```sql
SELECT f1.follower, COUNT(DISTINCT f2.follower) AS num
FROM Follow f1
JOIN Follow f2 ON f1.follower = f2.followee
GROUP BY f1.follower
ORDER BY f1.follower;
```

### 复杂度分析

- 时间复杂度：O(n²)（无索引时的连接代价），n 为关注关系行数；有 `(followee, follower)` 主键索引时接近 O(n log n)。
- 空间复杂度：O(n)，连接与分组的哈希开销。

:::

## 建表与测试数据

```sql
Create table If Not Exists Follow (followee varchar(255), follower varchar(255));
Truncate table Follow;
insert into Follow (followee, follower) values ('Alice', 'Bob');
insert into Follow (followee, follower) values ('Bob', 'Cena');
insert into Follow (followee, follower) values ('Bob', 'Donald');
insert into Follow (followee, follower) values ('Donald', 'Edward');
```
