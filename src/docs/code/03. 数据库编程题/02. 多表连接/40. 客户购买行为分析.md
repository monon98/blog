# 客户购买行为分析

> 难度：中等 | 标签：多表连接、分组聚合、窗口函数 | [LeetCode 原题](https://leetcode.cn/problems/customer-purchasing-behavior-analysis/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

`Transactions` 表：

```
+------------------+---------+
| Column Name      | Type    |
+------------------+---------+
| transaction_id   | int     |
| customer_id      | int     |
| product_id       | int     |
| transaction_date | date    |
| amount           | decimal |
+------------------+---------+
transaction_id 是该表的唯一主键。
每一行包含一次交易的客户 ID、产品 ID、交易日期和消费金额。
```

`Products` 表：

```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| product_id  | int     |
| category    | varchar |
| price       | decimal |
+-------------+---------+
product_id 是该表的唯一主键。
每一行表示一个产品的类别和价格。
```

编写解决方案，对每位客户统计：

- 总消费金额 `total_amount`
- 交易笔数 `transaction_count`
- 购买过的不同产品类别数 `unique_categories`
- 平均每笔交易金额 `avg_transaction_amount`
- 购买最频繁的产品类别 `top_category`（类别笔数并列时，取最近一笔交易所在的类别）
- 忠诚度得分 `loyalty_score`，定义为 `(交易笔数 × 10) + (总消费金额 / 100)`

`total_amount`、`avg_transaction_amount`、`loyalty_score` 均保留两位小数。返回结果按 `loyalty_score` 降序、`customer_id` 升序排序。

**示例 1：**

```
输入：
Transactions 表：
+----------------+-------------+------------+------------------+--------+
| transaction_id | customer_id | product_id | transaction_date | amount |
+----------------+-------------+------------+------------------+--------+
| 1              | 101         | 1          | 2023-01-01       | 100.0  |
| 2              | 101         | 2          | 2023-01-15       | 150.0  |
| 3              | 102         | 1          | 2023-01-01       | 100.0  |
| 4              | 102         | 3          | 2023-01-22       | 200.0  |
| 5              | 101         | 3          | 2023-02-10       | 200.0  |
+----------------+-------------+------------+------------------+--------+

Products 表：
+------------+-------------+-------+
| product_id | category    | price |
+------------+-------------+-------+
| 1          | A           | 100.0 |
| 2          | B           | 150.0 |
| 3          | C           | 200.0 |
+------------+-------------+-------+

输出：
+-------------+--------------+-------------------+------------------+----------------------+--------------+---------------+
| customer_id | total_amount | transaction_count | unique_categories| avg_transaction_amount | top_category | loyalty_score |
+-------------+--------------+-------------------+------------------+----------------------+--------------+---------------+
| 101         | 450.00       | 3                 | 3                | 150.00               | C            | 34.50         |
| 102         | 300.00       | 2                 | 2                | 150.00               | C            | 23.00         |
+-------------+--------------+-------------------+------------------+----------------------+--------------+---------------+

解释：
- 客户 101：总消费 100 + 150 + 200 = 450.00，3 笔交易，买了 A、B、C 三个类别；平均 450 / 3 = 150.00。
  三个类别各买 1 次并列，取最近交易（2023-02-10）所在的类别 C；忠诚度 = 3 × 10 + 450 / 100 = 34.50。
- 客户 102：总消费 100 + 200 = 300.00，2 笔交易，A、C 两个类别各 1 次并列，
  取最近交易（2023-01-22）所在的类别 C；忠诚度 = 2 × 10 + 300 / 100 = 23.00。
```

## 题解

::: details 点击查看题解

### 思路

整体结构是「先算每客户×类别的明细，再挑出冠军类别，最后回表聚合」三步走。

第一步，`Transactions` 按 `product_id` 连接 `Products` 拿到类别，按 `(customer_id, category)` 分组，得到每个客户每个类别的购买笔数 `cnt` 和该类别的最近交易日期 `max_date`。第二步，用 `ROW_NUMBER() OVER (PARTITION BY customer_id ORDER BY cnt DESC, max_date DESC)` 给类别编号，`rk = 1` 就是题目要的 `top_category`——先按笔数降序、再按最近交易日期降序，正好落实「并列时取最近交易的类别」的规则。

第三步把冠军类别回连到明细上（每个客户只有一行冠军，连接不会放大行数），再按 `customer_id` 聚合算 `SUM(amount)`、`COUNT(*)`、`COUNT(DISTINCT category)`、`AVG(amount)`，忠诚度直接用公式 `COUNT(*) * 10 + SUM(amount) / 100` 现算并 `ROUND(..., 2)`。

易错点：一是并列规则不能漏，只按 `cnt` 排序时并列类别的选择不确定；二是 `unique_categories` 要用 `COUNT(DISTINCT category)` 而不是 `COUNT(*)`；三是金额除法的结果类型，`SUM(amount) / 100` 在 MySQL 中保留 decimal 精度，最后统一 `ROUND` 到两位。替代写法：也可以先用窗口函数在明细层标出冠军类别再过滤，或用 `GROUP_CONCAT`/相关子查询挑最频繁类别。

### SQL 实现

```sql
WITH P AS (
    SELECT
        t.customer_id,
        p.category,
        COUNT(*) AS cnt,
        MAX(t.transaction_date) AS max_date
    FROM Transactions AS t
    JOIN Products AS p ON t.product_id = p.product_id
    GROUP BY t.customer_id, p.category
),
R AS (
    SELECT
        customer_id,
        category,
        ROW_NUMBER() OVER (
            PARTITION BY customer_id
            ORDER BY cnt DESC, max_date DESC
        ) AS rk
    FROM P
)
SELECT
    t.customer_id,
    ROUND(SUM(t.amount), 2) AS total_amount,
    COUNT(*) AS transaction_count,
    COUNT(DISTINCT p.category) AS unique_categories,
    ROUND(AVG(t.amount), 2) AS avg_transaction_amount,
    r.category AS top_category,
    ROUND(COUNT(*) * 10 + SUM(t.amount) / 100, 2) AS loyalty_score
FROM Transactions AS t
JOIN Products AS p ON t.product_id = p.product_id
JOIN R AS r ON t.customer_id = r.customer_id AND r.rk = 1
GROUP BY t.customer_id, r.category
ORDER BY loyalty_score DESC, t.customer_id;
```

### 复杂度分析

- 时间复杂度：O(n log n)，两次分组加窗口排序主导，n 为交易数。
- 空间复杂度：O(c × k)，c 为客户数、k 为客户平均类别数。

:::
