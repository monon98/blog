# 没有共同朋友的朋友

> 难度：中等 | 标签：多表连接、子查询 | [LeetCode 原题](https://leetcode.cn/problems/friends-with-no-mutual-friends/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

`Friends` 表：

```
+-------------+------+
| Column Name | Type |
+-------------+------+
| user_id1    | int  |
| user_id2    | int  |
+-------------+------+
(user_id1, user_id2) 是这张表的主键。
每一行表示 user_id1 和 user_id2 互为好友。
```

好友关系是双向的（表里只存一条记录，但两个人彼此都算对方的好友）。编写解决方案，找出 **互为好友、且没有任何共同好友** 的所有用户对。返回结果按 `user_id1`、`user_id2` 分别升序排序。

**示例 1：**

```
输入：
Friends 表：
+----------+----------+
| user_id1 | user_id2 |
+----------+----------+
| 1        | 2        |
| 2        | 3        |
| 2        | 4        |
| 1        | 5        |
| 6        | 7        |
| 3        | 4        |
| 2        | 5        |
| 8        | 9        |
+----------+----------+

输出：
+----------+----------+
| user_id1 | user_id2 |
+----------+----------+
| 6        | 7        |
| 8        | 9        |
+----------+----------+

解释：
- 用户 1 和 2 是好友，但两人都与用户 5 是好友，存在共同好友，排除。
- 用户 2 和 3 是好友，两人都与用户 4 是好友，排除；2 和 4、3 和 4、2 和 5 同理，都因为存在共同好友而排除。
- 用户 6 和 7、用户 8 和 9 各自构成孤立的好友对，没有任何共同好友，因此保留。
```

## 题解

::: details 点击查看题解

### 思路

关键在于「共同好友」的判定：A 与 B 有共同好友，等价于存在第三个人 C，使得 C 既是 A 的好友、也是 B 的好友。由于表只存单向的一条记录，第一步必须先把好友关系 **双向展开**——用 `UNION ALL` 把 `(user_id1, user_id2)` 和 `(user_id2, user_id1)` 拼成完整的「谁是谁的朋友」邻接表 T。

有了 T，就可以自连接 `T t1 JOIN T t2 ON t1.user_id2 = t2.user_id2`：两行共享同一个好友 user_id2，就说明 `t1.user_id1` 与 `t2.user_id1` 有共同好友。把这些「有共同好友」的点对收集起来，再从原始 `Friends` 表中 `NOT IN` 排除，剩下的就是答案。

两个易错点：其一，忘记双向展开，只按表里存的方向判断会漏掉一半关系；其二，`NOT IN` 子查询里不能出现 `NULL`，本题是主键列所以安全，但通用写法更推荐 `NOT EXISTS`。另外别忘了最终按 `user_id1, user_id2` 升序排序。替代写法：用 `GROUP BY` 统计每对好友的共同好友数，`HAVING COUNT(*) = 0`。

### SQL 实现

```sql
WITH T AS (
    SELECT user_id1, user_id2 FROM Friends
    UNION ALL
    SELECT user_id2, user_id1 FROM Friends
)
SELECT f.user_id1, f.user_id2
FROM Friends AS f
WHERE NOT EXISTS (
    SELECT 1
    FROM T AS t1
    JOIN T AS t2 ON t1.user_id2 = t2.user_id2
    WHERE t1.user_id1 = f.user_id1
      AND t2.user_id1 = f.user_id2
)
ORDER BY f.user_id1, f.user_id2;
```

### 复杂度分析

- 时间复杂度：O(n²)，双向边数 n 下自连接两两配对。
- 空间复杂度：O(n)，存储展开后的双向好友关系。
