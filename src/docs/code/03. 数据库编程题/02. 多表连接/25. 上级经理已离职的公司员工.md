# 上级经理已离职的公司员工

> 难度：简单 | 标签：多表连接、子查询 | [LeetCode 原题](https://leetcode.cn/problems/employees-whose-manager-left-the-company/)

## 题目描述

表: `Employees`

```
+-------------+----------+
| Column Name | Type     |
+-------------+----------+
| employee_id | int      |
| name        | varchar  |
| manager_id  | int      |
| salary      | int      |
+-------------+----------+
在 SQL 中，employee_id 是这个表的主键。
这个表包含了员工，他们的薪水和上级经理的id。
有一些员工没有上级经理（其 manager_id 是空值）。
```

查找这些员工的id，他们的薪水严格少于`$30000` 并且他们的上级经理已离职。当一个经理离开公司时，他们的信息需要从员工表中删除掉，但是表中的员工的`manager_id`  这一列还是设置的离职经理的id 。

返回的结果按照`employee_id `从小到大排序。

查询结果如下所示：

**示例：**

```
输入：
Employees table:
+-------------+-----------+------------+--------+
| employee_id | name      | manager_id | salary |
+-------------+-----------+------------+--------+
| 3           | Mila      | 9          | 60301  |
| 12          | Antonella | null       | 31000  |
| 13          | Emery     | null       | 67084  |
| 1           | Kalel     | 11         | 21241  |
| 9           | Mikaela   | null       | 50937  |
| 11          | Joziah    | 6          | 28485  |
+-------------+-----------+------------+--------+
输出：
+-------------+
| employee_id |
+-------------+
| 11          |
+-------------+

解释：
薪水少于 30000 美元的员工有 1 号(Kalel) 和 11号 (Joziah)。
Kalel 的上级经理是 11 号员工，他还在公司上班(他是 Joziah )。
Joziah 的上级经理是 6 号员工，他已经离职，因为员工表里面已经没有 6 号员工的信息了，它被删除了。
```

## 题解

::: details 点击查看题解

### 思路

"经理已离职"的判定标准藏在题面里：**经理的信息已被从 Employees 表删除，但员工行的 `manager_id` 还留着**。所以条件就是——`manager_id` 有值，却在 `Employees.employee_id` 里查不到。这是典型的"左表有、右表无"的**反连接**问题。

主解法用 `LEFT JOIN` 自己连自己：以 `e.manager_id = m.employee_id` 连接，`m` 侧整行为 `NULL` 说明该经理已不在表中；再叠上 `salary < 30000`（**严格小于**，等于 30000 不算）和 `manager_id IS NOT NULL`，按 `employee_id` 升序返回。

`manager_id IS NOT NULL` 这个条件不能省：没有上级（`manager_id` 为 `NULL`）的员工同样会在 `LEFT JOIN` 后得到 `m.employee_id IS NULL`，会被误判成"经理离职"。示例里 12、13、9 号都是空经理，虽然恰好被薪水条件挡掉，换组数据就会出错。同理 `salary < 30000` 是严格小于，`Antonella` 的 31000 本来就不够格。

替代写法：`WHERE e.manager_id IS NOT NULL AND e.manager_id NOT IN (SELECT employee_id FROM Employees)`，用 `NOT IN` 表达"查不到"，注意子查询无 `NULL` 时才安全；`NOT EXISTS` 写法最稳，语义与 `LEFT JOIN ... IS NULL` 完全一致。

### SQL 实现

```sql
SELECT e.employee_id
FROM Employees AS e
LEFT JOIN Employees AS m
  ON e.manager_id = m.employee_id
WHERE e.salary < 30000
  AND e.manager_id IS NOT NULL
  AND m.employee_id IS NULL
ORDER BY e.employee_id;
```

### 复杂度分析

- 时间复杂度：O(n log n)，n 为员工数，自连接近似线性配对，排序占主导。
- 空间复杂度：O(1)，除结果集外不需要额外结构。
