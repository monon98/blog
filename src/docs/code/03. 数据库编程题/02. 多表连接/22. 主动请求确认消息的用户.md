# 主动请求确认消息的用户

> 难度：简单 | 标签：多表连接、日期函数 | [LeetCode 原题](https://leetcode.cn/problems/users-that-actively-request-confirmation-messages/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

表 `Signups`：

```
+----------------+----------+
| Column Name    | Type     |
+----------------+----------+
| user_id        | int      |
| time_stamp     | datetime |
+----------------+----------+
user_id 是该表中具有唯一值的列。
每一行包含 ID 为 user_id 的用户的注册时间。
```

表 `Confirmations`：

```
+----------------+----------+
| Column Name    | Type     |
+----------------+----------+
| user_id        | int      |
| time_stamp     | datetime |
| action         | ENUM     |
+----------------+----------+
(user_id, time_stamp) 是该表的主键。
user_id 是引用 Signups 表的外键。
action 是枚举类型，取值为 ('confirmed', 'timeout')。
每一行表示 ID 为 user_id 的用户在 time_stamp 时刻请求了一条确认消息，
该确认消息要么被确认（'confirmed'），要么超时未确认（'timeout'）。
```

编写解决方案，找出在 **24 小时窗口内请求了两次确认消息**的用户 ID。两次请求恰好相差 24 小时也算落在窗口内。`action` 的取值不影响答案，只看请求时间。

返回 `user_id`，以任意顺序返回。

**示例 1：**

```
输入：
Signups 表：
+---------+---------------------+
| user_id | time_stamp          |
+---------+---------------------+
| 3       | 2020-03-21 10:16:13 |
| 7       | 2020-01-04 13:57:59 |
| 2       | 2020-07-29 23:09:44 |
| 6       | 2020-12-09 10:39:37 |
+---------+---------------------+
Confirmations 表：
+---------+---------------------+-----------+
| user_id | time_stamp          | action    |
+---------+---------------------+-----------+
| 3       | 2021-01-06 03:30:46 | timeout   |
| 3       | 2021-01-06 03:37:45 | timeout   |
| 7       | 2021-06-12 11:57:29 | confirmed |
| 7       | 2021-06-13 11:57:30 | confirmed |
| 2       | 2021-01-22 00:00:00 | confirmed |
| 2       | 2021-01-23 00:00:00 | timeout   |
| 6       | 2021-10-23 14:14:14 | confirmed |
| 6       | 2021-10-24 14:14:13 | timeout   |
+---------+---------------------+-----------+
输出：
+---------+
| user_id |
+---------+
| 2       |
| 3       |
| 6       |
+---------+
解释：
用户 2 的两次请求恰好相差 24 小时，落在窗口内，计入。
用户 3 的两次请求相差 6 分 59 秒，落在窗口内，计入。
用户 6 的两次请求相差 23 小时 59 分 59 秒，落在窗口内，计入。
用户 7 的两次请求相差 24 小时 1 秒，超出窗口，不计入。
```

## 题解

::: details 点击查看题解

### 思路

题意是「同一用户存在两条请求记录，时间差不超过 24 小时」，最直接的表达就是把 `Confirmations` **自连接**：自己连自己，`user_id` 相同、`c1.time_stamp < c2.time_stamp` 保证取到的是有先后的两条，再用时间差过滤。只要存在这样一对，该用户就满足条件，所以最后 `DISTINCT` 去重。

时间差用 `TIMESTAMPDIFF(SECOND, c1.time_stamp, c2.time_stamp)` 换算成秒，和 `24 * 60 * 60` 比较。用 `<=` 正好对应"恰好 24 小时也算在窗口内"——示例里用户 2 差值正好 86400 秒要计入，用户 7 差 86401 秒要排除，边界只差 1 秒，写成 `<` 就错了。

几个易错点：其一，`action` 完全不参与判断，示例里用户 6 一条 `confirmed` 一条 `timeout` 也要算，别顺手加 `WHERE action = 'confirmed'`；其二，只要**存在**一对即可，不能按 `COUNT(*) >= 2` 分组后用 `HAVING` 卡总条数——用户有 3 条记录但两两都超过 24 小时时总条数同样 ≥ 2，会被误判，必须成对比较时间差；其三，时间差函数要挑 MySQL 8 里真实存在的：`TIMESTAMPDIFF(SECOND, ...)` 最直观，`UNIX_TIMESTAMP(t2) - UNIX_TIMESTAMP(t1)` 也等价；`DATE_DIFF` 是 LeetCode 专属函数，在本地 MySQL 上会直接报错。替代写法：先按 `user_id` 分组、`LAG(time_stamp) OVER (PARTITION BY user_id ORDER BY time_stamp)` 取上一条请求，再过滤相邻间隔 ≤ 24 小时，窗口函数版本对"只要相邻两条够近"的语义更省连接。

### SQL 实现

```sql
SELECT DISTINCT c1.user_id
FROM Confirmations AS c1
JOIN Confirmations AS c2
  ON c1.user_id = c2.user_id
 AND c1.time_stamp < c2.time_stamp
WHERE TIMESTAMPDIFF(SECOND, c1.time_stamp, c2.time_stamp) <= 24 * 60 * 60
ORDER BY c1.user_id;
```

### 复杂度分析

- 时间复杂度：O(k²)，k 为每个用户的请求条数（判题数据下 k 很小），整体随记录数近似线性。
- 空间复杂度：O(u)，u 为满足条件的去重用户数。

:::
