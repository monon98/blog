# 组合两个表

> 难度：简单 | 标签：多表连接、LEFT JOIN | [LeetCode 原题](https://leetcode.cn/problems/combine-two-tables/)

## 题目描述

表: `Person`

```
+-------------+---------+
| 列名         | 类型     |
+-------------+---------+
| PersonId    | int     |
| FirstName   | varchar |
| LastName    | varchar |
+-------------+---------+
personId 是该表的主键（具有唯一值的列）。
该表包含一些人的 ID 和他们的姓和名的信息。
```

表: `Address`

```
+-------------+---------+
| 列名         | 类型    |
+-------------+---------+
| AddressId   | int     |
| PersonId    | int     |
| City        | varchar |
| State       | varchar |
+-------------+---------+
addressId 是该表的主键（具有唯一值的列）。
该表的每一行都包含一个 ID = PersonId 的人的城市和州的信息。
```

编写解决方案，报告 `Person` 表中每个人的姓、名、城市和州。如果 `personId` 的地址不在 `Address` 表中，则报告为 `null` 。

以 **任意顺序** 返回结果表。

结果格式如下所示。

**示例 1:**

```
输入:
Person表:
+----------+----------+-----------+
| personId | lastName | firstName |
+----------+----------+-----------+
| 1        | Wang     | Allen     |
| 2        | Alice    | Bob       |
+----------+----------+-----------+
Address表:
+-----------+----------+---------------+------------+
| addressId | personId | city          | state      |
+-----------+----------+---------------+------------+
| 1         | 2        | New York City | New York   |
| 2         | 3        | Leetcode      | California |
+-----------+----------+---------------+------------+
输出:
+-----------+----------+---------------+----------+
| firstName | lastName | city          | state    |
+-----------+----------+---------------+----------+
| Allen     | Wang     | Null          | Null     |
| Bob       | Alice    | New York City | New York |
+-----------+----------+---------------+----------+
解释:
地址表中没有 personId = 1 的地址，所以它们的城市和州返回 null。
addressId = 1 包含了 personId = 2 的地址信息。
```

## 题解

::: details 点击查看题解

### 思路

题面里「如果地址不在 `Address` 表中，则报告为 `null`」这半句话决定了连接方式：**必须用 `LEFT JOIN`**（以 `Person` 为左表）。用 `INNER JOIN` 的话，没有地址的 personId = 1 那行会直接被丢掉，输出只剩一行，显然不符——「保留左表全部行、右表补 `NULL`」正是左连接的语义。

连接键是 `Person.personId = Address.personId`。注意 `Address` 表里还有一行 `personId = 3`，这个人**不在** `Person` 表里，左连接天然不会把它带出来（它是右表的"孤儿行"）；如果写成 `RIGHT JOIN` 或者把两张表反过来连，这条多余记录就会混进结果。

另一个细节是输出列的顺序和命名：题面示例是 `firstName, lastName, city, state`，`Person` 表的插入语句里列顺序是 `(personId, lastName, firstName)`，照抄 `SELECT *` 或按建表顺序写都会错。城市/州为 `NULL` 时显示为空（判题环境格式化成 `Null`），不需要用 `IFNULL`/`COALESCE` 去填默认值——填了反而改变了「报告为 null」的题意。替代写法：`FROM Address RIGHT JOIN Person ON ...` 语义等价但可读性差，不推荐。

### SQL 实现

```sql
SELECT p.firstName, p.lastName, a.city, a.state
FROM Person p
LEFT JOIN Address a ON p.personId = a.personId;
```

### 复杂度分析

- 时间复杂度：O(n + m)，n 为人数、m 为地址数，哈希连接一次扫描（无索引时）。
- 空间复杂度：O(n + m)，连接所需的哈希表空间。

:::
