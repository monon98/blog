# 每台机器的进程平均运行时间

> 难度：简单 | 标签：多表连接、分组聚合 | [LeetCode 原题](https://leetcode.cn/problems/average-time-of-process-per-machine/)

## 题目描述

表: `Activity`

```
+----------------+---------+
| Column Name    | Type    |
+----------------+---------+
| machine_id     | int     |
| process_id     | int     |
| activity_type  | enum    |
| timestamp      | float   |
+----------------+---------+
该表展示了一家工厂网站的用户活动。
(machine_id, process_id, activity_type) 是当前表的主键（具有唯一值的列的组合）。
machine_id 是一台机器的ID号。
process_id 是运行在各机器上的进程ID号。
activity_type 是枚举类型 ('start', 'end')。
timestamp 是浮点类型,代表当前时间(以秒为单位)。
'start' 代表该进程在这台机器上的开始运行时间戳 , 'end' 代表该进程在这台机器上的终止运行时间戳。
同一台机器，同一个进程都有一对开始时间戳和结束时间戳，而且开始时间戳永远在结束时间戳前面。
```

现在有一个工厂网站有几台机器运行，每台机器上运行着一个或更多进程 。编写解决方案，计算每台机器各自完成一个进程任务的平均耗时。

完成一个进程任务的时间指进程的`'end' 时间戳` 减去 `'start' 时间戳`。平均耗时通过计算每台机器上所有进程任务的总耗费时间除以那台机器上的总进程数量获得。

结果表必须包含`machine_id（机器ID）` 和对应的 **average time（平均耗时）** 别名 `processing_time`，且**四舍五入保留3位小数。**

以 **任意顺序** 返回表。

具体参考例子如下。

**示例 1:**

```
输入：
Activity table:
+------------+------------+---------------+-----------+
| machine_id | process_id | activity_type | timestamp |
+------------+------------+---------------+-----------+
| 0          | 0          | start         | 0.712     |
| 0          | 0          | end           | 1.520     |
| 0          | 1          | start         | 3.140     |
| 0          | 1          | end           | 4.120     |
| 1          | 0          | start         | 0.550     |
| 1          | 0          | end           | 1.550     |
| 1          | 1          | start         | 0.430     |
| 1          | 1          | end           | 1.420     |
| 2          | 0          | start         | 4.100     |
| 2          | 0          | end           | 4.512     |
| 2          | 1          | start         | 2.500     |
| 2          | 1          | end           | 5.000     |
+------------+------------+---------------+-----------+
输出：
+------------+-----------------+
| machine_id | processing_time |
+------------+-----------------+
| 0          | 0.894           |
| 1          | 0.995           |
| 2          | 1.456           |
+------------+-----------------+
解释：
一共有3台机器,每台机器运行着两个进程.
机器 0 的平均耗时: ((1.520 - 0.712) + (4.120 - 3.140)) / 2 = 0.894
机器 1 的平均耗时: ((1.550 - 0.550) + (1.420 - 0.430)) / 2 = 0.995
机器 2 的平均耗时: ((4.512 - 4.100) + (5.000 - 2.500)) / 2 = 1.456
```

## 题解

::: details 点击查看题解

### 思路

start 和 end 分散在两行里，要先**把它们配成一对**才能算差值。最直接的做法是把 `Activity` 自连接：连接键是 `(machine_id, process_id)`，同时在 `ON` 里限定左边是 `start`、右边是 `end`，一次连接就得到「每个进程一条、带耗时差值」的中间结果。注意把两个 `activity_type` 条件放进 `ON` 而不是 `WHERE`——写在 `WHERE` 里语义虽然等价（INNER JOIN），但如果以后改成 `LEFT JOIN` 就会悄悄改变结果，放 `ON` 更稳妥。

配对之后按 `machine_id` 分组求 `AVG(end - start)` 即可。分母不需要额外处理：每台机器的配对行数天然等于该机器的进程数，直接求平均就是题目要的「总耗时 / 进程数」。

易错点有三个。第一，题目要求**四舍五入保留 3 位小数**，必须写 `ROUND(..., 3)`；不写的话 `timestamp` 是 `FLOAT`，`0.808 + 0.98` 这类计算很可能输出 `0.8940000000000001`。第二，别先 `SUM` 再手工除 `COUNT(DISTINCT process_id)`，绕一圈还容易把分母算成全表进程数（跨机器）。第三，分组列只能放 `machine_id`，选了它就要按它分组，否则在 `ONLY_FULL_GROUP_BY` 模式下直接报错。

替代写法：用条件聚合在一次分组里分别累加起止时间戳，`SUM(IF(activity_type = 'end', timestamp, 0)) - SUM(IF(activity_type = 'start', timestamp, 0))` 再除以 `COUNT(DISTINCT process_id)`，结果一致，行数多时比自连接少扫一遍表。

### SQL 实现

```sql
SELECT
    a1.machine_id,
    ROUND(AVG(a2.timestamp - a1.timestamp), 3) AS processing_time
FROM Activity AS a1
JOIN Activity AS a2
  ON a1.machine_id = a2.machine_id
 AND a1.process_id = a2.process_id
 AND a1.activity_type = 'start'
 AND a2.activity_type = 'end'
GROUP BY a1.machine_id;
```

### 复杂度分析

- 时间复杂度：O(n)，n 为 `Activity` 行数；连接条件等价于按 `(machine_id, process_id)` 配对，不会产生平方级中间结果，分组聚合再扫一遍。
- 空间复杂度：O(m)，m 为机器数量，用于存放分组结果。
