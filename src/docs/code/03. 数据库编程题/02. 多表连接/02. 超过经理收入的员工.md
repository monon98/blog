# 超过经理收入的员工

> 难度：简单 | 标签：多表连接、自连接 | [LeetCode 原题](https://leetcode.cn/problems/employees-earning-more-than-their-managers/)

## 题目描述

表：`Employee`

```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| id          | int     |
| name        | varchar |
| salary      | int     |
| managerId   | int     |
+-------------+---------+
id 是该表的主键（具有唯一值的列）。
该表的每一行都表示雇员的ID、姓名、工资和经理的ID。
```

编写解决方案，找出收入比经理高的员工。

以 **任意顺序** 返回结果表。

结果格式如下所示。

**示例 1:**

```
输入:
Employee 表:
+----+-------+--------+-----------+
| id | name  | salary | managerId |
+----+-------+--------+-----------+
| 1  | Joe   | 70000  | 3         |
| 2  | Henry | 80000  | 4         |
| 3  | Sam   | 60000  | Null      |
| 4  | Max   | 90000  | Null      |
+----+-------+--------+-----------+
输出:
+----------+
| Employee |
+----------+
| Joe      |
+----------+
解释: Joe 是唯一挣得比经理多的雇员。
```

## 题解

::: details 点击查看题解

### 思路

员工和经理是**同一张表**里的两行，所以要让 `Employee` 和自己连接（自连接），起两个别名：`e` 当员工、`m` 当经理，连接条件 `e.managerId = m.id` 把每一行的「下属 — 上司」配成一行，再用 `WHERE e.salary > m.salary` 挑出赚得比经理多的人，最后 `SELECT e.name`。

为什么用 `JOIN`（内连接）而不是 `LEFT JOIN`：`managerId` 为 `NULL` 的行（Sam、Max 是顶层经理）在等值连接里**永远匹配不上**，会被自然丢弃——而他们本来也不该出现在结果里（没有可比较的经理）。如果换成左连接，这些行会带着 `m.salary = NULL` 留下来，虽然 `e.salary > NULL` 结果为 `NULL` 不通过 `WHERE`，侥幸结果相同，但语义上是绕远路。同理，`managerId` 指向不存在的 `id` 的脏数据也会被内连接过滤。

输出列名必须是 `Employee`（示例里的表头），所以要 `AS Employee`；返回的是姓名不是 id，别写成 `e.id`。替代写法：相关子查询 `WHERE e.salary > (SELECT salary FROM Employee WHERE id = e.managerId)`，对每个人回表查一次经理薪资，数据量大时不如自连接高效；`EXISTS` 配合比较也能写，但语义更绕。

### SQL 实现

```sql
SELECT e.name AS Employee
FROM Employee e
JOIN Employee m ON e.managerId = m.id
WHERE e.salary > m.salary;
```

### 复杂度分析

- 时间复杂度：O(n)，n 为员工数，按 `id` 建哈希/索引后连接与过滤各扫一遍。
- 空间复杂度：O(n)，连接侧的哈希表规模。

:::
