# 当选者

> 难度：中等 | 标签：多表连接、分组聚合 | [LeetCode 原题](https://leetcode.cn/problems/winning-candidate/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

表 `Candidate`：

```
+-------------+----------+
| Column Name | Type     |
+-------------+----------+
| id          | int      |
| name        | varchar  |
+-------------+----------+
id 是该表中具有唯一值的列。
该表的每一行都包含一位候选人的 id 和姓名。
```

表 `Vote`：

```
+-------------+------+
| Column Name | Type |
+-------------+------+
| id          | int  |
| candidateId | int  |
+-------------+------+
id 是自增主键（具有唯一值的列）。
candidateId 是 Candidate 表中 id 的外键（reference 列）。
该表的每一行确定了获得第 i 张选票的候选人。
```

编写解决方案，**报告当选者的姓名**（即获得选票数量最多的候选人）。

测试数据保证 **恰好有一位候选人胜出**（不存在并列第一的情况）。

结果格式如下所示。

**示例 1：**

```
输入：
Candidate 表：
+----+------+
| id | name |
+----+------+
| 1  | A    |
| 2  | B    |
| 3  | C    |
| 4  | D    |
| 5  | E    |
+----+------+
Vote 表：
+----+-------------+
| id | candidateId |
+----+-------------+
| 1  | 2           |
| 2  | 4           |
| 3  | 3           |
| 4  | 2           |
| 5  | 5           |
+----+-------------+
输出：
+------+
| name |
+------+
| B    |
+------+
解释：
候选人 B 获得 2 张选票，C、D、E 各获得 1 张选票，因此 B 当选。
```

## 题解

::: details 点击查看题解

### 思路

`Vote` 表一行就是一张选票，所以「得票数」就是按 `candidateId` 分组后 `COUNT(*)`。先在 `Vote` 内部 `GROUP BY candidateId`、按票数降序 `LIMIT 1` 取出获胜者的 `id`，再回 `Candidate` 表取姓名——这是最直接的两步写法。

关键细节有三个。其一，`ORDER BY COUNT(*) DESC LIMIT 1` 必须写在 **子查询内部**：如果先连 `Candidate` 再排序取第一行，虽然本题也能得到答案，但把「取第一名」和「取姓名」耦合在一起，逻辑上不如先定 id、再查名字清晰。其二，题目保证唯一胜者，所以 `LIMIT 1` 安全；若变体允许并列，就要改成「票数等于最大票数」的过滤写法。其三，`Vote.candidateId` 理论上可能存在指向不存在候选人的脏数据，用内连接可以自动剔除，用 `LEFT JOIN` 从 `Candidate` 出发则要小心别把 0 票候选人顶到第一（`COUNT(1)` 对无票者为 0，通常不会，但语义上不如内连接稳）。

替代写法：从 `Candidate` 出发 `LEFT JOIN Vote ... GROUP BY c.id ORDER BY COUNT(1) DESC LIMIT 1`，省掉一层子查询；或用窗口函数 `RANK() OVER (ORDER BY cnt DESC)` 先排名再筛，便于扩展成「输出前三名」。

### SQL 实现

```sql
SELECT c.name
FROM Candidate c
JOIN Vote v ON c.id = v.candidateId
GROUP BY c.id, c.name
ORDER BY COUNT(*) DESC
LIMIT 1;
```

### 复杂度分析

- 时间复杂度：O(v + c log v)，v 为选票数、c 为候选人数，分组计数与排序各一遍。
- 空间复杂度：O(c)，分组计数的哈希表开销。
