# 用户购买平台

> 难度：困难 | 标签：分组聚合、多表连接 | [LeetCode 原题](https://leetcode.cn/problems/user-purchase-platform/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

表：`Spending`

| 列名 | 类型 |
| --- | --- |
| user_id | int |
| spend_date | date |
| platform | enum |
| amount | int |

该表记录了某购物网站（同时提供桌面端 desktop 和移动端 mobile 应用）用户的消费历史。`(user_id, spend_date, platform)` 是该表的主键，`platform` 是枚举类型，取值为 `('desktop', 'mobile')`。

编写一个查询，统计每个日期分别使用以下三种方式消费的**总人数**与**总金额**：

- 只使用桌面端（`desktop`）；
- 只使用移动端（`mobile`）；
- 桌面端和移动端都使用了（`both`）。

某一天如果没有用户使用某种方式，也要输出该行（人数与金额为 0）。

示例：

输入 `Spending` 表：

| user_id | spend_date | platform | amount |
| --- | --- | --- | --- |
| 1 | 2019-07-01 | mobile | 100 |
| 1 | 2019-07-01 | desktop | 100 |
| 2 | 2019-07-01 | mobile | 100 |
| 2 | 2019-07-02 | mobile | 100 |
| 3 | 2019-07-01 | desktop | 100 |
| 3 | 2019-07-02 | desktop | 100 |

输出：

| spend_date | platform | total_amount | total_users |
| --- | --- | --- | --- |
| 2019-07-01 | desktop | 100 | 1 |
| 2019-07-01 | mobile | 100 | 1 |
| 2019-07-01 | both | 200 | 1 |
| 2019-07-02 | desktop | 100 | 1 |
| 2019-07-02 | mobile | 100 | 1 |
| 2019-07-02 | both | 0 | 0 |

解释：

- 2019-07-01，用户 1 同时使用了桌面端和移动端，用户 2 只用了移动端，用户 3 只用了桌面端。
- 2019-07-02，用户 2 只用了移动端，用户 3 只用了桌面端，没有用户两种平台都用。

## 题解

::: details 点击查看题解

### 思路

"既用桌面端又用移动端"是把一个用户一天的多行**折叠成一个用户**之后才能判断的属性，所以第一层先按 `(spend_date, user_id)` 分组，用 `MAX(platform = 'desktop')`、`MAX(platform = 'mobile')` 得到该用户当天是否用过这两个平台，同时 `SUM(amount)` 得到该用户当天的总消费。第二层再用 `CASE` 把每个用户归入 `desktop` / `mobile` / `both` 三类之一，按日期 + 平台聚合出总金额和总人数。

最大的坑是**补零行**：结果要求每个日期都输出三种平台，哪怕当天 `both` 没有人（如 2019-07-02）。只做 `GROUP BY` 是补不出 0 行的，需要先用 `SELECT DISTINCT spend_date` 与固定的平台列表做交叉连接（`CROSS JOIN`），再左连接聚合结果，最后 `COALESCE(..., 0)` 兜底。

注意 `Spending.platform` 是 ENUM 类型，`platform = 'desktop'` 这种布尔比较在 MySQL 中返回 1/0，`MAX()` 取"是否用过"非常顺手；`amount` 对 `both` 用户是两个平台金额之和，与官方口径一致。输出顺序题目未强制要求，这里按示例用 `FIELD()` 固定为 desktop、mobile、both。

### SQL 实现

```sql
WITH user_day AS (
    SELECT spend_date,
           user_id,
           SUM(amount) AS amount,
           MAX(platform = 'desktop') AS has_desktop,
           MAX(platform = 'mobile')  AS has_mobile
    FROM Spending
    GROUP BY spend_date, user_id
),
classified AS (
    SELECT spend_date,
           user_id,
           amount,
           CASE WHEN has_desktop = 1 AND has_mobile = 1 THEN 'both'
                WHEN has_desktop = 1 THEN 'desktop'
                ELSE 'mobile' END AS platform
    FROM user_day
),
platform_list AS (
    SELECT 'desktop' AS platform
    UNION ALL SELECT 'mobile'
    UNION ALL SELECT 'both'
)
SELECT d.spend_date,
       p.platform,
       COALESCE(SUM(c.amount), 0) AS total_amount,
       COUNT(c.user_id) AS total_users
FROM (SELECT DISTINCT spend_date FROM Spending) d
CROSS JOIN platform_list p
LEFT JOIN classified c
       ON c.spend_date = d.spend_date
      AND c.platform = p.platform
GROUP BY d.spend_date, p.platform
ORDER BY d.spend_date, FIELD(p.platform, 'desktop', 'mobile', 'both');
```

### 复杂度分析

- 时间复杂度：O(n log n)，n 为消费记录数，分组与连接各需一次排序/哈希。
- 空间复杂度：O(u + d)，u 为（日期 × 用户）组合数，d 为日期数。

:::
