# 航班机票状态

> 难度：困难 | 标签：窗口函数、排序与排名 | [LeetCode 原题](https://leetcode.cn/problems/status-of-flight-tickets/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

表：`Flights`

```
+-------------+------+
| 列名        | 类型 |
+-------------+------+
| flight_id   | int  |
| capacity    | int  |
+-------------+------+
```

`flight_id` 列包含不同的值。每行包含航班 id 和座位容量。

表：`Passengers`

```
+--------------+----------+
| 列名         | 类型     |
+--------------+----------+
| passenger_id | int      |
| flight_id    | int      |
| booking_time | datetime |
+--------------+----------+
```

`passenger_id` 包含不同的值，`booking_time` 包含不同的值。每行包含乘客 id、预订时间以及所预订的航班 id。

乘客提前预订航班机票。如果乘客预订了一张机票，且航班上还有空座位，该机票将**得到确认（Confirmed）**；如果航班已经满员，乘客将被列入**等候名单（Waitlist）**。

编写解决方案，确定每个乘客机票的当前状态，按 `passenger_id` 升序返回结果表。

**示例 1：**

输入：

```
Flights 表:
+-----------+----------+
| flight_id | capacity |
+-----------+----------+
| 1         | 2        |
| 2         | 2        |
| 3         | 1        |
+-----------+----------+

Passengers 表:
+--------------+-----------+---------------------+
| passenger_id | flight_id | booking_time        |
+--------------+-----------+---------------------+
| 101          | 1         | 2023-07-10 16:30:00 |
| 102          | 1         | 2023-07-10 17:45:00 |
| 103          | 1         | 2023-07-10 12:00:00 |
| 104          | 2         | 2023-07-05 13:23:00 |
| 105          | 2         | 2023-07-05 09:00:00 |
| 106          | 3         | 2023-07-08 11:10:00 |
| 107          | 3         | 2023-07-08 09:10:00 |
+--------------+-----------+---------------------+
```

输出：

```
+--------------+-----------+
| passenger_id | Status    |
+--------------+-----------+
| 101          | Confirmed |
| 102          | Waitlist  |
| 103          | Confirmed |
| 104          | Confirmed |
| 105          | Confirmed |
| 106          | Waitlist  |
| 107          | Confirmed |
+--------------+-----------+
```

解释：

- 航班 1 容量为 2。乘客 103（12:00）和 101（16:30）最先预订，座位确认；102（17:45）是第三位，被列入等候名单。
- 航班 2 容量为 2，105（09:00）与 104（13:23）恰好占满两个座位，都得到确认。
- 航班 3 容量为 1。107（09:10）先订获得唯一位子；106（11:10）晚于他，进入等候名单。

## 题解

::: details 点击查看题解

### 思路

同一航班按预订时间先后分配座位：第 `k` 个预订的乘客，只要 `k ≤ 容量` 就确认，否则候补。因此按 `flight_id` 分区、`booking_time` 排序做排名，再与 `capacity` 比较即可，本质是「组内前 N 名」问题。

排名函数选 `RANK()` 还是 `ROW_NUMBER()` 都能通过：题目保证 `booking_time` 全表唯一，同一航班内不会出现并列，两者结果完全一致。若时间允许并列（同刻多人预订且都还有空位），`RANK()` 的名次会跳号，但按「名次不超过容量即确认」的口径，跳号只会让并列者整体落在同一侧，配合题面「只要还有空位就都可确认」的语义仍然自洽——这也是官方口径。

注意两点。其一，`Passengers` 与 `Flights` 是多对一关系，用 `JOIN ... ON` 把 `capacity` 带到每行上，不能用 `CROSS JOIN` 或漏连（漏连会丢航班）。其二，排名窗口写在 `CASE` 的分支里没有问题，`CASE` 不是窗口函数，不构成嵌套；但不能再对这个 `RANK()` 结果套一层 `OVER`。最后按 `passenger_id` 升序排列，输出列名为 `Status`。

### SQL 实现

```sql
SELECT
    p.passenger_id,
    CASE
        WHEN RANK() OVER (PARTITION BY p.flight_id ORDER BY p.booking_time) <= f.capacity
        THEN 'Confirmed'
        ELSE 'Waitlist'
    END AS Status
FROM Passengers AS p
JOIN Flights AS f ON f.flight_id = p.flight_id
ORDER BY p.passenger_id;
```

### 复杂度分析

- 时间复杂度：O(n log n)，窗口排序与最终排序，n 为乘客数。
- 空间复杂度：O(n)，窗口中间结果。
