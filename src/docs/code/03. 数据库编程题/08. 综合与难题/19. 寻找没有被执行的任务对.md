# 寻找没有被执行的任务对

> 难度：困难 | 标签：递归 CTE、多表连接 | [LeetCode 原题](https://leetcode.cn/problems/find-the-subtasks-that-did-not-execute/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

表：`Tasks`

| 列名 | 类型 |
| --- | --- |
| task_id | int |
| subtasks_count | int |

`task_id` 是该表的主键。该表的每一行表示任务 `task_id` 被拆分成了 `subtasks_count` 个子任务，子任务编号从 1 到 `subtasks_count`。可以保证 `2 <= subtasks_count <= 20`。

表：`Executed`

| 列名 | 类型 |
| --- | --- |
| task_id | int |
| subtask_id | int |

`(task_id, subtask_id)` 是该表的主键。该表的每一行表示任务 `task_id` 的子任务 `subtask_id` 被成功执行过。可以保证对每个 `task_id` 都有 `subtask_id <= subtasks_count`。

编写一个查询，报告每个任务中**未被执行**的子任务编号（`task_id`、`subtask_id`），结果顺序任意。

示例：

输入 `Tasks` 表：

| task_id | subtasks_count |
| --- | --- |
| 1 | 3 |
| 2 | 2 |
| 3 | 4 |

输入 `Executed` 表：

| task_id | subtask_id |
| --- | --- |
| 1 | 2 |
| 3 | 1 |
| 3 | 2 |
| 3 | 3 |
| 3 | 4 |

输出：

| task_id | subtask_id |
| --- | --- |
| 1 | 1 |
| 1 | 3 |
| 2 | 1 |
| 2 | 2 |

解释：

- 任务 1 拆成 3 个子任务（1、2、3），只有子任务 2 执行成功，因此输出 (1, 1)、(1, 3)；
- 任务 2 拆成 2 个子任务（1、2），没有任何子任务执行成功，因此输出 (2, 1)、(2, 2)；
- 任务 3 拆成 4 个子任务，全部执行成功，无需输出。

## 题解

::: details 点击查看题解

### 思路

`Tasks` 只记录"每个任务有几个子任务"，而结果要求的是**逐一列出**子任务编号，所以必须先把每个任务展开成 1 ~ subtasks_count 的多行——这是典型的"行内计数展开"，用递归 CTE 生成 1 ~ 20 的序号表（题面保证 `subtasks_count <= 20`），再按 `序号 <= subtasks_count` 与 `Tasks` 连接即可。

展开后，用左连接 `Executed` 并以 `e.task_id IS NULL` 过滤，剩下的就是未执行的组合。易错点：

- 序号表的上限要么写死 20（题面上界），要么动态取 `MAX(subtasks_count)`，写小了会漏行；
- 过滤条件要判断"连接不命中"，用 `WHERE e.task_id IS NULL`（或 `NOT EXISTS`），不能对 `subtask_id` 判 NULL——`Executed.subtask_id` 不会是 NULL；
- 输出按 `task_id`、`subtask_id` 排序便于对照（题目说任意顺序，排序更稳）。

替代写法：用两张小数字表交叉连接生成 1 ~ 100 的序列，可以避免递归；或者用 `NOT EXISTS` 逐行判断，但展开这一步无论如何都省不掉。

### SQL 实现

```sql
WITH RECURSIVE subtasks AS (
    SELECT 1 AS subtask_id
    UNION ALL
    SELECT subtask_id + 1
    FROM subtasks
    WHERE subtask_id < 20
)
SELECT t.task_id, s.subtask_id
FROM Tasks t
JOIN subtasks s ON s.subtask_id <= t.subtasks_count
LEFT JOIN Executed e
       ON e.task_id = t.task_id
      AND e.subtask_id = s.subtask_id
WHERE e.task_id IS NULL
ORDER BY t.task_id, s.subtask_id;
```

### 复杂度分析

- 时间复杂度：O(n × k)，n 为任务数、k 为子任务上限 20，展开与左连接近似线性。
- 空间复杂度：O(n × k)，用于存放展开后的组合。
