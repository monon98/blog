# 生成发票

> 难度：困难 | 标签：多表连接、分组聚合、子查询 | [LeetCode 原题](https://leetcode.cn/problems/generate-the-invoice/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

表：`Products`

```
+-------------+------+
| Column Name | Type |
+-------------+------+
| product_id  | int  |
| price       | int  |
+-------------+------+
product_id 包含唯一值。
该表中的每一行显示了一个产品的 ID 和一个单位价格。
```

表：`Purchases`

```
+-------------+------+
| Column Name | Type |
+-------------+------+
| invoice_id  | int  |
| product_id  | int  |
| quantity    | int  |
+-------------+------+
(invoice_id, product_id) 是该表的主键。
该表中的每一行显示了某张发票中的一种产品订购的数量。
```

编写解决方案，展示**价格最高的发票**的详细信息；如果两张或多张发票总价相同，则返回 `invoice_id` **最小**的那张发票的详细信息。

结果包含三列：`product_id`、`quantity`、`price`（其中 `price` = `quantity × 单位价格`，即该行的金额），以任意顺序返回。

**示例 1：**

输入：

```
Products 表：
+------------+-------+
| product_id | price |
+------------+-------+
| 1          | 100   |
| 2          | 200   |
+------------+-------+

Purchases 表：
+------------+------------+----------+
| invoice_id | product_id | quantity |
+------------+------------+----------+
| 1          | 1          | 2        |
| 3          | 2          | 1        |
| 2          | 2          | 3        |
| 2          | 1          | 4        |
| 4          | 1          | 10       |
+------------+------------+----------+
```

输出：

```
+------------+----------+-------+
| product_id | quantity | price |
+------------+----------+-------+
| 2          | 3        | 600   |
| 1          | 4        | 400   |
+------------+----------+-------+
```

解释：

- 发票 1：2 × 100 = 200
- 发票 2：4 × 100 + 3 × 200 = 1000
- 发票 3：1 × 200 = 200
- 发票 4：10 × 100 = 1000

最高总价为 1000，发票 2 和 4 并列，返回编号最小的发票 2 的两条明细。

## 题解

::: details 点击查看题解

### 思路

两步走：先在**发票粒度**上选出目标发票，再回**明细粒度**取该发票的行。把 `Purchases` 与 `Products` 连接得到每条明细的行金额（`quantity × price`）后，按 `invoice_id` 分组求和得到每张发票总价，`ORDER BY 总价 DESC, invoice_id LIMIT 1` 一步选出「总价最大且编号最小」的目标——`LIMIT` 配合二级排序是这类「Top-1 且带并列规则」最直接的写法；窗口函数 `ROW_NUMBER() OVER (ORDER BY amount DESC, invoice_id)` 写法等价，但多一层嵌套没有额外收益。

拿到目标 `invoice_id` 后再与明细连接取行即可。注意两个易错点：其一，输出列 `price` 是**行金额**（quantity × 单价），不是商品单价，别名虽然叫 price，也要重新计算；其二，并列规则必须写进排序（`ORDER BY amount DESC, invoice_id`），只按金额排序取第一行会随执行计划随机返回发票 2 或 4。中间结果我用 CTE `P` 同时承载明细与行金额，连接与汇总共用，避免重复 join。

### SQL 实现

```sql
WITH P AS (
    SELECT
        pu.invoice_id,
        pu.product_id,
        pu.quantity,
        pr.price AS unit_price
    FROM Purchases AS pu
    JOIN Products AS pr ON pr.product_id = pu.product_id
),
T AS (
    SELECT invoice_id
    FROM P
    GROUP BY invoice_id
    ORDER BY SUM(quantity * unit_price) DESC, invoice_id
    LIMIT 1
)
SELECT p.product_id, p.quantity, p.quantity * p.unit_price AS price
FROM P AS p
JOIN T AS t ON t.invoice_id = p.invoice_id;
```

### 复杂度分析

- 时间复杂度：O(m log m)，m 为明细行数；连接为 O(m)，发票分组排序主导复杂度。
- 空间复杂度：O(m)，CTE 中间结果。
