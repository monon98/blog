# 按年度列出销售总额

> 难度：困难 | 标签：递归 CTE、日期函数 | [LeetCode 原题](https://leetcode.cn/problems/total-sales-amount-by-year/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

表：`Product`

| 列名 | 类型 |
| --- | --- |
| product_id | int |
| product_name | varchar |

`product_id` 是该表的主键，`product_name` 是产品名称。

表：`Sales`

| 列名 | 类型 |
| --- | --- |
| product_id | int |
| period_start | date |
| period_end | date |
| average_daily_sales | int |

`product_id` 是该表的主键。`period_start` 与 `period_end` 表示该产品销售统计周期的开始与结束日期（两端均包含），`average_daily_sales` 表示该周期内每天的平均销售量。

编写一个查询，报告每个产品在每个日历年的总销售额，输出 `product_id`、`product_name`、`report_year` 与 `total_amount`。销售统计的年份范围在 2018 至 2020 年之间，结果按 `product_id`、`report_year` 升序排列。

总销售额 = 该周期与该年份交集的天数 × `average_daily_sales`。

示例：

输入 `Product` 表：

| product_id | product_name |
| --- | --- |
| 1 | LC Phone |
| 2 | LC T-Shirt |
| 3 | LC Keychain |

输入 `Sales` 表：

| product_id | period_start | period_end | average_daily_sales |
| --- | --- | --- | --- |
| 1 | 2019-01-25 | 2019-02-28 | 100 |
| 2 | 2018-12-01 | 2020-01-01 | 10 |
| 3 | 2019-12-01 | 2020-01-31 | 1 |

输出：

| product_id | product_name | report_year | total_amount |
| --- | --- | --- | --- |
| 1 | LC Phone | 2019 | 3500 |
| 2 | LC T-Shirt | 2018 | 310 |
| 2 | LC T-Shirt | 2019 | 3650 |
| 2 | LC T-Shirt | 2020 | 10 |
| 3 | LC Keychain | 2019 | 31 |
| 3 | LC Keychain | 2020 | 31 |

解释：

- LC Phone 的销售期为 2019-01-25 至 2019-02-28，共 35 天，总额 35 × 100 = 3500；
- LC T-Shirt 的销售期跨 2018-12-01 至 2020-01-01，三个年份分别有 31、365、1 天，总额为 310、3650、10；
- LC Keychain 的销售期跨 2019-12-01 至 2020-01-31，两个年份分别有 31、31 天，总额均为 31。

## 题解

::: details 点击查看题解

### 思路

本题要"按日历年拆分销售期"，本质是求两个日期区间的交集长度。核心公式：

```
交集天数 = DATEDIFF(LEAST(period_end, 年末), GREATEST(period_start, 年初)) + 1
```

只要某产品的销售期与年份有重叠（用 `BETWEEN YEAR(period_start) AND YEAR(period_end)` 筛选），交集就非空，`DATEDIFF` 结果 ≥ 0，`+1` 是因为 `DATEDIFF` 不含尾日。再乘 `average_daily_sales` 即为该年总额。

年份维度需要一张 2018、2019、2020 的小表，用递归 CTE 三行即可生成（也可以 `UNION ALL` 三条字面量，效果相同）；随后与 `Sales` 做带条件的连接，只保留有交集的年份，避免算出负天数。

易错点：

- 必须 `+1`：`DATEDIFF('2020-01-31', '2020-01-01')` 是 30，但实际有 31 天；
- 年初/年末要显式转成日期再参与 `LEAST/GREATEST`，用 `STR_TO_DATE` 拼 `年-01-01`、`年-12-31` 最稳妥；
- 只输出有重叠的年份：产品 1 只在 2019 年有销售，不能输出 2018/2020 的 0 行。

### SQL 实现

```sql
WITH RECURSIVE report_years AS (
    SELECT 2018 AS y
    UNION ALL
    SELECT y + 1 FROM report_years WHERE y < 2020
)
SELECT p.product_id,
       p.product_name,
       y.y AS report_year,
       s.average_daily_sales *
       (DATEDIFF(LEAST(s.period_end, STR_TO_DATE(CONCAT(y.y, '-12-31'), '%Y-%m-%d')),
                 GREATEST(s.period_start, STR_TO_DATE(CONCAT(y.y, '-01-01'), '%Y-%m-%d'))) + 1
       ) AS total_amount
FROM Sales s
JOIN Product p ON p.product_id = s.product_id
JOIN report_years y
       ON y.y BETWEEN YEAR(s.period_start) AND YEAR(s.period_end)
ORDER BY p.product_id, y.y;
```

### 复杂度分析

- 时间复杂度：O(n)，n 为销售记录数，年份表仅 3 行，连接近似一次扫描。
- 空间复杂度：O(n)，用于存放连接结果。
