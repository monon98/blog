# 职员招聘人数

> 难度：困难 | 标签：窗口函数、子查询、UNION | [LeetCode 原题](https://leetcode.cn/problems/the-number-of-seniors-and-juniors-to-join-the-company/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

表：`Candidates`

```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| employee_id | int     |
| experience  | enum    |
| salary      | int     |
+-------------+---------+
employee_id 是此表的主键列。
experience 是包含 'Senior'、'Junior' 两个值的枚举类型。
此表的每一行都显示候选人的 id、月薪和经验。
```

一家公司想雇佣新员工，公司的工资预算是 **70000 美元**。招聘标准是：

- 雇佣最多的高级（Senior）员工；
- 在雇佣最多的高级员工后，用剩余预算雇佣最多的初级（Junior）员工。

同一级别内应从薪水最低的开始雇佣，直到再雇佣不起为止。

编写一个 SQL 查询，查找按上述标准雇佣的高级员工和初级员工的数量。返回两列：`experience`、`accepted_candidates`，按任意顺序返回。

**示例 1：**

输入：

```
Candidates 表：
+-------------+------------+--------+
| employee_id | experience | salary |
+-------------+------------+--------+
| 1           | Junior     | 10000  |
| 9           | Junior     | 10000  |
| 2           | Senior     | 20000  |
| 11          | Senior     | 20000  |
| 13          | Senior     | 50000  |
| 4           | Junior     | 40000  |
+-------------+------------+--------+
```

输出：

```
+------------+---------------------+
| experience | accepted_candidates |
+------------+---------------------+
| Senior     | 2                   |
| Junior     | 2                   |
+------------+---------------------+
```

解释：

- 可以雇佣 2 名 ID 为 (2, 11) 的高级员工，工资合计 40000，还剩 30000，不足以雇佣 ID 为 13 的高级员工（50000）。
- 剩余 30000 预算可雇佣 2 名 ID 为 (1, 9) 的初级员工，工资合计 20000，还剩 10000，不足以雇佣 ID 为 4 的初级员工（40000）。

## 题解

::: details 点击查看题解

### 思路

预算固定 70000，且 Senior 绝对优先于 Junior，因此不能「两类混着按性价比挑」，必须分两段贪心：同类内部按工资升序录取，在预算内人数才最大；Junior 段的可用预算 = 70000 减去 Senior 段实际花掉的钱。

用窗口函数求前缀和即可表达「录到这个人时的累计支出」：`SUM(salary) OVER (ORDER BY salary ROWS UNBOUNDED PRECEDING)`。这里**必须显式写 `ROWS` 框架**——这是本题最大的坑：`ORDER BY salary` 的默认框架是 `RANGE`，会把工资**并列**的行算进同一个累计值。比如三人工资都是 30000、预算 70000，`RANGE` 下三人的累计都变成 90000，一个都录不上；正确答案是按 `ROWS` 逐行累加得到 30000 / 60000 / 90000，录取 2 人。本例数据里 Senior 恰好 20000、20000 并列，用默认框架算 Senior 的占用会得到 40000（碰巧一致），但 Junior 段会因此偏移，属于「样例能过、换数据就错」的典型。

结构上：CTE `s` 算 Senior 的逐行累计，筛 `cur <= 70000` 得到录取人数和实际占用（`MAX(cur)`，再用 `IFNULL(..., 0)` 兜底「一个 Senior 都录不上 / 表里没有 Senior」的情况）；CTE `j` 在 Junior 自身前缀和上叠加 Senior 占用，再筛 `cur <= 70000`；最后 `UNION ALL` 拼成两行。替代写法：先算出两类的累计和存临时表再连接，或用相关子查询逐人判断，但窗口前缀和是一趟扫描最简洁的。

### SQL 实现

```sql
WITH s AS (
    SELECT
        employee_id,
        SUM(salary) OVER (ORDER BY salary ROWS UNBOUNDED PRECEDING) AS cur
    FROM Candidates
    WHERE experience = 'Senior'
),
senior_used AS (
    SELECT IFNULL(MAX(cur), 0) AS used FROM s WHERE cur <= 70000
),
j AS (
    SELECT
        c.employee_id,
        su.used + SUM(c.salary) OVER (ORDER BY c.salary ROWS UNBOUNDED PRECEDING) AS cur
    FROM Candidates AS c
    CROSS JOIN senior_used AS su
    WHERE c.experience = 'Junior'
)
SELECT 'Senior' AS experience, COUNT(*) AS accepted_candidates
FROM s WHERE cur <= 70000
UNION ALL
SELECT 'Junior' AS experience, COUNT(*) AS accepted_candidates
FROM j WHERE cur <= 70000;
```

### 复杂度分析

- 时间复杂度：O(n log n)，排序求前缀和主导，n 为候选人数。
- 空间复杂度：O(n)，窗口中间结果。

:::
