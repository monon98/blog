# 合并在同一个大厅重叠的活动

> 难度：困难 | 标签：窗口函数、分组聚合 | [LeetCode 原题](https://leetcode.cn/problems/merge-overlapping-events-in-the-same-hall/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

表：`HallEvents`

```
+-------------+------+
| Column Name | Type |
+-------------+------+
| hall_id     | int  |
| start_day   | date |
| end_day     | date |
+-------------+------+
该表可能包含重复字段。
该表的每一行表示活动的开始日期、结束日期以及活动举行的大厅。
```

编写解决方案，合并在**同一个大厅**举行的所有重叠活动。如果两个活动**至少有一天相同**，那么它们就是重叠的。以任意顺序返回结果表，返回列 `hall_id`、`start_day`、`end_day`。不同大厅的活动互不干涉，分别处理。

**示例 1：**

输入：

```
HallEvents 表：
+---------+------------+------------+
| hall_id | start_day  | end_day    |
+---------+------------+------------+
| 1       | 2023-01-13 | 2023-01-14 |
| 1       | 2023-01-14 | 2023-01-17 |
| 1       | 2023-01-18 | 2023-01-25 |
| 2       | 2022-12-09 | 2022-12-23 |
| 2       | 2022-12-13 | 2022-12-17 |
| 3       | 2022-12-01 | 2023-01-30 |
+---------+------------+------------+
```

输出：

```
+---------+------------+------------+
| hall_id | start_day  | end_day    |
+---------+------------+------------+
| 1       | 2023-01-13 | 2023-01-17 |
| 1       | 2023-01-18 | 2023-01-25 |
| 2       | 2022-12-09 | 2022-12-23 |
| 3       | 2022-12-01 | 2023-01-30 |
+---------+------------+------------+
```

解释：

- 大厅 1：`[01-13, 01-14]` 与 `[01-14, 01-17]` 共享 01-14 这一天，合并为 `[01-13, 01-17]`；`[01-18, 01-25]` 与前者没有任何共同日期（01-17 与 01-18 相邻但不重叠），单独保留。
- 大厅 2：`[12-09, 12-23]` 与 `[12-13, 12-17]` 完全重叠，合并后仍是 `[12-09, 12-23]`。
- 大厅 3：只有一个活动，原样返回。

## 题解

::: details 点击查看题解

### 思路

经典的「区间合并」问题，但要用纯窗口函数一次成形，关键在于**段的判定依据**。按大厅分区、按开始日期排序后，维护一个「到当前行为止的最晚结束日」`MAX(end_day) OVER (... ORDER BY start_day)`（运行最大值），再用 `LAG` 取上一行的该值 `prev_max`：若当前 `start_day > prev_max`，说明与前面所有区间都没有共同日期，开一个新段；否则并入当前段。首行 `LAG` 为 NULL，`CASE` 里要把它显式当作新段。

两个易错点。其一，判定必须用**运行最大值**而非「上一行的 end_day」：区间 `[1,10] [2,3] [5,6]` 中第三行的上一行 end_day 是 3，`5 > 3` 会误开新段，而运行最大值是 10，`5 ≤ 10` 正确并入。其二，重叠判定是 `start_day <= prev_max`（**取等号**）：`[01-13,01-14]` 与 `[01-14,01-17]` 共享 01-14 当天，`=` 就是重叠；写成 `<` 会漏合并，写成 `start_day <= prev_max + 1`（允许相邻）又会把大厅 1 的 `[01-18,...` 错误粘上。

分组时把段首标记（0/1）做窗口累加 `SUM(...) OVER (...)` 得到段号 `gid`——注意段首判定里已经用了 `LAG`，**窗口函数不能嵌套**，必须拆成两个 CTE 先算 `prev_max` 再累加。最后按 (`hall_id`, `gid`) 分组取 `MIN(start_day)` 与 `MAX(end_day)` 即为合并后的区间（`MAX(end_day)` 而非末行的 `end_day`，因为段内最后一个区间的结束日未必最晚）。

### SQL 实现

```sql
WITH S AS (
    SELECT
        hall_id,
        start_day,
        end_day,
        MAX(end_day) OVER (PARTITION BY hall_id ORDER BY start_day) AS max_end
    FROM HallEvents
),
L AS (
    SELECT
        hall_id,
        start_day,
        end_day,
        LAG(max_end) OVER (PARTITION BY hall_id ORDER BY start_day) AS prev_max
    FROM S
),
G AS (
    SELECT
        hall_id,
        start_day,
        end_day,
        SUM(CASE WHEN prev_max IS NULL OR start_day > prev_max THEN 1 ELSE 0 END)
            OVER (PARTITION BY hall_id ORDER BY start_day) AS gid
    FROM L
)
SELECT hall_id, MIN(start_day) AS start_day, MAX(end_day) AS end_day
FROM G
GROUP BY hall_id, gid;
```

### 复杂度分析

- 时间复杂度：O(n log n)，按大厅与开始日期排序，n 为活动数。
- 空间复杂度：O(n)，三层窗口中间结果。

:::
