# 寻找环形礼物交换链

> 难度：困难 | 标签：递归 CTE、窗口函数 | [LeetCode 原题](https://leetcode.cn/problems/find-circular-gift-exchange-chains/)

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

## 题目描述

表：`SecretSanta`

```
+-------------+------+
| Column Name | Type |
+-------------+------+
| giver_id    | int  |
| receiver_id | int  |
| gift_value  | int  |
+-------------+------+
(giver_id, receiver_id) 是该表的主键。
该表的每一行代表两名员工之间的一次礼物交换：giver_id 是送出礼物的员工，receiver_id 是收到礼物的员工，gift_value 是礼物的价值。
```

编写一个查询，找出 Secret Santa 礼物交换中**环形链**的总礼物价值与链长：

环形链定义为一系列满足以下条件的交换：

- 每位员工恰好给另一位员工送出一份礼物；
- 每位员工恰好收到另一位员工的一份礼物；
- 这些交换构成一个连续的闭环（例如员工 A 送 B、B 送 C、C 又送回 A）。

结果按 `chain_length`、`total_gift_value` **降序**排列；若不同链的 `chain_length` 与 `total_gift_value` 完全相同，该组合只保留一次。

**示例：**

输入：

```
SecretSanta 表：

+----------+-------------+------------+
| giver_id | receiver_id | gift_value |
+----------+-------------+------------+
| 1        | 2           | 20         |
| 2        | 3           | 30         |
| 3        | 1           | 40         |
| 4        | 5           | 25         |
| 5        | 4           | 35         |
+----------+-------------+------------+
```

输出：

```
+----------+--------------+------------------+
| chain_id | chain_length | total_gift_value |
+----------+--------------+------------------+
| 1        | 3            | 90               |
| 2        | 2            | 60               |
+----------+--------------+------------------+
```

解释：

- 链 1 包含员工 1、2、3：1 送给 2、2 送给 3、3 送回 1，总价值 = 20 + 30 + 40 = 90，链长 3；
- 链 2 包含员工 4、5：4 送给 5、5 送回 4，总价值 = 25 + 35 = 60，链长 2。

## 题解

::: details 点击查看题解

### 思路

「每人只送一次、只收一次」意味着交换关系构成若干个**互不相交的有向环**。SQL 中沿边走环的标准手法是递归 CTE：

1. **基准行**：每条交换都作为起点，带上 `start_id = giver_id`；
2. **递归延伸**：`SecretSanta.giver_id = 上一行.receiver_id` 继续往下走，同时用 `giver_id != start_id` 挡住「回到起点」的那一步——这样递归在闭合前停止，每个环内的每条边都恰好被展开一次；
3. **按起点聚合**：同一环上以不同员工为起点的行会得到**相同的** `(chain_length, total_gift_value)`，所以先 `DISTINCT` 去重（题目要求重复组合只保留一次）；
4. **生成链编号**：按链长、总价值降序 `RANK() OVER (...)` 得到 `chain_id`，再外层 `ORDER BY` 输出。

注意 `RANK()` 在并列时会给相同排名，而题目的「去重」发生在 `(chain_length, total_gift_value)` 维度上，因此恰好一一对应。


### SQL 实现

```sql
WITH RECURSIVE Chains AS (
    SELECT giver_id,
           receiver_id,
           gift_value,
           giver_id AS start_id
    FROM SecretSanta
    UNION ALL
    SELECT s.giver_id,
           s.receiver_id,
           s.gift_value,
           c.start_id
    FROM SecretSanta s
    INNER JOIN Chains c ON s.giver_id = c.receiver_id
    WHERE s.giver_id != c.start_id
),
ChainSummary AS (
    SELECT start_id,
           COUNT(*) AS chain_length,
           SUM(gift_value) AS total_gift_value
    FROM Chains
    GROUP BY start_id
),
UniqueChains AS (
    SELECT DISTINCT chain_length, total_gift_value
    FROM ChainSummary
)
SELECT RANK() OVER (ORDER BY chain_length DESC, total_gift_value DESC) AS chain_id,
       chain_length,
       total_gift_value
FROM UniqueChains
ORDER BY chain_length DESC, total_gift_value DESC;
```

### 复杂度分析

- **时间复杂度**：`O(n log n)`，递归展开为 `O(n)`（`n` 为交换条数），排序与去重带对数开销。
- **空间复杂度**：`O(n)`，递归 CTE 的中间结果。

注意：MySQL 默认 `cte_max_recursion_depth = 1000`，本题员工数上限 1000，最长环需要 999 次递归，刚好在限制之内；若数据规模更大，可先执行 `SET SESSION cte_max_recursion_depth = 100000;`。
:::
