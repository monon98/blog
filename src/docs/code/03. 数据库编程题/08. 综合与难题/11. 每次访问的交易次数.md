# 每次访问的交易次数

> 难度：困难 | 标签：递归 CTE、多表连接 | [LeetCode 原题](https://leetcode.cn/problems/number-of-transactions-per-visit/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

表：`Visits`

| 列名 | 类型 |
| --- | --- |
| user_id | int |
| visit_date | date |

`(user_id, visit_date)` 是该表的主键。该表的每一行表示用户 `user_id` 在 `visit_date` 到访了银行。

表：`Transactions`

| 列名 | 类型 |
| --- | --- |
| user_id | int |
| transaction_date | date |
| amount | int |

该表没有主键，可能包含重复行。每一行表示用户 `user_id` 在 `transaction_date` 完成了一笔金额为 `amount` 的交易。可以保证该用户在 `transaction_date` 当天一定在 `Visits` 表中有一行记录（即每次交易都对应一次到访）。

某银行想绘制一张图表，展示"一次到访中完成的交易笔数"与"完成该笔数交易的到访次数"之间的关系。

编写一个查询，统计：

- `transactions_count`：一次到访中完成的交易笔数；
- `visits_count`：完成 `transactions_count` 笔交易的到访次数。

`transactions_count` 需要覆盖从 0 到所有到访中最大交易笔数的**每一个整数值**（即使某个笔数没有到访命中，也要输出一行，`visits_count` 为 0），结果按 `transactions_count` 升序排列。

示例：

输入 `Visits` 表：

| user_id | visit_date |
| --- | --- |
| 1 | 2020-01-01 |
| 2 | 2020-01-02 |
| 12 | 2020-01-01 |
| 19 | 2020-01-03 |
| 1 | 2020-01-02 |
| 2 | 2020-01-03 |
| 1 | 2020-01-04 |
| 7 | 2020-01-11 |
| 9 | 2020-01-25 |
| 8 | 2020-01-28 |

输入 `Transactions` 表：

| user_id | transaction_date | amount |
| --- | --- | --- |
| 1 | 2020-01-02 | 120 |
| 2 | 2020-01-03 | 22 |
| 7 | 2020-01-11 | 232 |
| 1 | 2020-01-04 | 7 |
| 9 | 2020-01-25 | 33 |
| 9 | 2020-01-25 | 66 |
| 8 | 2020-01-28 | 1 |
| 9 | 2020-01-25 | 99 |

输出：

| transactions_count | visits_count |
| --- | --- |
| 0 | 4 |
| 1 | 5 |
| 2 | 0 |
| 3 | 1 |

解释：

- `transactions_count = 0`：到访 (1, 2020-01-01)、(2, 2020-01-02)、(12, 2020-01-01)、(19, 2020-01-03) 没有任何交易，共 4 次；
- `transactions_count = 1`：到访 (1, 2020-01-02)、(2, 2020-01-03)、(1, 2020-01-04)、(7, 2020-01-11)、(8, 2020-01-28) 各完成 1 笔交易，共 5 次；
- `transactions_count = 2`：没有到访恰好完成 2 笔交易，但仍需输出 `visits_count = 0`；
- `transactions_count = 3`：到访 (9, 2020-01-25) 完成了 3 笔交易，共 1 次；
- 最大笔数为 3，因此到 3 为止结束。

## 题解

::: details 点击查看题解

### 思路

第一步统计每次到访的交易笔数：以 `Visits` 为主表，按 `(user_id, visit_date)` 左连接 `Transactions`（交易日期 = 到访日期），`COUNT(交易金额)` 即为该次到访的交易数——没有交易的到访连接不上，`COUNT` 忽略 NULL，天然得到 0。

第二步是本题的核心难点：**补齐 0 到最大值之间的所有整数**。直接 `GROUP BY 交易笔数` 只会输出出现过的值，样例中缺少的 `transactions_count = 2` 就丢了。解决办法是用递归 CTE 造一张 0, 1, 2, …, max 的序号表（上界左连接 `MAX(txn_count)` 动态确定），再左连接到每次到访的统计结果上，`COUNT(到访日期)` 即为命中次数，没命中就是 0。

几个注意点：

- 只要 `WITH` 列表里有自引用的 CTE，关键字必须写成 `WITH RECURSIVE`，否则 MySQL 会把 `seq` 当成基表、直接报 `Table 'xxx.seq' doesn't exist`；
- 序号表的上界在递归里动态取 `MAX(txn_count)`（左连接另一个 CTE 即可），不用写死常数，也不会多出空行；
- 分母口径是"到访次数"而不是"用户数"，同一用户多次到访要分别计数；
- 最终必须 `ORDER BY transactions_count`，否则图表顺序错乱。

替代写法：用交叉连接两张小数字表（0-9 × 0-9）生成序列，可以完全避开递归，但可读性更差。

### SQL 实现

```sql
WITH RECURSIVE visit_txn AS (
    SELECT v.user_id,
           v.visit_date,
           COUNT(t.amount) AS txn_count
    FROM Visits v
    LEFT JOIN Transactions t
           ON t.user_id = v.user_id
          AND t.transaction_date = v.visit_date
    GROUP BY v.user_id, v.visit_date
),
max_count AS (
    SELECT MAX(txn_count) AS mx FROM visit_txn
),
seq AS (
    SELECT 0 AS n
    UNION ALL
    SELECT n + 1
    FROM seq
    JOIN max_count ON n < max_count.mx
)
SELECT s.n AS transactions_count,
       COUNT(v.visit_date) AS visits_count
FROM seq s
LEFT JOIN visit_txn v ON v.txn_count = s.n
GROUP BY s.n
ORDER BY s.n;
```

### 复杂度分析

- 时间复杂度：O(n log n)，n 为到访记录数，连接与分组主导；序号表长度不超过最大交易笔数。
- 空间复杂度：O(n + k)，k 为最大交易笔数，用于存放到访统计与序号序列。
