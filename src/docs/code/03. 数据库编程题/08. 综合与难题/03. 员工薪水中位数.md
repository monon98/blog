# 员工薪水中位数

> 难度：困难 | 标签：窗口函数、分组聚合 | [LeetCode 原题](https://leetcode.cn/problems/median-employee-salary/)

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

## 题目描述

表：`Employee`

```
+-----+------------+--------+
| Id  | Company    | Salary |
+-----+------------+--------+
| Id  | int        |        |
| Company | varchar |        |
| Salary  | int     |        |
+-----+------------+--------+
Id 是这张表的主键列。
这张表包含员工的 Id、所在公司以及薪水。
```

编写一个解决方案，找出 **每个公司薪水中位数所在的行**。计算中位数时，如果某公司的员工数为 **偶数**，中位数位置的两行都要返回；为奇数时只返回正中间那一行。 Bonus：不使用任何内置 SQL 函数（如 `AVG`）完成本题。

返回结果表 **无顺序要求**。

结果格式如下所示。

示例：

**输入：**

Employee 表：

+----+---------+--------+
| id | company | salary |
+----+---------+--------+
| 1  | A       | 2341   |
| 2  | A       | 341    |
| 3  | A       | 15     |
| 4  | A       | 15314  |
| 5  | A       | 451    |
| 6  | A       | 513    |
| 7  | B       | 15     |
| 8  | B       | 13     |
| 9  | B       | 1154   |
| 10 | B       | 1345   |
| 11 | B       | 1221   |
| 12 | B       | 234    |
| 13 | C       | 2345   |
| 14 | C       | 2645   |
| 15 | C       | 2645   |
| 16 | C       | 2652   |
| 17 | C       | 65     |
+----+---------+--------+

**输出：**

+----+---------+--------+
| id | company | salary |
+----+---------+--------+
| 5  | A       | 451    |
| 6  | A       | 513    |
| 12 | B       | 234    |
| 9  | B       | 1154   |
| 14 | C       | 2645   |
+----+---------+--------+

**解释：**

	- 公司 A 有 6 名员工，薪水升序为 15、341、451、513、2341、15314，中位数是第 3、4 位的 451（id 5）与 513（id 6）。

	- 公司 B 有 6 名员工，薪水升序为 13、15、234、1154、1221、1345，中位数是第 3、4 位的 234（id 12）与 1154（id 9）。

	- 公司 C 有 5 名员工，薪水升序为 65、2345、2645、2645、2652，中位数是第 3 位的 2645（id 14，同薪的另一行 id 15 位于第 4 位，不属于中位数位置）。

## 题解

::: details 点击查看题解

### 思路

「中位数所在的行」本质是按公司分组、按薪水排序后取 **中间位置**：偶数长度取第 `n/2` 和 `n/2 + 1` 位，奇数长度取第 `(n+1)/2` 位。统一写法是 `ROW_NUMBER() OVER (PARTITION BY company ORDER BY salary)` 得到组内序号 `rn`，`COUNT(*) OVER (PARTITION BY company)` 得到组内人数 `cnt`，再过滤 `(cnt+1) DIV 2 <= rn <= (cnt+2) DIV 2`（整数除法）。验证：`cnt=6` 时区间为 `[3,4]`，`cnt=5` 时为 `[3,3]`，均与题意一致。

也可以用「比自己薪水低的不同薪水数 < 2」的自连接语义：`WHERE (SELECT COUNT(DISTINCT salary) FROM Employee e2 WHERE e2.company = e1.company AND e2.salary < e1.salary) < 2`，这就是题目 Bonus 提倡的「不用内置函数」路线，但每行都要回表计数，数据大时明显更慢。

易错点一：排序必须按 `salary`，且同薪并列时结果要确定——`ROW_NUMBER` 会给同薪行不同序号，公司 C 的两个 2645 分占 rn=3、rn=4，只有 rn=3 的行入选；次级排序键加 `id` 后稳定命中官方输出的 id 14。若改用 `RANK`，两个 2645 会同拿 rn=3，两行都输出，与期望不符，所以本题要的是 `ROW_NUMBER` + `ORDER BY salary, id`。易错点二：边界用整数除法 `DIV`（或 `FLOOR/CEIL`），写成 `rn BETWEEN cnt/2 AND cnt/2+1` 在 `cnt=5` 时变成 `[2.5, 3.5]`，由于 rn 是整数恰好也只命中 3，但 `cnt=6` 时 `[3,4]` 虽对、`cnt=1` 时 `[0.5,1.5]` 也对——虽然碰巧能过，浮点边界依赖隐式转换，不如 `DIV` 清晰可靠。

### SQL 实现

```sql
WITH ranked AS (
    SELECT id, company, salary,
           ROW_NUMBER() OVER (
               PARTITION BY company
               ORDER BY salary, id
           ) AS rn,
           COUNT(*) OVER (PARTITION BY company) AS cnt
    FROM Employee
)
SELECT id, company, salary
FROM ranked
WHERE rn >= (cnt + 1) DIV 2
  AND rn <= (cnt + 2) DIV 2;
```

### 复杂度分析

- 时间复杂度：O(n log n)，n 为员工数，按公司分组排序主导。
- 空间复杂度：O(n)，中间结果保留全部行。
