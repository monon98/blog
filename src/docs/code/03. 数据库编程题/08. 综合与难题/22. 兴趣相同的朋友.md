# 兴趣相同的朋友

> 难度：困难 | 标签：多表连接、分组聚合、HAVING | [LeetCode 原题](https://leetcode.cn/problems/leetcodify-similar-friends/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

表：`Listens`

```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| user_id     | int     |
| song_id     | int     |
| day         | date    |
+-------------+---------+
该表没有主键，因此会存在重复的行。
该表的每一行表示用户 user_id 在 day 这一天收听了歌曲 song_id。
```

表：`Friendship`

```
+---------------+---------+
| Column Name   | Type    |
+---------------+---------+
| user1_id      | int     |
| user2_id      | int     |
+---------------+---------+
(user1_id, user2_id) 是该表的主键。
该表的每一行表示 user1_id 和 user2_id 是好友。
注意：user1_id < user2_id。
```

请写一段 SQL 查询获取**兴趣相同的朋友**。用户 x 和用户 y 是兴趣相同的朋友，需满足下述条件：

- 用户 x 和 y 是朋友，且
- 用户 x 和 y 在同一天内听了相同的歌曲，且数量大于等于三首。

结果表无需排序。注意：返回结果需与源数据表呈现方式相同（即始终满足 `user1_id < user2_id`）。

**示例 1：**

输入：

```
Listens 表：
+---------+---------+------------+
| user_id | song_id | day        |
+---------+---------+------------+
| 1       | 10      | 2021-03-15 |
| 1       | 11      | 2021-03-15 |
| 1       | 12      | 2021-03-15 |
| 2       | 10      | 2021-03-15 |
| 2       | 11      | 2021-03-15 |
| 2       | 12      | 2021-03-15 |
| 3       | 10      | 2021-03-15 |
| 3       | 11      | 2021-03-15 |
| 3       | 12      | 2021-03-15 |
| 4       | 10      | 2021-03-15 |
| 4       | 11      | 2021-03-15 |
| 4       | 13      | 2021-03-15 |
| 5       | 10      | 2021-03-16 |
| 5       | 11      | 2021-03-16 |
| 5       | 12      | 2021-03-16 |
+---------+---------+------------+

Friendship 表：
+----------+----------+
| user1_id | user2_id |
+----------+----------+
| 1        | 2        |
| 2        | 4        |
| 2        | 5        |
+----------+----------+
```

输出：

```
+----------+----------+
| user1_id | user2_id |
+----------+----------+
| 1        | 2        |
+----------+----------+
```

解释：

- 用户 1 和 2 是朋友，并且他们在同一天内都听了 10、11、12 三首歌，所以他们是兴趣相同的朋友。
- 用户 1 和 3 在同一天听了相同的三首歌，但他们不是朋友。
- 用户 2 和 4 是朋友，但他们同一天内听过相同歌曲的数量小于 3。
- 用户 2 和 5 是朋友，也都听了 10、11、12，但不在同一天。

## 题解

::: details 点击查看题解

### 思路

与「好友推荐」（1917）互为镜像：这题从**已存在的好友对**出发，而不是枚举所有用户对。以 `Friendship` 为主表，分别用 `user1_id`、`user2_id` 去连接 `Listens` 两次，得到「这对朋友在同一天听同一首歌」的配对行，再按（好友对、天）分组统计去重歌曲数，`HAVING COUNT(DISTINCT song_id) >= 3` 即可。

几个易错点：其一，`Listens` 没有主键可能有重复行，必须 `COUNT(DISTINCT song_id)`，否则重复记录会虚增数量；其二，`l1.day = l2.day` 必须写——示例里用户 2 和 5 听了完全相同的三首歌，只因不在同一天就不算（少写这个条件就会多输出 (2, 5)）；其三，连接时只匹配 `song_id` 与 `day`，不要误加 `l1.user_id <> l2.user_id` 之类多余约束，好友对本来就是两个用户。

输出方向天然正确：连接是从 `Friendship` 行出发的，`user1_id < user2_id` 由表保证，不需要再交换方向。但一对好友可能在**多个不同日期**都满足条件，分组粒度含 `day` 就会输出多行，因此最外层加 `DISTINCT` 去重（也可以先把聚合包一层子查询再 `SELECT DISTINCT`）。替代写法：把双向展开后与 1917 共用同一套「自连接 + 聚合」逻辑，再反选好友对。

### SQL 实现

```sql
SELECT DISTINCT f.user1_id, f.user2_id
FROM Friendship AS f
JOIN Listens AS l1 ON l1.user_id = f.user1_id
JOIN Listens AS l2 ON l2.user_id = f.user2_id
WHERE l1.song_id = l2.song_id AND l1.day = l2.day
GROUP BY f.user1_id, f.user2_id, l1.day
HAVING COUNT(DISTINCT l1.song_id) >= 3;
```

### 复杂度分析

- 时间复杂度：O(f · k²)，f 为好友对数，k 为单个用户单天的收听条数；连接后按好友对与天分组。
- 空间复杂度：O(f · k²)，分组产生的中间行数。
