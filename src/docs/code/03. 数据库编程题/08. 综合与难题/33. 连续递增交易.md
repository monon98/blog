# 连续递增交易

> 难度：困难 | 标签：窗口函数、连续区间分组 | [LeetCode 原题](https://leetcode.cn/problems/consecutive-transactions-with-increasing-amounts/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

表：`Transactions`

```
+------------------+------+
| 字段名            | 类型 |
+------------------+------+
| transaction_id   | int  |
| customer_id      | int  |
| transaction_date | date |
| amount           | int  |
+------------------+------+
```

`transaction_id` 是该表的主键。每行包含一笔交易的信息，其中 `(customer_id, transaction_date)` 唯一，同时记录了该客户的 `amount`（交易金额）。

编写一个 SQL 查询，找出**至少连续三天**交易金额 `amount` **递增**的客户，并返回 `customer_id`、连续交易期的起始日期和结束日期。一个客户可能有多组满足条件的连续交易，都要返回。结果按 `customer_id`、`consecutive_start`、`consecutive_end` 升序排列。

**示例 1：**

输入：

```
Transactions 表:
+----------------+-------------+------------------+--------+
| transaction_id | customer_id | transaction_date | amount |
+----------------+-------------+------------------+--------+
| 1              | 101         | 2023-05-01       | 100    |
| 2              | 101         | 2023-05-02       | 150    |
| 3              | 101         | 2023-05-03       | 200    |
| 4              | 102         | 2023-05-01       | 50     |
| 5              | 102         | 2023-05-03       | 100    |
| 6              | 102         | 2023-05-04       | 200    |
| 7              | 105         | 2023-05-01       | 100    |
| 8              | 105         | 2023-05-02       | 150    |
| 9              | 105         | 2023-05-03       | 200    |
| 10             | 105         | 2023-05-04       | 300    |
| 11             | 105         | 2023-05-12       | 250    |
| 12             | 105         | 2023-05-13       | 260    |
| 13             | 105         | 2023-05-14       | 270    |
+----------------+-------------+------------------+--------+
```

输出：

```
+-------------+-------------------+-----------------+
| customer_id | consecutive_start | consecutive_end |
+-------------+-------------------+-----------------+
| 101         | 2023-05-01        | 2023-05-03      |
| 105         | 2023-05-01        | 2023-05-04      |
| 105         | 2023-05-12        | 2023-05-14      |
+-------------+-------------------+-----------------+
```

解释：

- 客户 101 在 2023-05-01 至 2023-05-03 期间有连续三天金额递增的交易，返回一组。
- 客户 102 虽然有 3 笔交易，但 05-01 与 05-03 不是相邻的一天，不满足「连续三天」，不返回。
- 客户 105 有两组：05-01 至 05-04（连续四天递增）和 05-12 至 05-14（连续三天递增），都要返回。

## 题解

::: details 点击查看题解

### 思路

「连续 + 递增」需要同时满足两个条件：相邻两笔交易的日期差恰好为 1 天，且后一笔金额**严格大于**前一笔。用 `LAG` 窗口函数在客户分区内按日期排序取前一行的日期与金额，两个条件用 `AND` 一起判定：满足则当前行仍属于同一段（断点标记为 0），否则当前行开启新段（断点标记为 1）。

注意首行没有前一行，`LAG` 返回 `NULL`，比较结果为 `NULL`，`CASE` 会走 `ELSE` 分支标记为 1——这正是想要的：每段的第一行必须是断点，否则段号会从错误的位置开始。段号由断点标记做窗口前缀和 `SUM(brk) OVER (PARTITION BY customer_id ORDER BY transaction_date)` 累加得到。

这里有个容易踩的坑：**窗口函数不能嵌套**（MySQL 报错 3593），所以「先算 `LAG`、再对结果累加」必须拆成两个 CTE 串联，不能写在同一个 `SELECT` 里。最后按 (`customer_id`, 段号) 分组，用 `HAVING COUNT(*) >= 3` 过滤掉长度不足三天的段，取 `MIN`/`MAX` 日期即为连续期的起止，并按要求排序。

判定「连续」时必须用日期差为 1 而不是行号连续，因为同一客户可能存在交易中断的日期（如客户 105 在 05-04 与 05-12 之间的空档），空档处金额即使更大也不能续接上一段。

### SQL 实现

```sql
WITH C AS (
    SELECT
        customer_id,
        transaction_date,
        amount,
        CASE
            WHEN DATEDIFF(transaction_date, LAG(transaction_date) OVER (PARTITION BY customer_id ORDER BY transaction_date)) = 1
             AND amount > LAG(amount) OVER (PARTITION BY customer_id ORDER BY transaction_date)
            THEN 0
            ELSE 1
        END AS brk
    FROM Transactions
),
G AS (
    SELECT
        customer_id,
        transaction_date,
        SUM(brk) OVER (PARTITION BY customer_id ORDER BY transaction_date) AS gid
    FROM C
)
SELECT
    customer_id,
    MIN(transaction_date) AS consecutive_start,
    MAX(transaction_date) AS consecutive_end
FROM G
GROUP BY customer_id, gid
HAVING COUNT(*) >= 3
ORDER BY customer_id, consecutive_start, consecutive_end;
```

### 复杂度分析

- 时间复杂度：O(n log n)，窗口排序与分组聚合，n 为交易记录数。
- 空间复杂度：O(n)，两个 CTE 的中间结果。
