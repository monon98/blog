# 最大化商品

> 难度：困难 | 标签：分组聚合、数学运算 | [LeetCode 原题](https://leetcode.cn/problems/maximize-items/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

`Inventory` 表：

```
+----------------+---------+
| Column Name    | Type    |
+----------------+---------+
| item_id        | int     |
| item_type      | varchar |
| item_category  | varchar |
| square_footage | decimal |
+----------------+---------+
item_id 是这张表的唯一主键。
每一行包含一件商品的 ID、类型（prime_eligible / not_prime）、类别和占地面积。
```

仓库要在一个 **500,000 平方英尺**的仓库里尽可能多地存放商品，规则如下：

- 同一 `item_type` 下**所有商品构成一个完整组合**，只能整套存放：要么整套放进去，要么一套都不放。
- 优先存放 `prime_eligible` 组合，用不完的空间再尽可能多地存放 `not_prime` 组合。
- 商品数量必须是**整数**（组合数 × 该类型的商品件数）；`not_prime` 数量为 0 时也要输出 0。

返回 `item_type`、`item_count`，先输出 `prime_eligible` 再输出 `not_prime`，并按 `item_count` 降序排序。

**示例 1：**

输入：

```
Inventory 表：
+---------+----------------+---------------+----------------+
| item_id | item_type      | item_category | square_footage |
+---------+----------------+---------------+----------------+
| 1374    | prime_eligible | Watches       | 68.00          |
| 4245    | not_prime      | Art           | 26.40          |
| 5743    | prime_eligible | Software      | 325.00         |
| 8543    | not_prime      | Clothing      | 64.50          |
| 2556    | not_prime      | Shoes         | 15.00          |
| 2452    | prime_eligible | Scientific    | 85.00          |
| 3255    | not_prime      | Furniture     | 22.60          |
| 1672    | prime_eligible | Beauty        | 8.50           |
| 4256    | prime_eligible | Furniture     | 55.50          |
| 6325    | prime_eligible | Food          | 13.20          |
+---------+----------------+---------------+----------------+
```

输出：

```
+----------------+-------------+
| item_type      | item_count  |
+----------------+-------------+
| prime_eligible | 5400        |
| not_prime      | 8           |
+----------------+-------------+
```

解释：

- `prime_eligible` 共 6 件商品，占地面积合计 555.20（68 + 325 + 85 + 8.50 + 55.50 + 13.20），可存放 900 套，共 900 × 6 = 5400 件，占用 499,680 平方英尺。
- `not_prime` 共 4 件商品，占地面积合计 128.50（26.40 + 64.50 + 15.00 + 22.60），剩余空间 500,000 − 499,680 = 320，可存放 2 套，共 2 × 4 = 8 件。
- 输出按 `item_count` 降序排列。

## 题解

::: details 点击查看题解

### 思路

这是「整套打包」的容量分配问题，纯 SQL 计算分三步：**先聚合、再算 prime、最后算 not_prime**。

聚合阶段按 `item_type` 分组，得到每类的 `COUNT(*)`（一件数）与 `SUM(square_footage)`（一套占地）。用两个只带聚合、不带 `GROUP BY` 的 CTE（`prime`、`not_prime` 各恒产一行，`IFNULL` 兜底为 0）把这两组标量取出来，后面就能像常量一样参与运算。

prime 的组合数是 `FLOOR(500000 / 套占地)`，件数 = 组合数 × 件数。not_prime 的可用空间不是 500,000，而是**减去 prime 实际占用之后的余量**：`500000 - prime套占地 × FLOOR(500000 / prime套占地)`，再除以自己的套占地取下整。这里用减法而不是 `MOD` 求余，可以完全走十进制精确运算，避免浮点误差把 320 算成 319.99… 导致组合数少 1（`FLOOR` 一旦向下取整，结果就会差一整套）。

易错点：一是把「按件最大化」当成「按套最大化」，用 `FLOOR(500000 / 单件占地)` 分别算两类，会忽略题目「必须整套」的约束；二是除数为 0（某类型缺失）时直接除会报错，用 `IF(... = 0, 0, ...)` 或 `NULLIF` 挡住；三是忘记 not_prime 的余量要先扣 prime 占用；四是输出顺序，必须按 `item_count` 降序而不是按 `item_type` 降序（两者在本例恰好一致，靠数据看不出差别）。

替代写法：一次 `GROUP BY item_type` 后用窗口 `SUM(...) OVER ()` 共享全局量，或按官方题解用 `UNION ALL` 拼两个分支，本质相同。

### SQL 实现

```sql
WITH prime AS (
    SELECT IFNULL(SUM(square_footage), 0) AS prime_sq,
           IFNULL(COUNT(*), 0) AS prime_cnt
    FROM Inventory
    WHERE item_type = 'prime_eligible'
),
not_prime AS (
    SELECT IFNULL(SUM(square_footage), 0) AS np_sq,
           IFNULL(COUNT(*), 0) AS np_cnt
    FROM Inventory
    WHERE item_type = 'not_prime'
)
SELECT 'prime_eligible' AS item_type,
       IF(prime_sq = 0, 0, prime_cnt * FLOOR(500000 / prime_sq)) AS item_count
FROM prime
UNION ALL
SELECT 'not_prime',
       IF(np_sq = 0, 0,
          np_cnt * FLOOR(
              IF(prime_sq = 0, 500000,
                 500000 - prime_sq * FLOOR(500000 / prime_sq)) / np_sq))
FROM not_prime
JOIN prime
ORDER BY item_count DESC;
```

### 复杂度分析

- 时间复杂度：O(n)，两次条件聚合各扫一遍表。
- 空间复杂度：O(1)，聚合结果只有常数个标量。
