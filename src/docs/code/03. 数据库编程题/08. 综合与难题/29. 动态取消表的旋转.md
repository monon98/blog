# 动态取消表的旋转

> 难度：困难 | 标签：列转行、动态 SQL | [LeetCode 原题](https://leetcode.cn/problems/dynamic-unpivoting-of-a-table/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

表：`Products`

```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| product_id  | int     |
| store_name1 | int     |
| store_name2 | int     |
|     :       | int     |
| store_namen | int     |
+-------------+---------+
product_id 是该表的主键。
该表中的每一行表示该商品在 n 家不同商店中的价格。
如果商店中没有该商品，则该商店列的价格为 NULL。
不同测试用例的商店名称可能会不同。至少 1 家店，最多 30 家店。
```

**重要提示：** 这个问题针对的是对 SQL 有丰富经验的人。

请实现 `UnpivotProducts` 过程来重新组织 `Products` 表：使每一行包含一个商品的 id、销售该商品的商店名称以及该商品在该商店的价格。如果某个商品在某商店不可用，则**不要**输出该 `product_id` 与 `store` 组合的行。结果有三列：`product_id`、`store`、`price`。过程执行后返回结果表，按任意顺序返回。

**示例 1：**

输入：

```
Products 表：
+------------+----------+--------+------+------+
| product_id | LC_Store | Nozama | Shop | Souq |
+------------+----------+--------+------+------+
| 1          | 100      | NULL   | 110  | NULL |
| 2          | NULL     | 200    | NULL | 190  |
| 3          | NULL     | NULL   | 1000 | 1900 |
+------------+----------+--------+------+------+
```

输出：

```
+------------+----------+-------+
| product_id | store    | price |
+------------+----------+-------+
| 1          | LC_Store | 100   |
| 1          | Shop     | 110   |
| 2          | Nozama   | 200   |
| 2          | Souq     | 190   |
| 3          | Shop     | 1000  |
| 3          | Souq     | 1900  |
+------------+----------+-------+
```

解释：商品 1 在 LC_Store 和 Shop 有售，价格分别为 100、110；商品 2 在 Nozama 和 Souq 有售；商品 3 在 Shop 和 Souq 有售。价格为 NULL 的组合不出现在结果中。

## 题解

::: details 点击查看题解

### 思路

这是 2252（动态行转列）的逆操作：把「每店一列」还原成「每店一行」，并且丢掉价格为 NULL 的组合。难点同样是**列名事先未知**——商店名只存在于表头，只能去数据字典 `information_schema.columns` 里查，因此仍然要走动态 SQL（`PREPARE` / `EXECUTE` / `DEALLOCATE`）三件套。

做法：查出 `Products` 的所有列（`table_schema = DATABASE()` 限定当前库、`table_name = 'Products'`、排除 `product_id`），按 `ordinal_position` 即表中列序遍历，为每列生成一段 `SELECT product_id, '列名' AS store, 列名 AS price FROM Products WHERE 列名 IS NOT NULL`，再用 `GROUP_CONCAT(... SEPARATOR ' UNION ')` 拼成一条完整的 `UNION` 查询后执行。`WHERE 列名 IS NOT NULL` 同时完成「去掉无货组合」的过滤；每段内部按主键顺序扫表，段间顺序即列序（题目允许任意顺序，这样输出也稳定）。

三个易错点：其一，`GROUP_CONCAT` 拼 30 家店的 SQL 默认 1024 字节会被截断，必须先 `SET group_concat_max_len = 10000;`；其二，拼进字符串的列名要用单引号包成字符串字面量，字面量内的单引号按 SQL 标准双写（`''`）转义；其三，列名当标识符用时加反引号，避免撞上保留字。LeetCode 上要求把逻辑包进 `CREATE PROCEDURE UnpivotProducts() BEGIN ... END`，本页给出同逻辑的会话级可执行写法。

### SQL 实现

```sql
SET group_concat_max_len = 10000;
SELECT GROUP_CONCAT(
    CONCAT('SELECT product_id, ''', column_name, ''' AS store, `', column_name, '` AS price FROM Products WHERE `', column_name, '` IS NOT NULL')
    SEPARATOR ' UNION '
) INTO @sql
FROM information_schema.columns
WHERE table_schema = DATABASE()
  AND table_name = 'Products'
  AND column_name <> 'product_id'
ORDER BY ordinal_position;
PREPARE stmt FROM @sql;
EXECUTE stmt;
DEALLOCATE PREPARE stmt;
```

### 复杂度分析

- 时间复杂度：O(c · p)，c 为商店列数、p 为商品行数；每列扫一次表。
- 空间复杂度：O(c · p)，`UNION` 结果行数为所有非空价格格子数。
