# 游戏玩法分析 V

> 难度：困难 | 标签：子查询、多表连接、日期函数 | [LeetCode 原题](https://leetcode.cn/problems/game-play-analysis-v/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

表：`Activity`

| 列名 | 类型 |
| --- | --- |
| player_id | int |
| device_id | int |
| event_date | date |
| games_played | int |

`(player_id, event_date)` 是该表的主键。该表记录了某游戏的玩家活动：每一行表示某个玩家在某天用某个设备登录，并在退出前玩了若干局游戏（可能为 0 局）。

- 玩家的**安装日期（install date）**定义为该玩家首次登录的日期。
- 某日期 X 的**次日留存率（day 1 retention）**定义为：安装日期为 X、且在 X 的第二天再次登录的玩家数，除以安装日期为 X 的玩家数，结果保留两位小数。

编写一个查询，报告每个安装日期的安装玩家数（`installs`）和次日留存率（`Day1_retention`）。

示例：

输入 `Activity` 表：

| player_id | device_id | event_date | games_played |
| --- | --- | --- | --- |
| 1 | 2 | 2016-03-01 | 5 |
| 1 | 2 | 2016-03-02 | 6 |
| 2 | 3 | 2017-06-25 | 1 |
| 3 | 1 | 2016-03-01 | 0 |
| 3 | 4 | 2018-07-03 | 5 |

输出：

| install_dt | installs | Day1_retention |
| --- | --- | --- |
| 2016-03-01 | 2 | 0.50 |
| 2017-06-25 | 1 | 0.00 |

解释：

- 玩家 1 和玩家 3 都在 2016-03-01 安装，但只有玩家 1 在 2016-03-02 再次登录，因此 2016-03-01 的次日留存率为 1 / 2 = 0.50。
- 玩家 2 在 2017-06-25 安装，第二天没有登录，因此 2017-06-25 的次日留存率为 0 / 1 = 0.00。

## 题解

::: details 点击查看题解

### 思路

留存率 = 次日回访人数 / 当天安装人数，关键是先确定每个玩家的"安装日期"，即 `MIN(event_date) GROUP BY player_id`。得到每人的安装日期后，把它当作左表（每个安装日期一行代表一个安装玩家），再与 `Activity` 表按"同一玩家 + 事件日期恰好为安装日期的下一天"做左连接：连接上的行就是次日回访的玩家，最后按安装日期分组统计即可。

几个易错点：

- 分子分母都要以**安装玩家**为口径，不能直接拿 `Activity` 全表分组，否则同一玩家多次登录会被重复计入分母；
- 次日判断用 `DATE_ADD(install_dt, INTERVAL 1 DAY)`（或 `DATE_SUB(event_date, INTERVAL 1 DAY) = install_dt`），不要用 `DATEDIFF(...) = 1` 之外的模糊写法，跨月、跨年时字符串拼接容易出错；
- `COUNT(*)` 统计的是分母（该日期的安装人数），`COUNT(b.player_id)` 统计的是左连接命中的回访人数——用 `COUNT(某列)` 而不是 `SUM(CASE ...)` 可以天然忽略 NULL；
- 留存率要 `ROUND(..., 2)`，且除法在 MySQL 中不会整数截断，但仍建议显式四舍五入。

替代写法：先在窗口函数里用 `LEAD(event_date)` 判断次日是否登录，再按安装日期聚合；对这种"逐玩家判断"的场景两种写法等价，左连接写法更通用。

### SQL 实现

```sql
WITH first_login AS (
    SELECT player_id,
           MIN(event_date) AS install_dt
    FROM Activity
    GROUP BY player_id
)
SELECT f.install_dt,
       COUNT(*) AS installs,
       ROUND(COUNT(b.player_id) / COUNT(*), 2) AS Day1_retention
FROM first_login f
LEFT JOIN Activity b
       ON b.player_id = f.player_id
      AND b.event_date = DATE_ADD(f.install_dt, INTERVAL 1 DAY)
GROUP BY f.install_dt
ORDER BY f.install_dt;
```

### 复杂度分析

- 时间复杂度：O(n log n)，n 为活动记录数，分组与连接各需一次哈希/排序。
- 空间复杂度：O(p)，p 为不同玩家数，用于存放每人的安装日期。
