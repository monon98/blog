# 页面推荐Ⅱ

> 难度：困难 | 标签：多表连接、分组聚合 | [LeetCode 原题](https://leetcode.cn/problems/page-recommendations-ii/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

表：`Friendship`

| 列名 | 类型 |
| --- | --- |
| user1_id | int |
| user2_id | int |

`(user1_id, user2_id)` 是该表的主键。该表的每一行表示 `user1_id` 与 `user2_id` 是好友关系（好友关系是双向的）。

表：`Likes`

| 列名 | 类型 |
| --- | --- |
| user_id | int |
| page_id | int |

`(user_id, page_id)` 是该表的主键。该表的每一行表示 `user_id` 喜欢 `page_id`。

你正在为某社交网站实现一个页面推荐系统：如果某页面被 `user_id` 的**至少一位好友**喜欢，且 `user_id` 自己**没有**喜欢该页面，系统就会把这个页面推荐给 `user_id`。

编写一个查询，找出所有用户可能的页面推荐，每一行包含：

- `user_id`：被推荐的用户 ID；
- `page_id`：推荐给该用户的页面 ID；
- `friends_likes`：`user_id` 的好友中喜欢该页面的人数。

结果顺序任意。

示例：

输入 `Friendship` 表：

| user1_id | user2_id |
| --- | --- |
| 1 | 2 |
| 1 | 3 |
| 1 | 4 |
| 2 | 3 |
| 2 | 4 |
| 2 | 5 |
| 6 | 1 |

输入 `Likes` 表：

| user_id | page_id |
| --- | --- |
| 1 | 88 |
| 2 | 23 |
| 3 | 24 |
| 4 | 56 |
| 5 | 11 |
| 6 | 33 |
| 2 | 77 |
| 3 | 77 |
| 6 | 88 |

输出：

| user_id | page_id | friends_likes |
| --- | --- | --- |
| 1 | 77 | 2 |
| 1 | 23 | 1 |
| 1 | 24 | 1 |
| 1 | 56 | 1 |
| 1 | 33 | 1 |
| 2 | 24 | 1 |
| 2 | 56 | 1 |
| 2 | 11 | 1 |
| 2 | 88 | 1 |
| 3 | 88 | 1 |
| 3 | 23 | 1 |
| 4 | 88 | 1 |
| 4 | 77 | 1 |
| 4 | 23 | 1 |
| 5 | 77 | 1 |
| 5 | 23 | 1 |

解释：

- 以用户 1 为例：他的好友是 2、3、4、6；好友喜欢的页面有 23、24、56、33、77（用户 2 和 3 都喜欢 77，故 `friends_likes = 2`）；页面 88 因为用户 1 自己已经喜欢而不被推荐。
- 用户 6 的好友只有用户 1，用户 1 只喜欢页面 88，而用户 6 自己也喜欢 88，因此用户 6 没有任何推荐。
- 用户 2、3、4、5 同理。

## 题解

::: details 点击查看题解

### 思路

好友关系是双向的，第一步先把 `Friendship` 展开成"我 → 好友"的有向边：`user1_id AS user_id, user2_id AS friend_id` 与 `UNION ALL` 的反向各一半，这样每对好友产生两行。

第二步用"我 → 好友"连接 `Likes`，得到（我, 好友喜欢的页面）；再左连接 `Likes`（条件为同一用户 + 同一页面）判断**我自己是否也喜欢**——连接不命中的行才是合法推荐，用 `WHERE mine.page_id IS NULL` 过滤。

最后按 `(user_id, page_id)` 分组，`COUNT(DISTINCT friend_id)` 即为 `friends_likes`：同一页面可能被我的多位好友喜欢（样例中页面 77 被 2 号和 3 号同时喜欢），必须去重计数，直接 `COUNT(*)` 会把 (1, 77) 数成 2 行。

易错点：

- 好友关系双向展开不能漏，否则只有一半用户有推荐；
- "自己没喜欢"的判断必须用左连接 + NULL 过滤（或 `NOT EXISTS`），放在 `HAVING`/`GROUP BY` 之后再排除就晚了；
- 没有任何推荐的用户（如 6 号）不应出现在结果里，用内连接/过滤天然满足。

### SQL 实现

```sql
WITH friends AS (
    SELECT user1_id AS user_id, user2_id AS friend_id
    FROM Friendship
    UNION ALL
    SELECT user2_id AS user_id, user1_id AS friend_id
    FROM Friendship
)
SELECT f.user_id,
       l.page_id,
       COUNT(DISTINCT f.friend_id) AS friends_likes
FROM friends f
JOIN Likes l ON l.user_id = f.friend_id
LEFT JOIN Likes mine
       ON mine.user_id = f.user_id
      AND mine.page_id = l.page_id
WHERE mine.page_id IS NULL
GROUP BY f.user_id, l.page_id;
```

### 复杂度分析

- 时间复杂度：O(n log n)，n 为好友边数与点赞数之和，连接与分组主导。
- 空间复杂度：O(n)，用于存放展开后的好友关系。
