# 查找具有持续行为模式的用户

> 难度：困难 | 标签：窗口函数、分组聚合、日期函数 | [LeetCode 原题](https://leetcode.cn/problems/find-users-with-persistent-behavior-patterns/)

## 题目描述

表：`activity`

```
+--------------+---------+
| Column Name  | Type    |
+--------------+---------+
| user_id      | int     |
| action_date  | date    |
| action       | varchar |
+--------------+---------+
(user_id, action_date, action) 是这张表的主键（值互不相同）。
每一行代表一个用户在特定日期执行的具体操作。
```

根据以下定义，编写一个解决方案来识别 **行为稳定的用户**：

	- 一个用户如果存在一个 连续至少 5 天的行为序列满足以下条件，则认为他是 行为稳定 的：

		该用户在该期间 每天只执行了一个操作。

		- 这些连续的日子里，操作都是相同的。

	- 如果一个用户有多个符合条件的序列，只考虑 最长 的那条序列。

返回结果表按 `streak_length` **降序 **排序，然后按* *`user_id` **升序** 排序。

结果格式如下所示。

示例：

**输入：**

activity 表：

+---------+-------------+--------+
| user_id | action_date | action |
+---------+-------------+--------+
| 1       | 2024-01-01  | login  |
| 1       | 2024-01-02  | login  |
| 1       | 2024-01-03  | login  |
| 1       | 2024-01-04  | login  |
| 1       | 2024-01-05  | login  |
| 1       | 2024-01-06  | logout |
| 2       | 2024-01-01  | click  |
| 2       | 2024-01-02  | click  |
| 2       | 2024-01-03  | click  |
| 2       | 2024-01-04  | click  |
| 3       | 2024-01-01  | view   |
| 3       | 2024-01-02  | view   |
| 3       | 2024-01-03  | view   |
| 3       | 2024-01-04  | view   |
| 3       | 2024-01-05  | view   |
| 3       | 2024-01-06  | view   |
| 3       | 2024-01-07  | view   |
+---------+-------------+--------+

**输出：**

+---------+--------+---------------+------------+------------+
| user_id | action | streak_length | start_date | end_date   |
+---------+--------+---------------+------------+------------+
| 3       | view   | 7             | 2024-01-01 | 2024-01-07 |
| 1       | login  | 5             | 2024-01-01 | 2024-01-05 |
+---------+--------+---------------+------------+------------+

**解释：**

	- 用户 1：

		从 2024 年 1 月 1 日至 2024 年 1 月 5 日连续五天执行 login 操作

		- 每一天都恰好有一个操作，且操作相同

		- 连续长度 = 5（满足最小要求）

		- 行动在 2024-01-06 发生变化，结束连续计数

	- 用户 2：

		只连续执行了 4 天 click 操作

		- 不满足最小连续计数 5 天的要求

		- 从结果排除

	- 用户 3：

		连续 7 天执行了 view 操作

		- 这是此用户的最长有效序列

		- 包含在结果中

结果表按 streak_length 降序排序，然后按 user_id 升序排序。

## 题解

::: details 点击查看题解

### 思路

这是一道典型的「间隙与岛屿（gaps and islands）」问题，分三层处理：

1. **先把"每天只有一个操作"的日期挑出来**。主键是 `(user_id, action_date, action)`，同一天同一用户可能有多行（执行了多个不同操作），这样的日子不满足"每天只执行了一个操作"，不能进序列。因此先按 `user_id, action_date` 分组，`HAVING COUNT(*) = 1`，并用 `MAX(action)` 把仅有的那个操作取出来（分组后 `action` 已函数依赖于分组，用 `MAX` 只是为了通过 `ONLY_FULL_GROUP_BY` 检查）。
2. **给连续日期打组号**。在 `user_id + action` 维度内按 `action_date` 编行号 `rn`，再用 `DATE_SUB(action_date, INTERVAL rn DAY)` 作为分组键——连续日期的"日期减行号"是同一个常数，一旦断档（某天缺失或换了操作）该值就会突变，天然把每段连续序列切开。这就是岛屿的形成原理。
3. **聚合 + 取每人最长的岛**。按该分组键 `COUNT(*)` 得到 `streak_length`，`MIN/MAX(action_date)` 得到起止日期；过滤 `streak_length >= 5` 后，用 `ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY streak_length DESC, start_date ASC)` 保留每人最长的一条（题目要求只留最长序列）。

易错点：

- 第 1 步的 `HAVING COUNT(*) = 1` 不能省——如果某天有 2 个操作，即使这两个操作相同，那天也不能算作"只执行了一个操作"，且它应当打断序列；
- 换操作也会重置岛屿（用户 1 的 1 月 6 日是 `logout`），所以分组键里必须包含 `action`，只按日期减行号会在不同操作之间"连成一片"；
- 过滤 `>= 5` 应放在取最长序列之前，避免被同用户的短于 5 天的长序列干扰——严格说取最长后再过滤也可以，但语义上先过滤更稳（同长度平手时用 `start_date` 兜底保证结果确定）。

### SQL 实现

```sql
WITH daily AS (
    SELECT
        user_id,
        action_date,
        MAX(action) AS action
    FROM activity
    GROUP BY user_id, action_date
    HAVING COUNT(*) = 1
),
marked AS (
    SELECT
        user_id,
        action,
        action_date,
        ROW_NUMBER() OVER (
            PARTITION BY user_id, action
            ORDER BY action_date
        ) AS rn
    FROM daily
),
streaks AS (
    SELECT
        user_id,
        action,
        MIN(action_date) AS start_date,
        MAX(action_date) AS end_date,
        COUNT(*) AS streak_length
    FROM marked
    GROUP BY user_id, action, DATE_SUB(action_date, INTERVAL rn DAY)
    HAVING COUNT(*) >= 5
),
longest AS (
    SELECT
        user_id,
        action,
        streak_length,
        start_date,
        end_date,
        ROW_NUMBER() OVER (
            PARTITION BY user_id
            ORDER BY streak_length DESC, start_date ASC
        ) AS rk
    FROM streaks
)
SELECT user_id, action, streak_length, start_date, end_date
FROM longest
WHERE rk = 1
ORDER BY streak_length DESC, user_id ASC;
```

### 复杂度分析

- 时间复杂度：O(n log n)，n 为 activity 行数，主要来自两处窗口函数的排序（按用户、操作、日期排序）。
- 空间复杂度：O(n)，CTE 中需保存去重后的逐日记录与打组结果。
