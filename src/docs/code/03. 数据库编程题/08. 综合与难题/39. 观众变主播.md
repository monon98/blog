# 观众变主播

> 难度：困难 | 标签：窗口函数、多表连接、分组聚合 | [LeetCode 原题](https://leetcode.cn/problems/viewers-turned-streamers/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

`Sessions` 表：

```
+---------------+----------+
| Column Name   | Type     |
+---------------+----------+
| user_id       | int      |
| session_start | datetime |
| session_end   | datetime |
| session_id    | int      |
| session_type  | enum     |
+---------------+----------+
session_id 是这张表的唯一主键。
session_type 是枚举类型，取值为 Viewer、Streamer。
本表记录用户的每次会话及其类型。
```

编写一个解决方案，统计**首次会话是观众（Viewer）的用户，后来进行的直播（Streamer）会话数量**。

返回 `user_id`、`sessions_count` 两列，结果按 `sessions_count` 降序、`user_id` 降序排序。从未直播过的用户不出现在结果中。

**示例 1：**

输入：

```
Sessions 表：
+---------+---------------------+---------------------+------------+--------------+
| user_id | session_start       | session_end         | session_id | session_type |
+---------+---------------------+---------------------+------------+--------------+
| 101     | 2023-11-06 13:53:42 | 2023-11-06 14:05:42 | 375        | Viewer       |
| 101     | 2023-11-22 16:45:21 | 2023-11-22 20:39:21 | 594        | Streamer     |
| 102     | 2023-11-16 13:23:09 | 2023-11-16 16:10:09 | 777        | Streamer     |
| 102     | 2023-11-17 13:23:09 | 2023-11-17 16:10:09 | 778        | Streamer     |
| 101     | 2023-11-20 07:16:06 | 2023-11-20 08:33:06 | 315        | Streamer     |
| 104     | 2023-11-27 03:10:49 | 2023-11-27 03:30:49 | 797        | Viewer       |
| 103     | 2023-11-27 03:10:49 | 2023-11-27 03:30:49 | 798        | Streamer     |
+---------+---------------------+---------------------+------------+--------------+
```

输出：

```
+---------+----------------+
| user_id | sessions_count |
+---------+----------------+
| 101     | 2              |
+---------+----------------+
```

解释：

- 用户 101 第一次会话是 2023-11-06 的 Viewer，之后有 2 次 Streamer 会话，计数为 2。
- 用户 102 有两次会话，但首次会话就是 Streamer，被排除。
- 用户 103 只有一次 Streamer 会话，没有 Viewer 首秀，排除。
- 用户 104 首次会话是 Viewer，但之后再无会话（0 次直播），排除。

## 题解

::: details 点击查看题解

### 思路

题目的资格判定只看一件事：**该用户按时间排序后的第一条会话是不是 Viewer**。这天然是窗口函数的活——`ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY session_start)`，`rn = 1` 的那一行就是首秀。

拿到「首秀为 Viewer 的用户集合」后，再回到 `Sessions` 数这些用户的 Streamer 会话条数。写法上可以把排名 CTE 与 `Sessions` 自连接（`rn = 1 AND t.session_type = 'Viewer'` 决定资格，`s.session_type = 'Streamer'` 决定计数对象），也可以先用子查询筛出合格 `user_id` 再 `WHERE user_id IN (...)`。注意资格判定和计数必须分开：不能在同一个过滤条件里写 `session_type = 'Viewer' AND session_type = 'Streamer'`，也不能只按「有过 Viewer 又有过 Streamer」判断——本例用户 102 若先直播后观看（本题数据里 102 首秀即 Streamer），按「两种都有」算就会错判，必须以**首次**会话类型为准。

自然，从未直播过的用户（104）不会被 `WHERE session_type = 'Streamer'` 产出，因而不会出现 `sessions_count = 0` 的行，与题意一致。排序别忘了二级键 `user_id DESC`。

易错点：一是用 `MIN(session_type)` 之类字符串比较代替时间排序（'Streamer' < 'Viewer' 字典序，会完全颠倒结果）；二是 `RANK()` 遇到首秀时间完全相同时会给多行都标 1，本题用 `ROW_NUMBER()` 更稳妥；三是聚合后漏掉 `GROUP BY user_id`。

### SQL 实现

```sql
WITH first_sessions AS (
    SELECT user_id,
           session_type,
           ROW_NUMBER() OVER (
               PARTITION BY user_id
               ORDER BY session_start
           ) AS rn
    FROM Sessions
)
SELECT s.user_id,
       COUNT(*) AS sessions_count
FROM Sessions AS s
JOIN first_sessions AS f
  ON f.user_id = s.user_id
 AND f.rn = 1
 AND f.session_type = 'Viewer'
WHERE s.session_type = 'Streamer'
GROUP BY s.user_id
ORDER BY sessions_count DESC, s.user_id DESC;
```

### 复杂度分析

- 时间复杂度：O(n log n)，n 为会话行数，窗口排序与连接分组各占一次。
- 空间复杂度：O(n)，排名 CTE 需要保存全部会话的序号。
