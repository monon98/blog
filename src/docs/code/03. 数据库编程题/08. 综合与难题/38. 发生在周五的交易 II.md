# 发生在周五的交易 II

> 难度：困难 | 标签：递归 CTE、日期函数、分组聚合 | [LeetCode 原题](https://leetcode.cn/problems/friday-purchases-ii/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

`Purchases` 表：

```
+---------------+------+
| Column Name   | Type |
+---------------+------+
| user_id       | int  |
| purchase_date | date |
| amount_spend  | int  |
+---------------+------+
(user_id, purchase_date, amount_spend) 是该表的联合主键。
purchase_date 的范围是 2023 年 11 月 1 日到 2023 年 11 月 30 日。
每一行记录一个用户在某天的消费金额。
```

编写一个查询，计算 2023 年 11 月**每个周**里**周五**的消费总额。与「发生在周五的交易 I」不同，**当某个周五没有任何交易时，消费总额按 `0` 输出**（即 11 月的每个周五都要出现一行）。

返回列：`week_of_month`（当月第几周，从 1 开始）、`purchase_date`（该周五的日期）、`total_amount`（当天消费总额），按 `week_of_month` 升序排列。

**示例 1：**

输入：

```
Purchases 表：
+---------+---------------+--------------+
| user_id | purchase_date | amount_spend |
+---------+---------------+--------------+
| 11      | 2023-11-07    | 1126         |
| 15      | 2023-11-30    | 7473         |
| 17      | 2023-11-14    | 2414         |
| 12      | 2023-11-24    | 9692         |
| 8       | 2023-11-03    | 5117         |
| 1       | 2023-11-16    | 5241         |
| 10      | 2023-11-12    | 8266         |
| 13      | 2023-11-24    | 12000        |
+---------+---------------+--------------+
```

输出：

```
+---------------+---------------+--------------+
| week_of_month | purchase_date | total_amount |
+---------------+---------------+--------------+
| 1             | 2023-11-03    | 5117         |
| 2             | 2023-11-10    | 0            |
| 3             | 2023-11-17    | 0            |
| 4             | 2023-11-24    | 21692        |
+---------------+---------------+--------------+
```

解释：

- 第 1 周周五 2023-11-03：只有 8 号用户一笔 5117。
- 第 2 周周五 2023-11-10、第 3 周周五 2023-11-17：没有任何交易，按 `0` 输出。
- 第 4 周周五 2023-11-24：9692 + 12000 = 21692。
- 2023-11-07、11-14、11-16、11-12、11-30 都不是周五，不参与统计。

## 题解

::: details 点击查看题解

### 思路

这题与 I 的唯一区别是「空周五也要输出 0」。直接从 `Purchases` 出发过滤 + 分组是做不到的——没有交易的日期根本不在表里，聚合之后整行会消失。所以必须先**造出完整的日期骨架**，再左连接实际消费。

骨架用递归 CTE 生成 2023-11-01 到 2023-11-30 的每一天：锚定成员取月初日期，递归成员每次 `+ INTERVAL 1 DAY`，直到 11-30 为止（注意递归条件写 `purchase_date < '2023-11-30'`，这样 30 日本身也会被生成，且递归在第 30 天停止）。然后用 `DAYOFWEEK(purchase_date) = 6` 筛出周五，`LEFT JOIN Purchases` 后 `IFNULL(SUM(amount_spend), 0)` 把空日期补成 0。

周内序号沿用「1—7 日为第 1 周」的口径：`CEIL(DAYOFMONTH(purchase_date) / 7)`，3 号落在第 1 周、10 号第 2 周、17 号第 3 周、24 号第 4 周。

易错点：一是 `DAYOFWEEK()` 把周日当作 1、周五是 6，与 `WEEKDAY()`（周一为 0、周五为 4）混淆会少筛一天；二是左连接的条件必须用日期而不是周号（仅按周号连接会在同周多笔交易时产生笛卡尔放大）；三是直接 `GROUP BY` 日期时，`week_of_month` 必须放进 `GROUP BY` 或放进子查询，避免 `ONLY_FULL_GROUP_BY` 报错；四是递归终止条件写成 `<= '2023-11-30'` 会导致多生成 12-01，虽然被周五过滤救回来，但写法不严谨。

替代写法：不用日期骨架，先用递归 CTE 直接生成 4 个周五（首个周五 11-03 起每次 `+ INTERVAL 7 DAY`），再左连接消费，结果一致且更省一步。

### SQL 实现

```sql
WITH RECURSIVE dates AS (
    SELECT CAST('2023-11-01' AS DATE) AS purchase_date
    UNION ALL
    SELECT purchase_date + INTERVAL 1 DAY
    FROM dates
    WHERE purchase_date < '2023-11-30'
),
fridays AS (
    SELECT purchase_date,
           CEIL(DAYOFMONTH(purchase_date) / 7) AS week_of_month
    FROM dates
    WHERE DAYOFWEEK(purchase_date) = 6
)
SELECT f.week_of_month,
       f.purchase_date,
       IFNULL(SUM(p.amount_spend), 0) AS total_amount
FROM fridays AS f
LEFT JOIN Purchases AS p ON p.purchase_date = f.purchase_date
GROUP BY f.week_of_month, f.purchase_date
ORDER BY f.week_of_month;
```

### 复杂度分析

- 时间复杂度：O(d + k log k)，d 为骨架日期数（30），k 为周五个数（4），分组聚合在极小结果集上完成。
- 空间复杂度：O(d)，递归 CTE 物化整月日期。
