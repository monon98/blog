# 市场分析 II

> 难度：困难 | 标签：窗口函数、子查询 | [LeetCode 原题](https://leetcode.cn/problems/market-analysis-ii/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

表：`Users`

| 列名 | 类型 |
| --- | --- |
| user_id | int |
| join_date | date |
| favorite_brand | varchar |

`user_id` 是该表的主键。该表包含某购物网站买家与卖家的信息。

表：`Orders`

| 列名 | 类型 |
| --- | --- |
| order_id | int |
| order_date | date |
| item_id | int |
| buyer_id | int |
| seller_id | int |

`order_id` 是该表的主键，`item_id` 是外键（指向 `Items` 表），`buyer_id` 和 `seller_id` 是外键（指向 `Users` 表）。

表：`Items`

| 列名 | 类型 |
| --- | --- |
| item_id | int |
| item_brand | varchar |

`item_id` 是该表的主键。

编写一个查询，判断每个用户卖出的**第二件商品（按日期）**的品牌是否是其最喜爱的品牌。如果一个用户卖出的商品少于两件，则该用户的结果记为 `no`。

可以保证：同一个卖家在同一天不会卖出一件以上的商品。

结果格式如下例所示。

示例：

输入 `Users` 表：

| user_id | join_date | favorite_brand |
| --- | --- | --- |
| 1 | 2019-01-01 | Lenovo |
| 2 | 2019-02-09 | Samsung |
| 3 | 2019-01-19 | LG |
| 4 | 2019-05-21 | HP |

输入 `Orders` 表：

| order_id | order_date | item_id | buyer_id | seller_id |
| --- | --- | --- | --- | --- |
| 1 | 2019-08-01 | 4 | 1 | 2 |
| 2 | 2019-08-02 | 2 | 1 | 3 |
| 3 | 2019-08-03 | 3 | 2 | 3 |
| 4 | 2019-08-04 | 1 | 4 | 2 |
| 5 | 2019-08-04 | 1 | 3 | 4 |
| 6 | 2019-08-05 | 2 | 2 | 4 |

输入 `Items` 表：

| item_id | item_brand |
| --- | --- |
| 1 | Samsung |
| 2 | Lenovo |
| 3 | LG |
| 4 | HP |

输出：

| seller_id | 2nd_item_fav_brand |
| --- | --- |
| 1 | no |
| 2 | yes |
| 3 | yes |
| 4 | no |

解释：

- 用户 1 没有卖出任何商品，结果为 `no`。
- 用户 2 和用户 3 卖出的第二件商品的品牌恰好是他们最喜爱的品牌，结果为 `yes`。
- 用户 4 卖出的第二件商品的品牌不是他最喜爱的品牌，结果为 `no`。

## 题解

::: details 点击查看题解

### 思路

"第二件（按日期）"天然是一个排名问题：以 `seller_id` 分区、按 `order_date` 升序编号，取 `rn = 2` 的那行就是每个卖家卖出的第二件商品。题目保证同一天不会卖出两件以上，所以按 `order_date` 排序即可确定唯一顺序，稳妥起见再加 `order_id` 做次级排序。

拿到第二件商品的品牌后，与 `Users.favorite_brand` 比较输出 `yes` / `no`。两个易错点：

- 必须以 `Users` 表为左表左连接排名结果——只卖出 0 件或 1 件的卖家没有 `rn = 2` 的行，左连接后为 `NULL`，`CASE` 落到 `ELSE 'no'` 分支，正好符合"少于两件记为 no"的要求；如果写成内连接，这类用户会整行消失；
- 结果要包含**所有用户**（包括从未卖出的 1 号），列名 `2nd_item_fav_brand` 以数字开头，在 SQL 中必须用反引号包裹。

另一种写法是用 `COUNT(*)` 统计卖出件数 + 相关子查询取第二件，但窗口函数一次扫描即可完成，是最优路径。

### SQL 实现

```sql
WITH ranked_orders AS (
    SELECT o.seller_id,
           i.item_brand,
           ROW_NUMBER() OVER (PARTITION BY o.seller_id
                              ORDER BY o.order_date, o.order_id) AS rk
    FROM Orders o
    JOIN Items i ON i.item_id = o.item_id
)
SELECT u.user_id AS seller_id,
       CASE WHEN r.item_brand = u.favorite_brand
            THEN 'yes' ELSE 'no' END AS `2nd_item_fav_brand`
FROM Users u
LEFT JOIN ranked_orders r
       ON r.seller_id = u.user_id
      AND r.rk = 2
ORDER BY u.user_id;
```

### 复杂度分析

- 时间复杂度：O(n log n)，n 为订单数，窗口排序主导。
- 空间复杂度：O(n)，用于存放排名后的订单。

:::
