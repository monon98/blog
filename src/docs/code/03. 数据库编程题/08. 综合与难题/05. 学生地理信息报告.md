# 学生地理信息报告

> 难度：困难 | 标签：窗口函数、分组聚合 | [LeetCode 原题](https://leetcode.cn/problems/students-report-by-geography/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

一所美国研究生院的学生来自亚洲（Asia）、欧洲（Europe）和美洲（America），学生信息存储在 `Student` 表中：

| name | continent |
| --- | --- |
| Jane | America |
| Pascal | Europe |
| Xi | Asia |
| Jack | America |

- `name`：学生姓名
- `continent`：学生所在大洲，取值为 `America`、`Asia`、`Europe`

编写一个查询，把 `continent` 列"透视"成三列：每个大洲的学生姓名按字母顺序依次排列，显示在对应大洲的下方。输出表头依次为 `America`、`Asia`、`Europe`。保证美洲的学生数量不少于其他任一大洲（因此以美洲的人数决定行数，其余大洲不足的行用 `NULL` 补齐）。

示例：

输入 `Student` 表如上，输出：

| America | Asia | Europe |
| --- | --- | --- |
| Jack | Xi | Pascal |
| Jane | NULL | NULL |

进阶：如果事先不知道哪个大洲的学生最多，还能写出生成学生报告的查询吗？

## 题解

::: details 点击查看题解

### 思路

这是一道经典的"行转列"透视题，难点在于三个大洲的人数不一致，需要把不同长度的姓名列表对齐到同一行。做法分两步：

1. 用 `ROW_NUMBER() OVER (PARTITION BY continent ORDER BY name)` 在每个大洲内部按字母序编号，得到行号 `rn`；
2. 按 `rn` 分组，用 `MAX(CASE WHEN continent = 'America' THEN name END)` 这类条件聚合，把每个大洲第 `rn` 名的学生"挑"到对应列上。

由于同一个 `rn` 分组里每个大洲最多只有一行，`MAX` 就等价于取值（写 `MIN` 也一样），MySQL 不支持直接按条件取字符串，条件聚合是标准解法。

易错点：排序必须按 `name` 而不是按 `continent`，否则列内不是字母序；分组行数由 `ROW_NUMBER` 自动决定，行数等于人数最多的大洲，题目保证是美洲，所以不会丢行——这同时也回答了进阶问题：即使不知道哪个大洲最多，这种写法依然正确。

另一种写法是准备一张序号表，再用三个相关子查询分别取第 n 名，但需要额外造数，不如窗口函数 + 条件聚合简洁。

### SQL 实现

```sql
WITH ranked AS (
    SELECT name,
           continent,
           ROW_NUMBER() OVER (PARTITION BY continent ORDER BY name) AS rn
    FROM Student
)
SELECT MAX(CASE WHEN continent = 'America' THEN name END) AS America,
       MAX(CASE WHEN continent = 'Asia'    THEN name END) AS Asia,
       MAX(CASE WHEN continent = 'Europe'  THEN name END) AS Europe
FROM ranked
GROUP BY rn
ORDER BY rn;
```

### 复杂度分析

- 时间复杂度：O(n log n)，n 为学生人数，窗口排序与分组排序各占一次排序。
- 空间复杂度：O(n)，用于存放带行号的中间结果。

:::
