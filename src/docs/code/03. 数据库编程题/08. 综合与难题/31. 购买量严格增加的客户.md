# 购买量严格增加的客户

> 难度：困难 | 标签：窗口函数、分组聚合、子查询 | [LeetCode 原题](https://leetcode.cn/problems/customers-with-strictly-increasing-purchases/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

表：`Orders`

```
+--------------+------+
| Column Name  | Type |
+--------------+------+
| order_id     | int  |
| customer_id  | int  |
| order_date   | date |
| price        | int  |
+--------------+------+
order_id 是该表的主键。
每行包含订单的 id、下单客户 id、订单日期和价格。
```

编写一个 SQL 查询，报告**总购买量每年严格增加**的客户 id：

- 客户某一年的总购买量 = 该年所有订单价格之和；如果某一年该客户没有下任何订单，总购买量记为 **0**；
- 对每个客户，要考虑的第一个年份是其**首次下单**的年份，最后一个是其**最后一次下单**的年份（中间的每一年都要比较，包括没有下单的年份）。

以任意顺序返回结果表。

**示例 1：**

输入：

```
Orders 表：
+----------+-------------+------------+-------+
| order_id | customer_id | order_date | price |
+----------+-------------+------------+-------+
| 1        | 1           | 2019-07-01 | 1100  |
| 2        | 1           | 2019-11-01 | 1200  |
| 3        | 1           | 2020-05-26 | 3000  |
| 4        | 1           | 2021-08-31 | 3100  |
| 5        | 1           | 2022-12-07 | 4700  |
| 6        | 2           | 2015-01-01 | 700   |
| 7        | 2           | 2017-11-07 | 1000  |
| 8        | 3           | 2017-01-01 | 900   |
| 9        | 3           | 2018-11-07 | 900   |
+----------+-------------+------------+-------+
```

输出：

```
+-------------+
| customer_id |
+-------------+
| 1           |
+-------------+
```

解释：

- 客户 1：2019 年 1100 + 1200 = 2300，2020 年 3000，2021 年 3100，2022 年 4700，逐年严格增加，入选。
- 客户 2：首单年 2015、末单年 2017，2015 年 700、**2016 年 0**、2017 年 1000——2016 年为 0 并不比 700 大，不满足严格递增，落选（只看有订单的年份会误判为 700 → 1000 递增）。
- 客户 3：2017 年 900、2018 年 900，不严格，落选。

## 题解

::: details 点击查看题解

### 思路

本题最大的陷阱是「缺年 = 0」这条规则：直接按客户 + 年份聚合后用 `LAG` 比较相邻年份总额，客户 2 会被判成 700 → 1000 递增而**误入选**，因为它缺了 2016 年（总额为 0）这一环。与其构造年份序列去补齐 0（需要递归 CTE 或数字表，年份跨度还不可控），不如用一个巧妙的等价判定：**「年份 - 总额名次」对每个客户是否只有一个取值**。

证明直觉：对每个客户按年份聚合出各年总额后，按总额升序取 `RANK()`。若总额逐年严格递增且年份连续，则年份每 +1、名次也恰好 +1，`年份 - 名次` 恒定。反之只要出问题差值必变——总额出现并列（客户 3）时并列行同名次而年份不同；年份出现断档（客户 2，2015 → 2017 跳 2 年而名次只 +1）时差值 +1；总额逆序时名次随年份反向变化。三种违规场景都会让差值出现至少两个取值，因此 `COUNT(DISTINCT 年份 - 名次) = 1` 与题意完全等价，缺年为 0 的情况也被自动涵盖（只要缺年，年份步长 ≥ 2，差值必散开）。

实现上分三层：内层 `GROUP BY customer_id, YEAR(order_date)` 聚合并算 `yr`、`total`；中层在客户内按 `total` 求 `RANK()`；外层按客户分组检验差值唯一性。注意窗口函数里直接写 `ORDER BY SUM(price)` 配外层 `YEAR(order_date)` 会触发 `ONLY_FULL_GROUP_BY` 报错（窗口表达式里的列不被函数依赖判定认可），所以把聚合先落进子查询、窗口再套一层最稳。替代写法：递归 CTE 补齐年份后 `LAG` 逐年比较，语义直观但代码长得多。

### SQL 实现

```sql
SELECT customer_id
FROM (
    SELECT
        customer_id,
        yr,
        RANK() OVER (PARTITION BY customer_id ORDER BY total) AS rk
    FROM (
        SELECT customer_id, YEAR(order_date) AS yr, SUM(price) AS total
        FROM Orders
        GROUP BY customer_id, YEAR(order_date)
    ) AS a
) AS t
GROUP BY customer_id
HAVING COUNT(DISTINCT yr - rk) = 1;
```

### 复杂度分析

- 时间复杂度：O(n log n)，按客户与年份分组、窗口按总额排序，n 为订单数。
- 空间复杂度：O(c · y)，c 为客户数、y 为各客户有订单的年份数。
