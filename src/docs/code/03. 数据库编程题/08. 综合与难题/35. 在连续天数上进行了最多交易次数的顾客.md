# 在连续天数上进行了最多交易次数的顾客

> 难度：困难 | 标签：窗口函数、连续区间分组 | [LeetCode 原题](https://leetcode.cn/problems/customers-with-maximum-number-of-transactions-on-consecutive-days/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

表：`Transactions`

```
+------------------+------+
| 列名             | 类型 |
+------------------+------+
| transaction_id   | int  |
| customer_id      | int  |
| transaction_date | date |
| amount           | int  |
+------------------+------+
```

`transaction_id` 是该表中具有唯一值的列。每行包含一笔交易的信息，其中 `(customer_id, transaction_date)` 唯一，同时记录了该客户的 `amount`。

编写一个解决方案，找出**在连续天数上进行了最多交易次数**的所有 `customer_id`。返回所有具有最大连续交易次数的 `customer_id`，结果表按 `customer_id` 升序排序。

**示例 1：**

输入：

```
Transactions 表:
+----------------+-------------+------------------+--------+
| transaction_id | customer_id | transaction_date | amount |
+----------------+-------------+------------------+--------+
| 1              | 101         | 2023-05-01       | 100    |
| 2              | 101         | 2023-05-02       | 150    |
| 3              | 101         | 2023-05-03       | 200    |
| 4              | 102         | 2023-05-01       | 50     |
| 5              | 102         | 2023-05-03       | 100    |
| 6              | 102         | 2023-05-04       | 200    |
| 7              | 105         | 2023-05-01       | 100    |
| 8              | 105         | 2023-05-02       | 150    |
| 9              | 105         | 2023-05-03       | 200    |
+----------------+-------------+------------------+--------+
```

输出：

```
+-------------+
| customer_id |
+-------------+
| 101         |
| 105         |
+-------------+
```

解释：

- 客户 101 共有 3 笔交易，且全部连续（05-01、05-02、05-03），最长连续天数为 3。
- 客户 102 共有 3 笔交易，但 05-01 与 05-03 之间断了一天，最长连续只有 2 笔。
- 客户 105 共有 3 笔交易，且全部连续，最长连续天数为 3。

最大连续交易次数为 3，由客户 101 和 105 达成，按 `customer_id` 升序返回。

## 题解

::: details 点击查看题解

### 思路

对每个顾客先求「最长连续交易天数」，再挑出达到**全局最大值**的顾客。求连续段的经典技巧是「日期减行号」：在顾客分区内按 `transaction_date` 排序编行号 `ROW_NUMBER()`，连续日期的行号也连续递增，`transaction_date - 行号` 的结果在同一条连续段内恒定，跨段则不同——于是 `DATE_SUB(transaction_date, INTERVAL ROW_NUMBER() ... DAY)` 得到的列即可直接当作段标识 `grp`。

拿到 (`customer_id`, `grp`) 后 `COUNT(*)` 就是每段的连续天数；再按 `customer_id` 分组取 `MAX(cnt)` 得到该顾客的最长连续段；最后用 `WHERE mx = (SELECT MAX(mx) FROM m)` 筛出全局并列最大的顾客。

两个细节要注意。其一，`ROW_NUMBER()` 里已经含窗口函数，不能再把它套进 `DATE_SUB` 之外的另一层窗口计算——这里 `DATE_SUB` 是普通函数，不构成窗口嵌套，可以写在同一层；但若再叠一层 `OVER` 就会触发 MySQL 的 3593 错误，稳妥起见本解法把每步都拆进独立 CTE。其二，该题只看「交易是否发生」，不关心 `amount`，因此无需任何金额比较；同一天多笔交易不会出现，因为 `(customer_id, transaction_date)` 唯一，`ROW_NUMBER` 不会并列。

### SQL 实现

```sql
WITH s AS (
    SELECT
        customer_id,
        DATE_SUB(transaction_date, INTERVAL ROW_NUMBER() OVER (
            PARTITION BY customer_id ORDER BY transaction_date
        ) DAY) AS grp
    FROM Transactions
),
t AS (
    SELECT customer_id, grp, COUNT(*) AS cnt
    FROM s
    GROUP BY customer_id, grp
),
m AS (
    SELECT customer_id, MAX(cnt) AS mx
    FROM t
    GROUP BY customer_id
)
SELECT customer_id
FROM m
WHERE mx = (SELECT MAX(mx) FROM m)
ORDER BY customer_id;
```

### 复杂度分析

- 时间复杂度：O(n log n)，窗口排序与三次分组聚合，n 为交易记录数。
- 空间复杂度：O(n)，三个 CTE 的中间结果。
