# 时间范围内的用户活动

> 难度：困难 | 标签：窗口函数、日期函数 | [LeetCode 原题](https://leetcode.cn/problems/user-activities-within-time-bounds/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

`Sessions` 表：

```
+---------------+----------+
| Column Name   | Type     |
+---------------+----------+
| user_id       | int      |
| session_start | datetime |
| session_end   | datetime |
| session_id    | int      |
| session_type  | enum     |
+---------------+----------+
session_id 是这张表的唯一主键。
session_type 是枚举类型，取值为 Viewer、Streamer。
本表记录用户的每次会话及其类型。
```

编写一个解决方案，找出**存在两次同类型会话、且间隔不超过 12 小时**的用户：

- 只比较**同一用户、同一类型**（两次都是 Viewer 或两次都是 Streamer）的会话。
- 间隔 = 后一次会话的 `session_start` − 前一次同类型会话的 `session_end`，不超过 12 小时（含恰好 12 小时）即算满足。
- 同一用户可能有多组满足条件的会话，但结果中只出现一次。

返回 `user_id`，按 `user_id` 升序排序。

**示例 1：**

输入：

```
Sessions 表：
+---------+---------------------+---------------------+------------+--------------+
| user_id | session_start       | session_end         | session_id | session_type |
+---------+---------------------+---------------------+------------+--------------+
| 101     | 2023-11-01 08:00:00 | 2023-11-01 09:00:00 | 1          | Viewer       |
| 101     | 2023-11-01 10:00:00 | 2023-11-01 11:00:00 | 2          | Streamer     |
| 102     | 2023-11-01 13:00:00 | 2023-11-01 14:00:00 | 3          | Viewer       |
| 102     | 2023-11-01 15:00:00 | 2023-11-01 16:00:00 | 4          | Viewer       |
| 101     | 2023-11-02 09:00:00 | 2023-11-02 10:00:00 | 5          | Viewer       |
| 102     | 2023-11-02 12:00:00 | 2023-11-02 13:00:00 | 6          | Streamer     |
| 101     | 2023-11-02 13:00:00 | 2023-11-02 14:00:00 | 7          | Streamer     |
| 102     | 2023-11-02 16:00:00 | 2023-11-02 17:00:00 | 8          | Viewer       |
| 103     | 2023-11-01 08:00:00 | 2023-11-01 09:00:00 | 9          | Viewer       |
| 103     | 2023-11-02 20:00:00 | 2023-11-02 23:00:00 | 10         | Viewer       |
| 103     | 2023-11-03 09:00:00 | 2023-11-03 10:00:00 | 11         | Viewer       |
+---------+---------------------+---------------------+------------+--------------+
```

输出：

```
+---------+
| user_id |
+---------+
| 102     |
| 103     |
+---------+
```

解释：

- 用户 101 没有任何两次同类型会话间隔 ≤ 12 小时：两次 Viewer 相隔 24 小时（11-01 09:00 → 11-02 09:00），两次 Streamer 相隔 26 小时，排除。
- 用户 102 的会话 3、4 均为 Viewer，14:00 结束、15:00 开始，间隔 1 小时，入选。
- 用户 103 的会话 10、11 均为 Viewer，23:00 结束、次日 09:00 开始，间隔 10 小时，入选。
- 结果按 `user_id` 升序。

## 题解

::: details 点击查看题解

### 思路

「同一用户同一类型的**相邻**两次会话」是关键观察：把会话按 `(user_id, session_type)` 分区、按开始时间排序后，用 `LAG(session_end)` 取上一次同类型会话的结束时间，只需比较当前行与其前一行，无需两两配对。之所以比较相邻行就够——如果相邻的间隔已经超过 12 小时，隔得更远的会话间隔只会更大，不可能满足条件（会话本身 `start < end`，不会交叉倒序）。

拿到 `prev_session_end` 后，时间差用 `session_start <= DATE_ADD(prev_session_end, INTERVAL 12 HOUR)` 表示「不超过 12 小时」。这个写法比 `TIMESTAMPDIFF(HOUR, prev_end, session_start) <= 12` 更严谨：`TIMESTAMPDIFF` 会**截断**小时数，比如间隔 12 小时 30 分会被截成 12 而误判为满足，边界测试就翻车；与 `DATE_ADD` 比较则是精确时间点比较。

最后 `DISTINCT user_id` 去重（一个用户可能有多组满足的会话），按 `user_id` 升序输出。分区必须同时包含 `user_id` 和 `session_type`——漏掉类型就会把 Viewer 与 Streamer 会话混在一起比较，用户 101 的 11-01 11:00（Streamer 结束）与 11-02 09:00（Viewer 开始）间隔 22 小时虽仍超限，但换成别的数据就会误判。

易错点：一是分区条件漏 `session_type`；二是排序用 `session_end` 还是 `session_start` 都可以（同一分区不重叠时等价），但必须与 `LAG` 的列对应，`LAG(session_end) ... ORDER BY session_start` 才是「上一次结束、这一次开始」的语义；三是忘记 `DISTINCT`；四是用 `< 12` 漏掉恰好 12 小时的边界。

### SQL 实现

```sql
WITH t AS (
    SELECT user_id,
           session_start,
           LAG(session_end) OVER (
               PARTITION BY user_id, session_type
               ORDER BY session_start
           ) AS prev_session_end
    FROM Sessions
)
SELECT DISTINCT user_id
FROM t
WHERE session_start <= DATE_ADD(prev_session_end, INTERVAL 12 HOUR)
ORDER BY user_id;
```

### 复杂度分析

- 时间复杂度：O(n log n)，n 为会话行数，窗口排序 + 去重排序各一次。
- 空间复杂度：O(n)，保存每行的前序会话结束时间。
