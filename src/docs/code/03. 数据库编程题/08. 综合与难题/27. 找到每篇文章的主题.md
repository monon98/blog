# 找到每篇文章的主题

> 难度：困难 | 标签：字符串函数、多表连接、分组聚合 | [LeetCode 原题](https://leetcode.cn/problems/finding-the-topic-of-each-post/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

表：`Keywords`

```
+----------+---------+
| Column Name | Type |
+----------+---------+
| topic_id    | int  |
| word        | varchar |
+----------+---------+
(topic_id, word) 是该表的主键。
该表的每一行都包含一个主题的 id 和一个用于表达该主题的词。
可以用多个词表达同一个主题，也可以用一个词表达多个主题。
```

表：`Posts`

```
+-----------+--------+
| Column Name | Type |
+-----------+--------+
| post_id     | int  |
| content     | varchar |
+-----------+--------+
post_id 是该表的主键。
该表的每一行都包含一个帖子的 ID 及其内容。
内容仅由英文字母和空格组成。
```

LeetCode 从其社交媒体网站收集了一些帖子，并对每个帖子的主题感兴趣。如果某个主题的关键字（不区分大小写）**作为一个完整的单词**出现在帖子内容中，那么这个帖子就有该主题。

编写解决方案，根据以下规则查找每篇文章的主题：

- 如果帖子没有任何主题的关键词，它的主题应为 `"Ambiguous!"`；
- 否则为主题 id 按升序排列、以英文逗号 `,` 分隔的字符串，字符串中不得包含重复的 id。

以任意顺序返回结果表，返回列 `post_id`、`topic`。

**示例 1：**

输入：

```
Keywords 表：
+----------+----------+
| topic_id | word     |
+----------+----------+
| 1        | handball |
| 1        | football |
| 3        | WAR      |
| 2        | Vaccine  |
+----------+----------+

Posts 表：
+---------+------------------------------------------------------------------------+
| post_id | content                                                                |
+---------+------------------------------------------------------------------------+
| 1       | We call it soccer They call it football hahaha                         |
| 2       | Americans prefer basketball while Europeans love handball and football |
| 3       | stop the war and play handball                                         |
| 4       | warning I planted some flowers this morning and then got vaccinated    |
+---------+------------------------------------------------------------------------+
```

输出：

```
+---------+------------+
| post_id | topic      |
+---------+------------+
| 1       | 1          |
| 2       | 1          |
| 3       | 1,3        |
| 4       | Ambiguous! |
+---------+------------+
```

解释：

- 帖子 1 的 `football` 命中主题 1；`soccer`、`hahaha` 不属于任何主题。
- 帖子 2 的 `handball`、`football` 都表示主题 1，去重后仍为 `1`。
- 帖子 3 的 `war` 命中主题 3、`handball` 命中主题 1，按升序拼成 `1,3`。
- 帖子 4 没有命中任何关键词：`warning` 不同于 `war`（虽然共享前缀），`vaccinated` 也不是 `Vaccine`，所以输出 `Ambiguous!`。

## 题解

::: details 点击查看题解

### 思路

核心是**整词匹配**：关键词只能作为独立单词出现。最朴素的 `content LIKE '%war%'` 一定会错——`warning` 包含子串 `war`，帖子 4 就会被误判为主题 3。题面给了关键线索：内容只由字母和空格组成，于是可以在两端各补一个空格，把「整词匹配」转化为「子串匹配」：`INSTR(CONCAT(' ', content, ' '), CONCAT(' ', word, ' ')) > 0`。补空格后，` war ` 只能命中被空格包住的独立 `war`，而 `warning` 前后没有 ` war ` 的形态，自然排除。`INSTR` 在 MySQL 默认大小写不敏感的排序规则下不区分大小写，所以 `WAR` 能匹配文中的 `war`，`Vaccine` 与 `vaccinated` 又因后缀不同而不匹配。

连接方式必须是 `Posts LEFT JOIN Keywords`：没有命中任何关键词的帖子要保留下来输出 `Ambiguous!`，用 `INNER JOIN` 会直接把帖子 4 从结果里丢掉。聚合阶段用 `GROUP_CONCAT(DISTINCT topic_id ORDER BY topic_id)`——`DISTINCT` 解决一个主题多个词（handball、football 同属主题 1）的重复，`ORDER BY` 保证升序；`IFNULL(..., 'Ambiguous!')` 把 `LEFT JOIN` 产生的 NULL（即一个关键词都没命中）替换成默认文案。

替代写法：`REGEXP` 用词边界 `\\b` 也能做整词匹配，但反斜杠要在 SQL 字符串里再转义，且必须确认 ICU 引擎行为，补空格 + `INSTR` 更朴素稳妥。

### SQL 实现

```sql
SELECT
    p.post_id,
    IFNULL(GROUP_CONCAT(DISTINCT k.topic_id ORDER BY k.topic_id), 'Ambiguous!') AS topic
FROM Posts AS p
LEFT JOIN Keywords AS k
    ON INSTR(CONCAT(' ', p.content, ' '), CONCAT(' ', k.word, ' ')) > 0
GROUP BY p.post_id;
```

### 复杂度分析

- 时间复杂度：O(p · k)，p 为帖子数、k 为关键词数，逐帖逐词做子串匹配。
- 空间复杂度：O(p)，每帖一行的分组结果。

:::
