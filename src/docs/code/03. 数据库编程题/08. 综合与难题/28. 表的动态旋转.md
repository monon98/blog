# 表的动态旋转

> 难度：困难 | 标签：行转列、动态 SQL | [LeetCode 原题](https://leetcode.cn/problems/dynamic-pivoting-of-a-table/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

表：`Products`

```
+------------+---------+
| Column Name | Type    |
+------------+---------+
| product_id | int     |
| store      | varchar |
| price      | int     |
+------------+---------+
(product_id, store) 是该表的主键。
该表的每一行表示商品 product_id 在某家商店 store 的售价 price。
表中最多有 30 个不同的商店。
```

**重要提示：** 这个问题针对的是对 SQL 有丰富经验的人。

请实现 `PivotProducts` 过程来重新组织 `Products` 表：每行是一个商品的 id 及其在**每家商店**的价格，商品不在该商店销售则价格为 NULL；结果表的列应包含每家商店，且商店列按**字典序**排序。过程执行后返回结果表，按任意顺序返回行。

**示例 1：**

输入：

```
Products 表：
+------------+----------+-------+
| product_id | store    | price |
+------------+----------+-------+
| 1          | Shop     | 110   |
| 1          | LC_Store | 100   |
| 2          | Nozama   | 200   |
| 2          | Souq     | 190   |
| 3          | Shop     | 1000  |
| 3          | Souq     | 1900  |
+------------+----------+-------+
```

输出：

```
+------------+----------+--------+------+------+
| product_id | LC_Store | Nozama | Shop | Souq |
+------------+----------+--------+------+------+
| 1          | 100      | NULL   | 110  | NULL |
| 2          | NULL     | 200    | NULL | 190  |
| 3          | NULL     | NULL   | 1000 | 1900 |
+------------+----------+--------+------+------+
```

解释：共有 4 家商店 Shop、LC_Store、Nozama、Souq，按字典序排列为 LC_Store、Nozama、Shop、Souq。商品 1 在 LC_Store 卖 100、在 Shop 卖 110，其余两家没有售卖，记为 NULL；商品 2、3 同理。

## 题解

::: details 点击查看题解

### 思路

静态行转列可以用 `MAX(CASE WHEN store = 'LC_Store' THEN price END)` 写死，但本题**列名本身来自数据**——写查询时并不知道有哪几家商店，这正是「动态」二字的含义：必须先查出全部商店名，再拼出 SQL 文本执行。MySQL 里标准做法是三件套：`PREPARE` 预处理、`EXECUTE` 执行、`DEALLOCATE PREPARE` 释放。

拼串细节有三处。其一，用 `GROUP_CONCAT` 对去重后的商店名生成 `MAX(CASE WHEN store = ... THEN price END)` 形式的聚合片段、别名取商店名（加反引号），并把 `ORDER BY store` 写进 `GROUP_CONCAT` 内部以保证字典序（这也是题面要求的列顺序）；这里我先 `SELECT DISTINCT store FROM Products` 再聚合——既天然去重，又让 `ORDER BY store` 落在聚合表达式的输入上，语法最稳。其二，先 `SET group_concat_max_len = 5000;` 防止 30 家商店的 SQL 文本被默认 1024 字节截断。其三，动态 SQL 拼成 `SELECT product_id, <各店片段> FROM Products GROUP BY product_id`，片段全是聚合函数，满足 `ONLY_FULL_GROUP_BY`。

在 LeetCode 上本题要求把这段逻辑包进 `CREATE PROCEDURE PivotProducts() BEGIN ... END` 存储过程；本页给出的是同逻辑的会话级写法，可在 MySQL 8 客户端里按顺序直接执行。易错点：片段里的单引号要成对转义（`''` 双写或 `\'`），列别名最好加反引号防保留字冲突。

### SQL 实现

```sql
SET group_concat_max_len = 5000;
SELECT GROUP_CONCAT(
    CONCAT('MAX(CASE WHEN store = ''', store, ''' THEN price ELSE NULL END) AS `', store, '`')
    ORDER BY store
) INTO @sql
FROM (SELECT DISTINCT store FROM Products) AS t;
SET @sql = CONCAT('SELECT product_id, ', @sql, ' FROM Products GROUP BY product_id');
PREPARE stmt FROM @sql;
EXECUTE stmt;
DEALLOCATE PREPARE stmt;
```

### 复杂度分析

- 时间复杂度：O(s · p)，s 为商店数、p 为商品数；拼串 O(s)，执行时每店一个条件聚合。
- 空间复杂度：O(s)，动态 SQL 文本与结果列数。
