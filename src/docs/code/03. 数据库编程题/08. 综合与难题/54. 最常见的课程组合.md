# 最常见的课程组合

> 难度：困难 | 标签：窗口函数、分组聚合、子查询 | [LeetCode 原题](https://leetcode.cn/problems/most-common-course-pairs/)

## 题目描述

表：`course_completions`

```
+-------------------+---------+
| Column Name       | Type    |
+-------------------+---------+
| user_id           | int     |
| course_id         | int     |
| course_name       | varchar |
| completion_date   | date    |
| course_rating     | int     |
+-------------------+---------+
(user_id, course_id) 是此表中具有不同值的列的组合。
每一行代表一个用户完成的课程及其评分（1-5 分）。
```

编写一个解决方案，通过分析顶尖学生完成课程的序列来识别 **课程路径**：

	- 只考虑 顶尖学生（完成 至少 5 门课程且平均评分 4 分或以上 的人）。

	- 对每个顶尖学生，确定他们按时间顺序完成的 课程序列。

	- 找出这些学生所学的所有 连续课程对 （课程 A → 课程 B）。

	- 返回课程对的频率，确定顶尖学生中最常见的课程路径。

返回结果表，按课程对频率 **降序** 排列，若频率相同则按第一课程名称和第二课程名称 **升序** 排列。

## 题解

::: details 点击查看题解

### 思路

整题分三步走，全部可以在一条查询里用 CTE 串起来：

1. **筛出顶尖学生**：按 `user_id` 分组，`HAVING COUNT(*) >= 5 AND AVG(course_rating) >= 4`。注意两个条件是"且"的关系，少于 5 门课的用户 4 和平均分 2.8 的用户 3 都会被剔除。
2. **生成有序课程序列 + 相邻对**：对筛出的学生按 `completion_date` 排序，用 `LEAD(course_name) OVER (PARTITION BY user_id ORDER BY completion_date)` 取"下一门课"，当前行与下一行就构成一个连续课程对。这样自连接（`self join` 取 a.completion_date < b.completion_date 且中间没有第三门课）的麻烦就省掉了。若同一天完成两门课，排序键追加 `course_id` 保证结果稳定。
3. **统计频率并排序**：对 `(first_course, second_course)` 分组 `COUNT(*)`，按 `transition_count DESC, first_course ASC, second_course ASC` 排序。

易错点：

- 最后一行的 `LEAD` 结果是 `NULL`，必须过滤掉，否则会统计出一个 `second_course` 为 NULL 的假对；
- 平均分用 `AVG >= 4` 而不是 `SUM >= 20`——两者在样本数据上等价，但语义上题目明确说的是"平均评分 4 分或以上"；
- 排序的第三关键字不能省，否则频率相同的多行顺序不稳定，样例中 Python Basics 开头的两行会乱序。

若不用窗口函数，也可以先给每门课编序号 `ROW_NUMBER()`，再自连接 `b.rn = a.rn + 1`，效果一样。

### SQL 实现

```sql
WITH top_students AS (
    SELECT user_id
    FROM course_completions
    GROUP BY user_id
    HAVING COUNT(*) >= 5
       AND AVG(course_rating) >= 4
),
seq AS (
    SELECT
        user_id,
        course_name,
        LEAD(course_name) OVER (
            PARTITION BY user_id
            ORDER BY completion_date, course_id
        ) AS next_course
    FROM course_completions
    WHERE user_id IN (SELECT user_id FROM top_students)
)
SELECT
    course_name AS first_course,
    next_course AS second_course,
    COUNT(*) AS transition_count
FROM seq
WHERE next_course IS NOT NULL
GROUP BY course_name, next_course
ORDER BY transition_count DESC, first_course ASC, second_course ASC;
```

### 复杂度分析

- 时间复杂度：O(n log n)，n 为课程记录数，窗口函数按用户排序占主导，分组计数为 O(n)。
- 空间复杂度：O(n)，窗口函数与 CTE 中间结果需要保存每个用户的有序序列。
