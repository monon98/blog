# Hopper 公司查询 I

> 难度：困难 | 标签：递归 CTE、日期函数 | [LeetCode 原题](https://leetcode.cn/problems/hopper-company-queries-i/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

表：`Drivers`

| 列名 | 类型 |
| --- | --- |
| driver_id | int |
| join_date | date |

`driver_id` 是该表的主键。该表每一行表示一名司机的 ID 及其加入 Hopper 公司的日期。

表：`Rides`

| 列名 | 类型 |
| --- | --- |
| ride_id | int |
| user_id | int |
| requested_at | date |

`ride_id` 是该表的主键。该表每一行表示一次行程请求的 ID、发起用户的 ID 以及请求日期。表中可能存在未被接受的行程请求。

表：`AcceptedRides`

| 列名 | 类型 |
| --- | --- |
| ride_id | int |
| driver_id | int |
| ride_distance | int |
| ride_duration | int |

`ride_id` 是该表的主键。该表每一行表示一次被接受的行程及其接单司机、行驶距离与时长。可以保证每条被接受的行程都存在于 `Rides` 表中。

编写一个查询，报告 2020 年**每个月**的以下统计信息：

- `active_drivers`：截至该月月底仍在公司的司机累计人数（即 `join_date` 不晚于该月最后一天的司机数）；
- `accepted_rides`：该月被接受的行程数量。

结果按 `month`（月份序号，1 表示一月，2 表示二月……）升序排列。

示例：

输入 `Drivers` 表：

| driver_id | join_date |
| --- | --- |
| 10 | 2019-12-10 |
| 8 | 2020-1-13 |
| 5 | 2020-2-16 |
| 7 | 2020-3-8 |
| 4 | 2020-5-17 |
| 1 | 2020-10-24 |
| 6 | 2021-1-5 |

输入 `Rides` 表（节选）：

| ride_id | user_id | requested_at |
| --- | --- | --- |
| 10 | 63 | 2020-3-4 |
| 13 | 52 | 2020-6-22 |
| 7 | 69 | 2020-7-16 |
| 17 | 70 | 2020-8-25 |
| 20 | 81 | 2020-11-2 |
| 5 | 57 | 2020-11-9 |
| 2 | 42 | 2020-12-9 |
| … | … | … |

输入 `AcceptedRides` 表（节选）：

| ride_id | driver_id | ride_distance | ride_duration |
| --- | --- | --- | --- |
| 10 | 10 | 63 | 38 |
| 13 | 10 | 73 | 96 |
| 7 | 8 | 100 | 28 |
| 17 | 7 | 119 | 68 |
| 20 | 1 | 121 | 92 |
| 5 | 7 | 42 | 101 |
| 2 | 4 | 6 | 38 |
| … | … | … | … |

输出：

| month | active_drivers | accepted_rides |
| --- | --- | --- |
| 1 | 2 | 0 |
| 2 | 3 | 0 |
| 3 | 4 | 1 |
| 4 | 4 | 0 |
| 5 | 5 | 0 |
| 6 | 5 | 1 |
| 7 | 5 | 1 |
| 8 | 5 | 1 |
| 9 | 5 | 0 |
| 10 | 6 | 0 |
| 11 | 6 | 2 |
| 12 | 6 | 1 |

解释：

- 截至 1 月底有 2 名司机（10、8），当月无被接受行程；
- 截至 3 月底有 4 名司机（10、8、5、7），当月有 1 单被接受；
- 截至 11 月底有 6 名司机（10、8、5、7、4、1），当月有 2 单被接受（行程 20、5）；
- 2021 年才入职的 6 号司机不计入 2020 年任何月份。

## 题解

::: details 点击查看题解

### 思路

输出要求 12 个月**一个都不能少**（即使当月没有行程也要输出 0 行），而两张事实表里未必每个月都有数据，所以先用递归 CTE 造出 1 ~ 12 的月份骨架，并顺手带上每月月初日期（`DATE_ADD('2020-01-01', INTERVAL m-1 MONTH)`），方便后续算月末。

两个指标的口径不同，要分开算：

- `active_drivers` 是**累计值**：对每个月，用相关子查询数一下 `join_date <= LAST_DAY(月初)` 的司机数量。注意是"截至月底在公司"，不是"当月入职"，也不是"当月接单的司机"；
- `accepted_rides` 是**当月流量**：`AcceptedRides` 没有日期列，必须回连 `Rides` 取 `requested_at`，按 `YEAR = 2020`、`MONTH` 分组计数，再左连接到月份骨架上补 0。

易错点：两个指标口径混淆（把 active_drivers 算成"当月接单司机数"）是最常见的错误；另外 `LAST_DAY()` 接收月初日期即可得到该月最后一天，跨年月份也正确。

### SQL 实现

```sql
WITH RECURSIVE months AS (
    SELECT 1 AS m, DATE('2020-01-01') AS month_start
    UNION ALL
    SELECT m + 1, DATE_ADD(month_start, INTERVAL 1 MONTH)
    FROM months
    WHERE m < 12
),
ride_stats AS (
    SELECT MONTH(r.requested_at) AS m,
           COUNT(*) AS accepted_rides
    FROM Rides r
    JOIN AcceptedRides a ON a.ride_id = r.ride_id
    WHERE YEAR(r.requested_at) = 2020
    GROUP BY MONTH(r.requested_at)
)
SELECT mo.m AS month,
       (SELECT COUNT(*)
        FROM Drivers d
        WHERE d.join_date <= LAST_DAY(mo.month_start)) AS active_drivers,
       COALESCE(rs.accepted_rides, 0) AS accepted_rides
FROM months mo
LEFT JOIN ride_stats rs ON rs.m = mo.m
ORDER BY mo.m;
```

### 复杂度分析

- 时间复杂度：O(d + r log r)，d 为司机数、r 为被接受行程数，相关子查询对 12 个月各扫一次司机表。
- 空间复杂度：O(12 + m)，m 为 2020 年有行程的月份数。
