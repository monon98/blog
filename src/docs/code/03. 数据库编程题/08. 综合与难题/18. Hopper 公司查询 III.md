# Hopper 公司查询 III

> 难度：困难 | 标签：递归 CTE、日期函数 | [LeetCode 原题](https://leetcode.cn/problems/hopper-company-queries-iii/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

表：`Drivers`

| 列名 | 类型 |
| --- | --- |
| driver_id | int |
| join_date | date |

`driver_id` 是该表的主键。该表每一行表示一名司机的 ID 及其加入 Hopper 公司的日期。

表：`Rides`

| 列名 | 类型 |
| --- | --- |
| ride_id | int |
| user_id | int |
| requested_at | date |

`ride_id` 是该表的主键。该表每一行表示一次行程请求的 ID、发起用户的 ID 以及请求日期。表中可能存在未被接受的行程请求。

表：`AcceptedRides`

| 列名 | 类型 |
| --- | --- |
| ride_id | int |
| driver_id | int |
| ride_distance | int |
| ride_duration | int |

`ride_id` 是该表的主键。该表每一行表示一次被接受的行程及其接单司机、行驶距离与时长。可以保证每条被接受的行程都存在于 `Rides` 表中。

编写一个查询，计算 2020 年从 **1 月至 3 月** 开始一直到 **10 月至 12 月** 为止、每个**连续 3 个月窗口**的 `average_ride_distance` 与 `average_ride_duration`，结果保留两位小数：

- `average_ride_distance` = 该 3 个月的 `ride_distance` 总和 ÷ 3；
- `average_ride_duration` = 该 3 个月的 `ride_duration` 总和 ÷ 3；
- 结果按 `month`（窗口起始月的月份序号，1 表示一月……10 表示十月）升序排列。

示例：

输入 `Drivers` 表、`Rides` 表、`AcceptedRides` 表同「Hopper 公司查询 I」。

输出：

| month | average_ride_distance | average_ride_duration |
| --- | --- | --- |
| 1 | 21.00 | 12.67 |
| 2 | 21.00 | 12.67 |
| 3 | 21.00 | 12.67 |
| 4 | 24.33 | 32.00 |
| 5 | 57.67 | 41.33 |
| 6 | 97.33 | 64.00 |
| 7 | 73.00 | 32.00 |
| 8 | 39.67 | 22.67 |
| 9 | 54.33 | 64.33 |
| 10 | 56.33 | 77.00 |

解释（以起始月 1 为例）：

- 1 ~ 3 月窗口：`ride_distance` 总和 = 0 + 0 + 63 = 63，平均 63 / 3 = 21.00；`ride_duration` 总和 = 0 + 0 + 38 = 38，平均 38 / 3 = 12.67；
- 起始月 6：4 ~ 6 月窗口距离总和 = 0 + 73 + 100 = 173，平均 57.67；时长总和 = 0 + 96 + 28 = 124，平均 41.33；
- 起始月 10：10 ~ 12 月窗口距离总和 = 0 + 163 + 6 = 169，平均 56.33；时长总和 = 0 + 193 + 38 = 231，平均 77.00。

## 题解

::: details 点击查看题解

### 思路

先把每月的被接受行程汇总成"月 → 距离合计、时长合计"的窄表：`AcceptedRides` 没有日期列，必须回连 `Rides` 取 `requested_at`，按 `YEAR = 2020`、`MONTH` 分组求和——**没有行程的月份不会出现在这张表里**，所以后面一律要 `COALESCE(..., 0)` 补零。

窗口骨架用递归 CTE 生成 1 ~ 12 月，再让 `m1`（起始月）与 `m1 + 1`、`m1 + 2` 自连接三次，把三个月的数据横向拼到一行；`WHERE m1.m <= 10` 限定只输出 1 ~ 10 月起始的窗口（10 ~ 12 月是最后一个）。最后总和除以 3 并 `ROUND(..., 2)`。

易错点：

- 分母固定是 3，哪怕窗口内某月没有行程也要按 0 计入再除以 3，不能只除以"有数据的月份数"；
- `SUM` 聚合结果是十进制类型，`/ 3` 在 MySQL 中不会整数截断，但仍要 `ROUND` 到两位；
- 用 `JOIN months m2 ON m2.m = m1.m + 1` 这种自然连接比范围条件（`BETWEEN`）更精确，也避免了笛卡尔积。

### SQL 实现

```sql
WITH RECURSIVE months AS (
    SELECT 1 AS m
    UNION ALL
    SELECT m + 1 FROM months WHERE m < 12
),
ride_month AS (
    SELECT MONTH(r.requested_at) AS m,
           SUM(a.ride_distance) AS dist,
           SUM(a.ride_duration) AS dur
    FROM Rides r
    JOIN AcceptedRides a ON a.ride_id = r.ride_id
    WHERE YEAR(r.requested_at) = 2020
    GROUP BY MONTH(r.requested_at)
)
SELECT m1.m AS month,
       ROUND((COALESCE(r1.dist, 0) + COALESCE(r2.dist, 0) + COALESCE(r3.dist, 0)) / 3, 2) AS average_ride_distance,
       ROUND((COALESCE(r1.dur, 0) + COALESCE(r2.dur, 0) + COALESCE(r3.dur, 0)) / 3, 2) AS average_ride_duration
FROM months m1
JOIN months m2 ON m2.m = m1.m + 1
JOIN months m3 ON m3.m = m1.m + 2
LEFT JOIN ride_month r1 ON r1.m = m1.m
LEFT JOIN ride_month r2 ON r2.m = m2.m
LEFT JOIN ride_month r3 ON r3.m = m3.m
WHERE m1.m <= 10
ORDER BY m1.m;
```

### 复杂度分析

- 时间复杂度：O(r log r)，r 为被接受行程数，按月聚合主导；窗口骨架仅 12 行。
- 空间复杂度：O(12)，用于存放月份与月度聚合结果。
