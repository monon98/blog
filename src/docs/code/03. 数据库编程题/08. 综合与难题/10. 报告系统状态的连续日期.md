# 报告系统状态的连续日期

> 难度：困难 | 标签：窗口函数、日期函数 | [LeetCode 原题](https://leetcode.cn/problems/report-contiguous-dates/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

表：`Failed`

| 列名 | 类型 |
| --- | --- |
| fail_date | date |

`fail_date` 是该表的主键。该表记录了任务失败的日期。

表：`Succeeded`

| 列名 | 类型 |
| --- | --- |
| success_date | date |

`success_date` 是该表的主键。该表记录了任务成功的日期。

一个系统每天运行一个任务，每天的任务相互独立，可能失败也可能成功。

编写一个查询，针对 **2019-01-01 至 2019-12-31** 期间的连续日期区间，生成系统状态报告：

- 区间内任务全部失败，`period_state` 为 `'failed'`；全部成功则为 `'succeeded'`；
- 每个连续区间给出 `start_date` 与 `end_date`；
- 结果按 `start_date` 升序排列。

2018 年的数据不属于报告期，直接忽略。

示例：

输入 `Failed` 表：

| fail_date |
| --- |
| 2018-12-28 |
| 2018-12-29 |
| 2019-01-04 |
| 2019-01-05 |

输入 `Succeeded` 表：

| success_date |
| --- |
| 2018-12-30 |
| 2018-12-31 |
| 2019-01-01 |
| 2019-01-02 |
| 2019-01-03 |
| 2019-01-06 |

输出：

| period_state | start_date | end_date |
| --- | --- | --- |
| succeeded | 2019-01-01 | 2019-01-03 |
| failed | 2019-01-04 | 2019-01-05 |
| succeeded | 2019-01-06 | 2019-01-06 |

解释：

- 2019-01-01 至 2019-01-03 任务全部成功，状态为 `succeeded`；
- 2019-01-04 至 2019-01-05 任务全部失败，状态为 `failed`；
- 2019-01-06 任务成功，状态为 `succeeded`。

## 题解

::: details 点击查看题解

### 思路

两张表分别存"失败日"和"成功日"，先用 `UNION ALL` 纵向合并成"日期 + 状态"的流水，并直接过滤出报告期 `2019-01-01 ~ 2019-12-31`（先过滤再算行号，2018 年的日期就不会干扰分组）。

接下来是经典的**连续日期分组**套路：按日期升序、**在每个状态内部**编 `ROW_NUMBER()`，再用 `日期 - 行号` 得到一个分组键——同一状态里连续的日期每天 `d` 加 1、`rn` 也加 1，差值不变；一旦出现断档，差值就会改变，于是每段连续区间对应唯一的分组键。

易错点：

- 行号**必须按 `period_state` 分区**再编号：本题报告期内每天都恰好有一个状态，日期是完全连续的，若对全体日期统一编号，`日期 - 行号` 会恒为同一个常数，两段被失败区间隔开的 `succeeded` 区间（01-01~01-03 与 01-06）会得到相同的分组键而被错误合并；状态分区内编号后，中间插入的另一种状态会让后一段的差值自然错开；
- 过滤条件放在窗口函数之前，只对 2019 年的日期编号，2018 年的数据既不参与分组也不参与行号；
- 输出列名要求 `period_state`、`start_date`、`end_date`，且只按 `start_date` 排序。

替代写法：也可以先 `LEAD(d)` 判断下一天是否同状态，再累加标志位分组；或用自连接找"没有同状态前一天"的区间起点。窗口差值法一次扫描即可，是最简洁的写法。

### SQL 实现

```sql
WITH all_days AS (
    SELECT fail_date AS d, 'failed' AS period_state
    FROM Failed
    UNION ALL
    SELECT success_date AS d, 'succeeded' AS period_state
    FROM Succeeded
),
grouped AS (
    SELECT d,
           period_state,
           DATE_SUB(d, INTERVAL ROW_NUMBER() OVER (PARTITION BY period_state ORDER BY d) DAY) AS grp
    FROM all_days
    WHERE d BETWEEN '2019-01-01' AND '2019-12-31'
)
SELECT period_state,
       MIN(d) AS start_date,
       MAX(d) AS end_date
FROM grouped
GROUP BY period_state, grp
ORDER BY start_date;
```

### 复杂度分析

- 时间复杂度：O(n log n)，n 为报告期内的天数，窗口排序主导。
- 空间复杂度：O(n)，用于存放合并后的日期序列。
