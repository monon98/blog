# 获取最近第二次的活动

> 难度：困难 | 标签：窗口函数 | [LeetCode 原题](https://leetcode.cn/problems/get-the-second-most-recent-activity/)

## 题目描述

> 本题为 LeetCode VIP 专属题，题面根据表结构与测试数据整理。

表：`UserActivity`

| 列名 | 类型 |
| --- | --- |
| username | varchar |
| activity | varchar |
| startDate | date |
| endDate | date |

该表没有主键，记录了每名用户在一段时间内进行的活动：用户 `username` 在 `startDate` 到 `endDate` 期间进行了活动 `activity`。同一名用户不会同时进行两个活动（活动时间段互不重叠）。

编写一个查询，展示每名用户**最近的第二个活动**：

- 如果该用户只有一次活动，就返回那一次活动；
- 结果顺序任意。

示例：

输入 `UserActivity` 表：

| username | activity | startDate | endDate |
| --- | --- | --- | --- |
| Alice | Travel | 2020-02-12 | 2020-02-20 |
| Alice | Dancing | 2020-02-21 | 2020-02-23 |
| Alice | Travel | 2020-02-24 | 2020-02-28 |
| Bob | Travel | 2020-02-11 | 2020-02-18 |

输出：

| username | activity | startDate | endDate |
| --- | --- | --- | --- |
| Alice | Dancing | 2020-02-21 | 2020-02-23 |
| Bob | Travel | 2020-02-11 | 2020-02-18 |

解释：

- Alice 最近的活动是 2020-02-24 至 2020-02-28 的 Travel，它之前的活动是 2020-02-21 至 2020-02-23 的 Dancing；
- Bob 只有一条记录，直接返回该活动。

## 题解

::: details 点击查看题解

### 思路

"每人最近的第二个"是标准的分组取第 n 问题：按 `username` 分区、按 `startDate` 降序编号，`rn = 2` 即为所求。但题目还有个例外——只有一次活动的用户也要返回，此时 `rn = 2` 根本不存在。所以窗口里再算一个 `COUNT(*) OVER (PARTITION BY username)` 得到每人的活动总数，外层用 `WHERE rn = 2 OR cnt = 1` 一次把两类情况都取出来。

易错点：

- 只写 `rn = 2` 会把只有一次活动的用户（如 Bob）漏掉，只写 `cnt = 2` 又会把三次活动用户的"第二个"弄错，两个条件必须用 `OR` 组合；
- 排序字段用 `startDate` 降序即可确定"最近"，由于同一用户活动不重叠，`endDate` 降序结果相同；
- 用 `ROW_NUMBER` 而非 `RANK`/`DENSE_RANK`：本题活动时间互不重复，三者结果一致，但 `ROW_NUMBER` 语义最贴合"取第几条"。

另一种写法是相关子查询统计" startDate 晚于本行的活动数 = 1"，逻辑等价但每次比较都要扫分区，不如窗口函数一次计算高效。

### SQL 实现

```sql
SELECT username, activity, startDate, endDate
FROM (
    SELECT username,
           activity,
           startDate,
           endDate,
           ROW_NUMBER() OVER (PARTITION BY username ORDER BY startDate DESC) AS rk,
           COUNT(*)     OVER (PARTITION BY username) AS cnt
    FROM UserActivity
) t
WHERE rk = 2 OR cnt = 1;
```

### 复杂度分析

- 时间复杂度：O(n log n)，n 为活动记录数，窗口排序主导。
- 空间复杂度：O(n)，用于存放窗口计算的中间结果。

:::

```sql
Truncate table UserActivity;

```
