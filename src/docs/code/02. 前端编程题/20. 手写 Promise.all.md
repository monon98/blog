# 手写 Promise.all

> 难度：简单 | 标签：Promise、异步、计数器

## 题目描述

实现 `myAll(promises)`：

- 全部成功时按**原始顺序**返回结果数组（即使后完成的也归位到自己的下标）
- 任一失败立即整体 reject，且 reject 原因为第一个失败的原因
- 支持数组元素为普通值或 thenable
- 空数组直接 resolve 空数组

**示例：**

```javascript
myAll([api1(), 42, delay(100).then(() => "late")]).then(console.log);
// [结果1, 42, "late"]
```

## 题解

::: details 点击查看题解

### 思路

计数器 + 按位写入两个要点：

1. **按索引写结果** `results[i] = value`——天然保证顺序与完成时间无关，不能用 push
2. **计数而非比较长度**：每次成功 count++，等于总数才 resolve；任一失败直接透传给外层 reject，剩余任务的结果被丢弃
3. 用 `MyPromise.resolve(item)` 包装普通值与非标准 thenable，保证统一走 then 流程

### 代码实现

```javascript
MyPromise.all = function (promises) {
  return new MyPromise((resolve, reject) => {
    const results = [];
    let fulfilledCount = 0;
    const list = Array.from(promises);
    const total = list.length;

    if (total === 0) return resolve(results);

    list.forEach((item, index) => {
      MyPromise.resolve(item).then((value) => {
        results[index] = value;
        fulfilledCount++;
        if (fulfilledCount === total) {
          resolve(results);
        }
      }, reject);
    });
  });
};
```

### 考察点

- 「短路失败」语义：一个 reject 整体 reject，但已发出的请求无法真正取消
- 为什么不用 `results.length === total` 判断完成——稀疏赋值会让 length 提前变大
- 变体追问：allSettled（收集全部状态）、all 的「进度百分比」如何上报
- Promise.all 与 for-await-of 在错误处理上的行为差异
