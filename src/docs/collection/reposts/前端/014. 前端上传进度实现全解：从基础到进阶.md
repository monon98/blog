# 前端上传进度实现全解：从基础到进阶

::: tip
转载自掘金 · 作者：前端切图崽_小郭 · [原文链接](https://juejin.cn/post/7655245911812194350)
:::

---

## 1. 为什么需要上传进度？

在文件上传场景中，**进度反馈**是提升用户体验的关键：

- 避免用户焦虑：无进度的等待界面会让用户怀疑系统是否卡住。
- 透明化过程：进度条/百分比能直观展示上传状态（如“已上传 75%”）。
- 业务需求：部分场景要求精确控制上传流程（如大文件分片、断点续传）。

---

## 2. 前端获取上传进度的 3 种基础方案

### 2.1 使用 Axios 监听上传进度

**适用场景**：基于 `axios` 的项目，支持 **单文件/多文件** 上传。

**核心原理**： `axios` 的 `onUploadProgress` 回调会接收一个 `ProgressEvent` 对象，包含：

- `loaded`: 已上传的字节数。
- `total`: 总字节数（需服务器支持 `Content-Length`）。
- `lengthComputable`: 标识是否可计算进度（通常为 `true`）。

**代码示例**：

```javascript
import axios from 'axios';

const formData = new FormData();
formData.append('file', file); // 单文件

axios.post('/api/upload', formData, {
  headers: { 'Content-Type': 'multipart/form-data' },
  onUploadProgress: (progressEvent) => {
    if (progressEvent.lengthComputable) {
      const percent = Math.round((progressEvent.loaded / progressEvent.total) * 100);
      console.log(`上传进度: ${percent}%`);
      // 更新 UI 进度条
      updateProgressBar(percent);
    }
  },
})
.then((res) => console.log('上传成功:', res))
.catch((err) => console.error('上传失败:', err));
```

**优点**：

- 代码简洁，集成方便。
- 支持取消上传（`CancelToken`）。

**缺点**：

- 依赖服务器返回 `Content-Length`（部分服务器可能不支持）。

---

### 2.2 使用原生 XMLHttpRequest (XHR)

**适用场景**：无框架项目或需要更细粒度控制的场景。

**核心原理**： 通过 `xhr.upload` 监听 `progress` 事件，获取上传进度。

**代码示例**：

```javascript
const xhr = new XMLHttpRequest();
const formData = new FormData();
formData.append('file', file);

xhr.upload.addEventListener('progress', (event) => {
  if (event.lengthComputable) {
    const percent = Math.round((event.loaded / event.total) * 100);
    console.log(`上传进度: ${percent}%`);
    updateProgressBar(percent);
  }
});

xhr.open('POST', '/api/upload', true);
xhr.send(formData);
```

**优点**：

- 无依赖，适用于所有浏览器。
- 可监听 `abort`、`error` 等事件。

**缺点**：

- 代码冗长，需手动处理错误。

---

### 2.3 使用 Fetch API + 自定义封装

**适用场景**：现代浏览器项目，追求简洁性。

**核心原理**： `fetch` 原生不支持上传进度监听，需通过 **`ReadableStream`** 或 **封装 XHR** 实现。

**方案 1：使用 `fetch` + `ReadableStream`（实验性）**

```javascript
async function uploadWithProgress(file, url, onProgress) {
  const formData = new FormData();
  formData.append('file', file);

  const response = await fetch(url, {
    method: 'POST',
    body: new ReadableStream({
      start(controller) {
        const reader = file.stream().getReader();
        let bytesRead = 0;

        reader.read().then(function process({ done, value }) {
          if (done) {
            controller.close();
            return;
          }
          bytesRead += value.length;
          onProgress(bytesRead, file.size);
          controller.enqueue(value);
          return reader.read().then(process);
        });
      },
    }),
  });

  return response;
}

// 使用
uploadWithProgress(file, '/api/upload', (loaded, total) => {
  const percent = Math.round((loaded / total) * 100);
  console.log(`上传进度: ${percent}%`);
});
```

**注意**：`ReadableStream` 浏览器兼容性较差（Chrome 52+），生产环境需谨慎使用。

**方案 2：封装 XHR 为 Fetch 样式**

```javascript
function fetchWithProgress(url, options) {
  return new Promise((resolve, reject) => {
    const xhr = new XMLHttpRequest();
    xhr.upload.addEventListener('progress', (event) => {
      if (event.lengthComputable && options.onProgress) {
        options.onProgress(event.loaded, event.total);
      }
    });
    xhr.open(options.method || 'GET', url);
    xhr.onload = () => resolve({ status: xhr.status, data: xhr.response });
    xhr.onerror = () => reject(new Error('上传失败'));
    xhr.send(options.body);
  });
}

// 使用
fetchWithProgress('/api/upload', {
  method: 'POST',
  body: formData,
  onProgress: (loaded, total) => {
    const percent = Math.round((loaded / total) * 100);
    console.log(`上传进度: ${percent}%`);
  },
});
```

**优点**：

- 符合现代前端风格。
- 可扩展性强（如添加超时、重试逻辑）。

**缺点**：

- 需额外封装，增加代码量。

## 3. 多文件上传的进度展示策略

### 3.1 单进度条展示所有文件上传进度

**适用场景**：多文件**并行上传**，希望用一个进度条展示整体进度。

**核心思路**：

1. 计算每个文件的权重（如文件大小占比）。
2. 根据已完成文件的数量/大小，动态更新总进度。

**代码示例**：

```ini
const files = [
  { file: file1, size: file1.size, status: 'uploading' },
  { file: file2, size: file2.size, status: 'uploading' },
  // ...
];

let totalUploaded = 0;
const totalSize = files.reduce((sum, file) => sum + file.size, 0);

// 并行上传所有文件
files.forEach((fileObj) => {
  const formData = new FormData();
  formData.append('file', fileObj.file);

  axios.post('/api/upload', formData, {
    onUploadProgress: (event) => {
      if (event.lengthComputable) {
        // 更新当前文件的已上传字节数
        const uploaded = event.loaded;
        totalUploaded += uploaded;
        // 计算总进度（避免超过 100%）
        const progress = Math.min(Math.round((totalUploaded / totalSize) * 100), 100);
        updateProgressBar(progress);
      }
    },
  }).then(() => {
    fileObj.status = 'completed';
  });
});
```

**优点**：

- 直观展示整体进度。

**缺点**：

- 文件大小差异大时，进度可能不均匀（如一个 1GB 文件和一个 1KB 文件）。

---

### 3.2 为每个文件单独展示进度条

**适用场景**：文件大小差异大，或需要精确控制每个文件的上传状态。

**核心思路**：

- 为每个文件维护独立的进度条。
- 可同时展示所有文件的进度，或只展示当前上传的文件。

**代码示例**：

```javascript
files.forEach((file, index) => {
  const formData = new FormData();
  formData.append('file', file);

  axios.post('/api/upload', formData, {
    onUploadProgress: (event) => {
      if (event.lengthComputable) {
        const percent = Math.round((event.loaded / event.total) * 100);
        updateFileProgress(index, percent); // 更新第 index 个文件的进度条
      }
    },
  });
});
```

**优点**：

- 精确反馈每个文件的上传状态。
- 用户体验更好（如可暂停/取消单个文件）。

**缺点**：

- UI 复杂度增加（需管理多个进度条）。

## 4. 大文件分片上传的进度展示

### 4.1 分片上传的优势

| 优势 | 说明 |
| --- | --- |
| **可靠性** | 网络中断后只需重传失败分片。 |
| **效率** | 并行上传分片，充分利用带宽。 |
| **断点续传** | 支持暂停/恢复上传。 |
| **内存友好** | 避免一次性加载大文件到内存。 |
| **服务器负载均衡** | 分片可分发到不同服务器。 |

---

### 4.2 分片上传的实现步骤

**切割文件**： 使用 `file.slice()` 将文件分割为固定大小的分片（如 1MB/片）。

```ini
function sliceFile(file, chunkSize = 1024 * 1024) {
function sliceFile(file, chunkSize = 1024 * 1024) {
const chunks = [];
let start = 0;
while (start < file.size) {
const end = Math.min(start + chunkSize, file.size);
chunks.push(file.slice(start, end));
start = end;
}
return chunks;
}
```

**上传分片**： 并行或串行上传分片，并携带分片索引（`chunkIndex`）和总分片数（`totalChunks`）。

```javascript
const chunks = sliceFile(file);
const uploadPromises = chunks.map((chunk, index) => {
const formData = new FormData();
  formData.append('chunk', chunk);
  formData.append('chunkIndex', index);
  formData.append('totalChunks', chunks.length);
  formData.append('filename', file.name);

  return axios.post('/api/upload/chunk', formData, {
    onUploadProgress: (event) => {
      if (event.lengthComputable) {
        const percent = Math.round((event.loaded / event.total) * 100);
        updateChunkProgress(index, percent); // 更新分片进度
      }
    },
  });
});

Promise.all(uploadPromises).then(() => {
  // 所有分片上传完成，通知服务器合并
  axios.post('/api/upload/merge', { filename: file.name });
});
```

**展示进度**：

**方案 1**：单进度条（基于分片数量）。

```ini
let uploadedChunks = 0;
const totalChunks = chunks.length;

// 每个分片上传完成后更新进度
const updateProgress = () => {
  uploadedChunks++;
  const progress = Math.round((uploadedChunks / totalChunks) * 100);
  updateProgressBar(progress);
};
```

**方案 2**：基于字节数（更精确）。

```ini
let uploadedBytes = 0;
const totalBytes = file.size;

chunks.forEach((chunk) => {
  axios.post('/api/upload/chunk', formData, {
    onUploadProgress: (event) => {
      if (event.lengthComputable) {
        uploadedBytes += event.loaded;
        const progress = Math.round((uploadedBytes / totalBytes) * 100);
        updateProgressBar(progress);
      }
    },
  });
});
```

**注意**：

需要服务器支持分片上传和合并逻辑。
分片大小可根据网络环境调整（如弱网下减小分片大小）。

## 5. 进度条 UI 设计建议

### 5.1 进度条类型选择

| 类型 | 适用场景 | 优点 | 缺点 |
| --- | --- | --- | --- |
| **环形进度条** | 单文件上传、简洁 UI | 占用空间小，视觉轻量 | 精确度低（难以显示具体百分比） |
| **线形进度条** | 多文件/分片上传 | 可显示百分比，直观 | 占用空间较大 |
| **数字百分比** | 需要精确反馈的场景 | 精确到小数点后一位 | 缺乏视觉冲击力 |
| **文件列表** | 多文件上传，每个文件单独进度 | 信息丰富，可操作性强 | UI 复杂度高 |

**示例代码（CSS 环形进度条）** ：

```ini
<div class="progress-circle">
  <svg viewBox="0 0 100 100">
    <circle cx="50" cy="50" r="45" fill="none" stroke="#eee" stroke-width="10" />
    <circle
      cx="50"
      cy="50"
      r="45"
      fill="none"
      stroke="#4CAF50"
      stroke-width="10"
      stroke-dasharray="283"
      stroke-dashoffset="283"
      style="stroke-dashoffset: calc(283 - (283 * 75) / 100);"
    />
    <text x="50" y="50" text-anchor="middle" dy="0.3em">75%</text>
  </svg>
</div>
```

### 5.2 UI 交互优化

**上传前**：

展示文件列表（支持删除/重新选择）。
显示文件大小（如“文件1: 2.5MB”）。

**上传中**：

进度条 + 百分比 + 速度（如“75% (1.2 MB/s)”）。
支持暂停/取消（需后端配合）。

**上传后**：

成功：显示“✅ 上传完成”。
失败：显示“❌ 上传失败” + 重试按钮。

**异常处理**：

网络中断：提示“网络异常，正在重试...”。
文件损坏：提示“文件损坏，请重新选择”。

## 6. 服务器端配合要点

**支持分片上传**：

接收分片数据，并存储到临时目录。
提供合并分片的接口（如 `/api/upload/merge`）。

**返回进度信息**：

对于大文件，可在响应头中返回 `Content-Length`。
分片上传时，返回已上传的分片索引。

**断点续传**：

服务器需记录已上传的分片（如数据库或 Redis）。
前端上传前可先查询已上传的分片，跳过重复上传。

## 7. 常见问题与解决方案

| 问题 | 原因 | 解决方案 |
| --- | --- | --- |
| 进度条卡住（不更新） | 服务器未返回 `Content-Length` | 使用分片上传，或让服务器支持 `Content-Length`。 |
| 进度条跳动（不平滑） | 网络波动导致 `loaded` 突变 | 使用平滑算法（如加权平均）计算进度。 |
| 多文件进度条不准确 | 文件大小差异大 | 基于字节数计算进度，而非文件数量。 |
| 分片上传后合并失败 | 服务器未正确存储分片 | 检查服务器端的分片存储逻辑。 |
| 浏览器兼容性问题 | 旧浏览器不支持 `ProgressEvent` | 使用 XHR 降级方案。 |

## 8. 总结与选择建议

| 场景 | 推荐方案 | 库/工具 | 难度 |
| --- | --- | --- | --- |
| 单文件上传 | Axios + 线形进度条 | `axios` | 低 |
| 多文件上传（并行） | 单进度条（基于字节数） | `axios` + 自定义逻辑 | 中 |
| 多文件上传（独立进度） | 每个文件单独进度条 | `axios` | 中 |
| 大文件上传 | 分片上传 + 单进度条 | `axios` + 服务器分片支持 | 高 |
| 现代浏览器项目 | Fetch + ReadableStream | 自定义封装 | 高 |
| 无框架项目 | 原生 XHR | 无依赖 | 中 |

**核心建议**：

**优先使用 Axios**：代码简洁，兼容性好。
**大文件必用分片**：提升可靠性和用户体验。
**UI 要直观**：进度条 + 百分比 + 速度。
**服务器配合**：分片上传、断点续传等功能需后端支持。
