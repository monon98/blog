# 面试场景题

## 1. Vite 核心原理

::: details
**问题**：Vite 为什么这么快？

### 核心原理

- 开发服务器：基于 ESM 的按需编译
- 生产构建：基于 Rollup
- 依赖预构建：esbuild 预构建依赖

### 与 Webpack 区别

| 阶段 | Webpack | Vite |
|------|---------|------|
| 启动 | 打包所有模块 | 按需编译 |
| HMR | 重新打包 | 精准更新 |
| 构建 | Webpack | Rollup |

### 优势

- 冷启动极快
- HMR 瞬间完成
- 原生 ESM 支持
- 开箱即用

:::

## 2. 依赖预构建

::: details
**问题**：Vite 依赖预构建如何工作？

### 预构建作用

- 将 CommonJS/UMD 转换为 ESM
- 合并小依赖，减少请求
- 使用 esbuild 加速

### 配置方式

- optimizeDeps.include：强制预构建
- optimizeDeps.exclude：排除预构建
- optimizeDeps.esbuildOptions：esbuild 配置

### 注意事项

- 首次启动预构建
- 依赖变化自动重建
- 缓存到 node_modules/.vite

:::

## 5. TypeScript 支持

::: details
**问题**：Vite 如何支持 TypeScript？

### 支持方式

- 原生 TypeScript 支持
- 无需 ts-loader
- 使用 esbuild 转译

### 配置要点

- tsconfig.json 配置
- 类型检查：tsc --noEmit
- 路径别名配置

### 注意事项

- 不进行类型检查
- 使用 IDE 或 tsc 检查类型
- 编译速度极快

:::

## 6. 环境变量

::: details
**问题**：Vite 如何处理环境变量？

### 使用方式

- import.meta.env.VITE_XXX
- .env 文件配置
- 模式区分

### 文件类型

- .env：所有模式
- .env.development：开发环境
- .env.production：生产环境
- .env.local：本地覆盖

### 注意事项

- 只暴露 VITE_ 前缀
- 客户端可访问
- 服务端使用 process.env
