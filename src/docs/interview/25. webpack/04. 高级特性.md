# 高级特性

## 1. 模块联邦（Module Federation）

::: details
**问题**：Webpack 5 模块联邦是什么？如何使用？

### 核心概念

- 多个独立构建的应用组成一个应用
- 运行时动态加载远程模块
- 解决微前端的代码共享问题

### 配置示例

```
// 宿主应用
new ModuleFederationPlugin({
  name: 'host',
  remotes: {
    remote: 'remote@http://localhost:3001/remoteEntry.js'
  },
  shared: ['react', 'react-dom']
});

// 远程应用
new ModuleFederationPlugin({
  name: 'remote',
  filename: 'remoteEntry.js',
  exposes: {
    './Button': './src/components/Button'
  },
  shared: ['react', 'react-dom']
});
```

### 关键配置

| 配置项 | 说明 |
|--------|------|
| name | 应用唯一标识 |
| remotes | 引用的远程应用 |
| exposes | 暴露给其他应用的模块 |
| shared | 共享的依赖（去重），核心库建议 singleton: true |

:::

## 2. 资源模块（Asset Modules）

::: details
**问题**：Webpack 5 如何处理静态资源？

### 四种资源类型

| 类型 | 说明 | 替代的 Loader |
|------|------|---------------|
| asset/resource | 导出文件 URL | file-loader |
| asset/inline | 导出 Data URI | url-loader |
| asset/source | 导出源码内容 | raw-loader |
| asset | 自动选择（小于阈值 inline） | file/url-loader |

### 配置示例

```
module: {
  rules: [
    {
      test: /\.png$/,
      type: 'asset',
      parser: {
        dataUrlCondition: { maxSize: 8 * 1024 }
      }
    }
  ]
}
```

### Webpack 5 的改进

- 内置资源处理，无需额外安装 Loader
- 减少配置复杂度
- 构建速度更快

:::

## 3. 持久化缓存

::: details
**问题**：Webpack 5 持久化缓存如何工作？

### 基本配置

```
cache: {
  type: 'filesystem',
  buildDependencies: {
    config: [__filename]
  }
}
```

### 工作原理

1. 首次构建：正常构建并将结果序列化到磁盘（node_modules/.cache）
2. 再次构建：读取缓存快照，只重新构建变化的模块
3. 快照校验：通过文件时间戳和哈希检测变化

### 失效条件

- 配置文件变化（buildDependencies）
- Webpack 版本变化
- Loader 版本变化

### 效果

- 二次构建速度提升 80% 以上
- 取代了 DllPlugin、hard-source-webpack-plugin 等旧方案

:::

## 4. 微前端中的 Webpack

::: details
**问题**：Webpack 在微前端架构中扮演什么角色？

### 三种方案对比

| 方案 | 技术基础 | 隔离性 | 适用场景 |
|------|----------|--------|----------|
| Module Federation | Webpack 5 运行时共享 | 无内置隔离 | 技术栈统一 |
| qiankun | single-spa + HTML Entry | JS/CSS 沙箱 | 技术栈多样 |
| iframe | 浏览器原生 | 完全隔离 | 强隔离需求 |

### qiankun 与 Webpack 的关系

- 子应用需要导出 bootstrap/mount/unmount 生命周期
- 主应用通过 import-html-entry 加载子应用资源
- 子应用打包需设置 publicPath 和 library 格式

### 选择建议

- 新项目 + 统一技术栈：优先 Module Federation
- 存量多技术栈：qiankun
- 第三方页面嵌入：iframe

:::

## 5. Webpack 5 其他重要更新

::: details
**问题**：Webpack 4 升级到 5 有哪些需要注意的点？

### 主要变更

- 移除 Node.js 内置模块自动 polyfill
- contenthash 支持所有文件类型
- 嵌套 Tree Shaking：分析嵌套属性的使用
- inner graph：模块内部依赖分析更精确
- 长期缓存算法改进

### 升级注意事项

```
// Webpack 4：自动注入 node_modules polyfill
// Webpack 5：需要手动配置 fallback

resolve: {
  fallback: {
    path: require.resolve('path-browserify'),
    buffer: require.resolve('buffer/')
  }
}
```

### 相关插件状态

| 插件 | 状态 |
|------|------|
| hard-source-webpack-plugin | 被 filesystem cache 替代 |
| DllPlugin/DllReferencePlugin | 不再必要 |
| clean-webpack-plugin | 被 output.clean: true 替代 |
| file-loader/url-loader/raw-loader | 被资源模块替代 |

:::
