# 基础概念

## 1. Webpack 是什么

::: details
Webpack 是一个静态模块打包工具，将项目中的各种资源（JS、CSS、图片等）视为模块，最终打包成浏览器可用的静态资源。

### 核心作用

- 模块打包：支持 CommonJS、ES Module、AMD
- 资源处理：通过 Loader 处理各类文件
- 代码转换：转译新语法为兼容代码
- 优化输出：压缩、分割、缓存

### 与其他工具的区别

| 工具 | 定位 |
|------|------|
| Webpack | 模块打包器 |
| Vite | 开发服务器 + 打包器 |
| Rollup | ES Module 打包器 |
| esbuild | 极速构建工具 |

:::

## 2. 五个核心概念

::: details
**问题**：Webpack 的五个核心概念是什么？

### Entry（入口）

- 指示构建从哪个文件开始
- 单入口：entry: './src/index.js'
- 多入口：entry: { app: './app.js', admin: './admin.js' }

### Output（输出）

- 指示打包后的资源输出位置
- path：输出目录
- filename：输出文件名，可用 [contenthash] 占位符
- publicPath：资源公共路径前缀

### Loader（加载器）

- 文件转换器，让 Webpack 能处理非 JS 文件
- 从右向左链式执行
- 例如 babel-loader 将 ES6+ 转译为 ES5

### Plugin（插件）

- 扩展 Webpack 功能，参与整个构建流程
- 基于 Tapable 钩子机制
- 例如 HtmlWebpackPlugin 自动生成 HTML 并引入打包资源

### Mode（模式）

- development：开发模式，保留调试信息
- production：生产模式，启用压缩和优化
- none：不设置任何默认优化

:::

## 3. 构建流程

::: details
**问题**：Webpack 的构建流程是怎样的？

### 完整流程

1. **初始化参数**：合并命令行和配置文件的参数
2. **开始编译**：创建 Compiler 对象，注册所有插件
3. **确定入口**：根据 entry 找到入口文件
4. **编译模块**：调用 Loader 转换模块，找出依赖的模块
5. **完成编译**：得到模块间的依赖关系图
6. **输出资源**：根据依赖图组装 Chunk，再转换为 Bundle
7. **输出完成**：将 Bundle 写入文件系统

### 关键对象

- Compiler：全局唯一的编译器实例，代表完整的生命周期
- Compilation：每次增量编译产生的上下文，包含模块资源信息
- Module：模块对象，代表一个被处理的文件

:::

## 4. 热更新（HMR）原理

::: details
**问题**：Webpack HMR 的实现原理是什么？

### 完整流程

1. **文件监听**：Webpack 监听文件变化（watch 模式）
2. **重新编译**：检测到变化后重新编译变更的模块
3. **推送消息**：DevServer 通过 WebSocket 推送 hash 给浏览器
4. **请求清单**：浏览器请求 manifest（JSON 文件）获取变更详情
5. **下载更新**：根据 manifest 下载更新的模块（JS 文件）
6. **热替换**：HotModuleReplacementPlugin 替换旧模块并执行 module.hot.accept 回调

### 关键点

- WebSocket 用于推送通知
- JSON + JS 文件用于传输更新内容
- 状态保留：只替换变更模块，页面不刷新
- 无法热替换时会自动降级为刷新

:::

## 5. Source Map 配置

::: details
**问题**：devtool 有哪些配置？如何选择？

### 常用配置

| devtool | 特点 | 适用场景 |
|---------|------|----------|
| eval | 最快，无映射 | 开发（简单调试） |
| eval-cheap-source-map | 快，仅行号映射 | 开发 |
| eval-cheap-module-source-map | 快，行号映射 + Loader 源码 | 开发（推荐） |
| source-map | 完整独立文件 | 生产排查 |
| hidden-source-map | 不暴露映射 | 生产（配合监控平台） |

### 选择原则

- 开发环境：eval-cheap-module-source-map（速度与质量平衡）
- 生产环境：hidden-source-map 或不生成（避免暴露源码）
- 排查线上问题时上传 map 文件到监控平台

:::

## 6. 文件监听原理

::: details
**问题**：Webpack 如何监听文件变化？

### 监听方式

- 轮询判断文件的最后编辑时间是否变化
- 默认聚合等待时间 aggregateTimeout: 300ms

### 优化手段

- Webpack 核心使用 watchpack 库监听文件变化
- watchOptions.ignore 忽略 node_modules 减少监听数量
- usePolling 在某些系统上更可靠但耗 CPU

:::
