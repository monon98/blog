# 面试场景题

## 1. 手写一个简易打包器

::: details
**问题**：实现一个类似 Webpack 的模块打包器。

### 核心步骤

1. 读取入口文件内容
2. 使用 babel/ast 解析出依赖列表
3. 递归构建依赖图（Module Graph）
4. 将所有模块包装为函数并拼接
5. 实现自定义 require 函数支持模块加载

### 关键实现点

- AST 解析：使用 @babel/parser 提取 import 声明
- 模块缓存：避免重复执行同一模块
- CommonJS 兼容：exports/module.exports 处理

:::

## 2. 打包后文件过大排查

::: details
**问题**：上线后发现 bundle 超过 2MB，如何排查和优化？

### 排查手段

- webpack-bundle-analyzer 可视化查看体积占比
- source-map-explorer 分析 map 文件
- 检查是否误引入了开发版依赖（如 lodash 全量、moment 语言包）

### 常见原因与对策

| 原因 | 对策 |
|------|------|
| 第三方库全量引入 | 改用按需引入或 ES 版本 |
| moment 语言包全量打包 | ContextReplacementPlugin 忽略 locales |
| 图片未压缩 | 压缩 + WebP 格式 |
| 重复依赖（多版本共存） | npm/yarn dedupe、pnpm 天然避免，或 alias 强制统一版本 |
| 缺少 Tree Shaking | 统一 ESM、配置 sideEffects |

### 分包策略调整

- 大型库独立分包，利用浏览器缓存
- 动态 import() 延迟加载非首屏模块

:::

## 3. 首屏白屏时间过长优化

::: details
**问题**：Webpack 打包的单页应用首屏很慢，怎么优化？

### 网络层

- 开启 HTTP/2 与 Gzip/Brotli 压缩
- 静态资源上 CDN
- HTML 使用协商缓存，带 hash 的静态资源使用强缓存

### 包体积层

- 路由级代码分割：React.lazy / Vue 异步组件
- SplitChunks 抽离公共依赖
- 移除生产环境无用的代码（console、注释）

### 加载体验层

- HTML 内联关键 CSS
- 骨架屏占位
- preload 提前加载关键资源

:::

## 4. 构建速度慢排查

::: details
**问题**：项目从 10 秒构建变成 2 分钟，如何定位？

### 定位工具

- speed-measure-webpack-plugin 测量各 Loader/Plugin 耗时
- node --cpu-prof 生成 CPU profile 分析热点

### 常见原因

- babel-loader 未排除 node_modules
- 未开启持久化缓存
- 引入了重量级 Plugin（每次全量处理）
- 依赖数量暴涨（lock 文件变化）
- Windows 上路径监听开销大（改用 polling 或忽略大目录）

### 快速止血

```
cache: { type: 'filesystem' },
module: {
  rules: [
    {
      test: /\.js$/,
      exclude: /node_modules/,
      use: 'babel-loader?cacheDirectory'
    }
  ]
}
```

:::

## 5. 循环依赖问题

::: details
**问题**：a.js 和 b.js 相互引用，打包后会怎样？

### 执行结果

- Webpack 按 entry 的依赖顺序执行：先完整执行 a.js，再执行 b.js
- a.js 中在顶层访问 b.js 导出的值时得到 undefined
- 在函数内延迟访问则能拿到正确值

### 解决方案

- 抽取公共逻辑到第三个模块
- 延迟引用（函数内部 require/import）
- ESLint 规则 no-cycle 提前发现循环依赖

:::

## 6. 多页面应用配置

::: details
**问题**：如何用 Webpack 配置多页应用（MPA）？

### 配置要点

- entry 配置多个入口
- HtmlWebpackPlugin 每个页面一个实例
- SplitChunks 抽取公共模块避免重复打包

```
entry: {
  index: './src/pages/index/index.js',
  about: './src/pages/about/about.js'
},
plugins: [
  new HtmlWebpackPlugin({ template: './index.html', chunks: ['index'] }),
  new HtmlWebpackPlugin({ template: './about.html', chunks: ['about'] })
]
```

### 注意事项

- chunks 显式指定，防止页面互相引入对方的 chunk
- 公共代码自动通过 cacheGroups 抽取

:::

## 7. 环境变量注入

::: details
**问题**：如何在 Webpack 中区分开发和生产环境？

### 方式一：DefinePlugin

```
new DefinePlugin({
  'process.env.NODE_ENV': JSON.stringify('production')
})
```

### 方式二：mode 参数

- mode: 'production' 自动定义 NODE_ENV

### 方式三：dotenv 文件

- dotenv-webpack 读取 .env.production
- 注意敏感信息不要打进客户端包

### 常见坑

- DefinePlugin 值必须是 JSON.stringify 后的字符串
- 替换发生在编译期，运行时无法修改

:::

## 8. CSS 处理链路

::: details
**问题**：描述从 .scss 文件到页面的完整处理链路。

### Loader 链

sass-loader → css-loader → postcss-loader → style-loader / MiniCssExtractPlugin.loader

### 各环节职责

| Loader | 职责 |
|--------|------|
| sass-loader | SCSS → CSS |
| css-loader | 解析 @import、url()，CSS Modules 支持 |
| postcss-loader | autoprefixer 自动加前缀 |
| style-loader | 运行时将 CSS 插入 style 标签 |

### 生产环境

- 用 MiniCssExtractPlugin.loader 替代 style-loader
- CSS 单独成文件，可被浏览器并行下载和缓存
- 配合 contenthash 实现长效缓存

:::
