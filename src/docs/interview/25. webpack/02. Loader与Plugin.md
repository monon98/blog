# Loader 与 Plugin

## 1. Loader 与 Plugin 的区别

::: details
**问题**：Loader 和 Plugin 有什么区别？

### 本质区别

| 对比项 | Loader | Plugin |
|--------|--------|--------|
| 职责 | 转换文件内容 | 扩展构建流程 |
| 运行时机 | 模块编译阶段 | 整个构建生命周期 |
| 执行方式 | 链式调用（从右到左） | 通过 Tapable 钩子触发 |
| 配置位置 | module.rules | plugins 数组 |
| 形态 | 一个函数 | 一个带有 apply 方法的类 |

### 常用 Loader

- babel-loader：ES6+ 转译
- css-loader：解析 CSS 中的 @import 和 url()
- style-loader：将 CSS 注入 DOM
- sass-loader/less-loader：预处理 CSS
- ts-loader：TypeScript 编译
- thread-loader：多线程加速

### 常用 Plugin

- HtmlWebpackPlugin：生成 HTML 并自动引入资源
- MiniCssExtractPlugin：提取 CSS 为独立文件
- DefinePlugin：定义编译期常量
- CopyWebpackPlugin：复制静态文件
- TerserWebpackPlugin：压缩 JS（Webpack 5 内置）

:::

## 2. Loader 的执行顺序

::: details
**问题**：为什么 Loader 是从右到左执行的？

### 执行顺序

```
module: {
  rules: [
    {
      test: /\.scss$/,
      use: ['style-loader', 'css-loader', 'sass-loader']
    }
  ]
}
```

执行顺序：sass-loader → css-loader → style-loader

### 原因

- Webpack 采用 compose 函数式组合
- 类似 redux 中间件的洋葱模型
- 后配置的 Loader 先执行，保证依赖关系正确

### 手动控制顺序

- 使用 enforce: 'pre'（优先执行）
- 使用 enforce: 'post'（最后执行）

:::

## 3. 编写一个 Loader

::: details
**问题**：如何编写一个自定义 Loader？

### 基本 Loader

```
// loaders/simple-loader.js
module.exports = function (source) {
  // source 是文件的原始内容
  const result = source.replace(/console\.log\(.*?\);?/g, '');
  return result;
};
```

### 异步 Loader

```
module.exports = function (source) {
  const callback = this.async();
  someAsyncWork(source).then(result => {
    callback(null, result);
  });
};
```

### 常用 API

- this.async()：声明异步 Loader
- this.query：获取配置参数
- this.cacheable(false)：禁用缓存
- this.getOptions()：获取 schema 校验后的选项

:::

## 4. 编写一个 Plugin

::: details
**问题**：如何编写一个自定义 Plugin？

### 基本 Plugin

```
class MyPlugin {
  apply(compiler) {
    compiler.hooks.emit.tapAsync('MyPlugin', (compilation, callback) => {
      // compilation.assets 包含所有待输出的资源
      console.log('即将输出文件');
      callback();
    });
  }
}
```

### 常用钩子

| 钩子 | 触发时机 |
|------|----------|
| entryOption | 读取 entry 配置后 |
| compile | 开始新一次编译 |
| emit | 输出资源到磁盘前 |
| done | 构建完成后 |

### 钩子类型

- tap：同步钩子
- tapAsync：异步回调
- tapPromise：返回 Promise

:::

## 5. Babel 配置与原理

::: details
**问题**：Babel 的工作原理是什么？

### 编译三阶段

1. **Parse（解析）**：源码转换为 AST 抽象语法树
2. **Transform（转换）**：遍历 AST，调用插件进行转换
3. **Generate（生成）**：将转换后的 AST 生成目标代码

### 核心概念

- @babel/core：Babel 核心库
- preset：一组插件的集合（如 preset-env）
- plugin：单个转换插件
- polyfill：补齐 API 实现（如 Promise）

### Babel 与 Webpack 集成

- babel-loader 处理 JS 文件
- cacheDirectory 开启缓存加速二次构建
- exclude: /node_modules/ 减少处理范围

### polyfill 方案演进

- @babel/polyfill：全量引入，体积大（已废弃）
- useBuiltIns: 'usage'：按需引入
- core-js 3 + regenerator-runtime：当前标准方案

:::
