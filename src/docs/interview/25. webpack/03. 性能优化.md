# 性能优化

## 1. 构建速度优化

::: details
**问题**：如何优化 Webpack 构建速度？

### 缩小处理范围

- include/exclude 限定 Loader 处理范围
- resolve.modules 减少模块查找层级
- resolve.extensions 减少后缀尝试列表
- resolve.alias 配置路径别名

### 开启缓存

- Webpack 5：cache: { type: 'filesystem' } 持久化缓存
- babel-loader：cacheDirectory: true

### 多进程构建

- thread-loader：将耗时的 Loader 放到 Worker 池
- 注意：小项目多进程反而更慢（进程通信开销）

### 其他手段

- DllPlugin 预编译第三方库（Webpack 4 时代方案，5 中已被持久化缓存取代）
- noParse 忽略无需解析依赖的库
- 升级到最新版本 Webpack/Node

:::

## 2. 打包体积优化

::: details
**问题**：如何减小打包体积？

### 代码层面

- Tree Shaking：删除未使用的导出
- 代码分割：动态 import() 按需加载
- 按需引入：lodash → lodash-es、echarts 按需注册

### 压缩层面

- TerserWebpackPlugin 压缩 JS（生产模式内置）
- CssMinimizerPlugin 压缩 CSS
- image-webpack-loader 压缩图片

### 分析工具

- webpack-bundle-analyzer：可视化分析包内容
- speed-measure-webpack-plugin：测量各环节耗时

### externals

- 通过 CDN 引入大型库，打包时排除（如 React、Vue）

:::

## 3. Tree Shaking 原理

::: details
**问题**：Tree Shaking 的工作原理和使用条件是什么？

### 工作原理

- 基于 ES Module 的静态结构分析
- usedExports 标记未被使用的导出
- Terser 在压缩阶段删除这些死代码

### 使用条件

- 使用 ES Module 语法（import/export）
- production 模式（自动开启 optimization.usedExports）
- package.json 设置 sideEffects 字段声明副作用

### sideEffects 示例

```
{
  "sideEffects": [
    "*.css",
    "./src/polyfills.js"
  ]
}
```

- false 表示所有文件都无副作用，可放心摇树
- 数组列出有副作用的文件，跳过摇树

### CommonJS 为什么不行

- require 是运行时动态加载
- 无法在编译期确定哪些导出被使用

:::

## 4. 代码分割策略

::: details
**问题**：SplitChunksPlugin 如何配置？

### 三种分割方式

- 多入口：entry 配置多个入口文件
- 动态导入：import() 语法自动分割
- SplitChunksPlugin：提取公共模块

### SplitChunks 关键配置

```
optimization: {
  splitChunks: {
    chunks: 'all',
    minSize: 20000,
    maxAsyncRequests: 30,
    cacheGroups: {
      vendors: {
        test: /[\\/]node_modules[\\/]/,
        priority: -10,
        name: 'vendors'
      },
      common: {
        minChunks: 2,
        priority: -20,
        reuseExistingChunk: true
      }
    }
  }
}
```

### 配置说明

- chunks: 'all'：同步异步代码都分割
- minSize：生成 chunk 的最小体积
- cacheGroups.priority：优先级，数值大的先匹配

:::

## 5. 长效缓存策略

::: details
**问题**：如何让浏览器缓存最大化利用？

### 文件命名

- [contenthash]：基于文件内容的哈希
- 内容不变则 hash 不变，浏览器命中强缓存

### runtime 抽离

```
optimization: {
  runtimeChunk: 'single'
}
```

- 将 webpack runtime 抽离为独立文件
- 避免业务代码变化导致所有 chunk hash 变化

### moduleIds 策略

- deterministic：基于模块路径生成稳定 ID
- 避免新增/删除模块导致其他模块 ID 变化

:::
