# 面试场景题

## 1. SSR 数据获取

::: details
**问题**：在 Nuxt 3 中如何正确获取服务端数据？

### useFetch vs useAsyncData

- useFetch：简单请求，自动序列化
- useAsyncData：复杂场景，支持缓存和转换

### 使用场景

- 首屏数据需要 SSR：useFetch 或 useAsyncData
- 客户端数据：useFetch + lazy 选项
- 需要缓存：useAsyncData + cachedData 选项

### 注意事项

- 不要在 onMounted 中获取数据
- 处理加载状态和错误状态
- 使用 key 实现缓存控制

:::

## 2. SSR vs CSR 选择

::: details
**问题**：什么场景用 SSR？什么场景用 CSR？

### SSR 适用场景

- SEO 要求高：博客、电商、新闻
- 首屏性能要求高
- 需要社交分享（Open Graph）
- 需要预渲染

### CSR 适用场景

- 后台管理系统
- 登录后的私有页面
- 复杂交互应用
- SEO 要求低

### Nuxt 3 混合模式

- 定义路由级别的渲染模式
- 使用 definePageMeta 配置
- 灵活切换 SSR/CSR

:::

## 3. 服务端渲染缓存

::: details
**问题**：如何优化 Nuxt 3 的 SSR 缓存？

### 缓存策略

- 使用 cachedData 选项
- 使用 routeRules 配置路由缓存
- 使用 Nitro 的缓存功能

### 缓存粒度

- 全局缓存：nitro.config 配置
- 路由缓存：routeRules 配置

### 失效策略

- 基于时间失效
- 基于事件失效
- 手动清除缓存

:::

## 6. 状态管理

::: details
**问题**：Nuxt 3 中如何管理状态？

### 状态管理方案

- useState：组件间共享状态
- useAsyncData：服务端数据
- Pinia：全局状态管理
- Composables：组合式函数

### useState vs Pinia

| 场景 | useState | Pinia |
|------|----------|-------|
| 简单状态 | ✅ 推荐 | 可以 |
| 复杂状态 | 可以 | ✅ 推荐 |
| 持久化 | 需要配置 | 支持插件 |
| DevTools | 基础 | 完整 |

### 最佳实践

- 优先使用 useState
- 复杂状态使用 Pinia
- 服务端状态使用 useAsyncData

:::

## 7. API 路由

::: details
**问题**：Nuxt 3 API 路由如何设计？

### 路由约定

- server/api/ 目录下的文件自动成为 API 路由
- 支持动态路由：[id].ts
- 支持路由组：[...].ts

### 请求处理

- 使用 eventHandler 处理请求
- 使用 getQuery 获取查询参数
- 使用 readBody 获取请求体

### 中间件

- 使用 defineEventHandler 定义
- 支持请求拦截
- 支持 CORS 配置

:::
