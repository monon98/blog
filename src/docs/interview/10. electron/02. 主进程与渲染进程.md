# 主进程与渲染进程

## 1. 主进程详解

::: details
主进程是 Electron 应用的核心，负责管理应用的生命周期和系统级功能。

### 创建主进程

```javascript
// main.js
const { app, BrowserWindow } = require('electron');
const path = require('path');

function createWindow() {
  const win = new BrowserWindow({
    width: 800,
    height: 600,
    webPreferences: {
      nodeIntegration: false,
      contextIsolation: true
    }
  });

  win.loadFile('index.html');
}

app.whenReady().then(() => {
  createWindow();

  app.on('activate', () => {
    if (BrowserWindow.getAllWindows().length === 0) {
      createWindow();
    }
  });
});

app.on('window-all-closed', () => {
  if (process.platform !== 'darwin') {
    app.quit();
  }
});
```

### 应用生命周期

| 事件 | 说明 |
|------|------|
| `ready` | 应用准备就绪，可以创建窗口 |
| `window-all-closed` | 所有窗口关闭 |
| `activate` | 应用被激活（macOS） |
| `before-quit` | 应用即将退出 |
| `will-quit` | 应用即将退出，所有窗口已关闭 |
| `quit` | 应用退出 |

### 主进程 API

```javascript
const { app, BrowserWindow, Menu, Tray, dialog, ipcMain } = require('electron');

// 应用信息
app.getVersion();          // 获取应用版本
app.name;                  // 获取应用名称（app.getName() 已弃用）
app.getPath('home');       // 获取系统路径

// 窗口管理
BrowserWindow.getAllWindows();  // 获取所有窗口

// 对话框
dialog.showOpenDialog({ properties: ['openFile'] });
dialog.showMessageBox({ type: 'info', message: 'Hello' });

// 菜单
const menu = Menu.buildFromTemplate([]);
Menu.setApplicationMenu(menu);

// 托盘
const tray = new Tray('icon.png');
```

### 总结

主进程是 Electron 应用的入口点，负责管理应用的生命周期、创建窗口、处理系统事件等。主进程可以使用 Node.js 的所有 API，也可以使用 Electron 提供的系统级 API。

:::

## 2. 渲染进程详解

::: details
渲染进程负责 Web 页面的渲染和用户交互，每个窗口都有自己的渲染进程。

### 渲染进程配置

```javascript
// 主进程中创建窗口时配置
const win = new BrowserWindow({
  webPreferences: {
    nodeIntegration: false,      // 禁用 Node.js 集成（默认值）
    contextIsolation: true,      // 启用上下文隔离（默认值）
    sandbox: true,               // 启用沙箱（当 nodeIntegration=false 时默认启用）
    preload: path.join(__dirname, 'preload.js'),  // 预加载脚本
    webSecurity: true,           // 启用 Web 安全（默认值）
    allowRunningInsecureContent: false  // 禁止不安全内容（默认值）
  }
});

// 推荐：在 app.ready 之前全局启用沙箱
app.enableSandbox();
```

### 渲染进程中的 Node.js

```javascript
// 渲染进程中使用 Node.js（不推荐）
const fs = require('fs');
const path = require('path');

// 推荐：通过 preload 脚本暴露安全的 API
```

### 预加载脚本

```javascript
// preload.js
const { contextBridge, ipcRenderer } = require('electron');

// 安全地暴露 API 给渲染进程
contextBridge.exposeInMainWorld('electronAPI', {
  send: (channel, data) => {
    const validChannels = ['toMain'];
    if (validChannels.includes(channel)) {
      ipcRenderer.send(channel, data);
    }
  },
  receive: (channel, func) => {
    const validChannels = ['fromMain'];
    if (validChannels.includes(channel)) {
      ipcRenderer.on(channel, (event, ...args) => func(...args));
    }
  }
});
```

### 渲染进程生命周期

```javascript
// 渲染进程中
window.addEventListener('DOMContentLoaded', () => {
  // DOM 加载完成
});

window.addEventListener('load', () => {
  // 页面完全加载
});

window.addEventListener('beforeunload', () => {
  // 页面即将卸载
});
```

### 总结

渲染进程负责 Web 页面的渲染和用户交互。出于安全考虑，现代 Electron 应用通常禁用 `nodeIntegration` 并启用 `contextIsolation`，通过预加载脚本安全地暴露 API。

:::

## 3. 主进程与渲染进程的区别

::: details
主进程和渲染进程有不同的职责和能力，理解它们的区别对于开发 Electron 应用至关重要。

### 职责对比

| 特性 | 主进程 | 渲染进程 |
|------|--------|----------|
| 职责 | 应用生命周期管理、系统交互 | 页面渲染、用户交互 |
| 进程数量 | 1 个 | 可以有多个（每个窗口一个） |
| Node.js | 完整支持 | 默认不支持（需配置） |
| DOM | 不支持 | 支持 |
| 原生 UI | 支持（窗口、菜单等） | 不支持 |
| 系统 API | 完整支持 | 受限 |

### 能力对比

```javascript
// 主进程可以做的
const { app, BrowserWindow, Menu, Tray, dialog, shell } = require('electron');

app.quit();                          // 退出应用
new BrowserWindow();                 // 创建窗口
Menu.setApplicationMenu(menu);       // 设置菜单
new Tray('icon.png');               // 创建托盘
dialog.showOpenDialog();            // 显示对话框
shell.openExternal('https://...');   // 打开外部链接

// 渲染进程可以做的
document.getElementById('app');     // 操作 DOM
window.addEventListener('click', handle);  // 监听事件
fetch('https://api.example.com');   // 发起网络请求
```

### 通信方式

```javascript
// 主进程 -> 渲染进程
win.webContents.send('channel', data);

// 渲染进程 -> 主进程
ipcRenderer.send('channel', data);

// 双向通信
ipcRenderer.invoke('channel', data).then(result => { ... });
```

### 数据共享

```javascript
// 主进程
const store = new Map();

// 渲染进程无法直接访问主进程数据
// 需要通过 IPC 通信

// 方案1：使用 electron-store
const Store = require('electron-store');
const store = new Store();
store.set('key', 'value');
store.get('key');

// 方案2：使用全局变量（不推荐）
global.sharedObject = { data: {} };
```

### 总结

主进程和渲染进程分工明确，主进程负责系统级操作，渲染进程负责页面展示。两者通过 IPC 通信，数据共享需要通过 IPC 或持久化存储实现。

:::

## 4. 上下文隔离（Context Isolation）

::: details
上下文隔离是 Electron 的一项重要安全特性，它防止渲染进程直接访问主进程的全局对象。

### 为什么需要上下文隔离

1. **安全考虑**：防止恶意脚本访问 Node.js API
2. **隔离性**：确保预加载脚本和页面脚本在不同的上下文中执行
3. **兼容性**：支持内容安全策略（CSP）

### 配置上下文隔离

```javascript
// 主进程中
const win = new BrowserWindow({
  webPreferences: {
    contextIsolation: true,  // 启用上下文隔离
    nodeIntegration: false,  // 禁用 Node.js 集成
    preload: path.join(__dirname, 'preload.js')
  }
});
```

### 上下文隔离的影响

```javascript
// 启用上下文隔离后
// 渲染进程中无法直接访问
require('fs');          // 错误：require is not defined
process.env;           // 错误：process is not defined
global;                // 错误：global is not defined

// 需要通过预加载脚本暴露 API
// preload.js
const { contextBridge, ipcRenderer } = require('electron');

contextBridge.exposeInMainWorld('myAPI', {
  readFile: (path) => ipcRenderer.invoke('read-file', path)
});

// 渲染进程中使用
const content = await window.myAPI.readFile('/path/to/file');
```

### 上下文隔离原理

```
┌─────────────────────────────────────┐
│           渲染进程                   │
│                                     │
│  ┌─────────────────────────────┐   │
│  │     页面脚本上下文            │   │
│  │  - 只能访问 Web API          │   │
│  │  - 不能访问 Node.js API     │   │
│  └─────────────────────────────┘   │
│              ↑                      │
│              │ contextBridge       │
│              ↓                      │
│  ┌─────────────────────────────┐   │
│  │   预加载脚本上下文            │   │
│  │  - 可以访问 Node.js API     │   │
│  │  - 可以访问 Electron API    │   │
│  └─────────────────────────────┘   │
└─────────────────────────────────────┘
```

### 总结

上下文隔离是 Electron 的重要安全特性，它通过隔离页面脚本和预加载脚本的执行上下文，防止恶意脚本访问系统资源。现代 Electron 应用应该始终启用上下文隔离。

:::

## 5. 沙箱模式（Sandbox）

::: details
沙箱模式是 Electron 提供的另一项安全特性，它限制渲染进程中可用的系统资源。

### 沙箱的作用

1. **限制系统调用**：防止渲染进程直接访问系统资源
2. **进程隔离**：渲染进程运行在受限的环境中
3. **安全增强**：与操作系统级别的沙箱配合使用

### 配置沙箱

```javascript
// 主进程中
const win = new BrowserWindow({
  webPreferences: {
    sandbox: true,  // 启用沙箱
    contextIsolation: true,
    nodeIntegration: false,
    preload: path.join(__dirname, 'preload.js')
  }
});
```

### 沙箱模式下的限制

```javascript
// 沙箱模式下渲染进程中无法使用
const { execSync } = require('child_process');  // 无法使用
const fs = require('fs');                        // 无法使用
const path = require('path');                    // 无法使用

// 只能通过预加载脚本暴露的安全 API 使用
// preload.js
const { contextBridge, ipcRenderer } = require('electron');

contextBridge.exposeInMainWorld('myAPI', {
  execCommand: (cmd) => ipcRenderer.invoke('exec-command', cmd),
  readFile: (path) => ipcRenderer.invoke('read-file', path)
});
```

### 沙箱与上下文隔离的关系

| 配置 | 说明 |
|------|------|
| `sandbox: true, contextIsolation: true` | 最安全，推荐配置 |
| `sandbox: false, contextIsolation: true` | 较安全，渲染进程可使用部分 Node.js API |
| `sandbox: true, contextIsolation: false` | 不推荐，存在安全风险 |
| `sandbox: false, contextIsolation: false` | 不安全，不推荐 |

### 沙箱模式下的预加载脚本

```javascript
// 沙箱模式下预加载脚本可以使用
const { contextBridge, ipcRenderer } = require('electron');

// 可以使用 IPC 通信
ipcRenderer.send('channel', data);
ipcRenderer.invoke('channel', data);

// 可以暴露安全的 API
contextBridge.exposeInMainWorld('myAPI', {
  send: (data) => ipcRenderer.send('to-main', data),
  invoke: (data) => ipcRenderer.invoke('from-main', data)
});
```

### 总结

沙箱模式是 Electron 的重要安全特性，它限制渲染进程中可用的系统资源，防止恶意脚本访问系统。现代 Electron 应用应该同时启用沙箱和上下文隔离。

:::
