# Electron 基础概念

## 1. 什么是 Electron

::: details
Electron 是一个基于 Chromium 和 Node.js 的桌面应用程序框架，允许使用 Web 技术（HTML、CSS、JavaScript）构建跨平台的桌面应用。

### 核心特点

- **跨平台**：支持 Windows、macOS、Linux
- **Web 技术栈**：使用 HTML、CSS、JavaScript 开发
- **双进程架构**：主进程（Main Process）和渲染进程（Renderer Process）
- **Node.js 集成**：渲染进程中可直接使用 Node.js API
- **Chromium 内核**：支持最新的 Web 特性

### 技术栈

| 组件 | 作用 |
|------|------|
| Chromium | 提供 Web 页面渲染能力 |
| Node.js | 提供系统级 API 访问能力 |
| 自定义 API | 提供桌面应用特有功能（窗口管理、托盘、通知等） |

### 与其他方案对比

| 方案 | 优点 | 缺点 |
|------|------|------|
| Electron | 生态成熟、社区活跃 | 包体积大、内存占用高 |
| Tauri | 包体积小、性能好 | 生态较新、需要 Rust |
| Flutter Desktop | 性能好、UI 一致 | Web 技术栈支持有限 |
| .NET MAUI | 原生性能 | 开发效率较低 |

### 总结

Electron 是一个成熟的桌面应用开发框架，适合已有 Web 技术栈的团队快速开发跨平台桌面应用。虽然包体积和内存占用较大，但其丰富的生态和成熟的解决方案使其仍然是桌面应用开发的主流选择。

:::

## 2. Electron 的架构

::: details
Electron 采用双进程架构，主进程负责系统级功能，渲染进程负责页面展示。

### 进程模型

```
┌─────────────────────────────────────┐
│           主进程 (Main Process)        │
│  - 应用生命周期管理                      │
│  - 原生 UI 创建（窗口、菜单、托盘）       │
│  - 系统级 API 调用                       │
│  - 进程间通信管理                        │
└─────────────────────────────────────┘
                    │
                    │ IPC
                    │
┌─────────────────────────────────────┐
│         渲染进程 (Renderer Process)    │
│  - Web 页面渲染                        │
│  - DOM 操作                           │
│  - 用户交互                           │
│  - 可选：Node.js 集成                  │
└─────────────────────────────────────┘
```

### 主进程职责

1. **应用生命周期**：管理应用的启动、退出、激活等事件
2. **窗口管理**：创建、管理、销毁 BrowserWindow
3. **原生 UI**：创建菜单、托盘、通知等原生组件
4. **系统交互**：访问文件系统、执行系统命令
5. **IPC 管理**：处理主进程与渲染进程间的通信

### 渲染进程职责

1. **页面渲染**：负责 Web 页面的展示
2. **用户交互**：处理用户输入、点击等事件
3. **DOM 操作**：操作页面元素
4. **业务逻辑**：执行应用的业务代码

### 总结

Electron 的双进程架构将系统级操作和页面渲染分离，主进程处理系统交互，渲染进程处理页面展示，两者通过 IPC 通信。

:::
