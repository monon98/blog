# IPC 通信

## 1. IPC 基础概念

::: details
IPC（Inter-Process Communication）是 Electron 中主进程和渲染进程之间通信的机制。

### 为什么需要 IPC

1. **进程隔离**：主进程和渲染进程运行在不同的进程中
2. **安全考虑**：防止渲染进程直接访问系统资源
3. **职责分离**：主进程处理系统操作，渲染进程处理页面展示

### IPC 通信方式

| 方向 | 方法 | 说明 |
|------|------|------|
| 渲染 → 主进程 | `ipcRenderer.send` | 异步发送消息 |
| 渲染 → 主进程 | `ipcRenderer.invoke` | 异步发送消息并等待响应 |
| 主进程 → 渲染 | `webContents.send` | 异步发送消息 |
| 渲染 → 主进程 | `ipcRenderer.sendSync` | 同步发送消息（不推荐） |

### 基本示例

```javascript
// 主进程 (main.js)
const { ipcMain } = require('electron');

ipcMain.on('channel', (event, data) => {
  console.log('收到消息:', data);
  event.reply('response', '已收到');
});

ipcMain.handle('channel', async (event, data) => {
  console.log('收到消息:', data);
  return '处理完成';
});

// 渲染进程 (renderer.js)
// 注意：以下代码仅在 nodeIntegration: true, contextIsolation: false 时可用
// 现代 Electron 推荐使用预加载脚本暴露 API（见预加载脚本章节）
const { ipcRenderer } = require('electron');

// 发送消息（不等待响应）
ipcRenderer.send('channel', 'hello');

// 发送消息并等待响应
const result = await ipcRenderer.invoke('channel', 'hello');
console.log(result); // '处理完成'
```

### 总结

IPC 是 Electron 中主进程和渲染进程通信的唯一方式，它提供了安全、高效的进程间通信机制。

:::

## 2. IPC 通信模式

::: details
Electron 提供了多种 IPC 通信模式，适用于不同的场景。

### 单向通信

```javascript
// 渲染进程 -> 主进程
// renderer.js（需要 nodeIntegration: true，不推荐）
ipcRenderer.send('to-main', { action: 'save', data: 'hello' });

// main.js
ipcMain.on('to-main', (event, payload) => {
  console.log(payload); // { action: 'save', data: 'hello' }
});
```

```javascript
// 主进程 -> 渲染进程
// main.js
win.webContents.send('to-renderer', { event: 'update', data: 100 });

// renderer.js（需要 nodeIntegration: true，不推荐）
ipcRenderer.on('to-renderer', (event, payload) => {
  console.log(payload); // { event: 'update', data: 100 }
});
```

### 双向通信（请求-响应）

```javascript
// renderer.js
const result = await ipcRenderer.invoke('get-data', { id: 1 });
console.log(result);

// main.js
ipcMain.handle('get-data', async (event, { id }) => {
  const data = await fetchDataFromDB(id);
  return data;
});
```

### 同步通信（不推荐）

```javascript
// renderer.js（阻塞渲染进程）
const result = ipcRenderer.sendSync('sync-channel', data);

// main.js
ipcMain.on('sync-channel', (event, data) => {
  event.returnValue = '同步响应';
});
```

### 错误处理

```javascript
// renderer.js
try {
  const result = await ipcRenderer.invoke('channel', data);
} catch (error) {
  console.error('IPC 调用失败:', error);
}

// main.js
ipcMain.handle('channel', async (event, data) => {
  try {
    const result = await processData(data);
    return result;
  } catch (error) {
    throw new Error('处理失败: ' + error.message);
  }
});
```

### 进度通知

```javascript
// main.js
ipcMain.handle('long-task', async (event, data) => {
  for (let i = 0; i <= 100; i += 10) {
    event.sender.send('progress', i);
    await new Promise(resolve => setTimeout(resolve, 100));
  }
  return '完成';
});

// renderer.js
ipcRenderer.on('progress', (event, percent) => {
  console.log(`进度: ${percent}%`);
});

const result = await ipcRenderer.invoke('long-task', data);
```

### 总结

Electron 提供了多种 IPC 通信模式，推荐使用 `ipcRenderer.invoke` 和 `ipcMain.handle` 进行双向通信，避免使用同步通信。

:::

## 3. 预加载脚本与 IPC

::: details
预加载脚本是连接主进程和渲染进程的桥梁，它在渲染进程创建时执行，但拥有完整的 Node.js 访问权限。

### 预加载脚本的作用

1. **安全暴露 API**：只暴露需要的 API 给渲染进程
2. **数据验证**：验证和过滤渲染进程发送的数据
3. **错误处理**：统一处理 IPC 通信的错误

### 预加载脚本示例

```javascript
// preload.js
const { contextBridge, ipcRenderer } = require('electron');

// 验证通道名
const validSendChannels = ['to-main'];
const validInvokeChannels = ['get-data', 'save-data'];
const validReceiveChannels = ['from-main'];

contextBridge.exposeInMainWorld('electronAPI', {
  // 单向发送
  send: (channel, data) => {
    if (validSendChannels.includes(channel)) {
      ipcRenderer.send(channel, data);
    }
  },
  
  // 双向调用
  invoke: async (channel, data) => {
    if (validInvokeChannels.includes(channel)) {
      return await ipcRenderer.invoke(channel, data);
    }
    throw new Error('Invalid channel');
  },
  
  // 接收消息
  receive: (channel, callback) => {
    if (validReceiveChannels.includes(channel)) {
      const subscription = (event, ...args) => callback(...args);
      ipcRenderer.on(channel, subscription);
      
      // 返回取消订阅函数
      return () => {
        ipcRenderer.removeListener(channel, subscription);
      };
    }
  }
});
```

### 渲染进程中使用

```javascript
// renderer.js
// 发送消息
window.electronAPI.send('to-main', { action: 'save' });

// 调用并等待响应
const data = await window.electronAPI.invoke('get-data', { id: 1 });

// 接收消息
const unsubscribe = window.electronAPI.receive('from-main', (data) => {
  console.log('收到消息:', data);
});

// 取消订阅
unsubscribe();
```

### 主进程处理

```javascript
// main.js
const { ipcMain } = require('electron');

ipcMain.on('to-main', (event, data) => {
  console.log('收到消息:', data);
});

ipcMain.handle('get-data', async (event, { id }) => {
  const data = await fetchDataFromDB(id);
  return data;
});
```

### 安全考虑

```javascript
// preload.js - 安全的 API 暴露
contextBridge.exposeInMainWorld('electronAPI', {
  // 使用类型检查确保数据安全
  readFile: async (path) => {
    if (typeof path !== 'string') {
      throw new Error('Path must be a string');
    }
    return await ipcRenderer.invoke('read-file', path);
  },
  
  // 使用白名单限制通道
  send: (channel, data) => {
    const allowedChannels = ['to-main'];
    if (!allowedChannels.includes(channel)) {
      throw new Error('Invalid channel');
    }
    ipcRenderer.send(channel, data);
  }
});
```

### 总结

预加载脚本是 Electron 安全架构的核心，它通过 `contextBridge` 安全地暴露 API 给渲染进程，同时通过白名单机制限制可用的通道，防止恶意代码利用 IPC 通信。

:::

## 4. IPC 通信最佳实践

::: details
遵循最佳实践可以确保 IPC 通信的安全性和效率。

### 1. 使用类型定义

```typescript
// electron.d.ts
export interface ElectronAPI {
  send: (channel: string, data: unknown) => void;
  invoke: (channel: string, data: unknown) => Promise<unknown>;
  receive: (channel: string, callback: (...args: unknown[]) => void) => () => void;
}

// preload.js
const { contextBridge, ipcRenderer } = require('electron');

contextBridge.exposeInMainWorld('electronAPI', {
  send: (channel, data) => ipcRenderer.send(channel, data),
  invoke: (channel, data) => ipcRenderer.invoke(channel, data),
  receive: (channel, callback) => {
    const subscription = (event, ...args) => callback(...args);
    ipcRenderer.on(channel, subscription);
    return () => ipcRenderer.removeListener(channel, subscription);
  }
});
```

### 2. 验证通道名称

```javascript
// preload.js
const VALID_CHANNELS = {
  send: ['to-main'],
  invoke: ['get-data', 'save-data'],
  receive: ['from-main']
};

contextBridge.exposeInMainWorld('electronAPI', {
  send: (channel, data) => {
    if (!VALID_CHANNELS.send.includes(channel)) {
      throw new Error(`Invalid send channel: ${channel}`);
    }
    ipcRenderer.send(channel, data);
  }
});
```

### 3. 错误处理

```javascript
// main.js
ipcMain.handle('risky-operation', async (event, data) => {
  try {
    const result = await performOperation(data);
    return { success: true, data: result };
  } catch (error) {
    return { success: false, error: error.message };
  }
});

// renderer.js
const response = await window.electronAPI.invoke('risky-operation', data);
if (response.success) {
  console.log('成功:', response.data);
} else {
  console.error('失败:', response.error);
}
```

### 4. 避免内存泄漏

```javascript
// renderer.js - 正确清理 IPC 监听器
class IPCManager {
  constructor() {
    this.cleanupFns = [];
  }
  
  on(channel, callback) {
    const cleanup = window.electronAPI.receive(channel, callback);
    this.cleanupFns.push(cleanup);
  }
  
  destroy() {
    this.cleanupFns.forEach(cleanup => cleanup());
    this.cleanupFns = [];
  }
}

// 组件卸载时清理
const ipcManager = new IPCManager();
ipcManager.on('update', handleUpdate);

// 组件卸载时
ipcManager.destroy();
```

### 5. 使用类型安全的 IPC 封装

```javascript
// ipc.js
class TypedIPC {
  constructor(channel, schema) {
    this.channel = channel;
    this.schema = schema;
  }
  
  async send(data) {
    if (!this.schema.validate(data)) {
      throw new Error('Invalid data');
    }
    return await window.electronAPI.invoke(this.channel, data);
  }
}

// 使用
const getUser = new TypedIPC('get-user', userSchema);
const user = await getUser.send({ id: 1 });
```

### 总结

IPC 通信的最佳实践包括：使用类型定义、验证通道名称、正确处理错误、避免内存泄漏、使用类型安全的封装。这些实践可以确保 IPC 通信的安全性和可维护性。

:::

## 5. IPC 通信性能优化

::: details
IPC 通信可能成为应用性能的瓶颈，以下是一些优化建议。

### 1. 减少通信频率

```javascript
// 不推荐：频繁通信
for (let i = 0; i < 100; i++) {
  ipcRenderer.send('update', { index: i });
}

// 推荐：批量通信
ipcRenderer.send('batch-update', Array.from({ length: 100 }, (_, i) => ({ index: i })));
```

### 2. 使用结构化克隆

```javascript
// 不推荐：序列化大对象
const largeData = { /* 大量数据 */ };
ipcRenderer.send('data', JSON.stringify(largeData));
const parsed = JSON.parse(result);

// 推荐：使用结构化克隆
ipcRenderer.send('data', largeData);
// Electron 内部使用结构化克隆，比 JSON 更高效
```

### 3. 使用 SharedArrayBuffer

```javascript
// 主进程
const { ipcMain } = require('electron');

ipcMain.on('share-buffer', (event) => {
  const buffer = new SharedArrayBuffer(1024);
  const view = new Int32Array(buffer);
  view[0] = 42;
  event.reply('buffer-ready', buffer);
});

// 渲染进程
ipcRenderer.on('buffer-ready', (event, buffer) => {
  const view = new Int32Array(buffer);
  console.log(view[0]); // 42
});
```

### 4. 使用 MessagePort

```javascript
// 主进程
const { MessageChannelMain } = require('electron');

ipcMain.handle('create-port', () => {
  const { port1, port2 } = new MessageChannelMain();
  
  // 将 port1 发送给渲染进程1
  win1.webContents.postMessage('port', null, [port1]);
  
  // 将 port2 发送给渲染进程2
  win2.webContents.postMessage('port', null, [port2]);
  
  return 'ports created';
});

// 渲染进程
ipcRenderer.on('port', (event) => {
  const [port] = event.ports;
  
  port.onmessage = (messageEvent) => {
    console.log('收到消息:', messageEvent.data);
  };
  
  port.postMessage('Hello from renderer');
});
```

### 5. 避免同步通信

```javascript
// 不推荐：同步通信（阻塞渲染进程）
const result = ipcRenderer.sendSync('sync-channel', data);

// 推荐：异步通信
const result = await ipcRenderer.invoke('async-channel', data);
```

### 总结

IPC 通信性能优化包括：减少通信频率、使用结构化克隆、使用 SharedArrayBuffer、使用 MessagePort、避免同步通信。这些优化可以显著提升应用的响应速度。

:::
