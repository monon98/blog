# 观察者模式

> 难度：简单 | 标签：设计模式、一对多依赖

## 题目描述

用代码表达观察者模式（Observer Pattern）：

- `Subject`（目标/被观察者）：维护观察者列表，提供 `addObserver`、`removeObserver`、`notify` 方法
- `Observer`（观察者）：实现 `update` 方法接收通知
- 目标状态变化时主动遍历通知所有观察者，双方松耦合（只依赖抽象接口）

**示例：**

```javascript
const subject = new Subject();
const a = new Observer((data) => console.log("A 收到:", data));
subject.addObserver(a);
subject.setState(42);
// A 收到: 42
```

## 题解

::: details 点击查看题解

### 思路

两个类 + 一个列表：

1. Subject 持有 observers 数组，状态 setter 里调用 notify 遍历触发 update
2. Observer 用构造函数注入回调，保持通用性
3. 与发布订阅的关键区别：观察者直接订阅目标本体，**没有中间调度中心**；目标知道观察者的存在。发布订阅里双方互不相识

Vue2 的响应式系统就是观察者模式的工业级应用：Dep 是 Subject，Watcher 是 Observer。

### 代码实现

```javascript
class Subject {
  constructor() {
    this.observers = [];
    this.state = null;
  }

  addObserver(observer) {
    if (!this.observers.includes(observer)) {
      this.observers.push(observer);
    }
    return this;
  }

  removeObserver(observer) {
    this.observers = this.observers.filter((o) => o !== observer);
    return this;
  }

  setState(newState) {
    this.state = newState;
    this.notify();
  }

  notify() {
    for (const observer of [...this.observers]) {
      observer.update(this.state);
    }
  }
}

class Observer {
  constructor(name, onUpdate) {
    this.name = name;
    this.update = onUpdate;
  }
}
```

### 考察点

- 观察者 vs 发布订阅的辨析是高频概念题
- notify 前复制数组防止「通知过程中增删观察者」导致的跳变
- 应用实例：Vue 的 Dep/Watcher、DOM 事件（广义）、WebSocket 推送分发
- 追问：如何避免重复注册、如何实现带优先级的通知顺序
