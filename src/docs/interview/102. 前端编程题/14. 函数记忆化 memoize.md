# 函数记忆化 memoize

> 难度：简单 | 标签：闭包、缓存、高阶函数

## 题目描述

实现 `memoize(fn, resolver)`，为纯函数添加结果缓存：

- 相同参数的重复调用直接返回缓存结果，不再执行原函数
- 默认以第一个参数作为缓存键；可选 `resolver` 函数自定义键生成规则
- 缓存对象需暴露在返回函数上（如 lodash 的 `memoized.cache`）便于检查与清理

**示例：**

```javascript
let calls = 0;
const slowSquare = memoize((n) => {
  calls++;
  return n * n;
});

slowSquare(4); // 16，calls === 1
slowSquare(4); // 16，calls 仍为 1，命中缓存
```

## 题解

::: details 点击查看题解

### 思路

闭包持有 Map 作为缓存仓库。调用时先算键（默认取首参，多参场景用 resolver 或 `JSON.stringify(args)` 序列化为键），命中即返回；未命中才执行并写入。

适用前提是函数必须纯：相同输入恒定输出、无副作用。对依赖时间/随机数的函数记忆化会得到错误结果。

### 代码实现

```javascript
function memoize(fn, resolver) {
  if (typeof fn !== "function") {
    throw new TypeError("memoize expects a function");
  }

  function memoized(...args) {
    const key = resolver
      ? resolver(...args)
      : args.length === 1
        ? args[0]
        : JSON.stringify(args);
    if (cache.has(key)) {
      return cache.get(key);
    }
    const result = fn.apply(this, args);
    cache.set(key, result);
    return result;
  }

  const cache = new Map();
  memoized.cache = cache;
  return memoized;
}
```

### 考察点

- 空间换时间的经典模式，与「动态规划的备忘录」同源
- 多参数作键的三种策略：JSON.stringify / resolver / 参数展开嵌套 Map
- 应用场景：斐波那契等递归优化、昂贵计算缓存、React useMemo 的思想雏形
- 追问：缓存上限与 LRU 结合（见 LRU 一题）、弱引用键 WeakMap 的适用边界
