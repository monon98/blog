# 并发控制 limitConcurrency

> 难度：中等 | 标签：Promise、异步调度、并发

## 题目描述

实现异步任务并发控制器 `limitConcurrency(tasks, limit)`：

- `tasks` 是返回 Promise 的工厂函数数组（注意不是 Promise 实例，否则任务已同时启动）
- 最多同时运行 `limit` 个任务
- 某个任务完成后立即从队列取下一个补位（保持满负荷）
- 全部完成后按**原始顺序** resolve 结果数组

**示例：**

```javascript
const tasks = urls.map((url) => () => fetch(url));
limitConcurrency(tasks, 3).then((responses) => {
  console.log(responses);
});
```

## 题解

::: details 点击查看题解

### 思路

「工作池」模型：

1. 先启动 `min(limit, total)` 个任务占满槽位
2. 维护一个游标 index 表示「下一个待领取的任务」，每个任务完成时立刻让游标对应的任务顶上——这就是「完成即补位」的关键
3. 用 finished 计数判断全部结束；结果按当前下标写入保证顺序
4. 任务工厂延迟执行是前提条件，直接传 Promise 实例会失去控制意义——面试必讲这一点

### 代码实现

```javascript
function limitConcurrency(taskFactories, limit) {
  return new Promise((resolve, reject) => {
    const total = taskFactories.length;
    const results = new Array(total);
    let nextIndex = 0;
    let settledCount = 0;
    let rejected = false;

    function run() {
      if (rejected) return;
      if (settledCount === total) {
        return resolve(results);
      }
      if (nextIndex >= total) return;

      const current = nextIndex++;
      taskFactories[current]()
        .then((value) => {
          results[current] = { status: "fulfilled", value };
        })
        .catch((reason) => {
          results[current] = { status: "rejected", reason };
        })
        .finally(() => {
          settledCount++;
          run();
        });
    }

    for (let i = 0; i < Math.min(limit, total); i++) {
      run();
    }
  });
}
```

这里选择了「失败不中断、收集每个状态」的健壮版本；若要求任一失败整体 reject，把 catch 改为直接 `rejected = true; reject(reason)` 即可。

### 考察点

- 为什么传任务工厂而不是 Promise 实例（惰性执行）
- 「完成即补位」与「每批等最慢者」两种调度的吞吐差异
- 变体追问：动态追加任务的队列版、限制并发 + 失败重试的组合、用 async-pool 思想的 for await 写法
- 应用场景：批量图片上传、接口分页抓取、大文件分片上传控制器
