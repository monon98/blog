# 手写 Vue 的 nextTick

> 难度：中等 | 标签：Vue、微任务、异步批处理

## 题目描述

实现 `nextTick(cb)`，模拟 Vue 的异步更新队列语义：

- cb 不立即执行，推迟到 DOM 更新之后调用
- 同一轮事件循环内多次调用 nextTick，回调只按序批量执行一次刷新
- 优先使用 Promise.then（微任务），不支持的环境降级到 MutationObserver / setImmediate / setTimeout
- 支持返回 Promise 用法（不传回调时）

本题是 Vue2/Vue3 源码面试必问的高频考点。

**示例：**

```javascript
state.count++;
console.log(dom.textContent); // 旧值
nextTick(() => {
  console.log(dom.textContent); // 新值，DOM 已更新
});
```

## 题解

::: details 点击查看题解

### 思路

「回调队列 + 单次冲刷」模型：

1. 回调全部 push 进 callbacks 数组，不立即执行
2. 首个入队的调用触发一次 flushCallbacks——它把队列复制后清空再依次执行。用 pending 标记防止同一轮重复安排 flush
3. flush 本身通过 Promise.resolve().then 安排为微任务，天然晚于所有同步代码与数据变更，早于渲染
4. Vue2 中 callbacks 里第一个固定是 flushSchedulerQueue（真正跑 watcher 更新），用户回调排在其后——所以用户在 nextTick 里能读到新 DOM

### 代码实现

```javascript
const callbacks = [];
let pending = false;

function flushCallbacks() {
  pending = false;
  const copies = callbacks.slice();
  callbacks.length = 0;
  for (const cb of copies) {
    cb();
  }
}

function nextTick(cb) {
  const p = new Promise((resolve) => {
    callbacks.push(() => resolve());
    if (cb) {
      callbacks.push(cb);
    }
  });

  if (!pending) {
    pending = true;
    Promise.resolve().then(flushCallbacks);
  }

  return cb ? undefined : p;
}
```

降级策略（旧环境）：

```javascript
const timerFunc =
  typeof Promise !== "undefined"
    ? (fn) => Promise.resolve().then(fn)
    : typeof MutationObserver !== "undefined"
    ? (fn) => {
        const observer = new MutationObserver(fn);
        const textNode = document.createTextNode("0");
        observer.observe(textNode, { characterData: true });
        return () => (textNode.data = String(Math.random()));
      }
    : (fn) => setTimeout(fn, 0);
```

### 考察点

- 微任务时序：同步代码 → 微任务（nextTick/更新）→ 渲染 → 宏任务
- 为什么用复制后清空：执行回调过程中可能又有新的 nextTick 入队，避免死循环
- Vue3 中 nextTick 基于 currentFlushPromise 实现，本质仍是同一模型
- 追问：为什么 $nextTick 里能拿到更新后的 DOM、事件循环中渲染时机在哪一步
