# 第一个错误的版本

> 难度：简单 | 标签：二分查找、交互 | [LeetCode 原题](https://leetcode.cn/problems/first-bad-version/description/)

## 题目描述

你是产品经理，目前正在带领一个团队开发新的产品。不幸的是，你的产品的最新版本没有通过质量检测。由于每个版本都是基于之前的版本开发的，所以错误的版本之后的所有版本都是错的。假设你有 `n` 个版本 `[1, 2, ..., n]`，你想找出导致之后所有版本出错的第一个错误的版本。你可以通过调用 `bool isBadVersion(version)` 接口来判断版本号 version 是否在单元测试中出错。实现一个函数来查找第一个错误的版本。你应该尽量减少对调用 API 的次数。

**示例 1：**

```
输入：n = 5, bad = 4
输出：4
解释：isBadVersion(3) → false；isBadVersion(4) → true；isBadVersion(5) → true，所以 4 是第一个错误版本。
```

**示例 2：**

```
输入：n = 1, bad = 1
输出：1
```

**提示：**

- `1 <= bad <= n <= 2^31 - 1`

## 题解

::: details 点击查看题解

### 思路

典型的「找左边界」二分：区间收缩时若 mid 是坏版本，答案可能是它本身，所以 `r = mid`（不排除）；若是好版本则 `l = mid + 1`。循环条件用 `l < r`，退出时 l 与 r 重合即为第一个坏版本。

注意 mid 要写成 `Math.floor((l + r) / 2)` 且不会越界（JavaScript 数字安全），本题也常被用来考察「最小化 API 调用次数」的意识——每次判断都要让搜索空间减半。

### 代码实现

```javascript
var solution = function(isBadVersion) {
  return function(n) {
    let l = 1;
    let r = n;
    while (l < r) {
      const mid = Math.floor((l + r) / 2);
      if (isBadVersion(mid)) {
        r = mid;
      } else {
        l = mid + 1;
      }
    }
    return l;
  };
};
```

### 复杂度分析

- 时间复杂度：O(log n)，API 调用次数为 O(log n)。
- 空间复杂度：O(1)。
