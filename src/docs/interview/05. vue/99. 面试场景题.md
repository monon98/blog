# 面试场景题

## 1. Vue 2 和 Vue 3 的区别

::: details
**问题**：Vue 3 相比 Vue 2 有哪些重要变化？

### 响应式系统

- Vue 2：Object.defineProperty
- Vue 3：Proxy

### API 风格

- Vue 2：Options API
- Vue 3：Composition API（可选）

### 性能优化

- 编译优化：静态提升、PatchFlag
- 体积减小：Tree-shaking 支持
- 渲染效率：更快的 diff 算法

### 新特性

- Teleport、Suspense、Fragment
- script setup 语法
- 更好的 TypeScript 支持

:::

## 2. Composition API 最佳实践

::: details
**问题**：如何组织 Composition API 代码？

### 代码组织

- 相关逻辑放在一起
- 使用 composable 函数封装共享逻辑
- 按功能而非类型组织

### 命名规范

- composable 函数以 use 开头
- 响应式变量使用 ref/reactive
- 计算属性使用 computed

### 常见模式

- useFetch：数据获取
- useLocalStorage：本地存储
- useDebounce：防抖
- useMediaQuery：响应式查询

:::

## 4. Pinia 状态管理

::: details
**问题**：Pinia 相比 Vuex 有哪些优势？

### 优势

- 更简单的 API
- 完整的 TypeScript 支持
- 模块化设计
- 支持 Composition API

### 使用方式

- defineStore 定义 store
- state、getters、actions
- 支持插件扩展

### 与 Vuex 对比

| 特性 | Vuex | Pinia |
|------|------|-------|
| API | 复杂 | 简单 |
| TypeScript | 一般 | 优秀 |
| 模块化 | 需要嵌套 | 扁平化 |
| DevTools | 支持 | 支持 |

:::

## 5. Vue 性能优化

::: details
**问题**：如何优化 Vue 应用的性能？

### 编译时优化

- 静态提升
- PatchFlag 标记动态节点
- 事件缓存

### 运行时优化

- 合理使用 v-show 和 v-if
- 使用 key 提高 diff 效率
- 避免在模板中使用复杂表达式

### 组件优化

- 使用 v-once 缓存静态内容
- 使用 computed 缓存计算结果
- 使用 shallowRef/shallowReactive

### 打包优化

- 路由懒加载
- 组件异步加载
- 第三方库按需引入

:::

## 6. Vue 3 新特性应用

::: details
**问题**：Vue 3 的新特性如何在实际项目中应用？

### Teleport

- 将组件渲染到 DOM 任意位置
- 常用于弹窗、通知
- 保持响应式和事件传递

### Suspense

- 处理异步组件
- 显示加载状态
- 配合 async setup 使用

### Fragment

- 组件可以有多个根节点
- 减少不必要的包裹元素
- 提高渲染效率

### script setup

- 更简洁的语法
- 自动导入组件
- 更好的 TypeScript 支持

:::

## 8. Vue 3 与 TypeScript

::: details
**问题**：如何在 Vue 3 中使用 TypeScript？

### 基本配置

- 使用 defineComponent
- 使用 ref/reactive 指定类型
- 使用 computed 指定返回类型

### Props 类型

- 使用 PropType 指定复杂类型
- 使用 withDefaults 设置默认值
- 使用类型声明定义接口

### 组件类型

- 使用泛型组件
- 使用 InstanceType 获取组件类型
- 使用 ExtractPropTypes 提取 Props 类型

## 10. Vue 项目架构

::: details
**问题**：如何设计一个可维护的 Vue 项目架构？

### 目录结构

- components：通用组件
- views：页面组件
- composables：组合式函数
- stores：状态管理
- services：API 服务
- utils：工具函数

### 设计原则

- 关注点分离
- 模块化设计
- 依赖注入
- 错误处理

### 状态管理

- 局部状态：ref/reactive
- 共享状态：composable
- 全局状态：Pinia
- 服务端状态：useAsyncData

:::
