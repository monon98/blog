# Vue 3.4 - 3.6 新特性

## 1. Vue 3.4 新特性

::: details
Vue 3.4 "Slam Dunk" 于 2023 年 12 月发布，包含模板解析器重写、响应式系统优化、`defineModel` 稳定化等重要更新。

### 1. 模板解析器重写（2x 性能提升）

Vue 3.4 完全重写了模板解析器，从递归下降解析器改为基于状态机的分词器：

- **性能提升**：解析速度提升 2 倍
- **SFC 编译优化**：生成 source map 时编译性能提升约 44%
- **100% 向后兼容**

### 2. 响应式系统优化

**computed 优化**：
```javascript
// 3.4 之前：computed 结果不变时 watchEffect 仍会触发
const double = computed(() => count.value * 2);
watchEffect(() => {
  console.log(double.value); // count 变化时，即使 double 结果不变也会触发
});

// 3.4 之后：只有 computed 结果真正变化时才触发
watchEffect(() => {
  console.log(double.value); // 只有 double 结果变化时才触发
});
```

**其他优化**：
- 多个 computed 依赖变化时，同步 effect 只触发一次
- 数组 `shift`、`unshift`、`splice` 方法只触发一次同步 effect

### 3. defineModel 稳定化

`defineModel` 从实验性特性升级为稳定特性，简化了 `v-model` 组件的实现：

```html
<!-- 子组件 -->
<script setup>
const model = defineModel();
// 或带修饰符
const [model, modifiers] = defineModel('value', {
  get: (v) => v.trim(),
  set: (v) => v.trim()
});
</script>

<template>
  <input v-model="model">
</template>
```

### 4. v-bind 同名简写

支持 `v-bind` 同名简写，当属性名与变量名相同时可以省略值：

```html
<!-- 3.4 之前 -->
<input :id="id" :name="name">

<!-- 3.4 之后 - 同名简写 -->
<input :id :name>
```

### 5. 改进的水合不匹配错误

- 错误信息更清晰（区分服务端渲染 vs 客户端期望）
- 包含具体的 DOM 节点信息，便于定位
- 支持 class、style 等动态属性的水合检查

### 总结

Vue 3.4 主要聚焦于性能优化和开发体验改进，模板解析器重写和响应式系统优化带来了显著的性能提升，`defineModel` 和 `v-bind` 简写则简化了日常开发。

:::

## 2. Vue 3.5 新特性

::: details
Vue 3.5 "Tengen Toppa Gurren Lagann" 于 2024 年 9 月发布，包含响应式系统重大优化、响应式 Props 解构、`useTemplateRef`、`useId` 等新 API。

### 1. 响应式系统重大优化

**内存使用减少 56%**：
- 使用新的依赖追踪算法（基于版本计数和双向链表）
- 解决了 SSR 中 stale computed values 和内存泄漏问题
- 大型深度响应式数组的操作速度提升最多 10 倍

### 2. 响应式 Props 解构（Reactive Props Destructure）

在 `<script setup>` 中解构 `defineProps` 的变量现在是响应式的：

```html
<script setup>
const props = defineProps({
  count: { type: Number, default: 0 },
  title: String
});

// 3.5 之前：解构后丢失响应性
const { count, title } = props;

// 3.5 之后：解构后保持响应性
const { count, title } = defineProps({
  count: { type: Number, default: 0 },
  title: String
});

// 使用原生默认值语法
const { count = 0, title } = defineProps({
  count: Number,
  title: String
});
</script>
```

> 注意：监听解构的 prop 变量需要使用 getter：`watch(() => count, (newVal) => {})`

### 3. useTemplateRef()

新的模板引用获取方式，支持动态 ref 绑定：

```html
<script setup>
import { useTemplateRef } from 'vue';

// 3.5 之前
// const inputRef = ref(null);
// <input ref="inputRef">

// 3.5 之后
const inputRef = useTemplateRef('input');
</script>

<template>
  <input ref="input" />
  <button @click="inputRef.focus()">聚焦</button>
</template>
```

### 4. useId()

生成应用内唯一的稳定 ID，适用于表单元素和无障碍属性：

```html
<script setup>
import { useId } from 'vue';

const id = useId(); // 生成唯一 ID，如 "v-0"
</script>

<template>
  <label :for="id">用户名</label>
  <input :id="id" type="text">
</template>
```

- ID 前缀默认为 `v-`，可通过 `app.config.idPrefix` 自定义
- SSR 和客户端渲染保证一致，不会出现水合不匹配

### 5. 懒加载水合策略

`defineAsyncComponent` 新增 `hydrate` 选项，控制组件何时水合：

```javascript
import { defineAsyncComponent, hydrateOnIdle, hydrateOnVisible, hydrateOnInteraction } from 'vue';

const HeavyComponent = defineAsyncComponent({
  loader: () => import('./HeavyComponent.vue'),
  hydrate: hydrateOnVisible() // 进入视口时水合
});

// 其他策略
hydrateOnIdle(1000);      // 浏览器空闲时水合
hydrateOnInteraction('click'); // 用户交互时水合
hydrateOnMediaQuery('(min-width: 600px)'); // 媒体查询匹配时水合
```

### 6. onWatcherCleanup()

在 watcher 中注册清理回调：

```javascript
import { watch, onWatcherCleanup } from 'vue';

watch(count, (newVal) => {
  const controller = new AbortController();
  
  fetch('/api/data', { signal: controller.signal });
  
  // watcher 清理时会调用
  onWatcherCleanup(() => {
    controller.abort();
  });
});
```

### 7. Deferred Teleport

`Teleport` 新增 `defer` 属性，目标元素可以在组件挂载后才存在：

```html
<!-- 3.5 之前：目标元素必须已存在 -->
<!-- 3.5 之后：目标元素可以后续出现 -->
<Teleport defer to="#modal-container">
  <div class="modal">内容</div>
</Teleport>
```

### 8. Watcher 增强

**深度监听指定深度**：
```javascript
watch(obj, (newVal) => {
  // 只监听前 2 层
}, { deep: 2 });
```

**暂停/恢复 watcher**：
```javascript
const stop = watch(count, (newVal) => { ... });

// 暂停
stop.pause();

// 恢复
stop.resume();
```

### 9. 其他改进

- `app.onUnmount()`：注册应用卸载时的回调
- `data-allow-mismatch`：允许特定类型的水合不匹配
- 自定义元素改进：`useHost()`、`useShadowRoot()`、`shadowRoot: false`

### 总结

Vue 3.5 是一个重要的性能和功能更新，响应式 Props 解构、`useTemplateRef`、`useId` 等新 API 大幅提升了开发体验，响应式系统的内存优化和懒加载水合策略则显著改善了应用性能。

:::

## 3. Vue 3.6 新特性

::: details
Vue 3.6 目前处于 Beta 阶段，主要聚焦于 Vapor Mode 和响应式系统性能的进一步提升。

### 1. Vapor Mode（无虚拟 DOM 模式）

Vapor Mode 是 Vue 3.6 最重要的新特性，它是一种新的编译模式，**不使用虚拟 DOM**，直接生成接近手写优化代码的输出。

**核心特点**：
- **无虚拟 DOM 开销**：直接操作真实 DOM，减少内存占用
- **性能媲美 Solid/Svelte 5**：在第三方基准测试中表现优异
- **100% 可选**：通过 `<script setup vapor>` 启用
- **API 兼容**：支持 Vue 现有 API 的子集，行为基本一致

**使用方式**：

```html
<!-- 启用 Vapor Mode -->
<script setup vapor>
import { ref } from 'vue';

const count = ref(0);
</script>

<template>
  <button @click="count++">{{ count }}</button>
</template>
```

**两种使用场景**：

```javascript
// 1. 创建纯 Vapor 应用（更小的包体积）
import { createVaporApp } from 'vue';
import App from './App.vue';

createVaporApp(App).mount('#app');

// 2. 在 VDOM 应用中使用 Vapor 组件
import { createApp, vaporInteropPlugin } from 'vue';
import App from './App.vue';

createApp(App).use(vaporInteropPlugin).mount('#app');
```

**Vapor Mode 限制**：
- 不支持 Options API
- 不支持 `app.config.globalProperties`
- `getCurrentInstance()` 返回 `null`
- 自定义指令接口不同

**自定义指令在 Vapor Mode 中**：

```typescript
// Vapor 模式下的指令接口
const MyDirective = (
  node: Element | VaporComponentInstance,
  value?: () => any,  // 响应式 getter
  argument?: string,
  modifiers?: DirectiveModifiers,
) => (() => void) | void;  // 可返回清理函数

// 使用示例
const vHighlight = (el, source) => {
  watchEffect(() => {
    el.style.backgroundColor = source();
  });
  return () => console.log('cleanup');
};
```

### 2. 响应式系统重构（基于 alien-signals）

Vue 3.6 基于 [alien-signals](https://github.com/stackblitz/alien-signals) 重构了响应式系统：

- **显著的性能提升**：进一步优化响应式系统的执行效率
- **内存使用优化**：减少响应式数据的内存占用
- **更好的可预测性**：computed 值永远不会是 stale 的

### 3. Rolldown 集成

Vue 3.6 将集成 Rolldown（基于 Rust 的打包工具）：

- **更快的构建速度**：替代 Rollup 和 esbuild
- **更好的 tree-shaking**：更精确的死代码消除
- **Environment API**：标准化客户端/服务端/边缘运行环境的代码执行

### 4. Vapor Mode 功能兼容性

| 特性 | VDOM 模式 | Vapor 模式 |
|------|-----------|------------|
| Composition API | 支持 | 支持 |
| Options API | 支持 | 不支持 |
| 自定义指令 | 标准接口 | 简化接口 |
| Suspense | 支持 | 不支持（可在 VDOM 中嵌套） |
| Teleport | 支持 | 支持 |
| Transition | 支持 | 支持 |

### 5. 性能对比

根据 js-framework-benchmark 测试：

| 框架 | 操作 | 耗时 |
|------|------|------|
| Solid | 创建 1000 行 | ~15ms |
| Svelte 5 | 创建 1000 行 | ~16ms |
| Vue 3.6 Vapor | 创建 1000 行 | ~17ms |
| Vue 3.5 VDOM | 创建 1000 行 | ~35ms |

### 总结

Vue 3.6 的 Vapor Mode 是一个革命性的特性，它在保持 Vue API 兼容性的同时，提供了接近原生 JavaScript 的性能表现。结合 alien-signals 响应式系统重构和 Rolldown 打包工具，Vue 3.6 将在性能和开发体验方面带来质的飞跃。

> 注意：Vapor Mode 目前仍处于 Beta 阶段，建议在新项目的小范围内尝试使用。

## 4. Vue 3.4-3.6 版本对比

::: details
以下是 Vue 3.4、3.5、3.6 三个版本的主要特性对比：

### 版本发布时间

| 版本 | 代号 | 发布时间 | 状态 |
|------|------|----------|------|
| Vue 3.4 | Slam Dunk | 2023 年 12 月 | 稳定 |
| Vue 3.5 | Tengen Toppa Gurren Lagann | 2024 年 9 月 | 稳定 |
| Vue 3.6 | - | Beta 阶段 | 预发布 |

### 核心特性对比

| 特性 | 3.4 | 3.5 | 3.6 |
|------|-----|-----|-----|
| 模板解析器 | 2x 性能提升 | - | - |
| 响应式优化 | computed 优化 | 内存减少 56% | alien-signals 重构 |
| defineModel | 稳定 | - | - |
| v-bind 同名简写 | 支持 | - | - |
| Props 解构 | 实验性 | 稳定 | - |
| useTemplateRef | - | 新增 | - |
| useId | - | 新增 | - |
| 懒加载水合 | - | 新增 | - |
| Deferred Teleport | - | 新增 | - |
| onWatcherCleanup | - | 新增 | - |
| Vapor Mode | - | - | 新增 |
| Rolldown | - | - | 集成 |

### 迁移建议

**从 3.3 升级到 3.4**：
- 移除 `propsDestructure` 编译选项（如已启用）
- 使用 `v-bind` 同名简写简化模板
- 验证 hydration mismatch 错误信息变化

**从 3.4 升级到 3.5**：
- 使用 `useTemplateRef` 替代传统 ref
- 使用 `useId` 生成唯一 ID
- 尝试响应式 Props 解构
- 使用 `onWatcherCleanup` 清理 watcher 副作用

**从 3.5 升级到 3.6**：
- 在性能敏感的组件中尝试 Vapor Mode
- 关注 alien-signals 响应式系统的变化
- 测试 Rolldown 打包兼容性

### 总结

Vue 3.4-3.6 的演进路线清晰：3.4 聚焦性能优化和 API 稳定化，3.5 引入多个实用新 API，3.6 则通过 Vapor Mode 实现性能质的飞跃。建议开发者逐步升级，充分利用每个版本的新特性。

:::
