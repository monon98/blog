# 移动端 H5

## 1. viewport 与适配体系

::: details
**问题**：移动端 H5 的 viewport 配置与适配方案？

### viewport meta

```
<meta name="viewport"
      content="width=device-width, initial-scale=1.0,
               maximum-scale=1.0, user-scalable=no">
```

- 不设置时手机默认按 980px 布局再缩放，导致字太小
- user-scalable=no 禁用缩放（无障碍角度不建议完全禁用）

### 适配方案回顾

- rem：动态根字体 + postcss-pxtorem
- vw：直接视口单位 + postcss-px-to-viewport
- 两者细节见 [CSS - 面试场景题](../02.%20css/99.%20面试场景题)

### DPR 与图片

- devicePixelRatio：物理像素 / CSS 像素
- 高倍屏提供 @2x/@3x 图或 SVG，避免模糊

:::

## 2. 经典兼容问题

::: details
**问题**：移动端有哪些经典兼容问题及解法？

### 1px 边框问题

- 原因：DPR > 1 时，CSS 1px 渲染为多物理像素，显得粗
- 方案一：伪元素 + transform: scale(0.5) 缩小
- 方案二：border-image 或背景渐变模拟
- 方案三：viewport 缩放方案（rem 页面整体 scale）
- 现代浏览器可尝试 0.5px（部分机型支持）

### 点击 300ms 延迟

- 历史：浏览器等待判断是否双击缩放
- 现在：正确设置 viewport 后现代浏览器已取消延迟
- fastclick 库已基本退役

### 触摸穿透

- 蒙层关闭后 click 事件作用到底层元素（如关闭弹窗的同时误触了下方链接）
- 解法：蒙层上的按钮监听 touchend 并调用 preventDefault，阻止浏览器合成 click；或延迟 300ms 再移除蒙层

### iOS 橡皮筋滚动

- body 固定 + 内部 overflow scroll
- 或 overscroll-behavior: contain

:::

## 3. 触摸事件体系

::: details
**问题**：移动端触摸事件有哪些？passive 是什么？

### 三大触摸事件

| 事件 | 触发时机 |
|------|----------|
| touchstart | 手指接触屏幕 |
| touchmove | 手指移动（高频触发） |
| touchend | 手指离开 |

- event.touches / changedTouches：触点列表，含 clientX/Y、pageX/Y

### passive 优化

```
el.addEventListener('touchmove', fn, { passive: true })
```

- 告知浏览器不会调用 preventDefault()
- 允许立即滚动，不再等待 JS 执行，消除滑动卡顿
- Chrome 对 document 级 touchstart/touchmove 默认 passive

### 手势封装

- 下拉刷新/轮播手势基于 touch 事件计算位移与方向
- 生产环境常用 hammer.js / 各 UI 库手势组件

:::

## 4. 安全区与软键盘

::: details
**问题**：全面屏安全区和软键盘问题如何处理？

### 刘海屏安全区

```
viewport-fit=cover 加到 viewport meta 中

padding-bottom: env(safe-area-inset-bottom);
/* 兼容写法 */
padding-bottom: constant(safe-area-inset-bottom);
```

### 软键盘问题

- **iOS**：键盘顶起页面，收起后页面可能停在上方 → 失焦时 window.scrollTo(0, 0)
- **Android**：键盘压缩视口（resize 模式）→ 监听窗口高度变化调整布局
- **输入框被遮挡**：scrollIntoView({ block: 'center' }) 定位到可视区
- **fixed 元素在键盘弹起时错位**：改用绝对定位或键盘弹出时隐藏 fixed 栏

:::

## 5. Hybrid 混合开发与 JSBridge

::: details
**问题**：H5 与原生 App 如何通信？

### 通信原理（JSBridge）

1. **H5 → Native**
   - 拦截 URL Scheme：iframe.src = 'app://action'，原生拦截请求解析执行
   - 注入 API：原生向 window 注入对象（如 window.AppBridge），H5 直接调用
2. **Native → H5**
   - iOS WKWebView：evaluateJavaScript；Android：evaluateJavascript，执行 JS 回调

### 现代方案

- iOS：WKScriptMessageHandler（window.webkit.messageHandlers.xxx.postMessage）
- Android：@JavascriptInterface 注解
- 通用封装：回调 ID 注册表 + Promise 化调用

### 选型对比

| 方案 | 特点 |
|------|------|
| 纯 H5 | 一套代码多端跑，能力受限 |
| Hybrid | H5 + Bridge 调原生，热更新灵活 |
| React Native/Flutter | 接近原生体验，独立技术栈 |

:::

## 6. 微信 H5 开发要点

::: details
**问题**：微信内 H5 开发有哪些特殊处理？

### 微信 JSSDK 自定义分享

1. 公众号后台配置 JS 安全域名
2. 后端生成签名（access_token → jsapi_ticket → 签名算法）
3. wx.config 注入权限验证
4. wx.updateAppMessageShareData / updateTimelineShareData 设置卡片

### 环境判断

- UA 含 MicroMessenger 判断微信内
- wx.miniProgram 用于公众号网页跳小程序

### 常见坑

- 分享签名 URL 必须是当前页（iOS 首次进入的 URL，SPA 需入口时缓存）
- 音视频播放需 WeixinJSBridgeReady 后触发
- 支付目录、授权域名需分别配置

:::
