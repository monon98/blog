# 并发控制类 Scheduler

> 难度：中等 | 标签：Promise、异步调度、并发、类设计

## 题目描述

用**类**封装一个并发限制调度器 `Scheduler`，与函数式写法不同，要求支持动态添加任务：

- 构造时传入最大并发数 `limit`
- `add(taskFactory)` 接收返回 Promise 的任务工厂，立即返回一个 Promise，在任务完成时以该任务的结果 settle
- 未超过并发数上限的任务立即执行；超出的进入等待队列，任一任务完成后自动补位
- 支持任意时刻持续调用 add，不要求一次性传入全部任务

**示例：**

```javascript
const timeout = (time) => new Promise((resolve) => setTimeout(resolve, time));

const scheduler = new Scheduler(2);

const addTask = (time, order) => {
  scheduler.add(() => timeout(time)).then(() => console.log(order));
};

addTask(1000, "1");
addTask(500, "2");
addTask(300, "3");
addTask(400, "4");
// 输出顺序: 2, 3, 1, 4
```

### 思路

与函数版的「游标补位」不同，类封装天然适合「队列 + 计数器」模型，因为实例字段就是天然的共享状态：

1. **三个实例字段**：`limit` 上限、`running` 当前执行数、`queue` 等待队列
2. **add 即入队**：把「真正执行任务」的启动器包成 task；有空位就立刻执行并计数加一，否则推入 queue。外层 new Promise 的 resolve/reject 交给 task 内部透传，实现 add 返回值与任务结果绑定
3. **完成即补位**：finally 中 running 减一后调用 `_next`，从队首取一个启动器执行

关键细节：`Promise.resolve().then(taskFactory)` 先微任务再调用工厂，避免工厂同步抛错炸掉调度循环；`.then(resolve, reject)` 把成功失败都转交给外层 Promise。

### 代码实现

```javascript
class Scheduler {
  constructor(limit) {
    if (!Number.isInteger(limit) || limit <= 0) {
      throw new RangeError("limit must be a positive integer");
    }
    this.limit = limit;
    this.running = 0;
    this.queue = [];
  }

  add(taskFactory) {
    return new Promise((resolve, reject) => {
      const start = () => {
        this.running++;
        Promise.resolve()
          .then(taskFactory)
          .then(resolve, reject)
          .finally(() => {
            this.running--;
            this._next();
          });
      };

      if (this.running < this.limit) {
        start();
      } else {
        this.queue.push(start);
      }
    });
  }

  _next() {
    if (this.queue.length && this.running < this.limit) {
      const start = this.queue.shift();
      start();
    }
  }
}
```

扩展方向：暴露 `pending()` 查询排队数、`clear()` 清空队列、支持优先级插入（unshift）或带标签的分组限额。

### 考察点

- 类字段作为调度状态的天然载体，对比函数闭包版（见 [并发控制 limitConcurrency](./29.%20并发控制%20limitConcurrency)）的适用场景：动态添加 vs 一次性批量
- add 返回的 Promise 与具体任务结果的绑定方式——resolve/reject 作为参数传进启动器
- finally 保证无论成败都释放槽位；微任务包装防御同步异常
- 应用场景：上传组件的动态加文件、爬虫持续产出 URL、消息队列消费限流
