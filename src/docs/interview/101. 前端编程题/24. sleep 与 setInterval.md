# sleep 与 setTimeout 实现 setInterval

> 难度：简单 | 标签：Promise、定时器

## 题目描述

两个定时器相关的小题：

1. 实现 `sleep(ms)`，在 async 函数中暂停指定毫秒后继续
2. 用 `setTimeout` 递归模拟 `setInterval`，返回一个停止函数；说明这种写法与原生 setInterval 的执行时序差异

**示例：**

```javascript
async function main() {
  console.log("start");
  await sleep(1000);
  console.log("1s later");
}
```

## 题解

::: details 点击查看题解

### 思路

1. **sleep**：一行 Promise 包装——`new Promise((resolve) => setTimeout(resolve, ms))`。这是把回调式 API Promise 化的最小范例
2. **setTimeout 版 interval**：每次回调执行完才排下一次。好处是「执行耗时不会导致堆积」，坏处是「两次执行的间隔 = interval + 执行时长」产生漂移；原生 setInterval 则固定间隔但可能堆叠回调（浏览器对同一回调有最小间隔保护）

### 代码实现

```javascript
const sleep = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

function mySetInterval(fn, interval) {
  let timer = null;
  let stopped = false;

  function loop() {
    timer = setTimeout(() => {
      if (stopped) return;
      fn();
      loop();
    }, interval);
  }

  loop();

  return function stop() {
    stopped = true;
    clearTimeout(timer);
  };
}
```

### 考察点

- Promise 化回调 API 是 async/await 生态的基石技巧
- setInterval 回调执行时间超过 interval 时会发生「重叠排队」，setTimeout 链天然规避
- 精确计时追问：漂移补偿方案（每轮用实际执行时刻重新计算剩余延迟）
- 组件卸载必须调用 stop/clearTimeout 清理，否则内存泄漏与僵尸回调
