# 手写 instanceof

> 难度：简单 | 标签：原型链、运算符

## 题目描述

实现一个 `myInstanceof(left, right)` 函数，模拟 `instanceof` 运算符的行为：

- 沿着 `left` 的原型链（`__proto__`）逐级向上查找
- 若某一级原型恰好等于 `right.prototype`，返回 `true`
- 走到原型链尽头（`null`）仍未找到，返回 `false`

**示例：**

```javascript
myInstanceof([], Array); // true
myInstanceof([], Object); // true（Array.prototype 的原型是 Object.prototype）
myInstanceof("abc", String); // false（原始值没有原型链）
```

## 题解

::: details 点击查看题解

### 思路

`instanceof` 的本质就是**在原型链上查找构造函数的 `prototype`**。用 `Object.getPrototypeOf` 循环向上爬取，与 `right.prototype` 做全等比较。

边界处理：原始值直接返回 false（它们无法取到原型）；`left` 为 `null` / `undefined` 同样短路；右操作数必须是函数且拥有 `prototype` 属性。

### 代码实现

```javascript
function myInstanceof(left, right) {
  if (typeof right !== "function" || !right.prototype) {
    throw new TypeError("Right-hand side must have a prototype property");
  }
  if (left === null || (typeof left !== "object" && typeof left !== "function")) {
    return false;
  }
  let proto = Object.getPrototypeOf(left);
  while (proto) {
    if (proto === right.prototype) return true;
    proto = Object.getPrototypeOf(proto);
  }
  return false;
}
```

### 考察点

- 原型链：`obj.__proto__ === Ctor.prototype` 是 `instanceof` 的判定依据
- 为什么 `[] instanceof Object` 为 true——原型链的传递性
- `Object.getPrototypeOf` 与 `__proto__` 的关系（前者是标准 API）
- 特殊值：`Symbol.hasInstance` 可自定义行为；原始值包装对象 vs 字面量的区别
