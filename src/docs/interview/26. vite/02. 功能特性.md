# 功能特性

## 1. CSS 处理

::: details
**问题**：Vite 如何处理各类 CSS 方案？

### 内置支持

- 预处理器：安装 sass/less/stylus 即可使用，无需配置 Loader
- 后处理：postcss.config.js 自动生效
- CSS Modules：.module.css 后缀自动启用

### CSS Modules 示例

```
// Button.module.css
.btn { color: red; }

// Button.jsx
import styles from './Button.module.css';
<button className={styles.btn} />
```

### 配置项

```
css: {
  modules: {
    localsConvention: 'camelCaseOnly'
  },
  preprocessorOptions: {
    scss: {
      additionalData: `@use "@/styles/var.scss" as *;`
    }
  },
  devSourcemap: true
}
```

:::

## 2. TypeScript 支持

::: details
**问题**：Vite 如何处理 TypeScript？有什么限制？

### 支持方式

- 使用 esbuild 转译 TS → JS
- 只做转译，不做类型检查（速度极快的原因之一）

### 类型检查方案

- IDE 实时检查（日常开发）
- 单独脚本：tsc --noEmit && vite build
- vite-plugin-checker 在 Dev Server 中集成检查

### 注意事项

- esbuild 不支持 const enum、部分旧版装饰器语法
- 路径别名需要同时配置 tsconfig 和 vite.config

```
resolve: {
  alias: {
    '@': '/src'
  }
}
```

:::

## 3. 静态资源处理

::: details
**问题**：Vite 如何处理静态资源？

### 导入资源

- import logo from './logo.png' 返回 URL
- 显式控制：?url（路径）、?raw（源码字符串）、?inline（强制 base64）

### public 目录

- 存放无需构建处理的静态文件
- 以根路径绝对引用（如 src="/icon.png"）
- 不参与 hash 命名和压缩

### 构建行为

- 小于 assetsInlineLimit（默认 4KB）转为 base64 内联
- 大文件输出到 assets 目录并带 contenthash

:::

## 4. 动态导入与代码分割

::: details
**问题**：Vite 中如何实现代码分割？

### 自动分割

- 动态导入 import() 的模块自动生成独立 chunk
- 路由懒加载是最常见的应用场景

```
const routes = [
  { path: '/about', component: () => import('./views/About.vue') }
]
```

### Rollup 打包产物特性

- Vite 会为动态导入自动注入依赖预加载逻辑（避免瀑布请求）
- 入口 chunk 与异步 chunk 分离

### 手动分包

```
build: {
  rollupOptions: {
    output: {
      manualChunks: {
        vendor: ['vue', 'vue-router'],
        echarts: ['echarts']
      }
    }
  }
}
```

:::

## 5. 服务端渲染支持

::: details
**问题**：Vite 如何支持 SSR？

### 开发阶段

- Dev Server 直接运行 ESM 源码
- 通过 ssrLoadModule 加载服务端入口
- HMR 同样适用于服务端代码

### 生产阶段

- ssrBuild 输出面向 Node.js 的包
- 与客户端构建分离（双构建）

### 上层框架

- Nuxt 3、SvelteKit 等基于 Vite 的 SSR 能力封装
- 一般不直接手写 Vite SSR 配置

:::
