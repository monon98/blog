# 基础概念

## 1. Vite 是什么

::: details
Vite 是一个由两部分组成的构建工具：

- 开发服务器：基于原生 ES Module 提供丰富的内置功能（HMR 极快）
- 构建命令：使用 Rollup 打包代码，输出高度优化的静态资源

### 前沿动态：Rolldown

- Vite 6+ 提供实验性的 rolldown-vite，用 Rust 重写的 Rollup 兼容打包器
- 目标：统一开发/生产构建引擎（替代 esbuild + Rollup 双工具链）
- 面试提及可体现对生态的持续关注

### 核心优势

- 冷启动快：无需打包，按需编译
- HMR 快：不受项目规模影响
- 开箱即用：TypeScript、CSS、JSX 内置支持

### 与 Webpack 对比

| 阶段 | Webpack | Vite |
|------|---------|------|
| 启动 | 全量打包后启动 | 直接启动，请求时编译 |
| HMR | 涉及入口的模块链重编 | 精准到单模块失效 |
| 生产构建 | 自身引擎 | Rollup |

:::## 2. 为什么 Vite 启动快

::: details
**问题**：Vite Dev Server 为什么能做到秒级启动？

### Webpack 启动慢的原因

- 启动前需要从 entry 递归分析所有依赖并打包成 bundle
- 项目越大，冷启动时间越长

### Vite 的解决思路

1. **按需编译**：浏览器通过 ESM 发起请求，Dev Server 只编译当前请求的模块
2. **依赖预构建**：node_modules 中的第三方依赖用 esbuild 预先处理
3. **esbuild 加速**：Go 编写，比 JS 打包器快 10-100 倍

### 预构建的作用

- CommonJS/UMD 转换为 ESM
- 合并被多次引用的小模块（如 lodash-es 的几百个函数文件），避免瀑布式请求
- 结果缓存在 node_modules/.vite

:::

## 3. 依赖预构建详解

::: details
**问题**：什么情况下需要手动配置预构建？

### 自动触发预构建的场景

- 首次启动
- lock 文件变化
- 配置文件变化
- 手动删除 node_modules/.vite

### 需要手动配置的情况

```
optimizeDeps: {
  // 动态导入的依赖 Vite 发现不了，强制预构建
  include: ['esm-dep', 'lodash-es'],
  // CJS 格式的插件排除
  exclude: ['some-cjs-plugin']
}
```

### 典型问题排查

- 页面报错 "new dependencies optimized" 后自动刷新 → 把该依赖加入 include
- 依赖内部使用了 CJS 特性导致转换失败 → 用 optimizeDeps.esbuildOptions 定制

:::

## 4. HMR 原理

::: details
**问题**：Vite 的 HMR 是如何实现的？

### 完整流程

1. 服务端监听文件变化（chokidar）
2. 变更文件在模块图中找到对应模块，使其失效
3. 通过 WebSocket 推送更新消息给客户端
4. 客户端根据消息类型执行：
   - js 更新：fetch 新模块并替换，触发 import.meta.hot 回调
   - css 更新：直接替换 style 标签内容
   - vue/react 组件：框架插件处理，保留组件状态

### 与 Webpack HMR 区别

| 对比项 | Webpack | Vite |
|--------|---------|------|
| 失效范围 | 以修改文件为起点向上传播到 entry | 精确到单个模块 |
| 速度 | 受模块链影响 | 始终恒定快速 |

:::

## 5. 环境变量与模式

::: details
**问题**：Vite 如何管理环境变量？

### 使用方式

- 代码中访问：import.meta.env.VITE_XXX
- 必须以 VITE_ 为前缀才会暴露给客户端
- TypeScript 支持：src/vite-env.d.ts 中声明 ImportMetaEnv

### .env 文件加载优先级

1. .env.[mode].local
2. .env.[mode]
3. .env.local
4. .env

### 三种模式

- development：vite / vite dev
- production：vite build
- 自定义模式：vite build --mode staging

### 注意事项

- 敏感信息不要加 VITE_ 前缀，会打进客户端包
- 服务端代码用 process.env（Nitro/Vite SSR 场景）

:::
