# 插件与生态

## 1. 插件机制

::: details
**问题**：Vite 插件和 Rollup 插件是什么关系？

### 兼容性设计

- Vite 扩展了 Rollup 插件接口
- 大部分 Rollup 插件可直接使用（开发阶段部分钩子不生效）
- Vite 特有钩子：config、configureServer、transformIndexHtml、handleHotUpdate

### 常用钩子执行时机

| 钩子 | 时机 | 用途 |
|------|------|------|
| config | 读取配置后 | 修改最终配置 |
| configureServer | Dev Server 创建时 | 添加自定义中间件 |
| transform | 模块请求时 | 转换模块代码 |
| buildStart | 生产构建开始 | 初始化资源 |
| generateBundle | 输出前 | 修改产物 |

### 编写示例

```
function myPlugin() {
  return {
    name: 'my-plugin',
    transform(code, id) {
      if (id.endsWith('.svg')) {
        return `export default ${JSON.stringify(code)}`;
      }
    }
  };
}
```

## 2. 常用官方插件

::: details
**问题**：Vite 有哪些必备的框架插件？

### 框架插件

- @vitejs/plugin-vue：Vue 3 SFC 支持
- @vitejs/plugin-react：React Fast Refresh（Babel 实现）
- @vitejs/plugin-legacy：旧浏览器支持（自动 polyfill + 双构建）

### 功能插件

- vite-plugin-compression2：Gzip/Brotli 预压缩
- unplugin-auto-import：API 自动导入
- unplugin-vue-components：组件自动注册
- vite-plugin-svg-icons：SVG 雪碧图
- vite-plugin-mock-dev-server：Mock 数据

### 使用建议

- 插件数量影响启动速度，按需引入
- 优先选择 unplugin 系列（跨构建工具兼容）

:::

## 3. 与 Webpack 项目迁移

::: details
**问题**：Webpack 项目如何迁移到 Vite？

### 迁移步骤

1. 安装 vite 及对应框架插件
2. 创建 vite.config.ts，迁移以下配置：
   - entry → index.html 中 script 标签
   - alias → resolve.alias
   - DefinePlugin → define
   - CopyWebpackPlugin → publicDir / vite-plugin-static-copy
3. 环境变量：process.env.XXX → import.meta.env.VITE_XXX
4. CommonJS 依赖处理：optimizeDeps.include 强制预构建

### 常见坑

- require() 动态路径不支持，需改为 new URL('./img/' + name + '.png', import.meta.url)
- JSX 文件扩展名要求严格（.jsx/.tsx）
- CSS 中 process.env 引用需要替换

### 渐进式策略

- 先用 Vitest 替代 Jest（测试层）
- 再切换 Dev Server
- 最后替换生产构建

:::

## 4. 构建优化配置

::: details
**问题**：Vite 生产构建有哪些优化手段？

### 分包与缓存

- manualChunks 抽离稳定的第三方库
- 产物默认带 contenthash，配合强缓存

### 目标环境

```
build: {
  target: 'es2020',
  cssTarget: 'chrome80'
}
```

- target 决定 esbuild/Rollup 的转译程度
- 兼容旧浏览器用 @vitejs/plugin-legacy

### 压缩与体积

- minify: 'esbuild'（默认）或 'terser'（更多压缩选项）
- chunkSizeWarningLimit 调整警告阈值
- reportCompressedSize: false 加快构建

### 其他

- sourcemap: 'hidden' 配合监控平台
- assetsInlineLimit 控制内联阈值

:::

## 5. Vitest 测试

::: details
**问题**：为什么推荐 Vitest 替代 Jest？

### 核心优势

- 复用 Vite 配置（alias、插件、env）
- 基于 esbuild 转换，测试运行极快
- 原生 ESM，无需配置 transformIgnorePatterns

### 兼容 Jest API

- describe/it/expect 完全兼容
- 从 jest.fn() 平滑迁移到 vi.fn()

### 特色功能

- 组件内联测试（In-source Testing）
- 浏览器模式（Browser Mode）真实 DOM 测试
- watch 模式下只重跑受影响的测试

:::
