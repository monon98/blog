# 面试场景题

## 1. 首次访问页面加载慢

::: details
**问题**：Vite 项目冷启动很快，但首次打开页面反而慢，为什么？

### 原因

- 按需编译的代价：首屏请求触发大量模块按需编译
- 依赖预构建在首次启动时执行，阻塞请求
- 未预构建的 CJS 依赖导致瀑布式请求（一个 import 触发几百个请求）

### 解决方案

```
optimizeDeps: {
  include: ['lodash-es', 'axios', 'vue-router']
}
```

- 将深层依赖显式加入 include，启动时一次性完成预构建
- 升级 Vite 版本（新版本持续优化了模块加载并行度）
- 减少首屏组件数量，配合路由懒加载

:::

## 2. 生产构建产物与开发不一致

::: details
**问题**：开发环境正常，打包后出现白屏或报错，如何排查？

### 常见原因

| 现象 | 原因 | 对策 |
|------|------|------|
| 白屏 + 资源 404 | base 路径配置错误 | 设置正确的 base |
| require is not defined | 源码中使用了 CJS 语法 | 改为 ESM 或加预构建 |
| 动态导入图片失败 | import(变量路径) 不支持 | 用 new URL() 方案 |
| CSS 变量丢失 | postcss 配置未迁移 | 迁移 postcss.config.js |
| 双份 Vue 实例警告 | monorepo 多版本共存 | 统一版本/resolve.dedupe |

### 排查步骤

1. vite build --sourcemap 后本地 preview 复现
2. 检查 Network 中资源请求路径是否正确
3. 对比 dev 与 build 的模块差异（vite-plugin-inspect）

:::

## 3. 大型项目 Dev Server 内存暴涨

::: details
**问题**：万级模块的项目使用 Vite 后 Node 进程内存溢出，怎么办？

### 定位手段

- NODE_OPTIONS=--max-old-space-size=8192 先扩大内存观察是否泄漏还是不足
- process.report / heapdump 抓取堆快照分析

### 常见原因与对策

- 预构建依赖过多：exclude 掉不需要转换的大依赖
- Source Map 开销大：关闭 css.devSourcemap
- 插件内存泄漏：transform 中缓存了所有模块内容
- Windows 路径监听开销：watch.ignore 忽略无关目录

:::

## 4. 微前端接入 Vite 子应用

::: details
**问题**：主应用是 qiankun，子应用想用 Vite，有什么难点？

### 核心矛盾

- qiankun 依赖 HTML Entry + 运行时 JS 沙箱劫持
- Vite Dev 模式的 ESM import 不经过传统 script 加载流程

### 解决方案

- vite-plugin-qiankun：改写入口注入生命周期
- Dev 模式用全局变量挂载代替 ESM 导出
- 生产模式正常构建后接入（与 Webpack 子应用一致）

### 替代思路

- 主子应用都升级为 Module Federation 体系
- 使用 wujie / micro-app 等对 Vite 支持更好的方案

:::

## 5. 库开发模式

::: details
**问题**：如何用 Vite 构建一个组件库？

### 库模式配置

```
build: {
  lib: {
    entry: 'src/index.ts',
    name: 'MyLib',
    formats: ['es', 'cjs', 'umd'],
    fileName: format => `my-lib.${format}.js`
  },
  rollupOptions: {
    external: ['vue'],
    output: { globals: { vue: 'Vue' } }
  }
}
```

### 要点

- external 排除宿主项目提供的依赖（如 vue）
- 生成 d.ts 类型：tsc --emitDeclarationOnly 或 vite-plugin-dts 与源码同步生成
- 样式分离：CSS 单独输出，支持按需引入
- package.json 配置 exports 字段声明多格式入口

:::

## 6. 低版本浏览器兼容

::: details
**问题**：需要兼容不支持 ESM 的旧浏览器，如何处理？

### @vitejs/plugin-legacy

- 自动生成现代/传统双份产物
- 传统产物包含 SystemJS 格式 + 全量 polyfill
- HTML 注入 nomodule/module 区分脚本和 Safari 10.1 修复

```
legacy: {
  targets: ['defaults', 'not IE 11'],
  additionalLegacyPolyfills: ['regenerator-runtime/runtime']
}
```

### 注意事项

- 双构建会显著增加构建时间，确认真的需要再开启
- 通过 browserslist 收敛目标范围减少 polyfill

:::

## 7. 自定义 Dev Server 行为

::: details
**问题**：如何在 Vite 中实现接口代理与 Mock？

### 代理配置

```
server: {
  proxy: {
    '/api': {
      target: 'http://backend.local',
      changeOrigin: true,
      rewrite: path => path.replace(/^\/api/, '')
    }
  }
}
```

### Mock 方案对比

| 方案 | 特点 |
|------|------|
| vite-plugin-mock-dev-server | 与 proxy 无缝集成 |
| MSW | 浏览器层拦截，可同时用于测试 |
| 自定义中间件 | configureServer 完全控制 |

### 中间件示例

```
configureServer(server) {
  server.middlewares.use('/mock', (req, res) => {
    res.end(JSON.stringify({ ok: true }));
  });
}
```

:::
