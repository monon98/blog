# 渲染原理

## 1. 从 URL 输入到页面渲染全过程

::: details
这是前端面试中最高频的综合题之一，串联了多个知识点。

### 完整流程

1. **URL 解析**：浏览器解析 URL，提取协议、域名、端口、路径
2. **DNS 解析**：将域名解析为 IP 地址
   - 浏览器缓存 → 系统缓存 → 路由器缓存 → ISP DNS 缓存 → 根域名服务器
3. **TCP 三次握手**：建立可靠的 TCP 连接
   - SYN → SYN-ACK → ACK
4. **TLS 握手**（HTTPS）：建立安全连接
   - 证书验证、密钥交换、加密套件协商
5. **HTTP 请求/响应**：发送请求并接收响应
6. **HTML 解析**：构建 DOM 树
7. **CSS 解析**：构建 CSSOM 树
8. **JavaScript 执行**：下载并执行 JS，可能修改 DOM
9. **构建渲染树**：合并 DOM 和 CSSOM
10. **布局（Layout）**：计算元素位置和大小
11. **绘制（Paint）**：将布局转换为像素
12. **合成（Composite）**：将图层合成到屏幕

### DNS 解析

- 递归查询：客户端向本地 DNS 服务器查询
- 迭代查询：本地 DNS 服务器向根域名服务器查询
- DNS 预解析：`<link rel="dns-prefetch" href="//example.com">`

### TCP 三次握手

1. 客户端发送 SYN 报文
2. 服务器返回 SYN-ACK 报文
3. 客户端发送 ACK 报文

为什么不能两次：防止已失效的连接请求报文被服务器接收

### TCP 四次挥手

1. 客户端发送 FIN 报文
2. 服务器返回 ACK 报文
3. 服务器发送 FIN 报文
4. 客户端返回 ACK 报文

:::

## 2. 浏览器多进程架构

::: details
现代浏览器采用多进程架构，提高稳定性和安全性。

### 主要进程

| 进程 | 职责 |
|------|------|
| Browser Process | 地址栏、书签、前进后退、网络请求、文件访问 |
| Renderer Process | 页面渲染、JavaScript 执行、事件处理 |
| GPU Process | GPU 相关操作，如 3D 绘制 |
| Network Process | 网络请求处理 |
| Utility Process | 工具进程，如 Chrome DevTools |

### Site Isolation

- 每个站点使用独立的 Renderer Process
- 防止跨站点数据泄露
- 提高安全性

### 沙箱机制

- Renderer Process 运行在沙箱中
- 限制文件系统访问、网络访问等
- 提高安全性

:::

## 3. 浏览器渲染原理

::: details
浏览器渲染是指浏览器将 HTML、CSS 和 JavaScript 等资源转换为用户可以看到的网页的过程。

### 渲染过程

1. **HTML 解析**：浏览器接收 HTML 文档，开始解析 HTML 标签，构建 DOM（文档对象模型）树。
2. **CSS 解析**：解析 CSS 文件，构建 CSSOM（CSS 对象模型）树。
3. **构建渲染树**：结合 DOM 树和 CSSOM 树，构建渲染树（Render Tree）。
4. **布局（Layout）**：根据渲染树，计算每个元素的位置和大小。这个过程也称为回流（Reflow）。
5. **绘制（Paint）**：将计算好的布局转换为屏幕上的像素。这个过程也称为重绘（Repaint）。
6. **合成（Composite）**：将绘制好的图层合成到一起，显示在屏幕上。

### 关键渲染路径

关键渲染路径是指从 HTML、CSS 和 JavaScript 到屏幕上呈现像素的过程。优化关键渲染路径可以提高页面加载速度和响应性能。

:::

## 2. 重排和重绘

::: details
重排（Reflow）和重绘（Repaint）是浏览器渲染过程中的两个重要概念。

### 重排（Reflow）

当元素的位置、大小或结构发生变化时，浏览器需要重新计算布局，这个过程称为重排。

会触发重排的操作：
- 修改元素的尺寸、位置或可见性
- 添加或删除 DOM 元素
- 改变窗口大小
- 计算 `offsetWidth` 和 `offsetHeight` 等布局属性

### 重绘（Repaint）

当元素的外观发生变化但不影响布局时，浏览器需要重新绘制元素，这个过程称为重绘。

### 优化策略

- **使用 CSS transforms**：`transform` 属性不会触发重排，只会触发合成
- **使用 `will-change`**：告诉浏览器元素即将发生变化
- **避免频繁操作 DOM**：批量处理 DOM 操作，减少重排次数
- **使用文档片段**：使用 `DocumentFragment` 一次性添加多个元素
- 仅使用 `transform` 和 `opacity` 的 CSS 动画性能优于 JavaScript 动画，因为可以被合成器线程独立处理；但改变布局属性的 CSS 动画同样会触发重排

:::
