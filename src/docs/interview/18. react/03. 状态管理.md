# 状态管理

## 1. Context API

::: details
Context 是 React 内置的状态共享方案。

### 基本用法

- 创建 Context：createContext(defaultValue)
- Provider：Context.Provider 包裹子组件
- 消费：useContext(Context)

### 适用场景

- 主题和语言：适合
- 用户认证：适合
- 频繁更新的数据：不适合
- 复杂状态逻辑：不适合

### 性能优化

- 拆分 Context：不同状态使用不同的 Context
- 使用 useMemo 优化 value
- 避免在 Provider 中创建新对象

### 总结

Context 适合低频更新的全局状态。

:::

## 2. Redux

::: details
Redux 是最流行的状态管理库。

### Redux Toolkit

- createSlice：创建切片，自动生成 action creator
- configureStore：配置 store，自动添加中间件
- Immer：支持直接修改 state

### 核心概念

- Store：全局状态容器
- Slice：功能模块，包含 reducer 和 action
- Dispatch：触发 action 的方法
- Selector：从 state 中提取数据的函数

### 异步操作

- createAsyncThunk：处理异步逻辑
- 三种状态：pending、fulfilled、rejected
- 在 extraReducers 中处理状态变化

### 总结

Redux Toolkit 是现代 Redux 的推荐写法。

:::

## 3. Zustand

::: details
Zustand 是轻量级的状态管理库。

### 基本用法

- 创建 store：create((set) => (...))
- 在组件中使用：const count = useStore(state => state.count)
- 更新状态：set((state) => (...))

### 中间件

- persist：持久化到 localStorage
- devtools：支持 Redux DevTools
- immer：支持 Immer 语法

### 与 Redux 对比

- API：Zustand 简单，Redux 丰富
- 模板代码：Zustand 少，Redux 多
- DevTools：Zustand 支持，Redux 完善
- 适用场景：Zustand 中小型项目，Redux 大型项目

### 总结

Zustand 适合追求简单状态管理的项目。

:::

## 4. 状态管理对比

::: details
选择合适的状态管理方案。

### 方案选择

- 是否需要全局状态？否：用 useState 或 useReducer
- 是：状态更新频率？
  - 低频：Context API
  - 高频：状态管理库
    - 简单需求：Zustand
    - 复杂需求：Redux Toolkit

### 功能对比

- 学习曲线：Context 低，Redux 中，Zustand 低
- 模板代码：Context 少，Redux 中，Zustand 少
- DevTools：Context 无，Redux 完善，Zustand 支持
- 性能优化：Context 需手动，Redux 内置，Zustand 内置

### 推荐方案

- 小型项目：useState 加 Context
- 中型项目：Zustand
- 大型项目：Redux Toolkit

### 总结

没有最好的方案，只有最适合的方案。

:::
