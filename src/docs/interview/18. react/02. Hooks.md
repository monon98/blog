# Hooks

## 1. useState

::: details
useState 用于在函数组件中添加状态。

### 基本用法

- 声明：const [count, setCount] = useState(0)
- 读取：count
- 更新：setCount(1) 或 setCount(prev => prev + 1)

### 函数式更新

- 当新状态依赖旧状态时使用：setCount(prev => prev + 1)
- 对象状态必须创建新对象
- 直接修改对象不会触发重渲染

### 惰性初始化

- 使用函数作为参数：useState(() => expensiveComputation())
- 只在首次渲染时执行
- 适合耗时计算

### 总结

useState 是最基础的 Hook，用于管理组件状态。

:::

## 2. useEffect

::: details
useEffect 用于处理副作用。

### 依赖数组

- 无依赖数组：每次渲染都执行
- 空数组：只在挂载时执行
- 有依赖：依赖变化时执行

### 清理函数

- 返回函数会在组件卸载时执行
- 常用于清理定时器、取消订阅等

### 常见场景

- 数据获取：在 effect 中调用 fetch
- 订阅：添加和移除事件监听
- 定时器：设置和清除 setInterval

### 总结

useEffect 用于处理数据获取、订阅、定时器等副作用。

:::

## 3. useRef

::: details
useRef 用于获取 DOM 元素引用或保存可变值。

### DOM 引用

- 创建：const inputRef = useRef(null)
- 绑定：元素的 ref 属性
- 访问：inputRef.current

### 保存可变值

- 不会触发重渲染
- 适合保存定时器 ID、之前的值等
- 与 useState 的区别：修改 ref 不会触发重渲染

### 总结

useRef 适合保存不触发重渲染的可变值。

:::

## 4. useReducer

::: details
useReducer 用于管理复杂的状态逻辑。

### 基本用法

- 签名：useReducer(reducer, initialState, init?)
- 返回：[state, dispatch]
- reducer：(state, action) => newState

### 与 useState 对比

| 特性 | useState | useReducer |
|------|----------|------------|
| 适用场景 | 简单状态 | 复杂状态逻辑 |
| 状态更新 | 直接调用 set | 调用 dispatch |
| 逻辑集中 | 分散在组件中 | 集中在 reducer |
| 可预测性 | 一般 | 更高 |

### 何时使用

- 状态逻辑复杂，包含多个子值
- 下一个状态依赖前一个状态
- 需要可预测的状态更新
- 与 Redux 模式一致

### 总结

useReducer 适合复杂状态逻辑，可预测且易测试。

:::

## 5. useMemo 和 useCallback

::: details
用于性能优化，避免不必要的计算和渲染。

### useMemo

- 缓存计算结果
- 依赖变化时才重新计算
- 适合昂贵的计算

### useCallback

- 缓存函数引用
- 配合 React.memo 使用
- 避免子组件因回调变化而重渲染

### 使用原则

- 昂贵的计算使用 useMemo
- 传递给子组件的回调使用 useCallback
- 传递给子组件的对象使用 useMemo

### 总结

过度使用反而会影响性能，只在必要时使用。

:::

## 5. 自定义 Hook

::: details
自定义 Hook 是复用状态逻辑的方式。

### 命名规则

- 必须以 use 开头
- 内部可以使用其他 Hook

### 常见自定义 Hook

- useFetch：数据获取
- useLocalStorage：本地存储同步
- useDebounce：防抖
- useThrottle：节流
- useMediaQuery：响应式查询

### 总结

自定义 Hook 是复用有状态逻辑的最佳方式。

:::

## 7. useTransition

::: details
useTransition 用于标记低优先级更新。

### 基本用法

- 返回：[isPending, startTransition]
- startTransition：将状态更新标记为过渡
- isPending：过渡是否正在进行

### 使用场景

- 搜索框实时过滤大量数据
- 标签页切换
- 任何不需要立即响应的更新

### 与 useDeferredValue 对比

| 特性 | useTransition | useDeferredValue |
|------|---------------|------------------|
| 用法 | 标记更新为过渡 | 延迟值的更新 |
| 返回值 | isPending | 延迟的值 |
| 适用场景 | 状态更新 | 值的渲染 |

### 总结

useTransition 让 UI 在处理大量更新时保持响应。

:::

## 8. useDeferredValue

::: details
useDeferredValue 用于延迟值的更新。

### 基本用法

- 签名：useDeferredValue(value)
- 返回：延迟的 value
- 在高优先级更新后延迟渲染

### 使用场景

- 搜索框输入时延迟更新结果列表
- 大量列表的滚动优化
- 避免卡顿的用户体验

### 总结

useDeferredValue 让 UI 在处理大量数据时保持流畅。

:::

## 9. Hook 规则

::: details
Hooks 有重要的使用规则。

### 基本规则

- 必须在组件顶层调用 Hook
- 不能在条件语句、循环、嵌套函数中调用
- 只能在 React 函数组件或自定义 Hook 中调用

### 为什么有这些规则

React 通过 Hook 的调用顺序来匹配状态。如果在条件语句中调用，顺序会变化，导致状态错乱。

### 总结

始终在组件顶层使用 Hook，遵循规则才能正确工作。

:::

## 10. React 19 新 Hook

::: details
React 19 引入了新的内置 Hook。

### use

- 在组件中读取 Promise 或 Context
- 替代 useContext 用于读取 Context
- 支持在条件语句中使用
- 读取 Promise 时会触发挂起，需配合 Suspense

### useActionState

- 简化表单处理
- 管理表单提交状态
- 处理服务器操作的返回值

### useFormStatus

- 读取最近的父级 form 元素的提交状态
- 适用于使用 form action 的场景
- 提供 pending、data、method 等信息

### useOptimistic

- 乐观更新
- 在异步操作完成前先更新 UI
- 操作完成后自动回滚或确认

### 总结

React 19 的新 Hook 简化了异步操作和表单处理。

:::
