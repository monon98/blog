# 面试场景题

## 1. useEffect 闭包陷阱

::: details
**问题**：以下代码有什么问题？如何修复？

```
function Counter() {
  const [count, setCount] = useState(0);

  useEffect(() => {
    const timer = setInterval(() => {
      console.log(count);
      setCount(count + 1);
    }, 1000);
    return () => clearInterval(timer);
  }, []);

  return <div>{count}</div>;
}
```

**问题分析**：

- 依赖数组为空，effect 只在挂载时执行
- setInterval 的回调中引用的 count 永远是 0
- 导致 count 永远不会增加

**修复方案**：

方案一：使用函数式更新
- setCount(prev => prev + 1) 不依赖外部 count

方案二：将 count 加入依赖数组
- 但会导致每次 count 变化都清除和重建定时器

方案三：使用 useRef 保存最新值
- ref.current 始终是最新的

:::

## 2. 状态更新 batching

::: details
**问题**：以下代码会触发几次渲染？

```
function App() {
  const [count, setCount] = useState(0);
  const [flag, setFlag] = useState(false);

  const handleClick = () => {
    setCount(1);
    setFlag(true);
  };

  console.log('render');
  return <div>{count} {String(flag)}</div>;
}
```

**答案**：React 18+ 只触发 1 次渲染

**原因**：

- React 18 引入了自动 batching
- 在事件处理、setTimeout、Promise 中的多个状态更新会合并为 1 次渲染
- React 18 之前，在 setTimeout 和 Promise 中会触发 2 次渲染

:::

## 3. 受控组件 vs 非受控组件

::: details
**问题**：什么时候用受控组件？什么时候用非受控组件？

### 受控组件

- 表单数据由 React 状态管理
- 通过 onChange 更新状态
- 适合：需要实时验证、动态表单、与 Redux 等状态管理集成

### 非受控组件

- 表单数据由 DOM 本身管理
- 通过 ref 获取值
- 适合：简单表单、文件上传、与非 React 代码集成

### 选择原则

- 需要即时验证 → 受控
- 需要动态控制输入 → 受控
- 简单表单、性能要求高 → 非受控
- 文件上传 → 非受控

:::

## 4. 列表渲染 key 的问题

::: details
**问题**：为什么不能用 index 作为 key？会有什么问题？

### 用 index 作为 key 的问题

场景：列表项从头部删除
- 删除前：[{id:1, name:'a'}, {id:2, name:'b'}, {id:3, name:'c'}]，key: [0, 1, 2]
- 删除后：[{id:2, name:'b'}, {id:3, name:'c'}]，key: [0, 1]

React 会认为：
- key=0 的元素从 'a' 变成 'b'，需要更新
- key=1 的元素从 'b' 变成 'c'，需要更新
- key=2 的元素被删除

实际上只需要删除第一个元素，但 React 会更新所有元素，导致：
- 性能浪费
- 状态错乱（如输入框内容错位）
- 动画异常

### 正确做法

- 使用唯一且稳定的 ID
- 不要使用随机数或时间戳
- 不要使用 index（除非列表是静态的）

:::

## 5. 性能优化场景

::: details
**问题**：列表有 1000 项，每项都有输入框，输入时如何避免其他项重渲染？

### 方案一：React.memo

- 包裹列表项组件
- 只有 props 变化时才重渲染
- 配合 useCallback 传递回调

### 方案二：虚拟列表

- 只渲染可视区域的元素
- 使用 react-window 或 react-virtuoso
- 大幅减少 DOM 数量

### 方案三：状态下推

- 将输入框状态移到列表项组件内部
- 避免父组件状态变化导致所有列表项重渲染

### 推荐组合

- 小规模：React.memo + useCallback
- 大规模：虚拟列表 + 状态下推

:::

## 7. 组件通信方案

::: details
**问题**：在一个复杂的 React 应用中，如何选择组件通信方案？

### 方案选择

| 关系 | 推荐方案 |
|------|----------|
| 父 → 子 | Props |
| 子 → 父 | 回调函数 Props |
| 兄弟组件 | 共同父组件状态 或 Context |
| 跨层级 | Context 或 状态管理库 |
| 任意组件 | 状态管理库（Redux/Zustand） |

### 最佳实践

- 优先使用 Props 逐层传递
- 避免过度使用 Context（性能问题）
- 复杂状态使用 Redux/Zustand
- 使用自定义 Hook 封装共享逻辑

:::

## 8. 错误边界使用

::: details
**问题**：如何优雅地处理 React 组件的渲染错误？

### 错误边界

- 使用 class 组件实现
- 捕获子组件的渲染错误
- 显示备用 UI

### 使用场景

- 页面级错误处理
- 组件级错误降级
- 配合 Sentry 等监控工具

### 注意事项

- 不能捕获事件处理器中的错误（使用 try/catch）
- 不能捕获异步代码中的错误（setTimeout、Promise）
- 不能捕获服务端渲染中的错误
- 不能捕获错误边界自身的错误

:::

## 9. 表单验证方案

::: details
**问题**：如何实现一个高性能的表单验证？

### 方案对比

| 方案 | 优点 | 缺点 |
|------|------|------|
| 手动验证 | 简单直接 | 代码冗余 |
| Formik | 功能完善 | 体积较大 |
| React Hook Form | 性能好、体积小 | 学习曲线 |
| Ant Design Form | 开箱即用 | 依赖 Ant Design |

### React Hook Form 原理

- 使用非受控组件，减少渲染
- 使用 useRef 管理表单状态
- 支持 Yup/Zod 等验证库

### 最佳实践

- 复杂表单使用 React Hook Form
- 简单表单手动验证
- 验证逻辑抽离到独立函数
- 使用 TypeScript 增强类型安全

:::

## 10. 代码分割与懒加载

::: details
**问题**：如何优化大型 React 应用的首屏加载速度？

### 代码分割

- 使用 React.lazy 动态导入组件
- 配合 Suspense 显示加载状态
- 减少初始包体积

### 路由级代码分割

- 每个路由使用独立的 chunk
- 按需加载页面组件
- 提升首屏加载速度

### 预加载

- 使用 preload 提前加载可能访问的路由
- 使用 prefetch 在空闲时预加载
- 提升用户体验

### 注意事项

- 错误处理：使用 ErrorBoundary 捕获加载失败
- 加载状态：使用 Suspense 或骨架屏
- 缓存策略：避免重复加载

:::

## 11. React 与 Vue 的区别

::: details
**问题**：React 和 Vue 的核心区别是什么？如何选择？

### 核心区别

| 特性 | React | Vue |
|------|-------|-----|
| 定位 | UI 库 | 渐进式框架 |
| 模板 | JSX | 模板语法 |
| 响应式 | 不可变 | 可变 |
| 状态管理 | 单向数据流 | 双向绑定 |
| 学习曲线 | 较陡 | 较平缓 |

### 选择原则

- 团队熟悉 React → React
- 团队熟悉 Vue → Vue
- 需要灵活度 → React
- 需要快速开发 → Vue
- 大型项目 → React（生态更完善）
- 中小型项目 → Vue（开发效率高）

:::

## 12. React 项目架构设计

::: details
**问题**：如何设计一个可维护的 React 项目架构？

### 目录结构

- components：通用组件
- pages：页面组件
- hooks：自定义 Hook
- services：API 服务
- store：状态管理
- utils：工具函数
- types：TypeScript 类型

### 设计原则

- 单一职责：每个组件只做一件事
- 组合优于继承：使用组合模式
- 关注点分离：UI、逻辑、数据分离
- 可测试性：编写可测试的代码

### 状态管理

- 局部状态：useState/useReducer
- 共享状态：Context/Zustand
- 全局状态：Redux Toolkit
- 服务端状态：React Query/SWR

:::
