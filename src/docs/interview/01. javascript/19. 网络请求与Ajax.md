# 网络请求与 Ajax 面试题

## 1. 请解释 HTTP 和 HTTPS 的区别

::: details
HTTP 和 HTTPS 是用于在客户端和服务器之间传输数据的协议。

### 基本区别

```javascript
// HTTP：超文本传输协议
// - 默认端口：80
// - 明文传输
// - 无状态

// HTTPS：安全超文本传输协议
// - 默认端口：443
// - SSL/TLS 加密
// - 需要 CA 证书
```

### HTTPS 的工作原理

```javascript
// HTTPS = HTTP + SSL/TLS

// 1. 客户端发起请求
// 2. 服务器返回证书
// 3. 客户端验证证书
// 4. 客户端生成随机密钥
// 5. 客户端用公钥加密随机密钥
// 6. 服务器用私钥解密
// 7. 双方使用随机密钥加密通信

// SSL/TLS 握手过程
Client Hello → Server Hello → Certificate → 
Key Exchange → Finished
```

### 为什么需要 HTTPS

```javascript
// 1. 数据加密
// 防止中间人攻击

// 2. 身份验证
// 确保连接到正确的服务器

// 3. 数据完整性
// 防止数据被篡改

// 4. SEO 优势
// Google 优先索引 HTTPS 网站
```

## 2. HTTP 1.0、1.1、2.0、3.0 有什么区别？

::: details
HTTP 协议经历了多个版本，每个版本都有重要的改进。

### HTTP 1.0

```javascript
// HTTP 1.0 的特点：
// 1. 短连接：每次请求都需要建立新的 TCP 连接
// 2. 无状态：服务器不保存客户端信息
// 3. 明文传输

// 示例
GET /index.html HTTP/1.0
Host: www.example.com

// 每个请求都需要三次握手
// 性能开销大
```

### HTTP 1.1

```javascript
// HTTP 1.1 的改进：
// 1. 长连接：默认开启 Keep-Alive
// 2. 管道化：允许同时发送多个请求
// 3. 分块传输：支持 Transfer-Encoding: chunked
// 4. 缓存控制：引入 Cache-Control

// 示例
GET /index.html HTTP/1.1
Host: www.example.com
Connection: keep-alive
Cache-Control: max-age=3600

// 长连接减少了建立连接的开销
```

### HTTP 2.0

```javascript
// HTTP 2.0 的改进：
// 1. 二进制分帧：将数据分割为更小的帧
// 2. 多路复用：一个连接上可以同时处理多个请求
// 3. 头部压缩：使用 HPACK 压缩头部
// 4. 服务器推送：主动推送资源给客户端

// 示例
// 服务器推送
Link: </style.css>; rel=preload; as=style

// 多路复用
// 一个 TCP 连接可以同时传输多个请求和响应
// 不同请求的数据帧可以交错发送
```

### HTTP 3.0

```javascript
// HTTP 3.0 的改进：
// 1. 基于 QUIC 协议：使用 UDP 而不是 TCP
// 2. 0-RTT 连接：减少连接建立时间
// 3. 连接迁移：网络切换时不需要重新建立连接
// 4. 更好的拥塞控制

// QUIC 协议的优势：
// 1. 减少延迟
// 2. 避免队头阻塞
// 3. 更好的安全性
// 4. 更好的移动性
```

### 版本对比

```javascript
const httpVersions = {
  'HTTP 1.0': {
    连接: '短连接',
    多路复用: '不支持',
    头部压缩: '不支持',
    服务器推送: '不支持'
  },
  'HTTP 1.1': {
    连接: '长连接',
    多路复用: '管道化（有限）',
    头部压缩: '不支持',
    服务器推送: '不支持'
  },
  'HTTP 2.0': {
    连接: '多路复用',
    多路复用: '支持',
    头部压缩: 'HPACK',
    服务器推送: '支持'
  },
  'HTTP 3.0': {
    连接: 'QUIC（UDP）',
    多路复用: '支持',
    头部压缩: 'QPACK',
    服务器推送: '支持'
  }
};
```

## 3. 如何实现 Ajax 请求？有哪些方式？

::: details
Ajax 是实现异步请求的核心技术，有多种实现方式。

### XMLHttpRequest

```javascript
// XMLHttpRequest：传统的 Ajax 实现方式
const xhr = new XMLHttpRequest();

// 配置请求
xhr.open('GET', 'https://api.example.com/data', true);

// 设置请求头
xhr.setRequestHeader('Content-Type', 'application/json');
xhr.setRequestHeader('Authorization', 'Bearer token123');

// 监听状态变化
xhr.onreadystatechange = function() {
  if (xhr.readyState === 4) { // 请求完成
    if (xhr.status === 200) { // 成功
      const data = JSON.parse(xhr.responseText);
      console.log(data);
    } else {
      console.error('请求失败:', xhr.status);
    }
  }
};

// 监听进度
xhr.onprogress = function(event) {
  if (event.lengthComputable) {
    const percentComplete = (event.loaded / event.total) * 100;
    console.log('上传进度:', percentComplete + '%');
  }
};

// 发送请求
xhr.send();

// 取消请求
xhr.abort();
```

### Fetch API

```javascript
// Fetch API：现代的 Ajax 实现方式
fetch('https://api.example.com/data', {
  method: 'GET',
  headers: {
    'Content-Type': 'application/json',
    'Authorization': 'Bearer token123'
  }
})
.then(response => {
  if (!response.ok) {
    throw new Error('Network response was not ok');
  }
  return response.json();
})
.then(data => {
  console.log(data);
})
.catch(error => {
  console.error('请求失败:', error);
});

// POST 请求
fetch('https://api.example.com/users', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json'
  },
  body: JSON.stringify({
    name: 'Alice',
    age: 25
  })
})
.then(response => response.json())
.then(data => console.log(data));

// 取消请求
const controller = new AbortController();
fetch('https://api.example.com/data', {
  signal: controller.signal
})
.then(response => response.json())
.then(data => console.log(data));

// 取消
controller.abort();
```

### Axios

```javascript
// Axios：流行的 HTTP 客户端库
import axios from 'axios';

// 基本用法
axios.get('https://api.example.com/data')
  .then(response => {
    console.log(response.data);
  })
  .catch(error => {
    console.error(error);
  });

// POST 请求
axios.post('https://api.example.com/users', {
  name: 'Alice',
  age: 25
})
.then(response => console.log(response.data));

// 配置
axios.defaults.baseURL = 'https://api.example.com';
axios.defaults.headers.common['Authorization'] = 'Bearer token123';
axios.defaults.timeout = 5000;

// 拦截器
axios.interceptors.request.use(config => {
  console.log('请求发出:', config);
  return config;
});

axios.interceptors.response.use(response => {
  console.log('收到响应:', response);
  return response;
});

// 取消请求
const source = axios.CancelToken.source();
axios.get('https://api.example.com/data', {
  cancelToken: source.token
})
.catch(error => {
  if (axios.isCancel(error)) {
    console.log('请求被取消:', error.message);
  }
});

// 取消
source.cancel('用户取消了请求');
```

## 4. 什么是 HTTP 状态码？常见的状态码有哪些？

::: details
HTTP 状态码表示服务器对请求的处理结果。

### 状态码分类

```javascript
// 1xx：信息性状态码
// 100 Continue：继续发送请求
// 101 Switching Protocols：切换协议

// 2xx：成功状态码
// 200 OK：请求成功
// 201 Created：资源创建成功
// 204 No Content：成功但无内容

// 3xx：重定向状态码
// 301 Moved Permanently：永久重定向
// 302 Found：临时重定向
// 304 Not Modified：资源未修改

// 4xx：客户端错误状态码
// 400 Bad Request：请求错误
// 401 Unauthorized：未授权
// 403 Forbidden：禁止访问
// 404 Not Found：资源不存在
// 405 Method Not Allowed：方法不允许

// 5xx：服务器错误状态码
// 500 Internal Server Error：服务器内部错误
// 502 Bad Gateway：网关错误
// 503 Service Unavailable：服务不可用
```

### 常见状态码详解

```javascript
// 200 OK
// 请求成功，服务器返回了请求的资源

// 301 Moved Permanently
// 资源已永久移动到新位置
// 浏览器会自动重定向
Location: https://new-url.com

// 302 Found
// 资源临时移动到新位置
Location: https://new-url.com

// 304 Not Modified
// 资源未修改，可以使用缓存
Cache-Control: max-age=3600

// 400 Bad Request
// 请求语法错误
// 可能原因：
// - 请求参数错误
// - 请求体格式错误
// - 请求头缺失

// 401 Unauthorized
// 需要身份验证
WWW-Authenticate: Basic realm="Example"

// 403 Forbidden
// 服务器拒绝请求
// 可能原因：
// - 权限不足
// - IP 被封禁

// 404 Not Found
// 请求的资源不存在

// 500 Internal Server Error
// 服务器内部错误
```

### 状态码最佳实践

```javascript
// 1. 正确使用状态码
// 成功：200, 201, 204
// 重定向：301, 302, 304
// 客户端错误：400, 401, 403, 404
// 服务器错误：500, 502, 503

// 2. 避免滥用状态码
// 不要用 200 表示错误
// 不要用 404 表示服务器错误

// 3. 提供有用的错误信息
// 返回错误详情，帮助调试
{
  "error": {
    "code": 400,
    "message": "Invalid request parameters",
    "details": {
      "field": "email",
      "reason": "Invalid email format"
    }
  }
}
```

## 5. 什么是 RESTful API？如何设计良好的 API？

::: details
RESTful API 是一种基于 HTTP 协议的 API 设计风格。

### REST 的核心原则

```javascript
// 1. 资源（Resource）
// 每个资源都有唯一的 URI
// GET /users - 获取用户列表
// GET /users/123 - 获取单个用户

// 2. 动词（Verb）
// 使用 HTTP 方法表示操作
// GET - 获取资源
// POST - 创建资源
// PUT - 更新资源（全量）
// PATCH - 更新资源（部分）
// DELETE - 删除资源

// 3. 表示（Representation）
// 资源可以有多种表示形式
// Accept: application/json
// Accept: application/xml

// 4. 无状态（Stateless）
// 每个请求都包含所有必要信息
// 服务器不保存客户端状态
```

### API 设计示例

```javascript
// 用户管理 API
// GET /users - 获取用户列表
// GET /users/:id - 获取单个用户
// POST /users - 创建用户
// PUT /users/:id - 更新用户
// DELETE /users/:id - 删除用户

// 嵌套资源
// GET /users/:id/posts - 获取用户的文章
// POST /users/:id/posts - 为用户创建文章

// 过滤和分页
// GET /users?page=1&limit=10
// GET /users?role=admin
// GET /users?sort=-createdAt

// 响应格式
{
  "data": [
    {
      "id": 1,
      "name": "Alice",
      "email": "alice@example.com"
    }
  ],
  "pagination": {
    "page": 1,
    "limit": 10,
    "total": 100,
    "totalPages": 10
  }
}

// 错误响应
{
  "error": {
    "code": 400,
    "message": "Invalid request",
    "details": {
      "field": "email",
      "reason": "Invalid email format"
    }
  }
}
```

### API 设计最佳实践

```javascript
// 1. 使用名词复数
// GET /users（推荐）
// GET /user（不推荐）

// 2. 使用嵌套表示资源关系
// GET /users/123/posts
// GET /posts/456/comments

// 3. 使用查询参数过滤
// GET /users?role=admin&status=active

// 4. 使用分页
// GET /users?page=2&limit=20

// 5. 使用标准 HTTP 状态码
// 200 OK
// 201 Created
// 400 Bad Request
// 401 Unauthorized
// 404 Not Found

// 6. 使用版本控制
// GET /api/v1/users
// GET /api/v2/users

// 7. 提供有用的错误信息
{
  "error": {
    "code": 400,
    "message": "Validation failed",
    "details": [
      {
        "field": "email",
        "message": "Invalid email format"
      }
    ]
  }
}
```
