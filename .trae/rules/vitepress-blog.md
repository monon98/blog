# VitePress 博客项目规则

## 项目结构规则

### 目录命名
- 使用英文目录名，避免使用中文或特殊字符
- 目录名应清晰反映其内容的功能和类型

### 文件组织
- 按功能和类型分类，保持目录结构清晰
- 文档内容应放在 src/docs 目录中
- 组件应放在 src/components 目录中

### 命名规范
- 统一文件和目录命名，使用小写字母和连字符，避免使用空格
- 文件名应清晰反映其内容的主题

## VitePress 配置规则

### 链接格式
- 使用相对路径，不包含 .md 扩展名
- 空格需要转义为 %20
- 链接应指向正确的文件路径

### 配置简化
- 保持配置文件简洁，只包含必要的设置
- 使用自动生成的侧边栏，减少手动配置

### 侧边栏配置
- 使用自动生成的侧边栏，根据目录结构自动生成导航
- 保持侧边栏配置与目录结构一致

## SSR 注意事项

### 浏览器对象
- 在使用浏览器特有对象（如 window、navigator、performance）时，添加条件判断
- 确保在服务端渲染时使用默认值，避免构建错误

### 构建测试
- 每次修改后运行构建命令，确保项目能够成功构建
- 及时处理构建过程中的警告和错误

## 构建优化

### 代码分割
- 考虑使用动态导入（dynamic import）来分割代码，减少 chunk 大小
- 优化图片和其他静态资源，减少构建产物大小

### 资源优化
- 优化图片和其他静态资源，减少构建产物大小
- 使用适当的图片格式和压缩方式

### 警告处理
- 及时处理构建过程中的警告，确保项目质量
- 避免使用未加载的语言标记，如 php-template

## 工具使用技巧

### PowerShell 命令
- 在 Windows 环境下，使用 PowerShell 命令时要注意语法差异
- 使用 Move-Item 命令移动文件，使用 Remove-Item 命令删除文件

### 文件操作
- 使用 Move-Item 命令移动文件，使用 Remove-Item 命令删除文件
- 在处理包含空格的路径时，使用双引号包裹路径

### 路径处理
- 在处理包含空格的路径时，使用双引号包裹路径
- 使用相对路径，避免使用绝对路径，提高项目的可移植性
